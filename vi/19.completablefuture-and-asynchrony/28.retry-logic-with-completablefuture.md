# How to Implement Retry Logic with CompletableFuture? (Cách triển khai logic retry với CompletableFuture)

## 🟢 Junior Level

**Retry** — thử lại một thao tác khi thất bại. Với CompletableFuture, điều này có thể được thực hiện qua `exceptionally()`:

```java
public CompletableFuture<String> withRetry(Supplier<CompletableFuture<String>> operation, int maxRetries) {
    return operation.get()
        .exceptionallyCompose(ex -> {
            if (maxRetries > 0) {
                return withRetry(operation, maxRetries - 1);
            }
            return CompletableFuture.failedFuture(new RuntimeException("All retries failed", ex));
        });
}
// Quan trọng: .join() bên trong exceptionally chặn thread callback.
// exceptionallyCompose (Java 12+) giữ được bản chất không chặn.

// Sử dụng
withRetry(() -> fetchDataAsync(), 3)
    .thenAccept(result -> System.out.println(result));
```

## 🟡 Middle Level

### Với Exponential Backoff

```java
// CompletableFuture.delayedExecutor có sẵn từ Java 9.
// exceptionallyCompose có sẵn từ Java 12.
// Đối với Java 8, dùng ScheduledExecutorService.
public CompletableFuture<String> withRetryAndDelay(
    Supplier<CompletableFuture<String>> operation,
    int maxRetries,
    long delayMs
) {
    return operation.get()
        .exceptionallyCompose(ex -> {
            if (maxRetries > 0) {
                // Chờ và thử lại
                return CompletableFuture.delayedExecutor(delayMs, TimeUnit.MILLISECONDS)
                    .thenCompose(v -> withRetryAndDelay(operation, maxRetries - 1, delayMs * 2));
            }
            return CompletableFuture.failedFuture(ex);
        });
}

// Sử dụng
withRetryAndDelay(() -> httpClient.getAsync(url), 3, 1000)
    .thenAccept(System.out::println);
```

### Với Kiểm Tra Loại Lỗi

```java
public CompletableFuture<String> withRetryIf(
    Supplier<CompletableFuture<String>> operation,
    int maxRetries,
    Predicate<Throwable> shouldRetry
) {
    return operation.get()
        .exceptionallyCompose(ex -> {
            if (maxRetries > 0 && shouldRetry.test(ex)) {
                return withRetryIf(operation, maxRetries - 1, shouldRetry);
            }
            return CompletableFuture.failedFuture(ex);
        });
}

// Chỉ cho timeout
withRetryIf(() -> fetchDataAsync(), 3,
    ex -> ex.getCause() instanceof TimeoutException);
```

### Các Lỗi Thường Gặp

1. **Retry vô hạn:**
```java
// ❌ Không giảm maxRetries
.exceptionallyCompose(ex -> withRetry(operation, maxRetries));

// ✅ Giảm dần
.exceptionallyCompose(ex -> withRetry(operation, maxRetries - 1));
```

## 🔴 Senior Level

### Tích Hợp Resilience4j

```java
import io.github.resilience4j.retry.Retry;

Retry retry = Retry.of("fetchData", RetryConfig.custom()
    .maxAttempts(3)
    .waitDuration(Duration.ofSeconds(1))
    .retryOnException(ex -> ex instanceof TimeoutException)
    .build());

CompletableFuture<String> result = Retry.decorateCompletionStage(
    retry,
    () -> fetchDataAsync()
);
```

### exceptionallyCompose Java 12+

```java
cf.exceptionallyCompose(ex -> {
    if (shouldRetry(ex)) {
        return retryOperation();
    }
    return CompletableFuture.failedFuture(ex);
});
```

### Kinh Nghiệm Production

**Tiện ích retry chung:**
```java
public class RetryUtil {
    public static <T> CompletableFuture<T> withRetry(
        Supplier<CompletableFuture<T>> operation,
        int maxRetries,
        long initialDelayMs,
        double backoffMultiplier
    ) {
        return attempt(operation, maxRetries, initialDelayMs, backoffMultiplier);
    }

    private static <T> CompletableFuture<T> attempt(
        Supplier<CompletableFuture<T>> operation,
        int remaining,
        long delayMs,
        double multiplier
    ) {
        return operation.get()
            .exceptionallyCompose(ex -> {
                if (remaining <= 0) {
                    return CompletableFuture.failedFuture(ex);
                }

                log.warn("Retry, {} attempts left", remaining - 1);

                return CompletableFuture.delayedExecutor(delayMs, TimeUnit.MILLISECONDS)
                    .thenCompose(v ->
                        attempt(operation, remaining - 1,
                            (long)(delayMs * multiplier), multiplier)
                    );
            });
    }
}

// Sử dụng
RetryUtil.withRetry(
    () -> httpClient.getAsync(url),
    3,
    1000,
    2.0  // exponential backoff
    // Exponential backoff thuần túy gây ra "thundering herd" — tất cả request retry
    // đến cùng lúc. Trong production, thêm jitter:
    // delayMs * (1 + random.nextDouble() * 0.5)
)
.thenAccept(System.out::println);
```

### Best Practices

```java
// ✅ Giới hạn số lần thử
withRetry(operation, 3);

// ✅ Exponential backoff
delayMs * Math.pow(2, attempt);

// ✅ Kiểm tra loại lỗi
ex -> ex.getCause() instanceof TimeoutException;

// ❌ Retry vô hạn
// ❌ Retry cho tất cả lỗi (không hợp lý cho tất cả)
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- exceptionallyCompose (Java 12+) — trả về một CF khác khi lỗi, nền tảng cho retry
- Exponential backoff: delayMs * multiplier^attempt, với jitter cho production
- Giới hạn số lần thử: maxRetries giảm 1 mỗi lần
- Kiểm tra loại lỗi: chỉ retry cho các lỗi có thể retry (Timeout, 5xx), không phải tất cả
- Resilience4j — giải pháp sẵn sàng cho production với Circuit Breaker + Retry + Bulkhead

**Các câu hỏi phụ thường gặp:**
- **exceptionally vs exceptionallyCompose cho retry?** — exceptionally trả về một giá trị, compose trả về một CF (retry bất đồng bộ)
- **Tại sao cần jitter trong backoff?** — Không có jitter, tất cả request retry đến cùng lúc (thundering herd)
- **delayedExecutor có chặn một thread không?** — Không, đó là một ScheduledExecutor. Thread không bị chặn trong khi chờ
- **Retry Java 8 không có exceptionallyCompose?** — Đệ quy trong exceptionally: return withRetry(operation, retries - 1)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Retry vô hạn cũng ổn" — lỗi dây chuyền khi có lỗi vĩnh viễn
- "Retry cho tất cả lỗi" — 4xx không nên được retry, chỉ 5xx và timeout
- "delayedExecutor chặn thread callback" — đó là một scheduler, nó không chặn

# What are the requirements for resources in try-with-resources? (Yêu cầu đối với resource trong try-with-resources là gì?)

## Junior Level

### Yêu cầu chính

Resource **phải** implement interface `java.lang.AutoCloseable`. Không có điều này, nó không thể được dùng trong try-with-resources.

```java
// Hoạt động - FileInputStream implement AutoCloseable
try (FileInputStream fis = new FileInputStream("file.txt")) {
    fis.read();
}

// Sẽ không biên dịch - String không implement AutoCloseable
try (String s = "hello") { } // Lỗi biên dịch
```

### Những class nào implement AutoCloseable

- Tất cả `InputStream` / `OutputStream` - file, mạng
- Tất cả `Reader` / `Writer` - văn bản
- `Connection`, `Statement`, `ResultSet` - database
- `Scanner`, `Formatter` - tiện ích

### Nhiều resource

```java
try (FileInputStream fis = new FileInputStream("in.txt");
     FileOutputStream fos = new FileOutputStream("out.txt")) {
    // Cả hai sẽ được đóng tự động
}
```

### Java 9+ - biến bên ngoài

```java
FileInputStream fis = createStream();
try (fis) { // fis phải là effectively final
    fis.read();
}
```

---

### Khi nào KHÔNG nên đặt resource vào try-with-resources

1. **Resource do container quản lý** (Spring @Bean) - framework tự đóng nó
2. **Pooled connection** (HikariCP) - pool quản lý vòng đời giúp bạn
3. **Cần truyền resource đi tiếp** - return từ phương thức, TWR sẽ đóng nó trước khi return

## Middle Level

### AutoCloseable so với Closeable

**`AutoCloseable`** (Java 7, `java.lang`):
- `void close() throws Exception`
- Đa dụng - cho bất kỳ resource nào

**`Closeable`** (Java 5, `java.io`):
- `void close() throws IOException`
- Chỉ cho I/O
- Kế thừa `AutoCloseable`

Cái nào cũng dùng được cho try-with-resources.

### Rủi ro rò rỉ trong lúc khởi tạo

```java
// AN TOÀN - nếu B lỗi, A sẽ được đóng
try (A a = new A(); B b = new B(a)) { }

// NGUY HIỂM - nếu B lỗi, A rò rỉ
try (B b = new B(new A())) { }
// A được tạo nhưng try không có tham chiếu tới nó
// Phân tích rò rỉ: new A() tạo object. new B(a) ném exception.
// A được tạo, nhưng biến trong TWR là B. TWR không có tham chiếu tới A,
// nên close() cho A sẽ không được gọi. Giải pháp:
// try (A a = new A(); B b = new B(a)) { ... }
```

### Idempotency của close()

Phương thức `close()` phải là idempotent - lời gọi lặp lại không được ném exception.

**Idempotency** - thuộc tính của một thao tác: lời gọi lặp lại cho cùng kết quả như lần đầu. close() phải là idempotent: lời gọi đầu tiên đóng resource, lời gọi thứ hai - không làm gì (không ném).

```java
public void close() {
    if (closed.compareAndSet(false, true)) {
        // giải phóng resource thực sự
    }
}
```

### Yêu cầu về biến (Java 9+)

Resource phải là `final` hoặc `effectively final`. Compiler tạo một bản sao local của tham chiếu - điều này đảm bảo rằng nếu một thread khác thay đổi biến bên ngoài, TWR vẫn đóng object gốc.

effectively final = biến không thay đổi sau khi khởi tạo, kể cả khi từ khóa `final` không được viết. Compiler thấy rằng bạn không thay đổi biến và cho phép dùng nó trong TWR.

## Senior Level

### Bên trong: compiler tạo một bản sao

Khi dùng một biến bên ngoài trong `try(resource)`, compiler tạo một bản sao local của tham chiếu. Điều này đảm bảo việc đóng an toàn với thread (thread-safe).

### Ném exception từ close()

Nếu `close()` ném một exception:
- Nếu không có lỗi nào trong `try` - exception từ `close()` trở thành cái chính
- Nếu đã có một exception trong `try` - cái từ `close()` được thêm vào `suppressed`

### Close bị gián đoạn

Trong các thao tác mạng, `close()` có thể bị chặn. Hãy đặt timeout, nếu không thread sẽ "treo" ở giai đoạn đóng resource.

### Cấp phát Object và GC

`try-with-resources` tạo object. Khi mở/đóng hàng nghìn resource mỗi giây, điều này tạo áp lực lên GC (Young Generation). Hãy dùng **resource pool** (HikariCP cho DB), thứ implement `AutoCloseable` nhưng thay vì đóng, trả object về lại pool.

### Các trường hợp biên (Edge Case)

- **Resource không mở được** - nếu constructor ném exception, TWR sẽ không cố đóng (không có gì để đóng)
- **Khởi tạo một phần** - nếu constructor đã mở resource native nhưng lỗi trước khi return - rò rỉ. Hãy giữ constructor nhẹ.

### Chẩn đoán

- **Resource Leak Detection** - IDE tô sáng các class `AutoCloseable` không được dùng trong TWR. Đừng bỏ qua.
- **Phân tích `jstack`** - nhiều thread ở trạng thái `BLOCKED` / `WAITING` trong `close()` - hãy kiểm tra deadlock giữa các resource.

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Resource phải implement `java.lang.AutoCloseable`
- `AutoCloseable` (Java 7, `java.lang`) - `close() throws Exception`; `Closeable` (Java 5, `java.io`) - `close() throws IOException`
- Phương thức `close()` phải là idempotent - lời gọi lặp lại không ném
- Khai báo resource riêng biệt: `try (A a = new A(); B b = new B(a))` - nếu không sẽ rò rỉ
- Java 9+: các biến bên ngoài phải là `effectively final`
- Compiler tạo bản sao local của tham chiếu - đảm bảo đóng thread-safe
- Nếu `close()` ném khi đang có lỗi trong `try` - được thêm vào `suppressed`
- Resource pool (HikariCP) implement AutoCloseable nhưng trả object về pool, không đóng

**Các câu hỏi phụ thường gặp:**
- **Khác biệt giữa AutoCloseable và Closeable là gì?** - AutoCloseable đa dụng hơn (throws Exception), Closeable chỉ cho I/O (throws IOException)
- **Idempotency của close() là gì?** - Lời gọi đầu tiên đóng resource, lời gọi thứ hai - không làm gì
- **Tại sao tạo resource lồng nhau nguy hiểm?** - `new B(new A())` - nếu B lỗi, TWR không có tham chiếu tới A, nó rò rỉ
- **Điều gì xảy ra khi mở/đóng resource hàng loạt?** - Áp lực lên GC; hãy dùng resource pool

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Close() có thể ném exception mỗi lần" - phải là idempotent
- "Tôi không khai báo resource riêng biệt cho ngắn gọn" - điều này gây rò rỉ
- "TWR đóng pooled connection" - pool tự quản lý vòng đời, trả về != đóng

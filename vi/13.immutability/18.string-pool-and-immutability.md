# How does String pool work and how is it related to immutability? (String pool hoạt động như thế nào và nó liên quan đến tính bất biến ra sao?)

---

## Basic Level

**String Pool** là một vùng lưu trữ bộ nhớ đặc biệt nơi Java chỉ giữ một bản sao duy nhất của mỗi chuỗi (string) duy nhất.

```java
String a = "Hello";
String b = "Hello";
System.out.println(a == b); // true — cùng một chuỗi từ pool
```

### Tại Sao Điều Này Chỉ Hoạt Động Với Các Chuỗi Bất Biến

Nếu các chuỗi có thể bị thay đổi, việc sửa một chuỗi sẽ ảnh hưởng đến mọi chuỗi khác tham chiếu đến nó:
```java
// Giả sử — nếu các chuỗi là mutable
String a = "Hello";
String b = "Hello"; // cùng tham chiếu từ pool
a.changeTo("World"); // cũng phá vỡ b!
```

### Method intern()
```java
String s1 = new String("Hello"); // object mới trong heap
String s2 = s1.intern();          // thêm vào pool, trả về tham chiếu
String s3 = "Hello";              // từ pool
System.out.println(s2 == s3);     // true
```

## Intermediate Level

### Cách Nó Hoạt Động

1. **Tại thời điểm biên dịch** — tất cả các chuỗi literal đi vào bảng hằng số (constant table) của class
2. **Tại thời điểm load** — JVM kiểm tra pool: nếu chuỗi tồn tại — trả về tham chiếu, nếu không — tạo một chuỗi mới
3. **Tại runtime** — `intern()` thêm một chuỗi từ heap vào pool

### Sự Tiến Hóa Của Bộ Nhớ
- **Java 6**: String Pool nằm trong **PermGen** (kích thước giới hạn, thường xuyên OOM)
- **Java 7u6+**: String Pool được chuyển từ PermGen sang **Heap** thông thường (được quản lý bởi GC)

### Lợi Ích
- **Tiết kiệm bộ nhớ** — các chuỗi trùng lặp không được tạo
- **So sánh nhanh** — các chuỗi được intern có thể được so sánh qua `==` trong O(1)
  (một lệnh CPU — so sánh tham chiếu), trong khi `equals()` phải duyệt qua tất cả các ký tự
- **hashCode được cache** — chỉ được tính một lần

### Khi Nào Dùng intern()
- Nhiều chuỗi lặp lại (key, hằng số cấu hình)
- Key trong `HashMap` với hàng tỷ entry (tiết kiệm khỏi việc trùng lặp)

## Advanced Level

### Mối Liên Hệ Với Tính Bất Biến

Tính bất biến là một **điều kiện tiên quyết** cho String Pool. Pattern **Flyweight** ở cấp độ ngôn ngữ chỉ hoạt động vì Java đảm bảo: nội dung của `String` sẽ không bao giờ thay đổi.

### Hiệu Năng

- So sánh qua `==` cho các chuỗi được intern — **O(1)**, nhưng trong business logic vẫn dùng `equals()`
- `hashCode` được cache giúp tăng tốc `HashMap` — các lần tra cứu lặp lại không cần tính toán lại

### Rủi Ro Của intern()

- **Rò rỉ bộ nhớ (Memory leak)** — các chuỗi trong pool không bị GC thu hồi chừng nào ClassLoader còn sống
- **PermGen/Heap OOM** — quá nhiều chuỗi duy nhất qua `intern()` có thể làm tràn bộ nhớ
- Trong Java 7+ pool nằm trong Heap, nhưng các chuỗi vẫn có thể tồn tại rất lâu

### Tóm Tắt Cho Advanced
- String Pool — pattern Flyweight ở cấp độ ngôn ngữ
- Chỉ hoạt động nhờ đảm bảo về tính bất biến
- Pool trong Heap (Java 7+), được quản lý bởi GC
- `intern()` — mạnh mẽ nhưng nguy hiểm: theo dõi khối lượng các chuỗi duy nhất

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- String Pool — kho lưu trữ các chuỗi duy nhất, chỉ hoạt động NHỜ tính bất biến (Flyweight)
- Các literal đi vào pool khi class được load, `intern()` thêm một chuỗi từ heap
- Java 6: pool trong PermGen (thường xuyên OOM); Java 7+: pool trong Heap (được quản lý bởi GC)
- So sánh các chuỗi được intern qua `==` — O(1), nhưng trong business logic dùng `equals()`
- String cache hashCode — chỉ tính một lần, tăng tốc HashMap
- Rủi ro của intern(): rò rỉ bộ nhớ, Heap OOM với quá nhiều chuỗi duy nhất

**Các câu hỏi phụ thường gặp:**
- *Tại sao pool không thể tồn tại nếu không có tính bất biến?* — Thay đổi một chuỗi sẽ phá vỡ mọi tham chiếu đến nó
- *Khi nào dùng intern()?* — Nhiều chuỗi lặp lại, key trong các HashMap khổng lồ
- *intern() có an toàn không?* — Các chuỗi trong pool không bị GC thu hồi chừng nào ClassLoader còn sống — rủi ro OOM
- *Compact Strings có ảnh hưởng đến pool không?* — Không, pool hoạt động độc lập; Compact Strings tiết kiệm 50% bộ nhớ

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "String Pool nằm trong PermGen" — từ Java 7+ nó nằm trong Heap
- "intern() luôn tăng tốc mọi thứ" — lạm dụng nó gây ra OOM
- "So sánh chuỗi qua == là ổn sau khi intern()" — trong business logic luôn dùng equals()
- "Pool sao chép các chuỗi" — các literal được đặt vào pool khi class được load

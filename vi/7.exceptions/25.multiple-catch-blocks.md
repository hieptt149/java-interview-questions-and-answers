# Can you have multiple catch blocks for one try? (Có thể có nhiều khối catch cho một try không?)

## Junior Level

### Có, bạn có thể!

Java cho phép dùng nhiều khối `catch` cho một `try`:

```java
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Paths;
import java.nio.file.FileNotFoundException;

public class FileProcessor {
    public String readFile(String path) {
        try {
            return Files.readString(Paths.get(path));
        } catch (FileNotFoundException e) {
            // Trường hợp cụ thể - file không tồn tại
            return "default content";
        } catch (IOException e) {
            // Chung hơn - các lỗi IO khác
            throw new ServiceException("Failed to read file: " + path, e);
        }
    }
}
```

### Quy tắc: từ cụ thể tới chung

Các khối `catch` phải đi **từ cụ thể tới chung**:

```java
// Đúng
try { ... }
catch (FileNotFoundException e) { }  // Cụ thể
catch (IOException e) { }            // Chung hơn
catch (Exception e) { }              // Chung nhất

// Sai - sẽ không biên dịch!
try { ... }
catch (Exception e) { }              // Bắt mọi thứ!
catch (FileNotFoundException e) { }  // Không bao giờ thực thi
```

### TẠI SAO thứ tự quan trọng: cơ chế "first match wins"

Compiler kiểm tra thứ tự các khối catch **lúc biên dịch**. Khi bạn viết nhiều catch, compiler xây dựng một cây phân cấp kiểu và kiểm tra rằng mỗi catch tiếp theo không phải là một kiểu con của một cái trước đó.

**Ở mức compiler:**
1. Compiler phân tích mỗi khối catch từ trên xuống dưới.
2. Với mỗi catch nó kiểm tra: "Đã có một catch ở trên là kiểu cha (supertype) của cái hiện tại chưa?"
3. Nếu có - lỗi biên dịch `"exception X has already been caught"`, vì code trong khối catch dưới là **không thể tiếp cận** (unreachable code, JLS 14.21).
4. Nếu không - catch được thêm vào Exception Table.

**Ở mức JVM (runtime):**
1. Khi `athrow`, JVM quét Exception Table **từ trên xuống dưới**.
2. Cái khớp đầu tiên theo kiểu (hoặc kiểu cha) giành quyền điều khiển.
3. Các khối catch còn lại **không được kiểm tra** - kể cả khi chúng cũng khớp.

Điều này được gọi là **"first match wins"**. Do đó thứ tự quyết định handler nào nhận quyền điều khiển.

```java
try { ... }
catch (FileNotFoundException e) { ... }  // #1: được kiểm tra đầu tiên
catch (IOException e) { ... }             // #2: chỉ được kiểm tra nếu #1 không khớp
```

Nếu `FileNotFoundException` được ném trong `try`, JVM tìm thấy một khớp ở #1 và **không tới** #2, dù `FileNotFoundException` cũng là một `IOException`.

### finally sau tất cả các catch

```java
try {
    // code
} catch (IOException e) {
    // handler IO
} catch (Exception e) {
    // handler cho phần còn lại
} finally {
    // Thực thi sau bất kỳ catch nào
}
```

### Khi nào KHÔNG nên dùng nhiều khối catch

1. **Xử lý giống nhau** - nếu tất cả các khối catch làm cùng một việc, hãy dùng multi-catch (`A | B`) - ngắn hơn và dễ đọc hơn (Java 7+)
2. **Hơn 5 khối catch** - dấu hiệu vi phạm SRP, phương thức làm quá nhiều. Cân nhắc tách thành nhiều phương thức
3. **Catch `Exception` khi các đặc thù không quan trọng** - cho việc ghi log chung, một catch là đủ
4. **Theo phong cách hàm** - thay vì catch dùng các monad `Either`/`Try` (thư viện Vavr)
5. **Khi @ControllerAdvice là đủ** - trong Spring REST một global handler thay thế 10 khối catch

### Lưu ý: Java 7+ multi-catch như một giải pháp thay thế

Bắt đầu từ Java 7, thay vì nhiều khối catch riêng biệt với logic giống hệt nhau, bạn có thể dùng **multi-catch**:

```java
// Thay vì:
catch (IOException e) {
    log.error("Error", e);
    throw new ServiceException(e);
}
catch (SQLException e) {
    log.error("Error", e);
    throw new ServiceException(e);
}

// Viết:
catch (IOException | SQLException e) {
    log.error("Error", e);
    throw new ServiceException(e);
}
```

Multi-catch được ưa chuộng hơn khi việc xử lý là giống hệt nhau. Các catch riêng biệt chỉ cần khi logic **khác nhau** (ví dụ: retry cho IO, nhưng không cho SQL).

## Middle Level

### Cách JVM tìm handler

Trong file `.class`, một **Exception Table** được tạo ra:

| from | to  | target | type                  |
| ---- | --- | ------ | --------------------- |
| 0    | 10  | 13     | FileNotFoundException |
| 0    | 10  | 25     | IOException           |
| 0    | 10  | 37     | Exception             |

Khi `athrow` xảy ra, JVM quét bảng **từ trên xuống dưới** cho tới khi khớp đầu tiên.

### Anti-pattern: trùng lặp code

```java
// Xấu - trùng lặp
try { ... }
catch (IOException e) {
    log.error("Error", e);
    throw new ServiceException(e);
}
catch (SQLException e) {
    log.error("Error", e);       // Giống hệt!
    throw new ServiceException(e); // Giống hệt!
}

// Tốt - multi-catch
try { ... }
catch (IOException | SQLException e) {
    log.error("Error", e);
    throw new ServiceException(e);
}
```

### Tách biệt logic

Nếu cần xử lý khác nhau - các khối `catch` riêng biệt là hợp lý:

```java
try {
    // code
} catch (FileNotFoundException e) {
    log.warn("File not found, using default");
    return getDefaultData();
} catch (IOException e) {
    log.error("IO error", e);
    throw new ServiceException(e);
}
```

### Chi phí của Catch

Việc cố đi vào một `catch` bản thân nó là "miễn phí" cho tới khi một exception được ném. Việc có một Exception Table không làm chậm việc thực thi khối `try`.

## Senior Level

### Kích thước Exception Table

Số lượng khối `catch` khổng lồ có thể làm phình kích thước phương thức vượt quá 64KB -> lỗi biên dịch. Đây là một dấu hiệu chắc chắn của vi phạm SRP - phương thức làm quá nhiều.

### Đa hình so với Catch

Thay vì 10 khối `catch`, đôi khi tốt hơn:

```java
// Giải pháp thay thế - xử lý qua cây phân cấp
catch (BusinessException e) {
    // Xử lý tất cả các kiểu con: OrderException, PaymentException, v.v.
    handleBusinessError(e);
}
```

Hoặc Pattern Matching (Java 17+):

```java
catch (Exception e) {
    if (e instanceof FileNotFoundException fnf) {
        // fnf đã được cast sang kiểu
    } else if (e instanceof IOException io) {
        // io đã được cast sang kiểu
    }
}
```

### Bắt Error

Bạn có thể bắt `Error` hoặc `Throwable`, nhưng sau `OutOfMemoryError` trạng thái ứng dụng là không dự đoán được. Chỉ bắt để "hơi thở cuối cùng" - ghi log trước khi sập.

### Chẩn đoán

- **`javap -v MyClass.class`** - hiển thị Exception Table thật
- **Log Correlation** - lưu metadata chung (Trace ID) cho mọi loại lỗi
- **Static Analysis** - Sonar cảnh báo về trùng lặp trong các khối catch
- **Metric** - đếm mỗi loại exception qua Micrometer

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Nhiều khối `catch` cho một `try` - được phép và dùng rộng rãi
- Quy tắc: từ cụ thể tới chung - `FileNotFoundException` trước `IOException` trước `Exception`
- Compiler kiểm tra thứ tự lúc biên dịch - thứ tự sai = lỗi "already been caught"
- JVM tìm handler "first match wins" - quét Exception Table từ trên xuống dưới cho tới khớp đầu tiên
- Việc có Exception Table không làm chậm việc thực thi khối `try` - kiểm tra là "miễn phí" cho tới khi có exception
- Nếu xử lý giống hệt nhau - dùng multi-catch (`IOException | SQLException`) thay vì trùng lặp
- Hơn 5 khối catch - dấu hiệu vi phạm SRP, phương thức làm quá nhiều

**Các câu hỏi phụ thường gặp:**
- **Tại sao `Exception` không thể đi trước `IOException`?** - `Exception` bắt mọi thứ, `IOException` trở thành unreachable code
- **JVM tìm handler như thế nào?** - Quét Exception Table từ trên xuống dưới, khớp đầu tiên giành quyền điều khiển
- **Khi nào cần các catch riêng biệt thay vì multi-catch?** - Khi logic xử lý khác nhau (retry cho IO, không cho SQL)
- **Số lượng catch có ảnh hưởng hiệu suất không?** - Tìm kiếm O(n) trong Exception Table, đặt các cái thường gặp lên trước

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi đặt `catch (Exception e)` đầu tiên cho đơn giản" - sẽ không biên dịch với các catch cụ thể hơn
- "Nhiều khối catch không ảnh hưởng hiệu suất `try`" - đúng, nhưng ảnh hưởng việc tìm kiếm khi có exception
- "Tôi dùng catch cho `Error` trong logic nghiệp vụ" - sau `OutOfMemoryError` trạng thái không dự đoán được
- "Tôi trùng lặp code trong mỗi catch" - dùng multi-catch khi việc xử lý giống hệt nhau

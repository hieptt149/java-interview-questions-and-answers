# Can HashMap Store a null Value? (HashMap có thể lưu một null Value không?)

## 🟢 Junior Level

**Có**, HashMap cho phép lưu bất kỳ số lượng giá trị `null` nào.

**Ví dụ:**
```java
HashMap<String, String> map = new HashMap<>();
map.put("name", null);
map.put("email", null);
map.put("age", "25");

System.out.println(map.get("name")); // null
System.out.println(map.size());      // 3 (cả ba phần tử được lưu)
```

**Vấn đề:** Khi `get(key)` trả về `null`, không rõ — key vắng mặt hay giá trị là `null`?

**Giải pháp:** Dùng `containsKey()` để kiểm tra:
```java
if (map.containsKey("name")) {
    // Key tồn tại, và giá trị của nó có thể là null
}
```

## 🟡 Middle Level

### Vấn đề Mơ hồ

`get(key)` trả về `null` trong hai trường hợp:
1. Key **vắng mặt** khỏi map
2. Key **tồn tại**, nhưng giá trị của nó = `null`

```java
Map<String, String> map = new HashMap<>();
map.put("key", null);

System.out.println(map.get("key"));      // null (giá trị)
System.out.println(map.get("missing"));  // null (không có key)
// Làm sao phân biệt chúng?

System.out.println(map.containsKey("key"));      // true
System.out.println(map.containsKey("missing"));  // false
```

### So sánh Collection

| Collection        | Null value    | Ghi chú                   |
| ----------------- | --------------- | -------------------------- |
| HashMap           | Cho phép      | Hành vi chuẩn          |
| Hashtable         | Bị cấm (NPE)  | Deprecated              |
| ConcurrentHashMap | Bị cấm (NPE)  | An toàn đa luồng        |
| TreeMap           | Cho phép      | Sắp xếp theo key        |

### Tại sao ConcurrentHashMap cấm Null?

Trong môi trường đa luồng, bạn không thể kiểm tra atomic `get()` + `containsKey()`:
```java
// Thread A:
String val = map.get(key);     // null
// Thread B xóa key giữa các lời gọi:
// Thread A:
boolean exists = map.containsKey(key); // false — nhưng val đã là null rồi!
```

### Best Practices

1. **Tránh các giá trị null** — dùng Optional hoặc Null Object
2. **Luôn kiểm tra `containsKey()`** trước khi xử lý null
3. **Ghi chép tài liệu** — liệu method của bạn có thể trả về null từ một Map hay không

### Các sai lầm thường gặp

1. **NPE khi dùng giá trị:**
```java
map.get("key").toString(); // NPE nếu giá trị = null
```
2. **Nhầm lẫn với key vắng mặt** — lỗi logic

## 🔴 Senior Level

### Vấn đề Liveness

Trong ConcurrentHashMap, cấm null loại bỏ sự mơ hồ trong check-then-act:
```java
// Kịch bản giả định (CHM thực tế cấm null)
// Cho thấy TẠI SAO CHM cấm null:
if (map.get(key) == null) {        // Bước 1: null
    if (!map.containsKey(key)) {   // Bước 2: false (key được thêm bởi thread khác!)
        map.put(key, value);       // Bước 3: ghi đè giá trị của người khác
    }
}
```

Cấm null làm cho `get() == null` là một chỉ báo rõ ràng về sự vắng mặt của key.

### Hiện thực bên trong

Trong HashMap, null value được lưu như một entry thông thường:
```java
// putVal:
Node<K,V> e;
// ...
e.value = value; // value có thể là null
```
Value không tham gia vào việc hashing — không có hạn chế.

### Optional như một giải pháp thay thế

```java
Map<String, Optional<Value>> map = new HashMap<>();

// Ý định tường minh:
map.put("key", Optional.empty());  // Cố ý "không có gì"
map.put("key", Optional.of(val));  // Có một giá trị

// Lấy ra:
Optional<Value> opt = map.getOrDefault("key", Optional.empty());
```

Overhead: một object `Optional` bổ sung mỗi entry.

### Null Object Pattern

```java
class User {
    static final User EMPTY = new User("", 0);
    // ...
}

Map<String, User> map = new HashMap<>();
map.put("missing", User.EMPTY); // Thay vì null
```

Zero overhead, ngữ nghĩa tường minh, an toàn với NPE.

### Hệ quả về bộ nhớ

Một null value không tiêu tốn bộ nhớ bổ sung:
- Tham chiếu tới null = 0 byte (chỉ là sự vắng mặt của một object)
- Node vẫn được tạo (header + hash + key + value ref + next)

### Chẩn đoán Production

Dấu hiệu của các vấn đề null-value:
- NPE trong các chain method: `map.get(key).method()`
- Lỗi logic: null được diễn giải là "không có dữ liệu"
- Trong DB: các giá trị null trong Map → null trong cột (có thể vi phạm constraint)

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- HashMap cho phép bất kỳ số lượng giá trị null nào
- Vấn đề: get(key) = null là mơ hồ — key vắng mặt HAY value = null?
- Giải pháp: containsKey() để kiểm tra rõ ràng
- ConcurrentHashMap cấm các giá trị null — để loại bỏ sự mơ hồ trong check-then-act
- Null Object Pattern: tạo một hằng số EMPTY thay vì null
- Optional như giải pháp thay thế: Map<String, Optional<Value>> — ý định tường minh

**Các câu hỏi phụ thường gặp:**
- **Tại sao CHM cấm các giá trị null?** — Vấn đề Liveness: get=null phải rõ ràng nghĩa là "không có key" cho các thao tác atomic
- **Làm sao phân biệt null với key vắng mặt?** — containsKey()
- **null value khác null key như thế nào?** — nhiều null value được cho phép, chỉ một null key
- **Optional vs Null Object?** — Optional = object bổ sung (overhead), Null Object = zero overhead

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "HashMap cấm các giá trị null" — nó cho phép chúng
- "ConcurrentHashMap cho phép các giá trị null" — không, NPE
- "null value = 0 byte" — Node vẫn được tạo (~32-48 byte)

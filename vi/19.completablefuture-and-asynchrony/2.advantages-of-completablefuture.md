# What Are the Main Advantages of CompletableFuture over Future? (Những ưu điểm chính của CompletableFuture so với Future)

## 🟢 Junior Level

CompletableFuture có **5 ưu điểm chính** so với Future thông thường:

1. **Không chặn (Non-blocking)** — có thể xây dựng chuỗi mà không cần chờ
2. **Kết hợp (Combining)** — có thể gộp nhiều CompletableFuture
3. **Xử lý lỗi** — các phương thức tích hợp sẵn cho ngoại lệ
4. **Hoàn thành thủ công** — có thể hoàn thành kết quả bất cứ lúc nào
5. **Nhiều phương thức hơn** — 40+ phương thức cho các tình huống khác nhau

```java
// Future — chỉ có thể chờ
Future<String> future = executor.submit(() -> "Hello");
String result = future.get();  // chặn!

// CompletableFuture — chuỗi mà không cần chờ
CompletableFuture.supplyAsync(() -> "Hello")
    .thenApply(s -> s + " World")
    .thenAccept(System.out::println);  // không chặn!
```

## 🟡 Middle Level

### Chi Tiết Các Ưu Điểm

**1. Khả năng kết hợp (Composability):**
```java
// Future — không thể kết hợp
Future<Integer> f1 = executor.submit(() -> 10);
Future<Integer> f2 = executor.submit(() -> 20);
// Cần chờ cả hai và cộng thủ công

// CompletableFuture — thenCombine
CompletableFuture<Integer> cf1 = CompletableFuture.supplyAsync(() -> 10);
CompletableFuture<Integer> cf2 = CompletableFuture.supplyAsync(() -> 20);

cf1.thenCombine(cf2, (a, b) -> a + b)
   .thenAccept(System.out::println);  // 30
```

**2. Xử lý lỗi:**
```java
// Future — try/catch thủ công
try {
    Integer result = future.get();
} catch (ExecutionException e) {
    // xử lý thủ công
}

// CompletableFuture — exceptionally
cf.exceptionally(ex -> {
    log.error("Error", ex);
    return defaultValue;
});
```

**3. Hoàn thành thủ công:**
```java
// Có thể hoàn thành thủ công
CompletableFuture<String> cf = new CompletableFuture<>();

// Trong một thread khác:
cf.complete("result");     // thiết lập kết quả
cf.completeExceptionally(new RuntimeException("Error"));  // thiết lập lỗi
```

**4. Chuỗi bất đồng bộ mà không chặn:**
```java
// Future — chặn ở mỗi bước
String url = future1.get();
String data = future2.get();
Result result = process(url, data);

// CompletableFuture — toàn bộ chuỗi bất đồng bộ
supplyAsync(() -> getUrl())
    .thenCompose(url -> fetchDataAsync(url))
    .thenApply(data -> processData(data))
    .thenAccept(result -> save(result));
```

**5. Hỗ trợ timeout:**
```java
// Java 9+
cf.orTimeout(5, TimeUnit.SECONDS);
cf.completeOnTimeout(defaultValue, 5, TimeUnit.SECONDS);
```

### Các Lỗi Thường Gặp

1. **Không dùng các phương thức async:**
```java
// ❌ Thực thi trong cùng thread
cf.thenApply(s -> s.toUpperCase());

// ✅ Thực thi bất đồng bộ
cf.thenApplyAsync(s -> s.toUpperCase(), executor);
```
// thenApply trong cùng thread KHÔNG phải là bug, đó là thiết kế có chủ ý.
// Dùng nó cho các biến đổi nhẹ. Đối với chặn — chỉ dùng *Async.

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Interface CompletionStage:**
```java
// CompletableFuture triển khai CompletionStage<T>
// CompletionStage cung cấp 40+ phương thức:
// - thenApply, thenAccept, thenRun
// - thenCombine, thenCompose
// - allOf, anyOf
// - exceptionally, handle, whenComplete

// Mỗi phương thức trả về một CompletionStage — có thể xây dựng chuỗi
```

**Thực thi không chặn:**
```java
// CompletableFuture dùng cách tiếp cận dựa trên callback
// Thay vì get() chặn — callback chạy khi hoàn thành

class CompletableFuture<T> {
    volatile Object result;
    volatile Completion stack;  // danh sách liên kết các callback

    // Khi hoàn thành — tất cả callback thực thi
    void completeValue(T t) {
        // CAS để thiết lập result
        // Sau đó tất cả callback đang chờ thực thi
    }
}
```

### Đánh Đổi Kiến Trúc

| Cách tiếp cận              | Ưu điểm                           | Nhược điểm             |
| --------------------- | ------------------------------ | ---------------- |
| **CompletableFuture** | Không chặn, có thể kết hợp       | Khó debug hơn  |
| **Future + get()**    | Đơn giản                         | Chặn         |
| **Reactive Streams**  | Backpressure, streaming        | Phức tạp hơn        |
| **Virtual Threads**   | Code đơn giản, không chặn      | Java 21+         |

### Edge Cases

**1. Bọc ngoại lệ:**
```java
// Ngoại lệ được bọc trong CompletionException
cf.thenApply(s -> {
    throw new RuntimeException("Original");
}).exceptionally(ex -> {
    // ex — CompletionException
    // ex.getCause() — ngoại lệ gốc
    return null;
});
```

**2. Hủy (Cancellation):**
```java
// CompletableFuture.cancel() không ngắt việc thực thi
cf.cancel(true);  // mayInterruptIfRunning bị bỏ qua

// Cần xử lý thủ công
cf.obtrudeValue(null);  // buộc hoàn thành
```

### Kinh Nghiệm Production

**Giao tiếp Microservice:**
```java
@Service
public class OrderService {
    private final UserService userService;
    private final InventoryService inventoryService;
    private final PaymentService paymentService;

    public CompletableFuture<Order> createOrder(CreateOrderRequest req) {
        return userService.validateUserAsync(req.userId())
            .thenCompose(user ->
                inventoryService.checkStockAsync(req.items())
                    .thenCompose(stock ->
                        paymentService.processPaymentAsync(req.payment())
                            .thenApply(payment ->
                                new Order(user, stock, payment)
                            )
                    )
            )
            .exceptionally(ex -> {
                log.error("Order creation failed", ex);
                throw new OrderCreationException(ex);
            });
    }
}
```

### Best Practices

```java
// ✅ Chuỗi thay vì chặn
cf.thenApply(...).thenAccept(...);

// ✅ Xử lý lỗi
cf.exceptionally(ex -> defaultValue);

// ✅ Executor tùy chỉnh cho I/O
CompletableFuture.supplyAsync(task, ioExecutor);

// ✅ Kết hợp
cf1.thenCombine(cf2, (a, b) -> combine(a, b));

// ❌ get() chặn mà không có lý do
// ❌ Bỏ qua ngoại lệ
// ❌ commonPool cho thao tác I/O
```

### Khi Nào KHÔNG Nên Dùng CompletableFuture

- **Fire-and-forget đơn giản** — `executor.submit()` là đủ
- **Virtual Threads (Java 21+)** — thường viết code đồng bộ đơn giản hơn
- **Luồng dữ liệu (Data streams)** — reactive (Flux/Mono) tốt hơn

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Kết hợp không chặn — chuỗi mà không chặn get()
- Kết hợp — thenCombine, allOf, anyOf cho các lời gọi song song
- Xử lý lỗi — exceptionally, handle, whenComplete
- Hoàn thành thủ công — complete(), completeExceptionally()
- 40+ phương thức CompletionStage cho mọi tình huống
- Hỗ trợ timeout — orTimeout(), completeOnTimeout() (Java 9+)

**Các câu hỏi phụ thường gặp:**
- **Ưu điểm chính so với Future?** — Kết hợp không chặn và xử lý lỗi mà không cần get()
- **Cách kết hợp hai CF?** — thenCombine(cf2, combiner) cho song song, thenCompose cho phụ thuộc
- **Khi nào KHÔNG nên dùng?** — Fire-and-forget đơn giản, Virtual Threads (Java 21+), luồng dữ liệu (Reactor tốt hơn)
- **Cách tránh chặn?** — Chuỗi thenApply/thenAccept thay vì get()/join()

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Future và CompletableFuture có thể thay thế cho nhau" — Future không có chuỗi hoặc xử lý lỗi
- "thenCompose và thenCombine giống nhau" — thenCompose là tuần tự, thenCombine là song song
- "Tôi luôn dùng commonPool" — đối với I/O đây là thread pool starvation

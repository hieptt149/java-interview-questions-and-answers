## 🔗 Các Kết Nối Chủ Đề Chính

### Chủ Đề: Kafka Cơ Bản

```
Q1 (Topic) → Q2 (Partition) → Q3 (Phân phối) → Q4 (Key)
```

**Các kết nối chính:**
- Q2 ↔ Q16: Các partition được replicate để chịu lỗi
- Q3 ↔ Q20: acks=all ảnh hưởng đến khi nào một message được coi là đã delivered
- Q4 ↔ Q3: Key quyết định partition qua MurmurHash

### Chủ Đề: Consumer Group

```
Q5 (Consumer Group) → Q6 (Cân bằng) → Q7 (Nhiều consumer hơn)
     ↓
Q8 (Thêm consumer) → Q15 (Rebalancing)
```

**Các kết nối chính:**
- Q5 ↔ Q12: Mỗi consumer commit offset cho mỗi partition
- Q6 ↔ Q15: Cân bằng chính là rebalance
- Q7 ↔ Q8: Các consumer nhàn rỗi lãng phí tài nguyên, thêm một cái mới kích hoạt rebalance

### Chủ Đề: Offset Và Delivery

```
Q12 (Offset) → Q13 (Commit) → Q14 (Auto vs Manual)
     ↓
Q9 (Đảm bảo) → Q10 (At-most/at-least/exactly) → Q11 (Cấu hình exactly-once)
```

**Các kết nối chính:**
- Q13 ↔ Q9: Commit TRƯỚC khi xử lý = at-most-once, SAU = at-least-once
- Q14 ↔ Q13: Auto commit = đơn giản hơn nhưng rủi ro mất mát; Manual = kiểm soát
- Q10 ↔ Q11: Exactly-once yêu cầu producer transactional

### Chủ Đề: Producer

```
Q20 (acks) → Q21 (Batch) → Q22 (Compression) → Q23 (Idempotent)
```

**Các kết nối chính:**
- Q20 ↔ Q23: Idempotent producer + acks=all = delivery exactly-once đến topic
- Q21 ↔ Q22: Batch + compression = throughput tối đa
- Q23 ↔ Q11: Idempotent producer — nền tảng của exactly-once

### Chủ Đề: Fault Tolerance

```
Q16 (Replication) → Q17 (Leader/Follower) → Q18 (ISR) → Q19 (Fault tolerance)
```

**Các kết nối chính:**
- Q17 ↔ Q18: Leader luôn nằm trong ISR, các follower bị loại nếu tụt hậu
- Q18 ↔ Q19: ISR shrink → giảm khả năng chịu lỗi
- Q16 ↔ Q20: acks=all chờ acknowledgment từ tất cả các replica ISR

### Chủ Đề: Vận Hành

```
Q24 (Xử lý lỗi) → Q25 (DLQ) → Q26 (Giám sát lag)
```

## 🎓 Tóm Tắt: Cần Biết Gì Cho Mỗi Cấp Độ

### 🟢 Junior
- Topic = kênh logic, partition = kênh con để song song hóa
- Consumer Group = cơ chế để phân phối các partition giữa các consumer
- Offset = vị trí trong partition, commit = lưu vị trí
- acks=0 (fire-and-forget), acks=1 (chỉ leader), acks=all (tất cả ISR)
- At-most-once, at-least-once, exactly-once — ba ngữ nghĩa delivery

### 🟡 Middle
- Rebalancing: eager (dừng hoàn toàn) vs cooperative (một phần)
- ISR: các replica đã bắt kịp leader. Leader luôn nằm trong ISR
- Batch: batch.size, linger.ms, compression — ba đòn bẩy throughput
- DLQ: hàng đợi cho các message không thể xử lý sau N lần retry
- Retention: retention.ms (thời gian) + retention.bytes (kích thước mỗi partition)
- Sticky partitioning: Kafka 2.4+ thay thế round-robin

### 🔴 Senior
- Exactly-once: EOS v2 (Kafka 2.5+), Producer ID + Epoch, transaction coordinator
- Idempotent producer: deduplication ở cấp broker qua PID + sequence
- ISR shrink/expand: giám sát rất quan trọng cho khả năng chịu lỗi
- Cascading rebalancing: GC pause → loại trừ → rebalance → quá tải → một cái khác lại lỗi
- Outbox pattern: cho exactly-once Kafka-đến-Database
- Leader Epoch: theo dõi mất dữ liệu trong quá trình failover

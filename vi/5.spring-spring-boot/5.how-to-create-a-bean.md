# How to Create a Bean in Spring? (Cách tạo một Bean trong Spring?)

## Junior Level

**Các cách tạo một bean:**

**1. Annotation (phổ biến nhất):**
```java
@Service
public class UserService { }

@Component
public class EmailSender { }
```

**2. @Bean trong configuration:**
```java
@Configuration
public class Config {
    @Bean
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}
```

**Quy tắc:**
- Code của bạn -> `@Service`, `@Component`
- Class bên thứ ba -> `@Bean`

---

## Middle Level

### Các annotation stereotype

```java
@Component        // Component chung
@Service          // Logic nghiệp vụ
@Repository       // Truy cập database (tự động dịch exception)
@Controller       // Web controller
@RestController   // REST API (@Controller + @ResponseBody)
```

**Cách hoạt động:**
```
@ComponentScan -> quét các package
  -> Tìm thấy @Component
  -> Tạo BeanDefinition
  -> Đăng ký vào context
```

### Java Config (@Bean)

```java
@Configuration
public class InfrastructureConfig {

    @Bean
    @Primary  // Bean chính nếu có nhiều bean
    public ObjectMapper mapper() {
        ObjectMapper mapper = new ObjectMapper();
        mapper.findAndRegisterModules();
        return mapper;
    }

    @Bean(initMethod = "init", destroyMethod = "close")
    public DataSource dataSource() {
        return new HikariDataSource();
    }
}
```

### FactoryBean

```java
// Cho logic tạo phức tạp
public class MyFactoryBean implements FactoryBean<MyService> {
    public MyService getObject() { return new MyService(); }
    public Class<?> getObjectType() { return MyService.class; }
}

// Spring sẽ gọi getObject() và đăng ký kết quả
```

## Senior Level

### CGLIB Proxy hóa @Configuration

```java
@Configuration
public class Config {
    @Bean
    public A a() { return new A(); }

    @Bean
    public B b() {
        return new B(a());  // Gọi phương thức a()!
    }
}

// Spring proxy Config qua CGLIB:
// -> Lần gọi a() đầu tiên -> tạo bean, cache lại
// -> Lần gọi a() thứ hai -> trả về từ cache!
// -> Luôn là một instance (Singleton)
```

### Đăng ký theo lối lập trình (Spring 5+)

```java
// Không dùng reflection và quét annotation -> khởi động nhanh hơn.
// Spring Boot dùng cách này cho GraalVM Native Image, nơi reflection bị hạn chế.
context.registerBean(MyService.class, () -> new MyService());

// Với GraalVM Native Image -> reflection bị hạn chế
// Đăng ký theo lối lập trình được ưu tiên
```

### ImportSelector / ImportBeanDefinitionRegistrar

```java
// ImportSelector - một interface cho phép import động các class bean theo điều kiện. Đây là cách mọi annotation @Enable... hoạt động (ví dụ @EnableCaching, @EnableScheduling).

// ASM - thư viện để đọc bytecode của class mà không nạp chúng vào JVM. Spring dùng nó trong lúc @ComponentScan để tìm các annotation.

// Đây là cách mọi annotation @Enable... hoạt động
public class MyImportSelector implements ImportSelector {
    public String[] selectImports(AnnotationMetadata metadata) {
        return new String[] { "com.example.Service1", "com.example.Service2" };
    }
}

// Cách dùng:
@Import(MyImportSelector.class)
public @interface EnableMyFeature { }
// Bây giờ @EnableMyFeature import Service1 và Service2

@EnableMyFeature  // -> Import Service1 và Service2
```

### Quét: Thư viện ASM

```
ClassPathBeanDefinitionScanner:
  -> Đọc bytecode qua ASM
  -> KHÔNG nạp class vào JVM!
  -> Tìm kiếm các annotation
  -> Tạo BeanDefinition

-> Trên các dự án lớn -> khởi động chậm
-> Hạn chế @ComponentScan vào các package cụ thể
```

### Khi nào KHÔNG dùng @Bean

1. **Đối tượng dữ liệu đơn giản** — DTO, Entity — tạo bằng `new` hoặc bởi ORM
2. **Quá nhiều bean** — mỗi bean = overhead lúc khởi động. Với 1000+ bean, cân nhắc khởi tạo lazy
3. **FactoryBean** — chỉ cần khi logic tạo phức tạp và phụ thuộc vào các điều kiện bên ngoài (ví dụ EntityManagerFactory)

### Kinh nghiệm Production

**Tình huống thực tế: khởi động chậm**
- 10.000 class trong classpath
- Quét: 15 giây
- Giải pháp: giới hạn @ComponentScan("com.myapp")
- Kết quả: khởi động 2 giây

### Best Practices

1. **@Service/@Component** -> code của bạn
2. **@Bean** -> thư viện bên thứ ba
3. **Giới hạn phạm vi quét** -> các package cụ thể
4. **@Primary** -> nếu có nhiều bean cùng kiểu
5. **Đăng ký theo lối hàm (functional)** -> GraalVM Native
6. **@Configuration được proxy** -> lời gọi phương thức = cache

### Tóm tắt cho Senior

- **@Component** -> quét qua ASM
- **@Bean** -> Java Config, CGLIB proxy
- **FactoryBean** -> logic tạo phức tạp
- **registerBean** -> theo lối lập trình, GraalVM
- **ImportSelector** -> các annotation @Enable...
- **Giới hạn phạm vi quét** -> khởi động nhanh hơn

## Interview Cheat Sheet

**Cần phải biết:**
- Code của bạn -> `@Service`, `@Component`, `@Repository`, `@Controller` (quét tự động)
- Thư viện bên thứ ba -> `@Bean` trong `@Configuration` (cấu hình thủ công)
- `@ComponentScan` quét các package qua ASM (đọc bytecode mà không nạp class)
- `@Configuration` được proxy qua CGLIB: các lời gọi phương thức lặp lại trả về Singleton từ cache
- `@Primary` — bean chính nếu có nhiều bean cùng kiểu
- `FactoryBean` — cho logic tạo phức tạp (Spring gọi `getObject()`)
- Đăng ký theo lối lập trình `registerBean()` — GraalVM Native Image, không reflection
- `ImportSelector` — import bean động, đây là cách mọi annotation `@Enable...` hoạt động

**Các câu hỏi phụ thường gặp:**
- **Tại sao gọi `a()` bên trong `@Configuration` lại trả về cùng một bean?** CGLIB proxy chặn lời gọi và trả về Singleton từ cache.
- **Tại sao phải giới hạn `@ComponentScan`?** Trên các dự án lớn, quét hàng nghìn class làm chậm khởi động (15 giây -> 2 giây).
- **Khi nào dùng `FactoryBean`?** Khi việc tạo phụ thuộc vào các điều kiện bên ngoài (ví dụ EntityManagerFactory).
- **ImportSelector là gì?** Một interface để import động các class bean — nền tảng của mọi annotation `@Enable...`.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Có thể khai báo `@Bean` cho DTO/Entity" (đây là các đối tượng dữ liệu thông thường, không phải bean)
- "`@ComponentScan` càng rộng càng tốt — Spring sẽ tìm ra hết" (khởi động chậm trên các dự án lớn)
- "Các phương thức `@Configuration` được gọi trực tiếp" (CGLIB proxy chặn và cache)
- "FactoryBean và `@Bean` là như nhau" (FactoryBean là một interface với logic tạo phức tạp, `@Bean` là một phương thức đơn giản)

# What is API Gateway and what problems does it solve (API Gateway là gì và nó giải quyết những vấn đề gì)

## Junior Level

**API Gateway** là **điểm vào duy nhất** cho một hệ thống microservice. Tất cả các request từ client đi qua nó.

```
Client -> API Gateway -> Service A
                      -> Service B
                      -> Service C
```

**Trách nhiệm của API Gateway:**
1. **Routing** — chuyển hướng request đến đúng service
2. **Authentication** — xác minh token một lần
3. **Rate limiting** — giới hạn request (Rate Limiting — hạn chế số lượng request từ một client)
4. **Logging** — ghi log tất cả request
5. **CORS** — xử lý các request cross-origin (CORS — Cross-Origin Resource Sharing, một cơ chế bảo mật của trình duyệt)

## Middle Level

### Khi Nào KHÔNG Nên Dùng API Gateway

- **Các microservice nội bộ** không đối diện client bên ngoài
- **2-3 service** — gọi trực tiếp đơn giản hơn
- **Hệ thống nhạy cảm với độ trễ** — hop thêm gây ra delay

### Các Chức Năng Của API Gateway

```
1. Routing request: /api/users -> User Service
                    /api/orders -> Order Service

2. Authentication: xác minh JWT token

3. Rate limiting: 100 request mỗi phút mỗi client

4. Caching: cache response

5. Chuyển đổi response: chuyển đổi định dạng

6. Aggregation request: thu thập dữ liệu từ nhiều service
```

### Các Ví Dụ

- **Spring Cloud Gateway**
- **Kong**
- **Nginx**
- **AWS API Gateway**
- **Zuul (Netflix)**

### Các Lỗi Thường Gặp

1. **Gateway bottleneck:**
```
Tất cả request qua một Gateway -> một thread duy nhất
Giải pháp: horizontal scaling cho Gateway
```

## Senior Level

### Đánh Đổi Kiến Trúc

| Gateway                                                                                     | BFF (Backend for Frontend) |
| ------------------------------------------------------------------------------------------- | -------------------------- |
| Một Gateway đơn giản hơn để vận hành (một thành phần để giám sát).                                | Riêng biệt cho mỗi client   |
| BFF linh hoạt hơn: mỗi client (web, mobile, API) nhận endpoint được tối ưu riêng.       | Nhiều hạ tầng hơn         |

### Kinh Nghiệm Production

**Spring Cloud Gateway:**
```java
@Bean
public RouteLocator routes(RouteLocatorBuilder builder) {
    return builder.routes()
        .route("user-service", r -> r
            .path("/api/users/**")
            .filters(f -> f
                .circuitBreaker(config -> config
                    .setName("userCircuitBreaker"))
                .requestRateLimiter(config -> config
                    .setRateLimiter(redisRateLimiter)))
            .uri("lb://user-service"))
        .route("order-service", r -> r
            .path("/api/orders/**")
            .uri("lb://order-service"))
        .build();
}
```
// Khi circuit breaker open — client thấy 503 Service Unavailable
// (hoặc một response đã cache, nếu được cấu hình).

### Best Practices

```
✅ Gateway không có business logic
✅ Circuit breaker trên Gateway
✅ Rate limiting
✅ Monitoring và logging
✅ Health check

❌ Business logic trong Gateway
❌ Chỉ một instance Gateway duy nhất
❌ Không có rate limiting
```

## Interview Cheat Sheet

**Cần phải biết:**
- API Gateway — điểm vào duy nhất, route request đến các microservice
- Trách nhiệm: routing, authentication, rate limiting, logging, CORS
- Gateway KHÔNG nên chứa business logic
- Circuit breaker trên Gateway bảo vệ khỏi cascade failure
- BFF (Backend for Frontend) — Gateway riêng cho mỗi client (web, mobile)
- Horizontal scaling cho Gateway là bắt buộc (không phải một instance duy nhất)
- Phổ biến: Spring Cloud Gateway, Kong, Nginx, AWS API Gateway

**Các câu hỏi phụ thường gặp:**
- **Khi nào KHÔNG dùng Gateway?** Các service nội bộ, 2-3 service, hệ thống nhạy cảm với độ trễ.
- **Gateway vs BFF?** Gateway — một cho tất cả, BFF — riêng biệt cho mỗi client, linh hoạt hơn nhưng nhiều hạ tầng hơn.
- **Cách scale Gateway?** Theo chiều ngang + load balancer phía trước.
- **Điều gì nếu Gateway sập?** Toàn bộ hệ thống không khả dụng — cần deployment HA.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Gateway là nơi tốt nhất cho business logic" — không, chỉ routing và các mối quan tâm xuyên suốt
- "Một instance Gateway là đủ" — đây là một single point of failure
- "Không cần rate limiting" — bảo vệ khỏi abuse là bắt buộc
- "Gateway thêm độ trễ không đáng kể" — nó thêm một hop, quan trọng cho hệ thống nhạy cảm với độ trễ

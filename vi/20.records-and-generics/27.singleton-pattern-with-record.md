# How to Implement Singleton Pattern with Record? (Cách triển khai pattern Singleton với Record)

## 🟢 Junior Level

**Record là một lựa chọn tuyệt vời cho Singleton!** Từ **Java 21** (JEP 445), Record hỗ trợ serialization nâng cao, làm cho chúng lý tưởng cho Singleton.

Nhưng cách đơn giản nhất là **Enum Singleton**, và Record có thể được dùng với một **compact constructor**.

```java
// Cách tiếp cận 1: Record với trường static final
public record Config(String databaseUrl, int maxConnections) {
    public static final Config INSTANCE =
        new Config("jdbc:postgresql://localhost:5432/mydb", 10);
}

// Sử dụng
Config config = Config.INSTANCE;
```

**Tại sao Record tốt cho Singleton:**
- ✅ Tự động bất biến
- ✅ Serialization an toàn (Java 21+)
- ✅ Không có vấn đề tấn công reflection
- ✅ Code tối thiểu

## 🟡 Middle Level

### Các Cách Tiếp Cận Triển Khai

**1. Trường static trong Record:**
```java
public record Logger(String name, LogLevel level) {
    public static final Logger INSTANCE = new Logger("App", LogLevel.INFO);

    public void log(String message) {
        System.out.println("[" + name + "] " + message);
    }
}

// Sử dụng
Logger.INSTANCE.log("Hello");
```

**2. Phương thức factory static:**
```java
public record DatabaseConnection(String url) {
    private static final DatabaseConnection INSTANCE =
        new DatabaseConnection("jdbc:postgresql://localhost:5432/db");

    public static DatabaseConnection getInstance() {
        return INSTANCE;
    }

    public void execute(String sql) {
        // thực thi query
    }
}

// Sử dụng
DatabaseConnection.getInstance().execute("SELECT 1");
```

**3. Enum Singleton (kinh điển, Joshua Bloch):**
```java
public enum Config {
    INSTANCE;

    private final String databaseUrl;
    private final int maxConnections;

    Config() {
        this.databaseUrl = "jdbc:postgresql://localhost:5432/db";
        this.maxConnections = 10;
    }

    public String getDatabaseUrl() { return databaseUrl; }
    public int getMaxConnections() { return maxConnections; }
}
```

### Các Lỗi Thường Gặp

1. **Cố gắng tạo Singleton mutable:**
```java
public record Config(String url) {
    // ❌ Không thể — Record là bất biến
    public void setUrl(String url) { }  // lỗi
}
```

2. **Nhiều instance:**
```java
public record Config(String url) {
    // ⚠️ Có thể tạo một instance mới!
    // new Config("other-url") — vẫn có thể
}

// ✅ Giải pháp — constructor private
public record Config(String url) {
    private static final Config INSTANCE = new Config("default");

    private Config { }  // compact constructor private

    public static Config getInstance() {
        return INSTANCE;
    }
}
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Tại sao Enum tốt hơn Record cho Singleton:**
```java
// Enum đảm bảo tính duy nhất ở tầng JVM
// Record — không đảm bảo, có thể tạo instance mới

public enum EnumSingleton {
    INSTANCE;
    // JVM đảm bảo instance duy nhất
}

public record RecordSingleton(String value) {
    public static final RecordSingleton INSTANCE = new RecordSingleton("default");
    // Bạn có thể làm new RecordSingleton("other") — không có đảm bảo
}
```

**An toàn Serialization (Java 21+ JEP 445):**
```java
// Record dùng deserialization nâng cao
// Thông qua canonical constructor thay vì readObject

public record Config(String url) implements Serializable {
    private static final Config INSTANCE = new Config("default");

    // Deserialization gọi canonical constructor
    // Có thể kiểm soát thông qua validation
    public Config {
        // Validation trong quá trình deserialize
    }
}
```

### Đánh Đổi Kiến Trúc

**Enum vs Record vs Class Singleton:**

| Cách tiếp cận   | Đảm bảo       | Code    | Serialization        | Reflection       |
| ---------- | --------------- | ------- | -------------------- | ---------------- |
| **Enum**   | ✅ Đảm bảo JVM | Tối thiểu | ✅ An toàn               | ✅ Được bảo vệ      |
| **Record** | ❌ Không đảm bảo  | Tối thiểu | ✅ An toàn (Java 21+)    | ⚠️ Có thể tạo được    |
| **Class**  | ❌ Phải tự quản lý   | Nhiều    | ⚠️ Cần readResolve  | ⚠️ Phải tự bảo vệ  |

### Edge Cases

**1. Khởi tạo thread-safe:**
```java
public record Config(String url) {
    // Khởi tạo static thread-safe theo JLS
    private static final Config INSTANCE = new Config("default");

    // Khởi tạo lazy
    private static class Holder {
        static final Config INSTANCE = new Config("default");
    }

    public static Config getInstance() {
        return Holder.INSTANCE;
    }
}
```

**2. Singleton có tham số:**
```java
public record ServiceRegistry(Map<String, Service> services) {
    private static volatile ServiceRegistry INSTANCE;

    public static synchronized ServiceRegistry getInstance() {
        if (INSTANCE == null) {
            INSTANCE = new ServiceRegistry(new ConcurrentHashMap<>());
        }
        return INSTANCE;
    }

    public void register(String name, Service service) {
        services.put(name, service);
    }
}
```

**3. Bảo vệ khỏi Reflection:**
```java
public record Config(String url) {
    private static final Config INSTANCE = new Config("default");

    private Config {
        // Kiểm tra này KHÔNG bảo vệ khỏi tấn công reflection.
        // Compact constructor chạy cho MỖI lần tạo, bao gồm cả INSTANCE.
        // Lần khởi tạo đầu tiên của INSTANCE vượt qua (INSTANCE vẫn là null).
        // Nhưng reflection có thể gọi constructor trực tiếp.
        // Bảo vệ đầy đủ cần một cờ boolean hoặc cách tiếp cận dựa trên Enum.
        if (INSTANCE != null) {
            throw new IllegalStateException("Singleton already created");
        }
    }

    public static Config getInstance() {
        return INSTANCE;
    }
}
```

### Hiệu Năng

```
Tạo Singleton:
- Trường static: 0 ns (thời gian tải class)
- Khởi tạo lazy: ~1 ns sau khi khởi tạo
- Double-checked locking: ~5 ns

Enum vs Record:
- Enum: đảm bảo JVM, nhanh hơn một chút
- Record: giống nhau, nhưng có thể tạo mới
```

### Kinh Nghiệm Production

**Singleton Cấu Hình:**
```java
public record AppConfig(
    String databaseUrl,
    int maxConnections,
    Duration timeout,
    Map<String, String> properties
) {
    private static final AppConfig INSTANCE;

    static {
        // Tải từ file/môi trường
        INSTANCE = loadFromEnvironment();
    }

    private static AppConfig loadFromEnvironment() {
        return new AppConfig(
            System.getenv("DB_URL"),
            Integer.parseInt(System.getenv("MAX_CONNECTIONS")),
            Duration.ofSeconds(30),
            Map.of()
        );
    }

    public static AppConfig getInstance() {
        return INSTANCE;
    }
}
```

**Best practices:**
```java
// ✅ Enum cho Singleton — thực hành tốt nhất
public enum DatabaseConnection {
    INSTANCE;
    private final Connection conn;

    DatabaseConnection() {
        this.conn = createConnection();
    }

    private Connection createConnection() { /* ... */ }
}

// ✅ Record cho cấu hình bất biến
public record Config(String url, int timeout) {
    public static final Config INSTANCE = new Config("default", 30);
}

// ❌ Record không có bảo vệ khỏi nhiều instance
// ❌ Class Singleton không có readResolve
// ❌ Khởi tạo lazy không đồng bộ hóa
```

### Khi Nào KHÔNG Nên Dùng Singleton

Singleton là một pattern gây tranh cãi: dependency ẩn, vấn đề về khả năng test,
trạng thái toàn cục, phức tạp về threading. Xem xét DI (Spring) như một lựa chọn thay thế.

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Enum — Singleton tốt nhất trong Java (Joshua Bloch): đảm bảo JVM về tính duy nhất
- Record có thể được dùng làm Singleton qua trường `static final INSTANCE`
- Record không đảm bảo tính duy nhất — bạn có thể tạo `new Config("other")`
- Compact constructor private KHÔNG bảo vệ hoàn toàn khỏi reflection
- Serialization nâng cao Java 21+ (JEP 445) làm cho serialization của Record an toàn
- Singleton là một anti-pattern: dependency ẩn, vấn đề về khả năng test, DI tốt hơn

**Các câu hỏi phụ thường gặp:**
- **Tại sao Enum tốt hơn Record cho Singleton?** — JVM đảm bảo instance duy nhất, được bảo vệ khỏi reflection
- **Có thể bảo vệ Record khỏi việc tạo instance mới không?** — Không hoàn toàn, constructor private không bảo vệ khỏi reflection
- **Cách tạo Singleton thread-safe với Record?** — Khởi tạo static final là thread-safe theo JLS (thời điểm tải class)
- **Khi nào KHÔNG nên dùng Singleton?** — Hầu như luôn luôn, DI (Spring, CDI) tốt hơn

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Record đảm bảo một instance duy nhất" — Không, bạn có thể tạo mới
- ❌ "Constructor private của Record bảo vệ khỏi reflection" — Không, reflection có thể bỏ qua nó
- ❌ "Singleton là thực hành tốt nhất" — Pattern gây tranh cãi, DI được ưu tiên hơn
- ❌ "Record Singleton an toàn cho serialization" — Chỉ Java 21+ với JEP 445

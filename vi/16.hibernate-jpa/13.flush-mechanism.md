# How Does the Flush Mechanism Work in Hibernate (Cơ chế flush hoạt động như thế nào trong Hibernate)

## Overview

Flush là quá trình đồng bộ hóa dữ liệu từ persistence context (cache Hibernate) vào database. Hiểu về cơ chế flush là quan trọng để quản lý transaction và tối ưu hiệu năng.

---

## Junior Level

### Flush Là Gì

Flush là quá trình ghi tất cả các thay đổi từ bộ nhớ (persistence context) vào database.

```java
User user = entityManager.find(User.class, 1L);
user.setName("New Name");  // đã thay đổi trong bộ nhớ

// Flush chưa xảy ra - DB CHƯA cập nhật!

entityManager.flush();  // flush rõ ràng - UPDATE thực thi trong DB
// hoặc
// Khi commit - flush tự động
```

### Khi Nào Flush Xảy Ra

1. **Khi transaction `commit`** - tự động
2. **Khi `entityManager.flush()`** - rõ ràng
3. **Trước khi thực thi một truy vấn** - để trả về dữ liệu thực tế

```java
@Transactional
public void updateUser() {
    User user = entityManager.find(User.class, 1L);
    user.setName("New");

    // flush chưa xảy ra
    // DB vẫn chứa name cũ

    // Khi thoát phương thức -> @Transactional commit -> flush
}
```

### Ví Dụ Flush Thủ Công

```java
@Transactional
public void batchInsert(List<User> users) {
    for (int i = 0; i < users.size(); i++) {
        entityManager.persist(users.get(i));

        if (i % 50 == 0) {
            entityManager.flush();  // flush vào DB
            entityManager.clear();  // xóa cache
        }
    }
}
```

## Middle Level

### FlushMode

```java
// AUTO (mặc định) - flush khi cần thiết
entityManager.setFlushMode(FlushModeType.AUTO);

// COMMIT - chỉ flush khi commit
entityManager.setFlushMode(FlushModeType.COMMIT);

// ALWAYS - trước mỗi truy vấn (hiếm khi dùng)
entityManager.setFlushMode(FlushModeType.ALWAYS);
// (Lưu ý: FlushModeType.ALWAYS đã bị deprecated trong Hibernate 5 và bị loại bỏ trong Hibernate 6. Trong các phiên bản hiện đại, hãy dùng AUTO hoặc COMMIT.)
```

### FlushMode.AUTO vs COMMIT

```java
// AUTO - flush trước truy vấn
User user = entityManager.find(User.class, 1L);
user.setName("New");

// Trước truy vấn này - flush (để trả về dữ liệu thực tế)
List<User> users = entityManager.createQuery("FROM User", User.class)
    .getResultList();  // bao gồm user "New"

// COMMIT - chỉ flush khi commit
entityManager.setFlushMode(FlushModeType.COMMIT);
user.setName("New");

// Truy vấn này sẽ KHÔNG thấy user "New" (flush chưa xảy ra)
List<User> users = entityManager.createQuery("FROM User", User.class)
    .getResultList();  // KHÔNG bao gồm user "New"
```

### Flush Thủ Công Cho Các Thao Tác Batch

```java
@Transactional
public void batchUpdate(List<User> users) {
    for (int i = 0; i < users.size(); i++) {
        entityManager.merge(users.get(i));

        if (i % 50 == 0) {
            entityManager.flush();  // flush 50 UPDATE vào DB
            entityManager.clear();  // xóa persistence context
        }
    }
    // Flush cuối cùng cho phần còn lại
    entityManager.flush();
    entityManager.clear();
}
```

### Các Lỗi Thường Gặp

```java
// Flush thường xuyên - chậm
for (User user : users) {
    entityManager.persist(user);
    entityManager.flush();  // mỗi lần - rất chậm!
}

// Flush định kỳ
for (int i = 0; i < users.size(); i++) {
    entityManager.persist(users.get(i));
    if (i % 50 == 0) {
        entityManager.flush();
        entityManager.clear();
    }
}
```

## Senior Level

### Triển Khai Nội Bộ

```
Quy trình flush:

1. Dirty checking
   - Duyệt qua tất cả entity trong persistence context
   - So sánh snapshot với trạng thái hiện tại
   - Với những cái thay đổi - lên lịch UPDATE

2. Thứ tự tạo
   - INSERT trước (để lấy ID)
   - UPDATE tiếp theo
   - DELETE cuối cùng (để tránh vi phạm FK)

3. Tạo SQL
   - Với mỗi thao tác đã lên lịch
   - Tạo SQL có tính đến các trường dirty

4. Thực thi
   - Thực thi SQL trong DB (JDBC batch)
   - Cập nhật snapshot

5. Post-flush
   - Cập nhật trạng thái EntityEntry
   - Reset các cờ dirty
```

### Thứ Tự Các Thao Tác

```
Khi flush, Hibernate tuân theo thứ tự này:

1. Tất cả các INSERT entity (theo thứ tự persist())
2. Tất cả các UPDATE entity (theo thứ tự phát hiện dirty)
3. Tất cả các UPDATE collection (cho các thay đổi collection)
4. Tất cả các DELETE collection (cho các phần tử bị loại bỏ)
5. Tất cả các DELETE entity (theo thứ tự remove())

Điều này quan trọng cho:
- Ràng buộc khóa ngoại
- Tính toàn vẹn tham chiếu
- Sinh identity

Thứ tự này quan trọng vì các ràng buộc khóa ngoại. Nếu Hibernate
cố INSERT một child trước khi INSERT parent, DB sẽ ném lỗi vi phạm FK.
Tương tự - DELETE parent trước DELETE child.
```

### Cài Đặt Nâng Cao

```yaml
spring:
  jpa:
    properties:
      hibernate:
        # Thứ tự flush cho các thao tác khác nhau
        order_inserts: true       # nhóm các INSERT
        order_updates: true       # nhóm các UPDATE
        order_deletes: true       # nhóm các DELETE

        # Kích thước batch JDBC
        jdbc.batch_size: 50
```

### Flush Và Transaction

```java
// @Transactional định nghĩa ranh giới flush
@Transactional
public void method1() {
    user.setName("A");
    // flush khi commit
}

@Transactional
public void method2() {
    user.setName("B");
    entityManager.flush();  // flush rõ ràng
    // một flush khác khi commit (nếu có thay đổi)
}
```

### Best Practices

```
Chế độ flush AUTO theo mặc định
Flush thủ công cho các thao tác batch
flush + clear mỗi 50-100 entity
Chế độ COMMIT khi không cần dữ liệu thực tế
order_inserts/order_updates để tối ưu

Chế độ ALWAYS (tránh)
Flush mà không có lý do
Không có clear sau flush trong batch
Bỏ qua thứ tự các thao tác
```

## Interview Cheat Sheet

**Cần phải biết:**
- Flush - đồng bộ hóa dữ liệu từ persistence context vào DB
- Xảy ra khi: commit, entityManager.flush(), trước truy vấn (chế độ AUTO)
- FlushMode: AUTO (mặc định), COMMIT (chỉ khi commit), ALWAYS (deprecated)
- Thứ tự thao tác: INSERT -> UPDATE -> DELETE (cho ràng buộc FK)
- Cho batch: flush + clear mỗi 50-100 entity
- order_inserts/order_updates - nhóm SQL để tối ưu

**Các câu hỏi phụ thường gặp:**
- **AUTO vs COMMIT?** AUTO - flush trước truy vấn (dữ liệu thực tế), COMMIT - chỉ khi commit
- **Tại sao thứ tự INSERT->UPDATE->DELETE quan trọng?** Ràng buộc khóa ngoại: không thể INSERT child trước khi INSERT parent
- **Tại sao flush thường xuyên chậm?** Mỗi flush = truy vấn SQL, 1000 entity x flush = 1000 SQL
- **JDBC batch_size là gì?** Nhóm các truy vấn SQL để gửi theo batch, giảm số lần round trip network

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Flush sau mỗi persist" - rất chậm, nên flush theo batch
- "Chế độ ALWAYS cho tất cả truy vấn" - deprecated, overhead lớn
- "Không có clear sau flush trong batch" - persistence context tăng, OOM
- "Tôi không hiểu thứ tự thao tác" - có thể gây vi phạm FK

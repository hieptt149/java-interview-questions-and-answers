# What is Comparable and Comparator? (Comparable và Comparator là gì?)

## 🟢 Junior Level

**Comparable** — bản thân đối tượng biết cách so sánh chính nó.
**Comparator** — một "trọng tài" bên ngoài so sánh hai đối tượng.

```java
// Comparable: bên trong class
class User implements Comparable<User> {
    String name;
    public int compareTo(User other) {
        return this.name.compareTo(other.name);  // Theo name
    }
}

// Comparator: một "trọng tài" riêng biệt
Comparator<User> byAge = (u1, u2) -> u1.age - u2.age;

// Cách dùng:
Collections.sort(users);       // Dùng compareTo
users.sort(byAge);             // Dùng Comparator
```

`Collections.sort(list)` — nhận một List và tùy chọn một Comparator. `list.sort(comparator)` — một phương thức default từ Java 8. Với ArrayList, cả hai đều giống hệt nhau. Hãy ưu tiên `list.sort()` — nó ngắn hơn.

## 🟡 Middle Level

### Comparable — thứ tự tự nhiên (natural ordering)

```java
// String, Integer, LocalDate implement Comparable
"apple".compareTo("banana");  // → âm
LocalDate.now().compareTo(LocalDate.MAX);  // → âm

// Chỉ MỘT thứ tự cho mỗi class
```

### Comparator — nhiều chiến lược

```java
// Java 8+: phong cách khai báo (declarative)
Comparator<User> comparator = Comparator
    .comparing(User::getLastName)           // Theo họ
    .thenComparing(User::getFirstName)      // Rồi theo tên
    .thenComparingInt(User::getAge)         // Rồi theo tuổi
    .reversed();                            // Theo thứ tự đảo ngược

// Xử lý null
Comparator<User> safe = Comparator
    .comparing(User::getName, Comparator.nullsLast(String::compareTo));
```

### Sự nguy hiểm của phép trừ

```java
// ❌ Tràn số (overflow)!
return o1.id - o2.id;  // Có thể vượt quá giới hạn của int!

// ✅ Đúng:
return Integer.compare(o1.id, o2.id);
return Long.compare(o1.id, o2.id);
```

Ví dụ: o1.id = -2_000_000_000, o2.id = 2_000_000_000. Kết quả: -2_000_000_000 - 2_000_000_000 = -4_000_000_000 — nằm ngoài phạm vi int (tối đa 2_147_483_647). Kết quả trở thành một số dương, việc sắp xếp bị sai.

## 🔴 Senior Level

### Khi nào KHÔNG dùng Comparable

1. **Cần nhiều biến thể sắp xếp** của cùng một class — hãy dùng Comparator
2. **Class từ một thư viện bên thứ ba** (không thể sửa đổi) — hãy dùng Comparator
3. **Thứ tự phụ thuộc vào ngữ cảnh/locale** (sắp xếp chuỗi cho các ngôn ngữ khác nhau) — Comparator

### Tính nhất quán với equals

```java
// TreeSet/TreeMap dùng compareTo, KHÔNG phải equals!
// Nếu compareTo = 0 → phần tử đã tồn tại
// Ngay cả khi equals = false!

// KHUYẾN NGHỊ:
// (x.compareTo(y) == 0) == (x.equals(y))

// Nếu không nhất quán → mất dữ liệu trong TreeSet!
```

### compareTo so với compare

```java
// Comparable:
this.compareTo(other)  // "Tôi" so sánh với "một cái khác"

// Comparator:
compare(o1, o2)  // "trọng tài" so sánh hai cái
```

### Timsort

```java
// Collections.sort() = Timsort
// → Hybrid của Merge Sort + Insertion Sort
// → Ổn định (stable) (các phần tử bằng nhau giữ nguyên thứ tự)
// → O(n log n)
// → Yêu cầu tính bắc cầu (transitivity) của comparator!

// Vi phạm tính bắc cầu:
// A > B, B > C, nhưng A < C
// → IllegalArgumentException!
```

Timsort — thuật toán sắp xếp của Java. Ổn định (các phần tử bằng nhau giữ nguyên thứ tự ban đầu của chúng).
Tính bắc cầu (Transitivity) — nếu A > B và B > C, thì nhất thiết A > C. Vi phạm dẫn đến IllegalArgumentException.

### Kinh nghiệm Production

**Tình huống thực tế: tràn số**
```java
// Comparator cho ID kiểu long
return (int)(o1.id - o2.id);  // Ép kiểu (cast) sang int!
// → Với các ID lớn → sai dấu
// → Sắp xếp không đúng

// Giải pháp: Long.compare(o1.id, o2.id)
```

### Best Practices

1. **Comparable** = thứ tự tự nhiên (một cái cho mỗi class)
2. **Comparator** = nhiều chiến lược
3. **Comparator.comparing** → dễ đọc, an toàn
4. **Integer/Long.compare** → bảo vệ chống tràn số
5. **nullsFirst/nullsLast** → xử lý null
6. **compareTo = equals** cho TreeSet/TreeMap
7. **Tính bắc cầu** là bắt buộc!

### Tóm tắt cho Senior

- **Comparable** = bên trong, thứ tự tự nhiên
- **Comparator** = bên ngoài, nhiều chiến lược
- **comparing/thenComparing** → API khai báo
- **Tràn số** → Integer/Long.compare
- **compareTo so với equals** → cực kỳ quan trọng cho TreeSet
- **Timsort** → ổn định, yêu cầu tính bắc cầu

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `Comparable` — đối tượng tự so sánh chính nó (`compareTo`), một thứ tự cho mỗi class (natural ordering)
- `Comparator` — "trọng tài" bên ngoài (`compare`), nhiều chiến lược sắp xếp
- `Comparator.comparing().thenComparing().reversed()` — API khai báo Java 8+
- Phép trừ `o1.id - o2.id` thì nguy hiểm — tràn số int; hãy dùng `Integer.compare()`/`Long.compare()`
- `TreeSet`/`TreeMap` dùng `compareTo`, KHÔNG phải `equals` — không nhất quán = mất dữ liệu
- Timsort — sắp xếp ổn định O(n log n), yêu cầu tính bắc cầu của comparator
- `Comparator.nullsFirst()`/`nullsLast()` — xử lý null an toàn

**Các câu hỏi phụ thường gặp:**
- *Tại sao `o1.id - o2.id` nguy hiểm?* — Với các giá trị lớn, tràn số int: -2 tỷ - 2 tỷ = -4 tỷ (nằm ngoài giới hạn), kết quả có sai dấu.
- *Điều gì xảy ra nếu `compareTo` và `equals` không nhất quán trong TreeSet?* — `compareTo = 0` nghĩa là "phần tử đã tồn tại", ngay cả khi `equals = false` — dữ liệu bị mất.
- *Tính bắc cầu của comparator là gì?* — Nếu A > B và B > C, thì nhất thiết A > C. Vi phạm → `IllegalArgumentException` từ Timsort.
- *Khi nào KHÔNG dùng Comparable?* — Nhiều biến thể sắp xếp, class bên thứ ba (không thể sửa đổi), thứ tự phụ thuộc ngữ cảnh (locale).

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Comparator định nghĩa thứ tự tự nhiên của một class" — không, Comparable làm việc đó
- "Phép trừ là một cách an toàn để so sánh các số" — không, tràn số int phá vỡ việc sắp xếp
- "TreeSet dùng equals để so sánh" — không, TreeSet dùng `compareTo`
- "Bạn có thể vi phạm tính bắc cầu của comparator" — không, Timsort sẽ ném `IllegalArgumentException`

# What is the difference between Error and Exception? (Sự khác biệt giữa Error và Exception là gì?)

## Junior Level

### Khác biệt chính

Cả hai lớp đều kế thừa từ `Throwable`, nhưng chúng biểu thị các vấn đề khác nhau về bản chất:

**Error** - các vấn đề của JVM (không phải ứng dụng), thường không thể sửa được.

**Exception:** `AssertionError` về mặt kỹ thuật là một Error, nhưng phát sinh từ logic ứng dụng. Được dùng để kiểm tra bất biến (invariant), không phải các lỗi bên ngoài.
- Không nằm trong tầm kiểm soát của lập trình viên
- Đừng bắt trong code thông thường
- Ví dụ: `OutOfMemoryError`, `StackOverflowError`

**Exception** - các lỗi ứng dụng:
- Các lỗi được lường trước có thể được xử lý
- Cần được xử lý
- Ví dụ: `IOException`, `SQLException`

Đừng bắt Error trong code thông thường. Ngoại lệ: handler thread toàn cục (`setDefaultUncaughtExceptionHandler`), graceful shutdown, các cơ chế health-check.

### Trực quan

```
Throwable
  ├── Error        <- JVM bị hỏng
  └── Exception    <- Ứng dụng gặp phải một vấn đề
```

### Ví dụ

```java
// Error - ứng dụng bất lực
// java.lang.OutOfMemoryError: Java heap space
List<byte[]> memoryHog = new ArrayList<>();
while (true) memoryHog.add(new byte[1024 * 1024]);

// Exception - có thể xử lý
try {
    Files.readAllLines(Paths.get("missing.txt"));
} catch (IOException e) {
    System.out.println("File not found, using default");
}
```

### Nguyên tắc đơn giản

- **Error** - "JVM đã chết" -> để nó sập
- **Exception** - "có gì đó không ổn" - xử lý hoặc ghi log

## Middle Level

### OutOfMemoryError - các kiểu con

`OutOfMemoryError` có nhiều dạng khác nhau:

- **`Java heap space`** - heap đầy
- **`Metaspace`** - không còn bộ nhớ cho metadata (thường khi sinh class qua CGLIB)
- **`Unable to create new native thread`** - OS từ chối tạo thread mới

Ngay cả khi bạn bắt `OOM`, JVM vẫn có thể ở trạng thái không ổn định.

### NoClassDefFoundError so với ClassNotFoundException

Đây là một câu hỏi phỏng vấn kinh điển:

**`ClassNotFoundException` (Exception):**
- Bạn **một cách tường minh** yêu cầu nạp một class: `Class.forName("com.mysql.Driver")`
- Class không có trong classpath
- Có thể được xử lý

**`NoClassDefFoundError` (Error):**
- Class có mặt lúc biên dịch nhưng thiếu lúc runtime
- Hoặc việc nạp nó thất bại do một lỗi trong khối static
- Lỗi môi trường nghiêm trọng

// Nếu trong khối static của một class:
// static { int x = 1/0; }
// Ở lần nạp đầu tiên: ExceptionInInitializerError
// Ở các lần thử tiếp theo: NoClassDefFoundError (class chưa được khởi tạo)

### AssertionError

Kế thừa từ `Error`. Được ném bởi toán tử `assert` (với cờ `-ea`):

```java
assert x > 0 : "x must be positive"; // AssertionError nếu x <= 0
```

Dùng `assert` để kiểm tra các bất biến của thuật toán, **không phải** để validate đầu vào của API - hãy dùng `IllegalArgumentException` cho việc đó.

### StackOverflowError so với OutOfMemoryError

- StackOverflowError - stack cạn kiệt (đệ quy sâu). Sửa: tăng -Xss hoặc sửa đệ quy
- OutOfMemoryError - heap cạn kiệt (nhiều object). Sửa: tăng -Xmx hoặc sửa rò rỉ (leak)

## Senior Level

### Xử lý Error - tại sao đó là thực hành xấu

Ngay cả khi bạn đã bắt một `Error`, JVM vẫn có thể ở trạng thái không ổn định. Thao tác tiếp theo (kể cả ghi log) có thể gây ra một `Error` mới.

### Mẫu Fail Fast & Die

Trong các hệ thống Highload, khi gặp `Error` ứng dụng nên kết thúc nhanh:

```java
public static void main(String[] args) {
    Thread.setDefaultUncaughtExceptionHandler((thread, e) -> {
        if (e instanceof Error) {
            log.error("Fatal error in thread {}", thread.getName(), e);
            System.exit(1); // Chết để orchestrator có thể khởi động lại
        }
    });
}
```

Kubernetes hoặc một orchestrator khác sẽ khởi động lại một instance mới tinh.

### Cờ JVM cho OOM

```
-XX:OnOutOfMemoryError="kill -9 %p"
```

Đảm bảo tiến trình chết khi gặp `OutOfMemoryError`.

### StackOverflowError

`Error` thường gặp khi đệ quy vô hạn. Kích thước stack bị giới hạn bởi `-Xss`. Trong các cây phân cấp sâu hoặc các vòng lặp trong các entity Hibernate, có thể cần tăng nó lên.

```java
// Đệ quy vô hạn
public int factorial(int n) {
    return n * factorial(n); // StackOverflowError
}
```

### Ghi log Error

Nếu bạn bắt `Throwable` ở tầng cao nhất (`main` hoặc `UncaughtExceptionHandler`), hãy làm `System.exit(1)` sau khi ghi log để không để hệ thống ở "trạng thái zombie".

### Chẩn đoán

- **`javap -v`** - xem các thuộc tính của phương thức để hiểu cách xử lý exception
- **Thread Dump** - `jstack <pid>` hiển thị trạng thái của tất cả các thread khi treo
- **Heap Dump** - `jmap` giúp phân tích `OutOfMemoryError`
- **`-XX:+HeapDumpOnOutOfMemoryError`** - tự động heap dump khi gặp OOM

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `Error` - vấn đề của JVM (không thể sửa), `Exception` - lỗi ứng dụng (có thể xử lý)
- Error: `OutOfMemoryError`, `StackOverflowError`, `NoClassDefFoundError` - đừng bắt
- Exception chia thành checked và unchecked (RuntimeException)
- `NoClassDefFoundError` != `ClassNotFoundException`: cái đầu là Error (có lúc biên dịch, thiếu lúc runtime), cái sau là Exception (được nạp tường minh, không có trong classpath)
- `AssertionError` - về mặt kỹ thuật là Error, nhưng từ logic ứng dụng (kiểm tra bất biến)
- Fail Fast & Die: khi gặp Error - `System.exit(1)`, để orchestrator khởi động lại
- Cờ JVM `-XX:OnOutOfMemoryError="kill -9 %p"` đảm bảo chết khi gặp OOM
- `Thread.setDefaultUncaughtExceptionHandler` - bắt Error ở tầng cao nhất

**Các câu hỏi phụ thường gặp:**
- **Có thể bắt OutOfMemoryError không?** - Về mặt kỹ thuật thì có, nhưng JVM ở trạng thái không ổn định - thao tác tiếp theo sẽ thất bại
- **Khác biệt giữa StackOverflowError và OutOfMemoryError là gì?** - StackOverflowError - stack cạn kiệt (đệ quy), OOM - heap cạn kiệt (nhiều object)
- **Khi nào AssertionError là một Error, không phải Exception?** - Vì assert kiểm tra các bất biến của thuật toán, không phải các lỗi bên ngoài
- **Làm gì với Error trong production?** - Ghi log và `System.exit(1)`, Kubernetes sẽ khởi động lại pod

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi bắt Error và tiếp tục làm việc" - JVM không ổn định, việc đó vô nghĩa
- "NoClassDefFoundError và ClassNotFoundException giống nhau" - không, cái đầu là Error, cái sau là Exception
- "AssertionError được dùng để validate đầu vào" - IllegalArgumentException là để làm việc đó

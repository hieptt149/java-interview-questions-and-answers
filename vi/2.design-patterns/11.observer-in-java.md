# How is Observer Implemented in Java? (Observer được triển khai như thế nào trong Java?)

## Junior Level

**Observer** là một pattern trong đó một đối tượng (Subject) thông báo cho các đối tượng quan sát khác (Observer) về những thay đổi.

**Ví dụ minh họa đơn giản:** Việc đăng ký kênh YouTube. Khi tác giả đăng một video mới, tất cả người đăng ký (subscriber) sẽ nhận được thông báo.

**Ví dụ:**
```java
// Observer
interface NewsListener {
    void onNewVideo(String title);
}

// Subject (nhà xuất bản)
class YouTuber {
    private List<NewsListener> listeners = new ArrayList<>();

    public void subscribe(NewsListener listener) {
        listeners.add(listener);
    }

    public void unsubscribe(NewsListener listener) {
        listeners.remove(listener);
    }

    public void publishVideo(String title) {
        System.out.println("New video: " + title);
        // Thông báo cho tất cả người đăng ký
        for (NewsListener listener : listeners) {
            listener.onNewVideo(title);
        }
    }
}

// Cách sử dụng
YouTuber youtuber = new YouTuber();
youtuber.subscribe(title -> System.out.println("I'll watch: " + title));
youtuber.publishVideo("Java Tutorial");
```

**Nơi được sử dụng:**
- Các nút bấm và sự kiện UI
- Đăng ký nhận tin tức
- Các hệ thống reactive (phản ứng)

## Middle Level

> `java.util.Observable` và `java.util.Observer` đã bị deprecated (không dùng nữa) kể từ Java 9.
> Các giải pháp thay thế: `PropertyChangeListener`, Flow API (Java 9+), Spring Events.

### Java Bean PropertyChangeListener

```java
// Cách triển khai Observer có sẵn trong Java
public class Model {
    private final PropertyChangeSupport support = new PropertyChangeSupport(this);
    private String name;

    public void addPropertyChangeListener(PropertyChangeListener listener) {
        support.addPropertyChangeListener(listener);
    }

    public void setName(String name) {
        String old = this.name;
        this.name = name;
        support.firePropertyChange("name", old, name);  // Thông báo!
    }
}

// Cách sử dụng
Model model = new Model();
model.addPropertyChangeListener(evt ->
    System.out.println(evt.getPropertyName() + ": " + evt.getOldValue() + " -> " + evt.getNewValue())
);
model.setName("New Name");
```

### Observer dạng hàm (Java 8+)

```java
// Thay vì interface — dùng lambda
public class EventSource {
    private final List<Consumer<String>> listeners = new ArrayList<>();

    public void onEvent(Consumer<String> listener) {
        listeners.add(listener);
    }

    public void emit(String event) {
        listeners.forEach(listener -> listener.accept(event));
    }
}

// Cách sử dụng
EventSource source = new EventSource();
source.onEvent(e -> System.out.println("Listener 1: " + e));
source.onEvent(e -> System.out.println("Listener 2: " + e));
source.emit("Hello!");
```

### Các vấn đề thường gặp

1. **Exception trong một listener làm dừng tất cả các listener khác**
   ```java
   // Nếu một listener ném ra exception — những listener khác sẽ không nhận được thông báo
   for (NewsListener listener : listeners) {
       listener.onNewVideo(title);  // Exception -> vòng lặp bị dừng lại!
   }

   // Cô lập các listener
   for (NewsListener listener : listeners) {
       try {
           listener.onNewVideo(title);
       } catch (Exception e) {
           log.error("Listener failed", e);
           // Tiếp tục thông báo cho các listener khác
       }
   }
   ```

2. **ConcurrentModificationException**
   ```java
   // Listener tự loại bỏ chính nó trong lúc đang được thông báo
   for (NewsListener listener : listeners) {
       listener.onNewVideo(title);  // Bên trong: listeners.remove(this) -> Exception!
   }

   // Sao chép danh sách hoặc dùng CopyOnWriteArrayList
   private final List<NewsListener> listeners = new CopyOnWriteArrayList<>();
   ```

3. **Rò rỉ bộ nhớ (Memory leak)**
   ```java
   // Listener không được loại bỏ -> rò rỉ
   model.addPropertyChangeListener(listener);
   // Quên loại bỏ -> model giữ listener mãi mãi

   // Luôn luôn phải loại bỏ
   model.removePropertyChangeListener(listener);
   ```

## Senior Level

### Kiến trúc hướng sự kiện (Event-driven Architecture)

```java
// Spring Events — Observer phiên bản nâng cấp
@Component
public class OrderService {
    private final ApplicationEventPublisher publisher;

    public void createOrder(Order order) {
        // Lưu đơn hàng
        orderRepository.save(order);

        // Phát ra sự kiện (Publish event)
        publisher.publishEvent(new OrderCreatedEvent(order));
    }
}

// Listener
@Component
public class NotificationService {
    @EventListener
    public void onOrderCreated(OrderCreatedEvent event) {
        sendEmail(event.getOrder().getEmail());
    }
}

// Listener bất đồng bộ (Async)
@Component
public class AnalyticsService {
    @Async
    @EventListener
    public void onOrderCreated(OrderCreatedEvent event) {
        trackAnalytics(event.getOrder());  // Không chặn luồng chính!
    }
}
```

### Reactive Streams (Java 9+)

```java
// Flow API — cách triển khai Observer hiện đại
public class NewsPublisher implements Flow.Publisher<String> {
    private final List<Flow.Subscriber<String>> subscribers = new ArrayList<>();

    @Override
    public void subscribe(Flow.Subscriber<String> subscriber) {
        subscribers.add(subscriber);
        subscriber.onSubscribe(new Flow.Subscription() {
            public void request(long n) { /* backpressure */ }
            public void cancel() { subscribers.remove(subscriber); }
        });
    }

    public void publish(String news) {
        subscribers.forEach(s -> s.onNext(news));
    }
}
```

### An toàn với luồng (Thread Safety)

```java
// Các vấn đề đa luồng trong Observer
public class EventSource {
    // ArrayList không an toàn với luồng
    private List<Consumer<String>> listeners = new ArrayList<>();

    // CopyOnWriteArrayList cho trường hợp đọc thường xuyên, ghi hiếm khi
    private List<Consumer<String>> listeners = new CopyOnWriteArrayList<>();

    // Hoặc dùng synchronized
    public synchronized void addListener(Consumer<String> listener) {
        listeners.add(listener);
    }

    // AtomicReference cho listener kiểu singleton
    private final AtomicReference<Consumer<String>> listener = new AtomicReference<>();
}
```

### Observer dùng WeakReference

```java
// Ngăn ngừa rò rỉ thông qua tham chiếu yếu (weak reference)
public class WeakEventSource {
    private final List<WeakReference<Consumer<String>>> listeners = new ArrayList<>();

    public void addListener(Consumer<String> listener) {
        listeners.add(new WeakReference<>(listener));
    }

    public void emit(String event) {
        // Sao chép danh sách để tránh ConcurrentModificationException
        // nếu listener thêm một listener mới trong lúc đang notify
        new ArrayList<>(listeners).forEach(ref -> {
            Consumer<String> l = ref.get();
            if (l != null) l.accept(event);
        });
    }
}
```

### Kinh nghiệm Production

**Tình huống thực tế: Listener chặn (blocking) đã giết chết API**
- @EventListener đồng bộ (synchronous) gửi email
- Dịch vụ email chậm -> toàn bộ API bị đợi
- Giải pháp: dùng @Async cho listener
- Kết quả: API ổn định < 100ms

### Best Practices (Thực hành tốt nhất)

1. **Cô lập các listener** — try/catch bao quanh mỗi cái
2. **CopyOnWriteArrayList** để đảm bảo an toàn với luồng
3. **Loại bỏ các listener** khi hủy (destruction)
4. **@Async** cho các thao tác nặng
5. **WeakReference** để ngăn ngừa rò rỉ
6. **Backpressure** trong Reactive Streams
7. **Spring Events** cho các ứng dụng doanh nghiệp (enterprise)

### Tóm tắt cho Senior

- **Observer** = nền tảng của kiến trúc hướng sự kiện
- **Spring @EventListener** = cách triển khai sẵn sàng cho production
- **Reactive Streams** = backpressure + không chặn (non-blocking)
- **An toàn với luồng:** CopyOnWriteArrayList hoặc synchronized
- **Listener bất đồng bộ (Async)** không chặn publisher
- **WeakReference** ngăn ngừa rò rỉ
- **Cô lập** từng listener (try/catch)

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- java.util.Observable và Observer đã bị deprecated kể từ Java 9, các giải pháp thay thế: PropertyChangeListener, Flow API, Spring Events
- Spring @EventListener — Observer sẵn sàng cho production: đồng bộ (synchronous) và @Async cho các listener không chặn
- Flow API (Java 9+) — Reactive Streams có backpressure: Publisher, Subscriber, Subscription
- An toàn với luồng: CopyOnWriteArrayList cho trường hợp đọc thường xuyên/ghi hiếm khi, hoặc synchronized
- Exception trong một listener không được làm dừng những listener khác — dùng try/catch bao quanh mỗi cái
- Observer dùng WeakReference ngăn ngừa rò rỉ bộ nhớ khi quên loại bỏ
- ConcurrentModificationException khi loại bỏ listener trong lúc đang thông báo — giải quyết bằng cách sao chép danh sách

**Các câu hỏi phụ thường gặp:**
- **Tại sao Observable/Observer bị deprecated?** — Thiết kế đã lỗi thời, không hỗ trợ backpressure, mang tính đồng bộ
- **Spring Events giải quyết các vấn đề của Observer như thế nào?** — @EventListener + ApplicationEventPublisher, @Async cho các listener không chặn
- **Backpressure trong Reactive Streams là gì?** — Cơ chế cho phép subscriber kiểm soát tốc độ nhận dữ liệu
- **Làm sao để tránh rò rỉ bộ nhớ trong Observer?** — Luôn luôn loại bỏ listener, sử dụng WeakReference

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi dùng java.util.Observable" — đã bị deprecated kể từ Java 9
- "Listener không thể gây ra deadlock" — listener đồng bộ + lock = deadlock
- "Sửa đổi đồng thời không phải là vấn đề" — ConcurrentModificationException khi loại bỏ trong lúc notify
- "Tất cả các listener đều phải đồng bộ" — @Async cho các thao tác nặng (email, phân tích dữ liệu)

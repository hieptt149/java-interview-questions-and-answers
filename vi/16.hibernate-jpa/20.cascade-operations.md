# How Do Cascade Operations Work (Các thao tác Cascade hoạt động như thế nào)

## Overview

Cascading trong JPA là một cơ chế tự động truyền các thao tác thực hiện trên entity parent sang tất cả các entity con liên quan. Điều này cho phép quản lý toàn bộ object graph thông qua một lệnh gọi phương thức EntityManager duy nhất.

---

## Junior Level

### Cascade Là Gì

Cascade - tự động **truyền các thao tác** từ entity parent sang các entity liên quan.

```java
@Entity
public class Order {
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL)
    private List<OrderItem> items;
}

Order order = new Order();
OrderItem item = new OrderItem();
order.getItems().add(item);

entityManager.persist(order);  // persist cũng được gọi cho items!
```

### CascadeType

```java
CascadeType.ALL       - tất cả thao tác (persist, merge, remove, refresh, detach)
CascadeType.PERSIST   - chỉ persist
CascadeType.MERGE     - chỉ merge
CascadeType.REMOVE    - chỉ remove
CascadeType.REFRESH   - chỉ refresh
CascadeType.DETACH    - chỉ detach
```

### Ví Dụ

```java
@Entity
public class Order {
    @Id
    private Long id;

    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL)
    private List<OrderItem> items = new ArrayList<>();

    public void addItem(OrderItem item) {
        items.add(item);
        item.setOrder(this);
    }
}

// persist(order) -> persist cho tất cả items
Order order = new Order();
order.addItem(new OrderItem());
order.addItem(new OrderItem());
entityManager.persist(order);  // 3 INSERT: order + 2 item
```

## Middle Level

### Cascade vs orphanRemoval

```java
@OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
private List<OrderItem> items;

// Cascade - truyền các thao tác (persist, merge, remove)
// orphanRemoval - xóa các entity bị loại khỏi collection

order.getItems().remove(0);  // orphanRemoval xóa item khỏi DB!

// Không có orphanRemoval:
// order.getItems().remove(0) -> item vẫn còn trong DB (orphan)

// Khác biệt chính: CascadeType.REMOVE chỉ kích hoạt khi parent bị xóa.
// orphanRemoval cũng kích hoạt khi child bị loại khỏi collection
// (order.getItems().remove(item)), ngay cả khi parent không bị xóa.
```

### Khuyến Nghị Sử Dụng

```
@OneToMany (composite):  CascadeType.ALL + orphanRemoval = true
@ManyToOne:              CascadeType.PERSIST, MERGE (hoặc không có cascade)
@OneToOne:               CascadeType.ALL
@ManyToMany:             CascadeType.PERSIST, MERGE
```

### Các Lỗi Thường Gặp

```java
// Cascade.ALL cho @ManyToOne
@ManyToOne(cascade = CascadeType.ALL)
private User user;

// Khi Order bị xóa -> User bị xóa!
entityManager.remove(order);  // cascade.REMOVE -> User bị xóa

// Không có cascade cho các entity dùng chung
@ManyToOne
private User user;  // User được quản lý riêng biệt
```

### JPA Cascade vs DB Cascade

```
JPA Cascading:
- Được thực thi bởi code Hibernate
- Hibernate phải biết về tất cả object trong bộ nhớ
- Tiện lợi cho logic hướng đối tượng

DB Cascading (ON DELETE CASCADE):
- Được thực thi bởi DBMS engine
- Xảy ra nhanh hơn
- Đảm bảo tính toàn vẹn trên các truy vấn SQL trực tiếp
- Hibernate có thể không biết về các object đã bị xóa
```

## Senior Level

### Triển Khai Nội Bộ

```
Quy trình cascade:
1. Khi có thao tác trên parent (persist, merge, remove)
2. Hibernate duyệt qua tất cả các entity liên quan
3. Với mỗi child - áp dụng thao tác
4. Đệ quy cho các association lồng nhau
5. Tất cả các thao tác được lên lịch trong persistence context
6. Khi flush - được thực thi theo đúng thứ tự
```

### Nguy Hiểm Của Cascade Vòng Lặp

```java
// Cascade vòng lặp - đệ quy vô hạn
@Entity
public class A {
    @OneToOne(cascade = CascadeType.ALL)
    private B b;
}

@Entity
public class B {
    @OneToOne(cascade = CascadeType.ALL)
    private A a;
}

a.setB(b);
b.setA(a);
entityManager.persist(a);  // Hibernate phát hiện chu trình và ngăn ngừa đệ quy vô hạn. Tuy nhiên kết quả không thể dự đoán trước: có thể là PersistentObjectException, các truy vấn SQL thừa, hoặc trạng thái không đúng một cách âm thầm. Cascade vòng lặp là một anti-pattern.
```

### Cascading Trong Many-to-Many

```java
// Cascade.REMOVE trong Many-to-Many - nguy hiểm!
@Entity
public class Author {
    @ManyToMany(cascade = CascadeType.ALL)
    private List<Book> books;
}

// Xóa Author -> xóa tất cả book -> xóa các Author khác
// Xóa Author với cascade=ALL xóa tất cả Book của tác giả này. Nếu Book cũng có cascade=ALL đến Author - author thứ hai cũng bị xóa, cùng với book của họ, và cứ thế qua toàn bộ graph. Kết quả - xóa hàng loạt.

// Không có REMOVE cho Many-to-Many
@ManyToMany(cascade = {CascadeType.PERSIST, CascadeType.MERGE})
private List<Book> books;
```

### Các Cân Nhắc Về Hiệu Năng

```java
// Xóa cascade của collection lớn - N truy vấn DELETE
Author author = entityManager.find(Author.class, id);
entityManager.remove(author);
// DELETE cho author
// DELETE cho mỗi book (nếu cascade = ALL)

// ON DELETE CASCADE cấp độ DB - 1 truy vấn
// ALTER TABLE author_books ADD CONSTRAINT ... ON DELETE CASCADE
entityManager.createNativeQuery("DELETE FROM authors WHERE id = ?")
    .setParameter(1, id)
    .executeUpdate();
```

### Best Practices

```
CascadeType.ALL cho composition (child không có ý nghĩa nếu không có parent)
PERSIST, MERGE cho association (entity dùng chung)
orphanRemoval cho các child composite
Không có REMOVE cho các entity dùng chung
Hiểu sự khác biệt giữa cascade và orphanRemoval
Cascade cấp độ DB cho các xóa hàng loạt

CascadeType.ALL cho @ManyToOne
Cascade.REMOVE cho các entity dùng chung
Cascade vòng lặp
Cascade.REMOVE trong Many-to-Many
Xóa cascade của các collection lớn thông qua JPA
```

### Tóm Tắt Cho Senior

- Cascading là một công cụ để giảm code khi làm việc với object graph
- Chỉ dùng `CascadeType.ALL` cho **composition** (child object không có ý nghĩa nếu không có parent)
- Với **association** (liên kết giữa các entity độc lập), cascade xóa thường có hại
- JPA cascade chỉ hoạt động với các object **Managed**
- Với các xóa hàng loạt, ưu tiên `ON DELETE CASCADE` cấp độ DB

## Interview Cheat Sheet

**Cần phải biết:**
- Cascade tự động truyền các thao tác (persist, merge, remove) sang các entity liên quan
- CascadeType.ALL - tất cả thao tác, PERSIST/MERGE/REMOVE - các loại riêng lẻ
- CascadeType.ALL cho composition (Order -> OrderItem), PERSIST/MERGE cho association (Order -> User)
- Cascade.REMOVE cho @ManyToOne - nguy hiểm: xóa Order xóa User
- Cascade vòng lặp - antipattern: cascade A->B->A gây hành vi không thể dự đoán
- JPA cascade chỉ hoạt động với các object Managed

**Các câu hỏi phụ thường gặp:**
- **Cascade vs orphanRemoval?** Cascade - truyền các thao tác, orphanRemoval - xóa khi loại khỏi collection
- **Tại sao Cascade.REMOVE trong Many-to-Many nguy hiểm?** Xóa Author xóa tất cả Book, và Book có thể có cascade đến Author khác - xóa hàng loạt
- **JPA Cascade vs DB Cascade?** JPA - thông qua code Hibernate (tiện lợi), DB - thông qua DBMS engine (nhanh hơn, đảm bảo tính toàn vẹn)
- **Khi nào KHÔNG cần cascade?** Khi cả hai entity là aggregate root với vòng đời riêng (Order và Customer)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "CascadeType.ALL cho @ManyToOne" - xóa child xóa parent
- "Cascade.REMOVE cho Many-to-Many" - xóa hàng loạt các entity liên quan
- "Cascade vòng lặp A<->B" - hành vi không thể dự đoán
- "Xóa cascade của 10k collection thông qua JPA" - 10k truy vấn DELETE, tốt hơn nên dùng CASCADE cấp độ DB

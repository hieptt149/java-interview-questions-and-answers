# Why @Transactional Does Not Work with Self-Invocation? (Tại sao @Transactional không hoạt động với Self-Invocation?)

## Junior Level

**Self-invocation** — khi một phương thức gọi một phương thức khác của CÙNG một class.

```java
@Service
public class UserService {

    public void outer() {
        inner();  // @Transactional sẽ KHÔNG hoạt động!
    }

    @Transactional
    public void inner() { }
}
```

**Tại sao:** Spring đã tạo một Proxy bao quanh đối tượng, nhưng lời gọi `inner()` đi thẳng qua `this`, bỏ qua Proxy!

---

## Middle Level

### Proxy hoạt động như thế nào

```
[ Client ] -> [ Proxy ] -> [ TransactionInterceptor ] -> [ Target ]
                                                         |
                                                   [ outer() ]
                                                         |
                                                   [ inner() ] <- vòng qua proxy!
```

**Lời gọi từ bên ngoài (hoạt động):**
```
Client -> Proxy.inner() -> TransactionInterceptor -> Target.inner()
```

**Self-invocation (KHÔNG hoạt động):**
```
Target.outer() -> this.inner() -> Target.inner() <- Proxy bị bỏ qua!
```

### Tại sao CGLIB không giúp được

```
CGLIB tạo một subclass, nhưng:
  -> Trong CGLIB proxy - nó là một subclass. Khi code bên ngoài gọi một phương thức, nó đi qua MethodInterceptor. Nhưng khi một phương thức gọi một phương thức khác của cùng class qua `this`, lời gọi đi thẳng tới code phương thức gốc, bỏ qua interceptor.
```

### Những annotation nào khác cũng không hoạt động

```
@Async        -> không bất đồng bộ
@Cacheable    -> không cache
@Validated    -> không validate
@Retryable    -> không retry

-> Tất cả đều dựa trên AOP Proxy!
```

## Senior Level

### Chẩn đoán

```java
// Kiểm tra có transaction hay không:
TransactionSynchronizationManager.isActualTransactionActive();

// Trong debugger:
// Proxy: UserService$$EnhancerBySpringCGLIB$$abc123
// Target: UserService
```

### Bộ nhớ: JDK so với CGLIB Proxy

```
JDK Proxy:
  -> com.sun.proxy.$Proxy123
  -> Implement các interface

CGLIB:
  -> UserService$$EnhancerBySpringCGLIB$$abc123
  -> Kế thừa class
```

### Kinh nghiệm Production

**Tình huống thực tế: nguyên nhân bug thường gặp**
```
Các lập trình viên viết:
  Phương thức @Transactional gọi một phương thức @Transactional khác

-> @Transactional bên trong bị bỏ qua
-> Dữ liệu được lưu không có transaction
-> Bug chỉ được phát hiện trên production

Self-invocation là một trong những lý do phổ biến nhất khiến @Transactional "không hoạt động" trong các dự án thực tế.

Giải pháp: Code Review để tìm self-invocation
```

### Best Practices

1. **Tách thành các bean khác nhau**
2. **TransactionTemplate** -> kiểm soát theo lối lập trình
3. **Self-injection** -> @Lazy + ObjectProvider
4. **AspectJ** -> bytecode weaving (phức tạp)
5. **Tránh** self-invocation
6. **Kiểm tra** qua TransactionSynchronizationManager

### Tóm tắt cho Senior

- **Proxy** chỉ chặn các lời gọi TỪ BÊN NGOÀI
- **this.method()** -> đi thẳng, vòng qua Proxy
- **CGLIB** không giúp được (this = Target)
- **Self-invocation** — lý do thường gặp khiến @Transactional "không hoạt động"
- **TransactionSynchronizationManager** -> để kiểm tra
- **Giải pháp**: các bean khác nhau hoặc TransactionTemplate

## Interview Cheat Sheet

**Cần phải biết:**
- Self-invocation = một phương thức gọi một phương thức khác của CÙNG một class
- Spring AOP hoạt động qua proxy, nhưng `this.method()` đi thẳng, bỏ qua proxy
- Điều này ảnh hưởng đến TẤT CẢ các annotation AOP: @Transactional, @Async, @Cacheable, @Validated, @Retryable
- CGLIB cũng không giúp được — bên trong đối tượng Target, `this` trỏ tới Target, không phải tới proxy subclass
- Kiểm tra có transaction: TransactionSynchronizationManager.isActualTransactionActive()
- Một trong những lý do phổ biến nhất khiến "@Transactional không hoạt động" trong các dự án thực tế
- Chẩn đoán: trong debugger proxy = `$$EnhancerBySpringCGLIB$$`, target = class thông thường

**Các câu hỏi phụ thường gặp:**
- *Tại sao CGLIB không giải quyết được vấn đề?* -> CGLIB chặn các lời gọi từ bên ngoài, nhưng `this.method()` bên trong Target đi thẳng
- *Những annotation nào khác không hoạt động với self-invocation?* -> Tất cả những cái dựa trên AOP: @Async, @Cacheable, @Validated, @Retryable
- *Làm sao phát hiện self-invocation trong code?* -> Code Review, gọi một phương thức của cùng class bên trong một phương thức @Transactional
- *Bug xuất hiện khi nào?* -> Trên production, khi dữ liệu được lưu không có transaction như mong đợi

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "CGLIB giải quyết self-invocation" — không giải quyết, this = Target
- "@Transactional trên các phương thức private hoạt động" — Spring AOP chỉ cho public
- "Đây là một vấn đề hiếm gặp" — một trong những nguyên nhân bug phổ biến nhất
- "Chỉ cần đặt @Transactional lên class" — self-invocation vẫn không hoạt động

# How to create an immutable class in Java? (Cách tạo một immutable class trong Java?)

---

## Basic Level

Để tạo một immutable class, hãy làm theo các bước sau:

### Bước 1: Khai Báo Class Là Final
```java
public final class Person {
```

### Bước 2: Làm Cho Tất Cả Các Trường Thành private final
```java
    private final String name;
    private final int age;
```

### Bước 3: Đừng Tạo Setter
Chỉ có getter (các method để đọc):
```java
    public String getName() { return name; }
    public int getAge() { return age; }
```

### Bước 4: Khởi Tạo Các Trường Trong Constructor
```java
    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
```

### Ví Dụ Hoàn Chỉnh
```java
public final class Person {
    private final String name;
    private final int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }
    public int getAge() { return age; }
}
```

### Khi Nào KHÔNG Nên Tạo Một Immutable Class

- **Entity JPA** — thường mutable (ORM yêu cầu setter, constructor không tham số)
- **Script/prototype đơn giản** — tốc độ phát triển quan trọng hơn
- **DTO cho serialization** — thường tiện lợi hơn khi mutable với setter

## Intermediate Level

### Làm Việc Với Các Trường Mutable

Nếu class chứa collection hoặc các object mutable khác, bạn cần tạo **defensive copy**:

```java
public final class ImmutableReport {
    private final String title;
    private final List<String> items;

    public ImmutableReport(String title, List<String> items) {
        this.title = title;
        this.items = (items == null) ? List.of() : List.copyOf(items);
    }

    public String getTitle() { return title; }

    public List<String> getItems() {
        return items; // List.copyOf đã trả về một list bất biến rồi
    }
}
```

### Hiện Thực Qua Record (Java 14+)
```java
public record ImmutableReport(String title, List<String> items) {
    public ImmutableReport {
        items = List.copyOf(items); // compact constructor
    }
}
```
Một `record` tự động:
- Làm class thành `final`
- Làm các trường thành `private final`
- Sinh constructor, `equals()`, `hashCode()`, `toString()`

### Năm Quy Tắc Của Joshua Bloch
1. Đừng cung cấp các method mutator
2. Đảm bảo class không thể được mở rộng (`final`)
3. Làm tất cả các trường thành `final`
4. Làm tất cả các trường thành `private`
5. Đảm bảo quyền truy cập độc quyền đến các thành phần mutable

## Advanced Level

### Nguy Hiểm Rò Rỉ "this" (Constructor Escape)
```java
public ImmutableClass() {
    ExternalService.register(this); // LỖI!
}
```
Nếu một thread khác truy cập object trước khi constructor hoàn thành, nó sẽ thấy các trường `final` ở trạng thái mặc định của chúng.

### Deep Copy
Nếu list chứa các object mutable, `List.copyOf` là không đủ:
```java
public record Order(Long id, List<Item> items) {
    public Order {
        items = items.stream()
            .map(original -> new Item(original)) // Thay vì clone() (được coi là hỏng — Effective Java Item 13): copy constructor — đáng tin cậy hơn
            .toList();
    }
}
```

### Tấn Công Reflection
Bắt đầu từ Java 9 (Project Jigsaw) và đặc biệt là Java 16+ (JEP 396), quyền truy cập reflection vào các trường `java.base` bị chặn theo mặc định.

### Tóm Tắt Cho Advanced
- `final` thông thường là không đủ với các kiểu tham chiếu mutable
- Luôn dùng `List.copyOf()` hoặc `Collections.unmodifiableList()`
- Nhớ **Constructor Escape**
- Cho các DTO đơn giản, chọn **Record**
- Tính bất biến sâu (deep immutability) đòi hỏi sao chép toàn bộ hệ thống phân cấp object

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- 4 bước: class final, các trường private final, không có setter, khởi tạo trong constructor
- Năm quy tắc của Joshua Bloch: không có mutator, không mở rộng, các trường final, các trường private, bảo vệ các thành phần mutable
- Với các trường mutable — `List.copyOf()` trong constructor và trả về wrapper bất biến từ getter
- Record (Java 14+) tự động làm class final, các trường private final, sinh equals/hashCode/toString
- Constructor Escape — không expose `this` trong quá trình construct
- Deep Copy: nếu list chứa các object mutable, mỗi phần tử phải được clone
- Khi nào KHÔNG nên tạo: entity JPA, prototype đơn giản, DTO cho serialization

**Các câu hỏi phụ thường gặp:**
- *Làm gì với các collection trong constructor?* — `List.copyOf(input)` tạo một bản sao độc lập
- *Record vs class thông thường?* — Record: code tối thiểu, nhưng không có kế thừa; class thông thường: kiểm soát đầy đủ
- *Constructor Escape là gì?* — Publish `this` trước khi constructor hoàn thành = thread khác thấy các trường null
- *List.copyOf có đủ cho tính bất biến sâu không?* — Không, nếu các phần tử của list là mutable

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Chỉ cần các trường final — thế là xong" — không có defensive copy, các trường mutable vẫn dễ bị tổn thương
- "Bạn có thể truyền this trong constructor để đăng ký" — đó là Constructor Escape
- "List.copyOf sao chép các phần tử" — chỉ container được sao chép, các phần tử vẫn giữ nguyên
- "Record giải quyết mọi vấn đề" — các collection trong Record cũng cần sao chép thủ công

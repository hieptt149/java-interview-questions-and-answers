# Can You Inherit from Record or Have Record Inherit from Another Class? (Có thể kế thừa từ Record hoặc để Record kế thừa từ class khác không)

## 🟢 Junior Level

**Không, bạn không thể.** Record trong Java có hai ràng buộc nghiêm ngặt:

1. **Record không thể được mở rộng** — Record là `implicit final`
2. **Record không thể kế thừa class khác** — tất cả Record tự động kế thừa từ `java.lang.Record`

```java
// ❌ Không thể kế thừa từ Record
public record Point(int x, int y) {}
public class Bad extends Point {}  // lỗi biên dịch

// ❌ Record không thể kế thừa class khác
public record Bad extends Object {}  // lỗi biên dịch
// Record luôn extends java.lang.Record
```

**Nhưng bạn có thể triển khai interface:**
```java
public record User(String name) implements Serializable, Comparable<User> {
    @Override
    public int compareTo(User other) {
        return this.name.compareTo(other.name);
    }
}
```

## 🟡 Middle Level

### Tại Sao Có Những Ràng Buộc Này?

Record được tạo ra cho **truyền tải dữ liệu đơn giản**, không phải cho kế thừa hướng đối tượng.

**Lý do:**
1. **Đảm bảo tính bất biến** — nếu Record có thể được mở rộng, một subclass có thể thêm các trường mutable
2. **Hành vi dự đoán được** — `equals()`, `hashCode()` luôn hoạt động theo cùng một cách
3. **Tối ưu hóa JVM** — JIT có thể đưa ra giả định về cấu trúc
4. **Tương thích với value type** — chuẩn bị cho Project Valhalla

### Ứng Dụng Thực Tế

**Thay vì kế thừa — dùng composition:**
```java
// ❌ Không thể làm
public record AuditedRecord(String name) extends BaseEntity {}

// ✅ Có thể làm qua composition
public record BaseEntity(LocalDateTime createdAt, String createdBy) {}
public record User(String name, BaseEntity audit) {}

// Hoặc qua interface
public interface Auditable {
    LocalDateTime createdAt();
    String createdBy();
}

public record User(String name, LocalDateTime createdAt, String createdBy) implements Auditable {}
```

### Các Lỗi Thường Gặp

1. **Cố gắng dùng với Hibernate:**
```java
// ❌ JPA yêu cầu kế thừa từ base entity
@Entity
public record User(Long id, String name) {}  // không hoạt động

// ✅ Class thông thường cho JPA
@Entity
public class User {
    @Id private Long id;
    private String name;
}
```

2. **Mong đợi tính đa hình (polymorphism):**
```java
// Record không hỗ trợ đa hình thông qua kế thừa class, nhưng hỗ trợ
// nó thông qua interface và sealed type.
public record Circle(double radius) {}
public record Rectangle(double w, double h) {}

// ✅ Dùng sealed interface + pattern matching (Java 21+)
public sealed interface Shape permits Circle, Rectangle {}
public record Circle(double radius) implements Shape {}
public record Rectangle(double w, double h) implements Shape {}

double area(Shape s) {
    return switch (s) {
        case Circle c -> Math.PI * c.radius() * c.radius();
        case Rectangle r -> r.w() * r.h();
    };
}
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Cấu trúc class file:**
```
// Record có cờ ACC_FINAL | ACC_RECORD
// super_class luôn trỏ đến java/lang/Record

ClassFile {
    access_flags: ACC_FINAL | ACC_RECORD  // implicit final
    super_class: constant_pool[java/lang/Record]
    interfaces_count: N  // có thể triển khai interface
}
```

**Đặc tả JVM (JVMS 4.7.31 — thuộc tính Record và JVMS 4.1 — access_flags ACC_RECORD):**
- Record phải có cờ `ACC_FINAL`
- Super class phải là `java.lang.Record`
- Không thể thay đổi thông qua thao tác bytecode

### Đánh Đổi Kiến Trúc

**Tại sao Record không thể được mở rộng:**
```
1. Vi phạm encapsulation — subclass có thể thay đổi hành vi equals/hashCode
2. Vấn đề hợp đồng hashCode — các subclass khác nhau có thể có các trường khác nhau
3. Serialization — khó xác định dạng canonical cho hệ thống phân cấp
4. Pattern matching — deconstruction cần cấu trúc cố định
```

### Edge Cases

**1. Sealed interface như lựa chọn thay thế:**
```java
public sealed interface Event permits UserCreated, UserDeleted, OrderPlaced {}

public record UserCreated(String userId, Instant timestamp) implements Event {}
public record UserDeleted(String userId, String reason) implements Event {}
public record OrderPlaced(String orderId, BigDecimal amount) implements Event {}

// Pattern matching để xử lý
String process(Event event) {
    return switch (event) {
        case UserCreated uc -> "User created: " + uc.userId();
        case UserDeleted ud -> "User deleted: " + ud.userId();
        case OrderPlaced op -> "Order placed: " + op.orderId();
    };
}
```

**2. Record Generic:**
```java
public record ApiResponse<T>(int status, T data, String message) {}

// Chuyên biệt hóa thông qua interface
public interface Validated {}
public record ValidatedResponse<T>(ApiResponse<T> response, boolean isValid)
    implements Validated {}
```

**3. Composition thay vì kế thừa:**
```java
public record Pagination(int page, int size) {}
public record Sort(String field, Direction direction) {}

public record PagedRequest(Pagination pagination, Sort sort, String filter) {}

// Thay vì:
// public class PagedRequest extends Pagination { Sort sort; String filter; }
```

### Hiệu Năng

```
Kế thừa vs Composition:
- Kế thừa: truy cập trường nhanh hơn một chút (một tầng)
- Composition: overhead không đáng kể (tham chiếu bổ sung)
- JIT inline hiệu quả cả hai cách tiếp cận
- Khác biệt < 1% trong ứng dụng thực tế
```

### Kinh Nghiệm Production

**Trường hợp thực tế — Event Sourcing:**
```java
// Kiến trúc event-driven với sealed + record
public sealed interface DomainEvent {
    UUID eventId();
    Instant occurredAt();
}

public record UserCreatedEvent(
    UUID eventId, Instant occurredAt, String userId, String name
) implements DomainEvent {}

public record UserEmailChangedEvent(
    UUID eventId, Instant occurredAt, String userId, String oldEmail, String newEmail
) implements DomainEvent {}

// Xử lý
public void handle(DomainEvent event) {
    switch (event) {
        case UserCreatedEvent e -> createUser(e.userId(), e.name());
        case UserEmailChangedEvent e -> updateEmail(e.userId(), e.newEmail());
    }
}
```

### Best Practices

```java
// ✅ Sealed interface + record cho tính đa hình
public sealed interface Payment permits CashPayment, CardPayment, CryptoPayment {}
public record CashPayment(BigDecimal amount) implements Payment {}
public record CardPayment(BigDecimal amount, String cardNumber) implements Payment {}
public record CryptoPayment(BigDecimal amount, String walletAddress) implements Payment {}

// ✅ Composition để tái sử dụng
public record AuditInfo(LocalDateTime createdAt, String createdBy) {}
public record User(String name, String email, AuditInfo audit) {}

// ❌ Đừng cố gắng mô phỏng kế thừa
// ❌ Đừng dùng Record cho JPA entity
// ❌ Đừng dùng Record cho trạng thái mutable
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Record không thể được mở rộng — implicit final (cờ ACC_FINAL)
- Record không thể kế thừa class khác — luôn extends `java.lang.Record`
- Record có thể triển khai interface: `record User implements Serializable`
- Lựa chọn thay thế cho kế thừa — composition hoặc sealed interface
- Sealed interface + Record + pattern matching = thay thế cho tính đa hình
- JVM cấm extends Record ở tầng bytecode (cờ ACC_RECORD)

**Các câu hỏi phụ thường gặp:**
- **Tại sao Record không thể được mở rộng?** — Để đảm bảo tính bất biến, equals/hashCode dự đoán được và tối ưu hóa JVM
- **Cách triển khai tính đa hình với Record?** — Sealed interface + pattern matching (Java 21+)
- **Có thể dùng Record với Hibernate không?** — Không, JPA yêu cầu kế thừa và trạng thái mutable
- **Tại sao composition tốt hơn kế thừa cho Record?** — Giữ được tính bất biến, không phá vỡ hợp đồng của Record

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Bạn có thể mở rộng Record thông qua một class trung gian" — Bị cấm ở tầng JVM
- ❌ "Record kế thừa Object" — Record kế thừa `java.lang.Record`
- ❌ "Record hỗ trợ tính đa hình thông qua kế thừa" — Chỉ thông qua interface và sealed type
- ❌ "Bạn có thể dùng Record cho hệ thống phân cấp JPA entity" — JPA không hỗ trợ Record

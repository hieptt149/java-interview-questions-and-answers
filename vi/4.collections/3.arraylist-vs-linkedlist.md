# What is the difference between ArrayList and LinkedList? (Sự khác nhau giữa ArrayList và LinkedList là gì?)

## Junior Level

**ArrayList** và **LinkedList** — hai cài đặt của interface List.

**Sự khác biệt chính:**

|                       | ArrayList           | LinkedList                |
| --------------------- | ------------------- | ------------------------- |
| **Cấu trúc**          | Mảng động           | Danh sách liên kết đôi     |
| **Đọc theo index**    | Nhanh `get(0)`      | Chậm (iterate)            |
| **Chèn vào đầu**      | Chậm (dịch chuyển)  | Nhanh                     |
| **Bộ nhớ**            | Thấp                | Cao (một đối tượng cho mỗi phần tử) |

**Quy tắc đơn giản:**
- **ArrayList** — cho hầu hết các trường hợp ✅
- **LinkedList** — chiếm chưa đến 1% các kịch bản thực tế. Trường hợp thực tế duy nhất: xóa thông qua iterator trong các list khổng lồ (100k+ phần tử) nơi không thể dùng `removeIf()`. ❌

**Ví dụ:**
```java
List<String> arrayList = new ArrayList<>();
arrayList.get(0);  // Tức thì!

List<String> linkedList = new LinkedList<>();
linkedList.get(0);  // Iterate qua tất cả các phần tử!
```

> **Mẹo:** Nếu bạn cần LinkedList như một queue hoặc stack — hãy dùng **ArrayDeque** thay thế. ArrayDeque nhanh hơn LinkedList 3-10 lần khi iterate và 2-5 lần khi chèn/xóa.

## Middle Level

### ArrayList: Mảng động

```java
// Bên trong: mảng Object[]
// Truy cập: array[index] → O(1)

// Thêm vào:
list.add(e)        // O(1)* trung bình (amortized)
list.add(0, e)     // O(n) dịch chuyển mảng
list.remove(0)     // O(n) dịch chuyển mảng

// Resize: khi đầy → mảng mới × 1.5
// System.arraycopy() → rất nhanh (các lệnh SIMD)
// SIMD (Single Instruction, Multiple Data) — CPU sao chép nhiều phần tử trong một lệnh của một chu kỳ đồng hồ.
```

### LinkedList: Danh sách liên kết đôi

```java
// Bên trong: chuỗi các đối tượng Node
class Node<E> {
    E item;
    Node<E> next;
    Node<E> prev;
}

// Truy cập:
list.get(0)        // O(n) iterate từ đầu/cuối
list.add(e)        // O(1) ở cuối
list.add(0, e)     // O(1) ở đầu
list.remove(iterator)  // O(1) nếu bạn có iterator
```

### So sánh

| Thao tác              | ArrayList   | LinkedList    |
| --------------------- | ----------- | ------------- |
| **get(index)**        | O(1)        | O(n)          |
| **add(e)**            | O(1)*       | O(1)          |
| **add(0, e)**         | O(n)        | O(1)          |
| **remove(0)**         | O(n)        | O(1)          |
| **contains(e)**       | O(n)        | O(n)          |
| **iterator.remove()** | O(n)        | O(1)          |
| **Bộ nhớ**            | 4-8 byte/phần tử | 24-32 byte/phần tử |

### Cache Locality

```
ArrayList: [A][B][C][D]  ← liền kề trong bộ nhớ
  → CPU nạp cache line (64 byte)
  → A, B, C, D đã nằm trong L1 cache!
  → Iterate: rất nhanh

LinkedList: [A]...[B]...[C]...[D]  ← nằm rải rác
  → Mỗi tham chiếu = cache miss
  → Chờ từ RAM: 100+ chu kỳ CPU
  → Iterate: rất chậm
```

### Khi nào dùng LinkedList?

```
Trường hợp duy nhất:
  1. List RẤT LỚN (hàng triệu phần tử)
  2. Xóa THÔNG QUA ITERATOR trong lúc duyệt
  3. Không thể thay thế bằng removeIf()

Trong tất cả các trường hợp khác → ArrayList!
```

### Giải pháp thay thế: ArrayDeque

```java
// ❌ LinkedList như một queue/stack
Deque<String> stack = new LinkedList<>();

// ✅ ArrayDeque (nhanh hơn và ít bộ nhớ hơn)
Deque<String> stack = new ArrayDeque<>();

// ArrayDeque:
// → Mảng vòng (circular array)
// → Không có các đối tượng Node
// → Chèn/xóa O(1) ở cả hai đầu
// → Cache locality tốt hơn
```

## Senior Level

### Đào sâu về Memory Footprint

```
LinkedList Node:
┌─────────────────────────┐
│ Object Header (12 byte)  │
│ item reference (4 byte)  │
│ next reference (4 byte)  │
│ prev reference (4 byte)  │
│ Padding (8 byte)         │
└─────────────────────────┘
Tổng: 32 byte cho mỗi phần tử!

Các con số được hiển thị cho JVM 64-bit với Compressed Oops (mặc định lên đến 32 GB heap). Nếu không có Compressed Oops, các kích thước nhân đôi.

ArrayList:
┌─────────────────────────┐
│ Mảng Object[]           │
│ reference (4 byte)      │
└─────────────────────────┘
Tổng: 4 byte cho mỗi phần tử!

→ LinkedList lớn hơn 8 lần!
→ Áp lực GC: hàng triệu đối tượng Node
```

### Ảo tưởng về Big O

```
Lý thuyết: LinkedList.add(0, e) = O(1)
Thực tế: ArrayList.add(0, e) nhanh hơn với các list nhỏ!

Tại sao?
  ArrayList: System.arraycopy() → các lệnh SIMD
    → 1000 phần tử → ~1 µs

  LinkedList: new Node() + 3 tham chiếu
    → Cấp phát đối tượng → overhead GC
    → 1000 phần tử → ~5 µs

ArrayList thắng cho đến ~10-20k phần tử!
```

### Áp lực GC (GC Pressure)

```
LinkedList khi xóa:
  → Mỗi Node → rác
  → 1M lần xóa = 1M đối tượng trong Young Gen
  → Minor GC thường xuyên → các khoảng dừng STW

ArrayList khi xóa:
  → Gán null cho tham chiếu trong mảng
  → 0 đối tượng mới
  → GC hoạt động tức thì
```

### Vector và Stack — đã lỗi thời (deprecated)

```java
// ❌ Vector (ArrayList được synchronized)
Vector<String> v = new Vector<>();  // Chậm!

// ❌ Stack (kế thừa từ Vector)
Stack<String> s = new Stack<>();  // Overhead gấp đôi!

// ✅ ArrayList (không đồng bộ hóa)
List<String> list = new ArrayList<>();

// ✅ ArrayDeque (thay cho Stack)
Deque<String> stack = new ArrayDeque<>();

// ✅ CopyOnWriteArrayList (nếu cần thread-safety)
List<String> threadSafe = new CopyOnWriteArrayList<>();
```

### Marker RandomAccess

```java
// ArrayList implements RandomAccess
// LinkedList KHÔNG implement RandomAccess

// JDK kiểm tra điều này để tối ưu hóa:
Collections.binarySearch(list, key);
// → Nếu RandomAccess: tìm kiếm nhị phân theo index
// → Nếu không: iterate (chậm hơn)

// Code của bạn:
if (list instanceof RandomAccess) {
    for (int i = 0; i < list.size(); i++) { ... }  // for-i
} else {
    for (E e : list) { ... }  // foreach/iterator
}
```

### Java 21: SequencedCollection

```java
// Giờ đây List kế thừa SequencedCollection
list.getFirst();   // Phương thức mới!
list.getLast();    // Phương thức mới!
list.reversed();   // Thứ tự đảo ngược (view)

// ArrayList.reversed() → Hiệu quả (mảng theo chiều ngược)
// LinkedList.reversed() → Hiệu quả (danh sách liên kết đôi)
```

### Kinh nghiệm Production

**Tình huống thực tế #1: LinkedList giết chết hiệu năng**
- Ứng dụng: 1M phần tử, iterate thường xuyên
- LinkedList: 10 giây, 500 MB bộ nhớ
- ArrayList: 50 ms, 50 MB
- Tăng tốc: **200 lần!**

**Tình huống thực tế #2: Áp lực GC**
- LinkedList: 10M lần xóa → 320 MB rác
- Minor GC mỗi 2 giây → lag
- ArrayList: 0 rác → ổn định

### Best Practices

1. **ArrayList** — lựa chọn mặc định (99% các trường hợp)
2. **ArrayDeque** — thay cho LinkedList cho các queue/stack
3. **Tránh** LinkedList do áp lực GC
4. **Kiểm tra RandomAccess** cho các vòng lặp
5. **removeIf()** thay vì iterate kèm xóa
6. **ensureCapacity()** nếu biết trước kích thước
7. **Java 21** → getFirst(), getLast(), reversed()

### Tóm tắt cho Senior

- **ArrayList** = mảng động, thân thiện với cache
- **LinkedList** = danh sách liên kết đôi, anti-pattern đối với CPU
- **Bộ nhớ:** ArrayList gọn hơn 8 lần
- **GC:** LinkedList tạo ra hàng triệu đối tượng Node
- **Ảo tưởng Big O:** LinkedList O(1) thường chậm hơn ArrayList O(n)
- **ArrayDeque** > LinkedList cho các stack/queue
- **RandomAccess** = marker để tối ưu hóa
- **Valhalla (tương lai):** Inline Types sẽ nới rộng khoảng cách. Project Valhalla dự kiến không sớm hơn Java 23+. Chưa nên dùng nó khi lập kế hoạch kiến trúc.

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- ArrayList = mảng động (Object[]), truy cập theo index O(1), thân thiện với cache
- LinkedList = danh sách liên kết đôi (Node với item/next/prev), truy cập O(n), 32 byte cho mỗi phần tử
- Bộ nhớ: ArrayList ~4 byte/phần tử so với LinkedList ~32 byte/phần tử — nhiều hơn 8 lần
- Cache locality — lý do chính: ArrayList nạp 8 tham chiếu cho mỗi cache line, LinkedList — cache miss ở mỗi phần tử
- Ảo tưởng Big O: LinkedList.add(0,e) = O(1) về lý thuyết, nhưng ArrayList nhanh hơn cho đến 10-20k phần tử nhờ SIMD
- Áp lực GC: LinkedList tạo ra hàng triệu đối tượng Node, ArrayList — chỉ gán null cho các tham chiếu
- ArrayDeque > LinkedList cho các stack và queue — nhanh hơn 3-10 lần khi iterate
- Marker RandomAccess: JDK kiểm tra nó để chọn thuật toán (tìm kiếm nhị phân theo index so với iterate)

**Các câu hỏi phụ thường gặp:**
- Khi nào LinkedList thực sự hợp lý? — Xóa thông qua iterator trong các list 100k+ phần tử nơi không thể dùng removeIf()
- Tại sao ArrayList nhanh hơn LinkedList khi chèn vào đầu? — System.arraycopy() = các lệnh SIMD, cấp phát Node tốn kém hơn
- Áp lực GC là gì? — Minor GC thường xuyên từ hàng triệu đối tượng Node → các khoảng dừng STW → lag
- Tại sao ArrayList implement RandomAccess? — Để JDK dùng các thuật toán tối ưu cho truy cập nhanh theo index

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "LinkedList nhanh hơn khi chèn vào đầu" — ArrayList nhanh hơn cho đến 10-20k phần tử nhờ SIMD
- "LinkedList tiết kiệm bộ nhớ hơn" — ngược lại, nhiều hơn 8 lần (32 byte so với 4 byte cho mỗi phần tử)
- "Hãy dùng LinkedList như một queue" — ArrayDeque nhanh hơn và dùng ít bộ nhớ hơn
- "Big O = hiệu năng thực tế" — LinkedList O(1) thường chậm hơn ArrayList O(n) do các hằng số

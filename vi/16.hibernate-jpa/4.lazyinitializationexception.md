# What is LazyInitializationException and How to Avoid It (LazyInitializationException là gì và cách tránh nó)

## Overview

`LazyInitializationException` là một trong những exception phổ biến nhất trong Hibernate. Nó xảy ra khi cố gắng truy cập một association được tải lazy sau khi session Hibernate đã đóng. Hiểu được nguyên nhân và các phương pháp phòng ngừa là một kỹ năng quan trọng khi làm việc với JPA/Hibernate.

---

## Junior Level

### LazyInitializationException Là Gì

Exception này xảy ra khi bạn cố truy cập một **trường được tải lazy** (LAZY) và **session Hibernate đã đóng**.

**Session (EntityManager)** là một kết nối đến DB. Trong Spring, nó mở khi vào một phương thức @Transactional và đóng khi thoát ra. Bên ngoài một transaction, Hibernate không thể thực thi truy vấn SQL.

```java
@Transactional
public Order getOrder(Long id) {
    return entityManager.find(Order.class, id);
    // Session mở, nhưng sau khi thoát khỏi phương thức - nó đóng lại
}

// Bên ngoài transaction:
Order order = service.getOrder(1L);
order.getItems().size();  // LazyInitializationException!
// Session đã đóng, Hibernate không thể tải items
```

### Tại Sao Nó Xảy Ra

```
1. Order.getItems() là một proxy (PersistentCollection)
2. Khi truy cập, Hibernate cố tải dữ liệu từ DB
3. Nhưng session (EntityManager) đã đóng rồi
4. Hibernate không thể thực thi SELECT -> exception
```

### Cách Tránh - Các Cách Tiếp Cận Cơ Bản

1. **JOIN FETCH** - tải dữ liệu trước khi session đóng
```java
@Query("SELECT DISTINCT o FROM Order o JOIN FETCH o.items WHERE o.id = :id")
Order findByIdWithItems(@Param("id") Long id);
```

2. **@EntityGraph** - chỉ định cái gì cần tải
```java
@EntityGraph(attributePaths = {"items"})
Order findById(Long id);
```

3. **Hibernate.initialize()** - khởi tạo bắt buộc
```java
@Transactional
public Order getOrderWithItems(Long id) {
    Order order = entityManager.find(Order.class, id);
    Hibernate.initialize(order.getItems());  // tải items
    return order;
}
```

### Cách Chọn Giải Pháp Đúng

- **JOIN FETCH** - khi bạn biết chính xác cần gì trong truy vấn NÀY
- **EntityGraph** - khi cần chọn động cái gì cần tải
- **Hibernate.initialize()** - khi cần khởi tạo ở tầng service mà không viết JPQL

## Middle Level

### Các Giải Pháp Chi Tiết

#### 1. JOIN FETCH trong Repository

```java
public interface OrderRepository extends JpaRepository<Order, Long> {

    @Query("SELECT DISTINCT o FROM Order o JOIN FETCH o.items WHERE o.id = :id")
    Optional<Order> findByIdWithItems(@Param("id") Long id);

    @Query("SELECT DISTINCT o FROM Order o " +
           "JOIN FETCH o.user u " +
           "JOIN FETCH o.items i " +
           "WHERE o.id = :id")
    Optional<Order> findByIdWithUserAndItems(@Param("id") Long id);
}
```

#### 2. Khởi Tạo Ở Tầng Service

```java
@Service
@RequiredArgsConstructor
public class OrderService {
    private final EntityManager entityManager;

    @Transactional(readOnly = true)
    public OrderDto getOrderDto(Long id) {
        Order order = entityManager.find(Order.class, id);

        // Khởi tạo mọi thứ cần thiết ở đây, khi session vẫn còn mở
        order.getItems().size();       // buộc tải items
        order.getUser().getName();     // buộc tải user
        order.getAddress().getCity();  // buộc tải address

        return OrderDto.from(order);
    }
}
```

#### 3. @EntityGraph Để Tải Động

```java
public interface OrderRepository extends JpaRepository<Order, Long> {

    @EntityGraph(attributePaths = {"user", "items"})
    @Query("SELECT o FROM Order o WHERE o.id = :id")
    Optional<Order> findWithUserAndItems(@Param("id") Long id);
}
```

### Open Session In View - Tại Sao Không Khuyến Nghị

```yaml
// Không khuyến nghị trong production, nhưng một số team cố tình bật OSIV trong Spring Boot để đơn giản hóa việc phát triển, chấp nhận sự đánh đổi. Điều này chấp nhận được nếu team giám sát truy vấn SQL và kiểm soát N+1.
spring.jpa.open-in-view: true
```

**OSIV** (Open Session In View) là một pattern trong đó session Hibernate tồn tại trong suốt toàn bộ HTTP request, bao gồm cả tầng render. "View" trong MVC nói đến JSP/Thymeleaf. Trong các ứng dụng REST, việc serialize JSON đóng vai trò "view".

**Các Vấn Đề Của OSIV:**
- Session vẫn mở cho đến khi render view (bao gồm cả serialize JSON)
- Transaction dài -> giữ kết nối DB
- Vấn đề hiệu năng ẩn (N+1 không thấy được)
- Nguy cơ rò rỉ connection khi tải cao

### Các Lỗi Thường Gặp

```java
// "Sửa" thông qua EAGER
@OneToMany(fetch = FetchType.EAGER)
private List<OrderItem> items;
// "Đã sửa" LazyInitializationException nhưng tạo ra vấn đề N+1

// Truy cập trường lazy trong controller
@RestController
public class OrderController {
    @GetMapping("/orders/{id}")
    public Order getOrder(@PathVariable Long id) {
        Order order = service.getOrder(id);  // session đã đóng
        return order;  // serialize JSON -> LazyInitializationException
    }
}
```

## Senior Level

### Triển Khai Nội Bộ

```
Cơ chế exception:

1. Order.items -> proxy PersistentCollection
2. Khi truy cập order.getItems():
   - Hibernate.checkTransactionState()
   - session.isOpen() ? có -> tải từ DB
   - session.isOpen() ? không -> ném LazyInitializationException

3. PersistentCollection giữ một tham chiếu đến Session
4. Khi Session đóng -> tham chiếu không còn hợp lệ
5. Proxy không thể tải dữ liệu -> exception
```

### Các Cách Tiếp Cận Kiến Trúc

#### 1. DTO Tại Ranh Giới Transaction

```java
@Service
@RequiredArgsConstructor
public class OrderService {
    private final OrderRepository repository;

    @Transactional(readOnly = true)
    public OrderDto getOrderDto(Long id) {
        // Bên trong @Transactional - session mở
        Order order = repository.findById(id).orElseThrow();

        // Map sang DTO khi session vẫn còn mở
        return OrderDto.from(order);
    }
    // Session đóng - nhưng DTO không còn phụ thuộc vào Hibernate nữa
}
```

#### 2. Specification Pattern Cho Fetch Plan Động

```java
public class OrderSpecifications {

    public static Specification<Order> withUser() {
        return (root, query, cb) -> {
            // Specification trả về null trong kịch bản fetch vì chúng ta không lọc
            // dữ liệu, chỉ sửa đổi fetch plan. Không cần Predicate.
            root.fetch("user", JoinType.LEFT);
            return null;
        };
    }

    public static Specification<Order> withItems() {
        return (root, query, cb) -> {
            // Specification trả về null trong kịch bản fetch vì chúng ta không lọc
            // dữ liệu, chỉ sửa đổi fetch plan. Không cần Predicate.
            root.fetch("items", JoinType.LEFT);
            return null;
        };
    }
}

// Cách dùng:
List<Order> orders = repository.findAll(
    Specification.where(OrderSpecifications.withUser())
        .and(OrderSpecifications.withItems())
);
```

### Kinh Nghiệm Production

```java
// Cho REST API - luôn trả về DTO
@RestController
@RequiredArgsConstructor
public class OrderController {
    private final OrderService service;

    @GetMapping("/orders/{id}")
    public OrderDto getOrder(@PathVariable Long id) {
        return service.getOrderDto(id);  // DTO, không có vấn đề lazy
    }
}

// Cho batch processing - khởi tạo trong vòng lặp
@Transactional
public void processAllOrders() {
    List<Order> orders = repository.findAll();
    for (Order order : orders) {
        // Khởi tạo trong transaction
        order.getItems().forEach(Item::calculateTotal);
        order.getUser().getDiscount();
        // Xử lý...
    }
}
```

### Best Practices

```
JOIN FETCH trong truy vấn khi dữ liệu cần thiết
Khởi tạo bên trong các phương thức @Transactional
@EntityGraph để tải động
DTO projection cho response API
Map sang DTO tại ranh giới transaction
Hibernate.initialize() cho các trường hợp hiếm

Open Session In View trong production
Truy cập trường lazy bên ngoài transaction
"Sửa" thông qua EAGER "để tránh"
Bỏ qua LazyInitializationException
Serialize entity trực tiếp sang JSON
```

## Interview Cheat Sheet

**Cần phải biết:**
- LazyInitializationException xảy ra khi truy cập một trường LAZY sau khi session đóng
- Session (EntityManager) mở khi vào @Transactional và đóng khi thoát ra
- 3 giải pháp chính: JOIN FETCH, EntityGraph, Hibernate.initialize()
- DTO projection là cách tiếp cận tốt nhất: map tại ranh giới transaction
- Open Session In View là antipattern cho production (transaction dài, vấn đề ẩn)
- REST controller nên trả về DTO, không phải entity

**Các câu hỏi phụ thường gặp:**
- **Cách chọn giải pháp?** JOIN FETCH - khi bạn biết chính xác cần gì; EntityGraph - động; Hibernate.initialize() - ở tầng service
- **Tại sao OSIV không khuyến nghị?** Transaction dài, rò rỉ connection, N+1 ẩn
- **Có thể giải quyết thông qua EAGER không?** Về mặt kỹ thuật thì có, nhưng nó tạo ra vấn đề N+1 - giải pháp sai

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi bật EAGER để tránh LazyInitializationException" - tạo ra N+1
- "Open Session In View là thực hành tốt" - antipattern cho production
- "Tôi serialize entity trực tiếp sang JSON" - StackOverflowError + LazyInitializationException
- "Tôi sửa nó thông qua spring.jpa.open-in-view=true" - che giấu vấn đề

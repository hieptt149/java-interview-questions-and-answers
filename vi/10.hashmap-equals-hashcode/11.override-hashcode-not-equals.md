# What Happens If You Override hashCode() But Not equals()? (Điều gì xảy ra nếu bạn override hashCode() nhưng không override equals()?)

## 🟢 Junior Level

Nếu bạn chỉ override `hashCode()`, các object có cùng hash rơi vào cùng một bucket, nhưng `HashMap` vẫn coi chúng khác nhau — vì `equals()` mặc định so sánh các tham chiếu object (`==`).

**Điều gì xảy ra:**
```java
public class User {
    private Long id;

    @Override
    public int hashCode() { return id != null ? id.intValue() : 0; }
    // equals() KHÔNG được override — Object.equals() được dùng (so sánh tham chiếu)
}

Map<User, String> map = new HashMap<>();
map.put(new User(1L), "Alice");  // hashCode=1, bucket #1 → equals không được gọi (bucket rỗng) → OK
map.put(new User(1L), "Bob");    // hashCode=1, bucket #1 → equals(Alice, Bob) → false (Object.equals = so sánh tham chiếu!) → phần tử mới
System.out.println(map.size()); // 2! Hai key "giống hệt"
```

**Quy tắc chính:** Nếu bạn override hashCode — hãy override cả equals!

## 🟡 Middle Level

### Hệ quả thực tế

**1. Trùng lặp trong HashMap:**
- Cả hai `User(id=1)` rơi vào cùng một bucket (hashCode = 100)
- Khi kiểm tra `equals()`, các tham chiếu được so sánh → các object khác nhau → các key khác nhau
- HashMap cho phép cả hai

**2. Không thể lấy dữ liệu:**
- Đặt `new User(1L)` → cố lấy bằng `new User(1L)`
- hashCode đúng (cùng bucket)
- `equals()` trả về `false` (các tham chiếu khác nhau)
- Kết quả: `null`

**3. Tăng tiêu thụ bộ nhớ:**
- HashSet chứa nhiều phần tử hơn mong đợi. Với khối lượng dữ liệu cao, điều này dẫn tới tăng tiêu thụ bộ nhớ và OutOfMemoryError tiềm tàng.

### So sánh hai tình huống

| Tình huống             | Tìm ở đâu?       | Kết quả                 |
| ---------------------- | --------------- | ---------------------- |
| equals OK, hashCode KHÔNG | Các bucket khác nhau | Không tìm thấy (sai chỗ) |
| hashCode OK, equals KHÔNG | Cùng bucket     | Không tìm thấy (không được nhận diện) |

### Hệ quả về hiệu năng

Cùng hashCode cho mọi key → mọi phần tử trong một bucket → suy giảm xuống O(n)/O(log n). Cộng thêm các lời gọi `equals()` vô nghĩa.

## 🔴 Senior Level

### Cơ chế bên trong

Khi `map.get(new User(1L))`:
```java
// 1. Tìm bucket (đúng): index = (n-1) & hash = 100
// 2. Duyệt các phần tử trong bucket 100
// 3. Với mỗi cái: p.hash == hash (true) → p.key.equals(key)
// 4. Object.equals(): this == obj → false (các object khác nhau)
// 5. Trả về null
```

Phần tử về mặt vật lý ở đúng bucket, nhưng không được nhận diện.

### Rò rỉ bộ nhớ trong Production

```java
Set<Event> uniqueEvents = new HashSet<>();
// hashCode được override theo eventId, equals — không
for (Event e : stream) {
    uniqueEvents.add(e); // Mọi object đều được thêm!
}
// Kết quả: OOM khi xử lý một stream lớn
```

### So sánh với Object.equals()

```java
// Object.equals() — đơn giản là:
public boolean equals(Object obj) { return this == obj; }
```
Cái này so sánh các tham chiếu, không phải nội dung. Ngay cả hai `new User(1L)` — các tham chiếu khác nhau → các object khác nhau.

### Các trường hợp biên (Edge Case)

1. **Các object kiểu Singleton**: Nếu cùng một instance luôn được dùng, vấn đề sẽ không biểu hiện (nhưng đó là một giải pháp mong manh)
2. **Deserialization**: Khi deserialize, một object mới luôn được tạo — vấn đề được đảm bảo

### Chẩn đoán Production

Dấu hiệu của vấn đề:
- Kích thước collection tăng dần mà không có sự tăng như mong đợi
- `containsKey()` trả về `false` cho các key "đã tồn tại"
- Heap dump hiển thị nhiều object "giống hệt" trong Map

### Best Practices

1. **Luôn sinh cặp** — dùng IDE hoặc Lombok `@EqualsAndHashCode`
2. **Record** — tự động sinh cả hai method
3. **Phân tích tĩnh** — SonarQube/SpotBugs tìm vi phạm này

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Không có equals(), các object có cùng hashCode rơi vào cùng một bucket, nhưng Object.equals = so sánh tham chiếu (==)
- HashMap cho phép các bản trùng lặp: hai new User(1L) = các key khác nhau
- get() trả về null — đúng bucket, nhưng equals không nhận diện object bằng nhau
- OOM khi xử lý stream: HashSet thêm mọi object thay vì dedup
- Object.equals() = chỉ là `this == obj`, so sánh tham chiếu

**Các câu hỏi phụ thường gặp:**
- **Nó khác "equals OK, hashCode KHÔNG" như thế nào?** — ở đó, tìm kiếm ở bucket sai; ở đây, ở đúng bucket, nhưng không được nhận diện
- **Khi nào vấn đề không biểu hiện?** — nếu cùng một instance luôn được dùng (singleton)
- **Tại sao OOM?** — uniqueEvents.add() thêm mọi object, Set tăng vô hạn
- **Deserialization có làm nó tệ hơn không?** — có, luôn tạo một object mới — vấn đề được đảm bảo

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Đây là một lỗi ít nghiêm trọng hơn thiếu hashCode" — không, cả hai đều then chốt
- "equals không cần override cho các object immutable" — không, ngay cả các object immutable cũng được so sánh theo tham chiếu
- "Điều này không xảy ra trong production" — có, khi deserialize

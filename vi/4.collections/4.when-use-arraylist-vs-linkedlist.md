# When to use ArrayList vs LinkedList? (Khi nào dùng ArrayList so với LinkedList?)

## 🟢 Junior Level

**Câu trả lời ngắn gọn:** Trong đại đa số các trường hợp, hãy dùng **ArrayList**.

**Ngoại lệ cho LinkedList:** (1) Xóa thông qua iterator trong các list có 100k+ phần tử, nơi không thể dùng `removeIf()` (Java 8+). (2) Các cấu trúc dữ liệu chuyên biệt (LRU cache dựa trên danh sách liên kết đôi).

```java
// ✅ 99% thời gian:
List<String> list = new ArrayList<>();

// ❌ LinkedList — đừng dùng khi không có lý do
List<String> list = new LinkedList<>();
```

**Lý do duy nhất để dùng LinkedList:**
- List rất lớn (hàng triệu phần tử)
- Và bạn cần xóa các phần tử **thông qua iterator** trong lúc duyệt

**Cho queue/stack hãy dùng ArrayDeque:**
```java
// ❌ LinkedList như một queue
Deque<String> queue = new LinkedList<>();

// ✅ ArrayDeque (nhanh hơn!)
Deque<String> queue = new ArrayDeque<>();
```

## 🟡 Middle Level

### ArrayList: khi nào dùng

```java
// ✅ Truy cập ngẫu nhiên theo index
list.get(100);  // O(1) — tức thì

// ✅ Iterate (duyệt qua tất cả các phần tử)
for (String s : list) { ... }  // Nhanh (cache locality)

// ✅ Thêm vào cuối
list.add(e);  // O(1)* — trung bình (amortized)

// ✅ Nếu biết trước kích thước
ArrayList<String> list = new ArrayList<>(10000);
// → Không có resize
```

### LinkedList: khi nào (hiếm khi) dùng

```java
// ⚠️ Trường hợp duy nhất:
// 1. List khổng lồ (100,000+ phần tử)
// 2. Xóa thường xuyên THÔNG QUA ITERATOR
// 3. Trong lúc duyệt

Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (shouldRemove(it.next())) {
        it.remove();  // O(1) với LinkedList, O(n) với ArrayList
    }
}

// NHƯNG! Trong Java 8+ tốt hơn nên dùng:
list.removeIf(this::shouldRemove);  // O(n) cho cả hai
```

### ArrayDeque: cho các queue và stack

```java
// Stack (LIFO)
Deque<String> stack = new ArrayDeque<>();
stack.push("A");
stack.pop();

// Queue (FIFO)
Deque<String> queue = new ArrayDeque<>();
queue.offer("A");
queue.poll();

// → Nhanh hơn LinkedList, ít bộ nhớ hơn
```

### So sánh thực tế

| Kịch bản              | ArrayList   | LinkedList   | ArrayDeque   |
| --------------------- | ----------- | ------------ | ------------ |
| **Nhiều lần đọc**     | ✅           | ❌            | N/A          |
| **Thêm vào cuối**     | ✅           | ✅            | ✅            |
| **Chèn vào đầu**      | ❌           | ✅            | ✅            |
| **Xóa theo index**    | ❌           | ❌            | N/A          |
| **Xóa qua iterator**  | ❌           | ✅            | N/A          |
| **Bộ nhớ**            | ✅           | ❌            | ✅            |
| **Áp lực GC**         | ✅           | ❌            | ✅            |

## 🔴 Senior Level

### Cache Locality — luận điểm chính

```
CPU Cache Lines: 64 byte
Cache line — khối bộ nhớ tối thiểu mà CPU nạp từ RAM vào cache. Ngay cả khi bạn chỉ cần 1 byte, CPU vẫn nạp toàn bộ 64 byte xung quanh nó. Vì vậy dữ liệu liền kề trong mảng là "miễn phí".

ArrayList:
  [ref1][ref2][ref3][ref4][ref5][ref6][ref7][ref8]
  → Một lần đọc → 8 ref trong L1 cache
  → 7 phần tử tiếp theo = 0 latency!

LinkedList:
  [Node1]......[Node2]......[Node3]
     ↓             ↓             ↓
  Truy cập RAM: 100+ chu kỳ MỖI lần
  → Cache miss ở MỖI phần tử!
```

### System.arraycopy so với việc tạo Node

```java
// ArrayList.add(0, e):
// → System.arraycopy() → các lệnh SIMD
// → 1000 phần tử → ~1 μs

// LinkedList.add(0, e):
// → new Node() → cấp phát trên heap
// → 3 ref (item, next, prev)
// → 1000 phần tử → ~5 μs + overhead GC

// ArrayList nhanh hơn cho đến ~10-20k phần tử!
// (Dựa trên các benchmark JMH trên các JVM hiện đại. Ngưỡng chính xác phụ thuộc vào CPU, phiên bản JVM và mẫu hình truy cập.)
```

### Đào sâu về Áp lực GC

```
LinkedList: 1M phần tử
  → 1M đối tượng Node
  → chỉ riêng overhead đã 32 MB
  → Minor GC: quét 1M đối tượng
  → các khoảng dừng STW!

ArrayList: 1M phần tử
  → 1 mảng Object[]
  → 4 MB
  → GC: một ref → tức thì
```

### Tối ưu hóa removeIf

```java
// ❌ Xóa thủ công thông qua iterator
for (Iterator<String> it = list.iterator(); it.hasNext(); ) {
    if (condition(it.next())) {
        it.remove();  // O(n) với ArrayList (dịch chuyển mỗi lần)
    }
}

// ✅ removeIf (Java 8+)
list.removeIf(e -> condition(e));
// → Trước tiên tìm tất cả các phần tử cần xóa (O(n))
// → Sau đó MỘT lần dịch chuyển (O(n))
// → Tổng cộng: O(n) thay vì O(n²)!
```

### Khi nào ArrayList cũng thua

```java
// Chèn thường xuyên vào ĐẦU của list lớn (> 100k phần tử)
// ArrayList: dịch chuyển 100k phần tử mỗi lần

// Giải pháp:
// 1. ArrayDeque (nếu chèn vào cả hai đầu)
// 2. Hoặc hai ArrayList (head + tail)
// 3. Hoặc suy nghĩ lại về kiến trúc
```

### Kinh nghiệm Production

**Trường hợp thực tế #1: LinkedList → ArrayList**
- Log: 500,000 dòng trong LinkedList
- Bộ nhớ: 800 MB
- Iterate: 5 giây
- Giải pháp: ArrayList
- Kết quả: 80 MB, 100 ms (tăng tốc 50 lần!)

**Trường hợp thực tế #2: LinkedList như một queue**
- Hàng đợi tin nhắn: LinkedList
- GC: mỗi 2 giây (tạo Node)
- Giải pháp: ArrayDeque
- Kết quả: GC mỗi phút một lần

### Best Practices

1. **ArrayList** — 99% các trường hợp
2. **ArrayDeque** — các queue/stack
3. **removeIf()** thay vì iterate kèm xóa
4. **ensureCapacity()** cho kích thước đã biết
5. **Tránh LinkedList** khi không có lý do chính đáng
6. **Cache Locality** > độ phức tạp thuật toán
7. **Áp lực GC** quan trọng khi chọn collection

### Tóm tắt cho Senior

- **ArrayList** — lựa chọn mặc định (cache locality)
- **LinkedList** — anti-pattern đối với các CPU hiện đại
- **ArrayDeque** — cho các stack và queue
- **removeIf()** > iterate kèm xóa
- **Cache Locality** > Big O trong thực tế
- **Áp lực GC** — chi phí ẩn giấu của LinkedList
- **System.arraycopy** nhanh hơn việc tạo Node
- **Valhalla** (tương lai): Inline Types sẽ nới rộng khoảng cách

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- ArrayList — lựa chọn mặc định cho 99% kịch bản
- Cache locality > độ phức tạp thuật toán: CPU nạp cache line 64-byte cùng một lúc, lấy được 8-16 ref "miễn phí"
- System.arraycopy() = các lệnh SIMD — nhanh hơn new Node() cho các list lên đến 10-20k phần tử
- removeIf() tốt hơn xóa thủ công qua iterator: một lần duyệt + một lần dịch chuyển = O(n) thay vì O(n²)
- ArrayDeque — cho các stack và queue (nhanh hơn LinkedList, ít bộ nhớ hơn, không có áp lực GC)
- Áp lực GC: LinkedList 1M phần tử = 32 MB rác, ArrayList = 0 đối tượng mới
- ensureCapacity() tiết kiệm 30+ lần resize khi biết trước kích thước
- Trường hợp thực tế: thay LinkedList → ArrayList cho tăng tốc 50-200 lần và giảm 10 lần bộ nhớ

**Các câu hỏi phụ thường gặp:**
- Khi nào LinkedList có thể thắng? — Chèn thường xuyên vào ĐẦU của list >100k phần tử; xóa qua iterator trong các list khổng lồ
- Cache line là gì và tại sao nó quan trọng? — Khối 64-byte, CPU nạp toàn bộ nó; ArrayList tận dụng nó, LinkedList — không
- Tại sao removeIf() nhanh hơn vòng lặp iterator? — Trước tiên tìm tất cả các phần tử cần xóa, sau đó MỘT lần dịch chuyển mảng
- Khi nào ArrayList cũng thua? — Chèn thường xuyên vào đầu của list lớn (>100k) — khi đó dùng ArrayDeque

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "LinkedList tốt hơn cho việc chèn thường xuyên" — ArrayList nhanh hơn cho đến 10-20k phần tử nhờ SIMD
- ❌ "Hãy dùng LinkedList cho queue" — ArrayDeque luôn tốt hơn (nhanh hơn, ít bộ nhớ hơn)
- ❌ "Big O quyết định hiệu năng" — cache locality và các hằng số quan trọng hơn trong thực tế
- ❌ "Xóa qua iterator là thực hành bình thường" — hãy dùng removeIf() trong Java 8+

# What Happens If an Exception Occurs in CompletableFuture Chain? (Điều gì xảy ra nếu một ngoại lệ xuất hiện trong chuỗi CompletableFuture)

## 🟢 Junior Level

Một ngoại lệ trong chuỗi CompletableFuture **làm gián đoạn việc thực thi** và lan truyền xuống dưới — tất cả các giai đoạn tiếp theo (thenApply, thenAccept, thenRun) **không được thực thi**.

```java
CompletableFuture<String> future = CompletableFuture
    .supplyAsync(() -> {
        throw new RuntimeException("Error!");
    })
    .thenApply(s -> s.toUpperCase());  // Sẽ không thực thi

// future.isCompletedExceptionally() = true
// future.join() — ném ra CompletionException
```

**Analogy đơn giản:**
- Chuỗi CF giống như một dây chuyền lắp ráp
- Nếu một giai đoạn gặp lỗi — toàn bộ dây chuyền dừng lại
- Bạn cần một "lối thoát khẩn cấp" (exceptionally/handle)

### Xử Lý Ngoại Lệ

```java
// 1. exceptionally — giá trị fallback
CompletableFuture<String> future = CompletableFuture
    .supplyAsync(() -> { throw new RuntimeException("Error!"); })
    .exceptionally(ex -> "Fallback value");

// 2. handle — xử lý cả kết quả và ngoại lệ
CompletableFuture<String> future = CompletableFuture
    .supplyAsync(() -> { throw new RuntimeException("Error!"); })
    .handle((result, ex) -> ex != null ? "Fallback" : result);

// 3. whenComplete — chỉ quan sát (không bắt được!)
CompletableFuture<String> future = CompletableFuture
    .supplyAsync(() -> "Hello")
    .whenComplete((result, ex) -> {
        if (ex != null) {
            log.error("Error", ex);
        }
    });
    // Ngoại lệ vẫn còn trong CF — cần exceptionally/handle
```

## 🟡 Middle Level

### CompletionException

`join()` và `get()` bọc ngoại lệ gốc trong một `CompletionException`.
Ngoại lệ gốc có thể truy cập qua `getCause()`.
`exceptionally` nhận một `CompletionException` với ngoại lệ gốc làm `cause`.

```java
CompletableFuture<String> future = CompletableFuture
    .supplyAsync(() -> { throw new RuntimeException("Original error"); });

try {
    future.join();  // ném ra CompletionException
} catch (CompletionException e) {
    Throwable cause = e.getCause();  // RuntimeException: "Original error"
}
```

### Lan Truyền Ngoại Lệ

```
supplyAsync(ném ra) → thenApply(bỏ qua) → thenAccept(bỏ qua) → exceptionally(bắt được)

Ngoại lệ đi qua toàn bộ chuỗi cho đến handler đầu tiên
```

### exceptionally vs handle vs whenComplete

| Phương thức          | Bắt được                 | Trả về giá trị         | Thực thi khi thành công     |
| --------------- | ----------------------- | ---------------------- | ----------------------- |
| `exceptionally` | Có                     | Có (fallback)        | Không                      |
| `handle`        | Có                     | Có                   | Có                     |
| `whenComplete`  | Không (chỉ quan sát)   | Không (đi qua)   | Có                     |

```java
// whenComplete KHÔNG bắt được — ngoại lệ vẫn còn trong CF
cf.whenComplete((r, ex) -> log("done"))
  .join();  // vẫn ném ra!

// handle bắt được — CF hoàn thành bình thường
cf.handle((r, ex) -> ex != null ? "fallback" : r)
  .join();  // OK
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

Ngoại lệ được lưu trong trường `result` như một `AltResult` (class nội bộ) bọc lấy throwable. Khi `join()`/`get()` được gọi, nó được mở gói thành một `CompletionException`.

```java
// Đơn giản hóa:
private volatile Object result;  // có thể là AltResult với Throwable

// completeExceptionally(Throwable ex)
// — thiết lập result = new AltResult(ex)
// — thông báo cho tất cả các CF phụ thuộc
```

### Kết Hợp Ngoại Lệ

```java
// Nhiều CF với xử lý lỗi
CompletableFuture<String> cf1 = service1()
    .exceptionally(ex -> "fallback1");
CompletableFuture<String> cf2 = service2()
    .exceptionally(ex -> "fallback2");

// allOf chỉ thất bại nếu cả hai đều thất bại
// và không xử lý lỗi
CompletableFuture.allOf(cf1, cf2).join();
```

### Best Practices

```java
// ✅ Luôn thêm exceptionally/handle
cf.exceptionally(ex -> { log.error("...", ex); return defaultValue; });

// ✅ Kiểm tra cause trong CompletionException
catch (CompletionException e) { handleCause(e.getCause()); }

// ✅ whenComplete chỉ cho side effect (logging, metrics)
cf.whenComplete((r, ex) -> metrics.record(ex != null ? "error" : "ok"));

// ❌ Đừng bỏ qua ngoại lệ trong whenComplete
// ❌ Đừng quên một handler ở cuối chuỗi
// ❌ Đừng bọc ngoại lệ mà không giữ lại cause
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Ngoại lệ phá vỡ chuỗi — tất cả thenApply/thenAccept/thenRun phía sau không được thực thi
- join()/get() bọc trong CompletionException, gốc thông qua getCause()
- exceptionally bắt và trả về fallback, handle — kiểm soát toàn diện, whenComplete — chỉ quan sát
- Ngoại lệ được lưu như AltResult (class nội bộ), không chặn CF
- Handler ở cuối chuỗi — bắt buộc cho production

**Các câu hỏi phụ thường gặp:**
- **whenComplete có bắt ngoại lệ không?** — Không, chỉ quan sát. CF vẫn ở trạng thái lỗi
- **exceptionally có nhận ngoại lệ gốc không?** — Không, CompletionException. Dùng getCause() cho ngoại lệ gốc
- **Điều gì xảy ra với allOf nếu một CF thất bại?** — allOf hoàn thành với lỗi. Cần handle trên mỗi CF
- **Ngoại lệ trong exceptionally — điều gì xảy ra?** — Ngoại lệ mới, được exceptionally phía sau bắt được

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "whenComplete bắt ngoại lệ" — chỉ quan sát, lỗi vẫn còn trong CF
- "exceptionally nhận ngoại lệ gốc" — nhận CompletionException
- "Ngoại lệ chặn CF mãi mãi" — CF hoàn thành với lỗi, không chặn

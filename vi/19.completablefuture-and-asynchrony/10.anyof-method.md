# What Does anyOf() Method Do and When Is It Useful? (Phương thức anyOf() làm gì và khi nào hữu ích)

## 🟢 Junior Level

**`anyOf()`** — chờ CompletableFuture **ĐẦU TIÊN** trong số các CF được truyền vào hoàn thành và trả về kết quả của nó.

```java
CompletableFuture<String> fast = CompletableFuture.supplyAsync(() -> {
    Thread.sleep(100);
    return "Fast";
});

CompletableFuture<String> slow = CompletableFuture.supplyAsync(() -> {
    Thread.sleep(1000);
    return "Slow";
});

// Trả về kết quả của cái hoàn thành ĐẦU TIÊN
CompletableFuture<Object> any = CompletableFuture.anyOf(fast, slow);

any.thenAccept(result -> System.out.println(result));  // "Fast"
```

**Khi nào nên dùng:**
- Truy vấn nhiều nguồn — bất kỳ ai phản hồi trước
- Fallback: dịch vụ chính và dịch vụ dự phòng
- Timeout thông qua một CF thay thế

## 🟡 Middle Level

### Cách Hoạt Động

```java
// Truy vấn nhiều server
CompletableFuture<String> server1 = queryServerAsync("server1");
CompletableFuture<String> server2 = queryServerAsync("server2");
CompletableFuture<String> server3 = queryServerAsync("server3");

// Lấy phản hồi đầu tiên
CompletableFuture<Object> fastest = CompletableFuture.anyOf(server1, server2, server3);

fastest.thenAccept(response -> System.out.println("Got response: " + response));
```

**Quan trọng:** `anyOf()` trả về `CompletableFuture<Object>` — bạn cần ép kiểu (cast):

```java
CompletableFuture.anyOf(cf1, cf2)
    .thenAccept(result -> {
        String str = (String) result;  // cần cast!
        System.out.println(str);
    });
```

### Các Lỗi Thường Gặp

1. **Không biết CF nào đã hoàn thành:**
```java
CompletableFuture.anyOf(cf1, cf2).thenAccept(result -> {
    // result — Object, không rõ nó đến từ CF nào
    // Nếu các kiểu khác nhau — cần kiểm tra
    if (result instanceof String s) { }
    if (result instanceof Integer i) { }
});
```

2. **Các CF còn lại tiếp tục thực thi:**
```java
// anyOf không hủy các CF còn lại!
CompletableFuture.anyOf(fast, slow);
// slow vẫn tiếp tục chạy ở background
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

```java
public static CompletableFuture<Object> anyOf(CompletableFuture<?>... cfs) {
    return new OrRelay<>(cfs, null);
}

// Khi CF đầu tiên hoàn thành — kết quả được sao chép vào OrRelay
// Các CF còn lại bị bỏ qua (nhưng vẫn tiếp tục thực thi)
```

### Đánh Đổi Kiến Trúc

| anyOf()            | allOf()         |
| ------------------ | --------------- |
| Cái đầu tiên hoàn thành    | Tất cả hoàn thành   |
| Kết quả Object      | Kết quả Void     |
| Fail nhanh          | Chờ đầy đủ       |

### Edge Cases

**1. Pattern timeout:**
```java
CompletableFuture<String> operation = fetchDataAsync();
CompletableFuture<Object> timeout = CompletableFuture
    .delayedExecutor(5, TimeUnit.SECONDS)
    .thenApply(v -> { throw new TimeoutException(); });

CompletableFuture<Object> result = CompletableFuture.anyOf(operation, timeout);
```

**2. Nhiều nguồn với fallback:**
```java
CompletableFuture<Data> primary = fetchFromPrimaryAsync();
CompletableFuture<Data> fallback = fetchFromCacheAsync();

CompletableFuture<Object> any = CompletableFuture.anyOf(primary, fallback);

any.thenAccept(result -> {
    Data data = (Data) result;
    // anyOf có thể đã hoàn thành từ fallback trong khi primary vẫn đang chạy.
    // isCompletedExceptionally() không cho bạn biết AI đã thắng cuộc đua.
    // Cách tiếp cận đáng tin cậy — so sánh kết quả với các nguồn đã biết.
    if (result == fallbackResult) {
        log.warn("Primary failed or hasn't completed yet, using fallback");
    }
});
```

**3. Hủy các CF còn lại:**
```java
CompletableFuture<String> cf1 = fetchAsync(1);
CompletableFuture<String> cf2 = fetchAsync(2);
CompletableFuture<String> cf3 = fetchAsync(3);

CompletableFuture<Object> any = CompletableFuture.anyOf(cf1, cf2, cf3);

any.thenAccept(result -> {
    // Hủy các cái còn lại
    // cancel trên một CF đã hoàn thành là no-op. Nhưng đoạn code này gây hiểu lầm,
    // như thể cả ba vẫn đang chạy. Tốt hơn là theo dõi ai đã thắng.
    cf1.cancel(false);
    cf2.cancel(false);
    cf3.cancel(false);
});
```

### Hiệu Năng

```
anyOf():
- Tạo: ~10 ns
- Overhead: ~5 ns mỗi CF
- Cái hoàn thành đầu tiên — kết quả

Hủy các CF còn lại:
- cancel(false): ~100 ns
- Nhưng việc thực thi có thể vẫn tiếp tục
```

### Kinh Nghiệm Production

**Lời gọi service có khả năng phục hồi (Resilient):**
```java
@Service
public class ResilientService {
    public CompletableFuture<String> getData(String key) {
        CompletableFuture<String> primary = primaryClient.getAsync(key);
        CompletableFuture<String> secondary = secondaryClient.getAsync(key);
        CompletableFuture<String> cache = cacheClient.getAsync(key);

        return CompletableFuture.anyOf(primary, secondary, cache)
            .thenApply(result -> (String) result);
    }
}
```

### Khi Nào KHÔNG Nên Dùng anyOf

- **Cần TẤT CẢ kết quả** — dùng `allOf`
- **Cái nhanh nhất có thể đến từ một nguồn không đáng tin cậy** — anyOf trả về cái đầu tiên, không phải cái tốt nhất

### Best Practices

```java
// ✅ anyOf cho phản hồi nhanh nhất
CompletableFuture.anyOf(cf1, cf2, cf3)
    .thenAccept(result -> process((Type) result));

// ✅ Timeout qua anyOf
CompletableFuture.anyOf(operation, timeoutCF);

// ✅ Hủy các cái còn lại khi hoàn thành
any.thenAccept(r -> { cf1.cancel(false); cf2.cancel(false); });

// ❌ anyOf khi bạn cần tất cả kết quả
// ❌ Bỏ qua kiểu trả về Object
// ❌ Không hủy các CF còn lại
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- anyOf() trả về kết quả của CF ĐẦU TIÊN hoàn thành
- Trả về CompletableFuture<Object> — cần cast
- Không hủy các CF còn lại — chúng tiếp tục thực thi
- Độ trễ = min(tất cả CF) — phản hồi nhanh nhất
- Trường hợp dùng: nhanh nhất trong nhiều server, fallback, timeout

**Các câu hỏi phụ thường gặp:**
- **anyOf có hủy các CF còn lại không?** — Không, cần cancel(false) thủ công
- **Cách biết CF nào đã thắng?** — So sánh kết quả với các nguồn đã biết
- **anyOf vs applyToEither?** — applyToEither cho hai CF (có kiểu), anyOf cho N (Object)
- **Điều gì xảy ra nếu CF đầu tiên thất bại?** — anyOf hoàn thành với một lỗi. Cần xử lý lỗi

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "anyOf trả về một kết quả có kiểu" — trả về Object, cần cast
- "anyOf tự động hủy các cái còn lại" — không, chúng tiếp tục thực thi
- "anyOf đảm bảo kết quả tốt nhất" — chỉ nhanh nhất, không phải tốt nhất

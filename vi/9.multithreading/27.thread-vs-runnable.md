# What is the difference between Thread and Runnable? (Sự khác biệt giữa Thread và Runnable là gì?)

`Thread` và `Runnable` là hai khái niệm khác nhau về bản chất trong Java thường bị nhầm lẫn. **Runnable** mô tả một tác vụ ("làm gì"), trong khi **Thread** là bên thực thi ("ai thực thi"). Sự tách biệt này là một ví dụ của pattern Command: object command (Runnable) tách biệt với object executor (Thread).

**Tại sao sự tách biệt này quan trọng:** nếu tác vụ bị gắn với bên thực thi (như khi kế thừa từ Thread), bạn không thể tái sử dụng cùng một tác vụ trong các bối cảnh khác nhau (thread pool, Virtual Thread, thread hiện tại). Sự tách biệt mang lại tính linh hoạt.

---

## Junior Level

### Hiểu biết cơ bản

`Thread` và `Runnable` là hai thứ khác nhau trong Java:

| Khái niệm    | Nó là gì               | Vai trò                        |
| ------------ | ----------------------- | ------------------------------ |
| **Runnable** | Interface (`interface`) | **Task** — "làm gì"            |
| **Thread**   | Class (`class`)         | **Bên chuyên chở** — "ai thực thi"|

**Runnable** — đây chỉ là một khối code có thể được thực thi. Bản thân nó không tạo một thread. **Thread** — đây là một wrapper bọc quanh một thread của hệ điều hành, thứ nhận một Runnable và chạy nó trong một thread thực thi riêng.

### Ví dụ minh họa đơn giản

- **Runnable** = công thức nấu ăn (mô tả nấu gì)
- **Thread** = đầu bếp (người nấu theo công thức)

### Ví dụ Runnable

```java
// Runnable — đây chỉ là một tác vụ
Runnable task = () -> {
    System.out.println("Executing task!");
};
```

### Ví dụ Thread

```java
// Thread — đây là bên thực thi
Thread thread = new Thread(task); // Truyền tác vụ
thread.start(); // Khởi chạy một thread mới
```

### So sánh đầy đủ

| Đặc điểm                   | Runnable                   | Thread                                     |
| -------------------------- | -------------------------- | ------------------------------------------ |
| **Kiểu**                   | Interface                  | Class                                      |
| **Method**                 | `run()`                    | `start()`, `join()`, `interrupt()`, ...    |
| **Tạo một thread?**        | Không                      | Có (khi `start()` được gọi)                |
| **Bộ nhớ**                 | Object trong heap (~24 byte)| Object + native stack (~1MB)              |
| **Tái sử dụng được?**      | Có                         | Không (một Thread = một lần thực thi)      |

### Sai lầm thường gặp: run() vs start()

```java
Runnable task = () -> System.out.println("Thread: " + Thread.currentThread().getName());

// XẤU: run() — thực thi trong thread HIỆN TẠI
task.run(); // "Thread: main" — KHÔNG phải một thread mới!

// TỐT: start() — tạo một thread MỚI
Thread thread = new Thread(task);
thread.start(); // "Thread: Thread-0" — thread mới!
```

## Middle Level

### Composition over Inheritance (Kết hợp thay vì kế thừa)

```java
// XẤU: kế thừa từ Thread
class MyTask extends Thread {
    @Override
    public void run() {
        // Bây giờ MyTask KHÔNG THỂ kế thừa từ bất kỳ thứ gì khác
    }
}

// TỐT: implement Runnable
class MyTask implements Runnable {
    @Override
    public void run() {
        // MyTask vẫn có thể kế thừa từ một class khác
    }
}
```

### Tại sao Runnable tốt hơn?

| Tiêu chí                    | extends Thread           | implements Runnable          |
| --------------------------- | ------------------------ | ---------------------------- |
| Đa kế thừa                  | Không (bị Thread chiếm)  | Có                          |
| Khả năng tái sử dụng        | Không (một Thread)       | Có (trong bất kỳ ExecutorService nào)|
| Tách biệt mối quan tâm      | Không (tác vụ + bên chuyên chở)| Có (tác vụ tách riêng) |

### Truyền Runnable cho các Executor khác nhau

```java
Runnable task = () -> System.out.println("Working...");

// 1. Trong Thread
new Thread(task).start();

// 2. Trong ExecutorService
ExecutorService executor = Executors.newFixedThreadPool(5);
executor.submit(task);

// 3. Trong ForkJoinPool
ForkJoinPool.commonPool().execute(task);

// 4. Chỉ trong thread hiện tại
task.run();
```

### Thành phần của Thread (Có gì bên trong)

```java
Thread thread = new Thread(task);

// Thread chứa:
thread.getId();                    // ID duy nhất
thread.getName();                  // Tên ("Thread-0")
thread.getPriority();              // Priority (1-10)
thread.isDaemon();                 // Daemon hay không
thread.getContextClassLoader();    // ClassLoader cho các framework
thread.getState();                 // NEW, RUNNABLE, BLOCKED, WAITING, ...
```

### Các trạng thái của Thread

| Trạng thái       | Mô tả                                          |
| ---------------- | ---------------------------------------------- |
| **NEW**          | Đã tạo, nhưng start() chưa được gọi            |
| **RUNNABLE**     | Đang thực thi hoặc sẵn sàng để thực thi        |
| **BLOCKED**      | Chờ giải phóng monitor (synchronized)          |
| **WAITING**      | Chờ notify() hoặc park()                       |
| **TIMED_WAITING**| Chờ có timeout (sleep, wait(timeout))          |
| **TERMINATED**   | Đã kết thúc                                    |

```java
Thread t = new Thread(() -> {});
System.out.println(t.getState()); // NEW

t.start();
System.out.println(t.getState()); // RUNNABLE (hoặc TERMINATED nếu nhanh)

t.join();
System.out.println(t.getState()); // TERMINATED
```

## Senior Level

### Bên trong: Tạo Thread

```java
// Khi gọi start():
thread.start();

// JVM làm:
// 1. Gọi native method:
//    - Linux: pthread_create()
//    - Windows: CreateThread()
// 2. OS cấp phát:
//    - Stack (mặc định 1MB)
//    - Thread-local storage
//    - Các entry trong scheduler
// 3. Thêm vào hàng đợi của OS scheduler
// 4. Chỉ sau đó mới gọi Runnable.run()
```

### Bộ nhớ Stack

```
1000 object Runnable:  ~24 KB  (chỉ là các object trong Young Gen)
1000 object Thread:    ~1 GB   (1000 x 1MB native stack)
```

### Thread Context ClassLoader

```java
// Các framework dùng nó để nạp class
Thread.currentThread().setContextClassLoader(myClassLoader);

// Hibernate, Spring và các framework khác dùng:
ClassLoader cl = Thread.currentThread().getContextClassLoader();
Class<?> clazz = cl.loadClass("com.example.MyEntity");
```

### Priority — Huyền thoại và thực tế

```java
Thread t = new Thread(task);
t.setPriority(Thread.MAX_PRIORITY); // 10

// Trên các OS hiện đại (Linux CFS) các priority của Java
// hầu như bị scheduler PHỚT LỜ!
// OS dùng các thuật toán fairness phức tạp của riêng nó
```

### UncaughtExceptionHandler

```java
Thread t = new Thread(() -> {
    throw new RuntimeException("Uncaught error!");
});

// Không có handler — lỗi chỉ đi ra System.err
t.setUncaughtExceptionHandler((thread, ex) -> {
    System.err.println("Thread " + thread.getName() + " crashed: " + ex);
    // Logging, alert, restart
});

t.start();
```

### Thread Group — Khái niệm đã lỗi thời (Deprecated)

```java
// ThreadGroup — KHÔNG được khuyến nghị
ThreadGroup group = new ThreadGroup("my-group");
new Thread(group, task).start();

// Ngày nay để nhóm hãy dùng:
// 1. ExecutorService
// 2. StructuredTaskScope (Java 21+)
// 3. Custom ThreadFactory với các tên
```

#### jstack

```

  at com.example.MyClass.myMethod(MyClass.java:42)

```

#### Thread Dump — Cái gì thấy được

- `Thread` — thấy được: trạng thái, tên, stack trace
- `Runnable` — KHÔNG thấy riêng, nó "tan biến" bên trong stack frame của method `run()`

### Best Practices

1. **Implement Runnable** — đừng kế thừa từ Thread
2. **Dùng ExecutorService** — đừng tạo Thread trực tiếp
3. **Gọi start()** — không phải run() để khởi chạy một thread
4. **Đặt UncaughtExceptionHandler** — để xử lý lỗi
5. **Đặt tên thread** — custom ThreadFactory để debug
6. **Thread Context ClassLoader** — để nạp class động
7. **Đừng dùng ThreadGroup** — ExecutorService hoặc StructuredTaskScope
8. **Đừng dựa vào các priority** — OS phớt lờ chúng

## Khi nào KHÔNG dùng Runnable

- **Tác vụ đơn luồng** — nếu code chạy trong chỉ một thread, Runnable thêm một sự trừu tượng không cần thiết
- **Cần một kết quả** — dùng `Callable<V>` thay vì `Runnable` (Runnable.run() trả về void)
- **Cần ném một checked exception** — Runnable.run() không khai báo throws, dùng Callable

## Khi nào KHÔNG tạo Thread trực tiếp

- **ExecutorService có sẵn** — thread pool hiệu quả hơn (tái sử dụng các thread, quản lý hàng đợi)
- **Virtual Thread có sẵn (Java 21+)** — cho các tác vụ I/O-bound `Thread.ofVirtual()` đơn giản và nhẹ hơn
- **StructuredTaskScope (Java 21 Preview)** — cho các nhóm tác vụ liên quan với lifecycle dùng chung

## Runnable vs Callable vs Thread: Chọn gì?

| Tình huống                          | Lựa chọn                           | Tại sao                                           |
| ----------------------------------- | ---------------------------------- | ------------------------------------------------ |
| Tác vụ không có kết quả (logging, gửi)| Runnable                          | Functional interface đơn giản                    |
| Tác vụ có kết quả                   | Callable<V>                        | Trả về V, có thể ném checked exception           |
| Prototype nhanh (1-2 thread)        | new Thread(runnable)               | Ít code nhất                                     |
| Production (pool, quản lý)          | ExecutorService.submit(runnable)   | Tái sử dụng thread, hàng đợi                     |
| I/O-bound, nhiều tác vụ (Java 21+)  | Thread.ofVirtual().start(runnable) | Hàng triệu thread nhẹ                            |

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Runnable — interface (tác vụ, "làm gì"), Thread — class (bên thực thi, "ai thực thi")
- Runnable.run() thực thi trong thread HIỆN TẠI, Thread.start() tạo một thread MỚI
- Composition over Inheritance: implements Runnable tốt hơn extends Thread (tính linh hoạt, thread pool, Virtual Thread)
- 1000 object Runnable = ~24 KB, 1000 Thread = ~1 GB (native stack)
- Các trạng thái Thread: NEW → RUNNABLE → BLOCKED/WAITING/TIMED_WAITING → TERMINATED
- Priority của Thread trên các OS hiện đại (Linux CFS) hầu như bị scheduler phớt lờ

**Các câu hỏi phụ thường gặp:**
- **Tại sao không nên kế thừa từ Thread?** — Có thể, nhưng đó là một anti-pattern: mất đa kế thừa, không thể tái sử dụng trong các thread pool
- **Tại sao cần Context ClassLoader trong Thread?** — Các framework (Hibernate, Spring) dùng nó để nạp class động từ classpath đúng
- **Tại sao ThreadGroup lỗi thời?** — Thay vào đó, dùng ExecutorService, StructuredTaskScope (Java 21+), hoặc custom ThreadFactory
- **Làm gì với các uncaught exception trong Thread?** — `setUncaughtExceptionHandler()` — nếu không lỗi chỉ đi ra System.err

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Thread và Runnable là cùng một thứ" — Runnable là tác vụ, Thread là bên thực thi
- "Gọi run() khởi chạy một thread mới" — run() thực thi trong thread hiện tại, cần start()
- "Priority của Thread đảm bảo thứ tự thực thi" — các OS hiện đại phớt lờ các priority của Java
- "ThreadGroup là một cách tốt để nhóm các thread" — lỗi thời, dùng ExecutorService hoặc StructuredTaskScope

# What is Projection in JPA (Projection trong JPA là gì)

## Overview

Projection là việc chỉ tải các trường cần thiết của một entity thay vì toàn bộ object. Điều này cải thiện đáng kể hiệu năng, giảm sử dụng bộ nhớ, và loại bỏ nhu cầu dirty checking trong các thao tác chỉ đọc.

---

## Junior Level

### Projection Là Gì

Projection - tải **một tập con các trường** thay vì toàn bộ entity.

```java
// Entity đầy đủ - tất cả các trường
SELECT u FROM User u

// Projection - chỉ các trường cần thiết
SELECT u.name, u.email FROM User u
```

### Tại Sao Sử Dụng Nó

- Ít dữ liệu từ DB hơn -> truy vấn nhanh hơn
- Ít dữ liệu trong bộ nhớ hơn -> tiết kiệm
- Không có dirty checking -> ít overhead hơn
- Kiểm soát API contract

### Ví Dụ Đơn Giản

```java
// Lớp DTO
public record UserDto(String name, String email) {}

// JPQL với constructor
@Query("SELECT new com.example.UserDto(u.name, u.email) FROM User u")
List<UserDto> findUserDtos();
```

## Middle Level

### Các Loại Projection

#### 1. Array Projection

```java
@Query("SELECT u.name, u.email FROM User u")
List<Object[]> findNamesAndEmails();

// Cách dùng
List<Object[]> results = repository.findNamesAndEmails();
for (Object[] row : results) {
    String name = (String) row[0];
    String email = (String) row[1];
}
```

**Nhược điểm:** không type-safe, bất tiện

#### 2. DTO Projection (Constructor Expression)

```java
public record UserDto(String name, String email) {}

@Query("SELECT new com.example.UserDto(u.name, u.email) FROM User u")
List<UserDto> findUserDtos();
```

**Ưu điểm:** type-safe, tiện lợi

#### 3. Interface-Based (Spring Data)

```java
interface UserNameOnly {
    String getName();
    String getEmail();
}

List<UserNameOnly> findBy();
```

**Ưu điểm:** Spring tạo một proxy thông qua interface và map các cột theo tên getter. getName() -> cột "name". Nếu tên không khớp - null.

#### 4. Class-Based (Spring Data)

```java
public class UserDto {
    private String name;
    private String email;

    public UserDto(String name, String email) {
        this.name = name;
        this.email = email;
    }
}

List<UserDto> findBy();
```

### Các Ví Dụ

```java
// Aggregation
@Query("SELECT new com.example.UserStats(u.name, COUNT(o), SUM(o.total)) " +
       "FROM User u LEFT JOIN u.orders o GROUP BY u.id")
List<UserStats> findUserStats();

// Với điều kiện
@Query("SELECT new com.example.OrderSummary(o.id, o.status, u.name) " +
       "FROM Order o JOIN o.user u WHERE o.createdAt > :date")
List<OrderSummary> findRecentOrders(@Param("date") LocalDate date);
```

### Các Lỗi Thường Gặp

```java
// Không có tên class đầy đủ
@Query("SELECT new UserDto(u.name, u.email) FROM User u")  // sai

// Có tên đầy đủ
@Query("SELECT new com.example.UserDto(u.name, u.email) FROM User u")  // đúng

// Thứ tự tham số sai
public record UserDto(String email, String name) {}  // email, name
@Query("SELECT new com.example.UserDto(u.name, u.email) FROM User u")  // sai - name, email

// Đúng - thứ tự phải khớp
public record UserDto(String name, String email) {}
@Query("SELECT new com.example.UserDto(u.name, u.email) FROM User u")  // đúng
```

## Senior Level

### So Sánh Hiệu Năng

```
Entity đầy đủ:
- SELECT * -> tải tất cả các trường
- Overhead dirty checking
- Lưu trữ trong L1 cache
- O(N) bộ nhớ mỗi entity

Projection:
- SELECT các cột cụ thể
- Không có dirty checking
- Ít bộ nhớ hơn
- O(1) bộ nhớ mỗi DTO

Khác biệt:
Projection tiết kiệm bộ nhớ đáng kể (chỉ tải các cột cần thiết) và tăng tốc truy vấn (ít dữ liệu qua network hơn). Con số chính xác phụ thuộc vào kích thước entity, DB, và network.
```

### Các Pattern Nâng Cao

```java
// Pattern 1: DTO Lồng Nhau
public record OrderDto(
    Long id,
    String status,
    UserDto user,
    List<ItemDto> items
) {}

@Query("""
    SELECT new com.example.OrderDto(
        o.id, o.status,
        new com.example.UserDto(u.name, u.email),
        // items có thể tải thông qua truy vấn thứ hai với @EntityGraph hoặc
        // truy vấn riêng biệt: SELECT i FROM Item i WHERE i.orderId IN (:orderIds)
        null
    )
    FROM Order o JOIN o.user u
    WHERE o.id = :id
    """)
OrderDto findByIdWithUser(@Param("id") Long id);

// Pattern 2: Projection dựa trên Tuple
@Query("SELECT u.name as name, u.email as email FROM User u")
List<Tuple> findUsers();

List<UserDto> dtos = tuples.stream()
    .map(t -> new UserDto(t.get("name", String.class),
                          t.get("email", String.class)))
    .toList();

// Pattern 3: Projection động với Criteria API
public <T> List<T> findUsers(Class<T> type) {
    CriteriaBuilder cb = em.getCriteriaBuilder();
    CriteriaQuery<T> query = cb.createQuery(type);
    Root<User> root = query.from(User.class);

    if (type == UserDto.class) {
        query.select(cb.construct(UserDto.class,
            root.get("name"), root.get("email")));
    } else {
        query.select(root);
    }

    return em.createQuery(query).getResultList();
}
```

### Khi Nào Dùng Projection

```
Projection cho:
- Các thao tác chỉ đọc
- Response API
- Danh sách/table
- Aggregation và statistics
- Tập dữ liệu lớn

Entity đầy đủ cho:
- Các thao tác CRUD
- Khi cần tất cả các trường
- Khi cần dirty checking
- Tập dữ liệu nhỏ
```

### Best Practices

```
DTO projection cho chỉ đọc
Interface-based cho tính linh hoạt
Class-based (record) cho type-safety
Tên class đầy đủ trong JPQL
Thứ tự tham số đúng

Array projection (không type-safe)
Entity đầy đủ cho chỉ đọc
Không có tên class đầy đủ
Thứ tự tham số constructor sai
```

## Interview Cheat Sheet

**Cần phải biết:**
- Projection - chỉ tải các trường cần thiết thay vì toàn bộ entity
- 4 loại: Array (không type-safe), DTO constructor (type-safe), Interface-based (Spring), Class-based (Spring)
- Ưu điểm: ít dữ liệu từ DB hơn, không có overhead dirty checking, kiểm soát API contract
- DTO projection yêu cầu tên class đầy đủ: new com.example.UserDto(...)
- Thứ tự tham số constructor phải khớp với thứ tự SELECT
- Cho chỉ đọc/API - projection, cho CRUD - entity đầy đủ

**Các câu hỏi phụ thường gặp:**
- **DTO vs Interface-based projection?** DTO (record) - type-safe, constructor rõ ràng; Interface - Spring tạo proxy, mapping getter theo tên
- **Tại sao Array projection xấu?** Không type-safe: row[0], row[1] - lỗi khi refactor, bất tiện
- **Sự khác biệt hiệu năng?** Projection tiết kiệm bộ nhớ (chỉ tải các cột cần thiết) và tăng tốc truy vấn (ít dữ liệu qua network)
- **Có thể tạo DTO lồng nhau không?** Có - new com.example.OrderDto(new UserDto(u.name), ...) trong JPQL

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Array projection cho code production" - không type-safe, row[0] dễ hỏng
- "Không có tên class đầy đủ trong JPQL" - ClassNotFoundException
- "Entity đầy đủ cho API chỉ đọc" - dirty checking không cần thiết, nhiều bộ nhớ hơn
- "Thứ tự tham số constructor sai" - dữ liệu bị lẫn lộn, name -> email

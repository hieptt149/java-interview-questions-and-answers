# What Do thenAccept() and thenRun() Methods Do? (Các phương thức thenAccept() và thenRun() làm gì)

## 🟢 Junior Level

Cả hai phương thức đều được dùng để **hoàn tất một chuỗi** CompletableFuture:

- **`thenAccept()`** — nhận kết quả và **tiêu thụ** nó (không trả về gì)
- **`thenRun()`** — chỉ đơn giản **thực hiện một hành động**, không biết về kết quả

```java
// thenAccept — nhận kết quả
CompletableFuture.supplyAsync(() -> "Hello")
    .thenAccept(s -> System.out.println("Got: " + s));  // Got: Hello

// thenRun — không nhận kết quả
CompletableFuture.supplyAsync(() -> "Hello")
    .thenRun(() -> System.out.println("Done!"));  // Done!
```

**Analogy đơn giản:**
- `thenAccept` — nhận một gói hàng và mở nó ra
- `thenRun` — chỉ biết rằng gói hàng đã được giao

## 🟡 Middle Level

### So Sánh Chi Tiết

**thenAccept — Consumer<T>:**
```java
CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> "Hello");

// Chúng ta nhận kết quả
cf.thenAccept(result -> {
    System.out.println("Result: " + result);
    saveToDatabase(result);
});

// Kiểu: CompletableFuture<Void> — không thể tiếp tục chuỗi với một giá trị
```

**thenRun — Runnable:**
```java
CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> "Hello");

// Chỉ là một hành động sau khi hoàn thành
cf.thenRun(() -> {
    System.out.println("Task completed");
    notifyUser();
});
```

### Khi Nào Dùng Cái Nào

**thenAccept:**
```java
// Khi bạn cần kết quả
fetchDataAsync()
    .thenAccept(data -> {
        process(data);
        saveToCache(data);
    });
```

**thenRun:**
```java
// Khi kết quả không quan trọng
sendEmailAsync(email)
    .thenRun(() -> log.info("Email sent"));

// Hoặc cho side effect
saveToDatabase(entity)
    .thenRun(() -> metrics.increment("saved"));
```

### Các Lỗi Thường Gặp

1. **Cố gắng lấy kết quả trong thenRun:**
```java
CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> "Hello");

// ❌ thenRun không nhận kết quả
cf.thenRun(() -> {
    // System.out.println(result);  // result không có sẵn!
    System.out.println("Done");
});

// ✅ thenAccept nhận kết quả
cf.thenAccept(result -> System.out.println(result));
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**thenApply vs thenAccept vs thenRun:**
```java
public <U> CompletableFuture<U> thenApply(Function<T, U> fn) {
    // fn: T -> U
    // Trả về CompletableFuture<U>
}

public CompletableFuture<Void> thenAccept(Consumer<T> action) {
    // action: T -> void
    // Trả về CompletableFuture<Void>
}

public CompletableFuture<Void> thenRun(Runnable action) {
    // action: () -> void
    // Trả về CompletableFuture<Void>
}
```

**Kết quả Void:**
```java
// thenAccept và thenRun trả về CompletableFuture<Void>
// Nhưng bạn vẫn có thể tiếp tục chuỗi:
cf.thenAccept(result -> process(result))
  .thenRun(() -> notify());  // OK

cf.thenRun(() -> log.info("Done"))
  .thenAccept(v -> { });  // v — Void, vô dụng
```

### Đánh Đổi Kiến Trúc

| Phương thức         | Nhận kết quả | Trả về    | Trường hợp dùng      |
| -------------- | --------------- | ---------- | ------------- |
| **thenApply**  | ✅ T             | U          | Biến đổi|
| **thenAccept** | ✅ T             | Void       | Tiêu thụ   |
| **thenRun**    | ❌               | Void       | Side effect   |

### Edge Cases

**1. Xử lý ngoại lệ:**
```java
// Ngoại lệ trong thenAccept:
cf.thenAccept(result -> {
    throw new RuntimeException("Error processing");
}).exceptionally(ex -> {
    // Sẽ bắt được ngoại lệ
    return null;
});

// thenRun cũng bắt được ngoại lệ
cf.thenRun(() -> {
    throw new RuntimeException("Error");
}).exceptionally(ex -> {
    // Sẽ bắt được
    return null;
});
```

**2. Các phiên bản Async:**
```java
// thenAcceptAsync — thực thi trong ForkJoinPool
cf.thenAcceptAsync(result -> process(result));

// Với Executor tùy chỉnh
cf.thenAcceptAsync(result -> process(result), executor);

// thenRunAsync — cách tiếp cận tương tự
cf.thenRunAsync(() -> notify(), executor);
```

### Hiệu Năng

```
thenApply: ~5 ns (function)
thenAccept: ~5 ns (consumer)
thenRun: ~3 ns (runnable — không có quyền truy cập vào T)

thenAcceptAsync / thenRunAsync:
- + ~1μs cho mỗi lần chuyển thread
```

### Kinh Nghiệm Production

**Logging và metrics:**
```java
@Service
public class OrderService {
    public CompletableFuture<Order> createOrder(OrderRequest req) {
        return orderRepository.saveAsync(req)
            .thenApply(order -> {
                metrics.increment("orders.created");
                eventPublisher.publish(new OrderCreatedEvent(order));
                return order;  // thenApply trả về kết quả — order nằm trong phạm vi
            });
    }

    // thenRun cho side effect
    public CompletableFuture<Void> sendNotification(Order order) {
        return notificationClient.sendAsync(order)
            .thenRun(() -> log.info("Notification sent for order {}", order.id()));
    }
}
```

### Best Practices

```java
// ✅ thenAccept để tiêu thụ kết quả
cf.thenAccept(result -> process(result));

// ✅ thenRun cho side effect
cf.thenRun(() -> metrics.increment("done"));

// ✅ Phiên bản Async với Executor
cf.thenAcceptAsync(result -> process(result), executor);

// ❌ thenRun khi bạn cần kết quả
// ❌ thenAccept khi kết quả không quan trọng
// ❌ Thao tác chặn trong thenAccept/thenRun
```

### Khi Nào KHÔNG Nên Dùng thenRun

Khi kết quả của giai đoạn trước cần thiết cho việc xử lý tiếp theo.
thenRun = "làm gì đó sau, nhưng tôi không quan tâm đến kết quả".

```java
// ❌ thenRun — order không thể truy cập được
orderRepository.saveAsync(req)
    .thenRun(() -> notifyUser(order.id()));  // lỗi biên dịch: không tìm thấy order

// ✅ thenAccept — order có thể truy cập được
orderRepository.saveAsync(req)
    .thenAccept(order -> notifyUser(order.id()));
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- thenAccept(Consumer<T>) — nhận kết quả T, trả về CompletableFuture<Void>
- thenRun(Runnable) — KHÔNG nhận kết quả, trả về CompletableFuture<Void>
- thenAccept để tiêu thụ kết quả, thenRun cho side effect (logging, metrics)
- Cả hai đều có phiên bản Async với việc chuyển thread
- thenApply vs thenAccept: thenApply trả về U, thenAccept trả về Void

**Các câu hỏi phụ thường gặp:**
- **Khi nào dùng thenAccept, khi nào dùng thenRun?** — thenAccept khi bạn cần kết quả của CF trước, thenRun khi kết quả không quan trọng
- **Có thể tiếp tục chuỗi sau thenAccept không?** — Có, nhưng liên kết tiếp theo nhận Void
- **thenAccept có chặn thread không?** — Không, nó thực thi như một callback khi CF hoàn thành
- **thenAccept vs thenApply — khi nào dùng cái nào?** — thenApply cho biến đổi (trả về U), thenAccept cho tiêu thụ (trả về Void)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "thenRun nhận kết quả của CF trước" — thenRun dùng Runnable, không có tham số
- "thenAccept kết thúc chuỗi vĩnh viễn" — bạn có thể tiếp tục, nhưng với Void
- "thenAcceptAsync luôn tốt hơn thenAccept" — Async thêm ~1μs overhead, quá mức cho các thao tác nhẹ

# What Happens When Trying to Create an Instance of Generic Type via new T()? (Điều gì xảy ra khi cố gắng tạo một instance của kiểu generic thông qua new T())

## 🟢 Junior Level

**Bạn không thể tạo một instance** của kiểu generic thông qua `new T()`. Đây là một lỗi biên dịch.

```java
public class Box<T> {
    private T value;

    public Box() {
        value = new T();  // ❌ lỗi biên dịch: "cannot instantiate T"
    }
}
```

**Tại sao:** Do **type erasure**, trình biên dịch không biết `T` đại diện cho kiểu gì tại runtime. Sau khi biên dịch, `T` trở thành `Object`, và `new Object()` không phải là điều bạn muốn.

**Giải pháp:**

```java
// Giải pháp 1: Truyền Class<T>
public class Box<T> {
    private T value;

    public Box(Class<T> type) throws Exception {
        value = type.getDeclaredConstructor().newInstance();
    }
}

// Giải pháp 2: Factory (Supplier)
public class Box<T> {
    private T value;

    public Box(Supplier<T> factory) {
        value = factory.get();
    }
}

// Sử dụng
Box<String> box1 = new Box<>(String.class);
Box<String> box2 = new Box<>(() -> "default");
```

## 🟡 Middle Level

### Tại Sao Không Được Phép?

**Type erasure:**
```java
public class Box<T> {
    public Box() {
        value = new T();  // ❌ điều này có nghĩa gì sau erasure?
    }
}

// Sau khi biên dịch:
public class Box {
    public Box() {
        value = new Object();  // T -> Object
        // Nhưng đây không phải là điều developer mong muốn!
    }
}
```

**Vấn đề:** Không có thông tin về constructor của `T`. Nếu `T` không có constructor không tham số thì sao?

### Các Giải Pháp Hoạt Động

**1. Cách tiếp cận Class<T>:**
```java
public class Factory<T> {
    private final Class<T> type;

    public Factory(Class<T> type) {
        this.type = type;
    }

    public T create() throws Exception {
        return type.getDeclaredConstructor().newInstance();
    }
}

Factory<String> stringFactory = new Factory<>(String.class);
String s = stringFactory.create();  // ""
```

**2. Cách tiếp cận Supplier:**
```java
public class Box<T> {
    private final Supplier<T> factory;

    public Box(Supplier<T> factory) {
        this.factory = factory;
    }

    public T create() {
        return factory.get();
    }
}

Box<User> userBox = new Box<>(User::new);
User user = userBox.create();
```

**3. Phương thức factory abstract:**
```java
public abstract class Creator<T> {
    protected abstract T createInstance();

    public T createAndProcess() {
        T instance = createInstance();
        // xử lý
        return instance;
    }
}

public class UserCreator extends Creator<User> {
    @Override
    protected User createInstance() {
        return new User();
    }
}
```

### Các Lỗi Thường Gặp

1. **Cố gắng bỏ qua qua cast:**
```java
public class Box<T> {
    public T create() {
        return (T) new Object();  // ⚠️ unchecked cast
        // Chỉ hoạt động nếu T = Object
        // ClassCastException cho các kiểu khác
    }
}
```

2. **Reflection mà không kiểm tra:**
```java
public T create(Class<T> type) throws Exception {
    return type.newInstance();  // deprecated trong Java 9+
}

// ✅ Tốt hơn
public T create(Class<T> type) throws Exception {
    return type.getDeclaredConstructor().newInstance();
}
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Tại sao trình biên dịch cấm điều này:**
```
JLS 15.9:
- new T() là bất khả thi vì T là một type variable
- Type variable không có metadata constructor trong class file.
- JVM về mặt kỹ thuật không thể phát ra một chỉ thị new cho T.
- Sau erasure T -> Object hoặc bound
```

**Cách tiếp cận Reflection:**
```java
public T create(Class<T> type) {
    try {
        Constructor<T> ctor = type.getDeclaredConstructor();
        return ctor.newInstance();
    } catch (NoSuchMethodException e) {
        // T không có constructor không tham số
        throw new RuntimeException(e);
    }
}
```

### Đánh Đổi Kiến Trúc

**Các cách tiếp cận để tạo T:**

| Cách tiếp cận            | Ưu điểm                      | Nhược điểm                            |
| ------------------- | ------------------------- | ------------------------------- |
| **Class<T>**        | An toàn kiểu, đơn giản         | Cần constructor không tham số        |
| **Supplier<T>**     | Linh hoạt, bất kỳ constructor nào | Cần truyền factory            |
| **Phương thức abstract** | Phong cách OOP                 | Cần một subclass                 |
| **Unchecked cast**  | Đơn giản                    | Không an toàn, nguy cơ ClassCastException |

### Edge Cases

**1. Bounded type với constructor không tham số:**
```java
public class Box<T extends Runnable> {
    public T create(Class<T> type) throws Exception {
        // T phải có constructor không tham số
        return type.getDeclaredConstructor().newInstance();
    }
}
```

**2. Constructor với tham số:**
```java
public T create(Class<T> type, String name) throws Exception {
    return type.getConstructor(String.class)
        .newInstance(name);
}
```

**3. Tạo mảng generic:**
```java
// Cũng không được phép
public class Box<T> {
    private T[] items = new T[10];  // ❌ lỗi

    // ✅ Giải pháp
    private T[] items = (T[]) new Object[10];
}
```

### Hiệu Năng

```
Các cách để tạo T:
- new T(): N/A (không được phép)
- Class.newInstance(): ~50-100 ns (deprecated)
// Giá trị xấp xỉ. Phụ thuộc JVM, mức tối ưu hóa, inline.
- Constructor.newInstance(): ~100-200 ns
- Supplier.get(): ~1-5 ns (lời gọi thông thường)
- Unchecked cast: ~1 ns (nhưng không an toàn)

Supplier — cách tiếp cận runtime nhanh nhất
```

### Kinh Nghiệm Production

**Spring Bean Factory:**
```java
@Component
public class EntityFactory {
    public <T> T create(Class<T> type) {
        return applicationContext.getBean(type);
    }
}

// Sử dụng
User user = entityFactory.create(User.class);
```

**Pattern Builder:**
```java
public class Builder<T> {
    private final Supplier<T> factory;
    private final Map<String, Object> properties = new HashMap<>();

    public Builder(Supplier<T> factory) {
        this.factory = factory;
    }

    public Builder<T> with(String name, Object value) {
        properties.put(name, value);
        return this;
    }

    public T build() {
        T instance = factory.get();
        // inject property
        return instance;
    }
}

User user = new Builder<>(User::new)
    .with("name", "John")
    .with("age", 25)
    .build();
```

### Best Practices

```java
// ✅ Supplier cho tính linh hoạt
public class Box<T> {
    private final Supplier<T> factory;
    public Box(Supplier<T> factory) { this.factory = factory; }
    public T create() { return factory.get(); }
}

// ✅ Class<T> cho các trường hợp đơn giản
public T create(Class<T> type) {
    return type.getDeclaredConstructor().newInstance();
}

// ✅ Phương thức factory abstract
protected abstract T createInstance();

// ❌ new T()
// ❌ Unchecked cast không cần thiết
// ❌ Class.newInstance() (deprecated)
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- `new T()` — lỗi biên dịch: "cannot instantiate T"
- Lý do: type erasure — sau khi biên dịch T -> Object, JVM không biết constructor của T
- Giải pháp 1: `Class<T>` — `type.getDeclaredConstructor().newInstance()`
- Giải pháp 2: `Supplier<T>` — `factory.get()` — cách tiếp cận linh hoạt và nhanh nhất
- Giải pháp 3: Phương thức factory abstract — subclass triển khai việc tạo
- `Class.newInstance()` deprecated trong Java 9+, dùng `getDeclaredConstructor().newInstance()`

**Các câu hỏi phụ thường gặp:**
- **Tại sao không thể làm new T()?** — Type erasure: T được thay bằng Object, không có thông tin constructor
- **Cách tiếp cận nào tốt hơn — Class<T> hay Supplier?** — Supplier linh hoạt hơn và nhanh hơn (~1-5 ns so với ~100-200 ns)
- **Có thể tạo T với tham số qua Class không?** — Có: `type.getConstructor(String.class).newInstance(name)`
- **Pattern TypeReference là gì?** — Phong cách Jackson: `new TypeReference<User>() {}` để lấy kiểu generic

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "new T() hoạt động qua unchecked cast" — Đây là lỗi biên dịch, không phải cảnh báo
- ❌ "Class.newInstance() là cách tốt nhất" — Deprecated trong Java 9+, dùng getDeclaredConstructor
- ❌ "Supplier chậm hơn Class" — Supplier nhanh hơn (~1-5 ns so với ~100-200 ns)
- ❌ "Bạn có thể tạo T qua reflection mà không cần Class" — Bạn cần Class<T> hoặc Supplier

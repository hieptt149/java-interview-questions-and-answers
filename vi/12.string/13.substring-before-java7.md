# What substring() Does and How It Worked Before Java 7 (substring() làm gì và nó hoạt động như thế nào trước Java 7)

## 🟢 Junior Level

Method `substring()` trả về một phần của chuỗi — một chuỗi con từ một index được chỉ định đến cuối hoặc đến một index khác.

**Ví dụ:**
```java
String text = "Hello, World!";
String sub = text.substring(0, 5); // "Hello"
String sub2 = text.substring(7);   // "World!"
```

**Chi tiết quan trọng:** Trong các phiên bản Java cũ (trước 7u6) `substring()` hoạt động một cách "khôn khéo" — nó không sao chép dữ liệu, mà tham chiếu đến cùng mảng ký tự với chuỗi gốc. Điều này gây ra các vấn đề về bộ nhớ.

Trong Java hiện đại, `substring()` luôn tạo một **bản sao** của các ký tự cần thiết — điều này an toàn và dễ dự đoán.

## 🟡 Middle Level

### Cách substring() Hoạt Động Hiện Nay (Java 7u6+)

```java
String text = "Hello, World!";
String sub = text.substring(7, 12); // "World"
```

Hiện thực hiện đại:
1. Tính độ dài chuỗi con
2. Tạo một mảng `byte[]` **mới** (Java 9+) hoặc `char[]` (Java 7-8)
3. Sao chép chỉ dữ liệu cần thiết
4. Trả về một object `String` mới

**Độ phức tạp:** O(n) — tỷ lệ thuận với độ dài chuỗi con (sao chép dữ liệu).

### Cách Nó Hoạt Động Trước Java 7u6

Trước Java 7u6, object `String` chứa:
- `char[] value` — tham chiếu đến mảng ký tự
- `int offset` — vị trí bắt đầu của chuỗi trong mảng
- `int count` — độ dài chuỗi

`substring()` tạo một `String` mới với cùng `value`, nhưng `offset` và `count` khác nhau.

**Ưu điểm:** O(1) — tức thì, không sao chép.
**Nhược điểm:** Rò rỉ bộ nhớ — một chuỗi con nhỏ giữ toàn bộ mảng cha khổng lồ.

### Các Lỗi Điển Hình
1. **Lỗi:** `substring(0, 5)` cho một chuỗi 3 ký tự
   **Giải pháp:** Kiểm tra giới hạn hoặc dùng `Math.min`

2. **Lỗi:** Kỳ vọng `substring()` sửa đổi bản gốc
   **Giải pháp:** `substring()` trả về một chuỗi mới, bản gốc không thay đổi

## 🔴 Senior Level

### Hiện Thực Nội Bộ

**Trước Java 7u6 (mảng dùng chung):**
```java
// JDK 6
String(int offset, int count, char[] value) {
    this.value = value;     // Tham chiếu dùng chung!
    this.offset = offset;
    this.count = count;
}

String substring(int beginIndex, int endIndex) {
    // Kiểm tra giới hạn
    // Tạo String mới với cùng char[] value
    return new String(offset + beginIndex, endIndex - beginIndex, value);
}
```

**Java 7u6 — Java 8 (sao chép):**
```java
// JDK 7u6+
String substring(int beginIndex, int endIndex) {
    // Kiểm tra giới hạn
    int subLen = endIndex - beginIndex;
    // Sao chép dữ liệu vào mảng mới
    return new String(value, beginIndex, subLen);
    // new String(...) gọi Arrays.copyOfRange
}
```

**Java 9+ (Compact String):**
```java
// JDK 9+ — byte[] thay vì char[]
String substring(int beginIndex, int endIndex) {
    // Kiểm tra giới hạn
    int subLen = endIndex - beginIndex;
    // Sao chép các byte có tính đến coder (LATIN1/UTF16)
    return isLatin1()
        ? StringLatin1.newString(value, beginIndex, subLen)
        : StringUTF16.newString(value, beginIndex, subLen);
}
```

### Đánh Đổi Về Kiến Trúc (Trade-off)

**Cách tiếp cận cũ (mảng dùng chung):**
- Ưu điểm: O(1), zero-copy, tiết kiệm bộ nhớ với nhiều chuỗi con
- Nhược điểm: Rò rỉ bộ nhớ — chuỗi con 5 ký tự giữ 10MB dữ liệu cha

**Cách tiếp cận mới (sao chép):**
- Ưu điểm: Bộ nhớ dễ dự đoán, bản gốc có thể được GC
- Nhược điểm: O(n) — sao chép dữ liệu, nhiều cấp phát hơn

### Các Trường Hợp Biên

1. **Rò Rỉ Bộ Nhớ (Java 6):**
   ```java
   String huge = readLargeFile(); // 100MB
   String small = huge.substring(0, 10); // 10 ký tự
   huge = null; // "Xóa" huge
   // NHƯNG: small.value vẫn tham chiếu đến mảng 100MB!
   ```
   Giải pháp tạm thời trong Java 6: `new String(huge.substring(0, 10))` — sao chép bắt buộc.

2. **IndexOutOfBoundsException:**
   ```java
   "abc".substring(0, 5); // Ném exception
   ```

3. **Chuỗi con rỗng:**
   ```java
   "abc".substring(2, 2); // "" — chuỗi rỗng (không phải null!)
   ```

### Hiệu Năng
| Thao tác        | Java 6 (dùng chung) | Java 7+ (sao chép) | Java 9+ (compact) |
| ---------------- | --------------- | ----------------- | ----------------- |
| substring(0, 10) | O(1), 0 byte   | O(n), ~48 byte   | O(n), ~34 byte   |
| substring từ 1MB| O(1), 0 byte  | O(n), ~2MB cấp phát  | O(n), ~1MB (Latin1)|
| Nguy cơ rò rỉ bộ nhớ | Cao            | Không            | Không            |

// ~48 byte = header String (24) + header byte[] (16) + 10 byte dữ liệu, làm tròn lên.
// Java 6: ~20000 byte — đây là kích thước của char[] dùng chung của cha (10,000 ký tự * 2 byte),
// không phải kích thước của bản thân object chuỗi con.

### Kinh Nghiệm Production
**Kịch bản:** Parse log (Java 6):
- Trích xuất `requestId` (36 ký tự) từ một dòng log 10MB
- 100K request → 100K chuỗi con → mỗi cái giữ 10MB → OOM
- Sửa lỗi: `new String(line.substring(0, 36))` — sao chép bắt buộc

**Kịch bản:** Migration Java 8 → Java 17:
- Trong Java 8, `substring()` sao chép `char[]` (2 byte/ký tự)
- Trong Java 17, `substring()` sao chép `byte[]` (1 byte/ký tự cho Latin1)
- Kết quả: -50% bộ nhớ cho các chuỗi con văn bản Latin

### Giám Sát
```java
// JOL — kích thước chuỗi con thực tế
String huge = "A".repeat(10000);
String sub = huge.substring(0, 5);
System.out.println(GraphLayout.parseInstance(sub).toFootprint());
// Java 7+: ~48 byte (bản sao riêng)
// Java 6:  ~20000 byte (chia sẻ mảng của cha!)
```

### Best Practices Cho Highload
- Trong Java hiện đại: `substring()` an toàn — dùng mà không lo lắng
- Cho việc parse zero-copy: làm việc với `CharSequence`, `CharBuffer`, hoặc `StringView` tùy chỉnh
- Nếu bạn cần một chuỗi con từ văn bản khổng lồ và cha không còn cần thiết: `substring()` tự động giải phóng mảng cha khi GC
- Cân nhắc `text.substring()` + `intern()` cho các chuỗi con lặp lại thường xuyên

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `substring(begin, end)` trả về chuỗi con từ `begin` đến `end` (không bao gồm)
- Trước Java 7u6: `substring()` chia sẻ `char[]` của cha — O(1), nhưng gây rò rỉ bộ nhớ
- Java 7u6+: `substring()` sao chép dữ liệu — O(n), nhưng an toàn
- Java 9+: sao chép `byte[]` có tính đến coder (Latin-1/UTF-16)
- Rò rỉ bộ nhớ trong Java 6: chuỗi con nhỏ giữ toàn bộ mảng cha khổng lồ
- Giải pháp tạm thời trong Java 6: `new String(substring())` — sao chép bắt buộc

**Các câu hỏi phụ thường gặp:**
- **Tại sao `substring()` được thay đổi trong Java 7?** — Phiên bản cũ gây ra các rò rỉ bộ nhớ ẩn: chuỗi con 5 ký tự giữ 10MB dữ liệu cha.
- **Độ phức tạp của `substring()` hiện nay là gì?** — O(n) — sao chép dữ liệu. Không phải O(1) như trước.
- **`new String(substring())` có cần trong Java hiện đại không?** — Không, đó là một cấp phát thừa. `substring()` đã sao chép rồi.
- **Điều gì xảy ra với `substring()` vượt ngoài giới hạn chuỗi?** — `IndexOutOfBoundsException`.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "`substring()` hoạt động trong O(1)" — chỉ trong Java 6, giờ là O(n)
- ❌ "`new String(substring())` — tối ưu hóa" — là cần thiết trong Java 6, giờ dư thừa
- ❌ "`substring()` sửa đổi bản gốc" — String bất biến, luôn trả về một chuỗi mới
- ❌ "Rò rỉ bộ nhớ từ `substring()` — vấn đề hiện tại" — đã được sửa trong Java 7u6

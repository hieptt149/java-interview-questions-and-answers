# How to Avoid Infinite Recursion When Serializing Entities (Cách tránh đệ quy vô hạn khi serialize Entity)

## Overview

Khi serialize các mối quan hệ hai chiều (ví dụ, sang JSON cho REST API), đệ quy vô hạn xảy ra, dẫn đến StackOverflowError. Có một số cách tiếp cận để giải quyết vấn đề này.

---

## Junior Level

### Vấn Đề

Khi serialize các mối quan hệ hai chiều, **đệ quy vô hạn** xảy ra:

```java
@Entity
public class Order {
    @ManyToOne
    private User user;
}

@Entity
public class User {
    @OneToMany(mappedBy = "user")
    private List<Order> orders;
}

// Serialize JSON:
// Order -> User -> Orders -> User -> Orders -> ... -> StackOverflowError
```

### Các Giải Pháp

1. **`@JsonIgnore`** - bỏ qua trường
2. **`@JsonManagedReference` / `@JsonBackReference`** - phá vỡ chu trình
3. **DTO projection** - dùng DTO thay vì entity

Đây là các annotation đặc thù Jackson (không phải JPA!). Chúng chỉ hoạt động khi serialize thông qua Jackson trong các REST controller Spring Boot.

```java
// Giải pháp 1: @JsonIgnore
@Entity
public class User {
    @OneToMany(mappedBy = "user")
    @JsonIgnore  // không serialize
    private List<Order> orders;
}

// Giải pháp 2: Managed/BackReference
@Entity
public class Order {
    @ManyToOne
    @JsonBackReference  // không serialize
    private User user;
}

@Entity
public class User {
    @OneToMany(mappedBy = "user")
    @JsonManagedReference  // serialize
    private List<Order> orders;
}
```

## Middle Level

### Các Giải Pháp Chi Tiết

#### @JsonIgnore

```java
@Entity
public class User {
    @OneToMany(mappedBy = "user")
    @JsonIgnore  // hoàn toàn bỏ qua khi serialize
    private List<Order> orders;
}

// GET /users/1
// { "id": 1, "name": "John" }  // không có orders
```

#### @JsonManagedReference / @JsonBackReference

```java
@Entity
public class User {
    @OneToMany(mappedBy = "user")
    @JsonManagedReference  // serialize phía này
    private List<Order> orders;
}

@Entity
public class Order {
    @ManyToOne
    @JsonBackReference  // KHÔNG serialize phía này
    private User user;
}

// GET /users/1
// { "id": 1, "name": "John", "orders": [
//     { "id": 1, "status": "new" },  // không có user
//     { "id": 2, "status": " shipped" }
// ]}
```

#### DTO (Giải Pháp Tốt Nhất)

```java
// DTO - kiểm soát hoàn toàn việc serialize
public record OrderDto(
    Long id,
    String status,
    String userName,
    LocalDateTime createdAt
) {}

// Mapping
@Query("""
    SELECT new com.example.OrderDto(
        o.id, o.status, u.name, o.createdAt
    )
    FROM Order o JOIN o.user u
    WHERE o.id = :id
    """)
OrderDto findOrderDto(@Param("id") Long id);

// GET /orders/1
// { "id": 1, "status": "new", "userName": "John", "createdAt": "..." }
```

### Các Lỗi Thường Gặp

```java
// Serialize entity trực tiếp
@RestController
public class OrderController {
    @GetMapping("/orders/{id}")
    public Order getOrder(@PathVariable Long id) {
        return service.getOrder(id);  // StackOverflowError
    }
}

// DTO thay vì entity
@GetMapping("/orders/{id}")
public OrderDto getOrder(@PathVariable Long id) {
    return service.getOrderDto(id);  // đúng
}
```

## Senior Level

### @JsonIdentityInfo

```java
@Entity
@JsonIdentityInfo(
    generator = ObjectIdGenerators.PropertyGenerator.class,
    property = "id"
)
public class User {
    @OneToMany(mappedBy = "user")
    private List<Order> orders;
}

// JSON: User với ID, Orders tham chiếu đến User ID
// {
//     "id": 1,
//     "name": "John",
//     "orders": [
//         { "id": 1, "status": "new", "user": 1 },
//         { "id": 2, "status": "shipped", "user": 1 }
//     ]
// }
// Cơ chế: lần xuất hiện đầu tiên của object được serialize đầy đủ (với "@id": 1).
// Các tham chiếu tiếp theo - chỉ ID: {"@id": 1}. Điều này ngăn ngừa vòng lặp vô hạn.
```

### Cách Tiếp Cận Kiến Trúc

```
Quy tắc: Không bao giờ serialize các entity JPA trực tiếp.

Tại sao:
1. Đệ quy vô hạn
2. Tải trường lazy bên ngoài transaction
3. Lộ cấu trúc DB nội bộ
4. Không thể kiểm soát API contract
5. Vấn đề hiệu năng

**LazyInitializationException khi serialize:** khi REST controller trả về entity,
Jackson serializer cố truy cập trường LAZY bên ngoài transaction -> exception.
Đây là một trong những vấn đề production phổ biến nhất.

Giải pháp: DTO pattern
```

### DTO Mapping

```java
// Pattern 1: Constructor record trong JPQL
@Query("""
    SELECT new com.example.UserDto(
        u.id, u.name, u.email,
        (SELECT COUNT(o) FROM Order o WHERE o.user.id = u.id)
    )
    FROM User u
    """)
List<UserDto> findAllUsers();

// Pattern 2: MapStruct
@Mapper(componentModel = "spring")
public interface OrderMapper {
    @Mapping(source = "user.name", target = "userName")
    @Mapping(source = "items", target = "items")
    OrderDto toDto(Order order);
}

// Pattern 3: Phương thức trong entity
@Entity
public class Order {
    public OrderDto toDto() {
        return new OrderDto(id, status, user.getName(), createdAt);
    }
}
```

### Best Practices

```
DTO projection (giải pháp tốt nhất)
@JsonManagedReference/BackReference (giải pháp nhanh)
@JsonIgnore cho một phía
@JsonIdentityInfo cho các tham chiếu vòng lặp
Không bao giờ serialize entity trực tiếp

Không có annotation (StackOverflowError)
EAGER + serialize
Trả về entity trực tiếp từ REST controller
Bỏ qua lazy loading khi serialize
```

## Interview Cheat Sheet

**Cần phải biết:**
- Các mối quan hệ hai chiều -> đệ quy vô hạn khi serialize JSON -> StackOverflowError
- 4 giải pháp: @JsonIgnore, @JsonManagedReference/@JsonBackReference, @JsonIdentityInfo, DTO projection
- DTO projection là giải pháp tốt nhất: kiểm soát API hoàn toàn, không có vấn đề lazy, cô lập contract
- @JsonManagedReference serialize parent -> child, @JsonBackReference bỏ qua child -> parent
- Không bao giờ trả về entity trực tiếp từ REST controller
- LazyInitializationException khi serialize - Jackson truy cập LAZY bên ngoài @Transactional

**Các câu hỏi phụ thường gặp:**
- **Tại sao DTO tốt hơn annotation?** Cô lập API contract, không có vấn đề lazy, kiểm soát trường, hiệu năng
- **@JsonIdentityInfo hoạt động như thế nào?** Lần xuất hiện đầu tiên - object đầy đủ với "@id", tiếp theo - chỉ ID
- **LazyInitializationException khi serialize là gì?** Jackson cố đọc trường LAZY bên ngoài @Transactional
- **Tại sao dùng MapStruct?** Mapping entity -> DTO tự động, ít boilerplate code hơn

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi trả về entity từ REST controller" - StackOverflowError + LazyInitializationException
- "EAGER để tránh vấn đề serialize" - tạo ra N+1, không giải quyết nguyên nhân gốc rễ
- "Không có annotation - hy vọng mọi thứ ổn" - StackOverflowError chắc chắn
- "Tôi serialize entity trực tiếp cho đơn giản" - nợ kỹ thuật, lộ cấu trúc DB

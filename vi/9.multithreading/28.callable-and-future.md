# What are Callable and Future? (Callable và Future là gì?)

`Callable` và `Future` là hai interface từ `java.util.concurrent` giải quyết các hạn chế nền tảng của `Runnable`. Nếu Runnable mô tả một tác vụ không có kết quả (void run()), thì **Callable** mô tả một tác vụ có kết quả (V call()), và **Future** là một "lời hứa" về kết quả đó, thứ có thể được lấy sau.

**Tại sao cần cái này:** trong các ứng dụng thực tế, hầu hết các tác vụ đều trả về một kết quả (phản hồi DB, phản hồi HTTP, kết quả tính toán). Runnable không thể trả về một giá trị và cũng không thể ném một checked exception — làm cho nó không phù hợp cho nhiều kịch bản.

---

## Junior Level

### Hiểu biết cơ bản

`Callable` và `Future` là các interface từ `java.util.concurrent` giải quyết các hạn chế của Runnable:

| Vấn đề của Runnable             | Giải pháp                                      |
| -------------------------------- | ---------------------------------------------- |
| Không thể trả về một kết quả     | **Callable** — trả về kết quả kiểu V           |
| Không thể ném checked exception  | **Callable** — method `call() throws Exception`|
| Không thể kiểm tra trạng thái tác vụ | **Future** — trạng thái, kết quả, hủy       |

**Callable** — giống Runnable, nhưng có một kết quả. Bạn định nghĩa một tác vụ tính toán một cái gì đó và trả về nó. **Future** — một "biên nhận" từ ExecutorService: bạn đã submit một Callable để thực thi và nhận về một Future, thứ bạn có thể dùng sau để lấy kết quả.

### Callable<V>

```java
// Callable — giống Runnable, nhưng trả về một kết quả
Callable<String> task = () -> {
    // Thao tác dài
    return "Result!";
};

// Runnable — không trả về gì
Runnable runnable = () -> {
    System.out.println("No result");
};
```

### Future<V>

```java
ExecutorService executor = Executors.newFixedThreadPool(2);

// submit trả về một Future
Future<String> future = executor.submit(() -> {
    Thread.sleep(2000);
    return "Done!";
});

// Kiểm tra trạng thái
System.out.println("Task done? " + future.isDone()); // false

// Lấy kết quả (chặn cho tới khi hoàn thành!)
String result = future.get(); // Chờ 2 giây...
System.out.println(result);   // "Done!"

System.out.println("Task done? " + future.isDone()); // true
```

### Ví dụ đơn giản

```java
Callable<Integer> calculateTask = () -> {
    int sum = 0;
    for (int i = 1; i <= 100; i++) {
        sum += i;
    }
    return sum;
};

Future<Integer> future = executor.submit(calculateTask);
Integer result = future.get(); // Chặn cho tới khi hoàn thành
System.out.println("Sum: " + result); // 5050
```

## Middle Level

### Callable vs Runnable

| Đặc điểm                      | Runnable      | Callable<V>                    |
| ----------------------------- | ------------- | ------------------------------ |
| **Method**                    | `void run()`  | `V call() throws Exception`    |
| **Trả về kết quả**            | Không         | Có                             |
| **Checked Exception**         | Không         | Có                             |
| **Functional interface**      | Có            | Có                             |

```java
// Runnable:
Runnable r = () -> System.out.println("Hello");

// Callable:
Callable<String> c = () -> {
    if (error) throw new IOException("Error!"); // Checked!
    return "Success";
};
```

### Future — Các method

| Method                | Mô tả                           |
| --------------------- | ------------------------------- |
| `get()`               | Lấy kết quả (chặn)              |
| `get(timeout, unit)`  | Lấy với timeout                 |
| `isDone()`            | Tác vụ đã hoàn thành?           |
| `isCancelled()`       | Tác vụ đã bị hủy?               |
| `cancel(mayInterrupt)`| Hủy tác vụ                      |

### Future với Timeout

```java
Future<String> future = executor.submit(() -> {
    Thread.sleep(10000); // Tác vụ dài
    return "Result";
});

try {
    String result = future.get(3, TimeUnit.SECONDS);
    System.out.println(result);
} catch (TimeoutException e) {
    future.cancel(true); // Hủy tác vụ
    System.out.println("Task didn't finish in time");
}
```

### invokeAll() — Chờ TẤT CẢ các tác vụ

```java
List<Callable<String>> tasks = List.of(
    () -> "Task 1",
    () -> "Task 2",
    () -> "Task 3"
);

// Chặn cho tới khi TẤT CẢ các tác vụ hoàn thành
List<Future<String>> futures = executor.invokeAll(tasks);

for (Future<String> f : futures) {
    System.out.println(f.get()); // Task 1, Task 2, Task 3
}
```

### invokeAny() — Chờ tác vụ ĐẦU TIÊN

```java
List<Callable<String>> tasks = List.of(
    () -> { Thread.sleep(3000); return "Slow"; },
    () -> { Thread.sleep(1000); return "Fast"; },
    () -> { Thread.sleep(2000); return "Medium"; }
);

// Trả về kết quả của tác vụ hoàn thành ĐẦU TIÊN
// Các tác vụ khác tự động bị hủy
String result = executor.invokeAny(tasks); // "Fast"
```

### Hủy tác vụ

```java
Future<?> future = executor.submit(() -> {
    for (int i = 0; i < 1_000_000; i++) {
        // Quan trọng: kiểm tra interruption!
        if (Thread.currentThread().isInterrupted()) {
            return; // Tác vụ bị hủy
        }
        process(i);
    }
});

// Hủy
boolean cancelled = future.cancel(true);
// true = gửi interrupt() tới thread
// Nhưng điều này KHÔNG đảm bảo dừng — tác vụ phải kiểm tra isInterrupted()!
```

## Senior Level

### Bên trong: FutureTask

Khi bạn gọi `executor.submit(callable)`, executor bọc Callable của bạn trong một object `FutureTask` nội bộ:

```java
// Đơn giản hóa
public class FutureTask<V> implements RunnableFuture<V> {
    private volatile int state; // NEW, COMPLETING, NORMAL, EXCEPTIONAL, CANCELLED
    private Callable<V> callable;
    private Object outcome;     // Kết quả hoặc exception

    public V get() throws InterruptedException, ExecutionException {
        if (state < COMPLETING) {
            // Chặn qua AwaitNode (hàng đợi chờ)
            awaitDone(false, 0L);
        }
        return report(state);
    }
}
```

### State Machine của FutureTask

| Trạng thái      | Mô tả                                  |
| --------------- | -------------------------------------- |
| **NEW**         | Tác vụ đã tạo                          |
| **COMPLETING**  | Kết quả đang được ghi (chuyển tiếp)    |
| **NORMAL**      | Hoàn thành thành công                  |
| **EXCEPTIONAL** | Exception được ném                     |
| **CANCELLED**   | Tác vụ bị hủy (trước khi khởi chạy)    |
| **INTERRUPTED** | Tác vụ bị hủy (bị interrupt)           |

### Vấn đề với get() blocking

```java
// get() CHẶN thread hiện tại
Future<String> future = executor.submit(callable);
String result = future.get(); // Thread bận — không thể xử lý các request khác

// Nếu bạn có 100 thread và mỗi cái chờ trên future.get() → hệ thống "dừng lại"
```

**Giải pháp:** `CompletableFuture` (Java 8+):

```java
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
    return fetchData();
});

future.thenAccept(result -> {
    // Callback — KHÔNG chặn!
    System.out.println(result);
});
// Thread rảnh — có thể tiếp tục xử lý các request
```

### ExecutionException — Bóc tách nguyên nhân (Cause)

```java
Future<Integer> future = executor.submit(() -> {
    throw new IOException("Database connection failed");
});

try {
    future.get();
} catch (ExecutionException e) {
    // e — ExecutionException
    // e.getCause() — IOException: Database connection failed
    Throwable cause = e.getCause();
    System.out.println(cause.getClass()); // java.io.IOException
    System.out.println(cause.getMessage()); // Database connection failed
}
```

### Kết quả bị mất

```java
Future<String> future = executor.submit(() -> "Result");

future.cancel(true); // Đã hủy

try {
    future.get(); // → CancellationException
} catch (CancellationException e) {
    System.out.println("Task was cancelled");
}
```

### invokeAll() với Timeout

```java
// LUÔN dùng timeout!
List<Future<String>> futures = executor.invokeAll(tasks, 10, TimeUnit.SECONDS);

// Nếu ít nhất một tác vụ "treo" — TimeoutException cho tất cả
```

### Memory Overhead

```
Mỗi FutureTask = object (~48 byte)
Triệu tác vụ/giây = triệu object → áp lực GC

Cho virtual thread — tốt hơn nên dùng các cơ chế nhẹ hơn
```

### Chẩn đoán

#### Không chặn

```java
Future<?> future = executor.submit(task);

// Kiểm tra không chặn
if (future.isDone()) {
    System.out.println("Completed");
}
if (future.isCancelled()) {
    System.out.println("Cancelled");
}
```

#### ListenableFuture (Guava)

Cho các dự án cũ không có Java 8+:

```java
ListenableFuture<String> future = listeningExecutor.submit(callable);
Futures.addCallback(future, new FutureCallback<String>() {
    public void onSuccess(String result) {
        // Callback — không chặn
    }
    public void onFailure(Throwable t) {
        // Xử lý lỗi
    }
}, executor);
```

### Best Practices

1. **Dùng Callable** — khi bạn cần một kết quả hoặc checked exception
2. **Luôn dùng timeout cho get()** — `get(5, TimeUnit.SECONDS)` thay vì `get()`
3. **CompletableFuture cho code non-blocking** — Java 8+
4. **invokeAny()** — cho các request tới mirror
5. **invokeAll() với timeout** — cho việc thực thi theo lô
6. **Kiểm tra isInterrupted()** — bên trong các Callable dài để hỗ trợ cancel()
7. **ExecutionException.getCause()** — để lấy nguyên nhân thật sự
8. **Tránh hàng triệu FutureTask** — dùng CompletableFuture hoặc VT

## Khi nào KHÔNG dùng Callable/Future

- **Tác vụ không có kết quả** (logging, gửi metric) — dùng Runnable, không có lý do gì để bọc void trong Callable<Void>
- **Các phép tính đơn luồng đơn giản** — nếu không cần thực thi song song, Callable thêm sự phức tạp không cần thiết
- **Cần một callback non-blocking** — Future.get() chặn thread. Dùng CompletableFuture cho các chuỗi callback async
- **Java 21+ với Virtual Thread** — cho các tác vụ I/O-bound đơn giản hơn khi tạo một VT và trả về kết quả qua closure thay vì bọc trong Callable/Future
- **Rất nhiều tác vụ ngắn** (triệu/giây) — mỗi FutureTask = object (~48 byte), áp lực GC. Dùng các cấu trúc lock-free hoặc xử lý theo lô

## Callable/Future vs CompletableFuture vs Virtual Thread: Chọn gì?

| Tình huống                           | Lựa chọn                          | Tại sao                                     |
| ------------------------------------ | --------------------------------- | ------------------------------------------- |
| Tác vụ có kết quả + get() blocking   | Callable + Future                 | Đơn giản, rõ ràng                           |
| Tác vụ có kết quả + timeout          | Callable + Future.get(timeout)    | Hỗ trợ tích hợp sẵn                         |
| Callback non-blocking                | CompletableFuture                 | thenAccept, thenApply — không chặn          |
| Nhiều tác vụ I/O-bound (Java 21+)    | Virtual Thread                    | Code blocking đơn giản, scale               |
| Các request tới mirror (ai nhanh hơn)| invokeAny() hoặc ShutdownOnSuccess| Tự hủy các cái chậm                         |
| Thực thi theo lô                     | invokeAll() với timeout           | Chờ tất cả, giới hạn thời gian              |

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Callable<V> trả về một kết quả (V call()) và có thể ném một checked exception; Runnable — void run(), không có checked exception
- Future — "biên nhận" từ Executor: get() (chặn), isDone(), cancel(mayInterrupt)
- Luôn dùng timeout cho get(): `get(5, TimeUnit.SECONDS)` thay vì `get()`
- invokeAll() — chờ TẤT CẢ các tác vụ, invokeAny() — kết quả của cái hoàn thành ĐẦU TIÊN (các cái khác bị hủy)
- ExecutionException.getCause() — bóc tách nguyên nhân lỗi thật sự
- Các trạng thái FutureTask: NEW → COMPLETING → NORMAL/EXCEPTIONAL/CANCELLED
- CompletableFuture — giải pháp non-blocking thay thế (thenAccept, thenApply)

**Các câu hỏi phụ thường gặp:**
- **Tại sao cancel(true) không đảm bảo dừng tác vụ?** — cancel gửi interrupt(), nhưng tác vụ phải tự kiểm tra isInterrupted()
- **CompletableFuture tốt hơn Future như thế nào?** — Future.get() chặn thread; CompletableFuture cung cấp các chuỗi callback (thenAccept, thenApply) không chặn
- **Overhead của FutureTask là gì?** — ~48 byte mỗi object; triệu tác vụ/giây = áp lực GC
- **Tại sao invokeAll() trả về List<Future> chứ không phải List<kết quả>?** — Vì mỗi tác vụ có thể hoàn thành với một exception; kết quả phải được lấy qua future.get() với xử lý ExecutionException

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Future.get() là một thao tác bất đồng bộ" — get() chặn thread gọi cho tới khi tác vụ hoàn thành
- "cancel() tức thì dừng tác vụ" — cancel chỉ gửi interrupt, tác vụ phải xử lý nó
- "Callable cần cho các tác vụ không có kết quả" — cho các tác vụ không có kết quả, dùng Runnable, Callable — khi bạn cần một kết quả hoặc checked exception
- "Future có thể tái sử dụng" — Future dùng một lần; để thực thi lại bạn cần một submit mới

# What is the AutoCloseable interface? (Interface AutoCloseable là gì?)

## Junior Level

### Định nghĩa

**`java.lang.AutoCloseable`** là một interface với một phương thức `close()` duy nhất, được gọi tự động khi thoát khỏi một khối try-with-resources.

AutoCloseable xuất hiện trong Java 7 riêng cho try-with-resources. Closeable (Java 5) chỉ dành cho các I/O stream. AutoCloseable - nằm trong java.lang (không cần import), nên bất kỳ resource nào cũng có thể trở nên "closeable".

```java
public interface AutoCloseable {
    void close() throws Exception;
}
```

### Cách dùng

```java
// FileInputStream implement AutoCloseable
try (FileInputStream fis = new FileInputStream("file.txt")) {
    fis.read();
} // fis.close() được gọi tự động
```

### Những class nào implement nó

- `InputStream` / `OutputStream` - file, mạng
- `Connection` / `Statement` - database
- `Reader` / `Writer` - văn bản
- `Scanner` - tiện ích

### Tại sao cần nó

Để bạn không quên đóng resource. Trước Java 7, bạn phải viết `finally` với `close()` thủ công.

## Middle Level

### Tại sao nằm trong java.lang?

Đây là một interface nền tảng. Nó được đặt trong `java.lang` để khả dụng ở mọi nơi mà không cần import - ngang tầm với `Runnable` hay `Iterable`.

### Hiện thực close() đúng cách

**1. Thu hẹp kiểu exception:**
Interface khai báo `throws Exception`. Hãy ghi đè bằng một kiểu cụ thể hơn:

```java
public class MyResource implements AutoCloseable {
    @Override
    public void close() throws IOException { // cụ thể hơn
        // đóng
    }
}
```

Hoặc không `throws` gì cả nếu phương thức an toàn.

**2. Mẫu "Safe Close":**
Nếu một resource sở hữu vài sub-resource:

```java
public void close() throws Exception {
    try {
        subResource1.close();
    } finally {
        subResource2.close(); // sẽ đóng ngay cả khi cái đầu tiên lỗi
    }
}
```

**3. Idempotency:**
Lời gọi `close()` lặp lại không được ném exception.

### Garbage Collector và AutoCloseable

`AutoCloseable` **không thay thế** việc quản lý bộ nhớ. Một resource (file, socket) là một descriptor native của OS. Nếu bạn không gọi `close()`, descriptor sẽ "treo" cho tới khi GC thu gom object.

Điều này dẫn tới lỗi **"Too many open files"**.

---

### Ba cách tiếp cận quản lý resource

| Cơ chế     | Kích hoạt khi        | Đảm bảo       | Khuyến nghị                |
| ---------- | -------------------- | ------------- | -------------------------- |
| TWR        | Khi thoát khối       | Được đảm bảo  | Phương pháp chính          |
| Cleaner    | Khi GC quyết định    | Dự phòng      | Dự phòng nếu quên close()  |
| finalize() | Khi GC quyết định    | Không dự đoán được | Deprecated (Java 9)    |

## Senior Level

### Bên trong: các descriptor native

Một resource không phải là một object Java, mà là một descriptor của OS. Một descriptor là một con số (int) mà OS cấp khi mở một file/socket. Object Java chỉ là một lớp bọc (wrapper). GC thấy lớp bọc nhưng không thấy resource native trong OS. Nếu không gọi close() tường minh, descriptor rò rỉ ngay cả khi GC đã thu gom object Java. GC không thấy các resource native. Không có `close()`, descriptor rò rỉ ngay cả khi object Java được thu gom.

### Trạng thái nguyên tử (Atomic State) trong môi trường đa luồng

```java
public class MyResource implements AutoCloseable {
    private final AtomicBoolean closed = new AtomicBoolean(false);

    public void close() {
        if (closed.compareAndSet(false, true)) {
            // giải phóng resource thực sự
        }
    }
}
```

Hai thread không được đóng cùng một socket đồng thời - hành vi không xác định ở mức driver native.

### Ném exception trong constructor

Nếu constructor ném một exception **sau khi** mở một resource native nhưng **trước khi** trả về object - rò rỉ:

```java
public class MyResource implements AutoCloseable {
    private final NativeHandle handle;

    public MyResource(String path) {
        this.handle = openNative(path); // đã mở
        if (!validate(path)) {
            throw new IllegalArgumentException(); // handle rò rỉ!
        }
    }
}
```

**Giải pháp:** constructor nhẹ, việc mở nặng - đặt dưới `try-with-resources`.

### Cleaner thay cho Finalizer (Java 9+)

`finalize()` đã bị deprecated. Để "bảo hiểm" cho resource hãy dùng `java.lang.ref.Cleaner`:

```java
public class MyResource implements AutoCloseable {
    private static final Cleaner cleaner = Cleaner.create();
    private final Cleaner.Cleanable cleanable;

    public MyResource() {
        this.cleanable = cleaner.register(this, () -> {
            // phòng tuyến cuối cùng - nếu close() chưa được gọi
            System.err.println("Resource not closed properly!");
        });
    }

    public void close() {
        cleanable.clean();
    }
}
// Cleaner được kích hoạt bởi GC. Khi không còn strong reference nào tới MyResource,
// GC đánh dấu object để dọn dẹp. Cleaner thực thi lambda trong một thread riêng.
// Đây KHÔNG phải là một sự thay thế cho TWR - GC có thể mất vài phút hoặc thậm chí vài giờ.
// Cleaner là bảo hiểm nếu bạn quên close().
```

Đây chỉ là bảo hiểm, không thay thế tầm quan trọng của TWR.

### Chẩn đoán

- **SonarLint Rule** - "Resources should be closed". Kiểm tra cây phân cấp kiểu.
- **`jcmd VM.native_memory`** - giám sát bộ nhớ native
- Rò rỉ descriptor - một nguyên nhân thường gặp của JVM crash sau nhiều ngày hoạt động

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `AutoCloseable` xuất hiện trong Java 7 riêng cho try-with-resources
- Một phương thức duy nhất: `void close() throws Exception`
- Nằm trong `java.lang` - khả dụng mà không cần import, như `Runnable`
- `close()` phải là idempotent (lời gọi lặp lại an toàn)
- GC không thấy các descriptor native - không có `close()` sẽ rò rỉ ngay cả khi object được thu gom
- Thu hẹp `throws Exception` thành kiểu cụ thể hoặc bỏ hoàn toàn
- `Cleaner` (Java 9+) - bảo hiểm, nhưng KHÔNG thay thế TWR

**Các câu hỏi phụ thường gặp:**
- **Tại sao nằm trong java.lang, không phải java.io?** - Để bất kỳ class nào cũng có thể trở nên closeable mà không cần import, ở tầm `Object`
- **Điều gì xảy ra nếu bạn không đóng một resource?** - Rò rỉ descriptor native -> "Too many open files" -> JVM crash
- **close() có thể ném exception không?** - Có, đó là lý do trong TWR nhiều resource các exception được suppressed
- **Cleaner tốt hơn finalize() như thế nào?** - Cleaner dễ dự đoán hơn, `finalize()` deprecated trong Java 9

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "GC tự đóng resource" - GC thu gom object Java, nhưng không đóng descriptor native
- "AutoCloseable chỉ cho I/O" - Đó là `Closeable`; `AutoCloseable` cho bất kỳ resource nào
- "close() không cần phải idempotent" - Javadoc khuyến nghị mạnh mẽ điều đó, lời gọi lặp lại không được lỗi

# What does the throws keyword do? (Từ khóa throws làm gì?)

## Junior Level

### Định nghĩa

`throws` - một từ khóa trong chữ ký phương thức **ghi lại hợp đồng (contract)**: nó nói cho code gọi biết những **checked exception** nào phương thức có thể ném và code gọi phải sẵn sàng xử lý những cái nào.

```java
public void readFile() throws IOException {
    Files.readAllLines(Paths.get("file.txt"));
}
```

### Nó có nghĩa là gì

Phương thức nói với bên gọi: "Tôi có thể không thành công, và bạn **phải** biết về điều đó".

Code gọi phải:
1. Bọc lời gọi trong `try-catch`
2. Hoặc cũng thêm `throws` vào chữ ký của nó

```java
// Cách 1: try-catch
public void safeRead() {
    try {
        readFile();
    } catch (IOException e) {
        log.error("Failed", e);
    }
}

// Cách 2: lan truyền lên tiếp
public void process() throws IOException {
    readFile();
}
```

### Nhiều exception

```java
public void process() throws IOException, SQLException {
    // Có thể ném cả hai
}
```

### Tại sao throws cần cho checked nhưng không cho unchecked

**Checked exception** (kế thừa `Exception`, nhưng không phải `RuntimeException`) - compiler **bắt buộc** xử lý. `throws` là một cách để phương thức ủy thác trách nhiệm cho bên gọi: "Tôi không biết cách xử lý lỗi này, hãy để bên gọi quyết định".

**Unchecked exception** (kế thừa `RuntimeException`) - compiler **không bắt buộc** xử lý. Chúng biểu thị các lỗi lập trình (`NullPointerException`, `IllegalArgumentException`) không thể xử lý một cách có ý nghĩa - chúng cần được sửa, không phải bắt. Đó là lý do `throws` không cần cho chúng.

```java
// Checked: compiler ép khai báo hoặc catch
public void readFile() throws IOException { ... }

// Unchecked: compiler không yêu cầu throws
public void process(String s) {
    if (s == null) throw new NullPointerException();
}
```

### Unchecked exception và throws

Với `RuntimeException`, `throws` về mặt kỹ thuật là không cần, dù ngôn ngữ cho phép viết nó:

```java
// Không cần viết throws NullPointerException
public void process(String s) {
    if (s == null) throw new NullPointerException();
}
```

Dù `void method() throws RuntimeException` biên dịch được, nó được coi là phong cách xấu - unchecked exception không nên làm rối chữ ký.

### Khi nào KHÔNG nên dùng throws

1. **Trong API của public library** - `throws Exception` ép client bắt "mọi thứ"
2. **Trong các interface với nhiều checked exception** - dấu hiệu vi phạm SRP, hãy tách interface
3. **Trong các Spring REST controller** - dùng `@ControllerAdvice` thay vì `throws` trong mỗi phương thức
4. **Trong các biểu thức lambda** - các functional interface không hỗ trợ checked exception
5. **Cho các lỗi lập trình** - `IllegalArgumentException`, `NullPointerException` không được khai báo qua `throws`

## Middle Level

### Bytecode: thuộc tính Exceptions

Trong file `.class`, thông tin về `throws` được lưu trong thuộc tính `Exceptions` của phương thức. JVM không dùng nó để kiểm soát lúc runtime - chỉ cho bộ verifier của compiler.

Khi gọi qua Reflection, JVM sẽ không ép bắt các exception:

```java
Method m = MyClass.class.getMethod("readFile");
m.invoke(obj); // IOException không nhất thiết phải được bắt
```

### Tính tương thích nhị phân (Binary Compatibility)

**Thêm một checked exception** phá vỡ tính tương thích nhị phân:
```java
// Trước:
public void process() { }

// Sau - tất cả client ngừng biên dịch được
public void process() throws IOException { }
```

**Bỏ exception** - tương thích nhị phân (các `try-catch` cũ vẫn tiếp tục hoạt động).

**Mẹo cho Senior:** nếu bạn cần thêm validation vào một public API, hãy dùng `RuntimeException` hoặc tạo một phương thức overload.

### Ghi đè (Overriding) và LSP

Nguyên tắc Liskov Substitution:

```java
interface Service {
    void process() throws IOException;
}

class Impl implements Service {
    @Override
    // ĐƯỢC: không ném gì cả (thu hẹp hợp đồng)
    public void process() { }

    @Override
    // ĐƯỢC: ném một kiểu con
    public void process() throws FileNotFoundException { }

    // KHÔNG ĐƯỢC: checked exception mới - lỗi biên dịch
    // public void process() throws IOException, SQLException { }
}
```

### Unchecked và throws

Về mặt kỹ thuật bạn có thể viết `void method() throws RuntimeException`, nhưng đó là phong cách xấu. Unchecked exception không nên làm rối chữ ký. Để làm tài liệu, dùng `@throws` trong JavaDoc.

## Senior Level

### Throws như tài liệu

Hãy coi `throws` như một phần của hợp đồng. `throws InsufficientFundsException` nói nhiều về logic nghiệp vụ hơn bất kỳ comment nào.

### Generic Throws

Java cho phép generic:

```java
public <E extends Exception> void doWork(ThrowingRunnable<E> task) throws E {
    task.run();
}
```

Được dùng tích cực trong các functional interface và wrapper.

### Interface Segregation

Nếu một interface ném quá nhiều `throws` khác nhau - dấu hiệu vi phạm SRP. Phương thức làm quá nhiều việc.

```java
// Xấu - quá nhiều trách nhiệm
public interface Service {
    void process() throws IOException, SQLException, AuthException, ValidationException;
}

// Tốt - tách thành các interface
public interface DataService {
    void save() throws DataAccessException;
}
public interface AuthService {
    void authenticate() throws AuthException;
}

// Càng tốt hơn - trong Spring dùng @ControllerAdvice
@RestController
public class OrderController {
    // không cần throws - @ControllerAdvice sẽ bắt
    @PostMapping("/orders")
    public Order createOrder(@RequestBody OrderRequest req) {
        return orderService.create(req);
    }
}
```

### ReflectiveOperationException

Khi Reflection, tất cả các checked exception của phương thức được gọi bị bọc trong `InvocationTargetException`.

### `throws Exception` - mẫu không nên dùng

Trong hầu hết các trường hợp, đừng viết `throws Exception` trong public API. Nó ép client bắt "mọi thứ", tước đi khả năng phản ứng phù hợp với các lỗi cụ thể.

### Chẩn đoán

- **`javap -v MyClass.class`** - bạn sẽ thấy thuộc tính `Exceptions` trong bytecode
- **Kiểm tra tính tương thích nhị phân** - các công cụ như JAPICC kiểm tra tính tương thích phiên bản
- **Static Analysis** - Sonar chặn `throws Exception` trong các public API

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `throws` ghi lại hợp đồng của phương thức - những checked exception nào bên gọi phải xử lý
- Checked exception (không phải `RuntimeException`) compiler bắt buộc khai báo hoặc catch
- Unchecked exception (`RuntimeException`) không yêu cầu `throws` - đây là các lỗi lập trình
- Khi ghi đè bạn có thể thu hẹp `throws` (bỏ hoặc thay bằng kiểu con), nhưng không mở rộng
- Thêm một checked exception phá vỡ tính tương thích nhị phân - client sẽ ngừng biên dịch được
- Trong Spring REST dùng `@ControllerAdvice` thay vì `throws` trong mỗi phương thức
- `throws Exception` trong public API - anti-pattern, ép client bắt "mọi thứ"

**Các câu hỏi phụ thường gặp:**
- **Checked exception có bắt buộc phải được bắt không?** - Có, hoặc `try-catch` hoặc `throws` của riêng bạn
- **Có thể thêm `throws RuntimeException` không?** - Về mặt kỹ thuật thì có, nhưng phong cách xấu
- **Điều gì xảy ra khi ghi đè phương thức?** - Có thể bỏ `throws` hoặc thu hẹp, nhưng không mở rộng (LSP)
- **`throws` được lưu trong bytecode như thế nào?** - Thuộc tính `Exceptions` trong `.class`, JVM không kiểm tra lúc runtime

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi viết `throws Exception` khắp nơi cho đơn giản" - anti-pattern, client không thể xử lý phù hợp
- "Tôi không khai báo checked exception - compiler sẽ không để ý" - sẽ không biên dịch được
- "`throws` ảnh hưởng hiệu suất lúc runtime" - không, đó chỉ là một kiểm tra của compiler
- "Có thể thêm checked exception mới mà không có hậu quả" - phá vỡ tính tương thích nhị phân

# What is the difference between List, Set and Queue? (Sự khác nhau giữa List, Set và Queue là gì?)

## Junior Level

**List, Set và Queue** — ba kiểu collection chính trong Java.

**Sự khác biệt chính:**

| Kiểu      | Thứ tự                                                                          | Trùng lặp    | Truy cập                  | Ví dụ minh họa     |
| --------- | -------------------------------------------------------------------------------- | ------------ | ------------------------- | ------------------ |
| **List**  | Giữ nguyên thứ tự                                                                | Được cho phép | Theo index `list.get(0)`  | Danh sách mua sắm  |
| **Set**   | Không đảm bảo (ngoại trừ LinkedHashSet)                                          | Không cho phép | Chỉ iterate               | Tập hợp các key    |
| **Queue** | FIFO (First-In-First-Out)                                                        | Được cho phép | Chỉ ở đầu (head)          | Hàng xếp hàng ở quầy thu ngân |

**Ví dụ:**
```java
// List: thứ tự và trùng lặp
List<String> list = new ArrayList<>();
list.add("B");
list.add("A");
list.add("B");  // OK
// → [B, A, B]

// Set: chỉ duy nhất
Set<String> set = new HashSet<>();
set.add("B");
set.add("A");
set.add("B");  // Sẽ không được thêm vào
// → [A, B] (không đảm bảo thứ tự)

// Queue: FIFO
Queue<String> queue = new ArrayDeque<>();
queue.offer("B");
queue.offer("A");
queue.poll();  // → "B" (vào trước, ra trước)
```

## Middle Level

### List (Sequence — chuỗi tuần tự)

```java
// Các cài đặt:
ArrayList    // Mảng động → đọc O(1)
LinkedList   // Danh sách liên kết đôi → đọc O(n)

// Các thao tác:
list.get(0)       // O(1) với ArrayList, O(n) với LinkedList
list.add(e)       // O(1)* trung bình (amortized)
list.contains(e)  // O(n) tìm kiếm tuyến tính
list.remove(0)    // O(n) dịch chuyển mảng
```

### Set (Collection các phần tử duy nhất)

```java
// Các cài đặt:
HashSet         // Dựa trên HashMap → tra cứu O(1)
LinkedHashSet   // + thứ tự chèn vào
TreeSet         // Cây đỏ-đen (red-black tree) → O(log n), được sắp xếp

// Bên trong HashSet:
// HashMap<E, Object> với value = static final Object PRESENT
// → Mặc dù dùng chung một đối tượng PRESENT, HashSet tiêu thụ nhiều bộ nhớ hơn ArrayList do lớp bọc HashMap.Node (key + value + hash + con trỏ next).

// Các thao tác:
set.add(e)       // O(1) với HashSet, O(log n) với TreeSet
set.contains(e)  // O(1) với HashSet, O(log n) với TreeSet
set.remove(e)    // O(1) với HashSet
```

### Queue

```java
// Các cài đặt:
ArrayDeque        // Mảng vòng (circular array) → chèn/xóa O(1)
PriorityQueue     // Binary Heap → O(log n), lấy ra theo độ ưu tiên
LinkedList        // Có thể dùng như Queue, nhưng chậm hơn ArrayDeque

// Các phương thức:
queue.offer(e)    // true/false (không ném exception)
queue.add(e)      // ném exception khi có lỗi
queue.poll()      // null nếu rỗng
queue.remove()    // ném exception nếu rỗng
queue.peek()      // null nếu rỗng
queue.element()   // ném exception nếu rỗng
```

### So sánh hiệu năng

| Thao tác          | ArrayList   | HashSet   | TreeSet   | ArrayDeque   |
| ----------------- | ----------- | --------- | --------- | ------------ |
| Chèn vào          | O(1)*       | O(1)      | O(log n)  | O(1)         |
| Tra cứu           | O(n)        | O(1)      | O(log n)  | O(n)         |
| Xóa               | O(n)        | O(1)      | O(log n)  | O(1)         |
| Truy cập theo index | O(1)      | N/A       | N/A       | N/A          |

### Khi nào dùng cái nào

| Kịch bản               | Chọn          | Tại sao                    |
| ---------------------- | ------------- | -------------------------- |
| Lưu trữ có thứ tự      | **List**      | Giữ nguyên thứ tự          |
| Kiểm tra tính duy nhất | **Set**       | contains nhanh             |
| Xử lý theo thứ tự      | **Queue**     | FIFO                       |
| Sắp xếp                | **TreeSet**   | Tự động sắp xếp            |
| Đọc thường xuyên       | **ArrayList** | Cache locality             |

Cache locality (tính cục bộ của cache) = các phần tử nằm liền kề nhau trong bộ nhớ. CPU nạp một cache line 64-byte cùng một lúc, lấy được ngay 8-16 tham chiếu. Điều này làm cho việc iterate nhanh hơn 10-100 lần so với các phần tử nằm rải rác trong LinkedList.

---

### Khi nào KHÔNG nên dùng

- **List (ArrayList):** Đừng dùng để kiểm tra tính duy nhất — `contains()` = O(n)
- **HashSet:** Đừng dùng nếu thứ tự chèn vào quan trọng — hãy dùng `LinkedHashSet`
- **TreeSet:** Đừng dùng nếu không cần sắp xếp — O(log n) chậm hơn O(1)
- **Queue:** Đừng dùng để truy cập ngẫu nhiên — hãy dùng `List`

## Senior Level

### Mức chiếm dụng bộ nhớ (Memory Footprint)

```
ArrayList:
  → Mảng Object[] (4-8 byte cho mỗi tham chiếu)
  → Overhead tối thiểu

HashSet:
  → HashMap bên trong
  → Node<K,V> cho mỗi phần tử
  → + static final Object PRESENT (dùng chung)
  → Nhiều bộ nhớ hơn ArrayList ~2 lần!

TreeSet:
  → TreeMap (cây đỏ-đen)
  → Entry<K,V> + left + right + parent + color
  → Nhiều bộ nhớ hơn ArrayList ~4 lần
```

### Concurrency (tính đồng thời)

```java
// List
CopyOnWriteArrayList      // Nhiều đọc, ít ghi
Collections.synchronizedList  // Phổ quát, nhưng chậm

// Set
ConcurrentHashMap.newKeySet()  // Lựa chọn tốt nhất!
Collections.synchronizedSet()

// Queue
ConcurrentLinkedQueue     // Lock-free, wait-free
LinkedBlockingQueue       // Producer-Consumer
ArrayBlockingQueue        // Bị giới hạn (bounded), một lock duy nhất
SynchronousQueue          // Sức chứa bằng không
```

### Cache Locality

```
ArrayList: các phần tử liền kề trong bộ nhớ
  → CPU prefetching → L1/L2 cache hit
  → Iterate: rất nhanh

HashSet: các phần tử nằm rải rác
  → Cache miss trong lúc iterate
  → Nhưng contains O(1) bù lại

LinkedList: các node nằm ở các vị trí khác nhau trên heap
  → Cache miss ở MỖI phần tử
  → Anti-pattern đối với các CPU hiện đại!
```

### Java 21: SequencedCollection

```java
// Bây giờ List và Deque kế thừa SequencedCollection
SequencedCollection<String> seq = new ArrayList<>();
seq.addFirst("A");   // Phương thức mới!
seq.addLast("B");    // Phương thức mới!
seq.getFirst();      // Phương thức mới!
seq.reversed();      // View theo thứ tự đảo ngược

// Đối với Set:
SequencedSet<String> seqSet = new LinkedHashSet<>();
// TreeSet cũng hỗ trợ thông qua NavigableSet
```

### Bloom Filter cho các Set khổng lồ

```java
// Khi số lượng phần tử lên đến hàng tỷ, HashSet sẽ không vừa trong RAM
// Giải pháp: Bloom Filter (cấu trúc dữ liệu bên thứ ba, không có trong JCF)
// "False positive" = bộ lọc có thể nói "phần tử có thể tồn tại" trong khi thực ra nó không tồn tại.
// Nhưng "false negative" là không thể: nếu bộ lọc nói "phần tử không tồn tại" — thì nó chắc chắn vắng mặt.

BloomFilter<String> filter = BloomFilter.create(
    Funnels.stringFunnel(),
    expectedInsertions,
    falsePositiveRate
);

// Tra cứu O(1), bộ nhớ tối thiểu
// Nhưng: có thể có false positive (không có false negative)
```

### Kinh nghiệm Production

**Tình huống thực tế: HashSet so với ArrayList cho contains**
```java
// ❌ Tra cứu O(n) trong một list 1M phần tử
List<String> blacklist = List.of("bad1", "bad2", ...);
if (blacklist.contains(input)) { ... }  // Chậm!

// ✅ Tra cứu O(1)
Set<String> blacklist = Set.of("bad1", "bad2", ...);
if (blacklist.contains(input)) { ... }  // Nhanh!
```

### Best Practices

1. **List** → ArrayList theo mặc định
2. **Set** → HashSet cho tính duy nhất, TreeSet cho sắp xếp
3. **Queue** → ArrayDeque cho stack/queue
4. **Concurrency** → ConcurrentHashMap.newKeySet() cho Set
5. **Bộ nhớ** → ArrayList gọn hơn Set
6. **Cache Locality** → ArrayList > LinkedList
7. **Java 21** → SequencedCollection cho API thống nhất

### Tóm tắt cho Senior

- **List** = đánh chỉ mục (indexing), thứ tự, cache locality
- **Set** = tính duy nhất, contains O(1) (HashSet)
- **Queue** = FIFO/LIFO, backpressure (Bounded)
- **Bộ nhớ:** ArrayList < HashSet < TreeSet
- **Cache Locality:** ArrayList >> LinkedList
- **Concurrency:** CopyOnWriteArrayList, ConcurrentHashMap.newKeySet()
- **Bloom Filter** cho các set khổng lồ
- **Java 21** → SequencedCollection thống nhất API

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- List = thứ tự + trùng lặp + truy cập theo index (ArrayList đọc O(1), LinkedList O(n))
- Set = tính duy nhất thông qua equals()/hashCode(), HashSet = tra cứu O(1), TreeSet = sắp xếp O(log n)
- Queue = FIFO, offer/poll/peek an toàn hơn add/remove/element
- HashSet bên trong = HashMap<E, Object> với PRESENT dùng chung, nhiều bộ nhớ hơn ArrayList ~2 lần
- Cache locality: ArrayList >> LinkedList — các phần tử liền kề trong bộ nhớ, CPU prefetching
- Cho concurrency: CopyOnWriteArrayList (nhiều đọc), ConcurrentHashMap.newKeySet() cho Set
- Bloom Filter — cho các set khổng lồ (hàng tỷ phần tử), tra cứu O(1), có thể có false positive

**Các câu hỏi phụ thường gặp:**
- Tại sao HashSet tiêu thụ nhiều bộ nhớ hơn ArrayList? — Bên trong là HashMap.Node (key + value + hash + con trỏ next)
- Khi nào dùng TreeSet thay vì HashSet? — Khi cần sắp xếp, nhưng O(log n) chậm hơn O(1)
- offer/poll khác add/remove như thế nào? — offer/poll trả về false/null thay vì exception
- Làm sao đảm bảo thread-safety cho Set? — ConcurrentHashMap.newKeySet() — lựa chọn tốt nhất

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "LinkedList nhanh hơn ArrayList khi iterate" — điều ngược lại mới đúng, cache locality của ArrayList cho lợi thế 10-100 lần
- "HashSet đảm bảo thứ tự chèn vào" — đó là LinkedHashSet, HashSet thông thường không đảm bảo thứ tự
- "Để có Set thread-safe bạn cần Collections.synchronizedSet" — ConcurrentHashMap.newKeySet() hiệu quả hơn
- "Queue và List có thể thay thế cho nhau" — Queue không hỗ trợ truy cập ngẫu nhiên theo index

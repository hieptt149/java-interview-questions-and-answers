# Difference between Constructor, Setter and Field Injection (Sự khác nhau giữa Constructor, Setter và Field Injection)

## Junior Level

**Constructor** — phụ thuộc đến qua constructor.
**Setter** — phụ thuộc đến qua một phương thức.
**Field** — phụ thuộc đến thẳng vào field.

```java
// Constructor
public class Service {
    private final Repo repo;
    public Service(Repo repo) { this.repo = repo; }
}

// Setter
public class Service {
    private Repo repo;
    @Autowired public void setRepo(Repo repo) { this.repo = repo; }
}

// Field
public class Service {
    @Autowired private Repo repo;  // Phụ thuộc bị ẩn!
}
```

**Khuyến nghị:** Dùng Constructor Injection làm mặc định. Setter — cho các phụ thuộc tùy chọn (`@Autowired(required = false)`). Field Injection — chỉ trong test.

## Middle Level

### Constructor Injection (Tiêu chuẩn vàng)

```java
// Ưu điểm:
// 1. field final -> tính bất biến (immutability)
// 2. Đối tượng được khởi tạo đầy đủ -> không NPE
// 3. Test không cần Spring: new Service(mockRepo)
// 4. Vòng phụ thuộc lộ ra ngay lập tức -> lỗi lúc khởi động
```

### Field Injection (Anti-pattern)

```java
// Vấn đề:
// 1. Phụ thuộc bị ẩn -> không thấy được class cần gì
// 2. Không thể là final -> có thể mất một phụ thuộc
// 3. Test đòi hỏi Spring context
// 4. Vòng phụ thuộc bị che giấu -> NPE lúc runtime
```

### Setter Injection (Hiếm khi)

```java
// Khi nào dùng:
// 1. Phụ thuộc tùy chọn (optional)
// 2. Hot-swap lúc runtime (hiếm!)

@Autowired(required = false)  // Tùy chọn
public void setRepo(Repo repo) { this.repo = repo; }
```

### Thứ tự khởi tạo

```
1. Constructor -> Constructor Injection
2. Tạo đối tượng
3. Fields -> Field Injection
4. Setters -> Setter Injection
5. @PostConstruct

-> Trong constructor, các phụ thuộc Field và Setter vẫn còn NULL!
```

### Khi nào Setter Injection là hợp lý

1. **Phụ thuộc tùy chọn**: `@Autowired(required = false)` — nếu phụ thuộc không được cung cấp, bean vẫn được tạo
2. **Cấu hình lại**: cần thay đổi một phụ thuộc sau khi tạo (hiếm, thường là anti-pattern)
3. **Spring Boot ConfigurationProperties**: bản thân Spring Boot dùng setter injection để binding cấu hình

## Senior Level

### AutowiredAnnotationBeanPostProcessor

```
Spring dùng BPP cho DI:
  1. Quét các field có @Autowired
  2. Quét các constructor
  3. Quét các setter
  4. Inject các phụ thuộc

> Spring 4.x+: một constructor duy nhất không cần @Autowired. Spring 6+: khuyến nghị constructor injection không cần annotation.

-> Reflection API -> overhead
-> Constructor Injection nhanh hơn một chút (Spring quét một constructor thay vì tất cả các field trong class). Trên thực tế chênh lệch chỉ tính bằng millisecond lúc khởi động.
```

### Circular Dependency (phụ thuộc vòng)

```
Constructor Injection:
  -> A cần B, B cần A
  -> Spring không thể tạo cái nào cả -> lỗi ngay lập tức

Field Injection:
  -> Spring tạo A và B qua constructor mặc định
  -> Sau đó điền vào các field
  -> Che giấu một vấn đề kiến trúc!
```

### Xung đột với CGLIB Proxy

```
Spring tạo một proxy qua subclass -> gọi constructor
-> Nếu constructor nặng -> nó sẽ chạy hai lần!
-> Constructor nên đơn giản: chỉ gán field
-> Toàn bộ logic -> đưa vào @PostConstruct
```

### Lombok @RequiredArgsConstructor

```java
@Service
@RequiredArgsConstructor
public class Service {
    private final Repo1 repo1;
    private final Repo2 repo2;
    // Lombok sẽ tự tạo constructor!
}
```

### Kinh nghiệm Production

**Tình huống thực tế: 10 phụ thuộc trong constructor**
- Class làm quá nhiều việc -> vi phạm SRP
- Giải pháp: tách thành 3 service
- Kết quả: dễ đọc + dễ test hơn

### Best Practices

1. **Constructor** — làm mặc định (99%)
2. **@RequiredArgsConstructor** — Lombok cho phần boilerplate
3. **Setter** — chỉ cho phụ thuộc tùy chọn
4. **Field** — KHÔNG dùng
5. **> 5 phụ thuộc** -> tách class ra
6. **@Lazy** — cách chữa cháy cho vòng phụ thuộc

### Tóm tắt cho Senior

- **Constructor** = tính bất biến, fail-fast, dễ test
- **Field** = phụ thuộc bị ẩn, khó test
- **Setter** = phụ thuộc tùy chọn
- **Vòng phụ thuộc** -> Constructor vỡ ngay lập tức
- **CGLIB** -> constructor bị gọi hai lần (đối tượng + proxy)
- **Lombok** -> @RequiredArgsConstructor loại bỏ boilerplate

## Interview Cheat Sheet

**Cần phải biết:**
- Constructor injection — phụ thuộc qua constructor, cho phép field `final` và tính bất biến
- Setter injection — qua một phương thức, phù hợp cho phụ thuộc tùy chọn (`@Autowired(required = false)`)
- Field injection — qua một field với `@Autowired`, anti-pattern: phụ thuộc bị ẩn, không thể để `final`
- Thứ tự khởi tạo: constructor -> fields (field injection) -> setters -> `@PostConstruct`
- Constructor injection là fail-fast: lỗi lúc khởi động nếu thiếu phụ thuộc
- Circular dependency qua constructor làm vỡ lúc khởi động, qua field — che giấu vấn đề
- Spring 6+ khuyến nghị constructor injection không cần annotation (nếu chỉ có một constructor)

**Các câu hỏi phụ thường gặp:**
- **Tại sao field injection là anti-pattern?** Phụ thuộc bị ẩn, không dùng được `final`, NPE lúc runtime, khó test mà không có Spring.
- **Khi nào setter injection là hợp lý?** Phụ thuộc tùy chọn, binding Spring Boot ConfigurationProperties, hot-swap (hiếm).
- **Tại sao constructor của CGLIB proxy bị gọi hai lần?** Proxy được tạo qua một subclass — trước là constructor của đối tượng thật, rồi đến constructor của proxy.
- **AutowiredAnnotationBeanPostProcessor làm gì?** Quét `@Autowired` trên các field, constructor và setter, inject các phụ thuộc qua Reflection.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Field Injection tiện nhất, ít code hơn" (tiện != chất lượng, nó là nợ kỹ thuật)
- "Setter injection ổn cho các phụ thuộc bắt buộc" (có thể quên gọi, đối tượng ở trạng thái chưa hoàn chỉnh)
- "Circular dependency không phải vấn đề, Spring lo được" (Spring che giấu, nhưng bug lúc runtime)
- "Lombok giải quyết trọn vẹn vấn đề boilerplate của constructor" (đúng vậy, nhưng không loại bỏ được vấn đề > 5 phụ thuộc)

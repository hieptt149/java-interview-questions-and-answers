# Are Record Fields Final? (Các trường của Record có phải là final không)

## 🟢 Junior Level

**Có, tất cả các trường trong Record đều tự động là `final`.** Điều này có nghĩa chúng không thể bị thay đổi sau khi object được tạo.

```java
public record User(String name, int age) {}

User user = new User("John", 25);

// ❌ Không thể thay đổi trường
user.name = "Jane";  // lỗi biên dịch — trường là final

// ✅ Có thể tạo một Record mới
user = new User("Jane", 25);  // OK
```

Điều này làm cho Record **bất biến (immutable)** theo thiết kế.

---

## 🟡 Middle Level

### Cách Hoạt Động

Trình biên dịch tự động làm cho tất cả các trường thành `private final`:

```java
public record Point(int x, int y) {}

// Trình biên dịch sinh ra:
public final class Point extends java.lang.Record {
    private final int x;  // implicit final
    private final int y;  // implicit final

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    public int x() { return x; }
    public int y() { return y; }
}
```

**Ngay cả khi bạn không viết `final`:**
```java
// Cả hai lựa chọn giống hệt nhau
public record Point(int x, int y) {}
public record Point(final int x, final int y) {}  // final là thừa
```

### Sắc Thái Quan Trọng: Các Thành Phần Mutable

Các trường là final, nhưng nếu chúng tham chiếu đến **object mutable**, nội dung có thể bị thay đổi:

```java
public record User(String name, List<String> tags) {}

User user = new User("John", new ArrayList<>(List.of("admin", "user")));

// ❌ Không thể thay thế list
// user.tags = new ArrayList<>();  // lỗi biên dịch

// ✅ Nhưng có thể thay đổi nội dung list
user.tags().add("moderator");  // OK! List là mutable
user.tags().clear();           // OK!
```

**Giải pháp — bản sao phòng thủ (defensive copy):**
```java
public record User(String name, List<String> tags) {
    public User {
        tags = List.copyOf(tags);  // list bất biến
    }
}

User user = new User("John", List.of("admin"));
// user.tags().add("moderator");  // UnsupportedOperationException!
```

### Các Lỗi Thường Gặp

1. **Mong đợi tính bất biến hoàn toàn:**
```java
public record Data(int[] values) {}

Data d = new Data(new int[]{1, 2, 3});
d.values()[0] = 99;  // ✅ Có thể — mảng là mutable!

// ✅ Giải pháp
public record SafeData(List<Integer> values) {
    public SafeData {
        values = List.copyOf(values);
    }
}
```

2. **Cố gắng thay đổi trường:**
```java
public record Point(int x, int y) {
    public void setX(int x) {
        // this.x = x;  // lỗi biên dịch — trường final
    }
}
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Tầng JVM:**
```
// Tất cả các thành phần Record có cờ ACC_FINAL
Field {
    access_flags: ACC_PRIVATE | ACC_FINAL
    name: "x"
    descriptor: "I"
}
```

**Reflection xác nhận:**
```java
Field[] fields = Point.class.getDeclaredFields();
for (Field f : fields) {
    System.out.println(f.getName() + " final=" + Modifier.isFinal(f.getModifiers()));
}
// Kết quả: x final=true, y final=true
```

### Đánh Đổi Kiến Trúc

**Trường final:**

| Ưu điểm                          | Nhược điểm                            |
| ------------------------------ | --------------------------------- |
| Thread-safe (safe publication) | Không thể thay đổi trạng thái         |
| Tối ưu hóa JIT                | Cần tạo object mới     |
| Tính dự đoán được                 | Các thành phần mutable cần được bảo vệ |
| Key HashMap                   | Khó làm việc với đồ thị hơn        |

### Edge Cases

**1. Các thành phần mutable:**
```java
public record MutableRecord(Date createdAt) {}

MutableRecord r = new MutableRecord(new Date());
r.createdAt().setTime(0);  // có thể thay đổi Date!

// ✅ Giải pháp
public record ImmutableRecord(Date createdAt) {
    public ImmutableRecord {
        createdAt = new Date(createdAt.getTime());  // bản sao phòng thủ
    }
}
```

**2. Final != bất biến:**
```java
public record Config(Map<String, String> props) {}

// trường final, nhưng Map có thể bị thay đổi
Config c = new Config(new HashMap<>());
c.props().put("key", "value");  // OK
```

**3. Khả năng nhìn thấy bộ nhớ (memory visibility):**
```java
// trường final đảm bảo safe publication
// sau khi constructor hoàn thành, tất cả các thread thấy giá trị đúng
public record SharedConfig(String url, int timeout) {}

// Publication an toàn
SharedConfig config = new SharedConfig("http://api.com", 5000);
// Thread khác sẽ thấy giá trị đúng
```

### Hiệu Năng

```
Trường final:
- JIT có thể inline giá trị
- Không cần volatile
- Safe publication mà không cần đồng bộ hóa
- Memory barrier khi khởi tạo
```

**Benchmark:**
```
// Giá trị xấp xỉ. Phụ thuộc JVM/phần cứng.
Thao tác          | Trường final | Trường mutable
-------------------|------------|-------------
Đọc                | 1 ns       | 1 ns
Publish (thread)    | 0 ns       | cần đồng bộ
Tối ưu hóa JIT    | Tối đa | Hạn chế
```

### Kinh Nghiệm Production

**DTO bất biến:**
```java
public record OrderDto(
    String id,
    Instant createdAt,
    BigDecimal amount,
    List<OrderItem> items
) {
    public OrderDto {
        items = List.copyOf(items);  // bảo vệ khỏi collection mutable
    }
}
```

**Value object:**
```java
public record Money(BigDecimal amount, Currency currency) {
    // Cả hai trường đều final — hoàn toàn bất biến
    public Money add(Money other) {
        // Trả về object mới, không sửa đổi object hiện tại
        return new Money(this.amount.add(other.amount), this.currency);
    }
}
```

### Best Practices

```java
// ✅ Record cho dữ liệu bất biến
public record User(String name, Email email) {}

// ✅ Bản sao phòng thủ cho các thành phần mutable
public record Tags(List<String> values) {
    public Tags { values = List.copyOf(values); }
}

// ✅ Collection bất biến
public record Config(Map<String, String> props) {
    public Config { props = Map.copyOf(props); }
}

// ❌ Các thành phần mutable không được bảo vệ
public record BadRecord(Date date, int[] array) {}
// ❌ Mong đợi rằng final = hoàn toàn bất biến
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Tất cả các trường của Record tự động là `private final` — trình biên dịch thêm final
- Final nghĩa là bạn không thể thay thế tham chiếu, nhưng object mutable bên trong có thể bị thay đổi
- Mảng, Date, collection — các thành phần mutable, cần bản sao phòng thủ
- `List.copyOf()`, `Set.copyOf()`, `Map.copyOf()` để bảo vệ collection mutable
- Trường final đảm bảo safe publication trong môi trường đa luồng (mà không cần volatile)
- JIT có thể tối ưu hóa trường final tốt hơn (inline)

**Các câu hỏi phụ thường gặp:**
- **Có thể thay đổi một mảng bên trong Record không?** — Có, mảng là mutable: `record.values()[0] = 99`
- **Cách bảo vệ thành phần mutable?** — Bản sao phòng thủ trong compact constructor: `tags = List.copyOf(tags)`
- **Final = hoàn toàn bất biến?** — Không, final chỉ bảo vệ tham chiếu, không phải nội dung object
- **Tại sao final quan trọng cho key HashMap?** — Key bị sửa đổi = hashCode hỏng, dữ liệu bị mất

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Final nghĩa là hoàn toàn bất biến" — Các thành phần mutable có thể bị thay đổi
- ❌ "Mảng trong Record an toàn" — Mảng luôn mutable, cần bản sao phòng thủ
- ❌ "Có thể thay đổi trường qua setter" — Trường là final, setter là bất khả thi
- ❌ "Final không mang lại lợi ích gì" — Final mang lại safe publication và tối ưu hóa JIT

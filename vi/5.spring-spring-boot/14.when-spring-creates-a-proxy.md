# When Does Spring Create a Proxy? (Khi nào Spring tạo một Proxy?)

## Junior Level

**Spring tạo một proxy khi nó thấy các annotation đặc biệt:**

| Annotation          | Proxy thêm gì    |
| ------------------ | ----------------------- |
| **@Transactional** | Quản lý transaction |
| **@Async**         | Thực thi bất đồng bộ  |
| **@Cacheable**     | Cache kết quả |
| **@PreAuthorize**  | Kiểm tra quyền truy cập   |

```java
@Service
public class MyService {

    @Transactional  // Proxy cho transaction
    public void save() { }

    @Async  // Proxy cho bất đồng bộ
    public CompletableFuture<Void> process() { }
}
```

---

## Middle Level

### Các trigger về mặt chức năng

**@Transactional:**
```
Proxy -> mở transaction -> gọi phương thức -> commit/rollback
```

**@Async:**
```
Proxy -> chuyển task cho TaskExecutor -> trả về Future ngay lập tức
```

**@Cacheable:**
```
Proxy -> kiểm tra cache -> nếu có -> trả về từ cache
     -> nếu không -> gọi phương thức -> lưu vào cache
```

**Scoped Proxy:**
```java
@Scope(value = "request", proxyMode = ScopedProxyMode.TARGET_CLASS)
// Proxy tìm bean thực tế trong RequestContextHolder
```

### Cơ chế tạo

```
BeanPostProcessor.postProcessAfterInitialization():
  -> AnnotationAwareAspectJAutoProxyCreator quét bean
  -> Tìm thấy annotation -> tạo proxy
  -> Proxy thay thế bean gốc trong context
```

## Senior Level

### AnnotationAwareAspectJAutoProxyCreator

```
BPP chính để tạo proxy:
  1. Quét tất cả các annotation và @Aspect
  2. Với mỗi bean, kiểm tra Pointcut
  3. Nếu khớp -> tạo proxy
  4. Proxy đi tiếp xuống chuỗi BPP
```

### Tránh các proxy không cần thiết

```
Proxy = overhead (bộ nhớ + CPU)
-> Đừng đặt @Transactional trên các phương thức chỉ đọc và không cần một ảnh chụp dữ liệu nhất quán. Nếu cần transaction, dùng readOnly = true để Hibernate tối ưu (bỏ qua dirty checking).
-> Proxy được tạo cho TOÀN BỘ bean, kể cả khi chỉ có một annotation
```

### Kinh nghiệm Production

**Tình huống thực tế: proxy không cần thiết**
```
Mỗi proxy - một đối tượng bổ sung trong bộ nhớ và một overhead nhỏ khi gọi (cỡ nanosecond). Với nhiều bean, điều này cộng dồn lại.

Giải pháp: bỏ @Transactional khỏi các phương thức đọc
-> Ít proxy hơn, ít overhead hơn
```

### Best Practices

1. **@Transactional** -> chỉ ở nơi cần
2. **@Async** -> cẩn thận, proxy trên toàn bộ bean
3. **Scoped Proxy** -> cho web scope trong Singleton
4. **Đừng proxy** các class/phương thức final
5. **Giảm thiểu** số lượng proxy
6. **AopUtils** -> để kiểm tra proxy

### Tóm tắt cho Senior

- **Proxy** được tạo cho @Transactional, @Async, @Cacheable
- **BPP** -> postProcessAfterInitialization
- **Scoped Proxy** -> cho web scope trong Singleton
- **Mỗi proxy** = overhead bộ nhớ + CPU
- **final** -> không được proxy
- **AnnotationAwareAspectJAutoProxyCreator** -> bộ tạo chính

## Interview Cheat Sheet

**Cần phải biết:**
- Proxy được tạo cho @Transactional, @Async, @Cacheable, @PreAuthorize
- Cơ chế: AnnotationAwareAspectJAutoProxyCreator (BeanPostProcessor) trong postProcessAfterInitialization()
- Scoped Proxy (@Scope với proxyMode) — tạo proxy cho web scope trong các Singleton bean
- Mỗi proxy = overhead bộ nhớ + CPU nhỏ (cỡ nanosecond mỗi lời gọi)
- Spring quét tất cả các annotation và @Aspect, kiểm tra Pointcut, tạo proxy
- @Transactional trên các phương thức đọc mà không cần thiết là overhead thừa — dùng readOnly = true

**Các câu hỏi phụ thường gặp:**
- *Component nào chịu trách nhiệm tạo proxy?* -> AnnotationAwareAspectJAutoProxyCreator (BPP)
- *Khi nào một Scoped Proxy được tạo?* -> Khi `@Scope(value="request", proxyMode=TARGET_CLASS)`
- *Có thể tránh việc tạo proxy không?* -> Có, đừng đặt annotation ở nơi không cần
- *Spring quyết định tạo loại proxy nào như thế nào?* -> proxy-target-class=true -> CGLIB, false + có interface -> JDK Proxy

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Proxy được tạo cho mọi bean" — chỉ khi có các annotation AOP
- "@Transactional trên các phương thức đọc luôn cần thiết" — overhead thừa nếu không cần
- "Proxy thêm độ trễ đáng kể" — cỡ nanosecond
- "Các class final được proxy qua CGLIB" — không được proxy

# What is an unchecked exception (Runtime Exception)? (Unchecked exception (Runtime Exception) là gì?)

## Junior Level

### Định nghĩa

**Unchecked exception** là các exception kế thừa từ `RuntimeException`. Trình biên dịch (compiler) **không bắt buộc** xử lý chúng.

### Cây phân cấp

```
Throwable
  └── Exception
        └── RuntimeException  <- unchecked
              ├── NullPointerException
              ├── IllegalArgumentException
              ├── IndexOutOfBoundsException
              ├── ArithmeticException
              └── ClassCastException
```

### Ví dụ

```java
// NullPointerException - phổ biến nhất
String s = null;
s.length(); // NPE

// IllegalArgumentException
public void setAge(int age) {
    if (age < 0) throw new IllegalArgumentException("Age must be positive");
}

// ArithmeticException
int x = 10 / 0; // ArithmeticException
```

### Khi nào chúng xảy ra

- Lỗi lập trình (null, sai tham số)
- Vi phạm hợp đồng của phương thức
- Lỗi logic trong code

### Có nên xử lý chúng không?

Các unchecked exception cơ bản (NPE, IllegalArgumentException) báo hiệu bug. Tuy nhiên, các domain unchecked exception (`UserNotFoundException`, `OrderAlreadyExistsException`) là các tình huống nghiệp vụ được lường trước, không phải bug.

## Middle Level

### Khi nào KHÔNG nên dùng unchecked exception

1. **Public library** cho lập trình viên bên thứ ba - checked exception ép buộc việc xử lý hữu ích
2. **Đội không có văn hóa xử lý lỗi** - checked = bảo hiểm chống sự đãng trí
3. **Hệ thống then chốt** - nếu bỏ qua một lỗi = thiệt hại tài chính, checked sẽ ép buộc việc xử lý

### Bên trong: fillInStackTrace()

"Chi phí" chính của một exception là phương thức native `fillInStackTrace()`, thứ duyệt stack của thread. Trong các hệ thống tải cao (100k+ RPS), việc sinh exception có thể ngốn 20-30% CPU.

### Nguyên tắc Fail-Fast

Fail-Fast - nguyên tắc: một lỗi nên bộc lộ càng sớm càng tốt, không "rò rỉ" qua 10 tầng code. NPE ở dòng `s.length()` chỉ ngay lập tức ra vấn đề, thay vì "nổi lên" sau một giờ hoạt động.

Unchecked exception là lý tưởng để hiện thực Fail-Fast:

```java
public User findUser(Long id) {
    Objects.requireNonNull(id, "ID cannot be null");
    // Nếu null - lỗi ngay lập tức, không phải sâu 10 tầng
    return repository.findById(id)
        .orElseThrow(() -> new UserNotFoundException("User not found: " + id));
}
```

### Xử lý tập trung

Trong Spring Boot, dùng `@ControllerAdvice` + `@ExceptionHandler`:

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(UserNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(UserNotFoundException e) {
        return ResponseEntity.status(404)
            .body(new ErrorResponse("USER_NOT_FOUND", e.getMessage()));
    }

    @ExceptionHandler(ValidationException.class)
    public ResponseEntity<ErrorResponse> handleValidation(ValidationException e) {
        return ResponseEntity.status(400)
            .body(new ErrorResponse("VALIDATION_ERROR", e.getMessage()));
    }
}
// Luồng: Exception "trồi lên" qua tất cả các tầng service ->
// Spring tìm @ExceptionHandler với kiểu khớp ->
// Gọi phương thức -> ResponseEntity trở thành JSON response.
```

### Tại sao Spring chọn unchecked

1. **Sự sạch sẽ của code** - không có tạp nhiễu `try-catch`
2. **Xử lý tập trung** - mọi lỗi trồi lên tới `@ControllerAdvice`
3. **Lập trình Reactive** - trong Project Reactor, checked exception gần như bất khả thi

## Senior Level

### Hiệu suất và tối ưu hóa

**Pre-instantiated Exceptions** - với các lỗi xảy ra thường xuyên, bạn có thể tạo một exception singleton không có stack trace:

```java
public static final ValidationException INVALID_FORMAT =
    new ValidationException("Invalid format", null, false, false);
```

Exception này không tạo tải cho GC, nhưng làm việc debug khó hơn (không có stack trace).

### Anti-pattern Control Flow

Đừng bao giờ dùng exception cho control flow (luồng điều khiển):

```java
// XẤU - chậm và khó đọc
try {
    User user = findUser(id);
} catch (UserNotFoundException e) {
    // chuyển sang bước tiếp theo
}

// TỐT
Optional<User> user = findUser(id);
if (user.isPresent()) { ... }
```

Trả về `Optional` nhanh hơn 100-1000 lần so với ném một exception.

### Error so với RuntimeException

Đừng nhầm lẫn chúng:
- **Error** - vấn đề của JVM (`OutOfMemoryError`, `StackOverflowError`). Bắt là thực hành xấu
- **RuntimeException** - lỗi của ứng dụng. Xử lý tập trung

### Nuốt Exception (Swallowing)

Tội ác tồi tệ nhất:
```java
catch (RuntimeException e) { } // Âm thầm nuốt bug
```

### Chẩn đoán và giám sát

- **Micrometer** - đếm số `RuntimeException`. Số NPE tăng vọt là lý do để rollback một lần deploy
- **Log Enrichment** - ghi log ngữ cảnh (`userId`, `orderId`), không chỉ stack trace
- **Metric-driven Exception Tracking** - cảnh báo dựa trên các bất thường trong exception

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Unchecked exception kế thừa từ `RuntimeException`, compiler không bắt buộc xử lý
- Unchecked cơ bản (NPE, IllegalArgumentException) báo hiệu bug; domain (`UserNotFoundException`) - tình huống nghiệp vụ
- Fail-Fast - lỗi nên bộc lộ càng sớm càng tốt
- Spring Boot xử lý unchecked tập trung qua `@ControllerAdvice` + `@ExceptionHandler`
- `fillInStackTrace()` - phần đắt đỏ nhất, có thể ngốn 20-30% CPU ở mức 100k+ RPS
- Pre-instantiated exception (singleton) giảm tải cho GC
- Đừng bao giờ dùng exception cho control flow - `Optional` nhanh hơn 100-1000 lần
- Nuốt exception (`catch (RuntimeException e) {}`) - tội ác tồi tệ nhất

**Các câu hỏi phụ thường gặp:**
- **Tại sao Spring ưa chuộng unchecked exception?** - Sự sạch sẽ của code, xử lý tập trung qua `@ControllerAdvice`, tương thích với lập trình Reactive
- **Khi nào KHÔNG khuyến nghị dùng unchecked exception?** - Public library, đội không có văn hóa xử lý lỗi, hệ thống tài chính then chốt
- **Cách tăng tốc việc tạo các exception thường xuyên?** - Pre-instantiated exception với `writableStackTrace = false`
- **Error khác RuntimeException như thế nào?** - Error - vấn đề của JVM (đừng bắt), RuntimeException - lỗi ứng dụng (xử lý tập trung)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi dùng exception cho control flow của logic nghiệp vụ" - đây là anti-pattern, chậm và khó đọc
- "Unchecked exception hoàn toàn không cần xử lý" - có cần, nhưng tập trung
- "Âm thầm nuốt RuntimeException là thực hành bình thường" - nó che giấu bug

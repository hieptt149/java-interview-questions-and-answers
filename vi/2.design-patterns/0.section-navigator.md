## Các mối liên kết chính giữa các chủ đề

### Chủ đề: Singleton

```
Q3 (Singleton) -> Q4 (Thread-safe) -> Q5 (DCL) -> Q6 (Các vấn đề)
```

**Các mối liên kết chính:**
- Q4 <-> Q5: DCL — một trong những cách triển khai Singleton an toàn với đa luồng
- Q6 <-> Q3: DI container (Spring) giải quyết các vấn đề của Singleton

### Chủ đề: Creational Patterns (Các mẫu khởi tạo)

```
Q7 (Factory) -> Q8 (Builder) -> Q9 (Prototype)
```

**Các mối liên kết chính:**
- Q7 <-> Q8: Factory = nhiều cách khác nhau để tạo đối tượng, Builder = tạo đối tượng theo từng bước
- Q8 <-> Q9: Builder = xây dựng, Prototype = sao chép

### Chủ đề: Behavioral Patterns (Các mẫu hành vi)

```
Q10 (Strategy) -> Q11 (Observer) -> Q13 (State vs Strategy)
```

**Các mối liên kết chính:**
- Q10 <-> Q13: Strategy = thuật toán được thay đổi từ bên ngoài, State = trạng thái được thay đổi từ bên trong
- Q11 <-> Q13: Observer = thông báo cho các subscriber (người đăng ký), State = ủy quyền hành vi (delegate behavior)

### Chủ đề: Structural Patterns (Các mẫu cấu trúc)

```
Q12 (Decorator) -> Q14 (Proxy) -> Q15 (Iterator)
```

**Các mối liên kết chính:**
- Q12 <-> Q14: Decorator thêm hành vi, Proxy kiểm soát quyền truy cập
- Q14 <-> Q6: Proxy giải quyết các vấn đề của Singleton (self-invocation, khả năng kiểm thử)

## Bảng tóm tắt: Cần biết gì cho mỗi cấp độ

### Junior
- Pattern — các giải pháp đã được kiểm chứng cho các bài toán điển hình
- 3 nhóm: creational (khởi tạo), structural (cấu trúc), behavioral (hành vi)
- Singleton = một instance duy nhất, Factory = khởi tạo đối tượng
- Builder = khởi tạo từng bước các đối tượng phức tạp

### Middle
- Bill Pugh Singleton = static inner class (lớp lồng tĩnh), an toàn với đa luồng mà không cần synchronized
- DCL = double check (kiểm tra hai lần) + volatile, tối ưu hóa synchronized
- DI container (Spring) giải quyết các vấn đề của Singleton
- Strategy = thuật toán thông qua interface, Observer = đăng ký nhận sự kiện
- Decorator vs kế thừa (inheritance): n decorator thay vì 2^n lớp

### Senior
- JMM (Java Memory Model): volatile = đảm bảo happens-before, DCL không có volatile = bị lỗi
- Ngưỡng megamorphic call = 5 trong HotSpot, tối ưu hóa inline cache
- java.util.Observable đã bị deprecated (từ Java 9), hãy dùng Flow API
- JDK Proxy ~= hiệu năng của CGLIB (từ JDK 8u40+), Spring Boot mặc định dùng = CGLIB
- clone() bỏ qua constructor (hàm khởi tạo), copy constructor đáng tin cậy hơn
- Chuyển trạng thái State thông qua Registry/Factory, không phải thông qua new State()

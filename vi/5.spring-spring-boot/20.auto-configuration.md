# What is Auto-Configuration in Spring Boot? (Auto-Configuration trong Spring Boot là gì?)

## Junior Level

**Auto-configuration** (tự động cấu hình) — Spring Boot tự cấu hình các bean, dựa vào những gì có trong classpath.

**Ví dụ minh họa đơn giản:** Một ngôi nhà thông minh. Bạn bước vào phòng — đèn tự bật. Bạn không cần bấm công tắc.

```java
// Không có Spring Boot:
@Bean
public DataSource dataSource() {
    // Cấu hình thủ công...
}

// Có Spring Boot:
// Chỉ cần thêm dependency vào pom.xml:
// <dependency>spring-boot-starter-data-jpa</dependency>
// -> DataSource sẽ được tạo tự động!
```

**Cách tắt:**
```java
@SpringBootApplication(exclude = {DataSourceAutoConfiguration.class})
```

## Middle Level

### Cách hoạt động

```
@SpringBootApplication
  -> @EnableAutoConfiguration
    -> AutoConfigurationImportSelector
      -> Đọc spring.factories (Boot 2.x)
      -> hoặc .imports (Boot 3.x)
        -> Nạp các auto-configuration
```

### Các annotation @Conditional

```java
@ConditionalOnClass(DataSource.class)  // Nếu class tồn tại
@ConditionalOnMissingBean              // Nếu chưa có bean như vậy
@ConditionalOnProperty("app.enabled")  // Nếu property là true
@ConditionalOnWebApplication           // Nếu là ứng dụng web
```

### Ví dụ Auto-Configuration

```java
@Configuration
@ConditionalOnClass(ObjectMapper.class)  // Nếu có Jackson
@ConditionalOnMissingBean(ObjectMapper.class)  // Nếu bạn chưa tự tạo
public class JacksonAutoConfiguration {

    @Bean
    @Primary
    public ObjectMapper objectMapper() {
        return new ObjectMapper();  // Tạo một cái mặc định
    }
}
```

### Debug

```bash
# Chạy với báo cáo:
java -jar app.jar --debug

# Đầu ra: Condition Evaluation Report
# -> Cho thấy tại sao mỗi bean được tạo hay không
```

## Senior Level

### Spring Boot 2.x so với 3.x

```
Boot 2.x:
  -> META-INF/spring.factories
  -> Key: EnableAutoConfiguration
  -> Các file này chứa một danh sách các class auto-configuration (tên class đầy đủ), mỗi dòng một cái. Spring Boot đọc chúng lúc khởi động và đăng ký các bean được chỉ định.

Boot 3.x:
  -> META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
  -> Chỉ là một danh sách các class
  -> Nhanh hơn, hỗ trợ GraalVM Native
```

### Thứ tự nạp

```java
@AutoConfigureAfter(DataSourceAutoConfiguration.class)
@AutoConfigureBefore(HibernateJpaAutoConfiguration.class)
public class MyAutoConfiguration { }

-> Cực kỳ quan trọng đối với các phụ thuộc giữa các configuration!
```

### Tạo Auto-Configuration của riêng bạn

```java
// Trong một module riêng: mylib-autoconfigure
@AutoConfiguration
@ConditionalOnClass(MyService.class)
public class MyLibAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean
    public MyService myService() {
        return new MyService();
    }
}

// Trong META-INF/spring/...AutoConfiguration.imports:
com.example.MyLibAutoConfiguration
```

### Kinh nghiệm Production

**Tình huống thực tế: khởi động chậm**
```
Số lượng lớn các auto-configuration làm tăng thời gian khởi động.
Loại bỏ những cái không cần thiết qua exclude và giới hạn phạm vi quét package có thể giảm thời gian khởi động 20-40%.
```

### Best Practices

1. **@ConditionalOnMissingBean** -> cho phép ghi đè
2. **@AutoConfiguration** (Spring Boot 2.7+: thay thế cho @Configuration đối với auto-configuration. Với Boot 3.x dùng file `.imports`, với Boot 2.x — `spring.factories`).
3. **exclude** -> tắt những cái không cần thiết
4. **--debug** -> debug cấu hình
5. **Thứ tự** -> các annotation After/Before
6. **Boot 3.x** -> định dạng .imports mới

### Tóm tắt cho Senior

- **Auto-configuration** = Convention over Configuration
- **@Conditional** -> kiểm tra điều kiện
- **Boot 3.x** -> .imports thay vì spring.factories
- **Thứ tự** -> cực kỳ quan trọng đối với các phụ thuộc
- **Auto-configuration của riêng bạn** -> module riêng
- **--debug** -> Condition Evaluation Report

## Interview Cheat Sheet

**Cần phải biết:**
- Auto-configuration = Convention over Configuration: Spring Boot cấu hình các bean theo classpath
- @SpringBootApplication -> @EnableAutoConfiguration -> AutoConfigurationImportSelector
- Boot 2.x đọc META-INF/spring.factories, Boot 3.x -> META-INF/spring/...AutoConfiguration.imports
- @ConditionalOnClass, @ConditionalOnMissingBean, @ConditionalOnProperty — các annotation conditional chính
- @ConditionalOnMissingBean cho phép ghi đè một bean bằng cấu hình của riêng bạn
- Thứ tự: @AutoConfigureAfter / @AutoConfigureBefore cho các phụ thuộc giữa các configuration
- Tắt: @SpringBootApplication(exclude = {...})
- Debug: --debug -> Condition Evaluation Report
- Auto-configuration của riêng bạn — module riêng với file .imports

**Các câu hỏi phụ thường gặp:**
- *Spring Boot làm sao biết cần cấu hình gì?* -> Quét classpath, đọc .imports/spring.factories, kiểm tra @Conditional
- *Boot 3.x khác 2.x như thế nào?* -> File .imports thay vì spring.factories, nhanh hơn, hỗ trợ GraalVM Native
- *Làm sao ghi đè auto-configuration?* -> Tạo @Bean của riêng bạn cùng kiểu — @ConditionalOnMissingBean sẽ không tạo cái mặc định
- *Làm sao tìm ra tại sao một bean KHÔNG được tạo?* -> Chạy với --debug, xem Condition Evaluation Report

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Auto-configuration luôn tạo tất cả các bean" — chỉ khi các điều kiện @Conditional được thỏa mãn
- "spring.factories được dùng trong Boot 3.x" — đã bị thay bằng .imports
- "@ConditionalOnMissingBean kiểm tra classpath" — kiểm tra bean trong context
- "Auto-configuration làm chậm ứng dụng lúc runtime" — chỉ ảnh hưởng đến khởi động, không phải runtime

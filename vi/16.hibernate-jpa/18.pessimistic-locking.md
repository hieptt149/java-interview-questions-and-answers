# How to Implement Pessimistic Locking in JPA (Cách triển khai pessimistic locking trong JPA)

## Overview

Pessimistic locking (khóa bi quan) khóa các dòng ở cấp độ DBMS, ngăn chặn truy cập đồng thời. Các transaction khác không thể đọc hoặc ghi dữ liệu bị khóa cho đến khi transaction hiện tại hoàn thành.

---

## Junior Level

### Pessimistic Locking Là Gì

Pessimistic locking - khóa một dòng trong DB ở cấp độ DBMS. Các transaction khác **không thể** đọc/ghi dữ liệu bị khóa.

```java
// Write lock - các cái khác không thể đọc/ghi
Order order = entityManager.find(Order.class, 1L,
    LockModeType.PESSIMISTIC_WRITE);

// Read lock - các cái khác có thể đọc, nhưng không ghi
Order order = entityManager.find(Order.class, 1L,
    LockModeType.PESSIMISTIC_READ);

// NOWAIT - không chờ, lỗi ngay lập tức nếu bị khóa
Order order = entityManager.find(Order.class, 1L,
    LockModeType.PESSIMISTIC_WRITE,
    Map.of("jakarta.persistence.lock.timeout", 0));
```

### Khi Nào Dùng

- Dữ liệu quan trọng thường xuyên được cập nhật
- Khi xung đột phổ biến (optimistic locking không phù hợp)
- Các thao tác tài chính, tồn kho, booking

## Middle Level

### LockModeType

```
PESSIMISTIC_READ:
- SELECT ... FOR SHARE (PostgreSQL) (PostgreSQL 9.3+; các phiên bản cũ hơn dùng FOR UPDATE)
- Các transaction khác có thể đọc, nhưng không ghi

PESSIMISTIC_WRITE:
- SELECT ... FOR UPDATE
- Các transaction khác không thể đọc hoặc ghi

PESSIMISTIC_FORCE_INCREMENT:
- UPDATE + tăng version
- Kết hợp giữa pessimistic locking và optimistic versioning
```

### Timeout

```java
// timeout 5 giây - chờ tối đa 5 giây
entityManager.find(Order.class, id,
    LockModeType.PESSIMISTIC_WRITE,
    Map.of("jakarta.persistence.lock.timeout", 5000));

// NOWAIT - không chờ chút nào
entityManager.find(Order.class, id,
    LockModeType.PESSIMISTIC_WRITE,
    Map.of("jakarta.persistence.lock.timeout", 0));
```

### Ví Dụ Sử Dụng

```java
@Transactional
public Order processOrder(Long id) {
    // Write lock - các transaction khác chờ
    Order order = entityManager.find(Order.class, id,
        LockModeType.PESSIMISTIC_WRITE);

    // Xử lý - các transaction khác chờ hoàn thành
    order.setStatus("processing");
    order.setProcessedAt(LocalDateTime.now());

    return order;
    // Khi commit - khóa được giải phóng
}
```

### Deadlock

```
Transaction 1: khóa A -> chờ B
Transaction 2: khóa B -> chờ A
Deadlock! -> một transaction bị rollback bởi DB

// Xử lý deadlock
try {
    Order order = entityManager.find(Order.class, id,
        LockModeType.PESSIMISTIC_WRITE);
} catch (PessimisticLockException | LockAcquisitionException e) {
    // retry hoặc xử lý lỗi
}
```

### Các Lỗi Thường Gặp

```java
// Transaction dài với khóa
@Transactional
public void longProcess(Long id) {
    Order order = entityManager.find(Order.class, id,
        LockModeType.PESSIMISTIC_WRITE);
    // ... xử lý dài ...
    // Các transaction khác chờ suốt thời gian này!
}

// Transaction ngắn
@Transactional
public Order lockAndProcess(Long id) {
    Order order = entityManager.find(Order.class, id,
        LockModeType.PESSIMISTIC_WRITE);
    order.setStatus("processing");
    return order;  // hoàn thành nhanh chóng
}
```

## Senior Level

### Triển Khai Nội Bộ

```
PostgreSQL: SELECT ... FOR UPDATE
MySQL:      SELECT ... FOR UPDATE
Oracle:     SELECT ... FOR UPDATE NOWAIT / WAIT n
SQL Server: SELECT ... WITH (UPDLOCK, ROWLOCK)

Hibernate tạo ra SQL đúng cho mỗi DBMS.
```

### NOWAIT Và SKIP LOCKED

```java
// NOWAIT - lỗi ngay lập tức nếu bị khóa
Map<String, Object> nowait = Map.of(
    "jakarta.persistence.lock.timeout", 0
);

// SKIP LOCKED - bỏ qua các dòng bị khóa (Hibernate 6+)
// Hữu ích cho các task queue
//
// SKIP LOCKED - bỏ qua các dòng bị khóa. Trong JPA điều này được triển khai thông qua
// query hint 'jakarta.persistence.lock.scope' = EXTENDED, nhưng hỗ trợ đầy đủ
// phụ thuộc vào provider và phiên bản Hibernate. Trong Hibernate 6+ nó hoạt động ổn định.
@Query("SELECT t FROM Task t WHERE t.status = 'PENDING'")
List<Task> findAvailableTasks(
    @Param("jakarta.persistence.lock.scope") LockScope EXTENDED,
    @Param("jakarta.persistence.lock.timeout", 0)
);
```

### Khóa Ở Cấp Độ Truy Vấn

```java
// Khóa trong truy vấn JPQL
@Query("SELECT o FROM Order o WHERE o.status = :status")
@Lock(LockModeType.PESSIMISTIC_WRITE)
List<Order> findOrdersForUpdate(@Param("status") String status);

// Khóa trong truy vấn native
@Query(value = "SELECT * FROM orders WHERE id = :id FOR UPDATE",
       nativeQuery = true)
Order findByIdForUpdate(@Param("id") Long id);
```

### Các Pattern Production

```java
// Pattern 1: Booking với khóa
@Transactional
public boolean reserveItem(Long itemId, int quantity) {
    Item item = entityManager.find(Item.class, itemId,
        LockModeType.PESSIMISTIC_WRITE);

    if (item.getStock() >= quantity) {
        item.setStock(item.getStock() - quantity);
        return true;
    }
    return false;
}

// Pattern 2: Xử lý queue với SKIP LOCKED
@QueryHints({
    @QueryHint(name = "jakarta.persistence.lock.timeout", value = "0"),
    @QueryHint(name = "jakarta.persistence.lock.scope", value = "EXTENDED")
})
@Lock(LockModeType.PESSIMISTIC_WRITE)
@Query("SELECT t FROM Task t WHERE t.status = 'PENDING' ORDER BY t.createdAt")
List<Task> findNextAvailableTask();
```

### Tối Ưu

```
Transaction ngắn với khóa
Timeout để ngăn ngừa chờ lâu
Index cho các cột bị khóa
Retry khi deadlock
SKIP LOCKED cho các queue

Transaction dài với khóa
Không có timeout
Không index các cột bị khóa
Khóa mà không cần thiết
Bỏ qua PessimisticLockException
```

### Monitoring

```java
// Giám sát các khóa trong PostgreSQL
@Query(value = """
    SELECT blocked_locks.pid     AS blocked_pid,
           blocking_locks.pid    AS blocking_pid,
           blocked_activity.query AS blocked_statement
    FROM pg_catalog.pg_locks blocked_locks
    JOIN pg_catalog.pg_stat_activity blocked_activity ON blocked_activity.pid = blocked_locks.pid
    JOIN pg_catalog.pg_locks blocking_locks ON blocking_locks.locktype = blocked_locks.locktype
    WHERE NOT blocked_locks.granted
    """, nativeQuery = true)
List<Object[]> findBlockedQueries();
```

### Best Practices

```
Transaction ngắn
Lock timeout
Index cho các cột bị khóa
Retry khi deadlock
SKIP LOCKED cho các queue
PESSIMISTIC_WRITE cho dữ liệu quan trọng

Transaction dài với khóa
Không có timeout
Không index
Khóa cho các thao tác chỉ đọc
Bỏ qua LockAcquisitionException
```

## Interview Cheat Sheet

**Cần phải biết:**
- Pessimistic locking - SELECT ... FOR UPDATE ở cấp độ DBMS
- LockModeType: PESSIMISTIC_READ (FOR SHARE), PESSIMISTIC_WRITE (FOR UPDATE)
- Timeout: jakarta.persistence.lock.timeout (0 = NOWAIT, ngược lại tính bằng mili giây)
- Deadlock có thể xảy ra - một transaction sẽ bị rollback bởi DB
- SKIP LOCKED (Hibernate 6+) - bỏ qua các dòng bị khóa, hữu ích cho các queue
- Transaction ngắn - các transaction khác chờ khóa hoàn thành

**Các câu hỏi phụ thường gặp:**
- **Khi nào pessimistic tốt hơn optimistic?** Xung đột thường xuyên, dữ liệu quan trọng, các thao tác tài chính
- **SKIP LOCKED là gì?** Bỏ qua các dòng bị khóa - lý tưởng cho các task queue
- **Khóa READ vs WRITE?** READ - các cái khác có thể đọc nhưng không ghi; WRITE - các cái khác không thể đọc/ghi
- **Cách xử lý deadlock?** Logic retry, giám sát các truy vấn bị block, index cho các cột bị khóa

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Transaction dài với khóa" - các transaction khác chờ suốt thời gian đó
- "Không có timeout cho khóa" - chờ vô hạn
- "Pessimistic cho chỉ đọc" - khóa không cần thiết
- "Tôi bỏ qua LockAcquisitionException" - deadlock không được xử lý

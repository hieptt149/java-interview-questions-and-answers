```
Q1 (String Pool) → Q2 (Literal vs new) → Q3 (intern())
     ↓
Q11 (Nơi lưu trữ) → Q12 (OOM từ String Pool)
```

**Các kết nối then chốt:**
- Q1 ↔ Q11: String Pool được lưu trong Java Heap (kể từ Java 7u6)
- Q3 ↔ Q12: intern() hàng loạt → tràn StringTable → OOM
- Q2 ↔ Q3: `new String("...").intern()` vs `"..."` — khi nào hợp lý

```
Q4 (Tính bất biến) → Q5 (StringBuilder vs StringBuffer) → Q6 (Tại sao StringBuffer chậm hơn)
```

**Các kết nối then chốt:**
- Q4 ↔ Q5: Tính bất biến = mỗi lần nối = object mới → StringBuilder cho việc sửa đổi

## 🎓 Tóm tắt: Cần biết gì cho mỗi cấp độ

### 🟢 Junior
- String là bất biến — không thể sửa đổi sau khi tạo
- Literal = từ pool, `new String()` = object mới
- StringBuilder cho việc sửa đổi, StringBuffer cho đa luồng
- `==` so sánh tham chiếu, `equals()` — nội dung
- `+` ổn cho 1-2 chuỗi, cho các vòng lặp — dùng StringBuilder

### 🟡 Middle
- String Pool trong Java Heap (kể từ Java 7u6), intern() tiết kiệm bộ nhớ trên các bản trùng lặp
- Compact String (Java 9+): Latin1 (1 byte/ký tự) cho ASCII, UTF-16 cho các ký tự khác
- `split()` — Fast Path cho các dấu phân cách đơn giản, regex cho trường hợp phức tạp
- `replace()` — thay thế theo nghĩa đen (literal), `replaceAll()` — regex
- Encoding mặc định phụ thuộc vào OS — luôn chỉ định tường minh

### 🔴 Senior
- StringTable — hash table native, có thể resize kể từ JDK 11 (JEP 341)
- substring Java 6: chia sẻ char[] (rò rỉ bộ nhớ), Java 7+: sao chép mảng
- invokedynamic cho việc nối chuỗi (JEP 280, Java 9+), StringConcatFactory
- Annotation `@Stable`, trường coder, các tối ưu hóa SIMD cho equals()
- Reflection trên String bị chặn bởi module system (Java 9+, thực thi nghiêm ngặt từ Java 16+)
- G1 String Deduplication: tiết kiệm 10-30% bộ nhớ trên các bản trùng lặp, không dành cho ZGC

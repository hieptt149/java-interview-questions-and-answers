# What is the difference between shallow copy and deep copy? (Sự khác biệt giữa shallow copy và deep copy là gì?)

---

## Basic Level

- **Shallow Copy** — sao chép container, nhưng các phần tử bên trong vẫn là các tham chiếu dùng chung với bản gốc
- **Deep Copy** — sao chép đệ quy container và tất cả các object lồng nhau bên trong nó

### Ví Dụ Về Vấn Đề
```java
public class User {
    private String name;
    private Address address; // mutable
}

User original = new User("Alice", new Address("Hanoi"));
User shallow = original; // Không phải một bản sao thực sự, cùng tham chiếu!
```
```java
List<User> copy = new ArrayList<>(originalList); // Shallow Copy
copy.get(0).getAddress().setCity("HCMC"); // Cũng thay đổi object User trong originalList!
```

### Analogy (Phép So Sánh)
Shallow Copy giống như sao chép một danh sách địa chỉ nhưng vẫn trỏ đến cùng những ngôi nhà thật; Deep Copy giống như xây một bản sao hoàn toàn mới của từng ngôi nhà.

## Intermediate Level

### Cơ Chế Của Shallow Copy

`Object.clone()` mặc định thực hiện Shallow Copy — nó sao chép các trường nguyên thủy theo giá trị, nhưng các trường tham chiếu vẫn trỏ đến cùng các object:
```java
class User implements Cloneable {
    private String name;
    private Address address;

    @Override
    public User clone() throws CloneNotSupportedException {
        return (User) super.clone(); // Shallow — address vẫn dùng chung!
    }
}
```

### Cơ Chế Của Deep Copy

**1. Copy constructor**
```java
public User(User other) {
    this.name = other.name;
    this.address = new Address(other.address); // sao chép object lồng nhau
}
```

**2. Serialization**
```java
// Sao chép qua serialize/deserialize (tốn kém, cần Serializable)
```

**3. Thư viện JSON**
```java
User deepCopy = objectMapper.readValue(objectMapper.writeValueAsString(original), User.class);
```

**4. Thư viện (Apache Commons, Gson, …)**

### Ví Dụ Code Deep Copy Với Cloneable
```java
class User implements Cloneable {
    private String name;
    private Address address;

    @Override
    public User clone() throws CloneNotSupportedException {
        User copy = (User) super.clone();
        copy.address = (Address) address.clone(); // sao chép sâu object lồng nhau
        return copy;
    }
}
```

### Khi Nào Dùng Cái Gì

| Tình huống                         | Cách tiếp cận  |
| ----------------------------------- | -------------- |
| Các object chỉ chứa kiểu nguyên thủy/bất biến | Shallow Copy   |
| Các object chứa các trường mutable lồng nhau  | Deep Copy      |
| Cần hiệu năng cao, ít bộ nhớ         | Shallow Copy   |
| Cần cô lập hoàn toàn khỏi bản gốc    | Deep Copy      |

## Advanced Level

### Shallow Immutability Là Nguồn Gốc Của Các Bug Ẩn

Ngay cả một `record` (bất biến ở cấp cao nhất) cũng có thể chứa lỗ hổng shallow:
```java
public record Team(String name, List<Player> players) {}

Team team = new Team("A", players); // players là List.copyOf() — không thể thêm/xóa
team.players().get(0).setScore(100); // Nhưng Player là mutable — VẪN CÓ THỂ thay đổi!
```
`record` chỉ đảm bảo tính bất biến của chính các trường của nó (Shallow), không đảm bảo tính bất biến của đồ thị object bên dưới.

### Hiệu Năng Của Deep Copy

Deep Copy có độ phức tạp **O(n × m)** (n phần tử, m độ sâu trung bình của đồ thị object mỗi phần tử) — tốn kém hơn nhiều so với Shallow Copy O(n).

### Structural Sharing (Chia Sẻ Cấu Trúc)

Các cấu trúc dữ liệu persistent (Vavr, PCollections) dùng **Structural Sharing**: khi "sửa đổi" một cấu trúc bất biến, chỉ những phần bị thay đổi được tạo mới, phần còn lại được dùng chung an toàn (vì bất biến) — mang lại độ phức tạp **O(log n)** thay vì O(n) cho việc sao chép toàn bộ.

### Tóm Tắt Cho Advanced
- Shallow Copy — nhanh (O(n)), nhưng các object lồng nhau vẫn dùng chung
- Deep Copy — an toàn hoàn toàn, nhưng tốn kém (O(n × m))
- record và các collection bất biến chỉ đảm bảo Shallow Immutability
- Structural Sharing (Vavr) — cách tiếp cận hiệu quả để có cả tính bất biến và hiệu năng

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Shallow Copy — sao chép container, các phần tử là tham chiếu dùng chung
- Deep Copy — sao chép đệ quy container và tất cả các object lồng nhau
- `Object.clone()` mặc định là Shallow
- Deep Copy: copy constructor, serialization, thư viện JSON, các thư viện chuyên dụng
- record/List.copyOf chỉ đảm bảo Shallow Immutability — các object lồng nhau vẫn có thể bị thay đổi
- Deep Copy: O(n × m); Structural Sharing (Vavr): O(log n)

**Các câu hỏi phụ thường gặp:**
- *clone() mặc định là shallow hay deep?* — Shallow
- *record có bảo vệ khỏi việc thay đổi các trường lồng nhau không?* — Không, chỉ bảo vệ Shallow
- *Khi nào Shallow Copy là đủ?* — Khi các phần tử là bất biến (String, Integer)
- *Structural Sharing là gì?* — Kỹ thuật dùng chung các phần không đổi giữa các phiên bản để tránh sao chép toàn bộ

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "clone() luôn tạo Deep Copy" — mặc định nó là Shallow
- "record hoàn toàn bất biến" — chỉ bất biến ở cấp trường, các object lồng nhau có thể mutable
- "Deep Copy luôn tốt hơn Shallow Copy" — Deep Copy tốn kém hơn nhiều, không phải lúc nào cũng cần
- "List.copyOf bảo vệ các phần tử bên trong" — chỉ bảo vệ container, không bảo vệ nội dung phần tử

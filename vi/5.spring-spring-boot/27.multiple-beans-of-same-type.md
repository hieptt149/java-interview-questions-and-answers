# What to Do If There Are Multiple Beans of the Same Type? (Làm gì khi có nhiều Bean cùng kiểu?)

## Junior Level

Nếu Spring tìm thấy nhiều bean cùng kiểu -> lỗi!

**Các giải pháp:**

**1. @Primary — bean chính:**
```java
@Primary
@Bean
public PaymentService defaultPayment() { ... }
```

**2. @Qualifier — chọn tường minh:**
```java
@Autowired
@Qualifier("stripePayment")
private PaymentService payment;
```

**3. Tên biến:**
```java
@Autowired
private PaymentService stripePayment;  // Theo tên bean!
```

---

## Middle Level

### Thứ tự phân giải

```
1. @Qualifier - bộ lọc tường minh theo tên (ưu tiên cao nhất)
2. @Primary - marker "mặc định" toàn cục
3. Tên biến (byName) - nếu không có @Qualifier và @Primary
4. @Priority (JSR-250) - ưu tiên dạng số ở cấp class
```

### Inject tất cả các bean

```java
// Tất cả các implementation của PaymentService
@Autowired
List<PaymentService> allPayments;

// Map: tên bean -> bean
@Autowired
Map<String, PaymentService> paymentMap;

// Cách dùng:
PaymentService service = paymentMap.get("stripe");
```

### ObjectProvider

```java
@Autowired
ObjectProvider<PaymentService> provider;

PaymentService service = provider.getIfAvailable(
    () -> new DefaultPaymentService()  // Fallback!
);
```

## Senior Level

### Custom Qualifier

```java
@Qualifier
@Retention(RUNTIME)
public @interface StripePayment { }

@StripePayment
@Bean
public PaymentService stripePayment() { ... }

@Autowired
@StripePayment
private PaymentService payment;

// -> Type-safe, không lỗi chính tả!
```

### Chẩn đoán NoUniqueBeanDefinitionException

```
// Spring Boot FailureAnalyzer tự động hiển thị tất cả các bean tìm thấy
// khi có NoUniqueBeanDefinitionException - không cần bới stack trace.
```

### Kinh nghiệm Production

**Tình huống thực tế: 10 implementation**
```
Strategy pattern:
  -> Map<String, Strategy> strategies
  -> Chọn theo key lúc runtime
  -> Không cần if/else!
```

### Best Practices

1. **@Primary** -> một bean chính
2. **@Qualifier** -> chọn tường minh
3. **Map** -> Strategy pattern
4. **Custom qualifier** -> type-safe
5. **ObjectProvider** -> fallback
6. **@ConditionalOnMissingBean** -> trong các starter

### Tóm tắt cho Senior

- **@Primary** -> bean mặc định
- **@Qualifier** -> chọn chính xác
- **Map** -> tất cả các bean, chọn theo key
- **Custom qualifier** -> type-safe
- **ObjectProvider** -> lazy + fallback
- **FailureAnalyzer** -> chẩn đoán lỗi

## Interview Cheat Sheet

**Cần phải biết:**
- Thứ tự phân giải: @Qualifier -> @Primary -> byName -> @Priority (JSR-250)
- @Primary — marker "bean mặc định" toàn cục cho một kiểu nhất định
- @Qualifier — bộ lọc tường minh theo tên, ưu tiên cao nhất
- Inject tất cả các bean: List<T> (thứ tự) hoặc Map<String, T> (tên -> bean) — Strategy pattern
- ObjectProvider.getIfAvailable(fallback) — lấy theo lối lazy với fallback
- Custom qualifier (@Qualifier + meta-annotation) — type-safe, không dùng chuỗi
- Spring Boot FailureAnalyzer tự động hiển thị tất cả các bean tìm thấy khi có NoUniqueBeanDefinitionException

**Các câu hỏi phụ thường gặp:**
- *Cái nào ưu tiên: @Primary hay @Qualifier?* — @Qualifier, lựa chọn tường minh luôn được ưu tiên.
- *Làm sao hiện thực Strategy pattern trong Spring?* — Map<String, Strategy> — key = tên bean, chọn lúc runtime không cần if/else.
- *Điều gì xảy ra nếu không có @Primary, không có @Qualifier, và không có tên khớp?* — NoUniqueBeanDefinitionException.
- *Tại sao cần custom qualifier?* — An toàn về kiểu: compiler bắt lỗi, không lỗi chính tả trong chuỗi.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "@Primary luôn ghi đè @Qualifier" — không, @Qualifier có ưu tiên cao nhất.
- "Map chỉ inject một bean" — không, Map chứa TẤT CẢ các bean của kiểu, key = tên.
- "Dùng chuỗi trong @Qualifier là ổn" — rủi ro: lỗi chính tả chỉ bị bắt lúc runtime.
- "Nếu có @Primary thì không có bean nào khác của kiểu này tồn tại" — không, tất cả các bean đều được đăng ký, @Primary chỉ chọn cái mặc định.

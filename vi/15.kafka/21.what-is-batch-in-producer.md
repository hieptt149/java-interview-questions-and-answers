# What is batch in Kafka producer (Batch trong Kafka producer là gì)

## Junior Level

### Định Nghĩa

**Batch** — một cơ chế nơi producer **tích lũy các message** và gửi chúng **như một gói** thay vì từng cái một.

```
Không có batching:
  msg1 → request
  msg2 → request
  msg3 → request
  3 request đến broker

Có batching:
  [msg1, msg2, msg3] → 1 request
  1 request đến broker
```

### Tại Sao Cần Đến Batching?

```
✅ Throughput cao hơn (ít request hơn)
✅ Độ trễ mỗi message thấp hơn
✅ Sử dụng network tốt hơn
```

### Các Cài Đặt Chính

```java
props.put("batch.size", 16384);       // 16KB — kích thước batch
props.put("linger.ms", 5);            // chờ 5ms để lấp đầy batch
props.put("buffer.memory", 33554432); // 32MB — buffer trong bộ nhớ
```

## Middle Level

### Batching Hoạt Động Như Thế Nào

```
1. Producer gọi send(record)
2. Message được thêm vào batch cho partition
3. Batch được gửi khi:
   - đạt batch.size
   - linger.ms đã trôi qua
   - flush() của Producer được gọi
```

### Kích Thước Batch

```java
// batch.size nhỏ
props.put("batch.size", 1024);  // 1KB
// → Gửi thường xuyên, throughput thấp hơn

// batch.size lớn
props.put("batch.size", 65536);  // 64KB
// → Gửi ít thường xuyên hơn, throughput cao hơn, nhiều memory hơn
```

### Linger.ms

```java
// linger.ms=0 — gửi ngay lập tức
props.put("linger.ms", "0");
// → Latency tối thiểu, throughput thấp hơn

// linger.ms=5 — chờ 5ms
props.put("linger.ms", "5");
// → Throughput cao hơn, latency nhỉnh hơn một chút
```

### Buffer Memory

```java
// Buffer để lưu trữ các batch đang chờ
props.put("buffer.memory", 33554432);  // 32MB

// Nếu buffer đầy:
// max.block.ms — chờ bao lâu trước khi báo lỗi
props.put("max.block.ms", 60000);
```

### Các Lỗi Thường Gặp

1. **batch.size quá nhỏ:**
```
batch.size=1KB ở throughput 10K msg/s → 10K request/giây thay vì ~100,
tải broker gấp 100 lần.
```

2. **linger.ms=0:**
```
Gửi ngay lập tức → batch không có thời gian để lấp đầy
→ Throughput thấp hơn
```

3. **buffer.memory quá nhỏ:**
```
buffer.memory=1MB → đầy nhanh
→ Producer chặn hoặc ném một lỗi
```

## Senior Level

### Cài Đặt Nội Bộ

**RecordAccumulator:**
```
Producer dùng RecordAccumulator để batching:
- Một batch mỗi partition
- Các batch được gửi khi đầy hoặc theo linger.ms
- Compression được áp dụng cho toàn bộ batch
```

**Hoàn Thành Batch:**
```
Một batch được coi là đầy khi:
1. Đạt batch.size (byte)
2. linger.ms (thời gian) đã trôi qua
3. flush() được gọi
4. Producer bị đóng
```

### Compression Và Batching

```
Compression được áp dụng cho toàn bộ batch:
props.put("compression.type", "lz4");

Ưu điểm:
- Batch lớn hơn → tỷ lệ compression tốt hơn
- Ít I/O network hơn
- Ít CPU trên broker hơn
```

### Tinh Chỉnh Hiệu Năng

```yaml
# Cấu hình throughput cao
batch.size: 65536          # 64KB
linger.ms: 10              # chờ 10ms
buffer.memory: 67108864    # 64MB
compression.type: lz4
max.in.flight.requests.per.connection: 5

# Cấu hình latency thấp
batch.size: 16384          # 16KB
linger.ms: 0               # không chờ
buffer.memory: 33554432    # 32MB
compression.type: none (trong các phiên bản hiện đại lz4 có overhead tối thiểu ~1-2% CPU,
nên thường được khuyến nghị ngay cả cho latency thấp).
max.in.flight.requests.per.connection: 1
```

### Quản Lý Memory

```
Tổng mức sử dụng memory:
  buffer.memory + (batch.size * số_partition * in_flight)

Ví dụ:
  32MB buffer + (64KB * 100 partition * 5 in-flight)
  = 32MB + 32MB = 64MB

Nếu buffer đầy:
  Producer chặn trong max.block.ms
  → Sau đó ném BufferExhaustedException
```

### Monitoring

**Các metrics chính:**
```
kafka.producer:batch-size-avg
kafka.producer:batch-size-max
kafka.producer:compression-rate-avg
kafka.producer:buffer-available-bytes
kafka.producer:buffer-exhausted-rate
kafka.producer:record-send-rate
```

**Các Alert:**
```yaml
- Tỷ lệ buffer exhausted > 0 → critical
- Kích thước batch trung bình < 1KB → điều tra
- Tỷ lệ compression < 1.5 → kiểm tra cấu hình compression
```

### Các Thực Hành Tốt Nhất

```
✅ batch.size=32KB-64KB cho throughput
✅ linger.ms=5-10ms cho batching
✅ compression=lz4 để tiết kiệm network
✅ Giám sát kích thước batch và mức sử dụng buffer
✅ buffer.memory đủ cho khối lượng công việc

❌ batch.size=0 hoặc quá nhỏ
❌ linger.ms=0 khi cần throughput
❌ buffer.memory quá nhỏ
❌ Không có giám sát các metrics batch
❌ Compression mà không có batching
```

### Các Quyết Định Kiến Trúc

1. **Tinh chỉnh kích thước batch** — cân bằng giữa throughput và latency
2. **Linger.ms** — thời gian để lấp đầy batch
3. **Compression trên batch** — tỷ lệ tốt hơn
4. **Quản lý buffer** — ngăn ngừa cạn kiệt

### Tóm Tắt Cho Senior

- Batching là một cơ chế then chốt cho throughput
- batch.size và linger.ms là các tham số tinh chỉnh chính
- Compression được áp dụng cho toàn bộ batch
- Quản lý buffer memory rất quan trọng cho sự ổn định
- Giám sát các metrics batch là bắt buộc cho production

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Batch — tích lũy các message và gửi như một gói thay vì từng cái một
- Batch được gửi khi: đạt `batch.size`, `linger.ms` trôi qua, hoặc `flush()` được gọi
- `batch.size=16KB` theo mặc định; cho throughput: 32KB-64KB
- `linger.ms=0` theo mặc định (gửi ngay lập tức); cho batching: 5-10ms
- Compression được áp dụng cho toàn bộ batch — batch lớn hơn = tỷ lệ compression tốt hơn
- Buffer memory (32MB theo mặc định) — khi đầy, producer chặn
- RecordAccumulator — cơ chế batching nội bộ, một batch mỗi partition

**Các câu hỏi phụ thường gặp:**
- *Điều gì xảy ra với batch.size=0?* — Gửi từng message một, tải broker gấp 100 lần.
- *Tại sao cần linger.ms nếu batch.size đã đầy?* — Với throughput thấp, batch không đầy; linger.ms cho thời gian tích lũy.
- *Điều gì xảy ra khi buffer cạn kiệt?* — Producer chặn trong max.block.ms → BufferExhaustedException.
- *Compression ảnh hưởng đến batching như thế nào?* — Được áp dụng cho toàn bộ batch, batch lớn hơn = tỷ lệ tốt hơn.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "linger.ms=0 là lựa chọn tối ưu cho throughput" — batch không có thời gian để lấp đầy
- "batch.size không quan trọng" — nó quyết định số lượng request đến broker
- "Compression trên mỗi message" — trên toàn bộ batch
- "Buffer memory không cần tinh chỉnh" — đầy nhanh ở throughput cao

## 🔗 Các kết nối chủ đề then chốt

### Chủ đề: Isolation Level và các hiện tượng bất thường

```
Q1 (ACID) → Q2 (Tổng quan level) → Q3 (Read Uncommitted) → Q4 (Read Committed)
     ↓                               ↓                        ↓
Q5 (Repeatable Read) → Q6 (Serializable)               Q7 (Dirty Read)
     ↓                               ↓                        ↓
Q8 (Non-repeatable Read) → Q9 (Phantom Read) → Q10 (Lost Update)
```

**Các kết nối then chốt:**
- Q2 ↔ Q7-Q10: Mỗi level bảo vệ chống lại các hiện tượng bất thường cụ thể
- Q4 ↔ Q8: Non-repeatable read xảy ra đặc biệt ở Read Committed
- Q5 ↔ Q9: Phantom read được ngăn chặn ở Repeatable Read (trong MySQL qua Gap Lock)

### Chủ đề: Spring Transaction

```
Q13 (Propagation) → Q14 (NESTED) → Q15 (REQUIRED vs REQUIRES_NEW)
     ↓                    ↓
Q16 (@Transactional) → Q17 (Các cấp độ) → Q22 (Self-invocation)
```

**Các kết nối then chốt:**
- Q13 ↔ Q15: Propagation định nghĩa hành vi khi đã tồn tại một transaction bên ngoài
- Q14 ↔ Q15: NESTED vs REQUIRES_NEW — savepoint vs commit độc lập
- Q16 ↔ Q19: @Transactional chỉ rollback cho RuntimeException + Error
- Q22 ↔ Q13: Bỏ qua self-invocation — proxy không tham gia, propagation không hoạt động

### Chủ đề: Rollback và các cấu hình đặc biệt

```
Q18 (Rollback) → Q19 (Rollback mặc định) → Q20 (Rollback tùy chỉnh)
     ↓
Q21 (ReadOnly)
```

**Các kết nối then chốt:**
- Q18 ↔ Q20: rollbackFor ghi đè hành vi mặc định
- Q19 ↔ Q20: Checked exception = commit theo mặc định → rollbackFor = Exception.class
- Q21 ↔ Q18: ReadOnly không gây ra rollback, nhưng tối ưu hóa việc đọc

## 🎓 Tóm tắt: Cần biết gì cho mỗi cấp độ

### 🟢 Junior
- ACID: Atomicity (tất cả hoặc không gì cả), Consistency (các ràng buộc được thỏa mãn), Isolation (không can thiệp lẫn nhau), Durability (được lưu trữ bền vững sau khi commit)
- 4 isolation level: Read Uncommitted, Read Committed, Repeatable Read, Serializable
- Dirty Read = thấy dữ liệu chưa commit, Non-repeatable = giá trị thay đổi giữa các lần SELECT, Phantom = các dòng xuất hiện/biến mất
- PostgreSQL mặc định = Read Committed, MySQL mặc định = Repeatable Read
- @Transactional: rollback cho RuntimeException, commit cho checked exception

### 🟡 Middle
- Read Committed: snapshot cho mỗi SELECT → có thể xảy ra non-repeatable read
- Repeatable Read: snapshot cho toàn bộ transaction → có thể xảy ra phantom read (trong PostgreSQL qua MVCC, trong MySQL qua Gap Lock — được ngăn chặn)
- Propagation: REQUIRED (tham gia transaction hiện có), REQUIRES_NEW (mới, tạm ngưng transaction bên ngoài), NESTED (savepoint)
- Self-invocation: `this.method()` bỏ qua proxy → @Transactional không hoạt động
- ReadOnly: vô hiệu hóa dirty checking, gợi ý cho optimizer, định tuyến đến replica (nếu được cấu hình)

### 🔴 Senior
- Serializable trong PG = SSI (Serializable Snapshot Isolation), không chặn việc đọc, nhưng abort khi có chu trình RW-conflict
- Lost Update: SQL nguyên tử (`SET x = x - 1`) giải quyết vấn đề mà không cần locking
- Overhead của REQUIRES_NEW: suspend ~2ms, connection mới ~0.5ms, Session suspend ~2ms, resume ~2ms
- NESTED: không hoạt động với JTA → fallback về REQUIRES_NEW. Cạm bẫy L1 cache sau khi rollback savepoint
- Rollback checked exception: TransactionInterceptor thấy exception TRƯỚC catch → setRollbackOnly() → UnexpectedRollbackException

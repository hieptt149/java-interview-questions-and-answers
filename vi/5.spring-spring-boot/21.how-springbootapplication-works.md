# How @SpringBootApplication Works (Cách @SpringBootApplication hoạt động)

## Junior Level

**@SpringBootApplication** là annotation chính của một ứng dụng Spring Boot.

```java
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

**Nó làm 3 việc:**
1. **@Configuration** -> class là một configuration
2. **@EnableAutoConfiguration** -> Spring Boot tự cấu hình các bean
3. **@ComponentScan** -> quét các package và tìm @Component, @Service

**Quy tắc:**
- Đặt trong package gốc
- Tất cả các sub-package sẽ được quét

---

## Middle Level

### Cấu tạo

```java
@SpringBootConfiguration    // = @Configuration cho test
@EnableAutoConfiguration   // Auto-configuration
@ComponentScan             // Quét package
public @interface SpringBootApplication { }
```

### Hành vi của ComponentScan

```java
// Application ở com.example.app
// -> Quét com.example.app và tất cả các sub-package

// Các service ở com.example.common -> sẽ KHÔNG được tìm thấy!
// Giải pháp:
@SpringBootApplication(scanBasePackages = "com.example")
```

### Quy trình khởi động

```
SpringApplication.run():
  1. Tạo ApplicationContext -> container cho tất cả các bean
  2. Nạp Environment -> application.properties, biến môi trường, tham số CLI
  3. Refresh Context -> lõi Spring: đăng ký các BPP, tạo TẤT CẢ các bean, phân giải các phụ thuộc
  4. Khởi động embedded server -> Tomcat/Jetty/Undertow trên port được chỉ định
  5. Chạy CommandLineRunner -> code của bạn sau khi context khởi động đầy đủ
```

### proxyBeanMethods

```java
// Theo mặc định: true (CGLIB proxy)
// Để tối ưu:
@SpringBootConfiguration(proxyBeanMethods = false)
// -> Khởi động nhanh hơn, ít bộ nhớ hơn: theo mặc định Spring tạo một CGLIB subclass
// cho mỗi class @Configuration (Full mode). Việc sinh bytecode tốn
// thời gian và bộ nhớ. Với proxyBeanMethods = false, các lời gọi phương thức @Bean đi thẳng.
// -> Nhưng các phương thức @Bean tạo đối tượng mới ở mỗi lời gọi
```

## Senior Level

### Refresh Context

```
Trái tim của quá trình khởi động:
  1. BeanFactoryPostProcessor -> sửa đổi BeanDefinition
  2. Đăng ký BeanPostProcessor
  3. Quét + auto-configuration
  4. Tạo bean
  5. Khởi động server
```

### FailureAnalyzers

```
Spring Boot bắt các lỗi lúc khởi động:
  -> "Port already in use"
  -> "DataSource not configured"

-> Thông báo đẹp thay vì stack trace
-> Có thể tạo các analyzer của riêng bạn
```

### Kinh nghiệm Production

**Tình huống thực tế: ComponentScan không tìm thấy bean**
```
Application -> com.example.app
Các service -> com.example.services
-> Không tìm thấy bean!

Giải pháp:
  @SpringBootApplication(scanBasePackages = "com.example")
```

### Best Practices

1. **Package gốc** -> com.example.app
2. **scanBasePackages** -> nếu các bean nằm ở các package khác
3. **proxyBeanMethods = false** — nếu các phương thức @Bean không gọi lẫn nhau (nếu không thì ngữ nghĩa singleton sẽ vỡ: mỗi lời gọi tạo một đối tượng mới).
4. **exclude** -> tắt các auto-configuration
5. **basePackageClasses** -> quét theo kiểu an toàn (type-safe)
6. **FailureAnalyzer** -> các thông báo lỗi của riêng bạn

### Tóm tắt cho Senior

- **@SpringBootApplication** = Configuration + AutoConfig + ComponentScan
- **Vị trí** -> xác định phạm vi quét
- **Refresh Context** -> pha tạo bean then chốt
- **proxyBeanMethods** -> tối ưu hóa khởi động
- **FailureAnalyzers** -> lỗi dễ đọc
- **scanBasePackages** -> cho các bean ngoài package gốc

## Interview Cheat Sheet

**Cần phải biết:**
- @SpringBootApplication = @Configuration + @EnableAutoConfiguration + @ComponentScan
- Đặt trong package gốc — quét tất cả các sub-package
- SpringApplication.run(): tạo context -> nạp Environment -> Refresh Context -> khởi động server -> CommandLineRunner
- proxyBeanMethods = false tăng tốc khởi động, nhưng phá vỡ singleton khi các phương thức @Bean gọi lẫn nhau
- scanBasePackages / basePackageClasses — nếu các bean nằm ngoài package gốc
- Refresh Context — pha then chốt: đăng ký BPP, auto-configuration, tạo bean
- FailureAnalyzers cho các lỗi dễ đọc thay vì stack trace

**Các câu hỏi phụ thường gặp:**
- *Điều gì xảy ra nếu Application không được đặt trong package gốc?* — Các component ở các nhánh package khác sẽ không được ComponentScan tìm thấy.
- *proxyBeanMethods dùng để làm gì?* — CGLIB proxy đảm bảo ngữ nghĩa singleton khi các phương thức @Bean gọi nhau; tắt nó tăng tốc khởi động.
- *Có thể tắt auto-configuration không?* — Có, qua @SpringBootApplication(exclude = ...).
- *Refresh Context làm gì?* — Đăng ký các BeanPostProcessor, tạo tất cả các bean, khởi động server.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "@SpringBootApplication chỉ chạy ứng dụng" — không, nó là 3 annotation trong một.
- "Có thể đặt @SpringBootApplication lên bất kỳ class nào" — chỉ lên một class configuration có main().
- "proxyBeanMethods = false luôn tốt hơn" — không, phá vỡ singleton khi các @Bean gọi nhau.
- "ComponentScan nạp tất cả các class vào JVM" — không, ASM chỉ đọc bytecode.

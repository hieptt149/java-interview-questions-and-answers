# What Is Record in Java and Since Which Version Are They Available? (Record trong Java là gì và có sẵn từ phiên bản nào)

## 🟢 Junior Level

**Record** là một loại class đặc biệt trong Java được thiết kế để lưu trữ dữ liệu bất biến (immutable). Nó xuất hiện như một **preview feature (tính năng thử nghiệm) trong Java 14** (JEP 359) và trở thành **tính năng chuẩn đầy đủ trong Java 16** (JEP 395).

Record cho phép bạn khai báo một class trong một dòng, tự động nhận được:
- các trường `private final`
- một constructor public
- getter (không có tiền tố `get`)
- `equals()`, `hashCode()` và `toString()`

**Ví dụ:**
```java
// Thay vì 50+ dòng code — một dòng
public record User(String name, int age, String email) {}

// Sử dụng
User user = new User("John", 25, "john@example.com");
System.out.println(user.name());  // John
System.out.println(user.age());   // 25
```

**Khi nào nên dùng:**
- DTO (Data Transfer Objects)
- Class để lưu kết quả truy vấn từ DB
- Key trong collection (HashMap, HashSet)
- Trả về nhiều giá trị từ một phương thức
- Bất kỳ tình huống nào cần một class bất biến đơn giản

## 🟡 Middle Level

### Cách Hoạt Động

Record không chỉ là "cú pháp đường" (syntactic sugar) — đó là một loại class đặc biệt với các ràng buộc nghiêm ngặt:

```java
// Những gì bạn viết:
public record Point(int x, int y) {}

// Những gì trình biên dịch tạo ra:
public final class Point extends java.lang.Record {
    private final int x;
    private final int y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    public int x() { return x; }
    public int y() { return y; }

    @Override
    public boolean equals(Object o) { /* tự động sinh */ }

    @Override
    public int hashCode() { /* tự động sinh */ }

    @Override
    public String toString() { /* tự động sinh */ }
}
```

### Ứng Dụng Thực Tế

**1. DTO trong Spring Boot:**
```java
public record CreateUserRequest(
    @NotBlank String name,
    @Email String email,
    @Min(18) int age
) {}

@RestController
public class UserController {
    @PostMapping("/users")
    public ResponseEntity<UserResponse> createUser(
        @Valid @RequestBody CreateUserRequest request
    ) {
        // request.name(), request.email() — truy cập trường
    }
}
```

**2. Trả về nhiều giá trị:**
```java
public record CalculationResult(int result, int operationTimeMs) {}

public CalculationResult calculate() {
    // ... logic phức tạp
    return new CalculationResult(42, 150);
}
```

**3. Pattern matching trong switch (Java 21+):**
```java
public sealed interface Shape permits Circle, Rectangle {}
public record Circle(double radius) implements Shape {}
public record Rectangle(double width, double height) implements Shape {}

public double getArea(Shape shape) {
    return switch (shape) {
        case Circle c -> Math.PI * c.radius() * c.radius();
        case Rectangle r -> r.width() * r.height();
    };
}
```

### Các Lỗi Thường Gặp

1. **Lỗi: cố gắng làm Record mutable**
   ```java
   // ❌ KHÔNG THỂ — các trường luôn final
   public record BadRecord() {
       public int mutableField = 0;  // lỗi biên dịch, trừ khi là static
   }
   ```

2. **Lỗi: các thành phần mutable trong Record**
   ```java
   // ⚠️ Cẩn thận — mảng là mutable!
   public record DataWithArray(int[] values) {}

   DataWithArray d1 = new DataWithArray(new int[]{1, 2, 3});
   d1.values()[0] = 99;  // có thể bị thay đổi!

   // ✅ Tốt hơn — dùng List.of() hoặc tạo bản sao
   public record SafeData(List<Integer> values) {}
   ```

3. **Lỗi: null trong Record**
   ```java
   // Record cho phép null theo mặc định
   public record User(String name) {}
   User user = new User(null);  // OK, nhưng có thể dẫn đến NPE

   // ✅ Giải pháp — kiểm tra null trong constructor (Java 16+)
   public record User(String name) {
       public User {
           Objects.requireNonNull(name, "Name cannot be null");
       }
   }
   ```

### So Sánh Với Các Lựa Chọn Thay Thế

| Cách tiếp cận           | Ưu điểm                                  | Nhược điểm                                      |
| ------------------ | -------------------------------------- | ------------------------------------------- |
| **Record**         | Code tối thiểu, bất biến, tự động sinh | Không thể kế thừa, chỉ trường final       |
| **Lombok @Data**   | Linh hoạt hơn, mutable/immutable     | Phụ thuộc Lombok, vấn đề với IDE       |
| **Class thủ công**   | Kiểm soát toàn diện                        | Nhiều boilerplate, lỗi trong equals/hashCode |
| **Class với @Value** | Bất biến, rõ ràng                    | Nhiều code hơn Record                     |

## 🔴 Senior Level

### Triển Khai Nội Bộ

Record không chỉ là cú pháp đường — đó là một **mô hình dữ liệu mới** trong JVM.

**Các JEP chính:**
- JEP 359: Records (Preview, Java 14)
- JEP 384: Records (Second Preview, Java 15)
- JEP 395: Records (Final, Java 16)

**Cấu trúc nội bộ:**

```java
// Trình biên dịch thêm các thuộc tính ẩn:
// - cờ ACC_RECORD trong class file
// - thuộc tính RecordComponents trong constant pool

// Tại runtime bạn có thể lấy các thành phần thông qua reflection:
RecordComponent[] components = Point.class.getRecordComponents();
for (RecordComponent rc : components) {
    System.out.println(rc.getName());     // "x", "y"
    System.out.println(rc.getType());     // int, int
    System.out.println(rc.getAccessor()); // Tham chiếu Method
}
```

**Cấu trúc class file:**
```
ClassFile {
    u2 access_flags;        // ACC_RECORD | ACC_FINAL
    u2 this_class;
    u2 super_class;         // java/lang/Record
    ...
    Record_attribute {
        u2 attribute_name_index;
        u4 attribute_length;
        u2 components_count;
        record_component_info components[];
    }
}
```

### Đánh Đổi Kiến Trúc

**Record so với class thông thường:**

| Khía cạnh            | Record                  | Class thông thường   |
| ----------------- | ----------------------- | --------------- |
| **Kế thừa**   | Không cho phép (implicit final) | Cho phép           |
| **Trường**        | Chỉ final            | Bất kỳ           |
| **Interface**    | Có thể triển khai  | Có thể           |
| **sealed**        | Có thể                   | Có thể           |
| **Annotation**   | Trên trường, constructor    | Trên bất cứ thứ gì   |
| **Serialization** | Logic riêng (JEP 445)   | Chuẩn     |

**Tại sao Record không thể mở rộng:**
```
java.lang.Record — superclass đặc biệt không khả dụng để extends trực tiếp.
Điều này được làm để:
1. Đảm bảo tính bất biến
2. equals/hashCode dự đoán được
3. Tối ưu hóa JVM (tương thích với value type)
4. Hỗ trợ pattern matching
```

### Edge Cases

**1. Record Generic:**
```java
public record ApiResponse<T>(int status, T data, String message) {}

// Sử dụng
ApiResponse<List<User>> response = new ApiResponse<>(200, users, "OK");
ApiResponse<Optional<User>> maybeUser = new ApiResponse<>(404, Optional.empty(), "Not found");
```

**2. Record đệ quy (cho cấu trúc liên kết):**
```java
public record ListNode<T>(T value, ListNode<T> next) {}

ListNode<String> list = new ListNode<>("A",
    new ListNode<>("B",
        new ListNode<>("C", null)));
```

**3. Record với annotation:**
```java
public record User(
    @JsonProperty("user_name") @NonNull String name,
    @Min(0) @Max(150) int age
) {
    // Annotation trên thành phần áp dụng cho:
    // - trường
    // - tham số constructor
    // - phương thức accessor
}

// Để kiểm soát chính xác — annotation trên các target element:
public record Config(
    String key
) {}
// Trong Java, annotation trên các thành phần Record áp dụng cho trường, tham số, và accessor.
// Để áp dụng có mục tiêu, dùng meta-annotation @Target({FIELD, METHOD, PARAMETER}).
```

**4. Record và Serialization (Java 21+):**
```java
// Serialization của Record: trong quá trình deserialize, canonical constructor được gọi,
// không phải readObject. Đây là serialization Java chuẩn (không phải JEP 445).

record SerializableData(String name, int value) implements Serializable {}

// JVM tự động xác thực:
// 1. Tất cả các trường final đã được khởi tạo
// 2. Các bất biến (invariant) được bảo toàn
// 3. Compact constructor có thể được dùng để validation
```

### Hiệu Năng

**Bộ nhớ:**
```
Record so với Class có cùng chức năng:
- Object header: 12-16 byte (phụ thuộc JVM)
- Trường: như thường lệ (int = 4, long = 8, tham chiếu = 4-8)
- Lombok sinh code tại compile time — không có overhead runtime trong cả hai trường hợp.
- Không có trường bổ sung cho cache equals/hashCode
```

**Thời gian thực thi:**
```
equals() / hashCode() tự động sinh:
- Trình biên dịch tạo triển khai tối ưu
- Dùng Objects.hash() hoặc Arrays.hashCode()
- Hiệu năng tương đương với triển khai thủ công
- JIT có thể inline tốt hơn (trường final)
```

**Benchmark (JMH, Java 21):**
```
// Giá trị xấp xỉ (JMH, Java 21). Phụ thuộc vào JVM và phần cứng.
Thao tác          | Record | Lombok @Value | Class thủ công
-------------------|--------|---------------|--------------
equals()           | 15 ns  | 15 ns         | 14 ns
hashCode()         | 12 ns  | 13 ns         | 12 ns
toString()         | 45 ns  | 48 ns         | 46 ns
Tạo object    | 8 ns   | 8 ns          | 8 ns

Khác biệt < 5% — Record không thua kém về hiệu năng
```

### Kinh Nghiệm Production

**Trường hợp thực tế — di chuyển DTO sang Record:**

```java
// Trước (Spring Boot 2.x, Lombok):
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class UserDto {
    private String name;
    private String email;
    private int age;
}

// Sau (Spring Boot 3.x, Java 17+):
public record UserDto(String name, String email, int age) {}

// Kết quả:
// - Code giảm từ ~15 dòng xuống 1
// - Loại bỏ phụ thuộc Lombok cho các class này
// - DTO trở nên bất biến (bảo vệ khỏi thay đổi ngoài ý muốn)
// - Jackson tự động serialize (thông qua constructor)
```

public record Order(@JsonProperty("order_id") String id) {}

**Reflection để kiểm tra:**
```java
public static void inspectRecord(Object record) {
    Class<?> clazz = record.getClass();
    if (!clazz.isRecord()) {
        throw new IllegalArgumentException("Not a record");
    }

    RecordComponent[] components = clazz.getRecordComponents();
    System.out.println("Record: " + clazz.getSimpleName());
    for (RecordComponent rc : components) {
        Method accessor = rc.getAccessor();
        Object value = accessor.invoke(record);
        System.out.println("  " + rc.getName() + " = " + value);
    }
}
```

### Xu Hướng Tương Lai

**Java 21+:**
```java
// Record Patterns (JEP 440) — Pattern matching cho Record
Point p = new Point(42, 0);
if (p instanceof Point(int x, int y)) {
    System.out.println(x + y);  // 42
}

// Switch với Record Patterns
double calcArea(Shape s) {
    return switch (s) {
        case Circle(double r) -> Math.PI * r * r;
        case Rectangle(double w, double h) -> w * h;
        case Triangle(double b, double h) -> 0.5 * b * h;
    };
}

// Sealed + Record + Pattern Matching = tổ hợp mạnh mẽ
public sealed interface Expr
    permits Num, Add, Mul {}

public record Num(int value) implements Expr {}
public record Add(Expr left, Expr right) implements Expr {}
public record Mul(Expr left, Expr right) implements Expr {}

int eval(Expr e) {
    return switch (e) {
        case Num(int n) -> n;
        case Add(Expr l, Expr r) -> eval(l) + eval(r);
        case Mul(Expr l, Expr r) -> eval(l) * eval(r);
    };
}
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Record xuất hiện như preview trong Java 14 (JEP 359), trở nên ổn định trong Java 16 (JEP 395)
- Record là một loại class đặc biệt kế thừa `java.lang.Record`
- Tự động sinh: canonical constructor, accessor, `equals()`, `hashCode()`, `toString()`
- Accessor được đặt tên theo trường: `user.name()`, KHÔNG PHẢI `user.getName()`
- Record lý tưởng cho DTO, key HashMap, value object
- Record không hỗ trợ kế thừa — implicit final
- Từ Java 21, pattern matching cho Record có sẵn (JEP 440)

**Các câu hỏi phụ thường gặp:**
- **Từ phiên bản nào Record ổn định?** — Java 16 (JEP 395), preview — Java 14
- **Có thể làm Record mutable không?** — Không, tất cả các trường tự động là final
- **Record hoạt động với Jackson như thế nào?** — Jackson 2.12+ hỗ trợ tự nhiên qua canonical constructor
- **Record khác gì với Lombok @Value?** — Record là chuẩn ngôn ngữ, ít code hơn, không phụ thuộc Lombok

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Record chỉ là cú pháp đường cho Lombok" — Record là một mô hình dữ liệu đầy đủ trong JVM
- ❌ "Bạn có thể kế thừa Record" — Record là implicit final, kế thừa bị cấm
- ❌ "Record có phương thức get/set" — accessor không có tiền tố get: `name()` thay vì `getName()`
- ❌ "Record chậm hơn class thông thường" — hiệu năng giống hệt (khác biệt < 5%)

# What is Orphan Removal (Orphan removal là gì)

## Overview

Orphan removal là một cơ chế tự động xóa các entity liên quan khi chúng bị loại khỏi collection hoặc mối quan hệ bị phá vỡ. Đây là một công cụ mạnh mẽ để duy trì tính toàn vẹn dữ liệu trong các composition.

---

## Junior Level

### Orphan Removal Là Gì

Orphan removal - tự động **xóa các entity liên quan khỏi DB** khi chúng bị **loại khỏi collection**.

```java
@Entity
public class Order {
    @OneToMany(mappedBy = "order", orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();
}

Order order = entityManager.find(Order.class, 1L);
order.getItems().remove(0);  // item bị loại bỏ tự động bị xóa khỏi DB!
```

### Cascade vs orphanRemoval

```java
// Cascade - truyền các thao tác
@OneToMany(cascade = CascadeType.REMOVE)
// entityManager.remove(order) -> remove cho tất cả items

// orphanRemoval - xóa các entity orphan
@OneToMany(orphanRemoval = true)
// order.getItems().remove(item) -> DELETE cho item khỏi DB

// Cùng nhau - kiểm soát toàn diện
@OneToMany(cascade = CascadeType.ALL, orphanRemoval = true)
// persist, merge, remove + tự động xóa orphan
```

### Ví Dụ

```java
@Entity
public class Order {
    @OneToMany(mappedBy = "order", orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();

    public void removeItem(OrderItem item) {
        items.remove(item);
        item.setOrder(null);  // thực hành tốt
    }
}

// Cách dùng
Order order = entityManager.find(Order.class, 1L);
order.removeItem(order.getItems().get(0));
// item bị xóa khỏi DB tự động!
```

## Middle Level

### Cascade + orphanRemoval Cùng Nhau

```java
@OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
private List<OrderItem> items;

order.getItems().add(newItem);   // persist thông qua cascade
order.getItems().remove(oldItem);  // xóa thông qua orphanRemoval
order.getItems().clear();         // xóa TẤT CẢ thông qua orphanRemoval
```

### Khi Nào orphanRemoval Hoạt Động

```
Hoạt động cho @OneToMany
Hoạt động cho @OneToOne
KHÔNG hoạt động cho @ManyToOne - vô nghĩa (orphanRemoval chỉ hợp lý cho collection và one-to-one nơi parent "sở hữu" child)
KHÔNG hoạt động cho @ManyToMany - vô nghĩa (không có chủ sở hữu duy nhất trong Many-to-Many)
```

### Các Lỗi Thường Gặp

```java
// orphanRemoval cho entity dùng chung
@ManyToOne(orphanRemoval = true)  // không được hỗ trợ cho @ManyToOne
private User user;

// orphanRemoval cho @ManyToMany
@ManyToMany(orphanRemoval = true)  // không được hỗ trợ cho @ManyToMany
private List<Tag> tags;

// Không hiểu sự khác biệt
@OneToMany(cascade = CascadeType.REMOVE)  // Chỉ khi parent bị xóa
private List<OrderItem> items;

@OneToMany(orphanRemoval = true)  // Khi loại khỏi collection
private List<OrderItem> items;
```

### Ví Dụ Với @OneToOne

```java
@Entity
public class User {
    @OneToOne(mappedBy = "user", orphanRemoval = true, cascade = CascadeType.ALL)
    private UserProfile profile;
}

User user = entityManager.find(User.class, 1L);
user.setProfile(null);  // profile bị xóa khỏi DB
```

## Senior Level

### Triển Khai Nội Bộ

```
Cơ chế orphanRemoval:
1. Khi flush: Hibernate kiểm tra tất cả các collection có orphanRemoval
2. So sánh trạng thái hiện tại với snapshot
3. Các entity từng có trong snapshot nhưng không có trong trạng thái hiện tại -> orphan
4. Với mỗi orphan -> lên lịch DELETE
5. Khi flush -> DELETE khỏi DB

Quan trọng: orphanRemoval kích hoạt khi flush, không phải ngay lập tức!
Flush xảy ra khi: (1) commit transaction, (2) gọi entityManager.flush() rõ ràng, (3) trước khi thực thi truy vấn SQL.
```

### Nguy Hiểm

```java
// clear() trên collection - xóa TẤT CẢ phần tử. Trong các trường hợp hợp pháp (thay thế toàn bộ nội dung) đây chính xác là điều cần thiết. Nguy hiểm khi clear() được gọi vô tình do một bug.
order.getItems().clear();  // tất cả item bị xóa khỏi DB!

// Đúng - xóa có chủ đích
order.getItems().remove(item);  // chỉ một item
```

### Kết Hợp Với @OnDelete

```java
@Entity
public class Order {
    @OneToMany(mappedBy = "order", orphanRemoval = true)
    @org.hibernate.annotations.OnDelete(
        action = org.hibernate.annotations.OnDeleteAction.CASCADE
    )
    private List<OrderItem> items;
}

// Bảo vệ kép:
// 1. orphanRemoval - ở cấp độ JPA
// 2. ON DELETE CASCADE - ở cấp độ DB
```

### Các Pattern Production

```java
// Pattern 1: Phương thức helper
@Entity
public class Order {
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();

    public void addItem(OrderItem item) {
        items.add(item);
        item.setOrder(this);
    }

    public void removeItem(OrderItem item) {
        items.remove(item);
        item.setOrder(null);  // quan trọng cho tính nhất quán
    }
}

// Pattern 2: Thay thế collection
Order order = entityManager.find(Order.class, 1L);
order.setItems(newItems);  // các item cũ trở thành orphan, bị xóa!

// Tốt hơn - sửa đổi collection
order.getItems().clear();
order.getItems().addAll(newItems);
```

### Best Practices

```
orphanRemoval cho các child composite
Cùng với cascade = ALL
Phương thức helper để sửa đổi collection
Chỉ cho quyền sở hữu riêng tư

Cho entity dùng chung
Không có cascade
Cho @ManyToOne hoặc @ManyToMany
Thay thế toàn bộ collection mà không hiểu hậu quả
```

## Interview Cheat Sheet

**Cần phải biết:**
- orphanRemoval - tự động xóa khỏi DB các entity bị loại khỏi collection
- Cascade.REMOVE - chỉ khi parent bị xóa, orphanRemoval - khi loại khỏi collection
- Chỉ hoạt động cho @OneToMany và @OneToOne, KHÔNG cho @ManyToOne/@ManyToMany
- Kích hoạt khi flush, không phải ngay lập tức - quan trọng để hiểu về timing
- Luôn dùng cùng với cascade = ALL để kiểm soát toàn diện
- Phương thức helper bắt buộc: removeItem() loại khỏi collection + đặt null

**Các câu hỏi phụ thường gặp:**
- **Cascade.REMOVE vs orphanRemoval?** REMOVE - khi entityManager.remove(parent), orphanRemoval - khi parent.getChildren().remove(child)
- **Tại sao orphanRemoval không kích hoạt ngay lập tức?** Giống dirty checking, thực thi khi flush - quan trọng để hiểu cho transaction
- **Điều gì xảy ra khi clear() collection?** TẤT CẢ phần tử bị xóa khỏi DB - trong các trường hợp hợp pháp điều này cần thiết, khi có bug - thảm họa
- **Có thể kết hợp với @OnDelete không?** Có - bảo vệ kép: orphanRemoval (JPA) + ON DELETE CASCADE (DB)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "orphanRemoval cho @ManyToOne" - không được hỗ trợ
- "orphanRemoval cho @ManyToMany" - không có chủ sở hữu duy nhất
- "orphanRemoval mà không có cascade" - orphanRemoval chỉ cho việc xóa, các thao tác khác không được truyền
- "Tôi thay thế toàn bộ collection mà không hiểu" - các item cũ trở thành orphan và bị xóa

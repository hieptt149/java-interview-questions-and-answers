# How does Collections.unmodifiableList() work internally? (Collections.unmodifiableList() hoạt động bên trong như thế nào?)

## 🟢 Junior Level

`Collections.unmodifiableList()` trả về một **lớp bọc (wrapper)** bên trên list gốc, cấm tất cả các thao tác sửa đổi.

```java
List<String> mutable = new ArrayList<>();
mutable.add("A");
mutable.add("B");

List<String> unmodifiable = Collections.unmodifiableList(mutable);

unmodifiable.add("C"); // ❌ UnsupportedOperationException!
unmodifiable.get(0);   // ✅ OK — đọc thì hoạt động
```

**Điểm then chốt:** `unmodifiableList` không phải là một bản sao, mà là một **lớp bọc**. Nếu bạn sửa đổi list gốc, các thay đổi sẽ nhìn thấy được qua lớp bọc:

```java
mutable.add("C");
System.out.println(unmodifiable); // [A, B, C] — thay đổi nhìn thấy được!
```

## 🟡 Middle Level

### Cài đặt bên trong

`Collections.unmodifiableList()` trả về một đối tượng của class nội bộ `Collections.UnmodifiableList`:

```java
public static <T> List<T> unmodifiableList(List<? extends T> list) {
    return (list instanceof RandomAccess)
        ? new UnmodifiableRandomAccessList<>(list)
        : new UnmodifiableList<>(list);
}
```

**Hai biến thể lớp bọc:**
- `UnmodifiableRandomAccessList` — nếu list hỗ trợ truy cập ngẫu nhiên (`ArrayList`)
- `UnmodifiableList` — nếu không (`LinkedList`)

Đây là một tối ưu hóa về hiệu năng: các list `RandomAccess` dùng truy cập theo index O(1), không phải iterator.

### Cấu trúc của UnmodifiableList

```java
static class UnmodifiableList<E> extends UnmodifiableCollection<E>
                                  implements List<E> {
    private final List<? extends E> list;

    UnmodifiableList(List<? extends E> list) {
        super(list);
        this.list = list;  // tham chiếu đến bản gốc, không phải bản sao!
    }

    // Tất cả các phương thức sửa đổi ném UnsupportedOperationException
    public E set(int index, E element) {
        throw new UnsupportedOperationException();
    }
    public void add(int index, E element) {
        throw new UnsupportedOperationException();
    }
    public E remove(int index) {
        throw new UnsupportedOperationException();
    }

    // Các phương thức đọc ủy thác cho bản gốc
    public E get(int index) {
        return list.get(index);  // gọi trực tiếp đến bản gốc
    }
    public int size() {
        return list.size();
    }
}
```

### UnmodifiableList so với List.copyOf (Java 10+)

| Đặc điểm            | `unmodifiableList()`    | `List.copyOf()`                |
| ------------------- | ----------------------- | ------------------------------ |
| Sao chép            | Không (lớp bọc)         | Có (defensive copy)            |
| Thay đổi bản gốc    | Nhìn thấy qua lớp bọc   | Không ảnh hưởng                |
| Phần tử null        | Được cho phép           | Không được cho phép            |
| Kiểu trả về         | `UnmodifiableList`      | `ImmutableCollections.ListN`   |
| Phiên bản Java      | Từ Java 1.2             | Từ Java 10                     |

RandomAccess — một marker interface có nghĩa là truy cập theo index O(1). Defensive copy — sao chép dữ liệu để bảo vệ chống lại các sửa đổi từ bên ngoài.

```java
List<String> original = new ArrayList<>(List.of("A", "B"));

// unmodifiableList — lớp bọc
List<String> wrapper = Collections.unmodifiableList(original);
original.add("C");
System.out.println(wrapper);  // [A, B, C] — thay đổi nhìn thấy được!

// List.copyOf — bản sao
List<String> copy = List.copyOf(original);
original.add("D");
System.out.println(copy);     // [A, B, C] — thay đổi KHÔNG nhìn thấy được
```

### Lớp bọc ListIterator

```java
ListIterator<String> it = unmodifiable.listIterator();
it.next();           // OK
it.set("X");         // ❌ UnsupportedOperationException
it.add("Y");         // ❌ UnsupportedOperationException
it.remove();         // ❌ UnsupportedOperationException
```

Một `UnmodifiableListIterator` được trả về, nó cũng chặn tất cả các sửa đổi.

### Hiệu năng

| Thao tác     | `ArrayList` trực tiếp | `unmodifiableList`                    |
| ------------ | --------------------- | ------------------------------------- |
| `get(i)`     | O(1)                  | O(1) (một lời gọi ủy thác)            |
| `size()`     | O(1)                  | O(1) (ủy thác)                        |
| `contains()` | O(n)                  | O(n) (ủy thác)                        |
| `iterator()` | O(1)                  | O(1) (iterator được bọc)             |

Overhead là tối thiểu: một cấp ủy thác (~1-2 ns cho mỗi lời gọi).

## 🔴 Senior Level

### Phân tích sâu mã nguồn JDK

```java
// Collections.java (OpenJDK)

static class UnmodifiableCollection<E> implements Collection<E>, Serializable {
    final Collection<? extends E> c;

    UnmodifiableCollection(Collection<? extends E> c) {
        if (c == null) throw new NullPointerException();
        this.c = c;
    }

    // Tất cả các phương thức làm biến đổi (mutating) đều ném exception:
    public boolean add(E e)     { throw new UnsupportedOperationException(); }
    public boolean remove(Object o) { throw new UnsupportedOperationException(); }
    public void clear()         { throw new UnsupportedOperationException(); }

    // Các phương thức đọc ủy thác:
    public int size()           { return c.size(); }
    public boolean isEmpty()    { return c.isEmpty(); }
    public boolean contains(Object o) { return c.contains(o); }
    public Iterator<E> iterator() {
        return new Iterator<E>() {
            private final Iterator<? extends E> i = c.iterator();
            public boolean hasNext() { return i.hasNext(); }
            public E next()          { return i.next(); }
            public void remove()     { throw new UnsupportedOperationException(); }
        };
    }
}
```

### Tối ưu hóa UnmodifiableRandomAccessList

```java
static class UnmodifiableRandomAccessList<E>
    extends UnmodifiableList<E>
    implements RandomAccess {

    UnmodifiableRandomAccessList(List<? extends E> list) {
        super(list);
    }

    // Override subList — cũng trả về unmodifiable
    public List<E> subList(int from, int to) {
        return new UnmodifiableRandomAccessList<>(
            list.subList(from, to)
        );
    }
}
```

Tối ưu hóa này quan trọng: `UnmodifiableList` (non-RandomAccess) chuyển đổi các thao tác theo index thành các thao tác dựa trên iterator, mà đối với `ArrayList` sẽ là O(n) thay vì O(1).

### Có thể bị bỏ qua thông qua reflection!

```java
List<String> list = new ArrayList<>(List.of("A", "B"));
List<String> unmod = Collections.unmodifiableList(list);

// Thông qua reflection — truy cập trường `list` trong UnmodifiableList
Field field = unmod.getClass().getDeclaredField("list");
field.setAccessible(true);
List<String> underlying = (List<String>) field.get(unmod);
underlying.add("C");  // Sửa đổi bỏ qua sự bảo vệ!

System.out.println(unmod); // [A, B, C]
```

Đây không phải là một bug, mà là một đặc điểm của cách tiếp cận dùng lớp bọc. `List.copyOf()` (Java 10+) giải quyết vấn đề này bằng cách tạo một collection thực sự bất biến.

Nếu dự án của bạn ở trên Java 8 — `List.copyOf()` không khả dụng. Hãy dùng `Collections.unmodifiableList(new ArrayList<>(original))` như một defensive copy.

### Serialization

`UnmodifiableList` implements `Serializable`. Khi deserialize:

```java
// Nếu bản gốc thay đổi sau khi lớp bọc được serialize — nó sẽ KHÔNG ảnh hưởng đến lớp bọc
```

### Khi nào dùng

| Kịch bản                                              | Khuyến nghị                                                        |
| ----------------------------------------------------- | ----------------------------------------------------------------- |
| API đọc, bản gốc do bạn kiểm soát                     | `unmodifiableList()`                                               |
| Bất biến hoàn toàn, Java 10+                          | `List.copyOf()`                                                    |
| List bất biến thread-safe                             | `List.copyOf()` hoặc `unmodifiableList()` + đồng bộ hóa bản gốc    |
| Bất biến sâu (các đối tượng lồng nhau)                | Không phương pháp nào trong số này — hãy dùng DTO bất biến        |

### Best Practices

```java
// ✅ Trả về unmodifiable từ public API
public List<String> getNames() {
    return Collections.unmodifiableList(names);
}

// ✅ Java 10+ — List.copyOf cho bất biến hoàn toàn
public List<String> getNames() {
    return List.copyOf(names);
}

// ❌ Đừng dùng unmodifiableList để bảo vệ chống lại các sửa đổi đồng thời
// Cho việc đó — hãy dùng CopyOnWriteArrayList hoặc Collections.synchronizedList()
```

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `unmodifiableList()` trả về `UnmodifiableRandomAccessList` hoặc `UnmodifiableList` tùy thuộc vào `RandomAccess`
- Tất cả các phương thức sửa đổi ném `UnsupportedOperationException`
- Các phương thức đọc ủy thác trực tiếp cho bản gốc — overhead là 1-2 ns
- `subList()` cũng trả về một lớp bọc unmodifiable
- Thông qua reflection bạn có thể tiếp cận bản gốc và bỏ qua sự bảo vệ
- `List.copyOf()` (Java 10+) — bất biến thực sự, defensive copy, không có kết nối với bản gốc
- Iterator/ListIterator cũng được bọc trong các phiên bản unmodifiable (remove/set/add bị cấm)

**Các câu hỏi phụ thường gặp:**
- *Tại sao có hai class — UnmodifiableList và UnmodifiableRandomAccessList?* — Tối ưu hóa: các list RandomAccess được truy cập theo index O(1), các list khác — thông qua iterator.
- *Sự bảo vệ của unmodifiableList có thể bị bỏ qua không?* — Có, thông qua reflection (`getDeclaredField("list")`). `List.copyOf()` giải quyết vấn đề này.
- *Overhead của việc gọi các phương thức lớp bọc là gì?* — Một cấp ủy thác, ~1-2 ns — gần như bằng không.
- *`subList()` của một unmodifiable list trả về cái gì?* — Một lớp bọc unmodifiable khác trên sublist.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "unmodifiableList tạo một bản sao của collection" — không, đó là pattern lớp bọc, lưu một tham chiếu đến bản gốc
- "Sự bảo vệ chống lại các sửa đổi được đảm bảo 100%" — reflection cho phép bỏ qua nó
- "unmodifiableList là thread-safe" — không, đồng bộ hóa cần được xử lý riêng
- "Iterator từ unmodifiableList cho phép xóa các phần tử" — không, `UnmodifiableListIterator` cũng chặn các sửa đổi

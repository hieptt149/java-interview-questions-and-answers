# What is a @Configuration Class? (@Configuration class là gì?)

## Junior Level

**@Configuration** là một class tạo ra các bean qua các phương thức @Bean.

```java
@Configuration
public class AppConfig {

    @Bean
    public UserService userService() {
        return new UserService();
    }

    @Bean
    public OrderController orderController() {
        return new OrderController(userService());  // Injection
    }
    // Ở chế độ Full (mặc định) Spring chặn lời gọi userService()
    // và trả về singleton. Ở chế độ Lite (proxyBeanMethods = false) một
    // đối tượng mới được tạo - xem phần Middle Level.
}
```

**Tại sao:**
- Cho các thư viện bên thứ ba (không thể đặt @Service lên chúng)
- Cho cấu hình bean phức tạp

## Middle Level

### Chế độ Full so với Lite

**Full Mode (mặc định):**
```java
@Configuration  // proxyBeanMethods = true
public class Config {
    @Bean public A a() { return new A(); }
    @Bean public B b() { return new B(a()); }  // Cùng một instance của A!
}

// CGLIB proxy chặn lời gọi a()
// -> Kiểm tra cache -> trả về bean đã có
```

**Lite Mode:**
```java
@Configuration(proxyBeanMethods = false)
// hoặc @Component, @Service với các phương thức @Bean

@Bean public A a() { return new A(); }
@Bean public B b() { return new B(a()); }  // Instance MỚI của A!

// Không có proxy -> gọi phương thức trực tiếp
```

### Khi nào proxyBeanMethods = false

```java
// Dùng false nếu:
// 1. Các phương thức @Bean không gọi lẫn nhau
// 2. Các phụ thuộc qua tham số của phương thức
@Bean
public Service service(Repo repo) {  // Spring tự tìm repo
    return new Service(repo);
}

// -> Khởi động nhanh hơn
// -> Ít bộ nhớ hơn
// -> Thân thiện với GraalVM Native
```

## Senior Level

### CGLIB Proxy

```
@Configuration -> CGLIB subclass:
  -> Chặn các lời gọi phương thức @Bean
  -> Kiểm tra cache singletonObjects
  -> Trả về cái đã có hoặc tạo mới

-> Không được là class/phương thức final! CGLIB tạo một subclass qua kế thừa.
  Nếu class hoặc phương thức là final - Java không cho phép kế thừa,
  proxy hóa là bất khả thi, Spring ném lỗi.
-> Overhead khi sinh bytecode
```

### Kế thừa

```java
@Configuration
public class ParentConfig {
    @Bean public CommonBean common() { return new CommonBean(); }
}

@Configuration
public class ChildConfig extends ParentConfig {
    // Bean common() cũng được đăng ký!
}
```

### Kinh nghiệm Production

**Tình huống thực tế: proxyBeanMethods = true làm chậm khởi động**
```
200 class @Configuration -> 5 giây cho CGLIB
Giải pháp: proxyBeanMethods = false
Kết quả: khởi động 2 giây
```

### Best Practices

1. **proxyBeanMethods = false** — làm mặc định cho các dự án mới, NHƯNG nếu các phương thức @Bean gọi lẫn nhau — giữ true (nếu không singleton sẽ vỡ).
2. **Tham số phương thức** -> thay vì gọi @Bean khác
3. **Không final** -> class và phương thức
4. **@Bean** -> cho các thư viện bên thứ ba
5. **Kế thừa** -> các bean của class cha cũng được đăng ký
6. **ConfigurationClassPostProcessor** -> xử lý ở giai đoạn sớm

### Tóm tắt cho Senior

- **@Configuration** = factory tạo bean
- **Full mode** -> CGLIB proxy, ngữ nghĩa singleton
- **Lite mode** -> không có proxy, các đối tượng mới
- **proxyBeanMethods = false** -> nhanh hơn, thân thiện với Native
- **Tham số phương thức** -> Spring tự inject
- **final** -> không thể proxy

## Interview Cheat Sheet

**Cần phải biết:**
- Class @Configuration tạo các bean qua các phương thức @Bean — cho các thư viện bên thứ ba và cấu hình phức tạp
- Full mode (proxyBeanMethods = true): CGLIB proxy chặn các lời gọi phương thức @Bean và trả về singleton
- Lite mode (proxyBeanMethods = false): gọi phương thức trực tiếp — mỗi lời gọi tạo một đối tượng mới
- Constructor Injection qua tham số phương thức @Bean — Spring tự inject các phụ thuộc
- CGLIB tạo một subclass qua kế thừa — không được là class/phương thức final
- proxyBeanMethods = false tăng tốc khởi động 40-60% và cần thiết cho GraalVM Native Image
- Kế thừa @Configuration: các bean của class cha cũng được đăng ký

**Các câu hỏi phụ thường gặp:**
- *Khi nào dùng proxyBeanMethods = false?* — Khi các phương thức @Bean không gọi lẫn nhau và các phụ thuộc được truyền qua tham số.
- *Điều gì xảy ra nếu gọi trực tiếp một phương thức @Bean ở Lite mode?* — Một instance mới được tạo, ngữ nghĩa singleton bị vỡ.
- *Tại sao class @Configuration không được là final?* — CGLIB tạo một subclass để proxy; kế thừa final là bất khả thi.
- *@Configuration khác @Component với các phương thức @Bean như thế nào?* — @Component hoạt động ở Lite mode — các lời gọi phương thức @Bean không được chặn.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Các phương thức @Bean luôn tạo singleton" — chỉ ở Full mode với proxy.
- "proxyBeanMethods = false luôn tốt hơn" — không, phá vỡ singleton khi các @Bean gọi nhau.
- "@Configuration chỉ là @Component" — không, Full so với Lite mode khác nhau cực kỳ quan trọng.
- "Có thể để các phương thức @Bean là final" — không, CGLIB không thể override phương thức.

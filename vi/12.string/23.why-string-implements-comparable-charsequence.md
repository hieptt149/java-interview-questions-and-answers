# Why String implements Comparable and CharSequence? (Tại sao String hiện thực Comparable và CharSequence?)

## 🟢 Junior Level

Class `String` hiện thực hai interface quan trọng, và mỗi interface mang lại cho nó khả năng riêng:

**`Comparable<String>`** — cho phép so sánh và sắp xếp các chuỗi:
```java
List<String> names = Arrays.asList("Charlie", "Alice", "Bob");
Collections.sort(names); // Hoạt động nhờ Comparable!
// ["Alice", "Bob", "Charlie"]
```

**`CharSequence`** — nghĩa là `String` là một "chuỗi ký tự", giống `StringBuilder`:
```java
// Method nhận bất kỳ CharSequence nào
void process(CharSequence text) { ... }

process("Hello");                  // String — hoạt động
process(new StringBuilder("Hi"));  // StringBuilder — cũng hoạt động!
```

**Ví dụ minh họa đơn giản:**
- `Comparable` — "khả năng so sánh" (giống cân cho thấy cái nào nặng hơn)
- `CharSequence` — "tôi là văn bản" (giống một tài liệu có thể đọc từng chữ cái một)

## 🟡 Middle Level

### Interface `Comparable<String>`

Method `compareTo(String anotherString)` so sánh các chuỗi **theo thứ tự từ điển (lexicographically)** (theo giá trị ký tự Unicode):

```java
"abc".compareTo("def");   // âm (abc < def)
"xyz".compareTo("abc");   // dương (xyz > abc)
"abc".compareTo("abc");   // 0 (bằng nhau)
```

**Nơi được dùng:**
- `Collections.sort()` và `Arrays.sort()` — sắp xếp danh sách chuỗi
- `TreeMap<String, V>` và `TreeSet<String>` — lưu trữ có sắp xếp
- `String` làm key trong `HashMap` (Java 8+) — khi xung đột hash, bucket trở thành cây, và `Comparable` giúp cân bằng

### Interface `CharSequence`

`CharSequence` là một interface với bốn method:
- `length()` — độ dài chuỗi
- `charAt(int index)` — ký tự tại index
- `subSequence(int start, int end)` — chuỗi con
- `toString()` — biểu diễn chuỗi

**Các hiện thực:** `String`, `StringBuilder`, `StringBuffer`, `CharBuffer`, `Segment` (Java 20+)

**Nơi được dùng:**
- `Pattern.matcher(CharSequence)` — regex hoạt động với bất kỳ CharSequence nào
- `String.join(CharSequence delimiter, CharSequence... elements)`
- Hầu hết các API văn bản nhận `CharSequence`, không phải `String`

### Bảng Các Lỗi Điển Hình

| Lỗi                                               | Hậu quả                                                  | Giải pháp                                                             |
| ----------------------------------------------------- | --------------------------------------------------------------- | -------------------------------------------------------------------- |
| `compareTo(null)`                                     | `NullPointerException`                                        | Luôn kiểm tra null trước khi so sánh                              |
| Nghĩ `compareTo` = `equals`                       | Logic sai                                                   | `compareTo` trả về int (thứ tự), `equals` — boolean (bình đẳng)       |
| Dùng `compareTo` cho so sánh phụ thuộc locale     | Sắp xếp sai (ё vs е, і vs и)                                | Dùng `Collator` cho tiếng Ukraine/Nga                                 |
| `StringBuilder` trong `TreeSet`                          | Không biên dịch được — `StringBuilder` không hiện thực `Comparable` | Chuyển sang `String` hoặc dùng `Comparator`                           |

### So Sánh: Comparable vs CharSequence

| Khía cạnh                | `Comparable<String>`                     | `CharSequence`                                         |
| --------------------- | ---------------------------------------- | ------------------------------------------------------ |
| Mục đích               | So sánh và sắp xếp                   | Trừu tượng hóa "chuỗi văn bản"                      |
| Method               | `compareTo(String)`                      | `length()`, `charAt()`, `subSequence()`, `toString()`  |
| Nơi cần thiết          | `TreeMap`, `TreeSet`, `Collections.sort()` | Regex, xử lý văn bản, string builder              |
| Kiểu trả về           | `int` (âm/không/dương)           | Nhiều loại (`int`, `char`, `CharSequence`, `String`)      |
| Yêu cầu tính bất biến| Bất biến (thay đổi phá vỡ thứ tự)          | Bất kỳ hiện thực nào                                     |

### Khi Nào KHÔNG Nên Dùng
- **`compareTo` cho sắp xếp phụ thuộc locale** — dùng `Collator.getInstance(locale)`
- **`CharSequence` cho lưu trữ** — nó là một interface, không phải class lưu trữ; cho văn bản mutable — `StringBuilder`
- **`CharSequence` mutable trong `TreeMap`/`TreeSet`** — thay đổi key phá vỡ thứ tự cây

## 🔴 Senior Level

### Hiện Thực Nội Bộ

**`Comparable<String>` — `compareTo`:**
```java
public int compareTo(String anotherString) {
    byte v1[] = this.value;
    byte v2[] = anotherString.value;
    byte coder = coder();
    if (coder == anotherString.coder()) {
        return isLatin1()
            ? StringLatin1.compareTo(v1, v2)
            : StringUTF16.compareTo(v1, v2);
    }
    return compareToUTF16(v1, v2);
}
```

So sánh từng ký tự theo code point Unicode. Nếu một chuỗi là tiền tố của chuỗi kia, chuỗi ngắn hơn được coi là "nhỏ hơn". JIT compiler inline `StringLatin1.compareTo` thành code tối ưu hóa SIMD.

**Contract của `CharSequence`:**
```java
public interface CharSequence {
    int length();
    char charAt(int index);
    CharSequence subSequence(int start, int end);
    public String toString();
}
```

Contract: `charAt(i)` nên trả về cùng ký tự với `toString().charAt(i)`. `subSequence(start, end)` nên tương đương với `toString().substring(start, end)`.

### Đánh Đổi Về Kiến Trúc (Trade-off)

**Comparable — tại sao String hiện thực Comparable:**

1. **Thứ tự tự nhiên:** Các chuỗi có thứ tự từ điển tự nhiên — thuộc tính cơ bản của văn bản
2. **Các collection dựa trên cây:** `TreeMap`/`TreeSet` yêu cầu `Comparable` hoặc `Comparator`
3. **Tree bin của HashMap (Java 8+):** Khi xung đột hashCode, bucket của HashMap trở thành cây đỏ-đen. `Comparable` được dùng để cân bằng:
   ```java
   // Bên trong HashMap.TreeNode
   Comparable<?> k = (key instanceof Comparable) ? (Comparable<?>)key : null;
   // Nếu key là Comparable — cây được cân bằng bởi compareTo
   // Nếu không — tie-breaking qua System.identityHashCode
   ```
   Nếu hashCode() của hai chuỗi khác nhau xung đột, HashMap xây dựng một cây
   cân bằng thay vì một danh sách, và compareTo() được dùng để sắp xếp các node cây.

**CharSequence — tại sao String hiện thực CharSequence:**

1. **Trừu tượng hóa:** Một interface duy nhất cho tất cả các loại "văn bản" — đa hình mà không cần chuyển đổi
2. **Tiết kiệm:** Không cần chuyển đổi `StringBuilder` → `String` để truyền vào API
3. **Tích hợp regex:** `Pattern.matcher(CharSequence)` — hoạt động trực tiếp với `StringBuilder`, không cấp phát chuỗi mới

### Các Trường Hợp Biên (Tối Thiểu 3)

**1. So sánh phụ thuộc locale:**
```java
"abc".compareTo("ABC"); // Âm (Unicode: 'a'(97) > 'A'(65))
// Đây KHÔNG phải điều người dùng kỳ vọng khi sắp xếp tên!

// Cho so sánh nhận biết locale, dùng Collator:
Collator collator = Collator.getInstance(Locale.UKRAINE);
collator.compare("аб", "аа"); // Sắp xếp tiếng Ukraine: аб > аа
collator.compare("є", "е");   // Thứ tự Ukraine: є sau е
```
`compareTo` so sánh theo **code point Unicode**, không theo quy tắc ngôn ngữ.

**2. StringBuilder KHÔNG hiện thực Comparable:**
```java
StringBuilder sb1 = new StringBuilder("abc");
StringBuilder sb2 = new StringBuilder("abc");
// sb1.compareTo(sb2) — KHÔNG TỒN TẠI!
// Lý do: các object mutable không nên nằm trong TreeSet/TreeMap
// — thay đổi key phá vỡ thứ tự cây, và get() sẽ không tìm thấy phần tử
```

**3. Cặp surrogate (UTF-16) và `compareTo`:**
```java
// Emoji = 2 char (cặp surrogate), 1 code point
String emoji = "😀"; // "😀"
emoji.length();        // 2 (số lượng char / code unit)
emoji.codePointCount(0, emoji.length()); // 1 (số lượng code point)

// compareTo hoạt động theo code unit (char), không theo code point
// Điều này có thể cho ra thứ tự không mong đợi với các chuỗi có emoji
String s1 = "a😀"; // "a😀"
String s2 = "ab";
s1.compareTo(s2); // Phụ thuộc vào giá trị surrogate, không phải ký tự "hiển thị"
```

**4. CharSequence và bí danh bộ nhớ (aliasing):**
```java
// StringBuilder.subSequence() trả về một String mới (bản sao!)
StringBuilder sb = new StringBuilder("Hello World");
CharSequence sub = sb.subSequence(0, 5); // "Hello" — String mới
// Đây KHÔNG phải zero-copy! Một object mới được cấp phát
// Nếu cần zero-copy — dùng ByteBuffer.asCharBuffer()
```

**5. Tree bin HashMap và Comparable:**
```java
// Java 8+: khi xung đột, HashMap dùng compareTo cho tree bin
String k1 = "FB"; // hashCode = 2236
String k2 = "Ea"; // hashCode = 2236 (xung đột!)
// HashMap.TreeNode dùng compareTo để cân bằng cây
// Không có Comparable, HashMap dùng tieBreakOrder() (identityHashCode + tên class).
// Cây KHÔNG suy giảm — vẫn O(log n), nhưng thứ tự trở nên tùy ý và không tái tạo được.
```

### Hiệu Năng

| Thao tác                             | Thời gian       | Ghi chú                            |
| ------------------------------------- | ---------- | -------------------------------- |
| `compareTo` (Latin-1, 10 ký tự)       | ~3ns       | Tối ưu hóa SIMD               |
| `compareTo` (UTF-16, 10 ký tự)        | ~5ns       |                                 |
| `compareTo` (khác nhau ở ký tự đầu)      | ~1ns       | Thoát sớm                      |
| `compareTo` (một cái là tiền tố)           | ~2ns       | Độ dài quyết định                  |
| `compareTo` vs `Comparator.comparing()`| ~3ns vs ~8ns | Instance method inline tốt hơn |
| `Collator.compare()`                  | ~50–200ns  | Nhận biết locale, tốn kém hơn đáng kể |

### Thread Safety

- `String.compareTo()` — **thread-safe** (String bất biến)
- `CharSequence` — **không được đảm bảo thread-safe**; tùy vào hiện thực
  - `String` — thread-safe
  - `StringBuilder` — không thread-safe
  - `StringBuffer` — thread-safe (synchronized)
- Khi dùng `CharSequence` làm tham số method — bên gọi chịu trách nhiệm đồng bộ hóa

### Câu Chuyện Thực Tế Trong Production

**Kịch bản 1:** Sắp xếp 1M chuỗi trong `TreeMap` (danh bạ người dùng, chỉ mục tìm kiếm):
- `Comparable.compareTo()`: ~3ns × 1M × log₂(1M) ≈ 60ms tổng cộng
- `Comparator` tùy chỉnh: ~8ns (overhead lời gọi virtual) ≈ 160ms
- Khác biệt: `compareTo` như một instance method được JIT compiler inline tốt hơn
- Cho sắp xếp phụ thuộc locale (tên tiếng Ukraine): `compareTo` sắp xếp sai ("Євген" sau "Евген" thay vì trước). Sửa lỗi: `TreeMap` với `Comparator` tùy chỉnh dựa trên `Collator.getInstance(Locale.UKRAINE)`.

**Kịch bản 2:** Regex matching trên `StringBuilder` (parser log):
```java
// XẤU — chuyển đổi và cấp phát thừa
StringBuilder sb = ...; // 10KB
Matcher m = Pattern.compile("\\d+").matcher(sb.toString()); // +10KB cấp phát

// TỐT — CharSequence trực tiếp, zero-copy
Matcher m = Pattern.compile("\\d+").matcher(sb);
```
Với 100K dòng log/giây: tiết kiệm 1GB/giây cấp phát.

**Kịch bản 3:** Xung đột HashMap trong production (Java 8+):
- Kẻ tấn công cố tình tạo các chuỗi có cùng hashCode → HashMap suy giảm xuống O(n) → DoS
- Java 8+: bucket trở thành cây, `compareTo` đảm bảo O(log n)
- Không có Comparable, thứ tự = không xác định. Lỗ hổng DoS qua xung đột hash
tồn tại độc lập với Comparable — tree bin giảm nhẹ từ O(n) xuống O(log n).

### Best Practices Cho Highload

- Dùng `CharSequence` làm kiểu tham số — **linh hoạt tối đa**, zero-copy khi làm việc với `StringBuilder`/`ByteBuffer`
- `compareTo` **nhanh hơn** `Comparator` tùy chỉnh (inline tốt hơn, ít overhead lời gọi virtual hơn)
- Cho **sắp xếp phụ thuộc locale**: `Collator`, không phải `compareTo` — `compareTo` không tính đến quy tắc ngôn ngữ
- Cho **không phân biệt hoa thường**: `String.CASE_INSENSITIVE_ORDER` (Comparator đã biên dịch trước, singleton)
- **Tránh các object mutable** trong `TreeMap`/`TreeSet` — thay đổi key phá vỡ thứ tự
- Cho **regex**: truyền `CharSequence` trực tiếp cho `Pattern.matcher()`, tránh `.toString()`
- Cho **bảo mật HashMap**: `Comparable` trên String bảo vệ khỏi DoS qua xung đột hash (cân bằng tree bin)
- Cho **độ trễ cực thấp**: `compareTo` tốt hơn `Comparator` 2–3ns mỗi lời gọi; ở 10M lời gọi = tiết kiệm 30ms

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `Comparable<String>` — method `compareTo()`, so sánh từ điển theo code point Unicode
- `CharSequence` — interface với 4 method: `length()`, `charAt()`, `subSequence()`, `toString()`
- `compareTo` được dùng trong `TreeMap`, `TreeSet`, `Collections.sort()`, và tree bin của HashMap (Java 8+)
- `CharSequence` cho phép truyền `String`, `StringBuilder`, `StringBuffer` vào một method — đa hình
- `compareTo` KHÔNG tính đến locale — cho sắp xếp tiếng Ukraine/Nga dùng `Collator`
- `StringBuilder` KHÔNG hiện thực `Comparable` — các object mutable không nên nằm trong `TreeSet`

**Các câu hỏi phụ thường gặp:**
- **Tại sao String hiện thực Comparable?** — Cho thứ tự từ điển tự nhiên và sử dụng trong `TreeMap`/`TreeSet`. Trong Java 8+ — để cân bằng tree bin của HashMap khi xung đột hashCode.
- **Tại sao `compareTo` != `equals`?** — `compareTo` trả về int (thứ tự), `equals` — boolean (bình đẳng). Contract: `compareTo() == 0` nên tương ứng với `equals() == true`.
- **Tại sao `StringBuilder` không hiện thực `Comparable`?** — Các object mutable không nên là key trong `TreeMap`/`TreeSet` — thay đổi key phá vỡ thứ tự cây.
- **Cách sắp xếp đúng các tên tiếng Ukraine?** — `Collator.getInstance(Locale.UKRAINE).compare()`, không phải `compareTo` — `compareTo` sắp xếp theo code point Unicode.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "`compareTo` tính đến ngôn ngữ" — sắp xếp theo code point Unicode, không theo quy tắc ngôn ngữ
- ❌ "`StringBuilder` có thể dùng trong `TreeSet`" — không hiện thực `Comparable`
- ❌ "`compareTo` và `equals` — giống nhau" — kiểu trả về và ngữ nghĩa khác nhau
- ❌ "`CharSequence` — một class lưu trữ" — nó là một interface, cho lưu trữ dùng `String` hoặc `StringBuilder`

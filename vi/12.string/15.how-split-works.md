# How split() Method Works (split() hoạt động như thế nào)

## 🟢 Junior Level

Method `split()` chia một chuỗi thành một mảng các chuỗi con theo một dấu phân cách (delimiter) cho trước.

**Ví dụ đơn giản:**
```java
String data = "apple,banana,cherry";
String[] fruits = data.split(",");
// ["apple", "banana", "cherry"]
```

**Quan trọng:** Dấu phân cách là một **biểu thức chính quy (regular expression)**, không chỉ là một chuỗi thông thường! Một số ký tự cần được escape:
```java
String ip = "192.168.1.1";
String[] parts = ip.split("\\."); // Dấu chấm cần được escape!
// ["192", "168", "1", "1"]
```

**Các chuỗi rỗng ở cuối bị xóa theo mặc định:**
```java
"a,b,,,".split(",");  // ["a", "b"] — các chuỗi rỗng bị xóa
"a,b,,,".split(",", -1); // ["a", "b", "", "", ""] — tất cả được giữ lại
```

## 🟡 Middle Level

### Hai Phiên Bản Của Method

```java
String[] split(String regex)           // limit = 0
String[] split(String regex, int limit) // kiểm soát đầy đủ
```

**Tham số `limit`:**
| Limit        | Hành vi                                               | Ví dụ `"a,b,c,,".split(",", limit)` |
| ------------ | ------------------------------------------------------ | ------------------------------------- |
| `0` (mặc định)| Chia tối đa, các chuỗi rỗng ở cuối **bị xóa**               | `["a", "b", "c"]`                     |
| `> 0`        | Không quá `limit` phần tử, phần còn lại — trong phần tử cuối  | `["a", "b,c,,"]` (limit=2)            |
| `< 0`        | Chia tối đa, các chuỗi rỗng **được giữ lại**                     | `["a", "b", "c", "", ""]`             |

### Tối Ưu Hóa Fast Path

`split()` **KHÔNG PHẢI** lúc nào cũng dùng regex engine nặng nề. Nếu dấu phân cách là một ký tự đơn (không phải metacharacter của regex), việc tìm kiếm trực tiếp được dùng:

```java
// Fast Path — không biên dịch regex
"hello world".split(" ");

// Regex engine — biên dịch Pattern/Matcher
"hello world".split("\\s+");
```

Các metacharacter phá vỡ Fast Path: ., $, |, (, ), [, ], ^, ?, *, +, \

### Các Lỗi Điển Hình
1. **Lỗi:** `split(".")` — dấu chấm = "bất kỳ ký tự nào" trong regex
   **Giải pháp:** `split("\\.")` hoặc `split(Pattern.quote("."))`

2. **Lỗi:** Kỳ vọng các chuỗi rỗng ở cuối theo mặc định
   **Giải pháp:** Dùng `split(",", -1)` để giữ lại các chuỗi rỗng

3. **Lỗi:** `split()` trong vòng lặp cho cùng một regex
   **Giải pháp:** Biên dịch `Pattern` một lần: `Pattern.compile(",").split(str)`

## 🔴 Senior Level

### Hiện Thực Nội Bộ

**OpenJDK — String.split():**
```java
public String[] split(String regex, int limit) {
    char ch = 0;
    // Fast Path: một ký tự đơn, không phải regex meta
    if (((regex.value.length == 1 &&
         ".$|()[{^?*+\\".indexOf(ch = regex.charAt(0)) == -1) ||
         (regex.length() == 2 &&
          regex.charAt(0) == '\\' &&
          (((ch = regex.charAt(1))-'0')|('9'-ch)) < 0 &&
          ((ch-'a')|('z'-ch)) < 0 &&
          ((ch-'A')|('Z'-ch)) < 0)) &&
        (ch < Character.MIN_HIGH_SURROGATE ||
         ch > Character.MAX_LOW_SURROGATE)) {
        // Điều này kiểm tra ch KHÔNG phải là chữ thường (tương tự cho chữ hoa
        // và chữ số) — đảm bảo rằng \ không phải là một shorthand đã biết (\d, \w v.v.)
        // FAST PATH — tìm kiếm trực tiếp qua mảng byte
        int off = 0;
        int next = indexOf(ch, off);
        // ... chia thủ công mà không cần Pattern/Matcher
    }
    // SLOW PATH — qua Pattern
    return Pattern.compile(regex).split(this, limit);
}
```

### Đánh Đổi Về Kiến Trúc (Trade-off)

**Fast Path:**
- Ưu điểm: Không cấp phát Pattern/Matcher, ~5-10ns mỗi lời gọi
- Nhược điểm: Chỉ hoạt động với các dấu phân cách đơn giản nhất

**Regex Engine (Pattern/Matcher):**
- Ưu điểm: Sức mạnh đầy đủ của biểu thức chính quy
- Nhược điểm: Biên dịch regex (~1-5μs), cấp phát Pattern + Matcher + kết quả

### Các Trường Hợp Biên

1. **Input rỗng:**
   ```java
   "".split(",");    // [""] — mảng có một chuỗi rỗng
   ",".split(",");   // [] — mảng rỗng (limit=0 xóa các chuỗi rỗng)
   ",".split(",", -1); // ["", ""] — hai chuỗi rỗng
   ```

2. **Regex với lookahead/lookbehind:**
   ```java
   "a1b2c3".split("(?=\\d)"); // ["a", "1b", "2c", "3"] — chia trước chữ số
   ```

3. **Các chuỗi rỗng ở cuối:**
   ```java
   "a,,b".split(",");     // ["a", "", "b"]
   "a,,b,,,".split(",");  // ["a", "", "b"] — các chuỗi rỗng ở cuối bị xóa
   "a,,b,,,".split(",", -1); // ["a", "", "b", "", "", ""]
   ```

### Hiệu Năng
| Kịch bản               | Fast Path | Regex Engine | Pattern Đã Biên Dịch Trước |
| ---------------------- | --------- | ------------ | -------------------- |
| `split(",")` 1M lần  | ~50ms     | ~500ms       | ~80ms                |
| `split("\\ ")` 1M    | ~60ms        | ~500ms               | ~80ms |
| `split("\\s+")` 1M     | N/A       | ~800ms       | ~120ms               |
| Overhead biên dịch regex | 0         | ~1-5μs       | 0 (một lần)             |

### Kinh Nghiệm Production
**Kịch bản:** Parse CSV (10M dòng):
```java
// XẤU — biên dịch regex trên mỗi dòng
for (String line : lines) {
    String[] fields = line.split(","); // 10M lần biên dịch regex!
}

// TỐT — Pattern đã biên dịch trước
private static final Pattern COMMA = Pattern.compile(",");
for (String line : lines) {
    String[] fields = COMMA.split(line);
}

// TỐT HƠN — Fast Path (ký tự đơn, không phải meta)
for (String line : lines) {
    String[] fields = line.split(","); // Fast Path sẽ được kích hoạt!
}
```

**Kịch bản 2:** Parse file log với dấu phân cách regex:
- `line.split("\\s\\|\\s")` — không phải Fast Path, mỗi lời gọi biên dịch regex
- Sửa lỗi: `private static final Pattern SEP = Pattern.compile("\\s\\|\\s");`
- Kết quả: -80% CPU khi parse

### Best Practices Cho Highload
- Cho các dấu phân cách một ký tự (không phải meta): `split(",")` — Fast Path
- Cho các dấu phân cách regex: `Pattern.compile(regex).split(str)` đã biên dịch trước
- Trong các hot path: cân nhắc hiện thực thủ công qua `indexOf()` — cấp phát tối thiểu
- Cho CSV/TSV: các thư viện chuyên dụng (OpenCSV, Apache Commons CSV)
- Cho độ trễ cực thấp: parse zero-copy qua các wrapper `CharSequence`

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `split(regex)` chia chuỗi theo biểu thức chính quy, trả về một mảng
- Fast Path: cho các dấu phân cách một ký tự không phải meta — tìm kiếm trực tiếp không cần regex engine
- Tham số `limit`: `0` — các chuỗi rỗng ở cuối bị xóa, `< 0` — được giữ lại, `> 0` — số phần tử tối đa
- Các metacharacter của regex cần escape: `. $ | ( ) [ ] { } ^ ? * + \`
- `Pattern.quote(".")` — cách an toàn để escape cho `split()`
- Biên dịch regex ở mỗi lần lặp vòng lặp — antipattern, dùng `Pattern` đã biên dịch trước

**Các câu hỏi phụ thường gặp:**
- **Tại sao `split(".")` không hoạt động?** — Dấu chấm trong regex = "bất kỳ ký tự nào". Cần `split("\\.")`.
- **`split(",", -1)` làm gì?** — Giữ lại các chuỗi rỗng ở cuối. Theo mặc định (`limit=0`) chúng bị xóa.
- **Fast Path trong `split()` là gì?** — Nếu dấu phân cách là một ký tự đơn không phải meta, việc tìm kiếm trực tiếp được dùng mà không cần Pattern/Matcher.
- **Làm sao tối ưu hóa `split()` trong vòng lặp?** — `Pattern` đã biên dịch trước: `private static final Pattern COMMA = Pattern.compile(",")`.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "`split()` nhận một chuỗi thông thường, không phải regex" — nhận regex, dấu chấm sẽ phá vỡ logic
- ❌ "`split()` luôn giữ lại các chuỗi rỗng" — theo mặc định (`limit=0`) xóa các chuỗi rỗng ở cuối
- ❌ "Bạn có thể biên dịch regex trong vòng lặp mà không có hậu quả" — 10M lần biên dịch = vài giây CPU
- ❌ "`split()` — cách duy nhất để chia một chuỗi" — còn có `indexOf()`, `StringTokenizer`, các parser chuyên dụng

# What is the difference between HashMap, LinkedHashMap and TreeMap? (Sự khác nhau giữa HashMap, LinkedHashMap và TreeMap là gì?)

## 🟢 Junior Level

**HashMap, LinkedHashMap và TreeMap** — ba cài đặt Map chính.

**Sự khác biệt chính:**

|               | HashMap      | LinkedHashMap                     | TreeMap                   |
| ------------- | ------------ | --------------------------------- | ------------------------- |
| **Thứ tự**    | Không có     | Thứ tự chèn vào                   | Sắp xếp                   |
| **Tốc độ**    | Nhanh O(1)   | Chậm hơn một chút O(1) + overhead của DLL | Chậm hơn O(log n) cây     |
| **key null**  | ✅ Một       | ✅ Một                            | ❌ Không cho phép          |
| **Độ phức tạp**| O(1)         | O(1)                              | O(log n)                  |

```java
// HashMap: không có thứ tự
Map<String, Integer> hm = new HashMap<>();
hm.put("C", 3); hm.put("A", 1); hm.put("B", 2);
// → {A=1, C=3, B=2} (không đảm bảo thứ tự)

// LinkedHashMap: thứ tự chèn vào
Map<String, Integer> lh = new LinkedHashMap<>();
lh.put("C", 3); lh.put("A", 1); lh.put("B", 2);
// → {C=3, A=1, B=2} (như đã chèn vào)

// TreeMap: được sắp xếp theo key
Map<String, Integer> tm = new TreeMap<>();
tm.put("C", 3); tm.put("A", 1); tm.put("B", 2);
// → {A=1, B=2, C=3} (được sắp xếp!)
```

## 🟡 Middle Level

### HashMap: tốc độ

```java
// Bên trong: mảng bucket + các list/cây
// O(1) cho get/put
// → Lựa chọn mặc định tốt nhất

// Treeification (Java 8+):
// > 8 phần tử trong một bucket → cây
// → Bảo vệ chống lại hashCode() tệ

// Resize: × 2 khi lấp đầy
// → Thao tác tốn kém (sao chép tất cả các phần tử)
```

### LinkedHashMap: thứ tự + LRU

```java
// Bên trong: HashMap + danh sách liên kết đôi
// O(1) cho get/put
// + thứ tự chèn vào

// LRU cache:
Map<K, V> cache = new LinkedHashMap<>(16, 0.75f, true) {
    protected boolean removeEldestEntry(Map.Entry eldest) {
        return size() > MAX;
    }
};
// accessOrder = true → get() di chuyển về cuối
```

### TreeMap: sắp xếp

```java
// Bên trong: cây đỏ-đen
// O(log n) cho get/put
// → Sắp xếp theo key
// → floorKey, ceilingKey, subMap

// Không chấp nhận null (nếu không có Comparator tùy chỉnh)
// compareTo quyết định tính duy nhất!
```

### Khi nào dùng cái nào

| Kịch bản          | Chọn cái gì                     |
| ----------------- | ------------------------------- |
| Từ điển, cache    | **HashMap**                     |
| Thứ tự chèn vào   | **LinkedHashMap**               |
| LRU cache         | **LinkedHashMap (accessOrder)** |
| Sắp xếp theo key  | **TreeMap**                     |
| Truy vấn khoảng (range query) | **TreeMap**          |

### Cache Locality

**Cache Locality:** HashMap — mảng bucket, các phần tử nằm gần nhau trong bộ nhớ (cache locality tốt hơn). LinkedHashMap — các node được liên kết bằng các tham chiếu, nằm rải rác khắp heap (nhiều cache miss hơn khi iterate).

## 🔴 Senior Level

### So sánh Bộ nhớ

```
HashMap entry: ~32 byte
LinkedHashMap entry: ~48 byte (+ before/after)
TreeMap entry: ~40-56 byte (left/right/parent/color)

→ 1 triệu entry:
  HashMap: ~36 MB
  LinkedHashMap: ~52 MB
  TreeMap: ~44 MB
```

### Java 21: SequencedMap

```java
// LinkedHashMap và TreeMap → SequencedMap (SequencedMap là Java 21+, không có sẵn trên các phiên bản cũ hơn.)
map.putFirst("A", 1);    // Phương thức mới!
map.putLast("Z", 26);    // Phương thức mới!
map.firstEntry();        // Phương thức mới!
map.reversed();          // Thứ tự đảo ngược (view)

// HashMap KHÔNG phải là SequencedMap
```

### False Sharing trong đa luồng

```
synchronizedMap(new HashMap<>())
  → Tranh giành các cache line
  → False sharing trên các CPU đa nhân

ConcurrentHashMap → giải pháp!
```

### compareTo so với equals

```java
// TreeMap dùng compareTo!
// Nếu compareTo = 0 → phần tử đã tồn tại
// Ngay cả khi equals = false!

class Key implements Comparable<Key> {
    String name;
    public int compareTo(Key o) {
        return name.compareTo(o.name);
    }
    public boolean equals(Object o) {
        return false; // Logic khác!
    }
}

// → Mất dữ liệu nếu không nhất quán!
```

### Kinh nghiệm Production

**Tình huống thực tế: LRU cache**
```java
// 10,000 phần tử, đọc thường xuyên
// HashMap + xóa thủ công phần tử cũ → phức tạp

// LinkedHashMap với accessOrder + removeEldestEntry
// → 5 dòng code → cache có sẵn!
```

### Best Practices

1. **HashMap** — lựa chọn mặc định nếu không cần thứ tự hoặc sắp xếp
2. **LinkedHashMap** — thứ tự hoặc LRU
3. **TreeMap** — sắp xếp/các khoảng
4. **initialCapacity** → tránh resize
5. **Các key bất biến** — bắt buộc
6. **Java 21** → API SequencedMap
7. **compareTo = equals** cho TreeMap
8. **Bộ nhớ** → HashMap gọn hơn

### Tóm tắt cho Senior

- **HashMap** = O(1), không có thứ tự, treeification
- **LinkedHashMap** = O(1), thứ tự, LRU cache
- **TreeMap** = O(log n), sắp xếp, điều hướng
- **Bộ nhớ:** HashMap < TreeMap < LinkedHashMap
- **SequencedMap (Java 21)** → putFirst/reversed
- **CPU Cache:** HashMap > TreeMap
- **compareTo ≠ equals** → mất dữ liệu
- **LRU** = LinkedHashMap(accessOrder=true)

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- HashMap = O(1), không có thứ tự, bên trong là mảng bucket + các list/cây, treeification khi có > 8 va chạm
- LinkedHashMap = O(1) + danh sách liên kết đôi để giữ thứ tự chèn vào, hỗ trợ LRU cache (accessOrder=true)
- TreeMap = O(log n), cây đỏ-đen, sắp xếp theo key, điều hướng (floorKey, ceilingKey, subMap)
- HashMap cho phép một key null, TreeMap thì không (nếu không có Comparator tùy chỉnh)
- TreeMap dùng compareTo cho tính duy nhất, không phải equals — không nhất quán = mất dữ liệu
- Bộ nhớ: HashMap (~32 byte/entry) < TreeMap (~40-56 byte) < LinkedHashMap (~48 byte)
- Java 21: API SequencedMap (putFirst, putLast, reversed) cho LinkedHashMap và TreeMap
- LRU cache = LinkedHashMap(16, 0.75f, true) + removeEldestEntry được override

**Các câu hỏi phụ thường gặp:**
- **LRU cache hoạt động trên LinkedHashMap như thế nào?** — accessOrder=true di chuyển phần tử về cuối ở mỗi lần get(). removeEldestEntry() loại bỏ phần tử cũ nhất khi vượt quá giới hạn.
- **Tại sao TreeMap không chấp nhận null?** — Vì nó cần gọi compareTo để sắp xếp, và null không có phương thức compareTo. Cách khắc phục: Comparator.nullsFirst().
- **Treeification trong HashMap là gì?** — Khi có > 8 phần tử trong một bucket, danh sách liên kết chuyển thành cây đỏ-đen — bảo vệ chống lại O(n) khi có va chạm.
- **Khi nào HashMap tốt hơn LinkedHashMap?** — Luôn luôn theo mặc định, trừ khi cần thứ tự iterate. LinkedHashMap dùng +50% bộ nhớ cho danh sách liên kết.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "TreeMap dùng equals để kiểm tra các key" — nó dùng compareTo!
- ❌ "HashMap giữ nguyên thứ tự chèn vào" — không, thứ tự không được đảm bảo
- ❌ "LinkedHashMap chậm hơn cho get/put" — cùng độ phức tạp O(1), chỉ nhiều bộ nhớ hơn
- ❌ "TreeMap dành cho thứ tự chèn vào" — LinkedHashMap dành cho việc đó, TreeMap sắp xếp theo key

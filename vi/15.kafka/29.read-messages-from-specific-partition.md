# Can you read messages from a specific partition in Kafka (Bạn có thể đọc message từ một partition cụ thể trong Kafka không)

## Junior Level

### Định Nghĩa

**Có, bạn có thể!** Một Kafka Consumer có thể đọc message từ một partition cụ thể thay vì tất cả cùng lúc. Điều này được thực hiện thông qua phương thức `assign()` thay vì `subscribe()`.

### Analogy

Hãy tưởng tượng một nhà hàng với nhiều đầu bếp (partition).

`subscribe()` — bạn ngồi ở một bàn chung và ăn bất cứ thứ gì bất kỳ đầu bếp nào mang đến (người phục vụ phân phối).

`assign()` — bạn chọn đầu bếp nào bạn muốn: "Từ đầu bếp 1 và 3, nhưng không phải 2."

### Ví Dụ Code

```java
Properties props = new Properties();
props.put("bootstrap.servers", "localhost:9092");
props.put("group.id", "my-consumer");
props.put("key.deserializer", "org.apache.kafka.common.serialization.StringDeserializer");
props.put("value.deserializer", "org.apache.kafka.common.serialization.StringDeserializer");

KafkaConsumer<String, String> consumer = new KafkaConsumer<>(props);

// assign() — gán thủ công các partition cụ thể
TopicPartition partition = new TopicPartition("orders", 0);  // topic "orders", partition 0
consumer.assign(List.of(partition));

// Chỉ đọc từ partition 0
while (true) {
    ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
    for (ConsumerRecord<String, String> record : records) {
        System.out.println("Offset: " + record.offset());
        System.out.println("Key: " + record.key());
        System.out.println("Value: " + record.value());
    }
}
```

### subscribe() vs assign()

```java
// subscribe() — gán tự động thông qua consumer group
consumer.subscribe(List.of("orders"));
// Kafka tự quyết định partition nào để đưa cho consumer này

// assign() — gán thủ công
TopicPartition p0 = new TopicPartition("orders", 0);
TopicPartition p1 = new TopicPartition("orders", 1);
consumer.assign(List.of(p0, p1));
// Bạn quyết định partition nào để đọc
```

### Khi Nào Sử Dụng

- **Testing** — đọc message từ một partition cụ thể
- **Replay** — đọc lại message từ một offset nhất định
- **Debugging** — điều tra một partition có vấn đề
- **Các tác vụ cụ thể** — khi logic yêu cầu một partition cụ thể

## Middle Level

### subscribe() vs assign() — So Sánh Chi Tiết

| Khía cạnh              | subscribe()                     | assign()                                                                                                                                     |
| --------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **Consumer group**    | Dùng consumer group             | Bỏ qua consumer group                                                                                                                        |
| **Rebalancing**       | Tự động                          | Không có rebalancing — nếu một consumer dùng assign() crash, các partition của nó KHÔNG được gán lại cho các consumer khác. Việc xử lý cho các partition đó dừng hoàn toàn cho đến khi restart. |
| **Quản lý offset**    | Tự động (dựa trên group)         | Thủ công (bạn tự xử lý)                                                                                                                       |
| **Fault tolerance**   | Cao (rebalancing khi lỗi)        | Thấp (xử lý thủ công)                                                                                                                         |
| **Khả năng mở rộng**  | Tự động                          | Thủ công                                                                                                                                      |
| **Trường hợp sử dụng**| Xử lý production                 | Testing, debugging, các tác vụ đặc biệt                                                                                                       |

### assign() — Cách Hoạt Động

```java
// 1. Tạo đối tượng TopicPartition
TopicPartition partition = new TopicPartition("orders", 0);

// 2. Gán cho consumer
consumer.assign(List.of(partition));

// 3. (Tùy chọn) Đặt offset
consumer.seek(partition, 1000);           // từ offset 1000
consumer.seekToBeginning(List.of(partition));  // từ đầu
consumer.seekToEnd(List.of(partition));        // từ cuối

// 4. Đọc
ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
// Chỉ từ partition 0
```

### Seek — Truy Cập Ngẫu Nhiên

```java
TopicPartition partition = new TopicPartition("orders", 0);
consumer.assign(List.of(partition));

// Đọc từ một offset cụ thể
consumer.seek(partition, 5000);

// Đọc từ đầu
consumer.seekToBeginning(List.of(partition));

// Đọc từ cuối (message mới)
consumer.seekToEnd(List.of(partition));

// Đọc từ một timestamp
long timestamp = System.currentTimeMillis() - 3600_000;  // 1 giờ trước
Map<TopicPartition, Long> timestamps = Map.of(partition, timestamp);
Map<TopicPartition, OffsetAndTimestamp> offsets = consumer.offsetsForTimes(timestamps);
OffsetAndTimestamp offsetAndTs = offsets.get(partition);
if (offsetAndTs != null) {
    consumer.seek(partition, offsetAndTs.offset());
}
```

### Bảng Các Lỗi Thường Gặp

| Lỗi                                  | Triệu Chứng                  | Hậu Quả                     | Giải Pháp                       |
| ----------------------------------- | ----------------------------- | --------------------------- | -------------------------------- |
| assign() + subscribe() cùng nhau     | Hành vi xung đột              | Hành vi không thể đoán trước | Dùng một trong hai                |
| Không quản lý offset thủ công        | Khi restart — đọc từ đầu       | Xử lý trùng lặp             | Lưu offset ở bên ngoài            |
| assign() cho xử lý production        | Không có rebalancing          | Consumer lỗi = dữ liệu bị đình trệ | Dùng subscribe() cho production |
| assign() không có group id           | Group.id bị bỏ qua            | OK, nhưng gây nhầm lẫn      | group.id không cần cho assign()   |
| Seek mà không có assign()            | IllegalStateException         | Exception                   | assign() trước, rồi seek()        |
| Đọc partition không tồn tại          | Exception hoặc kết quả rỗng   | Lỗi                          | Kiểm tra partition tồn tại        |

### Khi Nào assign() Hữu Ích

```
✅ Testing: kiểm tra một partition cụ thể
✅ Replay: đọc lại message từ đầu
✅ Debugging: điều tra một partition cụ thể
✅ Data migration: sao chép một partition sang cluster khác
✅ Backfill: xử lý dữ liệu lịch sử từ một partition cụ thể
✅ Audit: kiểm tra dữ liệu trong một partition cụ thể
```

### Khi Nào KHÔNG Nên Dùng assign()

- **Xử lý production** — không có fault tolerance
- **Auto-scaling** — không có rebalancing
- **Consumer group** — assign() bỏ qua group
- **Khi cần load balancing** — subscribe() làm điều này tự động

## Senior Level

### Cơ Chế Nội Bộ Sâu

#### assign() vs subscribe() — Triển Khai Nội Bộ

```java
// Cơ chế nội bộ KafkaConsumer

subscribe():
  consumer.coordinator — protocol GroupCoordinator
  consumer.subscriptions — động (thay đổi khi rebalance)
  consumer.assignment — được tính toán bởi GroupCoordinator

  Luồng:
    1. consumer.subscribe(topics) → request JoinGroup
    2. GroupCoordinator — bầu leader
    3. Leader tính toán assignment (PartitionAssignor)
    4. Response SyncGroup → mỗi consumer nhận partition của nó
    5. Callback consumer.onPartitionsAssigned()
    6. consumer.assignment ← assignment đã tính toán

assign():
  consumer.coordinator — KHÔNG được dùng
  consumer.subscriptions — tĩnh (do người dùng định nghĩa)
  consumer.assignment ← đầu vào trực tiếp từ người dùng

  Luồng:
    1. consumer.assign(partitions) → gán trực tiếp
    2. Không có JoinGroup, không có coordinator, không có rebalancing
    3. consumer.assignment ← các partition do người dùng cung cấp
    4. consumer.position(partition) → fetch từ __consumer_offsets (nếu group.id được đặt)
       HOẶC → từ đầu (nếu auto.offset.reset = earliest)
```

#### Quản Lý Offset Với assign()

```java
// assign() KHÔNG tự động quản lý offset
// Bạn phải tự theo dõi offset

// Lựa chọn 1: Dùng group.id (offset trong __consumer_offsets)
props.put("group.id", "my-consumer");
consumer.assign(List.of(partition));
// Offset vẫn có thể được commit!
consumer.commitSync();  // lưu vào __consumer_offsets

// Lựa chọn 2: Lưu trữ offset bên ngoài
Map<TopicPartition, Long> savedOffsets = loadOffsetsFromDB();
consumer.assign(List.of(partition));
for (Map.Entry<TopicPartition, Long> entry : savedOffsets.entrySet()) {
    consumer.seek(entry.getKey(), entry.getValue());
}
// Sau khi xử lý:
saveOffsetsToDB(partition, currentOffset);

// Lựa chọn 3: Không theo dõi offset
consumer.assign(List.of(partition));
consumer.seekToBeginning(List.of(partition));
// Mỗi lần chạy — đọc từ đầu
```

#### ConsumerRebalanceListener — Chỉ Cho subscribe()

```java
// subscribe() + ConsumerRebalanceListener
consumer.subscribe(List.of("orders"), new ConsumerRebalanceListener() {
    @Override
    public void onPartitionsRevoked(Collection<TopicPartition> partitions) {
        // Được gọi khi rebalancing
        consumer.commitSync();
        cleanupState(partitions);
    }

    @Override
    public void onPartitionsAssigned(Collection<TopicPartition> partitions) {
        // Được gọi khi nhận partition
        initializeState(partitions);
    }
});

// assign() — ConsumerRebalanceListener KHÔNG ĐƯỢC GỌI
// Không có rebalancing → không có callback
// Bạn hoàn toàn chịu trách nhiệm về vòng đời
```

### Đánh Đổi

| Khía cạnh                | subscribe()                  | assign()                     |
| ----------------------- | ----------------------------- | ----------------------------- |
| Độ phức tạp              | Thấp (tự động)                 | Cao (quản lý thủ công)          |
| Fault tolerance          | Cao                            | Thấp                            |
| Kiểm soát                | Thấp                           | Tối đa                          |
| Overhead vận hành        | Thấp                           | Cao                             |
| Phù hợp cho production   | Có                             | Hiếm khi                        |
| Phù hợp cho testing      | Không (không thể chọn partition) | Có                            |

### Edge Cases

**1. assign() và offset của consumer group:**

```java
// Kịch bản: group.id được đặt, assign() được dùng
props.put("group.id", "order-service");
consumer.assign(List.of(new TopicPartition("orders", 0)));

// Ở lần poll đầu tiên:
// consumer.position(partition) → kiểm tra __consumer_offsets
// Nếu committed offset tồn tại → tiếp tục từ đó
// Nếu không → auto.offset.reset được áp dụng (earliest/latest)

// Điều này có nghĩa là assign() CÓ THỂ dùng committed offset!
// NHƯNG: không tự động commit, cần consumer.commitSync()
```

**2. Trộn assign() và subscribe() — hành vi không xác định:**

```java
// ĐỪNG LÀM ĐIỀU NÀY:
consumer.subscribe(List.of("orders"));
consumer.assign(List.of(new TopicPartition("orders", 0)));

// Kết quả:
// Đăng ký subscribe() có thể bị ghi đè
// assign() có thể xung đột với group assignment
// Hành vi: không xác định, phụ thuộc vào phiên bản Kafka
```

**3. Seek trên một partition chưa được gán:**

```java
TopicPartition p0 = new TopicPartition("orders", 0);
TopicPartition p1 = new TopicPartition("orders", 1);
consumer.assign(List.of(p0));

// Exception!
consumer.seek(p1, 1000);
// IllegalStateException: You can only check the position for partitions assigned to this consumer.
```

**4. assign() với các thay đổi partition động:**

```java
// assign() — gán tĩnh
// Nếu các partition mới được thêm vào topic — assign() KHÔNG thấy chúng

Topic: orders (3 partition: 0, 1, 2)
consumer.assign(List.of(p0, p1, p2));

// Admin thêm partition 3 vào topic "orders"
// consumer tiếp tục chỉ đọc p0, p1, p2
// partition 3 — chưa được gán, không được đọc

// Giải quyết: gán lại định kỳ
while (running) {
    Set<TopicPartition> currentAssignment = consumer.assignment();
    Set<TopicPartition> desiredAssignment = getPartitionsForTopic("orders");
    if (!currentAssignment.equals(desiredAssignment)) {
        consumer.assign(desiredAssignment);
    }
    ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
    // xử lý...
}
```

**5. assign() với commit offset thủ công — mẫu exactly-once:**

```java
// assign() + offset thủ công = kiểm soát hoàn toàn
props.put("group.id", "order-service");
props.put("enable.auto.commit", "false");

TopicPartition partition = new TopicPartition("orders", 0);
consumer.assign(List.of(partition));

// Tải offset đã lưu
long savedOffset = loadOffsetFromDB(partition);
consumer.seek(partition, savedOffset);

while (running) {
    ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
    for (ConsumerRecord<String, String> record : records) {
        processWithTransaction(record);  // ghi DB + offset trong cùng transaction
    }
    // Offset được commit trong cùng transaction DB với việc xử lý
    // Exactly-once semantics!
}
```

**6. Đọc từ một partition cụ thể để debug:**

```java
// Điều tra: partition 2 có lag cao hơn
TopicPartition suspiciousPartition = new TopicPartition("orders", 2);
consumer.assign(List.of(suspiciousPartition));
consumer.seekToBeginning(List.of(suspiciousPartition));

// Đọc tất cả message từ partition 2
int count = 0;
while (true) {
    ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
    if (records.isEmpty()) break;

    for (ConsumerRecord<String, String> record : records) {
        count++;
        System.out.printf("Offset %d: key=%s, value=%s%n",
                         record.offset(), record.key(), record.value());
        if (count > 10000) break;  // giới hạn để an toàn
    }
}
System.out.println("Tổng message trong partition 2: " + count);
```

### Production War Story

**Tình huống:** E-commerce, 10 partition, 10 consumer (subscribe). Một consumer bắt đầu bị chậm lại — lag chỉ tăng trên partition 7.

**Điều tra:**
```bash
# Kiểm tra consumer nào có partition 7
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --describe --group order-service

GROUP           TOPIC    PARTITION  CURRENT-OFFSET  LOG-END-OFFSET  LAG  CONSUMER-ID
order-service   orders   7          500000          550000          50000  consumer-7-abc123
```

**Nguyên nhân gốc rễ:** Consumer-7 xử lý message chậm hơn — nó có kết nối DB chậm.

**Debug với assign():**
```java
// assign() đến partition 7 để phân tích chi tiết
TopicPartition p7 = new TopicPartition("orders", 7);
consumer.assign(List.of(p7));
consumer.seek(p7, 500000);  // bắt đầu từ offset lag

// Phân tích message
Map<String, Integer> keyDistribution = new HashMap<>();
while (true) {
    ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
    if (records.isEmpty()) break;

    for (ConsumerRecord<String, String> record : records) {
        String key = record.key();
        keyDistribution.merge(key, 1, Integer::sum);
    }
}

// Phát hiện: 80% message có key "user-42"
// → Tất cả message cho user-42 trong một partition (hash của key)
// → Một user = hot key = bottleneck của một consumer duy nhất
```

**Giải quyết:** Custom partitioner để phân phối key tốt hơn, không dựa vào hash mặc định.

### Các Thực Hành Tốt Nhất Cho Highload

```
✅ subscribe() cho xử lý production
✅ assign() cho testing, debugging, replay
✅ ConsumerRebalanceListener cho subscribe()
✅ Lưu trữ offset bên ngoài cho assign()
✅ assign() + seek() để debug có mục tiêu
✅ Giám sát lag mỗi partition (phát hiện hot key)
✅ Custom partitioner để phân phối đồng đều

❌ assign() cho production (không có fault tolerance)
❌ Trộn subscribe() + assign() (hành vi không xác định)
❌ assign() không có quản lý offset (xử lý trùng lặp khi restart)
❌ Seek trên partition chưa được gán (IllegalStateException)
❌ assign() với auto-scaling (không có rebalancing)
❌ Bỏ qua mất cân bằng lag partition (phát hiện hot key)
```

### Các Quyết Định Kiến Trúc

1. **subscribe() = mặc định cho production** — auto-scaling, fault tolerance, rebalancing
2. **assign() = công cụ chuyên biệt** — testing, debugging, replay, migration
3. **assign() + offset bên ngoài** = exactly-once với xử lý transactional
4. **Phát hiện hot key** — mất cân bằng lag partition → vấn đề partitioner
5. **Seek + assign** = công cụ mạnh mẽ để debug và điều tra dữ liệu

### Tóm Tắt Cho Senior

- assign() — kiểm soát trực tiếp việc gán partition, không cần quản lý consumer group
- subscribe() — gán tự động thông qua GroupCoordinator, với rebalancing
- assign() có thể dùng committed offset nếu group.id được đặt
- assign() KHÔNG kích hoạt ConsumerRebalanceListener — bạn hoàn toàn chịu trách nhiệm
- Trộn subscribe() + assign() = hành vi không xác định — đừng làm điều đó
- assign() + seek() = công cụ mạnh mẽ để debug và điều tra
- Phát hiện hot key thông qua giám sát lag partition
- Xử lý production: subscribe() — hầu như luôn là lựa chọn đúng
- assign() — công cụ chuyên biệt cho testing, replay, debugging, migration

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- `assign()` — gán thủ công các partition cụ thể; `subscribe()` — tự động qua consumer group
- `assign()` bỏ qua consumer group: không có rebalancing, không có fault tolerance
- Nếu một consumer dùng assign() crash — các partition của nó KHÔNG được gán lại, việc xử lý dừng lại
- Seek: đọc từ bất kỳ offset nào, từ đầu, từ cuối, hoặc theo timestamp
- `assign()` có thể dùng committed offset nếu `group.id` được đặt
- Trộn `subscribe()` + `assign()` = hành vi không xác định — đừng làm điều đó
- Production: subscribe() (fault tolerance); assign() — testing, debugging, replay

**Các câu hỏi phụ thường gặp:**
- *Bạn có thể commit offset với assign() không?* — Có, nếu group.id được đặt, nhưng thủ công (commitSync).
- *Điều gì xảy ra khi seek đến một partition chưa được gán?* — IllegalStateException.
- *assign() có thấy các partition mới khi được thêm vào không?* — Không, cần gán lại định kỳ.
- *ConsumerRebalanceListener có hoạt động với assign() không?* — Không, không có rebalancing → không có callback.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "assign() cho xử lý production" — không có fault tolerance
- "assign() tự động rebalance" — hoàn toàn không có rebalancing
- "subscribe() và assign() có thể trộn với nhau" — hành vi không xác định
- "assign() tự động quản lý offset" — bạn hoàn toàn chịu trách nhiệm

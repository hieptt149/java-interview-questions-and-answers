# What Is the Difference Between handle(), exceptionally() and whenComplete()? (Sự khác biệt giữa handle(), exceptionally() và whenComplete() là gì)

## 🟢 Junior Level

Ba phương thức để xử lý lỗi trong CompletableFuture:

- **`exceptionally()`** — trả về một fallback khi lỗi (giống `catch`)
- **`handle()`** — xử lý cả thành công và lỗi (giống `try/catch` với return)
- **`whenComplete()`** — thực hiện một hành động khi hoàn thành mà không thay đổi kết quả (giống `finally`)

```java
// 1. exceptionally — fallback khi lỗi
CompletableFuture.supplyAsync(() -> {
    throw new RuntimeException("Error");
}).exceptionally(ex -> "default value");  // sẽ trả về "default value"

// 2. handle — kiểm soát toàn diện
CompletableFuture.supplyAsync(() -> {
    throw new RuntimeException("Error");
}).handle((result, ex) -> {
    if (ex != null) return "error occurred";
    return result;
});

// 3. whenComplete — quan sát, không thay đổi kết quả
CompletableFuture.supplyAsync(() -> "Hello")
    .whenComplete((result, ex) -> {
        if (ex != null) {
            System.err.println("Error: " + ex);
        } else {
            System.out.println("Result: " + result);
        }
    });
```

## 🟡 Middle Level

### So Sánh Chi Tiết

**exceptionally — chỉ khi lỗi:**
```java
fetchDataAsync()
    .exceptionally(ex -> {
        log.error("Fetch failed", ex);
        return "default";  // giá trị fallback
    });
```

**handle — luôn được gọi:**
```java
fetchDataAsync()
    .handle((result, ex) -> {
        if (ex != null) {
            log.error("Failed", ex);
            return "error";
        }
        return result.toUpperCase();  // có thể sửa đổi kết quả
    });
```

**whenComplete — side effect, không thay đổi kết quả:**
```java
fetchDataAsync()
    .whenComplete((result, ex) -> {
        // Không thay đổi kết quả — chỉ là side effect
        if (ex == null) {
            metrics.increment("success");
        } else {
            metrics.increment("failure");
        }
    })
    .thenApply(s -> s.toUpperCase());  // kết quả không thay đổi
```

### Bảng So Sánh

| Phương thức            | Có thể thay đổi kết quả? | Có thể thay đổi kiểu? | Hấp thụ lỗi?   | Khi nào được gọi?    |
| ----------------- | ------------------ | ---------------- | ---------------- | --------------- |
| **exceptionally** | ✅ Có             | ❌ Không            | ✅ Có           | Chỉ khi lỗi   |
| **whenComplete**  | ❌ Không              | ❌ Không            | ❌ Không            | Luôn luôn          |
| **handle**        | ✅ Có             | ✅ Có           | ✅ Có           | Luôn luôn          |

### whenComplete: Hành Vi Quan Trọng

Nếu bản thân `action` ném ra một ngoại lệ — ngoại lệ MỚI sẽ thay thế ngoại lệ gốc làm kết quả của stage. Ngoại lệ gốc sẽ bị mất (không được thêm vào như suppressed).

```java
cf.whenComplete((result, ex) -> {
    throw new RuntimeException("New error");  // sẽ thay thế ex gốc!
});
// Ngoại lệ gốc bị mất!
```

### Các Lỗi Thường Gặp

**1. Xử lý null trong handle:**
```java
cf.handle((result, ex) -> {
    // Khi thành công: ex == null, result != null
    // Khi lỗi: ex != null, result == null
    // Kiểm tra null là bắt buộc!
    if (ex != null) return fallback;
    return result.toUpperCase();
});
```

**2. exceptionally không được gọi khi thành công:**
```java
cf.exceptionally(ex -> "fallback")
  .thenAccept(s -> System.out.println(s));
// Nếu cf thành công — exceptionally bị bỏ qua, kết quả tiếp tục đi
```

## 🔴 Senior Level

### exceptionallyCompose (Java 12+)

Đây là "flatMap" cho việc xử lý lỗi. `exceptionally` thông thường buộc bạn trả về một object đã sẵn sàng, trong khi `exceptionallyCompose` cho phép bạn trả về **một CompletableFuture khác**.

```java
// "Nếu microservice chính bị lỗi, chuyển sang backup một cách bất đồng bộ"
cf.exceptionallyCompose(ex -> {
    if (isRetryable(ex)) {
        return retryOperation();  // CompletableFuture<T>
    }
    return CompletableFuture.failedFuture(ex);
});
```

### Ngữ Cảnh Thread

Cả ba phương thức đều thực thi trong cùng thread đã hoàn thành stage trước (trừ khi bạn dùng phiên bản `*Async`). Điều này có thể dẫn đến việc chặn các pool "xa lạ".

```java
// Nguy hiểm: thực thi trong thread đã hoàn thành CF
cf.whenComplete((r, ex) -> heavyOperation());

// An toàn: chuyển thread
cf.whenCompleteAsync((r, ex) -> heavyOperation(), executor);
```

### Khi Nào KHÔNG Nên Dùng handle

- Khi bạn chỉ cần xử lý lỗi — dùng `exceptionally` (ý định rõ ràng hơn)
- Khi bạn cần một side effect mà không thay đổi kết quả — `whenComplete`

```java
// ❌ handle khi exceptionally là đủ
cf.handle((r, ex) -> ex != null ? defaultValue : r);  // thừa thãi

// ✅ exceptionally — ý định rõ ràng hơn
cf.exceptionally(ex -> defaultValue);

// ❌ handle khi bạn chỉ cần một side effect
cf.handle((r, ex) -> { log.info("done"); return r; });  // thừa thãi

// ✅ whenComplete — không thay đổi kết quả
cf.whenComplete((r, ex) -> log.info("done"));
```

### Short-circuit

Nếu một `exceptionally` ở giữa một chuỗi dài trả về một kết quả, tất cả các lời gọi `thenApply` tiếp theo sẽ làm việc với kết quả này như thể không có lỗi nào xảy ra.

```java
cf.thenApply(s -> { throw new RuntimeException("Error"); })
  .exceptionally(ex -> "fallback")  // trả về "fallback"
  .thenApply(s -> s.toUpperCase());  // làm việc với "fallback"!
```

### Best Practices

```java
// ✅ exceptionally cho fallback
cf.exceptionally(ex -> defaultValue);

// ✅ handle cho kiểm soát toàn diện
cf.handle((result, ex) -> ex != null ? fallback : transform(result));

// ✅ whenComplete cho giám sát
cf.whenComplete((r, ex) -> metrics.record(r, ex));

// ✅ exceptionallyCompose cho retry (Java 12+)
cf.exceptionallyCompose(ex -> isRetryable(ex) ? retry() : failedFuture(ex));

// ❌ Bỏ qua lỗi
// ❌ Thao tác chặn trong handler
// ❌ handle khi exceptionally là đủ
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- exceptionally — chỉ khi lỗi, trả về fallback, kiểu không thay đổi
- handle — luôn được gọi, có thể thay đổi kiểu, hấp thụ lỗi
- whenComplete — luôn được gọi, KHÔNG thay đổi kết quả, KHÔNG hấp thụ lỗi
- handle = kiểm soát toàn diện, exceptionally = fallback sạch, whenComplete = giám sát
- exceptionallyCompose (Java 12+) — retry bất đồng bộ, trả về một CF khác

**Các câu hỏi phụ thường gặp:**
- **Điều gì xảy ra nếu whenComplete ném ra ngoại lệ?** — Ngoại lệ mới thay thế ngoại lệ gốc, ngoại lệ gốc bị mất
- **exceptionally có thể thay đổi kiểu không?** — Không, trả về cùng T. handle có thể thay đổi kiểu
- **Khi nào dùng exceptionallyCompose?** — Khi một lỗi cần khởi chạy một thao tác bất đồng bộ khác (retry, fallback service)
- **handle vs exceptionally — khi nào dùng cái nào?** — handle khi bạn cũng cần xử lý kết quả, exceptionally chỉ cho lỗi

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "whenComplete chặn lỗi" — nó chỉ quan sát, lỗi vẫn còn trong CF
- "handle và exceptionally giống nhau" — handle luôn được gọi, exceptionally chỉ khi lỗi
- "exceptionally có thể trả về một kiểu khác" — không, chỉ T -> T

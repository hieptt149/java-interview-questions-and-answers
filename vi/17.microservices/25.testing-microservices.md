# How to test microservices (Cách test microservices)

## 🟢 Junior Level

**Ba cấp độ testing:**

1. **Unit test** — test một class/phương thức duy nhất
2. **Integration test** — test tương tác với DB, các service bên ngoài
3. **Contract test** — xác minh khả năng tương thích API giữa các service

```java
// Unit test
@Test
void testOrderCalculation() {
    OrderService service = new OrderService();
    Order order = service.createOrder(List.of(item1, item2));
    assertEquals(100, order.total());
}
```

## 🟡 Middle Level

### Integration Test

```java
@SpringBootTest
@Testcontainers
class OrderServiceIntegrationTest {

    @Container
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:15");

    @Test
    void testCreateOrder() {
        Order order = orderService.createOrder(request);
        assertNotNull(order.getId());
    }
}
```

### Contract Test (Pact)

```java
@Provider("Order Service")
@Consumer("User Service")
public class OrderServiceContractTest {
    @TestTemplate
    void testGetUserOrders(PactVerificationContext context) {
        // Interaction = một cặp request-response duy nhất giữa consumer và provider.
        // Pact xác minh rằng provider có thể xử lý request mà consumer mong đợi.
        // Contract test bắt các breaking change trong API trước khi chúng lên production.
        context.verifyInteraction();
    }
}
```

## 🔴 Senior Level

### Test Pyramid

```
     /  E2E    \      — ít (10%)
    / Integration \   — trung bình (20%)
   /    Unit       \  — nhiều (70%)
```

### Consumer-Driven Contracts

```
User Service (consumer) định nghĩa contract → Order Service (provider) xác minh
```

### Kinh Nghiệm Production

**Testcontainers:**
```java
@Testcontainers
class UserRepositoryTest {
    @Container
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:15");

    // @DynamicPropertySource (Spring Boot 2.2.6+) — truyền động các port của container
    // vào Spring Environment trước khi khởi tạo context.
    @DynamicPropertySource
    static void configureProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
    }
}
```

### Best Practices

```
✅ Test pyramid
✅ Testcontainers cho integration
✅ Contract test cho API
✅ Mock các service bên ngoài
✅ Pipeline CI/CD với test

❌ Chỉ có test E2E
❌ Test với các service thật
❌ Không có contract test
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Test pyramid: Unit (70%) → Integration (20%) → E2E (10%)
- Unit test — một class/phương thức duy nhất, nhanh, cô lập
- Integration test — tương tác với DB, các service bên ngoài (Testcontainers)
- Contract test (Pact) — xác minh khả năng tương thích API giữa các service, bắt các breaking change
- Testcontainers — container Docker cho integration test (PostgreSQL, Kafka)
- Consumer-driven contract: consumer định nghĩa contract, provider xác minh
- Mock các service bên ngoài — không test với các service thật (chậm, không ổn định)

**Các câu hỏi phụ thường gặp:**
- **Tại sao cần contract test?** Bắt các breaking change trong API trước khi lên production — consumer mong đợi X, provider phải cung cấp X.
- **Testcontainers vs mock?** Testcontainers = service thật trong Docker (đáng tin cậy hơn), mock = stub (nhanh hơn).
- **Tại sao không chỉ dùng E2E?** E2E chậm, dễ vỡ, khó debug. Unit test nhanh hơn, ổn định hơn.
- **@DynamicPropertySource làm gì?** Truyền động các port của container vào Spring Environment trước khi khởi tạo context.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Chỉ cần test E2E là đủ" — không, chậm, dễ vỡ, khó debug
- "Test với Payment Service thật" — không, chậm (100-500ms) và không ổn định
- "Không cần contract test, chúng ta có Swagger" — Swagger mô tả API, contract test xác minh khả năng tương thích
- "Unit test = integration test" — không, unit = một class duy nhất, integration = tương tác

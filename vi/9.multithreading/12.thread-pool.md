# What is Thread Pool? (Thread Pool là gì?)

---

## Junior Level

### Hiểu biết cơ bản

Một **Thread Pool** là một tập các thread được tạo sẵn, được tái sử dụng để thực thi các tác vụ (task).

**Tại sao:** tạo một thread tốn ~1MB bộ nhớ (stack) và 1-10ms thời gian (lời gọi OS + đăng ký với JVM). Nếu bạn có 10.000 tác vụ ngắn — tạo 10.000 thread sẽ giết server. Thread Pool giải quyết điều này bằng cách tái sử dụng một số lượng thread giới hạn. Thay vì tạo một thread mới cho mỗi tác vụ, ta lấy một thread đã tồn tại từ pool.

### Ví dụ minh họa

Hãy tưởng tượng taxi:
- **Không có pool:** Với mỗi hành khách, mua một xe mới, vứt bỏ sau chuyến đi
- **Có pool:** 10 taxi phục vụ tất cả hành khách theo lượt

### Tại sao ta cần một thread pool?

```java
// XẤU: tạo một thread cho mỗi tác vụ
for (int i = 0; i < 1000; i++) {
    new Thread(() -> process(i)).start();
    // Tạo thread = ~1MB bộ nhớ + thời gian tạo
    // 1000 thread = ~1GB bộ nhớ!
}

// TỐT: tái sử dụng các thread
ExecutorService pool = Executors.newFixedThreadPool(10);
for (int i = 0; i < 1000; i++) {
    pool.submit(() -> process(i));
    // 10 thread xử lý 1000 tác vụ
}
```

### Ưu điểm

| Ưu điểm                | Mô tả                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **Hiệu năng**          | Không lãng phí thời gian tạo thread (~1-10ms = lời gọi OS để tạo thread + cấp phát stack + đăng ký với JVM)          |
| **Bộ nhớ**             | Mỗi thread = ~1MB stack, pool tiết kiệm bộ nhớ                                                                     |
| **Quản lý**            | Giới hạn số lượng thread tối đa                                                                                    |
| **Giám sát**           | Dễ theo dõi hoạt động hơn                                                                                          |

### Ví dụ đơn giản

```java
// Tạo một pool 5 thread
ExecutorService executor = Executors.newFixedThreadPool(5);

// Submit các tác vụ
for (int i = 0; i < 20; i++) {
    executor.submit(() -> {
        System.out.println("Task executed by thread: " +
            Thread.currentThread().getName());
    });
}

// Tắt pool
executor.shutdown(); // Ngừng nhận tác vụ
executor.awaitTermination(60, TimeUnit.SECONDS); // Chờ hoàn thành
```

### Tạo Pool thủ công

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    5,              // corePoolSize — các thread luôn sống
    10,             // maximumPoolSize — số thread tối đa
    60,             // keepAliveTime — thời gian sống của các thread dư
    TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(100) // hàng đợi tác vụ
);
```

## Middle Level

### Giải phẫu ThreadPoolExecutor

```java
public ThreadPoolExecutor(
    int corePoolSize,              // 1. Số lượng thread tối thiểu
    int maximumPoolSize,           // 2. Số lượng thread tối đa
    long keepAliveTime,            // 3. Thời gian sống của các thread "dư"
    TimeUnit unit,                 // 4. Đơn vị thời gian
    BlockingQueue<Runnable> workQueue, // 5. Hàng đợi tác vụ
    ThreadFactory threadFactory,   // 6. Factory để tạo thread
    RejectedExecutionHandler handler // 7. Handler khi tràn
)
```

### Thuật toán thêm tác vụ (THEN CHỐT!)

```
Tác vụ mới
    │
    ▼
Số thread < corePoolSize?
    │ có                    │ không
    ▼                       ▼
Tạo thread            Hàng đợi đầy?
mới                       │ có            │ không
    │                     ▼               ▼
    ▼             Số thread < max?   Thêm vào hàng đợi
Thực thi             │ có     │ không
                     ▼        ▼
              Thread mới   RejectedExecutionHandler
```

**Quan trọng:** Một thread được tạo vượt quá `corePoolSize` CHỈ khi hàng đợi ĐẦY.

### Các loại hàng đợi

| Hàng đợi                | Đặc điểm                     | Khi nào dùng                   |
| ----------------------- | --------------------------- | ------------------------------ |
| `LinkedBlockingQueue`   | Không giới hạn (mặc định)    | Khi bạn biết tác vụ ít         |
| `ArrayBlockingQueue`    | Kích thước cố định           | **Production** — bảo vệ khỏi OOM |
| `SynchronousQueue`      | Sức chứa = 0                 | Mỗi tác vụ → thread mới        |
| `PriorityBlockingQueue` | Hàng đợi ưu tiên             | Các tác vụ quan trọng đi trước |

### Các chiến lược RejectedExecutionHandler

```java
// 1. AbortPolicy (mặc định) — ném exception
executor.setRejectedExecutionHandler(new ThreadPoolExecutor.AbortPolicy());
// → RejectedExecutionException

// 2. CallerRunsPolicy — thực thi trong thread đã submit
executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
// Tạo **back-pressure** — vì tác vụ chạy trong thread đã submit, nó không thể submit tác vụ mới cho tới khi pool giải phóng. Điều này tự động làm chậm nguồn tác vụ.

// 3. DiscardPolicy — âm thầm bỏ qua
executor.setRejectedExecutionHandler(new ThreadPoolExecutor.DiscardPolicy());

// 4. DiscardOldestPolicy — xóa tác vụ cũ nhất khỏi hàng đợi
executor.setRejectedExecutionHandler(new ThreadPoolExecutor.DiscardOldestPolicy());
```

### ThreadFactory — Đặt tên cho Thread

```java
ThreadFactory factory = new ThreadFactory() {
    private int count = 1;
    @Override
    public Thread newThread(Runnable r) {
        Thread t = new Thread(r);
        t.setName("my-pool-worker-" + count++);
        t.setDaemon(true); // Daemon — không ngăn JVM tắt
        return t;
    }
};

ThreadPoolExecutor executor = new ThreadPoolExecutor(
    5, 10, 60, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(100),
    factory // Factory tùy chỉnh
);
```

## Senior Level

### Bên trong: Trạng thái nội bộ

ThreadPoolExecutor lưu trạng thái trong một `AtomicInteger ctl` duy nhất:

```java
private final AtomicInteger ctl = new AtomicInteger(ctlOf(RUNNING, 0));
// 3 bit cao — trạng thái pool
// 29 bit thấp — số lượng thread
```

#### Vòng đời Pool

| Trạng thái     | Nhận tác vụ? | Thực thi tác vụ? | Mô tả                                   |
| -------------- | ------------ | ---------------- | --------------------------------------- |
| **RUNNING**    | Có           | Có               | Hoạt động bình thường                   |
| **SHUTDOWN**   | Không        | Có               | shutdown() — vét cạn hàng đợi           |
| **STOP**       | Không        | Không            | shutdownNow() — interrupt các tác vụ đang chạy |
| **TIDYING**    | Không        | Không            | Mọi tác vụ hoàn thành, các thread đã dừng |
| **TERMINATED** | Không        | Không            | terminated() đã được thực thi           |

### Chọn kích thước Pool

#### Tác vụ CPU-bound (tính toán)

```
Số thread = Số lõi + 1 (quy tắc thực nghiệm cho các tác vụ CPU-bound; "+1" bù cho các page fault thỉnh thoảng. Trên CPU hyperthreaded, đếm số lõi logic. Luôn đo trên phần cứng của bạn).
```

```java
int cores = Runtime.getRuntime().availableProcessors();
ExecutorService cpuPool = new ThreadPoolExecutor(
    cores + 1, cores + 1,
    0L, TimeUnit.MILLISECONDS,
    new ArrayBlockingQueue<>(1000)
);
```

#### Tác vụ I/O-bound (DB, API, file)

```
Số thread = Số lõi * (1 + Thời gian chờ / Thời gian phục vụ)
```

```java
int cores = Runtime.getRuntime().availableProcessors();
// Nếu 90% thời gian chờ (DB, API):
int ioThreads = cores * (1 + 9) = cores * 10;
// 90% thời gian chờ I/O, 10% tính toán → W/S = 90/10 = 9
// W/S được ước lượng bằng profiler: nếu request DB mất 100ms, 90ms là chờ → W/S = 9
// Với CPU 8 lõi: ~80 thread
```

### Vấn đề: ThreadLocal Leak (rò rỉ)

```java
// XẤU: ThreadLocal không được dọn
ThreadLocal<UserContext> context = new ThreadLocal<>();

executor.submit(() -> {
    context.set(new UserContext("user123"));
    // Tác vụ hoàn thành, nhưng thread quay lại pool!
    // Tác vụ tiếp theo sẽ thấy user123!
});

// TỐT: luôn dọn
executor.submit(() -> {
    try {
        context.set(new UserContext("user123"));
        process();
    } finally {
        context.remove(); // BẮT BUỘC!
    }
});
```

### Graceful Shutdown

```java
public void shutdown(ExecutorService executor) {
    executor.shutdown(); // 1. Ngừng nhận
    try {
        if (!executor.awaitTermination(60, TimeUnit.SECONDS)) { // 2. Chờ
            executor.shutdownNow(); // 3. Ép buộc
            if (!executor.awaitTermination(30, TimeUnit.SECONDS)) {
                System.err.println("Pool did not terminate");
            }
        }
    } catch (InterruptedException e) {
        executor.shutdownNow();
        Thread.currentThread().interrupt();
    }
}
```

### Best Practices

1. **Luôn giới hạn hàng đợi** — `ArrayBlockingQueue`, không phải `LinkedBlockingQueue`
2. **Dùng CallerRunsPolicy** — cho back-pressure khi quá tải
3. **Đặt tên thread** — ThreadFactory tùy chỉnh để debug
4. **Dọn ThreadLocal** — trong block finally
5. **Đừng tạo pool bên trong một method** — đó là rò rỉ thread
6. **Giám sát queue.size()** — hàng đợi tăng dần = suy giảm
7. **Shutdown đúng cách** — shutdown → awaitTermination → shutdownNow
8. **Kích thước pool** — CPU-bound: N+1, I/O-bound: N * (1 + W/S)

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Thread Pool — một tập các thread tái sử dụng; tạo một thread mới = ~1MB stack + 1-10ms
- Thuật toán thêm tác vụ: đầu tiên corePoolSize → rồi hàng đợi → rồi lên tới maximumPoolSize → rồi rejection
- Một thread được tạo vượt quá corePoolSize CHỈ khi hàng đợi ĐẦY (đây là một câu hỏi phỏng vấn thường gặp)
- 4 RejectedExecutionHandler: AbortPolicy (mặc định), CallerRunsPolicy (back-pressure), DiscardPolicy, DiscardOldestPolicy
- Pool CPU-bound: N+1 thread; I/O-bound: N * (1 + Thời gian chờ/phục vụ) — công thức của Little
- ThreadPoolExecutor lưu trạng thái trong một AtomicInteger ctl duy nhất (3 bit — status, 29 — số lượng thread)
- Vòng đời: RUNNING → SHUTDOWN → STOP → TIDYING → TERMINATED
- ThreadLocal phải được dọn trong finally — nếu không sẽ rò rỉ giữa các tác vụ trong pool

**Các câu hỏi phụ thường gặp:**
- **Tại sao hàng đợi đầy → tạo thread, không phải ngược lại?** — Để đầu tiên dùng hàng đợi rẻ, và chỉ scale thread khi quá tải
- **LinkedBlockingQueue khác ArrayBlockingQueue như thế nào?** — Cái đầu không giới hạn (rủi ro OOM), cái sau có giới hạn (an toàn cho production)
- **CallerRunsPolicy làm gì?** — Thực thi tác vụ trong thread đã submit, tạo back-pressure (bên submit chậm lại)
- **Tại sao ThreadLocal rò rỉ trong một pool?** — Thread quay lại pool với một ThreadLocal chưa dọn, tác vụ tiếp theo thấy dữ liệu của người khác

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi tạo một pool bên trong một method cho mỗi thao tác" — rò rỉ thread, pool nên là một singleton
- "Tôi dùng LinkedBlockingQueue trong production" — hàng đợi không giới hạn = rủi ro OOM
- "shutdownNow() lập tức dừng mọi thread" — nó chỉ gửi interrupt(), các tác vụ phải tự xử lý

# What is distributed tracing (Distributed tracing là gì)

## 🟢 Junior Level

**Distributed tracing** là việc theo dõi **một request duy nhất** qua tất cả các microservice mà nó đi qua.

```
Request: GET /orders/123

Trace ID: abc-123
  Span 1: API Gateway (10ms)
    Span 2: Order Service (50ms)
      Span 3: User Service (20ms)
      Span 4: Payment Service (30ms)
```

**Tại sao:** Hiểu được vấn đề (latency, lỗi) xảy ra ở đâu trong một chuỗi các service.

Trace ID được truyền qua HTTP header (W3C Trace Context: traceparent)
hoặc qua message header (Kafka header). Mỗi service thêm span ID riêng của nó.

## 🟡 Middle Level

### Trace, Span, TraceId

```
Trace — toàn bộ đường đi của request (traceId: abc-123)
Span — một call duy nhất trong chuỗi (spanId: span-1, span-2...)
TraceId — định danh cho toàn bộ trace
ParentSpanId — liên kết đến span trước đó
```

### Jaeger / Zipkin

```java
// Spring Cloud Sleuth + Zipkin
// ⚠️ Spring Cloud Sleuth đã deprecated trong Spring Boot 3.0+.
// Hãy dùng Micrometer Tracing với một backend (Zipkin, Jaeger).
// Tự động thêm traceId vào log và header

@RestController
public class OrderController {
    private final RestTemplate restTemplate;

    @GetMapping("/orders/{id}")
    public Order getOrder(@PathVariable Long id) {
        // Trace ID được tự động thêm vào HTTP header `traceparent` (W3C Trace Context).
        return restTemplate.getForObject(
            "http://order-service/orders/" + id, Order.class);
    }
}
```

### Các Lỗi Thường Gặp

1. **Mất traceId:**
```
Call bất đồng bộ → traceId không được truyền
Giải pháp: dùng trace context propagation
```

### Khi Nào KHÔNG Cần Distributed Tracing

- **2-3 service** — log với correlation ID là đủ
- **Sampling 100% chấp nhận được** với traffic thấp — không cần sampling

## 🔴 Senior Level

### OpenTelemetry

```java
// OpenTelemetry — chuẩn cho tracing
Tracer tracer = GlobalOpenTelemetry.getTracer("my-service");

Span span = tracer.spanBuilder("processOrder")
    .setSpanKind(SpanKind.SERVER)
    .startSpan();

try (Scope scope = span.makeCurrent()) {
    span.setAttribute("order.id", orderId);
    processOrder(orderId);
    span.setStatus(StatusCode.OK);
} catch (Exception e) {
    span.setStatus(StatusCode.ERROR);
    span.recordException(e);
    throw e;
} finally {
    span.end();
}
```

### Kinh Nghiệm Production

**Log correlation:**
```
Log với traceId:
[traceId=abc-123] [spanId=span-1] OrderService - Processing order 123
[traceId=abc-123] [spanId=span-2] UserService - Fetching user 456
[traceId=abc-123] [spanId=span-3] PaymentService - Charging payment
```

### Best Practices

```
✅ TraceId trong tất cả các log
✅ Sampling cho traffic cao
✅ Span cho tất cả các call bên ngoài
✅ Tag cho các metric nghiệp vụ

❌ Không có tracing trong production
❌ Sampling 100% cho traffic cao
❌ Không có traceId trong log
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Distributed tracing — theo dõi một request duy nhất qua tất cả các microservice
- Trace = toàn bộ đường đi của request (traceId), Span = một call duy nhất trong chuỗi (spanId)
- TraceId được truyền qua HTTP header (W3C Trace Context: traceparent) hoặc message header
- Jaeger / Zipkin — backend để lưu trữ và trực quan hóa trace
- OpenTelemetry — chuẩn tracing, thay thế OpenTracing/OpenCensus
- Sampling cho traffic cao (không phải 100%!) — tiết kiệm lưu trữ
- Log correlation: traceId trong mỗi log — liên kết log với trace
- KHÔNG cần cho 2-3 service — log với correlation ID là đủ

**Các câu hỏi phụ thường gặp:**
- **Trace vs Span?** Trace = toàn bộ đường đi của request qua tất cả các service, Span = một call duy nhất (một service) trong trace.
- **Tại sao cần sampling?** Sampling 100% cho traffic cao = terabyte dữ liệu. 1-10% là đủ để phân tích.
- **Trạng thái của Spring Cloud Sleuth?** Đã deprecated trong Spring Boot 3.0+ — hãy dùng Micrometer Tracing.
- **Trace context propagation là gì?** Truyền traceId/spanId qua HTTP header hoặc message header giữa các service.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Sampling 100% cho production" — không, terabyte dữ liệu ở traffic cao
- "Tracing = logging" — không, tracing = cấu trúc request, log = chi tiết
- "Không cần traceId trong log" — không có nó, bạn không thể liên kết log với trace
- "Distributed tracing luôn cần thiết" — không, với 2-3 service, correlation ID là đủ

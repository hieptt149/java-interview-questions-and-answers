# What are anyMatch(), allMatch(), noneMatch() operations? (Các thao tác anyMatch(), allMatch(), noneMatch() là gì?)

## 🟢 Junior Level

Ba thao tác terminal kiểm tra các phần tử theo một predicate và trả về `boolean`:

**`anyMatch(Predicate)`** — trả về `true` nếu ÍT NHẤT MỘT phần tử thỏa mãn điều kiện:
```java
boolean hasAdult = persons.stream()
    .anyMatch(p -> p.getAge() >= 18);
```

**`allMatch(Predicate)`** — trả về `true` nếu TẤT CẢ các phần tử thỏa mãn điều kiện:
```java
boolean allAdults = persons.stream()
    .allMatch(p -> p.getAge() >= 18);
```

**`noneMatch(Predicate)`** — trả về `true` nếu KHÔNG phần tử nào thỏa mãn điều kiện:
```java
boolean noMinors = persons.stream()
    .noneMatch(p -> p.getAge() < 18);
```

Cả ba đều dùng **short-circuiting** — chúng dừng ngay khi kết quả trở nên rõ ràng.

anyMatch: dừng ở khớp ĐẦU TIÊN (true). allMatch: dừng ở phần tử KHÔNG khớp ĐẦU TIÊN (false). noneMatch: dừng ở khớp ĐẦU TIÊN (false).

## 🟡 Middle Level

### Thuật toán thực thi

Tương đương một vòng lặp với thoát sớm:
```java
for (T element : source) {
    if (predicate.test(element)) {
        return true; // cho anyMatch
    }
}
```

Nhờ tính lười, các phần tử được yêu cầu từng cái một. Khi kết quả rõ ràng, pipeline dừng.

### So sánh

| Thao tác      | Dừng ở          | Stream.empty()  |
| ------------- | --------------- | --------------- |
| `anyMatch`    | `true` đầu tiên | `false`         |
| `allMatch`    | `false` đầu tiên | `true`         |
| `noneMatch`   | `true` đầu tiên | `true`          |

```
// Stream rỗng:
// anyMatch() → false (không có phần tử, không có khớp)
// allMatch() → true (vacuous truth — chân lý rỗng, không có phản ví dụ)
// noneMatch() → true (không có phần tử, do đó không có khớp)
```

### Vacuous Truth (chân lý rỗng)

Một câu hỏi mẹo phỏng vấn kinh điển:
- `anyMatch` trên một stream rỗng → `false` (không tìm thấy cái nào)
- `allMatch` trên một stream rỗng → `true` (điều kiện đúng — không có phần tử nào tồn tại)
- `noneMatch` trên một stream rỗng → `true` (không có cái nào vi phạm nó)

## 🔴 Senior Level

### Khi nào KHÔNG nên dùng các thao tác match

1. **Bạn cần chính phần tử đó** — dùng `findFirst()` / `findAny()`
2. **Bạn cần biết có bao nhiêu** — dùng `filter().count()`
3. **Điều kiện phức tạp** — nếu Predicate phức tạp, `filter()` + một tên phương thức dễ đọc thì tốt hơn

### Tính song song qua ShortCircuitTask

Trong chế độ parallel:
- Nhiều thread kiểm tra các phần khác nhau của dữ liệu
- Khi một phần tử "short-circuiting" được tìm thấy, một tín hiệu `Cancel` được gửi tới tất cả các tác vụ trong ForkJoinPool
- `anyMatch` trong một parallel stream cho một mức tăng khổng lồ trên dữ liệu lớn

### Ngữ cảnh Highload

**Non-blocking:** Tuyệt vời cho các kiểm tra nhanh trong các hệ thống reactive.

**Interference:** Nhạy cảm với việc sửa đổi nguồn trong lúc thực thi → `ConcurrentModificationException`.

**Chi phí Predicate:** Nếu predicate làm việc nặng (truy vấn Redis), short-circuiting là đồng minh chính để tối thiểu hóa độ trễ.

### Chẩn đoán

**Early Exit Logging:** Thêm `peek()` trước matcher — bạn sẽ chỉ thấy các phần tử thực sự được kiểm tra.

**Unit Testing:** Luôn test trên các collection rỗng, tính đến logic `allMatch`/`noneMatch`, để tránh các bug "vacuous truth".

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `anyMatch` — true nếu ít nhất một phần tử khớp (dừng ở true đầu tiên)
- `allMatch` — true nếu TẤT CẢ các phần tử khớp (dừng ở false đầu tiên)
- `noneMatch` — true nếu KHÔNG phần tử nào khớp (dừng ở true đầu tiên)
- Cả ba đều là các thao tác terminal có short-circuiting
- Stream rỗng: anyMatch → false, allMatch → true (vacuous truth), noneMatch → true
- Trong chế độ parallel, anyMatch cho một mức tăng khổng lồ trên dữ liệu lớn
- Nếu bạn cần chính phần tử đó — dùng findFirst/findAny thay vì các thao tác match

**Các câu hỏi phụ thường gặp:**
- **Tại sao allMatch trên một stream rỗng trả về true?** — Vacuous truth: không có phản ví dụ, do đó điều kiện đúng cho tất cả các phần tử (không tồn tại).
- **anyMatch khác filter().findFirst() như thế nào?** — anyMatch trả về một boolean và không tạo một Optional — ít overhead hơn nếu bạn không cần phần tử.
- **Short-circuiting có hoạt động trong parallelStream không?** — Có, nhưng kém hiệu quả hơn — các thread không nhận được tín hiệu Cancel ngay lập tức.
- **Khi nào các thao tác match là một lựa chọn tồi?** — Khi bạn cần chính phần tử đó, khi bạn cần một số đếm, hoặc khi predicate quá phức tạp cho tính dễ đọc.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "anyMatch trên một stream rỗng sẽ trả về true" — sai, nó trả về false
- "allMatch xử lý tất cả các phần tử" — sai, nó dừng ở phần tử không khớp đầu tiên
- "các thao tác match trả về một phần tử" — sai, chúng chỉ trả về một boolean
- "noneMatch trên một stream rỗng sẽ trả về false" — sai, nó trả về true (vacuous truth)

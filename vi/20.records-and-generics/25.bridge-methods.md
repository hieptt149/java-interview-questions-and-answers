# What Are Bridge Methods and Why Are They Needed? (Bridge method là gì và tại sao chúng cần thiết)

## 🟢 Junior Level

**Bridge method** — một phương thức đặc biệt mà trình biên dịch Java tạo ra **tự động** để giữ tính đa hình khi làm việc với generics.

Điều này xảy ra do **type erasure** — khi kiểu generic bị xóa, chữ ký phương thức thay đổi.

```java
public class Node<T> {
    private T data;
    public void setData(T data) { this.data = data; }
    public T getData() { return data; }
}

public class StringNode extends Node<String> {
    @Override
    public void setData(String data) { super.setData(data); }
    @Override
    public String getData() { return super.getData(); }
}
```

Sau type erasure, `Node<String>.setData(String)` trở thành `setData(Object)`, nhưng `StringNode.setData(String)` vẫn là `setData(String)`. Đây là **hai phương thức khác nhau**!

Để tính đa hình hoạt động, trình biên dịch tạo một **bridge method**:
```java
// Được thêm tự động vào StringNode
public void setData(Object data) {
    setData((String) data);  // gọi phương thức gốc
}
```

## 🟡 Middle Level

### Tại Sao Cần Bridge Method

**Vấn đề:**
```java
// Trước type erasure:
Node<String> node = new StringNode();
node.setData("Hello");  // nên gọi StringNode.setData(String)

// Sau type erasure:
Node node = new StringNode();
node.setData("Hello");  // Node.setData(Object) — nhưng StringNode chỉ có setData(String)!
```

**Giải pháp — bridge method:**
```java
class StringNode extends Node {
    // Phương thức gốc
    public void setData(String data) { /* ... */ }

    // Bridge method (được trình biên dịch tạo)
    public void setData(Object data) {
        setData((String) data);  // ủy quyền cho phương thức gốc
    }
}
```

### Cách Xem Bridge Method

**Qua reflection:**
```java
for (Method m : StringNode.class.getDeclaredMethods()) {
    System.out.println(m.getName() + " " +
        Arrays.toString(m.getParameterTypes()) +
        " bridge=" + m.isBridge());
}

// Kết quả:
// setData [class java.lang.String] bridge=false
// setData [class java.lang.Object] bridge=true
```

**Qua javap:**
```bash
javap -p StringNode.class
```

### Các Lỗi Thường Gặp

1. **Không hiểu tại sao một phương thức được gọi:**
```java
StringNode node = new StringNode();
node.setData(new Object());  // ClassCastException!

// Bridge method được gọi -> cast sang String -> ngoại lệ
```

2. **Annotation trên bridge method:**
```java
public class StringNode extends Node<String> {
    @Override
    @MyAnnotation  // ❌ sẽ không xuất hiện trên bridge method
    public void setData(String data) { }
}
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Đặc tả JLS:**
```
JLS 15.12.4.5:
- Khi override một phương thức với chữ ký khác (sau erasure)
- Trình biên dịch tạo một bridge method với chữ ký của class cha
- Bridge method ủy quyền cho phương thức gốc với một cast
```

**Desugaring:**
```java
// Source code
public class Node<T> {
    public T getData() { return data; }
    public void setData(T data) { this.data = data; }
}

public class StringNode extends Node<String> {
    @Override
    public String getData() { return super.getData(); }
    @Override
    public void setData(String data) { super.setData(data); }
}

// Sau khi biên dịch:
class Node {
    public Object getData() { return data; }
    public void setData(Object data) { this.data = data; }
}

class StringNode extends Node {
    public String getData() { return (String) super.getData(); }

    // Bridge method cho getData
    public Object getData() { return getData(); }

    public void setData(String data) { super.setData(data); }

    // Bridge method cho setData
    public void setData(Object data) { setData((String) data); }
}
```

### Đánh Đổi Kiến Trúc

**Bridge method:**

| Ưu điểm                               | Nhược điểm                     |
| ---------------------------------- | ------------------------ |
| Giữ tính đa hình              | Phương thức bổ sung       |
| Trong suốt với developer           | Gây nhầm lẫn trong stack trace |
| Cho phép kiểu trả về covariant       | Annotation không được kế thừa|

### Edge Cases

**1. Kiểu trả về covariant:**
```java
public class Parent {
    public Number getValue() { return 0; }
}

public class Child extends Parent {
    @Override
    public Integer getValue() { return 0; }
}

// Bridge method trong Child:
// public Number getValue() { return getValue(); }  // ủy quyền cho phiên bản Integer

// Bridge trả về Number, gọi Integer getValue().
// Auto-boxing được xử lý riêng — Integer đã là một object.
```

**2. Đa kế thừa:**
```java
// Java KHÔNG cho phép triển khai hai interface với cùng chữ ký
// nhưng kiểu trả về khác nhau. Trình biên dịch từ chối điều này ở tầng source code.
// Bridge method chỉ được sinh cho kiểu trả về covariant.
```

**3. Phương thức generic:**
```java
public class Util {
    public static <T> T identity(T t) { return t; }
}

// Khi được gọi với các kiểu khác nhau — một phương thức sau erasure
Util.identity("Hello");  // T = String
Util.identity(42);       // T = Integer
// Cả hai đều gọi identity(Object)
```

**4. Cách giải quyết annotation:**
```java
// Annotation không xuất hiện trên bridge method
// Giải pháp: dùng meta-annotation @Inherited hoặc reflection
// kiểm tra isBridge() và tìm phương thức gốc.
```

### Hiệu Năng

```
Overhead của bridge method:
- Một lời gọi bổ sung (ủy quyền)
- JIT inline bridge method
- Overhead: ~0-1 ns (thực tế bằng không)

Trong production: không đáng kể
```

### Kinh Nghiệm Production

**Ví dụ từ JDK:**
```java
// Collections — bridge method cho kiểu trả về covariant
public class ArrayList<E> extends AbstractList<E> {
    @Override
    public Object clone() { return super.clone(); }
    // Bridge: public Object clone() từ Object
}

// Enum — bridge cho compareTo
public abstract class Enum<E extends Enum<E>> implements Comparable<E> {
    public final int compareTo(E o) { return ordinal - o.ordinal; }
    // Bridge: public int compareTo(Object o) { return compareTo((E) o); }
}
```

**Reflection với bridge method:**
```java

for (Method m : methods) {

        System.out.println("Original: " + original);
    }
}
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Bridge method — phương thức tổng hợp được trình biên dịch tạo để giữ tính đa hình
- Lý do: type erasure thay đổi chữ ký phương thức, phá vỡ override
- Bridge method ủy quyền cho phương thức gốc với một cast tham số
- Có thể thấy qua reflection: `method.isBridge()` hoặc qua `javap -p`
- Annotation KHÔNG xuất hiện trên bridge method — cần thêm vào cả hai phương thức
- Overhead không đáng kể: JIT inline bridge method (~0-1 ns)

**Các câu hỏi phụ thường gặp:**
- **Tại sao cần bridge method?** — Giữ tính đa hình sau type erasure (chữ ký phương thức cha != con)
- **Cách xem bridge method?** — `javap -p ClassName` hoặc `method.isBridge()` qua reflection
- **Bridge method có thể gây ClassCastException không?** — Có, nếu được gọi với sai kiểu
- **Annotation có hoạt động trên bridge method không?** — Không, chỉ trên phương thức gốc

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Bridge method là phương thức do developer viết" — Chúng được trình biên dịch tự động tạo
- ❌ "Bridge method thêm overhead đáng kể" — JIT inline chúng, overhead ~0-1 ns
- ❌ "Annotation tự động xuất hiện trên bridge method" — Không, cần meta-annotation hoặc xử lý thủ công
- ❌ "Bridge method là một lỗi của Java" — Đây là thiết kế có chủ đích để tương thích với type erasure

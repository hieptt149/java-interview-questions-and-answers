# What is Collections.unmodifiableList()? (Collections.unmodifiableList() là gì?)

## 🟢 Junior Level

**unmodifiableList** — một lớp bọc **cấm sửa đổi** list.

```java
List<String> list = new ArrayList<>(List.of("A", "B"));
List<String> unmod = Collections.unmodifiableList(list);

unmod.get(0);       // ✅ OK → "A"
unmod.add("C");     // ❌ UnsupportedOperationException!
```

**QUAN TRỌNG:** đây là một **view**, không phải một bản sao!
```java
list.add("C");      // Đã sửa đổi bản gốc
unmod.get(2);       // → "C" (thay đổi nhìn thấy được!)
```

## 🟡 Middle Level

### View so với Immutable

```java
// View (unmodifiableList):
List<String> view = Collections.unmodifiableList(original);
original.add("X");  // Thay đổi nhìn thấy được trong view!

// Immutable (List.of):
List<String> immutable = List.of("A", "B");
// → Không thể được sửa đổi BỞI BẤT KỲ THỨ GÌ
// → Không có kết nối với bản gốc
```

**unmodifiableCollection** trả về một `Collection` (không có `get(int)`, `subList`). **unmodifiableList** trả về một `List` (giữ nguyên truy cập theo index). Hãy dùng `unmodifiableList` khi code gọi cần các phương thức của List.

### Khi nào dùng

```java
// ✅ Bảo vệ trạng thái nội bộ
public class UserService {
    private List<User> users = new ArrayList<>();

    public List<User> getUsers() {
        return Collections.unmodifiableList(users);
        // Client không thể sửa đổi list nội bộ!
    }
}

// ✅ Truy cập chỉ đọc
public void printAll(List<String> list) {
    List<String> readOnly = Collections.unmodifiableList(list);
    // Đảm bảo: phương thức sẽ không sửa đổi list
}
```

### Không bảo vệ các đối tượng bên trong

```java
List<User> users = Collections.unmodifiableList(list);
users.get(0).setName("Hacker");  // ✅ Có thể!
// → Lớp bọc bảo vệ cấu trúc của list, không phải các đối tượng!
```

Lớp bọc chỉ bảo vệ cấu trúc của list (thêm/xóa phần tử), không phải bản thân các đối tượng. Nếu cần tính bất biến sâu (deep immutability) — hãy làm cho User bất biến (các trường final, không có setter) hoặc dùng deep copy khi bọc.

## 🔴 Senior Level

### Khi nào KHÔNG dùng unmodifiableList

1. **Cần tính bất biến thực sự** — hãy dùng `List.copyOf()` (Java 10+)
2. **Cần bảo vệ khỏi reflection** — unmodifiableList dễ bị tấn công
3. **Collection sẽ bị sửa đổi từ một luồng khác** — bản gốc cần đồng bộ hóa

### Giữ nguyên RandomAccess

```java
// ArrayList implements RandomAccess
// UnmodifiableRandomAccessList cũng vậy!
// → binarySearch hoạt động tối ưu

// LinkedList KHÔNG phải RandomAccess
// UnmodifiableList cũng KHÔNG phải RandomAccess
```

### List.copyOf (Java 10+)

```java
// Bản sao → không có kết nối với bản gốc
List<String> copy = List.copyOf(original);
original.add("X");  // Không nhìn thấy trong copy!

// unmodifiableList → view → có kết nối
// List.copyOf → bản sao → không có kết nối
```

### Defensive Copying (sao chép phòng thủ)

```java
// Các API của service:
// unmodifiableList → client có thể tiếp cận bản gốc
// List.copyOf → cô lập hoàn toàn (an toàn hơn)

// Nhưng: List.copyOf = sao chép O(n)
// unmodifiableList = lớp bọc O(1)
```

### Kinh nghiệm Production

**Tình huống thực tế: rò rỉ bản gốc**
```java
// ❌ Client tìm ra bản gốc thông qua reflection
List<String> view = Collections.unmodifiableList(secret);
// → Tìm ra trường `list` bên trong lớp bọc
// → Sửa đổi nó!

// ✅ List.copyOf → không có bản gốc
List<String> safe = List.copyOf(secret);
```

### Best Practices

1. **unmodifiableList** = view, không phải immutable
2. **List.copyOf** = cô lập hoàn toàn
3. **Các đối tượng bên trong** vẫn có thể bị sửa đổi
4. **RandomAccess** được giữ nguyên
5. **Defensive copy** cho code quan trọng về bảo mật
6. Tạo **O(1)** so với sao chép **O(n)**

### Tóm tắt cho Senior

- **View** → có kết nối với bản gốc
- **List.copyOf** → cô lập
- **Không bảo vệ** các đối tượng bên trong
- **RandomAccess** được giữ nguyên
- Tạo lớp bọc **O(1)**
- **Defensive copy** cho bảo mật

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `unmodifiableList()` trả về một view, không phải một bản sao — các thay đổi trên bản gốc nhìn thấy được
- Bất kỳ sửa đổi nào (`add`, `remove`, `set`) đều ném `UnsupportedOperationException`
- Lớp bọc bảo vệ cấu trúc của list, nhưng KHÔNG bảo vệ các đối tượng bên trong (User mutable có thể bị sửa đổi)
- `unmodifiableList` so với `List.copyOf()`: view (có kết nối với bản gốc) so với bản sao đầy đủ (cô lập)
- Marker `RandomAccess` được giữ nguyên — tối ưu hóa cho tìm kiếm nhị phân
- Tạo lớp bọc là O(1), sao chép của `List.copyOf()` là O(n)
- Cho code quan trọng về bảo mật — `List.copyOf()` hoặc defensive copy

**Các câu hỏi phụ thường gặp:**
- *Các thay đổi trên bản gốc có nhìn thấy được qua unmodifiableList không?* — Có, nó là một view, không phải một bản sao.
- *unmodifiableList có bảo vệ khỏi việc sửa đổi các đối tượng bên trong list không?* — Không, chỉ khỏi việc sửa đổi cấu trúc của list (add/remove). Bản thân các đối tượng cần được làm cho bất biến.
- *Khi nào chọn List.copyOf() thay vì unmodifiableList()?* — Khi cần cô lập hoàn toàn khỏi bản gốc (Java 10+).
- *RandomAccess có được giữ nguyên qua lớp bọc không?* — Có, `UnmodifiableRandomAccessList` cũng `implements RandomAccess`.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "unmodifiableList tạo một bản sao của dữ liệu" — không, nó là một view trên bản gốc
- "unmodifiableList là tính bất biến thực sự" — không, bản gốc vẫn có thể bị sửa đổi
- "Các đối tượng bên trong cũng được bảo vệ" — lớp bọc chỉ bảo vệ cấu trúc, không phải nội dung
- "List.copyOf() giống với unmodifiableList" — List.copyOf() tạo một bản sao, không có kết nối với bản gốc

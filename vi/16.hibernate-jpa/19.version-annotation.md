# What is @Version and Why is It Needed (@Version là gì và tại sao cần đến nó)

## Overview

`@Version` là một annotation JPA để triển khai optimistic locking. Nó tự động theo dõi version của entity và ngăn ngừa các cập nhật xung đột từ nhiều transaction.

---

## Junior Level

### @Version Là Gì

`@Version` - annotation cho **optimistic locking**. Tự động theo dõi version của entity và ngăn ngừa các cập nhật xung đột.

```java
@Entity
public class Order {
    @Id
    private Long id;

    @Version
    private Integer version;  // tự động tăng

    private String status;
}
```

### Tại Sao Cần Đến Nó

Khi **hai transaction** cập nhật cùng một object, `@Version` đảm bảo một trong số chúng nhận được lỗi:

```
Ban đầu: Order(id=1, version=1, status="new")

Transaction 1: đọc (version=1)
Transaction 2: đọc (version=1)
Transaction 2: cập nhật -> UPDATE WHERE version=1 -> version=2 OK
Transaction 1: cập nhật -> UPDATE WHERE version=1 -> 0 dòng -> OptimisticLockException
```

### Cách Hoạt Động - Đơn Giản

```
1. Khi INSERT: version = 0. Ở mỗi UPDATE: version = version + 1.
2. Ở mỗi UPDATE: version = version + 1
3. Mệnh đề WHERE: WHERE id = ? AND version = ?
4. Nếu version không khớp -> 0 dòng được cập nhật -> OptimisticLockException
```

## Middle Level

### Các Kiểu Trường Version

```java
@Version
private Integer version;  // int - tăng thêm 1

@Version
private Long version;     // long - tăng thêm 1

@Version
private Timestamp version;  // timestamp - cập nhật với thời gian hiện tại
```

### Ví Dụ Chi Tiết

```java
@Entity
public class Product {
    @Id
    private Long id;

    @Version
    private Integer version;

    private String name;
    private int stock;
}

// Transaction A
Product pA = em.find(Product.class, 1L);  // version=1, stock=10

// Transaction B
Product pB = em.find(Product.class, 1L);  // version=1, stock=10
pB.setStock(8);
em.flush();  // UPDATE SET stock=8, version=2 WHERE id=1 AND version=1 OK

// Transaction A
pA.setStock(5);
em.flush();  // UPDATE SET stock=5, version=2 WHERE id=1 AND version=1
// -> 0 dòng -> OptimisticLockException!
// stock=8 (từ B) không bị ghi đè
```

### Các Lỗi Thường Gặp

```java
// Thay đổi version thủ công
order.setVersion(0);  // phá vỡ cơ chế khóa

// Không có @Version cho dữ liệu quan trọng
@Entity
public class Account {
    // không có @Version -> hai thread có thể đồng thời thay đổi balance
}

// Bỏ qua OptimisticLockException
try {
    em.flush();
} catch (OptimisticLockException e) {
    // âm thầm bỏ qua -> mất dữ liệu
}
```

## Senior Level

### Triển Khai Nội Bộ

```
Hibernate:
- Khi INSERT: version = 1 (hoặc 0 cho một số kiểu)
- Khi UPDATE: version = version + 1
- Mệnh đề WHERE: WHERE id = ? AND version = ?
- Nếu 0 dòng -> OptimisticLockException

Cho Timestamp:
- version = CURRENT_TIMESTAMP
- Mệnh đề WHERE: WHERE id = ? AND version = ?
- Version Timestamp rủi ro: nếu hai transaction cập nhật entity trong cùng mili giây, xung đột sẽ KHÔNG được phát hiện. Trong production hãy dùng Integer/Long, không phải Timestamp.
```

### OPTIMISTIC_FORCE_INCREMENT

```java
// Tăng version mà không thay đổi entity
em.lock(order, LockModeType.OPTIMISTIC_FORCE_INCREMENT);

// Khi cần thiết:
// - Khi collection con thay đổi
// - Để invalidate cache bắt buộc
// - Khi entity không thay đổi nhưng thay đổi cần được ghi lại
```

### Audit Với @Version

```java
@Entity
@EntityListeners(AuditingEntityListener.class)
public class Order {
    @Id
    private Long id;

    @Version
    private Integer version;

    @LastModifiedDate
    private LocalDateTime updatedAt;

    // version cho optimistic locking
    // updatedAt cho audit (khi nào có thay đổi gần nhất)
}
```

### Tác Động Hiệu Năng

```
Overhead của @Version:
- +1 cột trong table
- +1 điều kiện trong WHERE khi UPDATE
- Thực tế không đáng kể

Lợi ích:
- Ngăn ngừa mất cập nhật
- Không có khóa (khác với pessimistic)
- Quản lý tự động
```

### Các Pattern Production

```java
// Pattern 1: Retry với @Version
@Retryable(value = OptimisticLockException.class, maxAttempts = 3)
@Transactional
public Order updateOrder(OrderDto dto) {
    Order order = entityManager.find(Order.class, dto.id());
    order.setStatus(dto.status());
    return order;
}

// Pattern 2: Refresh và retry
@Transactional
public Order updateWithRefresh(OrderDto dto) {
    Order order = entityManager.find(Order.class, dto.id());
    try {
        order.setStatus(dto.status());
        entityManager.flush();
        return order;
    } catch (OptimisticLockException e) {
        entityManager.refresh(order);  // lấy dữ liệu thực tế
        order.setStatus(dto.status());  // áp dụng vào dữ liệu thực tế
        entityManager.flush();
        return order;
    }
}
```

### Best Practices

```
@Version trên tất cả các entity có thể thay đổi
Retry khi OptimisticLockException
Đừng thay đổi version thủ công
Giám sát tần suất xung đột
OPTIMISTIC_FORCE_INCREMENT khi cần

Không có @Version cho dữ liệu quan trọng
Quản lý version thủ công
Bỏ qua OptimisticLockException
Pessimistic locking mà không có lý do
```

## Interview Cheat Sheet

**Cần phải biết:**
- @Version - annotation cho optimistic locking, tự động tăng version ở UPDATE
- Mệnh đề WHERE: WHERE id = ? AND version = ? - nếu 0 dòng -> OptimisticLockException
- Các kiểu: Integer/Long (tăng thêm 1), Timestamp (cập nhật với thời gian hiện tại, rủi ro)
- Khi INSERT: version = 0, khi UPDATE lần đầu: version = 1
- OPTIMISTIC_FORCE_INCREMENT - tăng version mà không thay đổi entity
- @Version trên tất cả các entity có thể thay đổi - ngăn ngừa mất cập nhật

**Các câu hỏi phụ thường gặp:**
- **Tại sao Timestamp rủi ro cho @Version?** Hai cập nhật trong cùng mili giây - xung đột không được phát hiện
- **Khi nào dùng OPTIMISTIC_FORCE_INCREMENT?** Collection con thay đổi, invalidate cache, entity không thay đổi nhưng thay đổi cần ghi lại
- **Overhead hiệu năng của @Version?** +1 cột, +1 điều kiện trong WHERE - thực tế không đáng kể
- **Version có thể thay đổi thủ công không?** Không - phá vỡ cơ chế khóa

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Timestamp cho @Version trong production" - xung đột trong cùng mili giây không được phát hiện
- "Thay đổi version thủ công" - phá vỡ optimistic locking
- "Không có @Version cho Account/Balance" - có thể xảy ra mất cập nhật
- "Tôi bỏ qua OptimisticLockException" - dữ liệu bị mất âm thầm

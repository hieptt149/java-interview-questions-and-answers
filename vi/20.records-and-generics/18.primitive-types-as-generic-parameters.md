# Can You Use Primitive Types as Generic Parameters? (Có thể dùng kiểu nguyên thủy làm tham số generic không)

## 🟢 Junior Level

**Không, bạn không thể.** Generics trong Java chỉ hoạt động **với kiểu tham chiếu (reference type)**, không phải với kiểu nguyên thủy.

```java
// ❌ Không thể dùng kiểu nguyên thủy
List<int> ints = new ArrayList<>();       // lỗi biên dịch
Map<String, double> map = new HashMap<>(); // lỗi biên dịch
Box<char> box = new Box<>();              // lỗi biên dịch

// ✅ Dùng wrapper class
List<Integer> ints = new ArrayList<>();       // OK
Map<String, Double> map = new HashMap<>();     // OK
Box<Character> box = new Box<>();              // OK
```

**Tất cả kiểu nguyên thủy và wrapper class của chúng:**

| Nguyên thủy  | Wrapper     |
| ---------- | ----------- |
| `byte`     | `Byte`      |
| `short`    | `Short`     |
| `int`      | `Integer`   |
| `long`     | `Long`      |
| `float`    | `Float`     |
| `double`   | `Double`    |
| `boolean`  | `Boolean`   |
| `char`     | `Character` |

## 🟡 Middle Level

### Tại Sao Lại Như Vậy?

Generics dùng **type erasure** — sau khi biên dịch, `T` được thay bằng `Object`. Kiểu nguyên thủy không kế thừa từ `Object`, vì vậy chúng không thể là type parameter.

```java
public class Box<T> {
    private T value;
}

// Sau type erasure:
public class Box {
    private Object value;  // T -> Object
}

// int không thể là Object — đó là lý do Box<int> không được phép
```

### Autoboxing và Unboxing

Java tự động chuyển đổi kiểu nguyên thủy ↔ wrapper class:

```java
List<Integer> list = new ArrayList<>();

// Autoboxing: int -> Integer
list.add(42);  // trình biên dịch: list.add(Integer.valueOf(42))

// Unboxing: Integer -> int
int value = list.get(0);  // trình biên dịch: list.get(0).intValue()
```

**Overhead của autoboxing:**
```java
// Nguyên thủy — 4 byte, trên stack
int primitive = 42;

// Wrapper — ~24 byte, trên heap
Integer wrapper = Integer.valueOf(42);
// - Object header: 12-16 byte
// - giá trị int: 4 byte
// - Padding: 4 byte
```

### Các Lỗi Thường Gặp

1. **Autoboxing null:**
```java
Integer wrapper = null;
int primitive = wrapper;  // ❌ NullPointerException!
```

2. **Hiệu năng autoboxing:**
```java
// ❌ Chậm — Integer được tạo cho mỗi lần lặp
List<Integer> list = new ArrayList<>();
for (int i = 0; i < 1_000_000; i++) {
    list.add(i);  // autoboxing mỗi lần
}

// ✅ Nhanh hơn — collection nguyên thủy
int[] array = new int[1_000_000];
for (int i = 0; i < 1_000_000; i++) {
    array[i] = i;
}
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Cache của autoboxing:**
```java
// Integer cache các giá trị từ -128 đến 127
Integer a = 100;
Integer b = 100;
System.out.println(a == b);  // true (cùng object từ cache)

Integer c = 200;
Integer d = 200;
System.out.println(c == d);  // false (các object khác nhau)

// Integer.valueOf(int) kiểm tra cache:
public static Integer valueOf(int i) {
    if (i >= IntegerCache.low && i <= IntegerCache.high)
        return IntegerCache.cache[i + (-IntegerCache.low)];
    return new Integer(i);
}
```

**Overhead bộ nhớ:**
```
Kiểu         | Kích thước      | Vị trí
-------------|-----------|-------------
int          | 4 byte   | Stack
Integer      | ~24 byte | Heap
int[]        | 4N byte  | Heap
Integer[]    | ~24N byte| Heap
ArrayList<Integer> | ~32N byte | Heap
```

### Đánh Đổi Kiến Trúc

**Wrapper so với kiểu nguyên thủy:**

| Khía cạnh        | Wrapper   | Nguyên thủy  |
| ------------- | --------- | ----------- |
| **Bộ nhớ**    | 24 byte  | 4 byte     |
| **Tốc độ**     | Chậm hơn    | Nhanh hơn      |
| **Null**      | Cho phép   | Không cho phép |
| **Generics**  | ✅         | ❌           |
| **Collection**| ✅        | ❌           |

### Edge Cases

**1. Autoboxing trong điều kiện:**
```java
Integer count = 0;
for (int i = 0; i < 1000; i++) {
    count = count + i;  // unboxing + boxing mỗi lần
}
// 2000 thao tác autoboxing/unboxing!

// ✅ Tốt hơn
int count = 0;
for (int i = 0; i < 1000; i++) {
    count += i;
}
```

**2. Toán tử ternary với autoboxing:**
```java
Integer a = 1;
Integer b = null;

// ⚠️ Nguy hiểm — unboxing null
Integer result = condition ? a : b;  // OK
int primitive = condition ? a : b;   // ❌ NPE nếu a HOẶC b == null khi unboxing thành int.
```

### Hiệu Năng

**Benchmark (JMH, Java 21):**
```
Thao tác                | Thời gian
-------------------------|--------
Phép cộng int             | 0.3 ns
Phép cộng Integer         | 1.5 ns (chậm hơn 5 lần)
// Giá trị xấp xỉ (JMH). Phụ thuộc vào JVM, CPU, warmup.
Truy cập int[]             | 1 ns
ArrayList<Integer> get   | 3 ns (chậm hơn 3 lần)
Autoboxing int->Integer  | 5 ns
Unboxing Integer->int    | 1 ns
```

**Hậu quả trong Highload:**
```java
// ❌ Vấn đề — 1 triệu thao tác với autoboxing
List<Integer> numbers = new ArrayList<>();
for (int i = 0; i < 1_000_000; i++) {
    numbers.add(i);  // 1 triệu autoboxing = ~5ms + 24MB bộ nhớ
}

// ✅ Giải pháp — collection nguyên thủy
// Eclipse Collections, fastutil, hoặc mảng
int[] numbers = new int[1_000_000];  // 4MB bộ nhớ, không có autoboxing
```

### Kinh Nghiệm Production

**Collection nguyên thủy:**
```java
// fastutil — thư viện cho collection nguyên thủy
IntList numbers = new IntArrayList();
numbers.add(42);  // không có autoboxing
int value = numbers.getInt(0);  // không có unboxing

// Eclipse Collections
MutableIntList list = IntLists.mutable.empty();
list.add(1);
list.add(2);

// Hoặc chỉ đơn giản là mảng
int[] array = new int[100];
```

**Stream API với kiểu nguyên thủy:**
```java
// ❌ Stream<Integer> — autoboxing
List<Integer> list = List.of(1, 2, 3);
int sum = list.stream()
    .mapToInt(Integer::intValue)  // unboxing
    .sum();

// ✅ IntStream — không có autoboxing
int[] array = {1, 2, 3};
int sum = Arrays.stream(array).sum();

// ✅ IntStream range
int sum = IntStream.rangeClosed(1, 100).sum();
```

### Best Practices

```java
// ✅ Wrapper cho collection và generics
List<Integer> list = new ArrayList<>();
Map<String, Double> map = new HashMap<>();

// ✅ Kiểu nguyên thủy cho tính toán
int sum = 0;
for (int i = 0; i < 1000; i++) {
    sum += i;
}

// ✅ Stream nguyên thủy
int sum = IntStream.range(0, 100).sum();

// ✅ Collection nguyên thủy cho highload
int[] array = new int[1_000_000];

// ❌ Wrapper cho tính toán
// ❌ Bỏ qua overhead của autoboxing
// ❌ Autoboxing null
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Kiểu nguyên thủy không thể dùng làm type parameter: `List<int>` — lỗi biên dịch
- Lý do: type erasure thay T bằng Object, kiểu nguyên thủy không kế thừa Object
- Autoboxing: nguyên thủy -> wrapper (`int` -> `Integer`), unboxing: ngược lại
- Integer cache các giá trị -128..127 (IntegerCache), các wrapper khác cũng có cache
- Overhead của autoboxing: ~24 byte mỗi Integer so với 4 byte int, ~5 ns mỗi lần boxing
- Đối với highload: collection nguyên thủy (fastutil, Eclipse Collections) hoặc mảng

**Các câu hỏi phụ thường gặp:**
- **Tại sao kiểu nguyên thủy không thể dùng trong generics?** — Type erasure: T -> Object, kiểu nguyên thủy không phải Object
- **Overhead của autoboxing là gì?** — Bộ nhớ: 24 byte so với 4 byte, thời gian: ~5 ns mỗi lần boxing
- **Điều gì xảy ra khi unboxing null?** — NullPointerException: `Integer x = null; int y = x;`
- **Khi nào dùng collection nguyên thủy?** — Highload, khối lượng dữ liệu lớn (1 triệu+ phần tử)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "List<int> hoạt động trong Java mới" — Bị cấm vĩnh viễn, không có kế hoạch thêm
- ❌ "Autoboxing là miễn phí" — Gấp 6 lần bộ nhớ + thời gian cho boxing/unboxing
- ❌ "Integer a = 100; Integer b = 100; a == b luôn đúng" — Chỉ đúng với cache (-128..127)
- ❌ "Stream<Integer> nhanh như IntStream" — IntStream không có autoboxing nhanh hơn đáng kể

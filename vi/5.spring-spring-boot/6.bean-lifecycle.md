# What is Bean Lifecycle? (Bean Lifecycle là gì?)

## Junior Level

**Bean Lifecycle** (vòng đời của bean) là tất cả các giai đoạn của một bean từ lúc tạo đến lúc hủy.

**Tại sao cần biết vòng đời:** (1) khởi tạo tài nguyên vào đúng thời điểm, (2) hiểu tại sao @Transactional không hoạt động từ @PostConstruct, (3) dọn dẹp tài nguyên đúng cách, (4) giải quyết các circular dependency.

**Ví dụ minh họa đơn giản:** Cuộc đời của một con người: sinh ra -> lớn lên -> làm việc -> nghỉ hưu.

**Các giai đoạn chính:**
```
1. Tạo (constructor)
2. Tiêm phụ thuộc
3. Khởi tạo (@PostConstruct)
4. Hoạt động (sẵn sàng sử dụng)
5. Hủy (@PreDestroy)
```

> Trong Spring 6 / Boot 3: dùng `jakarta.annotation.PostConstruct` thay vì `javax.annotation.PostConstruct`.

```java
@Service
public class MyBean {

    public MyBean() {
        // 1. Tạo
    }

    @PostConstruct
    public void init() {
        // 3. Khởi tạo
    }

    @PreDestroy
    public void cleanup() {
        // 5. Hủy
    }
}
```

## Middle Level

### Các pha của vòng đời

```
1. BeanDefinition -> thông tin meta
2. Instantiation -> constructor
3. Populate Properties -> @Autowired
4. Aware Interfaces -> setBeanName, setBeanFactory
5. @PostConstruct -> khởi tạo
6. Ready -> bean đã sẵn sàng
7. @PreDestroy -> dọn dẹp
```

### Singleton so với Prototype

| Giai đoạn          | Singleton    | Prototype              |
| ------------- | ------------ | ---------------------- |
| Tạo      | Một lần     | Mỗi lần khi có yêu cầu |
| Khởi tạo | Có | Có           |
| Hủy   | Có | KHÔNG được gọi!       |

```java
// Prototype: bạn phải tự dọn dẹp tài nguyên!
PrototypeBean bean = context.getBean(PrototypeBean.class);
try {
    // sử dụng
} finally {
    bean.cleanup();  // Thủ công!
}
```

### SmartLifecycle

```java
// Để khởi động/dừng các component
@Component
public class MyService implements SmartLifecycle {
    public void start() { /* Khởi động sau khi tất cả bean đã được khởi tạo */ }
    public void stop() { /* Dừng khi shutdown */ }
    public boolean isRunning() { return running; }
    public int getPhase() { return 0; }  // Thứ tự khởi động
}
```

## Senior Level

### Khi nào KHÔNG dùng @PostConstruct

1. **Khởi tạo nặng** — chặn toàn bộ quá trình khởi động context. Dùng SmartLifecycle hoặc @EventListener(ContextRefreshedEvent)
2. **Gọi các phương thức @Transactional** — proxy chưa tồn tại, transaction không hoạt động
3. **Các thao tác có retry** — nếu khởi tạo có thể thất bại (chưa có kết nối DB), dùng SmartLifecycle với retry

### Cache ba tầng và các vòng phụ thuộc

Ba cache để giải quyết circular dependency:
1. **singletonObjects** — các bean đã sẵn sàng (đã khởi tạo đầy đủ)
2. **earlySingletonObjects** — đã tạo nhưng chưa khởi tạo (để phá vỡ vòng)
3. **singletonFactories** — các factory tạo ra các tham chiếu sớm (early reference)

```
Các cache của DefaultListableBeanFactory:
  1. singletonObjects -> các bean đã sẵn sàng
  2. earlySingletonObjects -> đã tạo nhưng chưa khởi tạo
  3. singletonFactories -> các factory để lấy tham chiếu sớm

-> Giải quyết các vòng cho Field/Setter Injection
-> Constructor Injection không thể dùng cache 3
```

### Điểm tạo Proxy

```
BPP.postProcessAfterInitialization():
  -> Đây là nơi các AOP Proxy được tạo
  -> Bean bị thay thế bằng Proxy trong container

@PostConstruct được gọi TRƯỚC proxy!
  -> Gọi một phương thức @Transactional từ @PostConstruct sẽ KHÔNG hoạt động
  -> Giải pháp: ApplicationListener<ContextRefreshedEvent>
```

### Thứ tự của các BPP

```java
// Thứ tự BPP quan trọng!
@Order(1)
public class FirstBPP implements BeanPostProcessor { }

@Order(2)
public class SecondBPP implements BeanPostProcessor { }

-> FirstBPP chạy sớm hơn
```

### Kinh nghiệm Production

**Tình huống thực tế: @PostConstruct + @Transactional**
```java
@PostConstruct
public void init() {
    loadData();  // @Transactional -> KHÔNG hoạt động!
}

// Lý do: proxy chưa tồn tại
// Giải pháp:
@EventListener(ContextRefreshedEvent.class)
public void init() {
    loadData();  // Bây giờ proxy đã tồn tại -> transaction hoạt động
}
```

### Best Practices

1. **@PostConstruct** -> validation, khởi tạo
2. **@PreDestroy** -> dọn dẹp tài nguyên
3. **Prototype** -> tự dọn dẹp tài nguyên
4. **SmartLifecycle** -> thứ tự khởi động
5. **@PostConstruct** -> proxy chưa tồn tại!
6. **Thứ tự BPP** -> quản lý qua @Order

### Tóm tắt cho Senior

- **Instantiation != Initialization**
- **Cache ba tầng** -> giải quyết vòng phụ thuộc
- **Proxy** được tạo SAU @PostConstruct
- **Prototype** -> @PreDestroy KHÔNG được gọi
- **SmartLifecycle** -> khởi động/dừng các component
- **ContextRefreshedEvent** -> khi mọi thứ đã sẵn sàng

## Interview Cheat Sheet

**Cần phải biết:**
- Bean Lifecycle: tạo -> tiêm phụ thuộc -> khởi tạo (`@PostConstruct`) -> sẵn sàng -> hủy (`@PreDestroy`)
- Vòng đời cần cho: khởi tạo tài nguyên, hiểu tại sao `@Transactional` không hoạt động từ `@PostConstruct`, dọn dẹp tài nguyên, giải quyết các vòng phụ thuộc
- Singleton: tất cả các giai đoạn 1-12, `@PreDestroy` được gọi khi context shutdown
- Prototype: chỉ tạo và khởi tạo, `@PreDestroy` KHÔNG được gọi — dọn dẹp thủ công
- Cache ba tầng (singletonObjects, earlySingletonObjects, singletonFactories) giải quyết circular dependency
- Proxy được tạo SAU `@PostConstruct` — gọi phương thức `@Transactional` từ `@PostConstruct` sẽ không hoạt động
- `SmartLifecycle` — để khởi động/dừng các component theo thứ tự (`getPhase()`)
- Trong Spring 6 / Boot 3: `jakarta.annotation.PostConstruct` thay vì `javax.annotation`

**Các câu hỏi phụ thường gặp:**
- **Tại sao `@Transactional` không hoạt động từ `@PostConstruct`?** Proxy được tạo sau `@PostConstruct`, lời gọi đi tới đối tượng gốc.
- **Làm sao giải quyết vấn đề transaction trong lúc khởi tạo?** `@EventListener(ContextRefreshedEvent.class)` — tất cả proxy đã tồn tại.
- **Tại sao Prototype không gọi `@PreDestroy`?** Spring không theo dõi việc hủy prototype bean — hãy gọi cleanup thủ công.
- **Cache ba tầng là gì?** Cache của các bean sẵn sàng, các tham chiếu sớm, và các factory — giải quyết các vòng cho Field/Setter Injection.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "`@PostConstruct` là nơi để khởi tạo nặng" (chặn quá trình khởi động context, dùng `SmartLifecycle`)
- "Prototype bean được dọn dẹp tự động" (`@PreDestroy` KHÔNG được gọi cho Prototype)
- "Mọi scope đều hoạt động giống nhau với vòng đời" (Prototype bỏ qua các giai đoạn hủy)
- "`@PostConstruct` và khởi tạo là cùng một thứ" (Instantiation != Initialization)

# What is Criteria API and When to Use It (Criteria API là gì và khi nào dùng nó)

## Overview

Criteria API là một cách xây dựng truy vấn JPQL theo cách lập trình mà **type-safe**. Nó đặc biệt hữu ích cho các truy vấn động với nhiều filter tùy chọn, nơi JPQL tĩnh sẽ bất tiện.

---

## Junior Level

### Criteria API Là Gì

Criteria API - cách xây dựng truy vấn JPQL theo cách lập trình mà **type-safe**.

```java
// JPQL - truy vấn dạng chuỗi
"SELECT u FROM User u WHERE u.age > 18"

// Criteria API - type-safe
CriteriaBuilder cb = entityManager.getCriteriaBuilder();
CriteriaQuery<User> query = cb.createQuery(User.class);
Root<User> root = query.from(User.class);
query.select(root).where(cb.gt(root.get("age"), 18));

List<User> users = entityManager.createQuery(query).getResultList();
```

### Các Thành Phần Chính

```java
CriteriaBuilder     - factory để tạo expression
CriteriaQuery<T>    - bản thân truy vấn
Root<T>             - entity gốc (mệnh đề FROM)
Predicate           - điều kiện WHERE
```

### Ví Dụ Đơn Giản

```java
CriteriaBuilder cb = entityManager.getCriteriaBuilder();
CriteriaQuery<User> query = cb.createQuery(User.class);
Root<User> root = query.from(User.class);

// SELECT u FROM User u WHERE u.age > 18
query.select(root)
     .where(cb.greaterThan(root.get("age"), 18));
     // Truy cập dạng chuỗi - KHÔNG type-safe. Để có type-safety hãy dùng Metamodel:
     // root.get(User_.age)

List<User> users = entityManager.createQuery(query).getResultList();
```

## Middle Level

### Khi Nào Dùng

```
Criteria API khi:
- Truy vấn động (nhiều filter tùy chọn)
- Cần type-safety (compilation bắt lỗi)
- Refactor an toàn

JPQL khi:
- Truy vấn tĩnh đơn giản
- Dễ đọc hơn
- Ít code hơn
```

### Truy Vấn Động Với Các Filter

```java
public List<User> findUsers(String name, Integer minAge, String status) {
    CriteriaBuilder cb = entityManager.getCriteriaBuilder();
    CriteriaQuery<User> query = cb.createQuery(User.class);
    Root<User> root = query.from(User.class);

    List<Predicate> predicates = new ArrayList<>();

    if (name != null) {
        predicates.add(cb.like(root.get("name"), "%" + name + "%"));
    }
    if (minAge != null) {
        predicates.add(cb.ge(root.get("age"), minAge));
    }
    if (status != null) {
        predicates.add(cb.equal(root.get("status"), status));
    }

    query.where(predicates.toArray(new Predicate[0]));
    query.orderBy(cb.asc(root.get("name")));

    return entityManager.createQuery(query).getResultList();
}
```

### Với Metamodel (Type-Safe)

```java
// Metamodel được tạo tự động
@StaticMetamodel(User.class)
public abstract class User_ {
    public static volatile SingularAttribute<User, String> name;
    public static volatile SingularAttribute<User, Integer> age;
    public static volatile SingularAttribute<User, String> status;
}

// Truy vấn type-safe
root.get(User_.age)  // thay vì root.get("age")
```

### JOIN Trong Criteria API

```java
CriteriaQuery<Order> query = cb.createQuery(Order.class);
Root<Order> root = query.from(Order.class);
Join<Order, User> userJoin = root.join("user");

query.select(root)
     .where(cb.equal(userJoin.get("name"), "John"));
```

## Senior Level

### Specification Pattern (Spring Data JPA)

```java
public class UserSpecifications {

    public static Specification<User> hasName(String name) {
        return (root, query, cb) ->
            cb.like(root.get(User_.name), "%" + name + "%");
    }

    public static Specification<User> hasMinAge(int minAge) {
        return (root, query, cb) ->
            cb.greaterThanOrEqualTo(root.get(User_.age), minAge);
    }

    public static Specification<User> hasStatus(String status) {
        return (root, query, cb) ->
            cb.equal(root.get(User_.status), status);
    }
}

// Cách dùng
Specification<User> spec = Specification
    .where(UserSpecifications.hasName("John"))
    .and(UserSpecifications.hasMinAge(18))
    .and(UserSpecifications.hasStatus("ACTIVE"));

List<User> users = userRepository.findAll(spec);
```

### Subquery

// Ví dụ đơn giản hóa - trong code thực tế subquery có thể phức tạp hơn nhiều
```java
CriteriaQuery<User> query = cb.createQuery(User.class);
Root<User> userRoot = query.from(User.class);

// Subquery
Subquery<Long> subquery = query.subquery(Long.class);
Root<Order> orderRoot = subquery.from(Order.class);
subquery.select(cb.max(orderRoot.get("total")))
        .where(cb.equal(orderRoot.get("user").get("id"), userRoot.get("id")));

query.select(userRoot)
     .where(cb.greaterThan(userRoot.get("totalSpent"), subquery));
```

### Fetch Join

```java
CriteriaQuery<Order> query = cb.createQuery(Order.class);
Root<Order> root = query.from(Order.class);
root.fetch("items", JoinType.LEFT);  // FETCH JOIN

query.select(root)
     .distinct(true);  // loại bỏ trùng lặp
```

### Sinh Metamodel

```xml
<!-- pom.xml -->
<dependency>
    <groupId>org.hibernate.orm</groupId>
    <artifactId>hibernate-jpamodelgen</artifactId>
    <scope>provided</scope>
</dependency>

```

### Best Practices

```
Criteria API cho truy vấn động
Metamodel cho type-safety
JPQL cho truy vấn tĩnh đơn giản
Spring Data JPA Specification
Fetch join cho dữ liệu liên quan
Distinct cho trùng lặp

Criteria API cho truy vấn đơn giản (thừa)
Không có metamodel (dạng chuỗi dễ lỗi)
Nối chuỗi trong Criteria - làm ô nhiễm query plan cache và khó đọc. Các giá trị vẫn được tham số hóa, SQL injection khó xảy ra.
Bỏ qua distinct trên fetch join
```

## Interview Cheat Sheet

**Cần phải biết:**
- Criteria API - cách xây dựng truy vấn JPQL theo cách lập trình mà type-safe
- Các thành phần chính: CriteriaBuilder, CriteriaQuery, Root, Predicate
- Tốt nhất cho các truy vấn động với nhiều filter tùy chọn
- Metamodel (User_) cung cấp type-safety hoàn toàn - lỗi tại compile time
- Specification pattern (Spring Data JPA) - criteria có thể tái sử dụng
- Với các truy vấn tĩnh đơn giản, JPQL đơn giản và dễ đọc hơn

**Các câu hỏi phụ thường gặp:**
- **Criteria API vs JPQL - khi nào dùng cái nào?** Criteria API cho truy vấn động (filter tùy chọn), JPQL cho tĩnh
- **Tại sao cần Metamodel?** root.get("age") - dạng chuỗi, lỗi runtime; root.get(User_.age) - type-safe, lỗi compile-time
- **Specification pattern mang lại điều gì?** Kết hợp criteria: where(hasName).and(hasMinAge), tái sử dụng code
- **Criteria API có hỗ trợ subquery và fetch join không?** Có - Subquery cho subquery, root.fetch() cho fetch join

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Criteria API cho SELECT đơn giản" - thừa, JPQL đơn giản hơn
- "Không có Metamodel - tôi dùng chuỗi" - lỗi runtime khi refactor
- "Nối chuỗi trong Criteria" - làm ô nhiễm query plan cache, khó đọc
- "Tôi bỏ qua distinct trên fetch join" - trùng lặp trong kết quả

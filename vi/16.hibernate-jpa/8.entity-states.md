# What Are the Transient, Persistent, Detached, Removed States (Các trạng thái transient, persistent, detached, removed là gì)

## Overview

Bốn thuật ngữ mô tả trạng thái tương tác của một object Java với cơ chế ORM (Hibernate/JPA) tại một thời điểm nhất định. Hiểu đúng các trạng thái này rất quan trọng để ngăn ngừa rò rỉ bộ nhớ, cập nhật dữ liệu không chính xác, và lỗi runtime.

---

## Junior Level

### 4 Trạng Thái Entity

| Trạng thái   | Có trong DB?              | Được Hibernate theo dõi?  |
| ------------ | ----------------------- | ------------------------- |
| **Transient**  | Không                | Không                     |
| **Persistent** | Có                    | Có                      |
| **Detached**   | Có                    | Không                     |
| **Removed**    | Có (đánh dấu để xóa) | Có (cho đến khi flush)              |

### Ví Dụ Về Mỗi Trạng Thái

```java
// 1. Transient - object mới, chưa có trong DB
User user = new User();
user.setName("John");
// user CHƯA có trong DB, Hibernate KHÔNG theo dõi

// 2. Persistent - đã lưu và được Hibernate quản lý
entityManager.persist(user);
// user đã có trong DB (INSERT được thực thi hoặc lên lịch)
// Hibernate theo dõi các thay đổi (dirty checking)

// 3. Detached - bản ghi trong DB tồn tại, nhưng Hibernate không theo dõi
entityManager.close();
// user vẫn tồn tại trong bộ nhớ
// user vẫn tồn tại trong DB
// Nhưng Hibernate không còn theo dõi các thay đổi

// 4. Removed - đánh dấu để xóa
User user2 = entityManager.find(User.class, 1L);
entityManager.remove(user2);
// user2 được đánh dấu để xóa
// Khi flush/commit, DELETE sẽ được thực thi
```

### Cách Kiểm Tra Trạng Thái

```java
// Kiểm tra xem entity có được quản lý không
boolean isManaged = entityManager.contains(user);

// Kiểm tra theo ID
// Điều này hoạt động với GenerationType.AUTO/IDENTITY.
// Với Assigned generation, ID có thể được đặt thủ công.
if (user.getId() == null) {
    // có thể là Transient
} else if (entityManager.contains(user)) {
    // Persistent
} else {
    // Detached (có ID, nhưng không được quản lý)
}
```

## Middle Level

### Khi Nào KHÔNG Nên Dùng Dirty Checking

Dirty checking tiện lợi cho các cập nhật đơn lẻ. Cho xử lý bulk (1000+ entity) overhead tăng lên - hãy dùng truy vấn SQL native hoặc StatelessSession.

### Các Thao Tác Chuyển Đổi Trạng Thái

```
persist()  - Transient -> Persistent
merge()    - Detached -> Persistent (trả về bản sao managed mới)
remove()   - Persistent -> Removed
refresh()  - tải lại từ DB (cập nhật Persistent)
detach()   - Persistent -> Detached (evict() trong Hibernate)
clear()    - tất cả Persistent -> Detached
```

### Hành Vi Chi Tiết Của Mỗi Thao Tác

#### persist()

```java
User user = new User();
user.setName("John");
entityManager.persist(user);

// user trở thành Persistent
// INSERT sẽ được thực thi khi flush/commit
user.setName("Jane");  // dirty checking - sẽ là UPDATE
```

#### merge()

```java
// merge - thao tác khó hiểu nhất
User detached = getDetachedUser();  // lấy được object detached từ đâu đó

User managed = entityManager.merge(detached);

// Điều gì xảy ra bên trong:
// 1. Hibernate tìm entity có cùng ID trong session hiện tại
// 2. Nếu không tìm thấy - tải từ DB
// 3. Sao chép trạng thái từ detached sang managed
// 4. Trả về object managed
// 5. detached vẫn là detached!

detached.setName("Changed");     // sẽ KHÔNG ảnh hưởng đến DB
managed.setName("Changed");      // sẽ ảnh hưởng (dirty checking)
```

SELECT là cần thiết để Hibernate có thể kiểm tra: (1) bản ghi có tồn tại trong DB không,
(2) tải trạng thái hiện tại cho dirty checking. Không có SELECT, Hibernate
không biết cần cập nhật cái gì.

#### detach() / evict()

```java
User user = entityManager.find(User.class, 1L);  // Persistent
entityManager.detach(user);  // user -> Detached
// user.getId() vẫn = 1
// Nhưng các thay đổi không còn được theo dõi

// Tương đương đặc thù Hibernate:
Session session = entityManager.unwrap(Session.class);
session.evict(user);
```

#### refresh()

```java
User user = entityManager.find(User.class, 1L);
// Một transaction khác đã thay đổi user trong DB
entityManager.refresh(user);  // tải lại từ DB
// Bây giờ user có các giá trị thực tế
```

### Các Lỗi Thường Gặp

```java
// Truyền detached entity vào persist
User user = new User();
user.setId(1L);  // ID được đặt thủ công
entityManager.persist(user);  // EntityExistsException

// Đúng
User merged = entityManager.merge(user);

// Bỏ qua giá trị trả về của merge()
entityManager.merge(detached);  // kết quả bị mất!
detached.setName("Changed");    // KHÔNG được lưu

// Đúng
User managed = entityManager.merge(detached);
managed.setName("Changed");  // sẽ được lưu

// merge() cho persistent
User user = entityManager.find(User.class, 1L);  // đã là persistent
entityManager.merge(user);  // SELECT thừa!
```

## Senior Level

### Triển Khai Nội Bộ

```
Cấu Trúc Persistence Context:

EntityManagerImpl {
    persistenceContext: StatefulPersistenceContext {
        entitiesByKey: Map<EntityKey, Object>,
        entityEntries: Map<Object, EntityEntry>,
    }
}

EntityEntry lưu trữ:
- loadedState - snapshot tại thời điểm tải
- status - MANAGED, DELETED, READ_ONLY, v.v.
- id - định danh
- version - cho optimistic locking
- lazyPropertiesAreUninitialized - cờ lazy loading
```

### Đảm Bảo Identity

```
Trong một session duy nhất, Hibernate đảm bảo:
- Với một ID trong DB, có chính xác một object trong bộ nhớ
- entityManager.find(User.class, 1L) luôn trả về cùng một object

User user1 = entityManager.find(User.class, 1L);
User user2 = entityManager.find(User.class, 1L);
assert user1 == user2;  // true (identity)

Điều này quan trọng cho:
- dirty checking (một object được theo dõi một lần)
- tính nhất quán dữ liệu trong một transaction
```

### Nhận Định Của Senior: Sự Kỳ Diệu Của Merge

```
Khi bạn gọi em.merge(detachedObject):

1. Kiểm tra: có entity với ID này trong persistence context không?
   -> Có: sao chép trạng thái từ detached sang managed
   -> Không: tải từ DB (SELECT)

2. Nếu không có trong DB - tạo managed mới (INSERT khi flush)

3. Sao chép tất cả các trường từ detachedObject sang managed

4. Trả về object managed

5. detachedObject vẫn là detached!
   Tất cả các hành động tiếp theo - với object được trả về!

Quan trọng: merge() có thể gây ra SELECT trước INSERT/UPDATE
```

### Tối Ưu Cho Dữ Liệu Lớn

```java
@Transactional
public void batchImport(List<User> users) {
    int batchSize = 50;
    for (int i = 0; i < users.size(); i++) {
        entityManager.persist(users.get(i));

        if (i % batchSize == 0 && i > 0) {
            entityManager.flush();    // flush vào DB
            entityManager.clear();    // xóa persistence context
        }
    }
}
```

### Best Practices

```
Hiểu các trạng thái entity
persist() cho entity mới
merge() cho detached (dùng giá trị trả về!)
Tránh lưu trữ lâu dài các object detached
Dùng entityManager.contains() để kiểm tra trạng thái
clear() cho các thao tác batch lớn

persist() với ID đã đặt
merge() cho persistent (SELECT thừa)
Bỏ qua giá trị trả về của merge()
Truy cập trường lazy trên các object detached
Truyền các object detached giữa các thread
```

## Interview Cheat Sheet

**Cần phải biết:**
- Transient: object mới, chưa có trong DB, Hibernate không theo dõi
- Persistent: có trong DB, có trong persistence context, dirty checking hoạt động
- Detached: có trong DB, nhưng KHÔNG có trong persistence context, thay đổi không được theo dõi
- Removed: đánh dấu để xóa, DELETE khi flush
- persist() - Transient -> Persistent, merge() - Detached -> Persistent (trả về một bản sao!)
- entityManager.contains() kiểm tra xem entity có được quản lý không
- Đảm bảo Identity: trong một session, một ID = một object trong bộ nhớ

**Các câu hỏi phụ thường gặp:**
- **Cách kiểm tra trạng thái?** ID null -> Transient, contains() true -> Persistent, contains() false + ID tồn tại -> Detached
- **Tại sao merge() trả về một object mới?** Bản gốc detached vẫn là detached, Hibernate tạo bản sao managed
- **Đảm bảo Identity là gì?** Trong một session, Hibernate đảm bảo một ID = một object trong bộ nhớ
- **Khi nào cần detach()?** Để giải phóng bộ nhớ, trong các thao tác batch, để xử lý dữ liệu lớn

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "persist() cho object có ID đã đặt" - EntityExistsException
- "merge() cho persistent - vẫn ổn" - SELECT thừa
- "Các object detached có thể sửa trực tiếp" - cần merge()
- "Tôi truyền các object detached giữa các thread" - không thread-safe

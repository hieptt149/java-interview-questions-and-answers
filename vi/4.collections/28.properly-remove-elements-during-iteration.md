# How to properly remove elements during iteration? (Cách xóa các phần tử đúng cách trong lúc iterate?)

## 🟢 Junior Level

**Quy tắc:** KHÔNG xóa thông qua `list.remove()` trong một vòng lặp!

```java
// ❌ ConcurrentModificationException!
for (String s : list) {
    list.remove(s);
}

// ✅ Iterator.remove()
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (condition(it.next())) {
        it.remove();  // An toàn!
    }
}

// ✅ removeIf (Java 8+) — cách tốt nhất!
list.removeIf(e -> condition(e));
```

---

## 🟡 Middle Level

### So sánh các cách tiếp cận

| Phương pháp           | ArrayList     | LinkedList    | An toàn?     |
| --------------------- | ------------- | ------------- | ------------ |
| **for-each + remove** | ❌ CME         | ❌ CME         | Không        |
| **Iterator.remove()** | O(n²)         | O(n)          | ✅ Có         |
| **removeIf()**        | O(n)          | O(n)          | ✅ Có         |
| **Vòng lặp ngược**    | O(n²)         | O(n²)         | ✅ Có         |
| **Stream + filter**   | O(n) + bộ nhớ | O(n) + bộ nhớ | ✅ Có         |

### removeIf — người chiến thắng

```java
// O(n) cho ArrayList:
// 1. Tìm phần tử đầu tiên cần xóa
// 2. Dịch chuyển phần còn lại MỘT LẦN
list.removeIf(e -> e.startsWith("A"));
```

`Iterator.remove()` cho ArrayList dịch chuyển tất cả các phần tử sau phần tử bị xóa ở mỗi lời gọi (System.arraycopy). Xóa N phần tử = N lần dịch chuyển = O(n^2). `removeIf()` thực hiện một lần duyệt với một lần dịch chuyển = O(n).

### LinkedList + Iterator

```java
// Sau next(), iterator đã ở tại node
// remove() = O(1) — nối lại các tham chiếu
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (condition(it.next())) {
        it.remove();  // O(1) cho LinkedList!
    }
}
// Tổng cộng: O(n)
```

## 🔴 Senior Level

### ArrayList.removeIf bên trong

```java
// Tối ưu hóa Java 9+:
// 1. Tìm phần tử đầu tiên cần xóa
// 2. Trước nó — KHÔNG động vào mảng
// 3. Sau đó — dịch chuyển trong O(n) một lần
// → Ghi bộ nhớ tối thiểu!
```

Trong Java 8, `removeIf` cho ArrayList cũng là O(n), nhưng không có tối ưu hóa "ghi tối thiểu" — nó có thể thực hiện sao chép thừa. Trong Java 9+, thuật toán được cải thiện: trước tiên nó đánh dấu các phần tử cần xóa, sau đó thực hiện một lần dịch chuyển duy nhất.

### Đa luồng

```java
// CopyOnWriteArrayList:
// Có thể xóa trong for-each (iterator = snapshot)
// NHƯNG: mỗi lần xóa = sao chép mảng!

// ConcurrentHashMap:
// iterator.remove() là an toàn
// Weakly consistent → không crash
```

### Kinh nghiệm Production

**Tình huống thực tế: O(n²) giết chết hiệu năng**
```java
// 1 triệu phần tử, xóa 50%
// Iterator.remove(): 10 phút!
// removeIf(): 50 ms

// Lý do: Iterator.remove() = System.arraycopy MỖI lần
```

### Best Practices

1. **removeIf** — theo mặc định (Java 8+)
2. **Iterator.remove()** — nếu cần logic bổ sung
3. **Đừng xóa** trong for-each cho các collection thông thường (ArrayList, LinkedList, HashSet) — bạn sẽ nhận được CME. Ngoại lệ: CopyOnWriteArrayList — for-each an toàn, nhưng iterator sẽ không nhìn thấy các lần xóa (snapshot).
4. **LinkedList** → Iterator là lý tưởng
5. **Stream + filter** → list mới, không phải mutation
6. **Vòng lặp ngược** → hoạt động, nhưng O(n²)

### Tóm tắt cho Senior

- **removeIf** = O(n), lựa chọn tốt nhất
- **Iterator.remove()** = O(n²) cho ArrayList, O(n) cho LinkedList
- **for-each + remove** = CME
- **ArrayList.removeIf** → ghi tối thiểu
- **Stream** → list mới, cách tiếp cận immutable

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `for-each + list.remove()` = `ConcurrentModificationException` được đảm bảo
- `removeIf()` (Java 8+) — cách tiếp cận tốt nhất: O(n) cho ArrayList, một `System.arraycopy` duy nhất
- `Iterator.remove()` cho ArrayList = O(n^2) (System.arraycopy mỗi lần), cho LinkedList = O(n)
- Vòng lặp ngược `for (int i = size-1; i >= 0; i--)` — hoạt động, nhưng O(n^2) cho ArrayList
- Stream + filter tạo một list mới, không làm biến đổi bản gốc (cách tiếp cận immutable)
- CopyOnWriteArrayList cho phép xóa trong for-each (snapshot iterator), nhưng mỗi lần xóa = sao chép mảng
- Tối ưu hóa `removeIf` của Java 9+: trước tiên đánh dấu, sau đó dịch chuyển một lần — ghi tối thiểu

**Các câu hỏi phụ thường gặp:**
- *Tại sao Iterator.remove() = O(n^2) cho ArrayList?* — Mỗi lời gọi thực hiện một `System.arraycopy` để dịch chuyển các phần tử; N lần xóa = N lần dịch chuyển.
- *Tại sao removeIf() nhanh hơn Iterator.remove() cho ArrayList?* — Một lần duyệt, một `System.arraycopy` duy nhất thay vì N lần dịch chuyển riêng biệt.
- *Có thể xóa các phần tử trong một vòng lặp for-each không?* — Chỉ với CopyOnWriteArrayList (snapshot iterator), nhưng nó tốn kém về bộ nhớ.
- *Cách tiếp cận nào để xóa 50% của 1 triệu phần tử?* — `removeIf()`: 50 ms thay vì 10 phút cho `Iterator.remove()`.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Bạn có thể xóa thông qua `list.remove()` bên trong for-each" — không, đó là một CME được đảm bảo
- "Iterator.remove() hiệu quả như removeIf() cho ArrayList" — không, O(n^2) so với O(n)
- "CopyOnWriteArrayList là cách tốt nhất để xóa trong lúc iterate" — không, mỗi sửa đổi sao chép toàn bộ mảng
- "Stream.filter làm biến đổi collection gốc" — không, nó tạo một list mới

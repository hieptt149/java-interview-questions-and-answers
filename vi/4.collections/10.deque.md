# What is Deque? (Deque là gì?)

## 🟢 Junior Level

**Deque (Double-Ended Queue)** — hàng đợi nơi bạn có thể thêm và xóa các phần tử **từ cả hai đầu**.

**Ví dụ minh họa:** Bộ bài — bạn có thể lấy lá bài từ trên cùng hoặc dưới cùng, đặt lên trên cùng hoặc dưới cùng.

**Ví dụ minh họa đơn giản:** Hàng đợi hai chiều ở công viên giải trí — có thể vào và ra từ cả hai đầu.

**Deque = Stack + Queue:**
```java
Deque<String> deque = new ArrayDeque<>();

// Như một stack (LIFO):
deque.push("A");     // Đẩy lên trên cùng
deque.pop();         // Lấy ra từ trên cùng

// Như một queue (FIFO):
deque.offer("A");    // Vào cuối
deque.poll();        // Từ đầu

// Từ cả hai đầu:
deque.addFirst("A"); // Vào đầu
deque.addLast("B");  // Vào cuối
deque.removeFirst(); // Xóa đầu
deque.removeLast();  // Xóa cuối
```

## 🟡 Middle Level

### ArrayDeque: cài đặt tốt nhất

```java
// Circular Buffer (bộ đệm vòng)
Deque<String> deque = new ArrayDeque<>();

// Các thao tác: O(1) phân bổ (amortized)
deque.addFirst("A");   // O(1)
deque.addLast("B");    // O(1)
deque.removeFirst();   // O(1)
deque.removeLast();    // O(1)
deque.peekFirst();     // O(1)
deque.peekLast();      // O(1)
```

### Tại sao ArrayDeque tốt hơn LinkedList

|                   | ArrayDeque                                                                                                              | LinkedList           |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------- |
| **Bộ nhớ**        | Mảng (ít)                                                                                                              | Các đối tượng Node (nhiều) |
| **Cache locality**| Xuất sắc                                                                                                               | Tệ hại               |
| **Cấp phát**      | Khi resize                                                                                                             | Ở mỗi lần chèn        |
| **Áp lực GC**     | Thấp                                                                                                                   | Cao                  |
| **Tốc độ**        | Theo các benchmark JMH: ArrayDeque nhanh hơn LinkedList 3-10 lần khi iterate, 2-5 lần khi chèn/xóa.                     |                      |

### Deque như một Stack

```java
// ❌ Đừng dùng Stack
Stack<String> stack = new Stack<>();

// ✅ Hãy dùng Deque
Deque<String> stack = new ArrayDeque<>();
stack.push("A");
stack.pop();
stack.peek();
```

### Java 21: SequencedCollection

// Java 21 không có sẵn ở mọi nơi. Với Java 11/17 hãy dùng `deque.peekFirst()` thay cho `getFirst()` và `deque.peekLast()` thay cho `getLast()`.

```java
// Deque giờ đây là SequencedCollection
deque.getFirst();    // Phương thức mới!
deque.getLast();     // Phương thức mới!
deque.reversed();    // Thứ tự đảo ngược (view)

// Thứ tự iterate được đảm bảo
for (String s : deque) { ... }  // Từ đầu đến cuối
for (String s : deque.reversed()) { ... }  // Ngược lại
```

## 🔴 Senior Level

### Circular Buffer (bộ đệm vòng)

```
Mảng: [A][B][C][ ][ ][ ][ ][ ]
       ↑head         ↑tail

addLast(D):
[A][B][C][D][ ][ ][ ][ ]
        ↑head      ↑tail

removeFirst():
[ ][B][C][D][ ][ ][ ][ ]
   ↑head      ↑tail

tail đến cuối → quay vòng (wrap around):
[ ][B][C][D][E][F][ ][ ]
   ↑head               ↑tail

Index: (tail + 1) & (length - 1)  // Bitwise AND!
```

### Bitmask thay vì phép chia

```java
// Index vòng thông thường:
index = (index + 1) % capacity;  // Phép chia — chậm!

// ArrayDeque (capacity = lũy thừa của 2):
index = (index + 1) & (elements.length - 1);  // AND — nhanh!

// Ví dụ: capacity = 8 (1000 ở dạng nhị phân)
// (7 + 1) & 7 = 8 & 7 = 0  ← Đã quay vòng!

// Tại sao lũy thừa của 2?
// 8 = 1000, 7 = 0111
// x & 7 = x % 8  (với x < 16)
// → Một lệnh CPU thay vì phép chia!
```

**Đánh đổi:** lũy thừa của 2 nghĩa là mảng chỉ có thể đầy 50-75% trước khi resize (để phân biệt "đầy" với "rỗng"). Điều này lãng phí một chút bộ nhớ, nhưng khoản tiết kiệm từ việc bỏ phép chia là đáng giá.

### Tại sao ArrayDeque cấm null?

```java
deque.offer(null);  // → NullPointerException!

// Tại sao?
// poll() và peek() trả về null cho deque rỗng
// Nếu null là một phần tử hợp lệ → không thể phân biệt!

// Đây là quyết định về kiến trúc, không phải một bug!
```

### Concurrency

```java
// ArrayDeque KHÔNG thread-safe!

// Deque lock-free:
Deque<String> deque = new ConcurrentLinkedDeque<>();

// Blocking Deque (Work Stealing):
BlockingDeque<String> deque = new LinkedBlockingDeque<>();
// → Các luồng có thể "đánh cắp" (steal) tác vụ từ tail
// → ForkJoinPool dùng điều này!

// **Work Stealing** — thuật toán cân bằng tải: khi một luồng hoàn thành hàng đợi tác vụ của mình, nó "đánh cắp" các tác vụ từ tail của hàng đợi của một luồng khác. Điều này ngăn một luồng bị quá tải trong khi luồng khác nhàn rỗi. Được dùng trong ForkJoinPool.
```

### Kinh nghiệm Production

**Trường hợp thực tế: LinkedList → ArrayDeque**
- Hàng đợi tin nhắn: LinkedList
- GC mỗi 2 giây (cấp phát Node)
- Giải pháp: ArrayDeque
- Kết quả: GC mỗi phút một lần, +50% throughput

### Best Practices

1. **ArrayDeque** — cho các stack và queue
2. **Cấm null** — hạn chế về kiến trúc
3. **Lũy thừa của 2** → bitmask thay vì phép chia
4. **Java 21** → getFirst(), getLast(), reversed()
5. **ConcurrentLinkedDeque** — lock-free
6. **LinkedBlockingDeque** — Work Stealing
7. **KHÔNG dùng** Stack hoặc LinkedList

### Tóm tắt cho Senior

- **Deque** = hàng đợi hai đầu (LIFO + FIFO)
- **ArrayDeque** = circular buffer, capacity = 2^n
- **Bitmask** → (index + 1) & (length - 1)
- **null bị cấm** → poll/peek không mơ hồ
- **Cache locality** >> LinkedList
- **SequencedCollection (Java 21)** → getFirst/reversed
- **Work Stealing** → LinkedBlockingDeque
- **KHÔNG BAO GIỜ** dùng Stack

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Deque (Double-Ended Queue) = hàng đợi hai đầu, hỗ trợ LIFO + FIFO
- ArrayDeque — cài đặt tốt nhất: circular buffer, O(1) phân bổ cho tất cả các thao tác trên cả hai đầu
- ArrayDeque tốt hơn LinkedList: nhanh hơn 3-10 lần khi iterate, 2-5 lần khi chèn/xóa, ít áp lực GC hơn
- Circular buffer: capacity = lũy thừa của 2 → bitmask thay vì phép chia ((index + 1) & (length - 1))
- ArrayDeque cấm null — quyết định về kiến trúc (poll/peek trả về null cho deque rỗng)
- Java 21: SequencedCollection → getFirst(), getLast(), reversed() cho Deque
- Concurrency: ConcurrentLinkedDeque (lock-free), LinkedBlockingDeque (Work Stealing, ForkJoinPool)
- ArrayDeque thay thế Stack: push/pop/peek — cùng các phương thức, không có overhead của synchronized và vi phạm LSP

**Các câu hỏi phụ thường gặp:**
- Tại sao ArrayDeque dùng capacity = lũy thừa của 2? — Để dùng bitmask: (index + 1) & (length - 1) thay vì phép chia % chậm
- Tại sao ArrayDeque cấm null? — poll()/peek() trả về null cho deque rỗng, phần tử null sẽ tạo ra sự mơ hồ
- Work Stealing là gì? — Các luồng "đánh cắp" tác vụ từ tail của các hàng đợi khác, cân bằng tải trong ForkJoinPool
- Deque khác Queue như thế nào? — Deque hỗ trợ các thao tác trên cả hai đầu, Queue — chỉ một đầu (FIFO)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "LinkedList — cài đặt Deque tốt" — ArrayDeque luôn tốt hơn (cache locality, ít bộ nhớ hơn)
- ❌ "ArrayDeque có thể được dùng làm key của Map" — Deque không có hợp đồng hashCode/equals cho các key
- ❌ "Deque có thể chứa null" — ArrayDeque cấm null, đây là quyết định về kiến trúc
- ❌ "Hãy dùng Stack như một stack" — ArrayDeque thay thế Stack mà không có overhead của synchronized và vi phạm LSP

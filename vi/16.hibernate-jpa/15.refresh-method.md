# What Does the refresh() Method Do (Phương thức refresh() làm gì)

## Overview

Phương thức `refresh()` tải lại một entity từ database, thay thế các giá trị hiện tại trong bộ nhớ bằng dữ liệu thực tế từ DB. Điều này hữu ích khi làm việc với trigger, cập nhật đồng thời, và khi cần đảm bảo dữ liệu tươi mới.

---

## Junior Level

### refresh() Làm Gì

`refresh()` - tải lại một entity từ database, thay thế các giá trị hiện tại trong bộ nhớ.

```java
User user = entityManager.find(User.class, 1L);
user.setName("Changed in memory");  // thay đổi trong bộ nhớ

// Một transaction khác đã thay đổi DB
// Hoặc một trigger đã thay đổi dữ liệu

entityManager.refresh(user);  // tải lại từ DB
// Bây giờ user có các giá trị thực tế từ DB
// "Changed in memory" - bị ghi đè
```

### Khi Nào Dùng

1. **Sau các trigger** - database thay đổi các trường thông qua trigger
2. **Trong khi cập nhật đồng thời** - một transaction khác đã cập nhật dữ liệu
3. **Để lấy dữ liệu thực tế** - khi có nghi ngờ về độ tươi mới

### refresh vs detach

```
refresh() - cập nhật dữ liệu từ DB (entity vẫn managed)
detach()  - ngắt kết nối entity (không cập nhật DB)
```

### Ví Dụ

```java
@Transactional
public void updateUser(User user) {
    entityManager.persist(user);
    // Trigger trong DB đặt created_at
    entityManager.refresh(user);
    // Bây giờ user.getCreatedAt() chứa giá trị từ DB
}
```

## Middle Level

### Cách Dùng Chi Tiết

```java
// Sau trigger
User user = new User();
user.setName("John");
entityManager.persist(user);
// flush -> trigger trong DB đặt created_at
entityManager.flush();
entityManager.refresh(user);  // lấy created_at từ DB

// Trong khi cập nhật đồng thời
User user = entityManager.find(User.class, 1L);
// Một transaction khác đã cập nhật user
entityManager.refresh(user);  // đồng bộ với DB
```

### refresh Với LockMode

```java
// OPTIMISTIC - kiểm tra version
entityManager.refresh(user, LockModeType.OPTIMISTIC);

// PESSIMISTIC_READ - khóa đọc
entityManager.refresh(user, LockModeType.PESSIMISTIC_READ);

// PESSIMISTIC_WRITE - khóa ghi
entityManager.refresh(user, LockModeType.PESSIMISTIC_WRITE);

// Với timeout
Map<String, Object> properties = Map.of(
    "jakarta.persistence.lock.timeout", 5000
);
entityManager.refresh(user, LockModeType.PESSIMISTIC_WRITE, properties);
```

### Các Lỗi Thường Gặp

```java
// refresh không có lý do
User user = entityManager.find(User.class, 1L);
entityManager.refresh(user);  // SELECT thừa!

// refresh cho detached
User detached = getDetachedUser();
entityManager.refresh(detached);  // IllegalArgumentException

// refresh chỉ cho managed
User managed = entityManager.find(User.class, 1L);
entityManager.refresh(managed);  // đúng
```

### Khi Nào KHÔNG Cần refresh

```java
// Không cần sau persist nếu không có trigger/cột generated trong DB. Nếu trigger đặt các trường - cần refresh (xem ví dụ Junior).
User user = new User();
entityManager.persist(user);
entityManager.refresh(user);  // dữ liệu giống nhau

// Không cần sau merge
User managed = entityManager.merge(detached);
entityManager.refresh(managed);  // dữ liệu đã thực tế rồi

// Cần sau các trigger
entityManager.persist(user);
entityManager.flush();
entityManager.refresh(user);  // trigger có thể đã thay đổi dữ liệu
```

## Senior Level

### Triển Khai Nội Bộ

```
refresh():
1. Kiểm tra entity là managed (không phải detached)
2. Thực thi SELECT * FROM table WHERE id = ?
3. Cập nhật tất cả các trường entity từ kết quả
4. Cập nhật snapshot trong persistence context
5. Cập nhật EntityEntry

Nếu LockMode được chỉ định:
- Thêm mệnh đề LOCK vào SELECT
- Kiểm tra version cho OPTIMISTIC
```

### refresh Và Sinh ID

```java
@Entity
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(insertable = false, updatable = false)
    private LocalDateTime createdAt;  // được đặt bởi trigger
}

User user = new User();
entityManager.persist(user);
entityManager.flush();
entityManager.refresh(user);  // lấy createdAt từ DB
```

### refresh Và Lazy Loading

```java
User user = entityManager.find(User.class, 1L);
user.getOrders().size();  // tải collection

// Một transaction khác đã thay đổi collection
entityManager.refresh(user);  // tải lại MỌI THỨ bao gồm cả collection

// Hoặc chỉ collection
entityManager.refresh(user, Map.of(
    "org.hibernate.refreshMode", RefreshMode.FETCH
));
// (Khả dụng trong Hibernate 6+)
```

### Các Pattern Nâng Cao

```java
// Pattern: refresh sau bulk update
@Modifying
@Query("UPDATE User u SET u.status = :status WHERE u.age > :age")
int bulkUpdate(@Param("status") String status, @Param("age") int age);

// Sau bulk update - refresh các entity bị ảnh hưởng
User user = entityManager.find(User.class, userId);
entityManager.refresh(user);  // lấy dữ liệu thực tế
```

### Best Practices

```
refresh() sau các trigger DB
refresh() trong khi thay đổi đồng thời
Với LockMode khi cần khóa
flush() trước refresh để đồng bộ

refresh() không có lý do (SELECT thừa)
refresh() cho các entity detached
refresh() thay cho dirty checking
refresh() sau persist/merge mà không cần thiết
```

## Interview Cheat Sheet

**Cần phải biết:**
- refresh() tải lại một entity từ DB, thay thế các giá trị hiện tại
- Dùng sau các trigger, trong khi cập nhật đồng thời, để có dữ liệu tươi mới
- Hỗ trợ LockMode: OPTIMISTIC, PESSIMISTIC_READ, PESSIMISTIC_WRITE
- Chỉ hoạt động cho các entity managed, cho detached - IllegalArgumentException
- Trong Hibernate 6+ có RefreshMode.FETCH để chỉ tải collection

**Các câu hỏi phụ thường gặp:**
- **Khi nào cần refresh()?** Sau các trigger DB, trong khi thay đổi đồng thời, sau bulk update
- **refresh vs detach?** refresh - cập nhật dữ liệu từ DB (vẫn managed), detach - ngắt kết nối (không cập nhật)
- **Tại sao refresh sau persist vô ích?** Dữ liệu chưa thay đổi, SELECT thừa
- **refresh có thể có timeout không?** Có, thông qua properties: jakarta.persistence.lock.timeout

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "refresh() sau mỗi persist" - SELECT thừa, dữ liệu giống nhau
- "refresh() cho detached" - IllegalArgumentException
- "refresh() thay cho dirty checking" - dirty checking tự động, refresh là bắt buộc
- "Tôi không hiểu khi nào cần refresh" - chỉ trigger, thay đổi đồng thời, bulk update

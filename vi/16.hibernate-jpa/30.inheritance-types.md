# What Inheritance Types Does JPA Support (JPA hỗ trợ những loại Inheritance nào)

## Overview

JPA hỗ trợ ba chiến lược inheritance entity, mỗi chiến lược ánh xạ hệ thống phân cấp class sang các table database theo cách khác nhau. Việc chọn chiến lược ảnh hưởng đến hiệu năng, chuẩn hóa, và độ phức tạp truy vấn.

---

## Junior Level

### 3 Chiến Lược Inheritance

JPA hỗ trợ **3 chiến lược inheritance**:

1. **SINGLE_TABLE** - tất cả các class trong một table
2. **JOINED** - mỗi class trong table riêng với JOIN
3. **TABLE_PER_CLASS** - mỗi class trong table riêng (không có JOIN)

```java
@Entity
@Inheritance(strategy = InheritanceType.SINGLE_TABLE)
@DiscriminatorColumn(name = "type")
public class Payment {
    @Id
    private Long id;
    private BigDecimal amount;
}

@Entity
@DiscriminatorValue("CARD")
public class CardPayment extends Payment {
    private String cardNumber;
}

@Entity
@DiscriminatorValue("CASH")
public class CashPayment extends Payment {
    private LocalDate cashDate;
}
```

## Middle Level

### SINGLE_TABLE

```
Table payments:
id | type | amount | card_number | cash_date
1  | CARD | 100    | 1234        | null
2  | CASH | 50     | null        | 2024-01-01

Nhanh (không có JOIN)
Truy vấn đơn giản
Nhiều NULL cho các subclass
Không thể thêm ràng buộc NOT NULL
```

```java
@Entity
@Inheritance(strategy = InheritanceType.SINGLE_TABLE)
@DiscriminatorColumn(name = "payment_type")
public abstract class Payment { }

@Entity
@DiscriminatorValue("CARD")
public class CardPayment extends Payment { }
```

### JOINED

```
Table payments:
id | amount
1  | 100
2  | 50

Table card_payments:
payment_id | card_number
1          | 1234

Table cash_payments:
payment_id | cash_date
2          | 2024-01-01

Chuẩn hóa
Có thể có ràng buộc NOT NULL
JOIN cho mỗi truy vấn
Chậm hơn khi truy xuất
```

```java
@Entity
@Inheritance(strategy = InheritanceType.JOINED)
public abstract class Payment { }

@Entity
@PrimaryKeyJoinColumn(name = "payment_id")
public class CardPayment extends Payment { }
```

### TABLE_PER_CLASS

```
Table card_payments:
id | amount | card_number
1  | 100    | 1234

Table cash_payments:
id | amount | cash_date
2  | 50     | 2024-01-01

Không có NULL, không có JOIN cho loại cụ thể
UNION cho truy vấn parent
Truy vấn parent phức tạp
```

```java
@Entity
@Inheritance(strategy = InheritanceType.TABLE_PER_CLASS)
public abstract class Payment { }

@Entity
public class CardPayment extends Payment { }
```

TABLE_PER_CLASS là tùy chọn trong đặc tả JPA. Không phải tất cả provider đều hỗ trợ nó. Hibernate hỗ trợ nó, nhưng để đảm bảo tính portable hãy kiểm tra provider của bạn.

### Các Lỗi Thường Gặp

```java
// SINGLE_TABLE với nhiều subclass
// Nhiều trường, nhiều NULL -> khó bảo trì

// JOINED cho hiệu năng cao
// JOIN cho mỗi truy vấn -> chậm

// TABLE_PER_CLASS với truy vấn polymorphic
// UNION cho SELECT FROM Payment -> chậm
```

## Senior Level

### So Sánh Chiến Lược

| Chiến lược      | INSERT   | SELECT (loại cụ thể)                                                          | SELECT (parent)     | NULL   | JOIN   | Polymorphism |
| --------------- | -------- | ----------------------------------------------------------------------------- | ------------------- | ------ | ------ | ----------- |
| SINGLE_TABLE    | Nhanh    | Nhanh                                                                          | Nhanh                | Nhiều  | Không  | Có           |
| JOINED          | Chậm     | Chậm                                                                           | Chậm                 | Không  | Có     | Có           |
| TABLE_PER_CLASS | Nhanh    | Nhanh (cho subclass cụ thể). Chậm (UNION ALL trên truy vấn parent)            | UNION                | Không  | Không  | Hạn chế       |

### Khi Nào Dùng Cái Gì

```
SINGLE_TABLE:
Hệ thống phân cấp nhỏ (2-3 subclass)
Các trường subclass có thể NULL
Cần hiệu năng cao
Truy vấn polymorphic thường xuyên

JOINED:
Chuẩn hóa quan trọng
Các trường subclass NOT NULL
Truy vấn polymorphic hiếm
Các subclass khác nhau có nhiều trường

TABLE_PER_CLASS:
Mỗi subclass là entity độc lập
Truy vấn polymorphic hiếm
Không có trường chung giữa các subclass
```

### Truy Vấn Polymorphic

```java
// SINGLE_TABLE - một truy vấn
SELECT p FROM Payment p  // SELECT * FROM payments

// JOINED - JOIN tất cả các table
SELECT p FROM Payment p  // SELECT * FROM payments p
                          // LEFT JOIN card_payments cp ON ...
                          // LEFT JOIN cash_payments cash ON ...

// TABLE_PER_CLASS - UNION
SELECT p FROM Payment p  // SELECT * FROM card_payments
                          // UNION ALL
                          // SELECT * FROM cash_payments
```

### TYPE Và TREAT Trong JPQL

```java
// TYPE - lọc theo loại
@Query("SELECT p FROM Payment p WHERE TYPE(p) = CardPayment")
List<CardPayment> findCardPayments();

// TREAT - cast sang subclass
@Query("SELECT p FROM Payment p JOIN TREAT(p AS CardPayment) cp WHERE cp.cardNumber = :number")
List<Payment> findByCardNumber(@Param("number") String number);
```

### Các Cải Tiến Của Hibernate 6

```
Hibernate 6:
- Cải thiện xử lý TABLE_PER_CLASS
- Tối ưu JOIN tốt hơn cho JOINED
- Discriminator tự động cho SINGLE_TABLE
```

### Các Pattern Nâng Cao

```java
// Pattern: @MappedSuperclass cho các trường chung
@MappedSuperclass
public abstract class BaseEntity {
    @Id
    private Long id;
    private LocalDateTime createdAt;
}

@Entity
public class CardPayment extends BaseEntity { }

@Entity
public class CashPayment extends BaseEntity { }
// Mỗi entity - table riêng biệt
// Không có truy vấn polymorphic
```

@MappedSuperclass - KHÔNG phải một entity: không thể truy vấn nó, không có table, không thể dùng trong các truy vấn polymorphic. Nó chỉ là một mẫu cho các trường chung. Bẫy phỏng vấn kinh điển: "@MappedSuperclass khác với @Entity như thế nào?"

### Best Practices

```
SINGLE_TABLE cho các trường hợp đơn giản (2-3 subclass)
JOINED cho chuẩn hóa và NOT NULL
TABLE_PER_CLASS cho các subclass độc lập
Tránh các hệ thống phân cấp inheritance sâu (>3 cấp). Lý do: hệ thống phân cấp sâu làm phức tạp truy vấn (nhiều JOIN hơn trong JOINED, nhiều cột hơn trong SINGLE_TABLE, nhiều nhánh UNION hơn trong TABLE_PER_CLASS), làm domain model khó hiểu hơn, và tạo ra các vấn đề dây chuyền khi thay đổi.
@MappedSuperclass khi không cần polymorphism
TYPE/TREAT cho các truy vấn có kiểu

SINGLE_TABLE với nhiều subclass
JOINED cho hệ thống hiệu năng cao
TABLE_PER_CLASS với truy vấn polymorphic thường xuyên
Hệ thống phân cấp inheritance sâu
```

## Interview Cheat Sheet

**Cần phải biết:**
- 3 chiến lược: SINGLE_TABLE (một table), JOINED (table mỗi class), TABLE_PER_CLASS (table mỗi class, UNION cho parent)
- SINGLE_TABLE - nhanh (không có JOIN), nhưng nhiều NULL, không thể dùng ràng buộc NOT NULL
- JOINED - chuẩn hóa, có thể NOT NULL, nhưng JOIN cho mỗi truy vấn - chậm
- TABLE_PER_CLASS - không có NULL/JOIN cho loại cụ thể, nhưng UNION cho các truy vấn polymorphic
- @MappedSuperclass - KHÔNG phải entity, không có table, không có truy vấn polymorphic - mẫu cho các trường chung
- TYPE để lọc theo loại, TREAT để cast sang subclass trong JPQL

**Các câu hỏi phụ thường gặp:**
- **Nên chọn chiến lược nào?** SINGLE_TABLE cho 2-3 subclass và tốc độ; JOINED cho chuẩn hóa; TABLE_PER_CLASS cho các subclass độc lập
- **Tại sao hệ thống phân cấp sâu xấu?** Nhiều JOIN hơn (JOINED), nhiều cột hơn (SINGLE_TABLE), nhiều UNION hơn (TABLE_PER_CLASS)
- **@MappedSuperclass vs @Entity với inheritance?** @MappedSuperclass - không có truy vấn polymorphic, không có table; @Entity - có cả hai
- **TABLE_PER_CLASS có tùy chọn trong đặc tả JPA không?** Có - không phải tất cả provider hỗ trợ nó, Hibernate thì có

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "SINGLE_TABLE với 10 subclass" - nhiều NULL, khó bảo trì
- "JOINED cho hệ thống hiệu năng cao" - JOIN cho mỗi truy vấn, chậm
- "TABLE_PER_CLASS với truy vấn polymorphic thường xuyên" - UNION ALL, thậm chí chậm hơn
- "@MappedSuperclass cho truy vấn polymorphic" - không thể truy vấn @MappedSuperclass

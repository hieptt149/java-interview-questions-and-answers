# Difference Between Creating String via Literal and via new (Sự khác biệt giữa việc tạo String qua literal và qua new)

## 🟢 Junior Level

Có hai cách để tạo một chuỗi trong Java, và chúng hoạt động khác nhau:

**Qua literal (được khuyến nghị):**
```java
String s = "Hello";
```
JVM kiểm tra String Pool. Nếu chuỗi đó đã tồn tại — trả về một tham chiếu đến nó. Nếu chưa — tạo một chuỗi mới trong pool.

**Qua constructor new (không được khuyến nghị):**
```java
String s = new String("Hello");
```
Luôn tạo một object **mới** trong heap thông thường, bỏ qua String Pool cho chính object đó.

**Ví dụ:**
```java
String s1 = "Hello";
String s2 = "Hello";
String s3 = new String("Hello");

System.out.println(s1 == s2); // true  (cùng object trong pool)
System.out.println(s1 == s3); // false (s3 — object riêng biệt)
System.out.println(s1.equals(s3)); // true (nội dung giống nhau)
```

**Khi nào nên dùng:** Trong 99% các trường hợp, hãy dùng literal. Constructor `new String(...)` chủ yếu cần khi chuyển đổi từ byte[]/char[], và cũng trong các trường hợp hiếm khi cần tạo một bản sao độc lập được đảm bảo (defensive copying).

## 🟡 Middle Level

### Cách Nó Hoạt Động Nội Bộ

**Literal:**
```java
String s = "Hello";
```
- Bytecode: lệnh `LDC` (Load Constant)
- JVM kiểm tra String Pool theo hash của chuỗi
- Nếu tìm thấy — trả về tham chiếu, nếu không — tạo object trong pool
- Việc tối ưu hóa xảy ra ở giai đoạn load class

**Constructor:**
```java
String s = new String("Hello");
```
- Bytecode: `NEW` → `DUP` → `LDC "Hello"` → `INVOKESPECIAL`
- Literal `"Hello"` đã ở trong String Pool rồi
- `new String(...)` tạo một object **thứ hai** trong Regular Heap với cùng nội dung
- Kết quả: hai object trong bộ nhớ với văn bản giống hệt nhau

### Các Lỗi Điển Hình
1. **Lỗi:** `new String("literal")` để "đảm bảo tính duy nhất"
   **Giải pháp:** Đây là một antipattern. Tính duy nhất của object String gần như không bao giờ cần thiết

2. **Lỗi:** Nghĩ rằng `new String()` nhanh hơn
   **Giải pháp:** Literal nhanh hơn — chúng dùng pool và không tạo object thừa

### Khi Nào Constructor Thực Sự Cần Thiết
| Trường hợp                   | Ví dụ                    | Giải thích                |
| ---------------------- | --------------------------- | --------------------------- |
| Từ byte[]            | `new String(bytes, UTF_8)` | Cách tiếp cận chính cho I/O      |
| Từ char[]            | `new String(chars)`        | Chuyển đổi ký tự       |
| Từ StringBuffer/Builder | `builder.toString()`    | Lời gọi constructor ngầm định  |

## 🔴 Senior Level

### Hiện Thực Nội Bộ

**Bytecode của literal:**
```
0: ldc           #2  // String Hello
2: astore_1
```
Một lệnh duy nhất — load hằng số từ Constant Pool của class.

**Bytecode của constructor:**
```
0: new           #3  // class java/lang/String    // NEW — cấp phát bộ nhớ cho object String mới
3: dup                                        // DUP — nhân đôi tham chiếu cho constructor
4: ldc           #2  // String Hello            // LDC — load literal từ Constant Pool
6: invokespecial #4  // Method ..."<init>":...  // INVOKESPECIAL — gọi constructor của String
9: astore_1
```
Bốn lệnh: cấp phát bộ nhớ, nhân đôi tham chiếu, load hằng số, gọi constructor.

### Đánh Đổi Về Kiến Trúc (Trade-off)

**Tại sao constructor tồn tại:**
- Về mặt lịch sử: để tạo chuỗi từ dữ liệu thô (byte[], char[], code point int[])
- Trong thực tế: `new String(String original)` sao chép nội dung vào một mảng mới (trong Java 7+), đảm bảo tính độc lập khỏi bản gốc

**Tại sao có thể cần một bản sao độc lập:**
- Trước Java 7u6: `substring()` chia sẻ `char[]` của cha. `new String(substring)` sao chép dữ liệu, giải phóng mảng cha cho GC
- Trong Java hiện đại điều này không còn liên quan — `substring()` luôn sao chép dữ liệu

### Các Trường Hợp Biên

1. **String với intern():**
   ```java
   String s = new String("Hello").intern();
   ```
   Tạo một object trong Heap, sau đó `intern()` kiểm tra pool. Nếu `"Hello"` đã ở trong pool — trả về tham chiếu pool, và object trong Heap trở thành rác.

2. **Constant Folding:**
   ```java
   String s = "Hel" + "lo"; // Compiler gộp cái này thành "Hello" tại thời điểm biên dịch
   ```
   Kết quả sẽ ở trong String Pool, giống như bạn viết `"Hello"`.

3. **Nối chuỗi tại thời điểm chạy:**
   ```java
   String a = "Hel";
   String s = a + "lo"; // KHÔNG trong pool! Được tạo qua invokedynamic/StringBuilder
   ```

### Hiệu Năng
| Thao tác             | Cấp phát               | Thời gian                 | Áp lực GC   |
| --------------------- | ------------------------- | --------------------- | ------------- |
| `"Hello"`             | 0 (nếu đã trong pool)            | ~0                   | Không có      |
| `new String("Hello")` | 1 object + literal trong pool| ~10-20ns             | Trung bình        |
| `"Hello".intern()`    | 0                         | Tra cứu hash table    | Thấp           |

### Kinh Nghiệm Production
Trong các parser JSON/XML, nơi cùng một trường (`"name"`, `"id"`, `"type"`) xuất hiện hàng triệu lần:
- Không có pool: hàng triệu object String → overhead GC đáng kể
- Có pool: hàng chục chuỗi độc nhất → tiết kiệm 90%+ bộ nhớ cho các chuỗi

### Giám Sát
```bash
# Xem số lượng object String
jmap -histo:live <pid> | grep java.lang.String

# Phân tích qua JOL
System.out.println(GraphLayout.parseInstance(s1).toFootprint());

```

### Best Practices
- **Không bao giờ** dùng `new String("literal")` mà không có lý do chính đáng
- Để chuyển một chuỗi từ Heap sang Pool, dùng `.intern()`
- Nếu bạn cần một bản sao độc lập được đảm bảo — `new String(existingString)` (dù điều này hiếm khi cần)

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Literal `String s = "Hello"` — JVM kiểm tra String Pool, trả về tham chiếu từ pool hoặc tạo trong pool
- `new String("Hello")` — luôn tạo một object MỚI trong heap (ngay cả khi literal đã ở trong pool)
- Literal dùng bytecode `LDC`, constructor — `NEW` + `DUP` + `LDC` + `INVOKESPECIAL`
- Constant folding: `"Hel" + "lo"` được compiler gộp thành `"Hello"` tại thời điểm biên dịch
- Nối chuỗi tại thời điểm chạy (`a + "lo"`) — KHÔNG trong pool, được tạo qua `invokedynamic`/`StringBuilder`
- `new String("...")` tạo 2 object: literal trong pool + object trong Heap

**Các câu hỏi phụ thường gặp:**
- **`new String("Hello")` tạo bao nhiêu object?** — Một hoặc hai. Literal `"Hello"` đã ở trong pool (khi class load), `new String()` tạo một object thứ hai trong Heap.
- **Tại sao constructor `new String(String)` lại tồn tại?** — Để tạo một bản sao độc lập (defensive copying). Trước Java 7u6 điều này cần thiết để giải phóng bộ nhớ khỏi mảng dùng chung.
- **Cái nào nhanh hơn: literal hay `new String()`?** — Literal nhanh hơn — 0 cấp phát (nếu đã trong pool). `new String()` — ~10-20ns + áp lực GC.
- **Khi nào cần `new String()` từ byte[]/char[]?** — Đây là cách tiếp cận chính cho I/O: `new String(bytes, UTF_8)`, `new String(chars)`.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "`new String("literal")` tạo ra một chuỗi duy nhất" — tạo một bản trùng lặp, không phải tính duy nhất
- ❌ "Literal và `new String()` — giống nhau" — vị trí bộ nhớ khác nhau
- ❌ "`new String()` nhanh hơn literal" — ngược lại, literal nhanh hơn
- ❌ "Constant folding hoạt động với biến" — chỉ với các hằng số `static final` và literal

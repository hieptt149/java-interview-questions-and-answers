# What Does the @ComponentScan Annotation Do? (Annotation @ComponentScan làm gì?)

## Junior Level

**@ComponentScan** cho Spring biết cần tìm bean (@Component, @Service, @Repository) trong những package nào.

```java
@SpringBootApplication  // Đã bao gồm @ComponentScan
public class Application { }

// Cấu hình thủ công:
@ComponentScan(basePackages = "com.example.services")
```

**Quy tắc:**
- @SpringBootApplication quét package hiện tại và tất cả các sub-package
- Thường không cần cấu hình thủ công

---

## Middle Level

### Quét hoạt động như thế nào

```
ClassPathBeanDefinitionScanner:
  1. Đọc các file .class qua ASM (thư viện để đọc bytecode mà không nạp class vào JVM)
  // Điều này quan trọng: các class không đi qua quá trình khởi tạo JVM đầy đủ, các static block của chúng không được thực thi.
  // Spring chỉ đọc các annotation từ các file .class.
  2. Tìm kiếm các annotation @Component, @Service...
  3. Tạo BeanDefinition
  4. KHÔNG nạp class vào JVM!
```

### Cấu hình

```java
// Quét các package cụ thể
@ComponentScan(basePackages = {"com.example.a", "com.example.b"})

// Type-safe (khuyến nghị!)
@ComponentScan(basePackageClasses = MyMarkerInterface.class)

// Loại trừ các class
@ComponentScan(excludeFilters = @Filter(Type.ASSIGNABLE_TYPE, classes = Config.class))
```

### spring-context-indexer

```
Với các dự án lớn -> quét chậm

Dependency: spring-context-indexer
  -> Tạo META-INF/spring.components lúc biên dịch
  -> Spring đọc danh sách thay vì quét
  -> Khởi động nhanh gấp 2-3 lần!
```

## Senior Level

### ConfigurationClassPostProcessor

```
Khởi động quá trình quét:
  1. Phân tích các class @Configuration
  2. Xử lý @Import
  3. Khởi động ClassPathBeanDefinitionScanner
  4. Đăng ký BeanDefinition
```

### Lọc

```java
@ComponentScan(
    useDefaultFilters = false,  // Tắt @Component
    includeFilters = @Filter(MyCustomAnnotation.class)
)
// Điều này hữu ích nếu bạn muốn chỉ quét các annotation tùy chỉnh của mình
// và bỏ qua @Component/@Service chuẩn. Tất cả các bean chuẩn
// sẽ KHÔNG được đăng ký!
```

### Kinh nghiệm Production

**Tình huống thực tế: 10 giây cho việc quét**
```
5000 class -> quét bằng ASM -> 10 giây
Giải pháp: spring-context-indexer
Kết quả: 2 giây
```

### Best Practices

1. **basePackageClasses** -> type-safe
2. **spring-context-indexer** -> cho các dự án lớn
3. **Giới hạn các package** -> đừng quét những thứ không cần thiết
4. **excludeFilters** -> cho test
5. **useDefaultFilters = false** -> các annotation tùy chỉnh
6. **ASM** -> không nạp class, đọc bytecode

### Tóm tắt cho Senior

- **@ComponentScan** -> tìm bean trong các package
- **ASM** -> đọc bytecode, không phải reflection
- **ConfigurationClassPostProcessor** -> khởi động quá trình quét
- **spring-context-indexer** -> tăng tốc khởi động
- **basePackageClasses** -> type-safe
- **Filter** -> include/exclude

## Interview Cheat Sheet

**Cần phải biết:**
- @ComponentScan tìm kiếm @Component, @Service, @Repository, @Controller trong các package được chỉ định
- @SpringBootApplication đã bao gồm @ComponentScan của package hiện tại và các sub-package
- ASM đọc bytecode của các file .class — các class KHÔNG được nạp vào JVM, các static block KHÔNG được thực thi
- ConfigurationClassPostProcessor khởi động quá trình quét ở một pha sớm
- spring-context-indexer tạo META-INF/spring.components lúc biên dịch — khởi động nhanh gấp 2-3 lần
- basePackageClasses — thay thế type-safe cho các package dạng chuỗi
- includeFilters / excludeFilters — kiểm soát chi tiết việc quét

**Các câu hỏi phụ thường gặp:**
- *Tại sao Spring không nạp các class trong lúc quét?* — ASM chỉ đọc các annotation từ bytecode, cách này nhanh hơn và an toàn hơn (các static block không được thực thi).
- *Làm sao tăng tốc quét trong một dự án lớn?* — spring-context-indexer: file meta được tạo lúc biên dịch, Spring đọc nó thay vì duyệt classpath.
- *Điều gì xảy ra với excludeFilters = @Filter(Type.ASSIGNABLE_TYPE, classes = Config.class)?* — Class Config sẽ không được đăng ký làm bean.
- *Tại sao cần useDefaultFilters = false?* — Để bỏ qua @Component chuẩn và chỉ quét các annotation tùy chỉnh.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "ComponentScan nạp tất cả các class qua reflection" — không, ASM đọc bytecode mà không nạp.
- "Luôn cần cấu hình @ComponentScan thủ công" — @SpringBootApplication đã quét rồi.
- "spring-context-indexer là một tối ưu hóa lúc runtime" — không, index được tạo lúc biên dịch.
- "basePackages an toàn hơn basePackageClasses" — ngược lại, basePackageClasses bắt lỗi lúc biên dịch.

# What is ConcurrentHashMap? (ConcurrentHashMap là gì?)

## 🟢 Junior Level

**ConcurrentHashMap** là một Map thread-safe cho các ứng dụng đa luồng.

Khác với `Collections.synchronizedMap(new HashMap<>())` (một khóa duy nhất cho toàn bộ map), CHM cho phép nhiều luồng làm việc song song bằng cách chỉ khóa các bucket riêng lẻ.

**Sự khác biệt then chốt so với HashMap:**
- HashMap: không thread-safe
- ConcurrentHashMap: thread-safe, không có khóa cho các lần đọc

```java
Map<String, Integer> map = new ConcurrentHashMap<>();

// An toàn từ nhiều luồng
map.put("A", 1);
map.get("A");  // → 1

// null không được cho phép!
map.put("A", null);  // → NullPointerException!
```

**Quy tắc kinh nghiệm:**
- Một luồng hoặc thread-local → HashMap
- Nhiều luồng đọc và ghi → ConcurrentHashMap
- Nhiều luồng chỉ đọc → HashMap là đủ (sau khi publish an toàn)

## 🟡 Middle Level

### Sự tiến hóa

**Java 7: Segment Locking**

Java 7 — tham chiếu lịch sử, không được dùng trong code hiện đại.

```
Map được chia thành 16 segment
  → Các luồng trên các segment khác nhau không chặn lẫn nhau
  → size() = khóa TẤT CẢ các segment!
```

**Java 8+: Node-level Locking**
```
CAS cho các bucket rỗng (không có khóa!)
Synchronized chỉ cho các va chạm (cho mỗi bucket!)
  → Tính song song tối đa
```

### Các thao tác nguyên tử (atomic)

```java
map.putIfAbsent(key, value);  // Chèn nếu vắng mặt

map.computeIfAbsent(key, k -> new ArrayList<>())
   .add(value);  // Tính toán và chèn

map.merge(key, 1, Integer::sum);  // Cập nhật nguyên tử
```

### Các đặc điểm

```java
// ❌ null không được cho phép!
map.put(key, null);  // → NullPointerException

// ⚠️ size() là gần đúng!
int size = map.size();  // Có thể thay đổi ngay lập tức!

// ✅ mappingCount() cho các collection lớn
long count = map.mappingCount();  // > 2^31

// ✅ Các iterator KHÔNG ném Exception
// → Weakly consistent (nhất quán yếu)
// → Weakly consistent = iterator nhìn thấy dữ liệu tại thời điểm tạo và có thể (nhưng không bắt buộc phải) nhìn thấy các thay đổi sau đó. Không bao giờ ném ConcurrentModificationException.
for (var entry : map) { ... }  // An toàn
```

## 🔴 Senior Level

### Đọc Lock-free

```java
// get() KHÔNG có khóa!
// Thông qua các trường volatile:
//   mảng table → volatile
//   Node.val → volatile
//   Node.next → volatile

// Đảm bảo Happens-Before:
// → Reader nhìn thấy lần ghi mới nhất
```

### CAS + Synchronized

CAS (Compare-And-Swap) — một lệnh CPU nguyên tử: "ghi giá trị mới chỉ khi giá trị hiện tại bằng với giá trị mong đợi." Hoạt động không có khóa — nếu hai luồng ghi cùng lúc, một cái thành công, cái kia thử lại.

```
put(key, value):
  1. Bucket rỗng → CAS (không có khóa!)
  2. Bucket bị chiếm → synchronized trên HEAD
     → Chỉ bucket này bị khóa
     → Các bucket khác làm việc song song
```

### Parallel Resizing (thay đổi kích thước song song)

```
Khi resize:
  → ForwardingNode trong các bucket cũ
  → Các luồng ghi NHÌN THẤY ForwardingNode
  → Gọi helpTransfer() → GIÚP với việc resize!

→ Resize phân tán, không có khóa toàn bộ
```

### CounterCells

```
Thay vì một size volatile duy nhất:
  → Mảng CounterCell (giống LongAdder)
  → Mỗi luồng tăng cell RIÊNG CỦA NÓ
  → size() = tổng của tất cả các cell

→ Contention tối thiểu!
```

### Bẫy của compute

```java
// ❌ Thao tác chạy lâu trong compute
map.computeIfAbsent(key, k -> {
    Thread.sleep(10000);  // Chặn bucket trong 10 giây!
    return value;
});

// ❌ Truy cập đệ quy → Deadlock!
map.computeIfAbsent(key1, k -> {
    return map.get(key2);  // Có thể chờ trên cùng một bucket!
});
```

### Java 21: Virtual Threads

```
synchronized trong CHM có thể "ghim" (pin) các virtual thread
  → Nhưng các phần tới hạn (critical section) RẤT ngắn
  → Hiếm khi là vấn đề trong thực tế

Nếu nó là vấn đề:
  → async-profiler sẽ hiển thị thời gian bị chặn
```

### Kinh nghiệm Production

**Tình huống thực tế: hashCode tệ**
```java
// Tất cả các key → một bucket
// → Synchronized trên một bucket duy nhất
// → 100 luồng chờ → 0 song song!

// Giải pháp: viết lại hashCode()
// Kết quả: +500% throughput
```

### Best Practices

1. **Lựa chọn mặc định** cho concurrency
2. **null không được cho phép** — bảo vệ chống mơ hồ
3. **computeIfAbsent** — khởi tạo nguyên tử
4. **Không có thao tác chạy lâu** trong compute
5. **mappingCount()** > size() cho > 2^31 phần tử
6. **hashCode tệ** → kẻ thù chính của tính song song
7. **Các iterator weakly consistent**

### Tóm tắt cho Senior

- **CAS** cho các bucket rỗng, **synchronized** cho các va chạm
- **Đọc lock-free** thông qua volatile
- **Parallel resizing** với helpTransfer()
- **CounterCells** = bộ đếm có khả năng mở rộng
- **compute** → không có thao tác dài, không đệ quy
- **null không được cho phép** — một quyết định mang tính triết lý
- **hashCode tệ** → contention trên một bucket duy nhất

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- ConcurrentHashMap — Map thread-safe, khác với HashMap nó cho phép làm việc song song mà không cần khóa toàn bộ map
- Java 8+: CAS cho các bucket rỗng (lock-free) + synchronized chỉ trên bucket cho các va chạm (thay vì Segment locking từ Java 7)
- Đọc lock-free thông qua volatile: table, Node.val, Node.next — get() không có khóa
- null không được cho phép (key và value) — bảo vệ chống mơ hồ (null = key vắng mặt so với null = value)
- Các iterator là weakly consistent — không ném ConcurrentModificationException, có thể không nhìn thấy các thay đổi mới nhất
- Parallel resizing: ForwardingNode + helpTransfer() — các luồng ghi giúp với việc resize
- CounterCells (giống LongAdder) — mỗi luồng tăng cell riêng của nó, size() = tổng
- size() là gần đúng, mappingCount() cho > 2^31 phần tử

**Các câu hỏi phụ thường gặp:**
- **CHM khác Collections.synchronizedMap như thế nào?** — synchronizedMap khóa TOÀN BỘ map ở mỗi thao tác. CHM chỉ khóa một bucket (synchronized) hoặc không khóa gì cả (CAS).
- **Tại sao các giá trị null không được cho phép trong CHM?** — Để phân biệt "key không có mặt" (get = null) với "value là null". Trong HashMap điều này là không thể, tạo ra sự mơ hồ.
- **Điều gì xảy ra với một thao tác chạy lâu trong computeIfAbsent?** — Bucket bị khóa trong suốt quá trình tính toán. Các luồng khác ghi vào cùng bucket sẽ chờ. Truy cập đệ quy → deadlock.
- **CHM resize không cần khóa toàn bộ như thế nào?** — Nó đặt ForwardingNode trong các bucket cũ. Các luồng ghi, khi nhìn thấy nó, gọi helpTransfer() và giúp chuyển dữ liệu.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "CHM dùng Segment locking" — đó là Java 7, Java 8+ dùng node-level locking
- ❌ "CHM khóa toàn bộ map khi ghi" — nó chỉ khóa một bucket, các bucket khác vẫn làm việc
- ❌ "CHM hỗ trợ các giá trị null" — không, NullPointerException cho các key và value null
- ❌ "size() trong CHM là chính xác" — nó là gần đúng, có thể thay đổi ngay sau lời gọi

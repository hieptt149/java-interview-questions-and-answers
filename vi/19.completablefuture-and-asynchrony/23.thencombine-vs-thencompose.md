# What Is the Difference Between thenCombine() and thenCompose()? (Sự khác biệt giữa thenCombine() và thenCompose() là gì)

## 🟢 Junior Level

Cả hai phương thức đều kết hợp CompletableFuture, nhưng theo cách khác nhau:

- **`thenCombine()`** — chờ **HAI** CF độc lập và kết hợp kết quả của chúng
- **`thenCompose()`** — chờ **MỘT** CF và khởi chạy **một CF khác** dựa trên kết quả của nó

```java
// thenCombine — hai CF, kết hợp kết quả
CompletableFuture<String> cf1 = CompletableFuture.supplyAsync(() -> "Hello");
CompletableFuture<String> cf2 = CompletableFuture.supplyAsync(() -> "World");

cf1.thenCombine(cf2, (s1, s2) -> s1 + " " + s2)
   .thenAccept(System.out::println);  // Hello World

// thenCompose — một CF, sau đó một cái khác
CompletableFuture<String> cf = getUserIdAsync();
cf.thenCompose(userId -> getUserAsync(userId))
  .thenAccept(user -> System.out.println(user.name()));
```

## 🟡 Middle Level

### thenCombine — Thực Thi Song Song

```java
CompletableFuture<User> user = getUserAsync(userId);
CompletableFuture<Order> order = getOrderAsync(userId);

// Cả hai thực thi song song
user.thenCombine(order, (u, o) -> new UserProfile(u, o))
    .thenAccept(profile -> System.out.println(profile));
```

### thenCompose — Thực Thi Tuần Tự

```java
// Đầu tiên getUserId, sau đó getUser
getUserIdAsync()
    .thenCompose(userId -> getUserAsync(userId))  // tuần tự
    .thenAccept(user -> System.out.println(user));
```

### Các Lỗi Thường Gặp

1. **Dùng thenCompose khi cần thenCombine:**
```java
// ❌ Tuần tự (chậm hơn)
getUserAsync(userId)
    .thenCompose(user -> getOrderAsync(userId));

// ✅ Song song (nhanh hơn)
CompletableFuture<User> user = getUserAsync(userId);
CompletableFuture<Order> order = getOrderAsync(userId);
user.thenCombine(order, (u, o) -> new Summary(u, o));
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**thenCombine:**
```java
public <U,V> CompletableFuture<V> thenCombine(
    CompletionStage<? extends U> other,
    BiFunction<? super T,? super U,? extends V> fn
) {
    return biApplyStage(null, other, fn);
}

// Biểu diễn đơn giản hóa của các phương thức JDK nội bộ. Các phương thức thực tế có
// chữ ký khác nhau và các tham số bổ sung. Về mặt khái niệm:
// biApplyStage — tạo một CF chờ CẢ HAI kết quả và áp dụng hàm.
```

**thenCompose:**
```java
public <U> CompletableFuture<U> thenCompose(
    Function<? super T, ? extends CompletionStage<U>> fn
) {
    return uniComposeStage(null, fn);
}

// uniComposeStage — tạo một CF chờ kết quả đầu tiên và khởi chạy thao tác thứ hai.
```

### Hiệu Năng

```
thenCombine:
- Cả hai CF song song
- Độ trễ = max(cf1, cf2)

thenCompose:
- Các CF tuần tự
- Độ trễ = cf1 + cf2
```

### Kinh Nghiệm Production

```java
// ✅ thenCombine cho các lời gọi song song
CompletableFuture<User> user = getUserAsync(userId);
CompletableFuture<Order> order = getOrderAsync(userId);
user.thenCombine(order, UserProfile::new);

// ✅ thenCompose cho các lời gọi phụ thuộc
getUserIdAsync()
    .thenCompose(userId -> getUserAsync(userId));
```

### Best Practices

```java
// ✅ thenCombine cho các CF độc lập
cf1.thenCombine(cf2, combiner);

// ✅ thenCompose cho các CF phụ thuộc
cf.thenCompose(result -> nextAsync(result));

// ❌ thenCompose cho các lời gọi độc lập (chậm hơn)
// ❌ thenCompose khi CF không phụ thuộc vào kết quả
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- thenCombine — hai CF ĐỘC LẬP, thực thi song song, độ trễ = max(cf1, cf2)
- thenCompose — CF PHỤ THUỘC, thực thi tuần tự, độ trễ = cf1 + cf2
- thenCombine nhận BiFunction<T, U, V>, thenCompose nhận Function<T, CompletionStage<U>>
- thenCompose tương tự flatMap, thenCombine tương tự zip
- Lỗi phổ biến: dùng thenCompose cho các CF độc lập — chậm không cần thiết

**Các câu hỏi phụ thường gặp:**
- **thenCombine cho các CF phụ thuộc?** — Không, thenCombine không thể dùng kết quả của cái đầu trong cái thứ hai
- **thenCompose cho các CF độc lập?** — Hoạt động, nhưng tuần tự (chậm hơn). Tốt hơn nên dùng thenCombine
- **thenCombine vs allOf?** — thenCombine cho hai CF với một combiner, allOf cho N CF (trả về Void)
- **Triển khai nội bộ?** — thenCombine: BiRelay chờ cả hai CF. thenCompose: uniComposeStage chờ cái đầu, khởi chạy cái thứ hai

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "thenCombine và thenCompose có thể thay thế cho nhau" — ngữ nghĩa khác nhau: song song vs tuần tự
- "thenCompose nhanh hơn" — thenCompose là tuần tự (tổng độ trễ), thenCombine là song song (độ trễ max)
- "thenCombine nhận một Function" — nó nhận một BiFunction từ cả hai kết quả CF

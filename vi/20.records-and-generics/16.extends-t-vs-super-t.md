# What Is the Difference Between <? extends T> and <? super T>? (Sự khác biệt giữa <? extends T> và <? super T> là gì)

## 🟢 Junior Level

**`<? extends T>`** — covariance (Producer).
- Bạn có thể **đọc** các phần tử dưới dạng kiểu `T`.
- **Không thể ghi** (trừ `null`).

```java
List<? extends Number> numbers = List.of(1, 2, 3);
Number n = numbers.get(0);  // ✅ có thể đọc
// numbers.add(4);  // ❌ không thể ghi
```

**`<? super T>`** — contravariance (Consumer).
- Bạn có thể **ghi** các phần tử kiểu `T`.
- Chỉ có thể đọc dưới dạng `Object`.

```java
List<? super Integer> integers = new ArrayList<>();
integers.add(42);  // ✅ có thể ghi
// Integer i = integers.get(0);  // ❌ chỉ có thể đọc dưới dạng Object
```

**Quy tắc đơn giản (PECS):**
- **P**roducer **E**xtends — đọc dữ liệu → `? extends T`
- **C**onsumer **S**uper — ghi dữ liệu → `? super T`

## 🟡 Middle Level

### Covariance — `<? extends T>`

Bound trên (upper bound): kiểu `T` hoặc bất kỳ kiểu con nào của nó.

```java
List<? extends Number> nums = new ArrayList<Integer>();
Number n = nums.get(0);  // ✅ Integer là một Number
// nums.add(42);  // ❌ trình biên dịch không biết đó là Integer hay Double
```

**Tại sao không thể ghi:** `List<? extends Number>` có thể là một `List<Integer>` hoặc `List<Double>`. Nếu việc ghi `Double` được cho phép nhưng list thực tế là `List<Integer>` — tính toàn vẹn bị phá vỡ.

### Contravariance — `<? super T>`

Bound dưới (lower bound): kiểu `T` hoặc bất kỳ kiểu cha nào của nó.

```java
List<? super Integer> target = new ArrayList<Number>();
target.add(42);  // ✅ Integer phù hợp với Number hoặc Object
Object o = target.get(0);  // ✅ chỉ có thể đọc dưới dạng Object
```

**Tại sao không thể đọc giá trị có kiểu:** `List<? super Integer>` có thể là `List<Number>` hoặc `List<Object>`. Không có gì đảm bảo rằng các phần tử `Integer` được lưu trữ ở đó.

### So Sánh

| Đặc điểm | `<? extends T>`          | `<? super T>`            |
| -------------- | ----------------------- | ----------------------- |
| **Vai trò**       | Producer (nguồn)       | Consumer (đích)         |
| **Đọc**       | ✅ Dưới dạng `T`                | ❌ Chỉ dưới dạng `Object`      |
| **Ghi**      | ❌ Bị cấm             | ✅ Dưới dạng `T`                |
| **Hệ thống phân cấp**  | `T` và tất cả **bên dưới**   | `T` và tất cả **bên trên**   |

### Capture of Wildcard

Lỗi thường gặp:
```java
void reverse(List<?> list) {
    // list.set(0, list.get(0)); // LỖI: capture of ?
}
```
Trình biên dịch không thể khớp kiểu bạn "lấy được" với kiểu để ghi.
**Giải pháp:** Một phương thức generic phụ trợ "chụp lại" (capture) kiểu:
```java
void reverse(List<?> list) { reverseHelper(list); }
private <T> void reverseHelper(List<T> list) {
    // bây giờ T đã được biết
}
```

## 🔴 Senior Level

### Use-site Variance

Java dùng variance **tại nơi sử dụng** (use site) — trong tham số phương thức.
Điều này khác với Kotlin/Scala, có **declaration-site variance** (`out T` / `in T`).

### Wildcard KHÔNG Ngăn Cấp Phát

Việc dùng wildcard trong chữ ký phương thức **không ngăn cấp phát**.
`ArrayList<Integer>` cấp phát các object `Integer` bất kể
nó được truyền dưới dạng `List<? extends Number>` hay không.
Wildcard chỉ là kiểm tra kiểu tại compile-time.

### Unbounded Wildcard `<?>`

Điều này thực chất là `<? extends Object>`. Hữu ích khi code chỉ dùng các phương thức của `Object`:
```java
void printSize(List<?> list) {
    System.out.println(list.size());  // chỉ các phương thức của Object
}
```

### Best Practices

```java
// ✅ extends — để trích xuất dữ liệu (Producer)
public double sum(List<? extends Number> numbers) { ... }

// ✅ super — để tích lũy dữ liệu (Consumer)
public void fill(List<? super Integer> list, int value) { ... }

// ✅ Không dùng wildcard khi bạn cần cả đọc và ghi
public <T> void swap(List<T> list, int i, int j) { ... }

// ❌ Extends để ghi
// ❌ Super để đọc một kiểu cụ thể
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- `<? extends T>` — covariance (Producer): có thể đọc dưới dạng T, không thể ghi (trừ null)
- `<? super T>` — contravariance (Consumer): có thể ghi T, chỉ có thể đọc dưới dạng Object
- `List<String>` KHÔNG kế thừa từ `List<Object>` — generics là bất biến (invariant)
- Quy tắc PECS: **P**roducer **E**xtends, **C**onsumer **S**uper
- Wildcard — use-site variance (khác với declaration-site variance của Kotlin)
- `<?>` = `<? extends Object>` — cho các trường hợp chỉ cần các phương thức của Object

**Các câu hỏi phụ thường gặp:**
- **Tại sao <? extends T> cấm ghi?** — Trình biên dịch không biết kiểu thực tế (có thể là List<Integer>), việc ghi sẽ phá vỡ tính toàn vẹn
- **Bạn có thể ghi gì vào List<? super Integer>?** — Integer và các lớp con của nó, vì chúng phù hợp với bất kỳ kiểu cha nào
- **Capture of wildcard là gì?** — Trình biên dịch không thể liên kết get() với set() cho `?`, cần một phương thức phụ trợ generic
- **Khi nào KHÔNG cần wildcard?** — Khi bạn cần cả đọc và ghi — dùng `<T>`

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "List<? extends Number> có thể là List<Integer>" — Đúng, nhưng bạn không thể thêm Integer vào nó
- ❌ "<? super T cho phép đọc dưới dạng T" — Bạn chỉ có thể đọc dưới dạng Object
- ❌ "Wildcard ngăn cấp phát" — Đây chỉ là một kiểm tra compile-time
- ❌ "List<?> là một list chỉ đọc" — Trình biên dịch chặn ghi do kiểu không xác định, không phải vì bất biến (immutable)

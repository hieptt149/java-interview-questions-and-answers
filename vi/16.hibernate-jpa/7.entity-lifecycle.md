# Describe the Entity Lifecycle in Hibernate (Mô tả vòng đời Entity trong Hibernate)

## Overview

Mỗi entity trong Hibernate trải qua các trạng thái nhất định (vòng đời) trong quá trình tương tác với database. Hiểu về vòng đời là quan trọng để dùng Hibernate đúng cách và ngăn ngừa lỗi.

**Tại sao điều này quan trọng:** để biết phương thức nào cần gọi (persist hay merge), tại sao các thay đổi được lưu tự động (dirty checking), tại sao "detached entity passed to persist" lại xảy ra.

---

## Junior Level

### 4 Trạng Thái Entity

Một entity trong Hibernate có thể ở một trong **bốn trạng thái**:

1. **Transient (Mới / Tạm thời)** - được tạo thông qua `new`, chưa có trong DB
2. **Persistent (Được quản lý)** - đã lưu vào DB, được Hibernate theo dõi
3. **Detached (Ngắt kết nối)** - đã có trong DB, nhưng session đã đóng
4. **Removed (Đã xóa)** - được đánh dấu để xóa, sẽ bị xóa khi flush

```
new User() --persist()--> Managed --close()--> Detached
                             |
                          remove()
                             v
                          Removed
```

### Ví Dụ

```java
// 1. Transient - object mới, chưa có trong DB
User user = new User();
user.setName("John");

// 2. Persistent - đã lưu, được theo dõi
entityManager.persist(user);
// Bây giờ user đã có trong DB và được Hibernate quản lý

// 3. Detached - session đã đóng
entityManager.close();
// user vẫn tồn tại trong bộ nhớ, nhưng Hibernate không còn theo dõi

// 4. Removed - được đánh dấu để xóa
entityManager.remove(user);
// Khi flush/commit, DELETE sẽ được thực thi
```

## Middle Level

### persist() vs merge()

| Thao tác   | Transient     | Detached      | Persistent          |
| ---------- | ------------- | ------------- | ------------------- |
| persist()  | INSERT        | LỖI           | LỖI                 |
| merge()    | SELECT+INSERT | SELECT+UPDATE | SELECT (vô ích)     |

### Chuyển Đổi Trạng Thái

```
Transient -> Persistent:  persist(), merge()
Persistent -> Detached:   close(), clear(), detach()/evict()
Detached -> Persistent:   merge(), update()
Persistent -> Removed:    remove()
Transient -> Detached:    (không thể trực tiếp)
```

### Mô Tả Chi Tiết Các Thao Tác

```java
// persist() - cho entity mới (INSERT)
User newUser = new User();
entityManager.persist(newUser);
// newUser bây giờ là Persistent

// merge() - cho entity detached (UPDATE)
User detached = getDetachedUser();
User managed = entityManager.merge(detached);
// managed - bản sao managed mới
// detached vẫn là detached!

// remove() - để xóa (DELETE)
entityManager.remove(managedUser);
// Khi flush, DELETE sẽ được thực thi

// refresh() - tải lại từ DB
entityManager.refresh(user);
// Cập nhật dữ liệu từ DB, ghi đè các thay đổi trong bộ nhớ

// detach()/evict() - ngắt kết nối. evict() - đặc thù Hibernate (Session). detach() - chuẩn JPA (EntityManager). Dùng detach() để dễ portable.
entityManager.detach(user);
// user trở thành Detached

// clear() - ngắt kết nối tất cả
entityManager.clear();
// Tất cả entity trở thành Detached
```

### Dirty Checking

Dirty checking - Hibernate tự động theo dõi các thay đổi của object. Bạn chỉ cần thay đổi một trường - Hibernate tự thực hiện UPDATE.

```java
@Transactional
public void updateUser(Long id, String name) {
    User user = entityManager.find(User.class, id);  // Persistent
    user.setName(name);
    // KHÔNG cần em.merge() hoặc em.save()!
    // Hibernate sẽ tự động phát hiện thay đổi và thực hiện UPDATE
}
```

### Các Lỗi Thường Gặp

```java
// Truyền detached entity vào persist
User user = new User();
user.setId(1L);  // ID đã được đặt
entityManager.persist(user);  // EntityExistsException hoặc lỗi

// Đúng: merge() cho detached
User merged = entityManager.merge(user);

// merge() cho entity mới (SELECT thừa)
User newUser = new User();
entityManager.merge(newUser);  // Đầu tiên SELECT, sau đó INSERT

// Đúng: persist() cho entity mới
entityManager.persist(newUser);  // INSERT ngay lập tức

// merge() cho persistent (vô ích)
User user = entityManager.find(User.class, 1L);  // đã là persistent
User merged = entityManager.merge(user);  // SELECT thừa
```

## Senior Level

### Triển Khai Nội Bộ

Persistence Context - container cho tất cả các entity managed trong một EntityManager.
EntityEntry - một bản ghi trong Persistence Context, lưu trạng thái hiện tại và snapshot.
Snapshot - bản sao trạng thái của object tại thời điểm tải, dùng cho dirty checking.

```
Persistence Context (StatefulPersistenceContext):

EntityManagerImpl {
    persistenceContext: StatefulPersistenceContext {
        entitiesByKey: Map<EntityKey, Object>,     // cache theo ID
        entityEntries: Map<Object, EntityEntry>,   // theo dõi trạng thái
    }
}

EntityEntry lưu trữ:
- snapshot - trạng thái khi tải (cho dirty checking)
- status - trạng thái hiện tại (MANAGED, DELETED, v.v.)
- loadedState - trạng thái khi được tải từ DB
```

### Cơ Chế Dirty Checking

```
1. Khi tải: Hibernate lưu snapshot của entity
2. Khi thay đổi: một trường trong object bị sửa đổi
3. Khi flush: Hibernate so sánh snapshot với trạng thái hiện tại
4. Nếu khác nhau -> tạo ra UPDATE SQL
5. Cập nhật snapshot

Thuật toán:
- O(N) trong đó N = số lượng entity trong persistence context
- Có thể chậm với các context lớn
- Giải pháp: entityManager.clear() định kỳ
```

### Quản Lý Bộ Nhớ Cho Các Thao Tác Lớn

```java
@Transactional
public void batchProcess(List<User> users) {
    for (int i = 0; i < users.size(); i++) {
        entityManager.merge(users.get(i));

        // Dọn dẹp persistence context định kỳ
        if (i % 50 == 0) {
            entityManager.flush();    // flush vào DB
            entityManager.clear();    // xóa cache
        }
    }
}
```

Sau clear(), tất cả các object đã tải/tạo trước đó trở thành detached.
Nếu vòng lặp tiếp tục - các vòng lặp tiếp theo làm việc với object mới,
các object cũ bị mất (và truy cập chúng sẽ cần merge()).

### Best Practices

```
persist() cho entity mới
merge() cho entity detached
remove() để xóa
Dirty checking cho cập nhật (không cần merge)
entityManager.clear() cho các thao tác batch
flush + clear mỗi 50-100 entity

persist() cho detached (lỗi)
merge() cho entity mới (SELECT thừa)
merge() cho persistent (SELECT thừa)
Bỏ qua trạng thái entity
Tải một số lượng lớn entity mà không có clear
```

## Interview Cheat Sheet

**Cần phải biết:**
- 4 trạng thái: Transient (mới), Persistent (managed), Detached (trong DB nhưng không theo dõi), Removed (đánh dấu để xóa)
- persist() - cho entity mới (INSERT), merge() - cho detached (UPDATE/INSERT)
- Dirty checking: Hibernate tự động theo dõi thay đổi của các entity managed
- Persistence Context - container cho tất cả entity managed, lưu snapshot cho dirty checking
- merge() trả về một object managed MỚI, bản gốc vẫn là detached
- entityManager.clear() xóa persistence context, tất cả entity trở thành detached

**Các câu hỏi phụ thường gặp:**
- **Tại sao persist() tốt hơn merge() cho entity mới?** persist() = INSERT ngay lập tức, merge() = SELECT trước (kiểm tra)
- **Snapshot là gì?** Bản sao trạng thái tại thời điểm tải, dùng cho dirty checking khi flush
- **Cách xử lý 10k+ entity?** persist/merge + flush + clear mỗi 50-100 entity
- **Tại sao merge() trả về object mới?** Vì bản gốc có thể là detached, Hibernate tạo một bản sao managed

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi dùng merge() cho entity mới" - SELECT thừa
- "Tôi bỏ qua giá trị trả về của merge()" - các thay đổi sẽ không được lưu
- "persist() cho detached có ID" - EntityExistsException
- "Tôi không dọn dẹp persistence context trong batch" - OutOfMemoryError

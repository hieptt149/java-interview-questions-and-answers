# What is Aspect, Advice, Pointcut, Join Point? (Aspect, Advice, Pointcut, Join Point là gì?)

## Junior Level

**Các thuật ngữ AOP:**

| Thuật ngữ         | Ý nghĩa                            | Ví dụ                        |
| -------------- | --------------------------------------- | ----------------------------- |
| **Join Point** | Phương thức cụ thể để chặn | `UserService.save()`          |
| **Pointcut**   | Quy tắc áp dụng Ở ĐÂU                  | "Tất cả các phương thức có @Transactional" |
| **Advice**     | LÀM GÌ (logic)                     | "Log thời gian thực thi"   |
| **Aspect**     | Module kết hợp Pointcut + Advice  | Class logging          |

```java
@Aspect
@Component
public class LoggingAspect {  // Aspect

    @Around("@annotation(LogTime)")  // Pointcut
    public Object logTime(ProceedingJoinPoint pjp) {  // Advice
        long start = System.currentTimeMillis();
        try {
            return pjp.proceed();  // Lời gọi Join Point
        } finally {
            log.info("Completed in " + (System.currentTimeMillis() - start) + "ms");
        }
    }
}
```

## Middle Level

### Các loại Advice

```java
@Before("pointcut")
public void before() { }  // Trước phương thức

@After("pointcut")
public void after() { }  // Sau phương thức (luôn luôn)
// @After = như finally, chạy LUÔN LUÔN (khi thành công và khi có exception)
// @AfterReturning = chỉ khi phương thức hoàn thành THÀNH CÔNG (không có exception)

@AfterReturning(pointcut = "pc", returning = "result")
public void afterReturn(Object result) { }  // Sau khi thành công

@AfterThrowing(pointcut = "pc", throwing = "ex")
public void afterThrow(Exception ex) { }  // Khi có exception

@Around("pointcut")
public Object around(ProceedingJoinPoint pjp) throws Throwable {
    // Trước
    Object result = pjp.proceed();  // Lời gọi phương thức
    // Sau
    return result;
}
```

### Static so với Dynamic Pointcut

```
Static (nhanh):
  -> Được kiểm tra một lần lúc tạo bean
  -> Theo annotation, signature, tên phương thức

Dynamic (chậm):
  -> Được kiểm tra ở MỖI lời gọi
  -> Theo giá trị của các tham số
  -> Overhead ở mỗi lần kiểm tra
```

## Senior Level

### Thông tin JoinPoint

```java
@Around("pointcut")
public Object log(ProceedingJoinPoint pjp) {
    pjp.getSignature();       // Signature của phương thức
    pjp.getArgs();            // Các tham số (bản sao mảng!)
    pjp.getTarget();          // Đối tượng gốc
    pjp.getThis();            // Proxy

    // getArgs() tạo một bản sao của mảng -> áp lực GC (chỉ đáng kể khi aspect được gọi rất thường xuyên - hàng trăm nghìn lần mỗi giây - hoặc với các mảng tham số lớn).
}
```

### Aspect = Singleton

```java
// Aspect là Singleton theo mặc định!
// -> KHÔNG lưu trạng thái trong các field của aspect!
@Aspect
public class MetricsAspect {
    // Không thread-safe!
    private int callCount = 0;

    // ThreadLocal
    private ThreadLocal<Long> startTime = new ThreadLocal<>();
}
```

### Pipeline

```
ReflectiveMethodInvocation:
  1. Tìm tất cả các Advisor
  2. Lọc theo Pointcut
  3. Sắp xếp theo @Order
  4. Tạo List<MethodInterceptor>
  5. Duyệt đệ quy qua tất cả
  6. Gọi target.invoke()
```

### Kinh nghiệm Production

**Tình huống thực tế: Around không có proceed**
```java
@Around("@annotation(Cacheable)")
public Object cache(ProceedingJoinPoint pjp) {
    if (cache.has(key)) return cache.get(key);
    // Quên pjp.proceed()!
    // -> Phương thức KHÔNG BAO GIỜ được gọi!
}
```

### Best Practices

1. **Static Pointcut** -> nhanh hơn
2. **Pointcut hẹp** -> ít overhead hơn. Pointcut càng chính xác, càng ít bean bị proxy và càng ít lần kiểm tra ở mỗi lời gọi phương thức.
3. **Không trạng thái** trong các aspect (Singleton!)
4. **@Order** -> thứ tự thực thi
5. **getArgs()** -> bản sao mảng, hãy cẩn thận
6. **@Around** -> đừng quên proceed()

### Tóm tắt cho Senior

- **Join Point** = ngữ cảnh của lời gọi
- **Pointcut** = bộ lọc phương thức
- **Advice** = kiểu chèn logic
- **Aspect** = module logic
- **Pipeline** = chuỗi interceptor
- **Aspect = Singleton** -> không trạng thái
- **proceed()** -> bắt buộc trong @Around

## Interview Cheat Sheet

**Cần phải biết:**
- Join Point = phương thức cụ thể, Pointcut = bộ lọc (ở đâu), Advice = logic (làm gì), Aspect = module
- 5 loại Advice: @Before, @After, @AfterReturning, @AfterThrowing, @Around
- @After chạy LUÔN LUÔN (như finally), @AfterReturning — chỉ khi thành công
- Static Pointcut được kiểm tra một lần lúc tạo bean, dynamic — ở mỗi lời gọi
- Aspect = Singleton -> KHÔNG lưu trạng thái trong các field, dùng ThreadLocal
- pjp.proceed() bắt buộc trong @Around — nếu không phương thức sẽ không được gọi
- Pipeline: ReflectiveMethodInvocation lọc các Advisor theo Pointcut, sắp xếp theo @Order, duyệt đệ quy
- getArgs() tạo bản sao mảng -> áp lực GC khi gọi thường xuyên

**Các câu hỏi phụ thường gặp:**
- *@After so với @AfterThrowing — khi nào dùng cái nào?* -> @After = dọn dẹp tài nguyên luôn luôn, @AfterThrowing = xử lý lỗi
- *Tại sao aspect = Singleton?* -> Spring đăng ký các aspect như các bean thông thường (Singleton theo mặc định)
- *Static so với dynamic Pointcut — chọn cái nào?* -> Static nhanh hơn, dynamic linh hoạt hơn; ưu tiên static
- *Điều gì xảy ra nếu quên pjp.proceed()?* -> Phương thức gốc sẽ không chạy chút nào

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "@After chỉ chạy khi thành công" — đó là @AfterReturning
- "Aspect lưu trạng thái là ổn" — Singleton, không thread-safe
- "Dynamic Pointcut nhanh hơn" — ngược lại, kiểm tra mỗi lần
- "getArgs() trả về mảng gốc" — tạo một bản sao

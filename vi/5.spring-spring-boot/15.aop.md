# What is AOP (Aspect-Oriented Programming)? (AOP (Aspect-Oriented Programming) là gì?)

## Junior Level

**AOP** là một cách để thêm chức năng chung (logging, transaction) vào nhiều class mà không thay đổi code của chúng.

**Ví dụ minh họa đơn giản:** Hãy tưởng tượng bạn muốn ghi âm mọi cuộc gọi trong một công ty. Thay vì yêu cầu mỗi nhân viên tự ghi nhật ký, bạn đặt chế độ ghi âm tự động cho tất cả các cuộc gọi.

```java
// Không có AOP:
public void save() {
    log.info("Start");  // Lặp lại ở khắp nơi
    repository.save(entity);
    log.info("End");
}

// Có AOP:
@LogExecution  // Một annotation!
public void save() {
    repository.save(entity);
}
```

**Tại sao:**
- Loại bỏ trùng lặp code
- Logic nghiệp vụ riêng, hạ tầng riêng
- Dễ bật/tắt

## Middle Level

### Spring AOP so với AspectJ

|                     | Spring AOP           | AspectJ                    |
| ------------------- | -------------------- | -------------------------- |
| **Cách thức**             | Proxy lúc runtime    | Sửa đổi bytecode        |
| **Làm được gì**       | Chỉ các phương thức public | Phương thức, field, constructor |
| **Self-invocation** | KHÔNG hoạt động        | Hoạt động                 |
| **Độ phức tạp**       | Đơn giản              | Thiết lập phức tạp          |

> Spring AOP chỉ hoạt động với các Spring bean (lời gọi qua proxy). AspectJ hoạt động với bất kỳ đối tượng nào, vì nó được dệt (weave) ở cấp độ bytecode (compile-time hoặc load-time weaving).

### Các thuật ngữ AOP

```
Aspect               = module logic cắt ngang (cross-cutting)
Pointcut             = áp dụng ở đâu (biểu thức)
Advice               = làm gì (logic)
Join Point           = phương thức cụ thể
```

### Các loại Advice

```java
@Before         // Trước phương thức
@After          // Sau phương thức (luôn luôn)
@AfterReturning // Sau khi thành công
@AfterThrowing  // Khi có exception
@Around         // Thay cho phương thức (mạnh nhất)
```

### Ví dụ Aspect

```java
@Aspect
@Component
public class LoggingAspect {

    @Around("@annotation(LogExecution)")
    public Object log(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.currentTimeMillis();
        try {
            return pjp.proceed();  // Gọi phương thức gốc
        } finally {
            long duration = System.currentTimeMillis() - start;
            log.info("Completed in " + duration + "ms");
        }
    }
}
```

## Senior Level

### Chuỗi Interceptor

```
Lời gọi phương thức -> ReflectiveMethodInvocation:
  1. SecurityInterceptor -> kiểm tra quyền
  2. TransactionInterceptor -> transaction
  3. CacheInterceptor -> cache
  4. LoggingAspect -> logging
  5. Phương thức đích -> code của bạn

-> Mỗi cái trả về kết quả hoặc ném exception
-> Thứ tự được xác định bởi @Order
```

### Hiệu năng

```
Overhead của AOP:
  -> Tạo đối tượng MethodInvocation
  -> Duyệt qua danh sách interceptor
  -> Reflection hoặc lời gọi trực tiếp

-> ~1-5 microsecond mỗi lời gọi
-> Trong Highload (1M RPS) -> đáng kể!
```

### Spring 6 + Virtual Threads

```
`synchronized` (từ khóa) trong các aspect -> Pinning (ghim) các virtual thread!
-> Kiểm tra xem các aspect của bạn có chặn các system thread không
```

### Kinh nghiệm Production

> Ví dụ đầy đủ với `Around` mà không có `proceed()` — trong file [[16. What is aspect advice pointcut join point]] (Aspect, advice, pointcut, join point là gì).

### Best Practices

1. **Spring AOP** -> 95% các trường hợp
2. **AspectJ** -> các phương thức private, các field
3. **@Order** -> thứ tự các aspect
4. **Static Pointcut** -> nhanh hơn dynamic
5. **Tránh trạng thái** trong các aspect (Singleton!)
6. **@Around** -> đừng quên pjp.proceed()

### Tóm tắt cho Senior

- **AOP** = chức năng cắt ngang mà không trùng lặp
- **Spring AOP** = proxy, **AspectJ** = bytecode
- **Chuỗi Interceptor** -> thứ tự qua @Order
- **Overhead** ~1-5 microsecond mỗi lời gọi
- **Pinning** -> cẩn thận với synchronized trong các aspect
- **pjp.proceed()** -> bắt buộc trong @Around

## Interview Cheat Sheet

**Cần phải biết:**
- AOP = chức năng cắt ngang (logging, transaction, cache) mà không trùng lặp code
- Spring AOP hoạt động qua proxy lúc runtime; AspectJ — qua sửa đổi bytecode
- Các thuật ngữ chính: Aspect (module), Pointcut (ở đâu), Advice (làm gì), Join Point (phương thức cụ thể)
- 5 loại Advice: @Before, @After, @AfterReturning, @AfterThrowing, @Around
- @Around — mạnh nhất, nhưng BẮT BUỘC phải gọi pjp.proceed()
- Thứ tự aspect được xác định qua @Order
- Spring AOP: chỉ các phương thức public của Spring bean, self-invocation KHÔNG hoạt động
- Overhead của AOP: ~1-5 microsecond mỗi lời gọi, cộng dồn trong Highload

**Các câu hỏi phụ thường gặp:**
- *Tại sao Spring AOP không hoạt động với các phương thức private?* -> Proxy chỉ chặn các lời gọi qua đối tượng proxy, các phương thức private không truy cập được
- *Khi nào chọn AspectJ thay vì Spring AOP?* -> Khi bạn cần các phương thức private, field, constructor, hoặc self-invocation
- *@After so với @AfterReturning — khác nhau chỗ nào?* -> @After = luôn luôn (như finally), @AfterReturning = chỉ khi hoàn thành thành công
- *ReflectiveMethodInvocation là gì?* -> Pipeline của Spring, duyệt tuần tự qua tất cả các interceptor

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Spring AOP hoạt động với các phương thức private" — không hoạt động
- "@Around không có proceed() là chấp nhận được" — phương thức sẽ không được gọi chút nào
- "AOP thêm overhead cỡ millisecond" — cỡ nanosecond (1-5 microsecond)
- "Aspect lưu trạng thái trong các field" — aspect = Singleton, không thread-safe

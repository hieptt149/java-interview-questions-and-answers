# What is multi-catch (catching multiple exceptions)? (Multi-catch là gì?)

## Junior Level

### Định nghĩa

**Multi-catch** - một tính năng của Java 7+ cho phép bạn bắt nhiều kiểu exception trong một khối `catch` duy nhất.

### Tại sao multi-catch xuất hiện riêng trong Java 7

Trước Java 7, lập trình viên đối mặt với hai vấn đề:

1. **Trùng lặp code:** nếu `IOException` và `SQLException` được xử lý giống hệt nhau, bạn phải viết hai khối catch giống hệt nhau.
2. **Tổ tiên chung quá rộng:** bắt `Exception` là quá thô, bạn mất kiểu khi lan truyền (`throws Exception`).

Trong Java 7, dự án **Coin** (Small Language Changes) đã thêm multi-catch như một giải pháp cho các vấn đề này. Song song đó xuất hiện **try-with-resources** và **Precise Rethrow** - cả ba tính năng hoạt động cùng nhau để cải thiện việc xử lý exception.

```java
import java.io.IOException;
import java.sql.SQLException;

public class DataService {
    public void loadData() {
        try {
            // Các thao tác IO + DB
        } catch (IOException | SQLException e) {
            // Một khối cho cả hai exception
            // e.getClass() trả về kiểu thật: IOException hoặc SQLException
            throw new DataException("Resource operation failed", e);
        }
    }
}
```

### Cú pháp

Các kiểu được ngăn cách bởi dấu gạch đứng `|`:

```java
catch (ExceptionType1 | ExceptionType2 | ExceptionType3 e) {
    // Xử lý chung
}
```

### Hạn chế: các kiểu trong multi-catch không được có quan hệ kế thừa

Compiler **cấm** chỉ định các kiểu có quan hệ kế thừa:

```java
// Lỗi biên dịch - FileNotFoundException kế thừa IOException
catch (FileNotFoundException | IOException e) { }
```

**TẠI SAO có hạn chế này:** nếu compiler cho phép `FileNotFoundException | IOException`, sẽ có sự mơ hồ. `FileNotFoundException` **đã là** một `IOException`, nên multi-catch với cả hai kiểu là dư thừa - `IOException` bao trùm cả hai trường hợp. Compiler coi đây là một lỗi để ngăn sự nhầm lẫn.

**Cách compiler kiểm tra:** khi biên dịch multi-catch, compiler xây dựng kiểm tra theo cặp: với mỗi cặp kiểu `(A, B)` trong multi-catch nó kiểm tra rằng `A` không phải là kiểu con của `B` và `B` không phải là kiểu con của `A`. Nếu vi phạm - lỗi `"Alternatives in a multi-catch statement cannot be related by subclassing"`.

**Cách sửa:** bỏ kiểu con khỏi multi-catch:
```java
// Đúng - chỉ cha bao trùm tất cả các trường hợp
catch (IOException e) { }

// Hoặc các catch riêng biệt nếu cần xử lý khác nhau:
catch (FileNotFoundException e) { /* cụ thể */ }
catch (IOException e) { /* phần còn lại */ }
```

### Biến exception

Trong multi-catch biến `e` là **implicitly final** (ngầm định final) - không thể gán lại:

```java
catch (IOException | SQLException e) {
    e = new Exception(); // Lỗi biên dịch!
}
```

## Middle Level

### Precise Rethrow

Tính năng cực kỳ quan trọng của Java 7+:

```java
public void process() throws IOException, SQLException { // Kiểu chính xác!
    try {
        // code ném IOException hoặc SQLException
    } catch (Exception e) { // Bắt tổ tiên chung
        log.error("Error occurred");
        throw e; // Compiler hiểu chỉ IOException hoặc SQLException sẽ bay ra
    }
}
```

Trước Java 7, bạn sẽ phải khai báo `throws Exception`. Giờ đây compiler phân tích nội dung của `try` và cho phép lan truyền mà không mất kiểu.

### Bytecode

Multi-catch không tạo một handler chung duy nhất. Trong Exception Table, **các mục riêng biệt** được tạo cho mỗi kiểu, trỏ tới cùng một `target`:

| from | to  | target | type         |
| ---- | --- | ------ | ------------ |
| 0    | 10  | 15     | IOException  |
| 0    | 10  | 15     | SQLException |

### Ưu điểm

- **Ít code hơn** - không có xử lý bị trùng lặp
- **File .class nhỏ hơn** - bytecode không bị trùng lặp
- **Chữ ký sạch hơn** - Precise Rethrow giữ các kiểu chính xác

### Nhược điểm

- Biến `e` là `effectively final`
- Không thể tách logic cho các kiểu khác nhau (dùng `catch` riêng biệt cho việc đó)

### Khi nào KHÔNG nên dùng multi-catch

1. **Xử lý khác nhau** - nếu `IOException` cần retry nhưng `SQLException` thì không, hãy dùng các catch riêng biệt. Multi-catch giả định logic **giống hệt nhau** cho tất cả các kiểu.
2. **Các HTTP status khác nhau** - `ValidationException` -> 400, `DataAccessException` -> 500. Status khác nhau = xử lý khác nhau = các catch riêng biệt.
3. **Interrupted + IOException** - `InterruptedException` cần khôi phục cờ interrupt (`Thread.currentThread().interrupt()`), IO thông thường thì không. Kết hợp dẫn tới mất cờ.
4. **Hơn 3 kiểu** - `catch (A | B | C | D e)` trở nên khó đọc. Nếu bạn cần 4+ kiểu, phương thức có lẽ làm quá nhiều.
5. **Khi cần thêm ngữ cảnh khác nhau** - `"File not found"` so với `"DB unavailable"` cần các message lỗi khác nhau. Trong multi-catch message sẽ chung chung và ít thông tin hơn.
6. **Khi một trong các kiểu là RuntimeException** - unchecked exception thường không được bắt một cách tường minh. Sự hiện diện của chúng trong multi-catch báo hiệu một thiết kế đáng xem xét lại.

## Senior Level

### Reflection và multi-catch

Code sạch khi xử lý các exception của reflection:

```java
try {
    Method method = MyClass.class.getDeclaredMethod("doSomething");
    method.invoke(obj);
} catch (NoSuchMethodException | IllegalAccessException | InvocationTargetException e) {
    log.error("Reflection failed", e);
    throw new FrameworkException("Method invocation failed", e);
}
```

### InterruptedException trong multi-catch

Nếu kết hợp `InterruptedException` với các cái khác, đừng quên khôi phục trạng thái interrupt:

```java
catch (InterruptedException | IOException e) {
    if (e instanceof InterruptedException) {
        Thread.currentThread().interrupt();
    }
    log.error("Interrupted or IO error", e);
}
```

### Kích thước Code và Bảo trì

Multi-catch giảm kích thước file `.class` và đơn giản hóa việc bảo trì trong các hệ thống tải cao nơi việc ghi log lỗi được chuẩn hóa.

### Ghi log chính xác

`e.getClass().getName()` trả về tên của class **thật sự** được ném, không phải tổ tiên chung:

```java
catch (IOException | SQLException e) {
    log.error("{} occurred", e.getClass().getSimpleName(), e);
    // Sẽ in "FileNotFoundException" hoặc "SQLTimeoutException"
}
```

### Chẩn đoán

- **SonarLint** - gợi ý thay các khối `catch` giống hệt nhau bằng multi-catch
- **`javap -v`** - hiển thị các mục Exception Table riêng biệt cho mỗi kiểu
- **Metric** - `e.getClass().getSimpleName()` để phân loại trong Prometheus

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Multi-catch (Java 7+) - bắt nhiều kiểu exception trong một `catch` qua `|`
- Xuất hiện trong dự án Coin (Java 7) cùng try-with-resources và Precise Rethrow
- Các kiểu trong multi-catch không được có quan hệ kế thừa - `FileNotFoundException | IOException` = lỗi biên dịch
- Biến `e` trong multi-catch là implicitly final - không thể gán lại
- Trong Exception Table, các mục riêng biệt được tạo cho mỗi kiểu, trỏ tới một target
- Precise Rethrow: `catch (Exception e) { throw e; }` giữ các kiểu chính xác trong `throws` (Java 7+)

**Các câu hỏi phụ thường gặp:**
- **Tại sao không thể `FileNotFoundException | IOException`?** - `FileNotFoundException` đã là một `IOException`, sự mơ hồ
- **Precise Rethrow là gì?** - Compiler phân tích `try` và hiểu các kiểu chính xác khi `throw e` từ `catch (Exception e)`
- **Khi nào KHÔNG nên dùng multi-catch?** - Xử lý khác nhau, các HTTP status khác nhau, `InterruptedException` (cần khôi phục cờ)
- **Cách biết kiểu thật trong multi-catch?** - `e.getClass()` trả về kiểu thật sự, không phải tổ tiên chung

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi kết hợp `InterruptedException` với các cái khác mà không khôi phục cờ" - interrupt của thread bị mất
- "Multi-catch tạo một handler chung trong bytecode" - không, các mục riêng biệt cho mỗi kiểu
- "Tôi viết `throws Exception` với multi-catch" - Precise Rethrow cho phép các kiểu chính xác
- "Multi-catch chậm hơn các catch riêng biệt" - giống nhau, cùng Exception Table

## 🎓 Tóm tắt: Cần biết gì cho mỗi cấp độ

### 🟢 Junior
- HashMap = hash table: mảng các bucket, mỗi bucket = linked list
- put/get: hashCode() → spread → `(n-1) & hash` → chỉ số bucket
- equals() và hashCode() — PHẢI được override cùng nhau
- Các object bằng nhau → cùng hashCode. Cùng hashCode ≠ các object bằng nhau
- HashMap cho phép null key (một) và các null value
- Hashtable — legacy, đừng dùng nó

### 🟡 Middle
- Va chạm — bình thường, không phải bug. HashMap xử lý qua linked list
- Treeification (Java 8+): ở 8 phần tử trong bucket và capacity >= 64 → cây đỏ-đen O(log n)
- Load Factor 0.75 — đánh đổi giữa bộ nhớ và va chạm
- Capacity luôn là lũy thừa của hai. Công thức: `expectedSize / 0.75 + 1`
- Rehashing = tăng đôi mảng, Lo/Hi split theo một bit của hash
- Key mutable = bug: sau khi sửa đổi hashCode tìm trong bucket sai
- String — key lý tưởng: immutable + hashCode được cache

### 🔴 Senior
- Hàm spread: XOR của 16 bit cao và thấp để phân bố đều
- Resize trong Java 8+: Tail Insertion (ngăn vòng lặp vô hạn từ Java 7), nhưng HashMap vẫn KHÔNG thread-safe
- ConcurrentHashMap: CAS + CounterCell (size O(1)), ForwardingNode trong lúc resize, iterator Weakly Consistent
- WeakHashMap: các key = WeakReference, bị GC xóa. KHÔNG dành cho cache!
- Hash Flooding Attack: kẻ tấn công tạo các va chạm → O(n). Giải pháp: hash randomization
- Bộ nhớ: HashMap ~48MB mỗi 1M entry, ConcurrentHashMap ~56MB, TreeMap ~80MB
- Ở capacity < 64 với các va chạm — resize thay vì treeification → O(n) được giữ nguyên

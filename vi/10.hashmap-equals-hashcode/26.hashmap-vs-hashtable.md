# What is the Difference Between HashMap and Hashtable? (Sự khác biệt giữa HashMap và Hashtable là gì?)

## 🟢 Junior Level

**HashMap** và **Hashtable** — cả hai lưu dữ liệu theo định dạng "key-value", nhưng chúng là các class rất khác nhau.

| HashMap                | Hashtable             |
| ---------------------- | --------------------- |
| Nhanh                  | Chậm                  |
| Không thread-safe      | Thread-safe           |
| Cho phép null          | Cấm null              |
| Hiện đại (Java 1.2)    | Legacy (Java 1.0)     |

**Ví dụ:**
```java
// HashMap — lựa chọn hiện đại
Map<String, Integer> map = new HashMap<>();
map.put(null, 1);     // OK
map.put("key", null); // OK

// Hashtable — deprecated, đừng dùng
Map<String, Integer> table = new Hashtable<>();
table.put(null, 1);     // NullPointerException!
table.put("key", null); // NullPointerException!
```

**Lời khuyên chính:** Luôn dùng **HashMap** (hoặc **ConcurrentHashMap** cho đa luồng). Hashtable là legacy.

## 🟡 Middle Level

### So sánh chi tiết

| Đặc điểm         | Hashtable              | HashMap              |
| ---------------- | ---------------------- | -------------------- |
| Đồng bộ hóa      | Có (mọi method)        | Không                |
| Null key         | Không (NPE)            | Có (1)               |
| Null value       | Không (NPE)            | Có (nhiều)           |
| Kế thừa          | Dictionary             | AbstractMap          |
| Phiên bản Java   | JDK 1.0                | JDK 1.2              |
| Lập chỉ mục      | `hash % n`             | `(n-1) & hash`       |
| Iterator         | Enumeration + Iterator | Iterator (fail-fast) |

### Tại sao Hashtable chậm?

Mọi method đều synchronized:
```java
public synchronized V put(K key, V value) { ... }
public synchronized V get(Object key) { ... }
```
Ngay cả để đọc — một khóa được acquire. Trong môi trường đa luồng, mọi thread xếp hàng.

### Thuật toán lập chỉ mục

**HashMap:** `(n-1) & hash` — mask bitwise nhanh (cần lũy thừa của hai)
**Hashtable:** `(hash & 0x7FFFFFFF) % n` — phép chia lấy dư (chậm hơn, nhưng hoạt động với bất kỳ kích thước nào)

HashMap còn spread hash qua một hàm spread (XOR của 16 bit cao và thấp) để phân bố tốt hơn. Hashtable lấy hashCode() trực tiếp.

### Hashtable vẫn được tìm thấy ở đâu?

- Code legacy (các dự án cũ hơn 15-20 năm)
- Các câu hỏi phỏng vấn 😊
- Các sách giáo khoa chưa được cập nhật

### Dùng gì thay thế?

| Nhu cầu                  | Dùng thay cho Hashtable                     |
| ------------------------ | -------------------------------------------- |
| Map đơn giản             | HashMap                                      |
| Thread safety            | ConcurrentHashMap                            |
| Synchronized Map         | `Collections.synchronizedMap(new HashMap<>())` |

### Các sai lầm thường gặp

1. **Dùng Hashtable trong code mới** — đây là một anti-pattern
2. **Nghĩ Hashtable = ConcurrentHashMap nhanh** — không, nó chậm hơn
3. **Enumeration vs Iterator** — Hashtable trả về Enumeration (không có remove, không fail-fast)

## 🔴 Senior Level

### Bên trong: Overhead Đồng bộ hóa

Mỗi method synchronized — monitor enter/exit:
```java
// Hashtable.put:
public synchronized V put(K key, V value) {
    // monitor enter
    // ... logic
    // monitor exit
}
```

Trong môi trường đa luồng:
- Tranh chấp trên một monitor duy nhất
- Thread parking/unparking
- Memory barrier ở mỗi enter/exit

ConcurrentHashMap giải quyết điều này qua CAS + khóa chi tiết.

### Bối cảnh Lịch sử

- **Dictionary** (1995) — tổ tiên trừu tượng của Hashtable, deprecated
- **Hashtable** (1995) — được thích ứng với Map trong Java 1.2
- **HashMap** (1998) — được tạo từ đầu cho Collections Framework

Hashtable chỉ được giữ lại để tương thích ngược.

### Lập chỉ mục: Modulo vs Bitwise AND

```java
// Hashtable:
int index = (hash & 0x7FFFFFFF) % table.length;
// & 0x7FFFFFFF — loại bỏ bit dấu (hash có thể âm)
// % — phép chia lấy dư, thao tác đắt

// HashMap:
int index = (n - 1) & hash;
// Chỉ khi n = 2^k
// & — bitwise AND, 1 chu kỳ
```

Hashtable có thể dùng các số nguyên tố cho kích thước table (phân bố tốt hơn), nhưng modulo đắt hơn.

### Thread Safety: Hashtable vs ConcurrentHashMap

| Chỉ số            | Hashtable   | ConcurrentHashMap   |
| ----------------- | ----------- | ------------------- |
| Đọc (1 thread)    | ~15 ns      | ~8 ns               |
| Đọc (8 thread)    | ~500 ns     | ~60 ns              |
| Ghi (1 thread)    | ~20 ns      | ~15 ns              |
| Ghi (8 thread)    | ~2000 ns    | ~120 ns             |

Hashtable thua 10-30x trên các thao tác đa luồng.

### Tại sao Hashtable vẫn còn trong JDK

- Tương thích ngược (hàng triệu dòng code legacy)
- Một số framework enterprise phụ thuộc vào nó
- Gỡ bỏ nó sẽ phá vỡ code (dù nó tồi)

### Best Practice Hiện đại

```java
// Không bao giờ:
Map<K, V> map = new Hashtable<>();

// Thay vào đó:
Map<K, V> map = new HashMap<>();                        // Đơn luồng
Map<K, V> map = new ConcurrentHashMap<>();              // Đa luồng
Map<K, V> map = Collections.synchronizedMap(new HashMap<>()); // Nếu cần đồng bộ hóa hoàn toàn
```

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Hashtable — legacy (Java 1.0), HashMap — lựa chọn hiện đại (Java 1.2)
- Hashtable là synchronized (mọi method) → chậm, HashMap — không
- Hashtable cấm null, HashMap cho phép null key và các null value
- Lập chỉ mục: Hashtable = `(hash & 0x7FFFFFFF) % n`, HashMap = `(n-1) & hash`
- HashMap dùng hàm spread (XOR 16 bit cao/thấp), Hashtable lấy hashCode() trực tiếp
- Hashtable thua 10-30x so với ConcurrentHashMap trên các thao tác đa luồng
- Hashtable chỉ được giữ lại để tương thích ngược

**Các câu hỏi phụ thường gặp:**
- **Khi nào dùng Hashtable?** — không bao giờ trong code mới; chỉ hỗ trợ legacy
- **Tại sao Hashtable chậm hơn ConcurrentHashMap?** — một monitor duy nhất cho mọi thứ so với khóa chi tiết + CAS
- **Enumeration khác Iterator như thế nào?** — Enumeration không có remove() và không fail-fast
- **Tại sao HashMap nhanh hơn?** — mask bitwise `&` so với phép chia `%`, không đồng bộ hóa

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Hashtable = Map thread-safe nhanh" — không, chậm hơn ConcurrentHashMap
- "HashMap dùng phép chia để lập chỉ mục" — không, mask bitwise
- "Có thể dùng Hashtable trong code mới" — không, nó là một anti-pattern

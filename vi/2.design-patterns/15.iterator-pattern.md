# What is Iterator Pattern? (Iterator Pattern là gì?)

## Junior Level

**Iterator** là một pattern để duyệt qua các phần tử của một collection mà không cần biết cấu trúc bên trong của nó.

**Ví dụ minh họa đơn giản:** Điều khiển từ xa của TV. Bạn chuyển kênh bằng nút "Next" mà không cần biết TV chuyển kênh như thế nào ở bên trong.

**Ví dụ:**
```java
// Iterator trong Java — đây là thứ mà forEach sử dụng
List<String> list = List.of("A", "B", "C");

// Iterator tường minh
Iterator<String> iterator = list.iterator();
while (iterator.hasNext()) {
    String item = iterator.next();
    System.out.println(item);
}

// Giống hệt như vậy nhưng thông qua forEach (sử dụng Iterator ở bên trong)
list.forEach(System.out::println);
```

**Tại sao cần thiết:**
- Cách tiếp cận thống nhất để duyệt bất kỳ collection nào
- Không cần biết cấu trúc bên trong
- Có thể loại bỏ các phần tử trong lúc duyệt

## Middle Level

### Iterator vs ListIterator

```java
List<String> list = new ArrayList<>(List.of("A", "B", "C"));
// List.of() trả về một danh sách immutable, add() sẽ ném ra UnsupportedOperationException

// Iterator — chỉ đi tới (forward)
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    String item = it.next();
    it.remove();  // Có thể loại bỏ
}

// ListIterator — đi tới và đi lùi
ListIterator<String> lit = list.listIterator();
while (lit.hasNext()) {
    lit.next();
    lit.add("new");  // Có thể thêm vào!
}
while (lit.hasPrevious()) {
    lit.previous();  // Có thể đi lùi!
}
```

### Custom Iterator (Iterator tùy chỉnh)

```java
class Tree<T> {
    private Node<T> root;

    public Iterator<T> iterator() {
        return new TreeIterator();
    }

    private class TreeIterator implements Iterator<T> {
        private Queue<Node<T>> queue = new LinkedList<>();

        TreeIterator() {
            if (root != null) queue.add(root);
        }

        public boolean hasNext() {
            return !queue.isEmpty();
        }

        public T next() {
            Node<T> node = queue.poll();
            if (node.left != null) queue.add(node.left);
            if (node.right != null) queue.add(node.right);
            return node.value;
        }
    }
}
```

## Senior Level

### Fail-Fast vs Fail-Safe

```java
// Fail-Fast (ArrayList, HashMap)
List<String> list = new ArrayList<>(List.of("A", "B", "C"));
Iterator<String> it = list.iterator();
it.next();
list.add("D");  // Collection bị sửa đổi
it.next();      // -> ConcurrentModificationException!

// Fail-Safe (CopyOnWriteArrayList, ConcurrentHashMap)
List<String> safeList = new CopyOnWriteArrayList<>(List.of("A", "B", "C"));
Iterator<String> safeIt = safeList.iterator();
safeIt.next();
safeList.add("D");  // Collection bị sửa đổi
safeIt.next();      // Không ném ra exception, nhưng iterator chỉ nhìn thấy các phần tử tại thời điểm tạo (snapshot). Phần tử mới "D" KHÔNG hiển thị trong lượt duyệt hiện tại.
```

### Stream API như một Iterator

```java
// Stream API sử dụng Spliterator ở bên trong, nhưng cung cấp một API cấp độ cao hơn
// (lazy evaluation - tính toán trì hoãn, parallel stream, kết hợp hàm - functional composition).
list.stream()
    .filter(s -> s.startsWith("A"))
    .map(String::toUpperCase)
    .forEach(System.out::println);

// Stream hỗ trợ lazy evaluation
// Iterator — thì không
```

### Kinh nghiệm Production

**Tình huống thực tế: Lỗi Fail-Fast**
- Loại bỏ phần tử trong vòng lặp forEach -> ConcurrentModificationException
- Giải pháp: iterator.remove() hoặc removeIf()
- Bài học: không thể sửa đổi collection trong lúc đang duyệt

### Best Practices (Thực hành tốt nhất)

1. **iterator.remove()** để loại bỏ trong lúc duyệt
2. **removeIf()** để lọc (Java 8+)
3. **Stream** cho các thao tác phức tạp
4. **Collection Fail-Safe** cho tính đồng thời (concurrency)
5. **Đừng sửa đổi** collection trong lúc duyệt

### Tóm tắt cho Senior

- **Iterator** = cách tiếp cận duyệt phổ quát
- **Fail-Fast** = ném ra exception khi bị sửa đổi
- **Fail-Safe** = iterator duyệt trên một bản sao
- **Stream API** = sử dụng Spliterator, cung cấp lazy evaluation và functional composition
- **removeIf()** được ưu tiên hơn so với việc loại bỏ thủ công

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Iterator — cách tiếp cận duyệt phổ quát che giấu cấu trúc bên trong của collection
- Fail-Fast (ArrayList, HashMap) — ConcurrentModificationException khi bị sửa đổi trong lúc duyệt
- Fail-Safe (CopyOnWriteArrayList, ConcurrentHashMap) — iterator duyệt trên snapshot, không ném ra exception
- Stream API sử dụng Spliterator — lazy evaluation, parallel stream, functional composition
- Để loại bỏ trong lúc duyệt: iterator.remove() hoặc removeIf() (Java 8+)
- ListIterator mở rộng Iterator: di chuyển lùi, thêm phần tử
- Không thể sửa đổi collection trong lúc duyệt (ngoại trừ iterator.remove() và các collection Fail-Safe)

**Các câu hỏi phụ thường gặp:**
- **Làm sao để loại bỏ một phần tử trong lúc duyệt?** — iterator.remove() hoặc list.removeIf(predicate)
- **Fail-Fast khác Fail-Safe như thế nào?** — Fail-Fast ném ra exception, Fail-Safe hoạt động trên snapshot
- **Tại sao forEach không thể loại bỏ phần tử?** — forEach sử dụng Iterator ở bên trong, sửa đổi -> ConcurrentModificationException
- **Spliterator là gì?** — Iterator có khả năng song song hóa dành cho Stream API, hỗ trợ việc chia phân vùng (partitioning)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi sửa đổi collection trong các vòng lặp forEach" — chắc chắn sẽ gây ra ConcurrentModificationException
- "Fail-Safe nghĩa là dữ liệu luôn luôn cập nhật mới nhất" — iterator nhìn thấy snapshot, các phần tử mới KHÔNG hiển thị
- "Iterator đã lỗi thời khi có Stream API" — Iterator vẫn được sử dụng ở bên dưới của Stream và forEach
- "removeIf() giống với iterator.remove()" — removeIf() nhận một Predicate, cấp độ cao hơn

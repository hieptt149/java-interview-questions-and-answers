# Which Map Implementation to Choose? (Comparison) (Nên chọn hiện thực Map nào? (So sánh))

## 🟢 Junior Level

Java có nhiều kiểu Map. Đây là một bảng tóm tắt đơn giản:

| Map                   | Khi nào dùng                                  |
| --------------------- | -------------------------------------------- |
| **HashMap**           | Mặc định. Nhanh, đơn giản                    |
| **LinkedHashMap**     | Khi thứ tự chèn quan trọng (hoặc LRU cache)  |
| **TreeMap**           | Khi cần các key được sắp xếp                 |
| **ConcurrentHashMap** | Khi nhiều thread đang làm việc               |
| **WeakHashMap**       | Cho dữ liệu tạm gắn với các object           |
| **EnumMap**           | Khi các key là enum                          |

**Ví dụ:**
```java
// Trường hợp mặc định:
Map<String, Integer> map = new HashMap<>();

// Thread-safe:
Map<String, Integer> concurrent = new ConcurrentHashMap<>();

// Được sắp xếp:
Map<String, Integer> sorted = new TreeMap<>();
```

**Quy tắc chính:** Nếu bạn không biết chọn gì — chọn **HashMap**.

## 🟡 Middle Level

### Bảng so sánh

| Hiện thực             | Thứ tự          | Thread Safety       | Null Key     | Độ phức tạp | Khi nào dùng       |
| --------------------- | --------------- | ------------------- | ------------ | ----------- | ------------------ |
| **HashMap**           | Không           | Không               | Có           | O(1)        | Mặc định           |
| **LinkedHashMap**     | Thứ tự chèn     | Không               | Có           | O(1)        | LRU cache, thứ tự  |
| **TreeMap**           | Được sắp xếp    | Không               | Không        | O(log n)    | Điều hướng, khoảng |
| **ConcurrentHashMap** | Không           | Có                  | Không        | O(1)        | Đa luồng           |
| **WeakHashMap**       | Không           | Không               | Có           | O(1)        | Metadata, cache    |
| **EnumMap**           | Thứ tự Enum     | Không               | Không        | O(1)        | Key là Enum        |
| **IdentityHashMap**   | Không           | Không               | Có           | O(1)        | So sánh tham chiếu |

### LinkedHashMap: LRU Cache

```java
Map<K, V> lruCache = new LinkedHashMap<>(capacity, 0.75f, true) {
    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > MAX_SIZE;
    }
};
```
Tham số `accessOrder = true` — thứ tự theo lần truy cập gần nhất.

### TreeMap: Điều hướng

```java
TreeMap<String, Integer> tree = new TreeMap<>();
tree.put("a", 1);
tree.put("c", 3);
tree.put("b", 2);

tree.subMap("a", "c");    // {"a"=1, "b"=2}
tree.headMap("b");        // {"a"=1}
tree.tailMap("b");        // {"b"=2, "c"=3}
tree.firstKey();          // "a"
tree.lastKey();           // "c"
```

### EnumMap: Tốc độ tối đa

```java
enum Status { ACTIVE, INACTIVE, PENDING }
Map<Status, Integer> counts = new EnumMap<>(Status.class);
// Bên trong: mảng Status.values().length — nhanh tối đa
```

### ConcurrentHashMap: Các thao tác atomic

```java
ConcurrentMap<String, Integer> map = new ConcurrentHashMap<>();
map.putIfAbsent("key", 0);
map.computeIfAbsent("key", k -> computeExpensive());
map.merge("key", 1, Integer::sum);
```

### Immutable Map (Java 10+)

```java
Map<K, V> immutable = Map.of("a", 1, "b", 2);
// Hoặc:
Map<K, V> copy = Map.copyOf(originalMap);
// Được tối ưu bộ nhớ, UnsupportedOperationException khi sửa đổi
```

### IdentityHashMap

**IdentityHashMap** — dùng `==` thay vì `equals()` để so sánh key. Hai object khác nhau với cùng các field được coi là các key khác nhau. Trường hợp sử dụng hiếm: khi reference identity quan trọng, không phải nội dung.

## 🔴 Senior Level

### Các hiện thực bên trong

**HashMap:** Mảng + linked list/tree. O(1) qua hashing.
**LinkedHashMap:** HashMap + list liên kết đôi để sắp thứ tự. Overhead ~2 ref mỗi entry.
**TreeMap:** Cây đỏ-đen. O(log n), không hashing, cần Comparable/Comparator.
**ConcurrentHashMap:** CAS + synchronized trên bucket. Các field volatile, multi-threaded resize.
**EnumMap:** Mảng `Object[enum.length]` thông thường. Truy cập theo `ordinal()`.
**IdentityHashMap:** Open addressing (không chaining). Dùng `==` và `System.identityHashCode()`.

### So sánh hiệu năng

| Thao tác    | HashMap   | LinkedHashMap   | TreeMap   | ConcurrentHashMap   | EnumMap   |
| ----------- | --------- | --------------- | --------- | ------------------- | --------- |
| get()       | O(1)      | O(1)            | O(log n)  | O(1)                | O(1)      |
| put()       | O(1)      | O(1)            | O(log n)  | O(1)                | O(1)      |
| iterate     | O(cap+n)  | O(n)            | O(n)      | O(cap+n)            | O(n)      |
| Bộ nhớ      | Cơ sở     | Cơ sở+16B       | ~48B/node | Cơ sở+volatile      | ~mảng     |
| get 1M (ns) | 5         | 6               | 50        | 8                   | 1         |

### Memory Footprint (mỗi 1M entry)

| Map               | Bộ nhớ xấp xỉ                                                                     |
| ----------------- | ---------------------------------------------------------------------------------- |
| HashMap           | ~48MB                                                                              |
| LinkedHashMap     | ~64MB (+2 ref/entry)                                                              |
| TreeMap           | ~80MB (cây đỏ-đen: 4 ref mỗi entry — parent, left, right, next + màu)             |
| ConcurrentHashMap | ~56MB (volatile + header)                                                          |
| EnumMap (10 key)  | ~100 byte (chỉ mảng)                                                              |

### Các trường hợp biên (Edge Case)

1. **TreeMap và các null key**: `new TreeMap<>()` ném NPE khi null. Với `Comparator.nullsFirst()` — hoạt động.
2. **LinkedHashMap accessOrder**: Khi `true` — mỗi `get()` thay đổi thứ tự (cho LRU). Đây là một mutation!
3. **ConcurrentHashMap size()**: O(n) — đếm mọi phần tử. Đừng dùng trong hot path.
4. **EnumMap**: Chỉ các key enum. Cố dùng kiểu khác = ClassCastException lúc tạo.

### Khi nào dùng cái nào

**Đường đi mặc định:**
```
Cần một Map?
├── Truy cập đa luồng? → ConcurrentHashMap
├── Key = Enum? → EnumMap
├── Cần sắp xếp? → TreeMap
├── Thứ tự chèn / LRU? → LinkedHashMap
├── Cache với GC tự dọn dẹp? → WeakHashMap
└── Mọi thứ khác → HashMap
```

### Các thư viện chuyên biệt

Cho cache production:
- **Caffeine** — thay thế cho Guava Cache, hiệu năng tốt nhất
- **Ehcache** — cache phân tán
- **Redis/Memcached** — cache bên ngoài

Các thư viện này cung cấp:
- Eviction TTL, LRU, LFU
- Thống kê (hit/miss rate)
- Nạp bất đồng bộ
- Hỗ trợ phân tán

### Ma trận quyết định Production

| Yêu cầu                    | Lựa chọn                 |
| -------------------------- | ------------------------ |
| Read-heavy, đơn luồng      | HashMap                  |
| Read-heavy, đa luồng       | ConcurrentHashMap        |
| Write-heavy, đa luồng      | ConcurrentHashMap        |
| Iterate có thứ tự          | LinkedHashMap            |
| Truy vấn theo khoảng       | TreeMap                  |
| Bộ nhớ tối thiểu (key enum)| EnumMap                  |
| Cache với GC dọn dẹp       | WeakHashMap hoặc Caffeine|
| Config immutable           | Map.of()                 |
| Ngữ nghĩa identity         | IdentityHashMap          |

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- HashMap — lựa chọn mặc định, O(1), không thứ tự, cho phép null
- LinkedHashMap — thứ tự chèn, LRU cache qua accessOrder + removeEldestEntry
- TreeMap — sắp xếp, O(log n), điều hướng (subMap, headMap, tailMap), không null key
- ConcurrentHashMap — đa luồng, CAS + synchronized trên bucket, không null
- EnumMap — key enum, bên trong là một mảng, O(1), nhanh nhất và gọn nhất
- WeakHashMap — tự dọn dẹp bởi GC, cho metadata, không dành cho cache production
- IdentityHashMap — so sánh theo `==` thay vì equals, open addressing (không chaining)

**Các câu hỏi phụ thường gặp:**
- **Làm sao tạo một LRU cache?** — LinkedHashMap với accessOrder=true và override removeEldestEntry
- **Tại sao IdentityHashMap dùng open addressing?** — cho ngữ nghĩa identity, không cần chaining
- **Khi nào TreeMap được ưu tiên hơn HashMap?** — cần truy vấn theo khoảng hoặc sắp xếp key
- **Tại sao EnumMap nhanh hơn HashMap?** — mảng với ordinal() làm chỉ số, không hashCode, không va chạm

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "TreeMap = O(1)" — không, O(log n)
- "WeakHashMap = cache production" — không, không có TTL/LRU/giới hạn; dùng Caffeine
- "IdentityHashMap = giống HashMap" — không, dùng `==` thay vì equals

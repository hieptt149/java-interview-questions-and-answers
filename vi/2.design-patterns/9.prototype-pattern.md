# What is Prototype Pattern? (Prototype Pattern là gì?)

## Junior Level

**Prototype** là một pattern cho phép tạo đối tượng mới bằng cách sao chép một đối tượng đã có sẵn. Copy constructor là giải pháp thay thế được khuyến nghị trong Java cho Object.clone().

**Ví dụ minh họa đơn giản:** Việc photocopy tài liệu. Thay vì viết một tài liệu từ đầu mỗi lần, bạn sao chép một mẫu (template) có sẵn và thay đổi những trường cần thiết.

**Ví dụ:**
```java
// Copy constructor
public class User {
    private String name;
    private List<String> permissions;

    // Constructor thông thường
    public User(String name, List<String> permissions) {
        this.name = name;
        this.permissions = new ArrayList<>(permissions);
    }

    // Copy constructor (Prototype)
    public User(User other) {
        this.name = other.name;
        this.permissions = new ArrayList<>(other.permissions); // Sao chép danh sách!
    }
}

// Cách sử dụng
User template = new User("admin", List.of("read", "write"));
User copy = new User(template);  // Bản sao của template!
```

**Khi nào nên sử dụng:**
- Việc tạo đối tượng tốn kém (truy vấn DB, mạng)
- Cần nhiều đối tượng tương tự nhau
- Constructor phức tạp

## Middle Level

### Tại sao Cloneable trong Java lại không tốt

```java
// Các vấn đề với Cloneable
public class User implements Cloneable {
    private String name;
    private List<String> permissions;

    @Override
    protected Object clone() throws CloneNotSupportedException {
        return super.clone();  // Sao chép nông (shallow copy)!
    }
}

User original = new User("Ivan", new ArrayList<>(List.of("read")));
User copy = (User) original.clone();

// Sao chép nông:
copy.getPermissions().add("admin");
// original.getPermissions() cũng bị thay đổi!
```

**Các vấn đề của Cloneable:**
1. Không chứa phương thức `clone()` (marker interface — interface đánh dấu)
2. `clone()` là protected — cần phải override
3. Mặc định là sao chép nông (shallow copy)
4. Không hoạt động với các trường `final`
5. Có checked exception `CloneNotSupportedException`

### Giải pháp: Copy Constructor

```java
// Cách tiếp cận được khuyến nghị (Joshua Bloch)
public class User {
    private final String name;
    private final List<String> permissions;

    // Copy constructor
    public User(User other) {
        this.name = other.name;
        this.permissions = new ArrayList<>(other.permissions); // Sao chép sâu (deep copy)!
    }

    // Static factory method
    public static User copyOf(User other) {
        return new User(other);
    }
}

User original = new User("Ivan", List.of("read"));
User copy = User.copyOf(original);  // Rõ ràng và an toàn về kiểu dữ liệu
```

### Deep Copy vs Shallow Copy

```java
// Shallow — sao chép các tham chiếu
public User(User other) {
    this.name = other.name;               // String — immutable, OK
    this.permissions = other.permissions; // Tham chiếu đến cùng một danh sách!
}

// Deep — sao chép mọi thứ
public User(User other) {
    this.name = other.name;
    this.permissions = new ArrayList<>(other.permissions); // Danh sách mới
    this.address = new Address(other.address);             // Sao chép đối tượng lồng bên trong
}
```

### Prototype Scope trong Spring

```java
// Prototype = instance mới cho mỗi lần request
@Component
@Scope("prototype")
public class OrderProcessor {
    private final Order order;

    public OrderProcessor(Order order) {
        this.order = order;  // Order mới mỗi lần
    }
}

// Cách sử dụng
OrderProcessor p1 = context.getBean(OrderProcessor.class);
OrderProcessor p2 = context.getBean(OrderProcessor.class);
// p1 != p2 -> các đối tượng khác nhau!

// Cạm bẫy: Prototype bên trong Singleton
@Component  // Singleton!
public class OrderService {
    @Autowired
    private OrderProcessor processor;  // Chỉ được tạo MỘT LẦN!
}

// Giải pháp 1: @Lookup
@Component
public abstract class OrderService {
    @Lookup
    protected abstract OrderProcessor getProcessor();
}

// Giải pháp 2: ObjectProvider
@Component
public class OrderService {
    private final ObjectProvider<OrderProcessor> processorProvider;

    public void process() {
        OrderProcessor processor = processorProvider.getObject();  // Mới mỗi lần!
    }
}
```

### Cloning thông qua Serialization

```java
// Đối với các đối tượng phức tạp có lồng nhau sâu
public static <T extends Serializable> T deepClone(T object) {
    try (ByteArrayOutputStream baos = new ByteArrayOutputStream();
         ObjectOutputStream oos = new ObjectOutputStream(baos)) {
        oos.writeObject(object);

        try (ByteArrayInputStream bais = new ByteArrayInputStream(baos.toByteArray());
             ObjectInputStream ois = new ObjectInputStream(bais)) {
            return (T) ois.readObject();
        }
    } catch (Exception e) {
        throw new RuntimeException(e);
    }
}

// Hoặc thông qua Jackson (JSON)
public static <T> T cloneViaJson(T object, Class<T> clazz) {
    String json = objectMapper.writeValueAsString(object);
    return objectMapper.readValue(json, clazz);
}
```

### Các lỗi thường gặp

1. **Sao chép nông các trường có thể thay đổi (mutable)**
   ```java
   // Thay đổi bản sao ảnh hưởng đến bản gốc
   copy.getList().add("item");
   original.getList().contains("item"); // true!
   ```

2. **Prototype bên trong Singleton**
   ```java
   // Prototype sẽ chỉ được tạo một lần
   @Service
   public class MyService {
       @Autowired
       private PrototypeBean bean;  // Chỉ có một instance duy nhất!
   }
   ```

## Senior Level

### Các vấn đề của Cloneable ở cấp độ JMM

```java
// super.clone() hoạt động ở cấp độ Object.clone()
// -> Sao chép bộ nhớ, bỏ qua constructor
// -> Các trường final KHÔNG được khởi tạo
// -> Bất biến (invariant) của class bị vi phạm

public class ImmutableUser {
    private final String name;
    private final List<String> permissions;

    public ImmutableUser(String name, List<String> permissions) {
        this.name = name;
        this.permissions = List.copyOf(permissions);
    }

    // clone() không thể khởi tạo các trường final!
    // Sẽ cần phải dùng reflection hoặc unsafe
}
```

### Copy Constructor vs Cloneable: Benchmark

```
1 triệu lần sao chép:
  Constructor copy:   50ms   (gọi trực tiếp)
  clone():            80ms   (phương thức native, không dùng reflection. Nhưng bỏ qua constructor, nên bất biến của class có thể bị vi phạm)
  JSON clone:         500ms  (serialization)
  Serialization:      800ms  (serialization của Java)
```

### Vòng đời Prototype trong Spring

```java
// Spring KHÔNG quản lý vòng đời của Prototype bean!
@Component
@Scope("prototype")
public class ExpensiveResource {

    @PostConstruct
    public void init() {
        System.out.println("Created");  // Sẽ được gọi
    }

    @PreDestroy
    public void cleanup() {
        System.out.println("Destroyed");  // SẼ KHÔNG được gọi!
    }
}

// Giải pháp: tự dọn dẹp thủ công
@Component
public class ResourceCleaner {
    private final List<ExpensiveResource> resources = new ArrayList<>();

    public ExpensiveResource getResource() {
        ExpensiveResource r = context.getBean(ExpensiveResource.class);
        resources.add(r);
        return r;
    }

    @PreDestroy
    public void cleanup() {
        resources.forEach(ExpensiveResource::cleanup);
    }
}
```

### Prototype để tối ưu hóa

```java
// Prototype được lưu bộ nhớ đệm (cached) thay vì tạo tốn kém
public class DocumentTemplate {
    private static final Document PROTOTYPE;

    static {
        // Khởi tạo tốn kém (DB, mạng)
        PROTOTYPE = loadFromDatabase();
    }

    public static Document createDocument() {
        return new Document(PROTOTYPE);  // Sao chép prototype
    }
}
```

### Kinh nghiệm Production

**Tình huống thực tế: Lỗi Prototype + Singleton**
- OrderProcessor (prototype) được inject vào OrderService (singleton)
- Lỗi: tất cả đơn hàng đều được xử lý bởi cùng một processor
- Mất 4 giờ để debug -> tìm ra thông qua thread dump
- Giải pháp: ObjectProvider

### Best Practices (Thực hành tốt nhất)

1. **ĐỪNG sử dụng Cloneable** — copy constructor tốt hơn
2. **Deep copy** cho các trường có thể thay đổi
3. **@Scope("prototype")** + ObjectProvider trong Spring
4. **JSON cloning** cho các đối tượng phức tạp
5. **Cache prototype** cho các đối tượng tốn kém
6. **@PreDestroy KHÔNG hoạt động** đối với Prototype trong Spring
7. **Trường final** không tương thích với clone()

### Tóm tắt cho Senior

- **Cloneable** = thiết kế có khiếm khuyết, hãy tránh nó
- **Copy Constructor** = an toàn về kiểu dữ liệu, hoạt động với final
- **Spring Prototype** = bean mới cho mỗi lần gọi getBean()
- **Vòng đời:** @PreDestroy KHÔNG được gọi đối với Prototype
- **Singleton + Prototype** = cạm bẫy -> ObjectProvider/@Lookup
- **Deep Clone:** JSON/Serialization cho các đối tượng phức tạp
- **Hiệu năng:** constructor > clone() > JSON > serialization

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Prototype — tạo đối tượng bằng cách sao chép các đối tượng đã có sẵn, không phải thông qua constructor
- Cloneable trong Java — thiết kế không tốt: marker interface không có phương thức clone(), sao chép nông, không tương thích với final
- Cách tiếp cận được khuyến nghị: copy constructor — an toàn về kiểu dữ liệu, hoạt động với các trường final
- Deep copy sao chép tất cả các trường có thể thay đổi, shallow copy sao chép các tham chiếu (thay đổi ảnh hưởng đến bản gốc)
- Spring @Scope("prototype") — instance mới cho mỗi lần gọi getBean(), nhưng @PreDestroy KHÔNG được gọi
- Prototype trong Singleton — cạm bẫy: chỉ được tạo một lần, giải pháp thông qua ObjectProvider hoặc @Lookup
- Benchmark: constructor copy (50ms) > clone() (80ms) > JSON (500ms) > serialization (800ms)

**Các câu hỏi phụ thường gặp:**
- **Tại sao Cloneable lại không tốt?** — Marker interface, clone() là protected, mặc định sao chép nông, không tương thích với final
- **Deep copy khác shallow copy như thế nào?** — Deep sao chép tất cả các đối tượng lồng bên trong, shallow chỉ sao chép các tham chiếu
- **Điều gì xảy ra nếu Prototype bean được inject vào Singleton?** — Chỉ được tạo một lần trong lúc khởi tạo Singleton
- **Làm sao để deep copy một đối tượng phức tạp?** — Serialization (ByteArrayOutputStream) hoặc JSON (Jackson)

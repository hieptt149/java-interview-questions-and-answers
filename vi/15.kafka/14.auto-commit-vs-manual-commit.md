# What is the difference between auto commit and manual commit (Sự khác biệt giữa auto commit và manual commit là gì)

## Junior Level

### Auto Commit

Client KafkaConsumer tự động gửi các request commit mỗi auto.commit.interval.ms.
Đây là logic phía client, không phải phía broker — broker không khởi xướng các commit.

```java
props.put("enable.auto.commit", "true");
props.put("auto.commit.interval.ms", "5000");  // mỗi 5 giây
```

**Ưu Điểm:**
- Đơn giản, không cần gọi thủ công
- Kafka tự xử lý các commit

**Nhược Điểm:**
- Có thể mất mát hoặc trùng lặp
- Commit ngay cả khi chưa xử lý

### Manual Commit

**Chính bạn** quyết định khi nào lưu offset.

```java
props.put("enable.auto.commit", "false");
consumer.commitSync();  // khi bạn muốn
```

**Ưu Điểm:**
- Kiểm soát hoàn toàn
- Commit sau khi xử lý

**Nhược Điểm:**
- Cần gọi thủ công
- Nhiều code hơn

### So Sánh

```java
// Auto commit — đơn giản
props.put("enable.auto.commit", "true");
consumer.subscribe(List.of("orders"));
// Kafka tự động commit mỗi 5 giây

// Manual commit — đáng tin cậy
props.put("enable.auto.commit", "false");
while (running) {
    ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
    for (var record : records) {
        process(record);
    }
    consumer.commitSync();  // sau khi xử lý
}
```

## Middle Level

### Auto Commit — Chi Tiết

```
Cách nó hoạt động:
1. Consumer poll → Kafka tự động commit
2. Mỗi auto.commit.interval.ms
3. Commit offset đã nhận cuối cùng (không phải offset đã xử lý!)

Các vấn đề:
- Commit trước khi xử lý → mất mát khi crash
- Khoảng cố định — độc lập với xử lý
- Không có kiểm soát lỗi
```

### Manual Commit — Các Lựa Chọn

**Sync Commit:**
```java
// Chờ xác nhận của broker
consumer.commitSync();
// Đáng tin cậy, nhưng chậm hơn
```

**Async Commit:**
```java
// Không chờ xác nhận
consumer.commitAsync((offsets, exception) -> {
    if (exception != null) {
        log.error("Commit failed", exception);
    }
});
// Async commit gửi request và không chờ. Nếu broker crash trước khi ghi — offset không được lưu.
// Khi restart, consumer sẽ đọc lại cùng các message (trùng lặp, không phải mất dữ liệu).
```

### Các Lỗi Thường Gặp

1. **Auto commit + xử lý lâu:**
```
Commit mỗi 5 giây → xử lý mất 10 giây → mất message
```

2. **Manual commit không có xử lý lỗi:**
```java
consumer.commitAsync();  // lỗi → không ai biết
```

3. **Kết hợp các chiến lược commit:**
```java
// Auto và manual commit đồng thời
// → Hành vi không thể dự đoán
```

### Khi Nào Dùng Cái Gì

| Chiến lược            | Khi nào dùng                                |
| ------------------- | ------------------------------------------ |
| Auto commit         | Prototype, test, dữ liệu không quan trọng       |
| Manual sync commit  | Production, dữ liệu quan trọng                  |
| Manual async commit | Throughput cao, chấp nhận trùng lặp    |

## Senior Level

### Cài Đặt Nội Bộ

**Auto Commit:**
```
Được cài đặt trong KafkaConsumer:
- Trên mỗi poll() kiểm tra xem khoảng thời gian đã trôi qua chưa
- Nếu có → gửi request commit
- Không chờ phản hồi (fire and forget)
```

**Manual Commit:**
```
commitSync():
  - Gửi request → chờ phản hồi
  - Retry khi có lỗi tạm thời
  - Ném exception khi thất bại

commitAsync():
  - Gửi request → không chờ
  - Callback khi hoàn thành
  - Không retry (trách nhiệm của người gọi)
```

### Các Vấn Đề Của Auto Commit — Đào Sâu

**1. Offset Lag:**
```
Auto commit commit offset đã nhận, không phải offset đã xử lý

Dòng thời gian:
  T=0: Poll nhận offset 100
  T=2: Auto commit offset 100
  T=5: Bắt đầu xử lý offset 100
  T=8: Crash

Kết quả: offset 100 bị mất (đã commit, chưa xử lý)
```

**2. Không Khớp Khoảng Commit:**
```
Xử lý nhanh + khoảng commit dài:
  Đã xử lý 1000 message → chờ 5 giây → commit
  Nếu crash → sẽ xử lý lại 1000 message

Xử lý chậm + khoảng commit ngắn:
  Commit các offset chưa xử lý → mất dữ liệu
```

### Các Pattern Production

**1. Manual Sync Commit Sau Batch:**
```java
while (running) {
    ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
    try {
        for (var record : records) {
            process(record);
        }
        consumer.commitSync();  // chỉ sau khi xử lý tất cả
    } catch (Exception e) {
        log.error("Processing failed, offsets not committed", e);
        // Không commit → các message sẽ được đọc lại
    }
}
```

**2. Async Commit Với Fallback:**
```java
consumer.commitAsync((offsets, exception) -> {
    if (exception != null) {
        // Fallback về sync commit
        try {
            consumer.commitSync(offsets);
        } catch (Exception e) {
            log.error("Both async and sync commit failed", e);
        }
    }
});
```

**3. Periodic Commit:**
```java
// Commit mỗi N giây bất kể các batch
ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor();
scheduler.scheduleAtFixedRate(() -> {
    consumer.commitAsync();
}, 0, 5, TimeUnit.SECONDS);
```

### So Sánh Hiệu Năng

```
Overhead độ trễ (mỗi commit):
  Auto commit:     ~0ms (fire and forget)
  Async commit:    ~1ms (callback)
  Sync commit:     ~10-50ms (chặn)

Độ tin cậy:
  Auto commit:     Thấp (không có xử lý lỗi)
  Async commit:    Trung bình (callback, không retry)
  Sync commit:     Cao (retry, xác nhận)
```

### Monitoring

**Các metrics chính:**


### Các Thực Hành Tốt Nhất

```
✅ Manual commit cho production
✅ CommitSync cho dữ liệu quan trọng
✅ CommitAsync cho throughput cao
✅ Xử lý lỗi cho tất cả các commit
✅ Giám sát sức khỏe commit

❌ Auto commit cho production
❌ Auto commit cho dữ liệu quan trọng
❌ Không có xử lý lỗi commit
❌ Kết hợp các chiến lược commit
❌ Bỏ qua độ trễ commit
```

### Các Quyết Định Kiến Trúc

1. **Manual sync commit** — tiêu chuẩn cho production
2. **Async commit với fallback** — cân bằng hiệu năng/độ tin cậy
3. **Auto commit không được khuyến nghị cho production với dữ liệu quan trọng.** Chấp nhận được cho: metrics, log, phân tích real-time với mất mát chấp nhận được.
4. **Xử lý lỗi là bắt buộc** — retry hoặc alert

### Tóm Tắt Cho Senior

- Auto commit commit offset đã nhận, không phải offset đã xử lý
- Manual commit cung cấp kiểm soát về độ tin cậy
- Sync commit cho độ tin cậy, async cho throughput
- Xử lý lỗi là bắt buộc cho production
- Giám sát độ trễ commit rất quan trọng cho các health check

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Auto commit: mỗi `auto.commit.interval.ms`, commit offset đã nhận (không phải đã xử lý!)
- Manual commit: kiểm soát hoàn toàn, commit SAU khi xử lý — đảm bảo at-least-once
- Sync commit: chặn cho đến khi xác nhận (10-50ms), đáng tin cậy; Async: không chặn, callback
- Các vấn đề của auto commit: offset lag (commit trước khi xử lý), không khớp khoảng
- Async commit với fallback: khi lỗi → sync commit (một lần thử retry duy nhất)
- Manual commit — tiêu chuẩn cho production; auto commit — chỉ cho prototype/test
- Kết hợp các chiến lược commit = hành vi không thể dự đoán

**Các câu hỏi phụ thường gặp:**
- *Tại sao auto commit nguy hiểm?* — Commit offset đã nhận, không phải đã xử lý → khi crash, dữ liệu bị mất.
- *Cái nào tốt hơn, sync hay async?* — Sync cho độ tin cậy, async cho throughput với fallback khi lỗi.
- *Fallback của async commit hoạt động như thế nào?* — Khi lỗi callback → sync commit → nếu cũng thất bại → log lỗi.
- *Auto commit có phải phía broker không?* — Không, đó là logic phía client trong KafkaConsumer, không phải broker.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Auto commit là lựa chọn tốt cho production" — commit trước khi xử lý
- "Async commit không có xử lý lỗi là ổn" — mất offset
- "Auto commit được khởi xướng bởi broker" — đó là logic phía client
- "Bạn có thể kết hợp auto và manual commit" — hành vi không thể dự đoán

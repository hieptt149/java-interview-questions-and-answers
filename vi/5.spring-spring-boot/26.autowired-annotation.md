# What Does the @Autowired Annotation Do? (Annotation @Autowired làm gì?)

## Junior Level

**@Autowired** báo cho Spring inject một phụ thuộc.

```java
@Service
public class OrderService {

    @Autowired  // Spring tự tìm và inject OrderRepository
    private OrderRepository repo;
}
```

**Nơi nó hoạt động:**
- Constructor
- Field
- Setter

**Quy tắc:**
- Một bean của kiểu đó -> inject nó
- Nhiều bean -> lỗi hoặc @Qualifier

---

## Middle Level

### AutowiredAnnotationBeanPostProcessor

```
Xử lý @Autowired:
  1. Quét các field/phương thức/constructor
  2. Tạo InjectionMetadata (cache)
  3. Tìm các bean phù hợp
  4. Inject qua reflection
```

### Thuật toán tìm kiếm

```
1. Theo kiểu (byType) - Spring tìm tất cả các bean của kiểu này
2. Nếu có nhiều - @Qualifier lọc theo tên
3. Nếu không có @Qualifier - kiểm tra @Primary (marker "mặc định" toàn cục)
4. Nếu không có @Primary - theo tên biến (byName)
```

### Constructor Injection (Khuyến nghị)

```java
@Service
public class OrderService {
    private final OrderRepository repo;

    // Một constructor duy nhất -> không cần @Autowired!
    public OrderService(OrderRepository repo) {
        this.repo = repo;
    }
}
```

### Inject Collection

```java
// Tất cả các bean kiểu PaymentService
@Autowired
List<PaymentService> payments;

// Map: tên bean -> bean
@Autowired
Map<String, PaymentService> paymentMap;
```

## Senior Level

### ObjectProvider

```java
@Autowired
ObjectProvider<PaymentService> provider;

// Lấy theo lối lazy
PaymentService service = provider.getIfAvailable();

// Stream của tất cả các bean
provider.stream().forEach(...);

// Giải quyết vòng phụ thuộc!
```

### Overhead của Reflection

```
Field Injection -> setAccessible(true) -> reflection
  -> + overhead lúc khởi tạo

Constructor Injection -> lời gọi trực tiếp
  -> Nhanh hơn

AOT (GraalVM) -> reflection -> code trực tiếp
  -> Không có overhead reflection (setAccessible). Các phụ thuộc được phân giải lúc biên dịch.
```

### Kinh nghiệm Production

**Tình huống thực tế: static field**
```java
@Autowired
private static Repo repo;  // KHÔNG hoạt động!

// Spring inject vào các instance, không phải các class
// -> repo = null
```

### Best Practices

1. **Constructor** -> làm mặc định
2. **Không cần @Autowired** cho constructor duy nhất
3. **ObjectProvider** -> cho các vòng phụ thuộc và lazy
4. **Tránh** các static field
5. **Collection** -> tất cả các bean của kiểu
6. **AOT** -> reflection được thay bằng code trực tiếp

### Tóm tắt cho Senior

- **AutowiredAnnotationBeanPostProcessor (AABPP)** -> xử lý @Autowired
- **Constructor** -> nhanh hơn, các field final
- **ObjectProvider** -> lazy, các vòng phụ thuộc
- **static** -> không hoạt động
- **Collection** -> tất cả các bean của kiểu
- **AOT** -> không có reflection trong Native Image

## Interview Cheat Sheet

**Cần phải biết:**
- @Autowired được xử lý bởi AutowiredAnnotationBeanPostProcessor — quét các field/phương thức/constructor
- Thuật toán: byType -> @Qualifier -> @Primary -> byName -> lỗi
- Constructor Injection — cách tiếp cận được khuyến nghị; với một constructor duy nhất, không cần @Autowired
- Inject Collection: List<T> — tất cả các bean của kiểu, Map<String, T> — tên bean -> bean
- ObjectProvider — lấy theo lối lazy, stream của tất cả các bean, giải quyết circular dependency
- @Autowired trên các static field KHÔNG hoạt động — Spring inject vào các instance, không phải các class
- Constructor Injection nhanh hơn Field Injection: lời gọi trực tiếp so với reflection (setAccessible)

**Các câu hỏi phụ thường gặp:**
- *Điều gì xảy ra nếu có hai bean cùng kiểu mà không có @Qualifier?* — NoUniqueBeanDefinitionException (trừ khi có @Primary hoặc tên khớp).
- *Làm sao giải quyết một circular dependency?* — ObjectProvider.getIfAvailable() hoặc setter/field injection thay vì constructor.
- *Tại sao Constructor Injection được khuyến nghị?* — Field bất biến (final), không reflection, dễ test hơn, phụ thuộc tường minh.
- *@Autowired có hoạt động trong GraalVM Native Image không?* — Có, nhưng reflection được thay bằng code trực tiếp trong lúc biên dịch AOT.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "@Autowired trên static field hoạt động" — không, Spring không inject vào các static field.
- "Spring tìm theo tên trước" — không, byType trước, rồi mới byName.
- "Field Injection tốt hơn Constructor Injection" — ngược lại, constructor cho tính bất biến và khả năng test.
- "@Autowired luôn bắt buộc" — không, với một constructor duy nhất Spring inject tự động.

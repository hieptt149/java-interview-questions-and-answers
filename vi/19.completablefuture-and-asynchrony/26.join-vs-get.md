# What Does join() Method Do and How Does It Differ from get()? (Phương thức join() làm gì và nó khác gì so với get())

## 🟢 Junior Level

**`join()`** và **`get()`** — cả hai đều chờ CompletableFuture hoàn thành và trả về kết quả.

**Khác biệt chính:**
- **`get()`** — ném ra **checked exception** (`InterruptedException`, `ExecutionException`)
- **`join()`** — ném ra **unchecked** (`CompletionException`)

```java
CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> "Hello");

// get() — cần try-catch
try {
    String result = cf.get();  // ném ra checked exception
} catch (InterruptedException | ExecutionException e) {
    // xử lý
}

// join() — đơn giản hơn
String result = cf.join();  // ném ra CompletionException (unchecked)
```

## 🟡 Middle Level

### Khi Nào Dùng Cái Nào

**get() — khi bạn cần checked exception:**
```java
try {
    String result = cf.get(5, TimeUnit.SECONDS);  // với timeout
} catch (TimeoutException e) {
    // xử lý timeout
} catch (InterruptedException e) {
    // xử lý interrupt
}
```

### Khác Biệt Thực Tế Quan Trọng

get() có phiên bản với timeout: get(5, TimeUnit.SECONDS).
join() KHÔNG có biến thể timeout. Trong code production khi bạn cần timeout,
dùng get() hoặc bọc join() qua orTimeout().

**join() — cho chuỗi và test:**
```java
// Trong chuỗi
CompletableFuture.allOf(cf1, cf2, cf3)
    .thenApply(v -> {
        String r1 = cf1.join();  // không cần try-catch
        String r2 = cf2.join();
        String r3 = cf3.join();
        return combine(r1, r2, r3);
    });

// Trong test
@Test
void test() {
    String result = cf.join();  // đơn giản hơn
    assertEquals("expected", result);
}
```

### Các Lỗi Thường Gặp

1. **join() không có xử lý lỗi:**
```java
// ❌ Nếu CF thất bại — CompletionException
String result = cf.join();  // có thể ném ra

// ✅ Có xử lý
cf.exceptionally(ex -> "fallback")
  .join();  // an toàn
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

```java
// Biểu diễn đơn giản hóa. Các phương thức JDK thực tế có thể khác.
public T get() throws InterruptedException, ExecutionException {
    Object r = reportGet();
    if (r instanceof AltResult alt) {
        if (alt.ex != null) throw new ExecutionException((Throwable) alt.ex);
    }
    return (T) r;
}

public T join() {
    Object r = reportGet();
    if (r instanceof AltResult alt) {
        if (alt.ex != null) throw new CompletionException((Throwable) alt.ex);
    }
    return (T) r;
}

// Khác biệt duy nhất là kiểu ngoại lệ!
```

### Hiệu Năng

```
get(): ~100 ns (xử lý checked exception)
join(): ~100 ns (nội bộ giống hệt)

Khác biệt không đáng kể — lựa chọn dựa trên sự tiện lợi
```

### Best Practices

```java
// ✅ join() trong chuỗi
cf.thenApply(v -> cf2.join());

// ✅ join() trong test
assertEquals("expected", cf.join());

// ✅ get(timeout) cho production
cf.get(5, TimeUnit.SECONDS);

// ❌ join() không có xử lý lỗi
// ❌ get() không có timeout trong production
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- join() — CompletionException unchecked, get() — checked InterruptedException + ExecutionException
- join() KHÔNG có timeout, get(timeout, unit) CÓ timeout
- join() được ưu tiên trong chuỗi và test, get(timeout) cho production
- Nội bộ giống hệt nhau — khác biệt chỉ ở kiểu ngoại lệ
- Cả hai đều chặn thread cho đến khi CF hoàn thành

**Các câu hỏi phụ thường gặp:**
- **join() hay get() — khi nào dùng cái nào?** — join() trong chuỗi/test, get(timeout) trong production
- **join() có thể ném ra TimeoutException không?** — Không. Cần orTimeout() trước join()
- **CompletionException vs ExecutionException?** — CompletionException (join) — unchecked, ExecutionException (get) — checked
- **join() sau allOf() có chặn không?** — Không, nếu allOf() đã hoàn thành. Nhưng join() không có allOf() — chặn

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "join() không chặn" — nó chặn cho đến khi CF hoàn thành
- "get() và join() hoàn toàn giống hệt nhau" — kiểu ngoại lệ khác nhau, get có timeout
- "join() không có timeout trong production là ổn" — chờ đợi vô hạn khi có lỗi

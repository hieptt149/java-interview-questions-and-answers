# What is the time complexity of operations in LinkedList? (Độ phức tạp thời gian của các thao tác trong LinkedList là gì?)

## 🟢 Junior Level

**LinkedList** — danh sách liên kết đôi, trong đó mỗi phần tử là một đối tượng riêng biệt.

| Thao tác          | Độ phức tạp | Giải thích                                                                               |
| ----------------- | ---------- | --------------------------------------------------------------------------------------- |
| `get(index)`      | **O(n)**   | Cần iterate qua các phần tử                                                               |
| `add(e)`          | **O(1)**   | Thêm vào cuối                                                                             |
| `addFirst(e)`     | **O(1)**   | Thêm vào đầu                                                                              |
| `add(index, e)`   | **O(n)**   | Cần tìm vị trí                                                                            |
| `remove(index)`   | **O(n)**   | Cần tìm vị trí                                                                            |
| `iterator.remove()`| **O(1)**  | Nếu iterator đã đến được phần tử đó (tức là, bạn đang duyệt và xóa phần tử hiện tại)       |

**Quan trọng:** `get(index)` thì chậm!
```java
// ❌ Chậm: O(n²)
for (int i = 0; i < list.size(); i++) {
    list.get(i);  // Duyệt mỗi lần!
}

// ✅ Nhanh: O(n)
for (String s : list) {
    // Một lần duyệt
}
```

## 🟡 Middle Level

### Chi tiết các thao tác

```java
// get(index): O(n)
// → Duyệt từ head HOẶC tail (cái nào gần hơn)
// → Không có truy cập ngẫu nhiên!

// add(e): O(1)
// → Thêm vào cuối
// → Không có resize (khác với ArrayList)

// add(0, e): O(1)
// → Thêm vào đầu
// → Nhanh hơn ArrayList (không dịch chuyển)

// add(index, e): O(n)
// → O(n) để tìm vị trí
// → O(1) để chèn
// → Tổng cộng: O(n)

// iterator.remove(): O(1)
// → Lợi thế duy nhất!
// → Nếu iterator đã ở phần tử đó
```

### Bẫy khi iterate

```java
// ❌ O(n²) — lỗi kinh điển!
LinkedList<String> list = ...;
for (int i = 0; i < list.size(); i++) {
    String s = list.get(i);  // O(n) mỗi lần!
    // Tổng cộng: n × n = n²
}

// ✅ O(n) — dùng foreach
for (String s : list) {
    // Một lần duyệt
}

// ✅ O(n) — dùng iterator
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    String s = it.next();
}
```

### Bộ nhớ

```
LinkedList Node: 32 byte
  → Object Header: 12 byte
  → item reference: 4 byte
  → next reference: 4 byte
  → prev reference: 4 byte
  → Padding: 8 byte

ArrayList: 4 byte cho mỗi tham chiếu
  → Chỉ có tham chiếu trong mảng

→ LinkedList dùng nhiều bộ nhớ hơn 8 lần!
```

## 🔴 Senior Level

### Khi nào KHÔNG dùng LinkedList

1. **Nếu hiệu năng quan trọng** — ArrayList hoặc ArrayDeque luôn nhanh hơn
2. **Nếu cần cache locality** — các node của LinkedList nằm rải rác khắp heap
3. **Nếu bộ nhớ hạn chế** — LinkedList lãng phí 24+ byte cho mỗi node (prev + next + item)

### Thảm họa Cache Locality

```
CPU Cache Line: 64 byte

ArrayList:
  [ref1][ref2][ref3][ref4]...
  → 1 lần đọc → 8 ref trong L1
  → Iterate: cache miss tối thiểu

LinkedList:
  [Node1]...[Node2]...[Node3]
  → Mỗi lần next = cache miss
  → Chờ RAM: 100+ chu kỳ
  → Pipeline stall — CPU buộc phải chờ dữ liệu từ RAM, toàn bộ pipeline lệnh dừng lại. Tốn 100-300 chu kỳ CPU.
```

### Áp lực GC (GC Pressure)

```
LinkedList: 1M phần tử
  → 1M đối tượng Node
  → 32 MB overhead
  → Minor GC: quét 1M đối tượng

ArrayList: 1M phần tử
  → 1 mảng Object[]
  → 4 MB
  → GC: một ref
```

### Khi nào LinkedList O(1) thực sự nhanh hơn?

```
Lý thuyết: LinkedList.add(0, e) = O(1)
Thực tế: ArrayList nhanh hơn cho đến ~10-20k phần tử!

Tại sao?
  LinkedList: new Node() → cấp phát → 3 ref
  ArrayList: System.arraycopy() → SIMD

→ Cấp phát đối tượng TỐN KÉM HƠN dịch chuyển mảng!

Với các list nhỏ (< 10-20k phần tử). Trên các list lớn có chèn vào đầu thường xuyên, LinkedList có thể thắng.
```

### Trường hợp duy nhất cho LinkedList

```java
// List RẤT lớn + xóa thông qua iterator
LinkedList<String> list = new LinkedList<>();

Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (shouldRemove(it.next())) {
        it.remove();  // O(1) — chỉ nối lại các ref
    }
}

// ArrayList: O(n) — dịch chuyển mảng mỗi lần
// NHƯNG! removeIf() trong ArrayList cũng O(n) một lần!
list.removeIf(e -> shouldRemove(e));  // Dùng cái này!
```

### Java 21: SequencedCollection

```java
// LinkedList giờ đây là SequencedCollection
list.getFirst();   // O(1)
list.getLast();    // O(1)
list.reversed();   // O(1) — view

// ArrayDeque cũng hỗ trợ
// Và nhanh hơn!
```

### Best Practices

1. **Tránh** LinkedList — trong đại đa số trường hợp ArrayList hoặc ArrayDeque hoạt động tốt hơn
2. **Không bao giờ** dùng `get(index)` trong vòng lặp
3. **ArrayDeque** > LinkedList cho các queue/stack
4. **removeIf()** > iterate kèm xóa
5. **foreach** > `for-i` cho LinkedList
6. **Bộ nhớ:** LinkedList lớn hơn 8 lần
7. **GC:** LinkedList tạo ra hàng triệu đối tượng

### Tóm tắt cho Senior

- **get(index)** = O(n) — nhược điểm chính
- **add/remove(0)** = O(1) — nhưng ArrayList nhanh hơn với list nhỏ
- **iterator.remove()** = O(1) — lợi thế thực sự duy nhất
- **Cache Miss** ở mỗi phần tử → pipeline stall
- **Áp lực GC** = 32 byte × N đối tượng
- **Bẫy O(n²)** — dùng foreach, không phải for-i
- **removeIf()** > iterate kèm xóa
- **ArrayDeque** > LinkedList luôn luôn cho các stack/queue

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- get(index) = O(n) — duyệt từ head hoặc tail (cái nào gần hơn), không có truy cập ngẫu nhiên
- add(e)/addFirst(e) = O(1), nhưng ArrayList nhanh hơn với list nhỏ nhờ SIMD
- iterator.remove() = O(1) — lợi thế thực sự duy nhất của LinkedList
- Bộ nhớ: 32 byte cho mỗi phần tử (Object header + item + next + prev + padding) — nhiều hơn ArrayList 8 lần
- Thảm họa Cache Miss: mỗi lần next = 100+ chu kỳ chờ RAM, pipeline stall
- Bẫy O(n²): for-i với get(i) = n × O(n) = O(n²), dùng foreach hoặc iterator
- Áp lực GC: 1M phần tử = 1M đối tượng Node = 32 MB overhead
- ArrayDeque > LinkedList cho các stack/queue — nhanh hơn và ít áp lực GC hơn

**Các câu hỏi phụ thường gặp:**
- Tại sao LinkedList.add(0,e) = O(1) nhưng chậm hơn ArrayList? — Cấp phát đối tượng Node tốn kém hơn System.arraycopy() với các list nhỏ
- Khi nào iterator.remove() = O(1) thực sự hữu ích? — Khi xóa qua iterator trong các list RẤT lớn (100k+), nơi không thể dùng removeIf()
- Bẫy O(n²) là gì? — Vòng lặp for-i với get(i): mỗi get(i) = O(n), tổng cộng n×n = O(n²)
- Tại sao LinkedList tệ cho cache? — Các node nằm rải rác khắp heap, mỗi lần next = cache miss → chờ RAM

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "LinkedList nhanh hơn ArrayList khi chèn" — chỉ trên các list >10-20k, và không phải lúc nào cũng vậy
- ❌ "Dùng for-i cho LinkedList" — đó là O(n²), hãy dùng foreach/iterator
- ❌ "LinkedList tiết kiệm bộ nhớ" — ngược lại, 32 byte so với 4 byte cho mỗi phần tử
- ❌ "LinkedList — lựa chọn tốt cho queue" — ArrayDeque luôn tốt hơn

# What is the Difference Between persist() and merge() (Sự khác biệt giữa persist() và merge() là gì)

## Overview

`persist()` và `merge()` là hai phương thức EntityManager chính để quản lý vòng đời entity. Hiểu sự khác biệt giữa chúng rất quan trọng để dùng Hibernate đúng cách.

---

## Junior Level

### Sự Khác Biệt Chính

**`persist()`** - cho các entity **mới** (thực hiện INSERT).

**`merge()`** - để **cập nhật entity detached** (thực hiện UPDATE hoặc INSERT).

```java
// persist - cho entity mới
User newUser = new User();
newUser.setName("John");
entityManager.persist(newUser);  // INSERT
// newUser bây giờ là Persistent

// merge - cho entity detached
User detached = getDetachedUser();  // lấy được detached từ đâu đó
User managed = entityManager.merge(detached);  // UPDATE
// managed - bản sao managed mới
// detached vẫn là detached!
```

### Hành Vi

|                     | persist()          | merge()           |
| ------------------- | ------------------ | ------------------ |
| **Cho**             | Transient          | Detached          |
| **SQL**             | INSERT             | UPDATE hoặc INSERT  |
| **Trả về**          | void               | Entity managed    |
| **Object nguồn**    | Trở thành managed  | Vẫn là detached  |

### Ví Dụ persist()

```java
User user = new User();
user.setName("John");

entityManager.persist(user);
// user trở thành Persistent
// Có thể tiếp tục làm việc với user
user.setName("Jane");  // dirty checking sẽ kích hoạt
```

### Ví Dụ merge()

```java
User detached = getDetachedUser();
detached.setName("Changed");

User managed = entityManager.merge(detached);
// detached - vẫn là detached!
// managed - bản sao managed mới

detached.setName("NotSaved");    // sẽ KHÔNG ảnh hưởng đến DB
managed.setName("WillBeSaved");  // sẽ ảnh hưởng (dirty checking)
```

## Middle Level

### Khi Nào merge() Thực Sự Cần Thiết

merge() thường cần thiết trong các ứng dụng web: một object đến từ frontend (JSON -> DTO -> entity), nó là detached - merge sao chép trạng thái của nó vào context managed.

### persist() Chi Tiết

```java
User user = new User();
entityManager.persist(user);

// Điều gì xảy ra:
// 1. Kiểm tra entity chưa được managed
// 2. Sinh ID (nếu auto)
// 3. Thêm vào persistence context
// 4. Lên lịch INSERT khi flush
// 5. user trở thành Persistent

// Sau persist, có thể làm việc với nó
user.setName("Updated");  // dirty checking
```

### merge() Chi Tiết

```java
User detached = getDetachedUser();
User managed = entityManager.merge(detached);

// Điều gì xảy ra bên trong:
// 1. Kiểm tra xem entity có cùng ID có tồn tại trong persistence context không
// 2. Nếu không - tải từ DB (SELECT)
// 3. Sao chép trạng thái từ detached sang managed
// 4. Lên lịch UPDATE khi flush (nếu có thay đổi)
// 5. Trả về entity managed

// QUAN TRỌNG:
// detached vẫn là detached!
// Tất cả các thao tác tiếp theo - với managed!
```

### persist vs merge - Khi Nào Dùng Cái Gì

```
persist() - Transient -> Persistent, INSERT
merge()   - Detached -> Persistent, UPDATE hoặc INSERT
```

### Các Lỗi Thường Gặp

```java
// merge() cho entity mới - SELECT thừa
User newUser = new User();
entityManager.merge(newUser);
// Đầu tiên SELECT (kiểm tra tồn tại), sau đó INSERT

// persist() cho entity mới
entityManager.persist(newUser);  // INSERT ngay lập tức

// persist() cho entity detached có ID đã đặt - EntityExistsException. Nếu ID được sinh ở cấp độ DB, hành vi phụ thuộc vào chiến lược generation.
User detached = getDetachedUser();
entityManager.persist(detached);  // EntityExistsException

// merge() cho detached
entityManager.merge(detached);

// Bỏ qua giá trị trả về của merge()
entityManager.merge(detached);  // kết quả bị mất!
detached.setName("Changed");    // KHÔNG được lưu!

// Dùng giá trị trả về
User managed = entityManager.merge(detached);
managed.setName("Changed");  // sẽ được lưu
```

### Phương Thức save Chung

```java
public <T extends BaseEntity> T save(T entity) {
    if (entity.getId() == null) {
        entityManager.persist(entity);
        return entity;
    } else {
        return entityManager.merge(entity);
    }
}
```

## Senior Level

### Triển Khai Nội Bộ

```
persist():
1. kiểm tra xem entity đã managed chưa -> lỗi nếu có
2. kiểm tra trạng thái entity (không phải detached)
3. lên lịch INSERT (không thực thi ngay lập tức!)
4. thêm vào persistence context
5. entity trở thành managed

merge():
1. kiểm tra xem có entity cùng ID trong persistence context không
   -> có: dùng entity managed hiện có
   -> không: SELECT từ DB
2. nếu không có trong DB: tạo instance managed mới
3. sao chép trạng thái từ detached sang managed
4. lên lịch UPDATE nếu trạng thái thay đổi
5. trả về entity managed

Sự khác biệt chính:
- persist: entity gốc trở thành managed
- merge: trả về instance managed MỚI, bản gốc vẫn detached
```

### Hiệu Năng

```
persist():
- 0 truy vấn SELECT
- 1 INSERT khi flush

merge():
- 1 SELECT (kiểm tra tồn tại)
- 1 UPDATE hoặc INSERT khi flush
- + sao chép trạng thái

Với entity mới, persist() nhanh hơn 1 SELECT!
```

### Các Kịch Bản Nâng Cao

```java
// Kịch bản: cập nhật với kiểm tra version
@Version
private Integer version;

User detached = getDetachedUser();
User managed = entityManager.merge(detached);
// Khi flush: UPDATE WHERE id = ? AND version = ?
// Nếu version không khớp -> OptimisticLockException
```

### Best Practices

```
persist() cho entity mới
merge() cho entity detached
Kiểm tra ID trước khi chọn phương thức
Dùng giá trị trả về của merge()
Hiểu rằng merge trả về một bản sao
save() chung với kiểm tra ID

merge() cho entity mới (SELECT thừa)
persist() cho detached (lỗi)
Bỏ qua giá trị trả về của merge()
merge() cho persistent (SELECT thừa)
```

## Interview Cheat Sheet

**Cần phải biết:**
- persist() - cho entity mới (Transient -> Persistent), thực hiện INSERT
- merge() - cho entity detached, trả về một object managed MỚI, thực hiện UPDATE/INSERT
- persist() nhanh hơn 1 SELECT (không kiểm tra tồn tại)
- merge() thực hiện SELECT trước UPDATE/INSERT - kiểm tra xem entity có tồn tại trong DB không
- Bản gốc sau merge() vẫn là detached - tất cả thao tác với object được trả về
- save() chung: kiểm tra ID == null -> persist, ngược lại merge

**Các câu hỏi phụ thường gặp:**
- **Tại sao merge() thực hiện SELECT?** Để kiểm tra entity có tồn tại không và tải trạng thái hiện tại cho dirty checking
- **Điều gì nếu persist() được gọi cho detached?** EntityExistsException - Hibernate nghĩ entity đã được managed
- **Tại sao merge() trả về một object mới?** Bản gốc detached có thể từ một session khác, Hibernate tạo bản sao managed trong session hiện tại
- **Khi nào merge() thực hiện INSERT?** Khi entity với ID đó không tồn tại trong DB

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "merge() cho entity mới" - SELECT thừa
- "Tôi bỏ qua giá trị trả về của merge()" - các thay đổi sẽ không được lưu
- "persist() cho detached" - EntityExistsException
- "merge() cho persistent" - SELECT thừa, vô nghĩa

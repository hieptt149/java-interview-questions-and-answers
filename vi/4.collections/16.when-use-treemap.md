# When to use TreeMap? (Khi nào dùng TreeMap?)

## 🟢 Junior Level

**TreeMap** — một Map đã được sắp xếp, trong đó các key luôn theo thứ tự.

**Dùng TreeMap khi:**
- Bạn cần sắp xếp theo key
- Bạn cần các truy vấn khoảng (range query)
- Bạn cần key "gần nhất"

```java
TreeMap<Integer, String> map = new TreeMap<>();
map.put(10, "A");
map.put(50, "B");
map.put(30, "C");

// Được sắp xếp: {10=A, 30=C, 50=B}

// Key gần nhất
map.floorKey(25);   // → 10 (≤ 25 gần nhất)
map.ceilingKey(25); // → 30 (≥ 25 gần nhất)
```

## 🟡 Middle Level

### Khi nào cần TreeMap

**1. Các truy vấn khoảng (Range query):**
```java
TreeMap<Integer, String> taxBrackets = new TreeMap<>();
taxBrackets.put(0, "0%");
taxBrackets.put(10000, "10%");
taxBrackets.put(50000, "20%");

// Thuế suất cho thu nhập 35,000
String rate = taxBrackets.floorEntry(35000).getValue();
// → "10%"

// HashMap không làm được điều này!
```

**2. Các báo cáo đã sắp xếp:**
```java
TreeMap<LocalDate, Report> reports = new TreeMap<>();
// Luôn theo thứ tự thời gian
// subMap cho các khoảng ngày
```

**3. Tìm kiếm theo tiền tố (prefix):**
```java
TreeMap<String, Data> index = new TreeMap<>();
// Tất cả các key có tiền tố "user:"
SortedMap<String, Data> users = index.subMap("user:", "user{");
```

### Khi nào KHÔNG cần TreeMap

```java
// ❌ Chỉ cần một từ điển
Map<String, Integer> map = new TreeMap<>();  // O(log n) — cây, cần duy trì thứ tự
// ✅ HashMap
Map<String, Integer> map = new HashMap<>();  // O(1) — hash table, chèn/tìm kiếm nhanh

// ❌ Cần thứ tự chèn vào
Map<String, Integer> map = new TreeMap<>();  // Nó sắp xếp!
// ✅ LinkedHashMap
Map<String, Integer> map = new LinkedHashMap<>();  // Thứ tự chèn vào
```

## 🔴 Senior Level

### Hiệu năng

```
TreeMap: O(log n) cho mỗi thao tác
HashMap: O(1)

→ 1 triệu phần tử:
  HashMap: ~0.001 ms
  TreeMap: ~0.05 ms (chậm hơn 50 lần!)

Con số gần đúng cho 1 triệu key Integer trên một CPU hiện đại. Con số thực tế phụ thuộc vào JVM và kiểu key. Điểm chính — sự khác biệt về bậc độ lớn: O(1) so với O(log n).

→ Đừng dùng TreeMap làm kho lưu trữ chính
  nếu hiếm khi cần sắp xếp!
```

### Giải pháp thay thế: sắp xếp khi cần (on the fly)

```java
// ❌ TreeMap cho việc iterate đã sắp xếp hiếm khi cần
TreeMap<K, V> sortedMap = new TreeMap<>();
// O(log n) ở mỗi lần chèn

// ✅ HashMap + sắp xếp khi iterate
HashMap<K, V> map = new HashMap<>();
List<K> sortedKeys = new ArrayList<>(map.keySet());
Collections.sort(sortedKeys);
// O(n log n) một lần khi iterate
// O(1) khi chèn!
```

### View: subMap, headMap, tailMap

```java
NavigableMap<Integer, String> view = map.subMap(10, true, 50, true);
// → View "sống" (live), không phải một bản sao!
// → Tạo O(1)

view.put(30, "X");  // Thêm vào map GỐC
map.remove(30);     // Xóa khỏi view luôn!

view.put(100, "Y"); // → IllegalArgumentException!
// → 100 nằm ngoài khoảng [10, 50]
```

### ConcurrentSkipListMap

```java
// TreeMap KHÔNG thread-safe!
// Cho sorted map concurrent:
ConcurrentSkipListMap<K, V> map = new ConcurrentSkipListMap<>();
// → Skip List thay vì cây
// → O(log n), lock-free

// Skip List = cấu trúc xác suất với các "làn tốc hành" (express lane) để tìm kiếm nhanh hơn.
// Dễ cài đặt hơn và lock-free, nhưng dùng nhiều bộ nhớ hơn một cây.
```

### Các key null

```java
// TreeMap không chấp nhận null!
map.put(null, "value");  // → NullPointerException!

// Cách khắc phục (không khuyến nghị):
TreeMap<String, String> map = new TreeMap<>(
    Comparator.nullsFirst(Comparator.naturalOrder())
);
map.put(null, "value");  // OK, null đi đầu tiên
```

### Kinh nghiệm Production

**Tình huống thực tế: Dữ liệu chuỗi thời gian (Time-series)**
```java
// Các cảm biến: timestamp → phép đo
TreeMap<Long, SensorData> data = new TreeMap<>();

// Dữ liệu của giờ vừa qua
Map<Long, SensorData> lastHour = data.tailMap(
    System.currentTimeMillis() - 3600000
);

// Phép đo gần nhất với một thời điểm
Map.Entry<Long, SensorData> closest = data.floorEntry(targetTime);
```

### Best Practices

1. **TreeMap** chỉ cho sắp xếp/các khoảng
2. **HashMap** — theo mặc định
3. **Sắp xếp "khi cần"** nếu hiếm khi cần
4. **View = sống (live)**, không phải một bản sao
5. **ConcurrentSkipListMap** cho đa luồng
6. **null bị cấm** nếu không có Comparator tùy chỉnh
7. **Bộ nhớ** nhiều hơn HashMap 3-4 lần

### Tóm tắt cho Senior

- **TreeMap** = sắp xếp + điều hướng + các khoảng
- **O(log n)** so với **O(1)** của HashMap
- **floorKey/ceilingKey** = key gần nhất
- **subMap** = view khoảng dạng sống
- **Đừng dùng** nếu hiếm khi cần sắp xếp
- **ConcurrentSkipListMap** cho concurrency
- **null** bị cấm (nếu không có Comparator)
- **Bộ nhớ** > HashMap

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- TreeMap = O(log n), sắp xếp theo key + điều hướng (floorKey, ceilingKey, subMap) — KHÔNG dành cho các từ điển thông thường
- HashMap = O(1) — mặc định, TreeMap chậm hơn ~50 lần với 1 triệu phần tử
- Các truy vấn khoảng: subMap cho chuỗi thời gian, các bậc thuế, tìm kiếm theo tiền tố
- View (subMap, headMap, tailMap) = view sống, không phải một bản sao — tạo O(1)
- TreeMap KHÔNG thread-safe — cho concurrency hãy dùng ConcurrentSkipListMap (skip list, lock-free, O(log n))
- Các key null bị cấm (nếu không có Comparator tùy chỉnh nullsFirst/nullsLast)
- Bộ nhớ: nhiều hơn HashMap 3-4 lần do các node cây (left, right, parent, color)
- Giải pháp thay thế cho sắp xếp hiếm: HashMap + Collections.sort(keySet) — chèn O(1), sắp xếp O(n log n) khi cần

**Các câu hỏi phụ thường gặp:**
- **Khi nào TreeMap là lựa chọn duy nhất?** — Khi cần các truy vấn khoảng (subMap) hoặc key "gần nhất" (floorKey/ceilingKey). HashMap không làm được điều này.
- **Live view là gì và tại sao nó quan trọng?** — subMap trả về không phải một bản sao mà là một view. Thêm/xóa qua view ảnh hưởng đến map gốc. Bạn không thể thêm một phần tử nằm ngoài khoảng.
- **ConcurrentSkipListMap khác TreeMap như thế nào?** — Thread-safe, dùng skip list thay vì cây, các thao tác lock-free, nhưng dùng nhiều bộ nhớ hơn.
- **Tại sao không dùng TreeMap làm kho lưu trữ chính?** — O(log n) ở mỗi thao tác. Nếu hiếm khi cần sắp xếp — HashMap + sắp xếp khi iterate thì rẻ hơn.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "TreeMap nhanh hơn HashMap" — chậm hơn 50 lần! Chỉ dùng khi cần sắp xếp
- ❌ "TreeMap là thread-safe" — không, hãy dùng ConcurrentSkipListMap cho đa luồng
- ❌ "subMap sao chép dữ liệu" — nó là một view sống, các thay đổi phản ánh trong map gốc
- ❌ "TreeMap dành cho thứ tự chèn vào" — LinkedHashMap dành cho việc đó, TreeMap sắp xếp theo key

# What are the main Collection Framework interfaces? (Các interface chính của Collection Framework là gì?)

## Junior Level

**Collection Framework** là một tập hợp các interface và class trong Java để làm việc với các nhóm đối tượng.

**Các interface chính:**

| Interface | Nó làm gì                                    | Ví dụ                 |
| --------- | ------------------------------------------- | --------------------- |
| **List**  | Danh sách có thứ tự, cho phép trùng lặp     | ArrayList, LinkedList |
| **Set**   | Chỉ các phần tử duy nhất (unique)           | HashSet, TreeSet      |
| **Queue** | Hàng đợi (FIFO)                             | PriorityQueue, ArrayDeque |
| **Map**   | Các cặp key-value                           | HashMap, TreeMap      |

> Về mặt kỹ thuật, Map KHÔNG kế thừa từ Collection (nó là một interface song song), nhưng được đưa vào Collection Framework cho đầy đủ.

**Ví dụ minh họa đơn giản:**
- **List** = danh sách mua sắm (thứ tự quan trọng, cho phép lặp lại)
- **Set** = tập hợp các key duy nhất (thứ tự không quan trọng, không lặp lại)
- **Queue** = hàng người xếp hàng ở cửa hàng (đến trước, được phục vụ trước)
- **Map** = từ điển (từ -> định nghĩa)

**Ví dụ:**
```java
List<String> list = new ArrayList<>();
list.add("Apple");
list.add("Banana");
list.add("Apple");  // Cho phép trùng lặp

Set<String> set = new HashSet<>();
set.add("Apple");
set.add("Banana");
set.add("Apple");  // Sẽ không được thêm vào (đã tồn tại)

**Cách Set phát hiện phần tử trùng lặp:** `HashSet` gọi `hashCode()` để tìm "bucket" và `equals()` để kiểm tra sự trùng khớp bên trong bucket đó. Đó là lý do tại sao các phần tử phải cài đặt (implement) `hashCode()` và `equals()` một cách đúng đắn.

Map<String, Integer> map = new HashMap<>();
map.put("Apple", 1);
map.put("Banana", 2);
```

## Middle Level

### Phân cấp Interface

```
Iterable<E>
  └── Collection<E>
       ├── List<E>         ← Có thứ tự, cho phép trùng lặp
       │    ├── ArrayList
       │    └── LinkedList
       ├── Set<E>          ← Các phần tử duy nhất
       │    ├── HashSet
       │    ├── LinkedHashSet
       │    └── TreeSet (SortedSet)
       └── Queue<E>        ← Hàng đợi
            ├── PriorityQueue
            └── Deque
                 └── ArrayDeque

Map<K,V> (KHÔNG kế thừa từ Collection!)
  ├── HashMap
  ├── LinkedHashMap
  └── TreeMap (SortedMap)
```

### Các đặc điểm then chốt

**List:**
- Truy cập theo index: `list.get(0)`
- Giữ nguyên thứ tự chèn vào (insertion order)
- Cho phép trùng lặp

**Set:**
- Tính duy nhất thông qua `equals()` và `hashCode()`
- HashSet: không đảm bảo thứ tự
- LinkedHashSet: thứ tự chèn vào
- TreeSet: được sắp xếp

**Queue:**
- FIFO (First-In-First-Out)
- Các phương thức: `offer()`, `poll()`, `peek()`
- PriorityQueue: lấy ra theo độ ưu tiên (priority)

**Map:**
- Các cặp key-value
- Các key là duy nhất
- `get(key)`, `put(key, value)`

### Các Marker Interface

RandomAccess — một marker interface không có phương thức nào. Nó chỉ đơn giản cho JDK biết: "list này hỗ trợ truy cập ngẫu nhiên nhanh theo index", để JDK có thể chọn thuật toán tối ưu (ví dụ, khi sắp xếp).

```java
// RandomAccess — truy cập nhanh theo index
ArrayList implements RandomAccess   // get(i) = O(1)
LinkedList                          // get(i) = O(n), không có RandomAccess

// NavigableSet — điều hướng (navigation) qua các phần tử
TreeSet implements NavigableSet
  → lower(e), floor(e), ceiling(e), higher(e)
```

### Fail-Fast so với Fail-Safe

**Fail-Fast** = collection theo dõi các sửa đổi thông qua `modCount` (bộ đếm sửa đổi) và ném `ConcurrentModificationException` khi phát hiện thay đổi trong lúc iterate. Đây là một bộ phát hiện bug đơn luồng, không phải một cơ chế đồng bộ hóa.

**Fail-Safe** = iterator làm việc với một bản sao của dữ liệu (snapshot), nên các thay đổi trên bản gốc không ảnh hưởng đến việc iterate. Không bao giờ ném `ConcurrentModificationException`.

```java
// Fail-Fast (ArrayList, HashMap)
List<String> list = new ArrayList<>();
Iterator<String> it = list.iterator();
list.add("new");    // Sửa đổi
it.next();          // → ConcurrentModificationException!

// Fail-Safe (CopyOnWriteArrayList, ConcurrentHashMap)
List<String> safe = new CopyOnWriteArrayList<>();
Iterator<String> safeIt = safe.iterator();
safe.add("new");    // Sửa đổi
safeIt.next();      // → Hoạt động bình thường (iterator trên một bản sao)
```

## Senior Level

### Java 21: Sequenced Collections (JEP 431)

Hầu hết các hệ thống production chạy trên Java 11/17, nơi `SequencedCollection` không khả dụng. Hãy dùng các kiểu cụ thể (`ArrayList`, `LinkedList`) với các phương thức như `get(0)`/`get(size-1)`.

```java
// Interface mới cho các collection có thứ tự iterate dự đoán được
SequencedCollection<E>
  → addFirst(e), addLast(e)
  → getFirst(), getLast()
  → reversed()      // View theo thứ tự đảo ngược

// Các lớp kế thừa: List, Deque

SequencedSet<E>
  → Các cài đặt: LinkedHashSet, SortedSet

SequencedMap<K, V>
  → firstEntry(), lastEntry()
  → reversed()
  → Các cài đặt: LinkedHashMap, SortedMap
```

**Trước Java 21:** Không có interface chung cho "phần tử đầu tiên/cuối cùng"
**Sau Java 21:** Hợp đồng (contract) thống nhất cho tất cả các collection có thứ tự

### Spliterator (Java 8+)

```java
// Bản thay thế Iterator cho Stream API
Spliterator<E> spliterator = list.spliterator();

// Các đặc tính (characteristics):
// IMMUTABLE    → collection không thay đổi
// CONCURRENT   → có thể được sửa đổi đồng thời
// DISTINCT     → tất cả các phần tử là duy nhất
// SORTED       → các phần tử được sắp xếp
// ORDERED      → thứ tự quan trọng

// Stream API dùng các đặc tính này cho các tối ưu hóa khi xử lý song song
// (ví dụ, DISTINCT tránh các phép kiểm tra thừa, SORTED bỏ qua việc sắp xếp lại)
spliterator.trySplit()  // Tách ra để xử lý song song
```

### Bên trong: Tối ưu hóa RandomAccess

```java
// JDK kiểm tra RandomAccess để chọn thuật toán
Collections.binarySearch(list, key);

// Bên trong JDK:
if (list instanceof RandomAccess) {
    // Tìm kiếm nhị phân theo index → O(log n)
    for (int i = 0; i < size; i++) { ... }
} else {
    // Iterate → O(n log n) đối với LinkedList!
    ListIterator<E> it = list.listIterator();
}
```

### Map: Tại sao KHÔNG phải là một Collection?

```
Map làm việc với các CẶP (Key-Value)
Collection làm việc với các phần tử ĐƠN LẺ

Map.Entry<K,V> — interface bên trong cho một cặp
  → getKey(), getValue(), setValue()

Do đó Map là một nhánh song song, không phải một Collection!
```

### Các thao tác tùy chọn (Optional Operations)

```java
// Nhiều phương thức của Collection = "optional operation" (thao tác tùy chọn)
// Các collection không thể sửa đổi ném UnsupportedOperationException

list.add(e)      // Có thể ném!
list.remove(e)   // Có thể ném!
list.clear()     // Có thể ném!

// Tại sao? Để hỗ trợ các collection bất biến (immutable):
List<String> unmodifiable = Collections.unmodifiableList(list);
unmodifiable.add("x");  // → UnsupportedOperationException!
```

### Kinh nghiệm Production

**Tình huống thực tế: LinkedList giết chết hiệu năng**
- Ứng dụng: 1 triệu phần tử trong LinkedList
- Vấn đề: 10 giây để iterate, 500 MB bộ nhớ
- Giải pháp: thay thế bằng ArrayList
- Kết quả: 50 ms, 50 MB (nhanh hơn 200 lần!)

### Best Practices

1. **Interface trong chữ ký (signature)**: `List<String>`, không phải `ArrayList<String>`
2. **Collection** nếu chỉ cần iterate
3. **SequencedCollection (Java 21)** để truy cập phần tử đầu/cuối
4. **Kiểm tra RandomAccess** cho các vòng lặp `for-i`
5. **Các collection Fail-Safe** cho đa luồng
6. **Tránh** Vector, Stack, Hashtable (legacy)
7. **Spliterator** cho các parallel stream tùy chỉnh

### Tóm tắt cho Senior

- **JCF** = kiến trúc thống nhất cho các collection
- **SequencedCollection (Java 21)** = chuẩn mới cho các collection có thứ tự
- **RandomAccess** = marker để tối ưu hóa thuật toán
- **Spliterator** = nền tảng của parallel Stream API
- **Optional operations** = hỗ trợ cho các collection không thể sửa đổi
- **Map** != Collection (các cặp so với các phần tử đơn lẻ)
- **Fail-Fast** = sửa đổi -> exception
- **Legacy (Vector/Stack)** = tránh

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Collection Framework = Iterable -> Collection (List, Set, Queue) + Map (nhánh song song)
- Map KHÔNG kế thừa từ Collection — làm việc với các cặp Key-Value, không phải các phần tử đơn lẻ
- List = có thứ tự, cho phép trùng lặp; Set = các phần tử duy nhất; Queue = FIFO
- Fail-Fast = sửa đổi trong lúc iterate -> ConcurrentModificationException (thông qua modCount)
- Fail-Safe = iterator trên một bản sao (snapshot), không bao giờ ném exception
- RandomAccess — marker interface không có phương thức nào, báo hiệu truy cập nhanh theo index
- Java 21: SequencedCollection thống nhất việc truy cập đầu/cuối/đảo ngược cho List và Deque
- Spliterator — bản thay thế Iterator cho Stream API, chứa các đặc tính để tối ưu hóa song song

**Các câu hỏi phụ thường gặp:**
- Tại sao Map không phải là một phần của Collection? — Map làm việc với các cặp (K,V), Collection làm việc với các phần tử đơn lẻ
- Fail-Fast khác Fail-Safe như thế nào? — Fail-Fast ném exception khi có sửa đổi, Fail-Safe làm việc với một bản sao
- RandomAccess dùng để làm gì? — JDK dùng nó để chọn thuật toán (tìm kiếm nhị phân theo index so với iterate)
- Optional operations là gì? — Các phương thức như add()/remove() có thể ném UnsupportedOperationException đối với các collection không thể sửa đổi

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Map kế thừa từ Collection" — nó là một nhánh song song
- "Vector là một lựa chọn tốt cho đa luồng" — nó là legacy, hãy dùng CopyOnWriteArrayList hoặc ConcurrentHashMap
- "Fail-Fast đảm bảo thread-safety" — nó là một bộ phát hiện bug đơn luồng, không phải đồng bộ hóa
- "Spliterator giống với Iterator" — Spliterator hỗ trợ xử lý song song thông qua trySplit()

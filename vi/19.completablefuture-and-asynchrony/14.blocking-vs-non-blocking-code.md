# What Is Blocking Code and How to Distinguish It from Non-blocking? (Blocking code là gì và cách phân biệt nó với non-blocking)

## 🟢 Junior Level

**Blocking code** — code **dừng thread lại** và chờ một thao tác hoàn thành.

**Non-blocking code** — thread không chờ và tiếp tục thực hiện các tác vụ khác.

```java
// ❌ Blocking — thread chờ
String result = future.get();  // chờ tác vụ hoàn thành
Thread.sleep(1000);            // chờ 1 giây
InputStream.read();            // chờ dữ liệu

// ✅ Non-blocking — thread được tự do
CompletableFuture.supplyAsync(() -> {
    return "result";  // thực thi trong thread khác
}).thenAccept(result -> System.out.println(result));

// Thread chính tiếp tục làm việc
```

**Analogy đơn giản:**
- Blocking — đứng xếp hàng và chờ đợi
- Non-blocking — để lại một yêu cầu rồi đi, họ sẽ gọi lại cho bạn

## 🟡 Middle Level

### Các Thao Tác Chặn

**I/O chặn:**
```java
// ❌ Chặn
InputStream.read();           // chờ dữ liệu
OutputStream.write(data);     // chờ gửi
Socket.accept();              // chờ kết nối
Files.readAllBytes(path);     // chờ đọc

// ✅ Không chặn (NIO)
AsynchronousFileChannel.read(buffer, position, null, completionHandler);
AsynchronousSocketChannel.connect(remote);
```

**Network chặn:**
```java
// ❌ Lời gọi HTTP chặn
HttpResponse<String> response = HttpClient.newHttpClient()
    .send(request, BodyHandlers.ofString());  // chặn!

// ✅ Lời gọi HTTP không chặn
HttpClient.newHttpClient()
    .sendAsync(request, BodyHandlers.ofString())  // trả về CompletableFuture
    .thenAccept(response -> process(response));
```

**Database:**
```java
// ❌ Chặn
ResultSet rs = statement.executeQuery(sql);  // chặn

// ✅ Không chặn (R2DBC)
Mono<Result> result = client.sql(sql).fetch().one();
```

### Cách Phân Biệt

**Dấu hiệu của blocking code:**
1. Phương thức **không trả** quyền điều khiển ngay lập tức
2. Tên không có `Async` (nhưng đây không phải là đảm bảo). Một phương thức có thể được đặt tên doSomethingAsync
nhưng bên trong dùng get()/join(), khiến nó chặn. Ngược lại, một phương thức
không có Async có thể trả về một CompletableFuture và không chặn.
3. Dùng `get()`, `join()`, `await()`, `sleep()`
4. Làm việc với I/O đồng bộ

### Các Lỗi Thường Gặp

1. **CompletableFuture.get() trong ngữ cảnh bất đồng bộ:**
```java
CompletableFuture<String> cf = fetchDataAsync();

// ❌ Chặn!
String result = cf.get();

// ✅ Không chặn
cf.thenAccept(result -> process(result));
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Blocking vs Non-blocking ở tầng OS:**
```
I/O chặn:
- Thread chuyển sang trạng thái WAIT
- OS thực hiện context switch
- Thread không làm việc hữu ích nào

I/O không chặn:
- Thread tiếp tục làm việc
- Callback khi I/O hoàn thành
- Event loop hoặc epoll/select (Linux)
```

**Trạng thái thread:**
```java
// BLOCKED — chờ monitor
// WAITING — chờ notify/Completion
// TIMED_WAITING — sleep, wait(timeout)

// Trực quan hóa:
jcmd <pid> Thread.print
// hoặc
jstack <pid>
```

### Đánh Đổi Kiến Trúc

| Cách tiếp cận            | Ưu điểm                      | Nhược điểm              |
| ------------------- | ------------------------- | ----------------- |
| **Blocking**        | Code đơn giản               | Throughput thấp    |
| **Non-blocking**    | Throughput cao           | Code phức tạp hơn |
| **Virtual Threads** | Code đơn giản + throughput  | Chỉ Java 21+          |

### Edge Cases

**1. Blocking ẩn:**
```java
// CompletableFuture trông giống bất đồng bộ, nhưng có thể chặn
cf.thenApply(s -> {
    return httpClient.sendBlocking(url);  // chặn ForkJoinPool!
});

// thenApply không có Async thực thi trong cùng thread với giai đoạn trước.
// Nếu đây là ForkJoinPool.commonPool() — một thao tác chặn sẽ chặn một trong
// số ít thread của pool → thread pool starvation cho tất cả tác vụ commonPool.

// ForkJoinPool có ít thread — chặn phá hủy hiệu năng
```

**2. Thread pool starvation:**
```java
// ❌ Tất cả thread bị chặn — các tác vụ mới không được thực thi
ExecutorService executor = Executors.newFixedThreadPool(10);

for (int i = 0; i < 100; i++) {
    CompletableFuture.supplyAsync(() -> {
        Thread.sleep(10000);  // chặn 10 giây
        return "done";
    }, executor);
}
// 10 tác vụ đầu tiên chặn tất cả thread
// 90 tác vụ còn lại phải chờ
```

### Hiệu Năng

```
I/O chặn:
- 100 thread → 100 request đồng thời
- Overhead thread: ~1MB mỗi thread

I/O không chặn:
- 1 thread → 10000+ request đồng thời
- Overhead callback: ~5-10 ns

Virtual Threads:
- 100000+ thread → hàng triệu request đồng thời
- Overhead thread: ~vài trăm byte
// (Java 21, xấp xỉ, phụ thuộc vào workload)
```

### Kinh Nghiệm Production

**Xác định blocking code:**
```bash
# Thread dump
jstack <pid> > threads.txt

# Tìm BLOCKED, WAITING, TIMED_WAITING
# Nếu nhiều thread ở các trạng thái này — blocking code

```

### Best Practices

```java
// ✅ Phương thức Async cho I/O
httpClient.sendAsync(request, handler);

// ✅ Executor tùy chỉnh cho các thao tác chặn
CompletableFuture.supplyAsync(blockingTask, ioExecutor);

// ✅ Virtual Threads (Java 21+)
Executors.newVirtualThreadPerTaskExecutor();

// ❌ get()/join() không có lý do
// ❌ Thao tác chặn trong ForkJoinPool
// ❌ Bỏ qua thread pool starvation
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Blocking code dừng thread và chờ (get(), sleep(), đọc I/O)
- Non-blocking — thread được tự do, callback khi hoàn thành (CompletableFuture, NIO)
- Dấu hiệu của blocking: get/join/sleep/await, I/O đồng bộ, không có Async trong tên (nhưng không đảm bảo)
- Blocking ẩn: phương thức được gọi Async nhưng bên trong gọi một thao tác chặn, chặn ForkJoinPool
- Thread pool starvation: tất cả thread của pool bị chặn, các tác vụ mới phải chờ

**Các câu hỏi phụ thường gặp:**
- **Cách phân biệt blocking với non-blocking?** — blocking không trả quyền điều khiển ngay lập tức, non-blocking trả về Future/CF ngay lập tức
- **CompletableFuture.get() có chặn không?** — Có, thread chuyển sang WAITING
- **Blocking ẩn là gì?** — Một phương thức Async bên trong gọi một thao tác chặn, chặn ForkJoinPool
- **Virtual Threads có giải quyết vấn đề không?** — Có, chặn tạm dừng virtual thread, không phải OS thread (Java 21+)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "get() trong chuỗi CompletableFuture là thực hành bình thường" — đây là chặn, phá hủy tính bất đồng bộ
- "Một phương thức được gọi Async nghĩa là non-blocking" — có thể bên trong gọi get/join
- "Chặn trong ForkJoinPool không phải là vấn đề" — thread pool starvation cho tất cả tác vụ

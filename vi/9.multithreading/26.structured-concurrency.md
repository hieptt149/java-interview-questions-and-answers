# What is structured concurrency? (Structured concurrency là gì?)

Structured Concurrency là một mô hình lập trình nơi một nhóm các tác vụ liên quan, thực thi trong các thread khác nhau, được xử lý như một **đơn vị công việc duy nhất với các ranh giới rõ ràng**. Ý tưởng then chốt: nếu một tác vụ sinh ra các tác vụ con, nó **phải** chờ chúng hoàn thành. Đây là phiên bản tương đương với try-with-resources cho đa luồng.

**Tại sao điều này quan trọng:** trong đa luồng cổ điển, các thread sống "theo cách của chúng" — method cha có thể kết thúc trong khi các thread được sinh ra vẫn tiếp tục chạy (hoặc rò rỉ). Structured Concurrency đảm bảo: đến lúc bạn ra khỏi block, mọi tác vụ con đã kết thúc — hoặc thành công hoặc với một lỗi.

**Lưu ý quan trọng:** `StructuredTaskScope` có sẵn từ Java 21 như một **Preview API**. Điều này nghĩa là API có thể thay đổi trong các phiên bản tương lai. Để dùng cho production trên Java 17 — dùng `ExecutorService` + `CompletableFuture`.

## Junior Level

### Hiểu biết cơ bản

**Structured Concurrency** — một mô hình lập trình nơi một nhóm các tác vụ liên quan, thực thi trong các thread khác nhau, được xử lý như một đơn vị công việc duy nhất với các ranh giới rõ ràng.

**Tại sao cách tiếp cận cổ điển có vấn đề:** khi bạn tạo các thread qua `new Thread().start()`, chúng trở thành "trẻ mồ côi" — method cha không biết trạng thái của chúng, không thể hủy chúng khi có lỗi, và không đảm bảo chúng hoàn thành. Structured Concurrency giải quyết điều này qua nguyên lý: **"cha chờ con"**.

### Vấn đề với đa luồng cổ điển

```java
// Các thread "mồ côi" — fire and forget
public void process() {
    Thread t1 = new Thread(() -> fetchUserData());
    Thread t2 = new Thread(() -> fetchOrderHistory());
    t1.start();
    t2.start();
    // Nếu t1 ném exception thì sao? t2 sẽ tiếp tục chạy!
    // Nếu main method ném exception thì sao? Các thread sẽ còn lại!
}
```

### Giải pháp: StructuredTaskScope (Java 21+ Preview)

```java
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Subtask<User> user = scope.fork(() -> fetchUser(id));
    Subtask<Order> orders = scope.fork(() -> fetchOrders(id));

    scope.join();            // Chờ tất cả các tác vụ
    scope.throwIfFailed();   // Nếu một cái thất bại — các cái khác bị hủy

    // Cả hai kết quả có sẵn
    return new Response(user.get(), orders.get());
}
// Đến lúc ra khỏi try-with-resources, mọi thread đã kết thúc!
```

### Ví dụ minh họa

```
Thread cổ điển:                Structured Concurrency:
  Parent                        Parent
    │                              │
    ├→ Thread 1 (mồ côi)          ├→ Task 1 (con)
    ├→ Thread 2 (mồ côi)          ├→ Task 2 (con)
    └→ Kết thúc                   └→ Chờ các con
                                     │
                                  Mọi con xong → Parent kết thúc
```

## Middle Level

### Các Shutdown Policy

#### 1. ShutdownOnFailure

Nếu ít nhất một subtask thất bại — phần còn lại bị hủy:

```java
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Subtask<Data> data = scope.fork(() -> fetchData());
    Subtask<Config> config = scope.fork(() -> fetchConfig());

    scope.join();
    scope.throwIfFailed();

    // Nếu fetchData() ném exception — fetchConfig() tự động bị hủy
    process(data.get(), config.get());
}
```

**Khi nào:** Thực thi song song các bước trong một business process.

#### 2. ShutdownOnSuccess

Ngay khi tác vụ đầu tiên trả về một kết quả — phần còn lại bị hủy:

```java
try (var scope = new StructuredTaskScope.ShutdownOnSuccess<String>()) {
    scope.fork(() -> fetchFromServer1(url));
    scope.fork(() -> fetchFromServer2(url));
    scope.fork(() -> fetchFromServer3(url));

    scope.join();
    String fastestResult = scope.result(); // Kết quả của cái hoàn thành đầu tiên
    // Các request khác tự động bị hủy!
}
```

**Khi nào:** Các request tới các mirror (ai phản hồi nhanh nhất).

### So sánh với ExecutorService

| Đặc điểm               | ExecutorService                  | StructuredTaskScope               |
| ---------------------- | -------------------------------- | --------------------------------- |
| **Lifecycle**          | Không gắn với scope              | Nghiêm ngặt bên trong try-with-resources|
| **Xử lý lỗi**          | Thủ công (qua Future)            | Tự động (dựa trên Policy)          |
| **Hủy (Cancellation)** | Thủ công (`future.cancel()`)     | Tự động (theo tầng — cascading)    |
| **Context Propagation**| Phức tạp (cần các wrapper)       | Hỗ trợ Scoped Values              |
| **Rò rỉ thread**       | Có thể                          | Không thể                         |

### Lan truyền lỗi (Error Propagation)

```java
// ExecutorService — lỗi "chết âm thầm"
Future<?> future = executor.submit(() -> {
    throw new RuntimeException("Error!");
});
// Không ai biết cho tới khi bạn gọi future.get()

// StructuredTaskScope — lỗi nổi lên tới cha
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    scope.fork(() -> {
        throw new RuntimeException("Error!");
    });
    scope.join();
    scope.throwIfFailed(); // → ExecutionException tự động
}
```

## Senior Level

### Bên trong: StructuredTaskScope hoạt động như thế nào

```java
// Đơn giản hóa
public abstract class StructuredTaskScope<T> implements AutoCloseable {
    private final ThreadFactory factory;
    private final Set<Subtask<T>> subtasks = ConcurrentHashMap.newKeySet();
    private volatile boolean closed = false;

    public <U extends T> Subtask<U> fork(Callable<? extends U> task) {
        if (closed) throw new IllegalStateException("Scope closed");

        Thread thread = factory.newThread(() -> {
            try {
                U result = task.call();
                handleSuccess(result);
            } catch (Throwable t) {
                handleFailure(t);
            }
        });
        thread.start();
        // ...
    }

    @Override
    public void close() {
        // Đảm bảo: mọi subtask đã kết thúc vào thời điểm ra
        join();
    }
}
```

### An toàn Resource

Mô hình đảm bảo rằng đến lúc bạn ra khỏi `try`, mọi thread đều đã **kết thúc**:

```java
// KHÔNG THỂ:
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    scope.fork(() -> longRunningTask());
    return; // ← Trình biên dịch sẽ không cho phép! Scope phải được đóng
}
// Đến lúc ra khỏi } — mọi tác vụ đã kết thúc
```

### Tích hợp với Virtual Thread

```java
// StructuredTaskScope được thiết kế cho Virtual Thread
try (var scope = new StructuredTaskScope.ShutdownOnFailure>(
        Thread.ofVirtual().factory())) {
    // Tạo một triệu subtask — VT scale
    for (int i = 0; i < 1_000_000; i++) {
        scope.fork(() -> processItem(i));
    }
    scope.join();
}
// Tạo một scope mỗi request — một thao tác rẻ
```

### Tích hợp Scoped Values

```java
// Truyền context mà không có overhead của ThreadLocal
static final ScopedValue<UserContext> CONTEXT = new ScopedValue<>();

try (var scope = new StructuredTaskScope.ShutdownOnFailure>()) {
    ScopedValue.runWhere(CONTEXT, userContext, () -> {
        scope.fork(() -> {
            // CONTEXT.get() có sẵn trong mọi subtask
            return fetchUser(CONTEXT.get().userId());
        });
        scope.fork(() -> {
            return fetchOrders(CONTEXT.get().userId());
        });
    });
    scope.join();
}
```

### Khi nào dùng

| Kịch bản                              | StructuredTaskScope    | ExecutorService |
| ------------------------------------- | ---------------------- | --------------- |
| Business transaction (nhiều bước)     | Có                     | Không           |
| Các request tới mirror                | Có (ShutdownOnSuccess) | Không           |
| Service nền chạy dài                  | Không                  | Có              |
| Xử lý hàng đợi liên tục               | Không                  | Có              |
| Các tác vụ độc lập song song          | Có                     | Có              |

### Best Practices

1. **Dùng cho các business transaction** — khi vài bước phải hoàn thành cùng nhau
2. **ShutdownOnFailure** — khi mọi bước là bắt buộc
3. **ShutdownOnSuccess** — cho các request tới mirror
4. **Kết hợp với VT** — để scale
5. **Scoped Values** — để truyền context thay vì ThreadLocal
6. **try-with-resources** — đảm bảo mọi thread kết thúc
7. **JSON thread dump** — để debug phân cấp
8. **Không cho các service chạy dài** — dùng ExecutorService

## Khi nào KHÔNG dùng Structured Concurrency

- **Các service nền chạy dài** (daemon, bộ xử lý hàng đợi) — StructuredTaskScope yêu cầu mọi tác vụ kết thúc khi ra khỏi block. Cho các tác vụ "vĩnh cửu", dùng ExecutorService
- **Dưới Java 21** — API ở dạng preview, có thể thay đổi. Dùng CompletableFuture + ExecutorService
- **Các tác vụ song song độc lập không có transaction dùng chung** — nếu các tác vụ thực sự độc lập, đơn giản hơn khi dùng `executor.submit()` mà không có overhead của scope
- **Cần kiểm soát lifecycle đầy đủ** — nếu bạn cần hủy, tạm dừng, tiếp tục các tác vụ thủ công, ExecutorService linh hoạt hơn

## StructuredTaskScope vs ExecutorService vs CompletableFuture: Chọn gì?

| Tình huống                                              | Lựa chọn                              | Tại sao                                        |
| ------------------------------------------------------ | ------------------------------------- | ---------------------------------------------- |
| Business transaction (fetchUser + fetchOrders cùng nhau)| StructuredTaskScope                   | Tự hủy khi có lỗi, đảm bảo hoàn thành          |
| Các request tới mirror (ai nhanh hơn)                 | StructuredTaskScope.ShutdownOnSuccess | Tự hủy các cái chậm                            |
| Xử lý hàng đợi nền                                     | ExecutorService                       | Vòng lặp vô hạn, scope không phù hợp           |
| Các chuỗi callback (thenApply, thenCompose)           | CompletableFuture                     | Async pipeline, không block                    |
| Các tác vụ song song độc lập                           | Bất kỳ                                | Nhưng StructuredTaskScope đơn giản hơn để debug|

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Structured Concurrency: nhóm các tác vụ = một đơn vị duy nhất; cha chờ mọi tác vụ con hoàn thành
- Phiên bản tương đương với try-with-resources cho đa luồng: đến lúc ra khỏi block, mọi thread được đảm bảo đã kết thúc
- ShutdownOnFailure: một cái thất bại — các cái khác bị hủy (các business transaction)
- ShutdownOnSuccess: cái đầu tiên hoàn thành — các cái khác bị hủy (các request tới mirror)
- `StructuredTaskScope` — Preview API trong Java 21, có thể thay đổi
- Tích hợp với Virtual Thread và Scoped Values để scale và truyền context
- Khác biệt so với ExecutorService: không rò rỉ thread, tự động hủy, thread dump có phân cấp

**Các câu hỏi phụ thường gặp:**
- **Tại sao cái này tốt hơn ExecutorService + CompletableFuture?** — ExecutorService: các thread mồ côi, hủy thủ công, có thể rò rỉ. SC: quản lý lifecycle tự động, hủy theo tầng, không thể rò rỉ
- **SC hoạt động với Virtual Thread như thế nào?** — SC được tạo với `Thread.ofVirtual().factory()` — mọi tác vụ fork chạy trên VT, scale tới hàng triệu
- **Khi nào KHÔNG dùng SC?** — Cho các service nền chạy dài (daemon, bộ xử lý hàng đợi) — SC yêu cầu hoàn thành khi ra khỏi block
- **Làm sao debug SC?** — JSON thread dump (`jcmd Thread.dump_to_file -format=json`) hiển thị phân cấp cha-con

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Structured Concurrency là một API ổn định trong Java 21" — `StructuredTaskScope` vẫn ở dạng Preview
- "SC thay thế ExecutorService hoàn toàn" — SC cho các business transaction, ExecutorService cho các service chạy dài
- "SC tự động xử lý mọi exception" — bạn cần gọi `throwIfFailed()` sau `join()`
- "Có thể trả về một kết quả từ một block SC trước khi nó hoàn thành" — block SC phải được đóng (try-with-resources), mọi tác vụ phải kết thúc trước khi ra

# Which exceptions must be handled? (Những exception nào bắt buộc phải xử lý?)

## Junior Level

### Checked exception - bắt buộc xử lý

Trình biên dịch (compiler) Java **ép buộc** bạn phải xử lý các checked exception. Đây là tất cả các lớp con của `Exception`, trừ `RuntimeException`.

Checked exception là một hợp đồng giữa một phương thức và bên gọi nó. Phương thức nói: "Tôi có thể gặp phải X, và bạn phải chuẩn bị sẵn sàng cho nó."

```java
// Bắt buộc: hoặc try-catch hoặc throws
public void readFile() throws IOException {
    Files.readAllLines(Paths.get("file.txt"));
}

// Hoặc xử lý ngay tại chỗ
public void safeRead() {
    try {
        Files.readAllLines(Paths.get("file.txt"));
    } catch (IOException e) {
        log.error("Failed to read file", e);
    }
}
```

### Các exception thường gặp cần xử lý

- `IOException` - thao tác file và mạng
- `SQLException` - thao tác database
- `ClassNotFoundException` - nạp class
- `InterruptedException` - đa luồng

### Unchecked exception - xử lý tùy chọn

`NullPointerException`, `IllegalArgumentException` và các `RuntimeException` khác không cần phải xử lý. Chúng báo hiệu lỗi trong code.

### Nguyên tắc cơ bản

- **Checked** - lỗi bên ngoài (file, mạng, DB) -> **phải xử lý**
- **Unchecked** - lỗi lập trình -> **phải sửa code**

## Middle Level

### Bắt buộc so với khuyến nghị xử lý

| Loại      | Nghĩa vụ                                | Ai yêu cầu                 |
| --------- | -------------------------------------- | -------------------------- |
| Checked   | **Phải** xử lý hoặc khai báo throws    | Compiler                   |
| Unchecked | **Khuyến nghị** xử lý                  | Kiến trúc/đội              |
| Error     | **Không nên** bắt                      | JVM (không thể phục hồi)   |

### Kiểm tra ở mức compiler

Ở mức JVM, **không có** sự phân tách giữa checked và unchecked. Lệnh `athrow` chỉ đơn giản là ném một object. Việc bắt buộc xử lý chỉ là một kiểm tra của `javac`.

### Thuộc tính Exceptions trong class file

Khi bạn khai báo `void method() throws IOException`, một thuộc tính `Exceptions` xuất hiện trong file `.class`. Compiler dùng nó để kiểm tra. Các ngôn ngữ khác (Kotlin, Groovy) bỏ qua thuộc tính này.

### Sneaky Throws - qua mặt kiểm tra

Bạn có thể ném một checked exception mà không cần `throws`:

```java
@SuppressWarnings("unchecked")
public static <E extends Throwable> void sneakyThrow(Throwable e) throws E {
    throw (E) e; // Type erasure đánh lừa compiler
}

// Lombok làm điều này tự động
@SneakyThrows
public void readFile() {
    // IOException không cần throws!
    Files.readAllLines(Paths.get("file.txt"));
}
```

### Exception Translation

Cách tiếp cận đúng - bắt các checked exception ở biên của tầng và chuyển dịch thành domain unchecked:

```java
public interface Storage {
    byte[] read(String path); // Không phụ thuộc vào SQL
}

public class SqlStorage implements Storage {
    public byte[] read(String path) {
        try {
            return jdbcTemplate.queryForObject(...);
        } catch (SQLException e) {
            throw new StorageException("Failed to read: " + path, e);
        }
    }
}
```

## Senior Level

### Lập trình hàm và checked exception

Các interface tiêu chuẩn (`Function`, `Predicate`, `Supplier`) không hỗ trợ checked exception:

```java
// Sẽ không biên dịch được
stream.map(path -> Files.readString(path))

// Giải pháp 1 - wrapper
stream.map(path -> {
    try { return Files.readString(path); }
    catch (IOException e) { throw new UncheckedIOException(e); }
})

// Giải pháp 2 - Sneaky Throws
stream.map(path -> sneakyRead(path))
```

### Hiệu suất

**Đừng bao giờ** dùng checked exception cho control flow. Ném một exception - tạo một object + duyệt stack - chậm hơn 100-1000 lần so với trả về `Optional`.

### Validation dữ liệu đầu vào

Với dữ liệu không hợp lệ, luôn dùng các exception **unchecked** (`IllegalArgumentException`). Đây là lỗi của lập trình viên, không phải vấn đề của thế giới bên ngoài.

> InterruptedException là exception xác nhận quy tắc. Đây không phải "control flow" theo nghĩa thông thường, mà là một cơ chế hủy thread có hợp tác (cooperative). Việc xử lý nó là một phần của hợp đồng đa luồng.

### UncaughtExceptionHandler

Nếu một checked exception "rò rỉ" qua sneaky throws và không được bắt, nó sẽ tới handler của thread. Hãy đặt một handler toàn cục:

```java
Thread.setDefaultUncaughtExceptionHandler((thread, e) -> {
    log.error("Uncaught exception in thread {}", thread.getName(), e);
});
```

### Khối Catch rỗng - tội ác tồi tệ nhất

```java
catch (IOException e) {} // Tội ác!
```

Nếu bạn phải xử lý nhưng không biết cách - ít nhất hãy ghi log:
```java
catch (IOException e) {
    log.error("IO error occurred", e);
    throw new RuntimeException(e);
}
```

### Chẩn đoán

- **Static Analysis** - SonarQube chặn các khối catch rỗng
- **Micrometer** - theo dõi số lượng exception qua metric
- **Log Correlation** - giữ Trace ID cho mọi loại lỗi

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Checked exception - phải xử lý hoặc khai báo `throws` (compiler yêu cầu)
- Unchecked - khuyến nghị xử lý ở mức kiến trúc (không phải compiler)
- Error - KHÔNG nên bị bắt (JVM ở trạng thái không ổn định)
- Ở mức JVM không có sự phân tách - lệnh `athrow` ném mọi thứ theo cùng một cách
- Sneaky throws - qua mặt kiểm tra của compiler qua type erasure
- Exception translation - bắt checked ở biên của tầng -> chuyển dịch thành domain unchecked
- Với dữ liệu đầu vào không hợp lệ luôn dùng unchecked (`IllegalArgumentException`)
- Khối catch rỗng - tội ác tồi tệ nhất: tối thiểu hãy ghi log

**Các câu hỏi phụ thường gặp:**
- **JVM xử lý checked so với unchecked như thế nào?** - Giống nhau; sự phân tách chỉ ở trong `javac`
- **Sneaky throws là gì?** - Qua mặt kiểm tra qua `@SneakyThrows` (Lombok) hoặc xóa generic
- **Tại sao InterruptedException đặc biệt?** - Nó là một cơ chế hủy thread có hợp tác, cần khôi phục trạng thái interrupt
- **Làm gì nếu bạn không biết cách xử lý?** - Ghi log và rethrow thành `RuntimeException`

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi để các khối catch rỗng nếu tôi không biết phải làm gì" - ít nhất hãy ghi log
- "Tôi bắt Error để ứng dụng không sập" - JVM không ổn định, việc đó vô nghĩa
- "Checked exception giống hệt unchecked" - không, compiler chỉ kiểm tra checked

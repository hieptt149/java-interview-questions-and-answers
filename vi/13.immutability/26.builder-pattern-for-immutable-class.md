# How to implement Builder pattern for an immutable class? (Cách triển khai Builder pattern cho một immutable class?)

---

## Basic Level

**Builder** là một pattern giúp tạo các object có nhiều trường, đặc biệt khi có các trường tùy chọn.

### Vấn Đề: Quá Nhiều Constructor
```java
// "Telescoping constructors" — tồi
new User("Ivan");
new User("Ivan", 25);
new User("Ivan", 25, "ivan@mail.com");
new User("Ivan", 25, "ivan@mail.com", "admin");
```

### Giải Pháp: Builder
```java
User user = new User.Builder("Ivan")
    .age(25)
    .email("ivan@mail.com")
    .role("admin")
    .build();
```

### Khi Builder Là Dư Thừa

Builder hợp lý cho 4+ trường. Với 1-2 trường hãy dùng constructor —
Builder thêm một class thừa và làm phức tạp code.

## Intermediate Level

### Cài Đặt Cổ Điển

```java
public final class UserProfile {
    private final String username;  // bắt buộc
    private final String email;     // tùy chọn
    private final int age;          // tùy chọn

    private UserProfile(Builder builder) {
        this.username = builder.username;
        this.email = builder.email;
        this.age = builder.age;
    }

    public String getUsername() { return username; }
    public String getEmail() { return email; }
    public int getAge() { return age; }

    public static class Builder {
        private final String username;
        private String email;
        private int age;

        public Builder(String username) {
            this.username = username; // trường bắt buộc
        }

        public Builder email(String email) {
            this.email = email;
            return this;
        }

        public Builder age(int age) {
            this.age = age;
            return this;
        }

        public UserProfile build() {
            return new UserProfile(this);
        }
    }
}
```

### Lombok (@Builder)
```java
@Value      // final class, private final fields, equals/hashCode/toString
@Builder    // @Builder sinh ra một static Builder class với các method cho từng trường.
public class UserProfile {
    String username;
    String email;
    int age;
}
```

### toBuilder() — Để "Sửa Đổi" Một Immutable Object
```java
UserProfile updated = user.toBuilder().age(30).build();
```

## Advanced Level

### Validate Trong build()

Method `build()` là nơi lý tưởng để validate xuyên các trường:
```java
public UserProfile build() {
    if (email != null && !email.contains("@")) {
        throw new IllegalArgumentException("Invalid email");
    }
    return new UserProfile(this);
}
```

### Lombok @Singular Cho Collection
```java
@Value @Builder
public class Order {
    String id;
    @Singular List<String> items; // tự động sao chép defensive
}
```
`@Singular` tự động gọi `List.copyOf()` trong `build()`.

### Tại Sao Điều Này Quan Trọng Với Senior

1. **Validate** — object không được công bố cho đến khi được lắp ráp và validate hoàn chỉnh
2. **Tính nguyên tử (Atomicity)** — object hoặc tồn tại trong trạng thái hoàn chỉnh hoặc không tồn tại chút nào
3. **Thiết kế API** — builder tự mô tả, việc thêm một trường không phá vỡ các lời gọi hiện có
4. **Hợp đồng bất biến** — builder là nơi mutable duy nhất, class chính hoàn toàn bất biến

### Tóm Tắt Cho Advanced
- Builder cho các object có 4+ trường
- Kết hợp Builder với các trường `final` của class chính
- Lombok `@Builder` + `@Singular` — boilerplate tối thiểu với sao chép defensive
- Luôn thêm `toBuilder()` để sửa đổi tiện lợi
- `build()` — nơi validate cuối cùng

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Builder giải quyết "telescoping constructors" — tên tham số tiện lợi qua fluent API
- Cài đặt cổ điển: static inner Builder class với chaining, `build()` tạo immutable object
- Constructor private của immutable class nhận Builder — nơi mutable duy nhất
- Lombok `@Builder` + `@Value` — boilerplate tối thiểu; `@Singular` tự động gọi `List.copyOf()`
- `toBuilder()` — để "sửa đổi" immutable object một cách tiện lợi
- `build()` — nơi validate xuyên các trường

**Các câu hỏi phụ thường gặp:**
- *Khi nào Builder hợp lý?* — 4+ trường, đặc biệt với các trường tùy chọn
- *@Singular làm gì?* — Tự động sao chép defensive các collection (`List.copyOf()`)
- *Builder vs Record?* — Record cho các DTO đơn giản; Builder cho các object phức tạp có validate
- *Tại sao constructor private?* — Để object chỉ được tạo thông qua Builder với validate

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Builder làm cho class mutable" — Builder là mutable, class chính là final với các trường final
- "Validate trong constructor của Record tốt hơn" — Builder cho phép validate TRƯỚC khi tạo object
- "@Builder không có @Singular là an toàn" — không có @Singular, các collection không được sao chép
- "Builder luôn cần thiết" — với 1-2 trường một constructor đơn giản hơn

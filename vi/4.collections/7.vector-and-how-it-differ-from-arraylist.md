# What is Vector and how does it differ from ArrayList? (Vector là gì và nó khác ArrayList như thế nào?)

## 🟢 Junior Level

**Vector** — phiên bản legacy của ArrayList, đã có trong Java từ những ngày đầu.

**Sự khác biệt then chốt:**

|                    | Vector                                                                       | ArrayList        |
| ------------------ | ---------------------------------------------------------------------------- | ---------------- |
| **Đồng bộ hóa**    | ✅ Tất cả các phương thức đều synchronized                                     | ❌ Không          |
| **Tốc độ**         | Chậm hơn                                                                     | Nhanh hơn        |
| **Resize**         | × 2                                                                          | × 1.5            |
| **Khi nào dùng**   | Chỉ trong code legacy, code mới — ArrayList hoặc CopyOnWriteArrayList          |                  |

**Ví dụ:**
```java
// ❌ Đừng dùng Vector
Vector<String> v = new Vector<>();  // Chậm!

// ✅ Hãy dùng ArrayList
List<String> list = new ArrayList<>();
```

**Tại sao Vector chậm:**
- Mọi phương thức = `synchronized`
- Ngay cả khi làm việc trong một luồng duy nhất!

## 🟡 Middle Level

### Các khác biệt kỹ thuật

```java
// Vector:
public synchronized boolean add(E e) {  // ← synchronized!
    modCount++;
    ensureCapacityHelper(elementCount + 1);
    elementData[elementCount++] = e;
    return true;
}

// ArrayList:
public boolean add(E e) {  // ← Không có synchronized!
    modCount++;
    add(e, elementData, size);
    return true;
}
```

### Resize

```
Vector: capacity × 2
  10 → 20 → 40 → 80
  → Tăng nhanh, lãng phí bộ nhớ nhiều hơn

ArrayList: capacity × 1.5
  10 → 15 → 22 → 33
  → Tiết kiệm hơn, ít phân mảnh hơn
```

### Tại sao đồng bộ hóa của Vector KHÔNG giúp ích

```java
// ❌ Vector KHÔNG thread-safe cho các thao tác kép (compound)!
if (!vector.contains(obj)) {  // Kiểm tra
    vector.add(obj);           // ← Luồng khác có thể chen vào!
}

Điều này được gọi là race condition **"check-then-act"**: kiểm tra (`contains`) và hành động (`add`) — hai thao tác riêng biệt nơi một luồng khác có thể xen vào.

// Vẫn cần synchronized bên ngoài:
synchronized (vector) {
    if (!vector.contains(obj)) {
        vector.add(obj);
    }
}
```

### Các giải pháp thay thế

```java
// Không đồng bộ hóa:
ArrayList<String> list = new ArrayList<>();

// Có đồng bộ hóa (nhiều lần đọc):
List<String> list = new CopyOnWriteArrayList<>();

// Có đồng bộ hóa (phổ quát):
List<String> list = Collections.synchronizedList(new ArrayList<>());

// Cho các queue:
ConcurrentLinkedQueue<String> queue = new ConcurrentLinkedQueue<>();
```

**Cách chọn:**
- Một luồng → ArrayList
- Đa luồng, nhiều lần đọc → CopyOnWriteArrayList
- Đa luồng, tải hỗn hợp → Collections.synchronizedList
- Đa luồng, queue → ConcurrentLinkedQueue

## 🔴 Senior Level

### Lock Contention (tranh chấp khóa)

```
100 luồng gọi vector.get(0):
  → Tất cả chờ một monitor duy nhất
  → Tuần tự hóa (serialization) → 0 song song!

ArrayList:
  → 100 luồng đọc đồng thời
  → Đọc lock-free
```

### JIT Lock Coarsening

Lock Coarsening — tối ưu hóa của JVM gộp nhiều khối synchronized tuần tự thành một để giảm overhead của việc khóa.

```
JVM cố gắng tối ưu:
  vector.get(0);
  vector.get(1);
  vector.get(2);

→ Lock Coarsening: một khóa cho cả ba
→ Nhưng điều này che giấu vấn đề, không giải quyết nó!
```

### Vi phạm LSP: Stack extends Vector

LSP (Liskov Substitution Principle) — nguyên tắc OOP: lớp con phải có thể thay thế được cho lớp cơ sở mà không phá vỡ tính đúng đắn. Stack vi phạm điều này bằng cách thêm các phương thức không tương thích với ngữ nghĩa của stack.

```java
// Stack extends Vector!
Stack<String> stack = new Stack<>();
stack.push("A");
stack.add(0, "B");  // ← Phá vỡ ngữ nghĩa của stack!

// → Stack có thể làm mọi thứ Vector có thể làm
// → Vi phạm Liskov Substitution Principle
```

### Enumeration so với Iterator

```java
// Vector có Enumeration (legacy)
Enumeration<String> e = vector.elements();
while (e.hasMoreElements()) {
    e.nextElement();  // Không phải fail-fast!
}

// Iterator (hiện đại)
Iterator<String> it = vector.iterator();
// → Fail-fast, giống ArrayList
```

### Kinh nghiệm Production

**Trường hợp thực tế: Vector giết chết throughput**
- Ứng dụng: 1000 RPS, Vector cho logs
- Lock contention: 80% thời gian dành cho synchronized
- Giải pháp: ArrayList
- Kết quả: +400% throughput

### Best Practices

1. **KHÔNG dùng** Vector — nó là legacy
2. **ArrayList** — theo mặc định
3. **CopyOnWriteArrayList** — cho thread-safe
4. **Collections.synchronizedList** — phổ quát
5. **ConcurrentLinkedQueue** — cho các queue
6. **Stack → ArrayDeque** — cho các stack
7. **Enumeration → Iterator** — hiện đại

### Tóm tắt cho Senior

- **Vector** = legacy, synchronized, chậm
- **ArrayList** = nhanh hơn, không đồng bộ hóa
- **Đồng bộ hóa của Vector** không đem lại thread-safety thực sự
- **Lock Contention** giết chết tính song song
- **Resize × 2** → phân mảnh nhiều hơn
- **Stack extends Vector** = vi phạm LSP
- **CopyOnWriteArrayList** = giải pháp thay thế thread-safe đúng đắn
- **KHÔNG BAO GIỜ** dùng Vector trong code mới

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Vector = legacy, tất cả các phương thức đều synchronized → chậm ngay cả trong một luồng duy nhất
- Resize: Vector × 2 (phân mảnh nhiều hơn) so với ArrayList × 1.5 (tiết kiệm hơn)
- Đồng bộ hóa của Vector KHÔNG đem lại thread-safety thực sự cho các thao tác kép (race condition "check-then-act")
- Lock Contention: 100 luồng gọi vector.get() → tuần tự hóa → 0 song song
- Stack extends Vector = vi phạm LSP — có thể gọi get(index), phá vỡ ngữ nghĩa LIFO
- Enumeration (Vector) là legacy → hãy dùng Iterator (fail-fast)
- Các giải pháp thay thế: ArrayList (một luồng), CopyOnWriteArrayList (nhiều lần đọc), Collections.synchronizedList (phổ quát)
- Trường hợp thực tế: thay Vector → ArrayList cho +400% throughput

**Các câu hỏi phụ thường gặp:**
- Tại sao synchronized trong Vector không đảm bảo thread-safety? — Các thao tác kép (check-then-act) vẫn cần synchronized bên ngoài
- Vi phạm LSP trong ngữ cảnh Stack là gì? — Stack extends Vector, có thể gọi add(0,e) — phá vỡ LIFO
- Khi nào JIT Lock Coarsening che giấu vấn đề? — Gộp các khối synchronized tuần tự, nhưng không giải quyết lock contention
- CopyOnWriteArrayList tốt hơn Vector như thế nào? — Copy khi ghi, đọc lock-free, tốt hơn cho các kịch bản "nhiều đọc, ít ghi"

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Vector — bản thay thế thread-safe cho ArrayList" — synchronized không đem lại thread-safety thực sự cho các thao tác kép
- ❌ "Vector × 2 resize tốt hơn ArrayList × 1.5" — ngược lại, phân mảnh nhiều hơn và lãng phí bộ nhớ
- ❌ "Hãy dùng Stack như một stack" — Stack extends Vector, hãy dùng ArrayDeque
- ❌ "Enumeration tốt hơn Iterator" — Enumeration là legacy, không phải fail-fast

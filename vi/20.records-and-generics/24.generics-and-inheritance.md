# How Do Generics Work with Inheritance? (Generics hoạt động như thế nào với kế thừa)

## 🟢 Junior Level

**Generics KHÔNG được kế thừa theo cách giống như các class thông thường!**

Mặc dù `String` kế thừa từ `Object`, `List<String>` **KHÔNG kế thừa** từ `List<Object>`.

```java
String extends Object;               // ✅ String là một lớp con của Object
List<String> extends List<Object>;   // ❌ SAI!

// Ví dụ:
List<String> strings = new ArrayList<>();
List<Object> objects = strings;  // ❌ lỗi biên dịch!
```

**Tại sao:** Nếu điều này được phép, bạn có thể thêm một `Integer` vào `List<String>` thông qua tham chiếu `List<Object>` — điều này sẽ phá vỡ tính an toàn kiểu.

```java
// Nếu điều này được phép:
List<String> strings = new ArrayList<>();
List<Object> objects = strings;  // giả sử OK
objects.add(42);  // đã thêm Integer vào List<String>!
String s = strings.get(0);  // ClassCastException!
```

## 🟡 Middle Level

### Tính Bất Biến Của Generics

Generics là **bất biến (invariant)** — `List<A>` và `List<B>` không liên quan, ngay cả khi `A extends B`.

```java
class Animal { }
class Dog extends Animal { }
class Cat extends Animal { }

List<Dog> dogs = new ArrayList<>();
List<Animal> animals = dogs;  // ❌ lỗi biên dịch!
```

### Cách Đạt Được Tính Linh Hoạt

**1. Wildcard — `? extends`:**
```java
List<Dog> dogs = new ArrayList<>();
List<? extends Animal> animals = dogs;  // ✅ OK

// Có thể đọc dưới dạng Animal
Animal a = animals.get(0);

// Không thể ghi
animals.add(new Cat());  // ❌ lỗi biên dịch
```

**2. Wildcard — `? super`:**
```java
List<Animal> animals = new ArrayList<>();
List<? super Dog> dogs = animals;  // ✅ OK

// Có thể ghi Dog
dogs.add(new Dog());

// Chỉ có thể đọc Object
Object obj = dogs.get(0);
```

### Class Generic Với Kế Thừa

```java
public class Box<T> {
    private T value;
    public void set(T value) { this.value = value; }
    public T get() { return value; }
}

// Box<Dog> KHÔNG kế thừa từ Box<Animal>
Box<Dog> dogBox = new Box<>();
Box<Animal> animalBox = dogBox;  // ❌ lỗi

// Nhưng bạn có thể dùng wildcard
Box<? extends Animal> animalBox2 = dogBox;  // ✅
```

### Các Lỗi Thường Gặp

1. **Mong đợi tính covariant:**
```java
List<Integer> ints = new ArrayList<>();
List<Number> numbers = ints;  // ❌ lỗi

// ✅ Đúng
List<? extends Number> numbers = ints;
```

2. **Phương thức generic không có wildcard:**
```java
public void processAnimals(List<Animal> animals) {
    // chỉ chấp nhận List<Animal>
}

List<Dog> dogs = new ArrayList<>();
processAnimals(dogs);  // ❌ lỗi

// ✅ Đúng
public void processAnimals(List<? extends Animal> animals) { }
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Type erasure và kế thừa:**
```java
class Parent<T> {
    private T value;
    public T get() { return value; }
}

class Child extends Parent<String> {
    @Override
    public String get() { return super.get(); }
}

// Sau erasure:
class Parent {
    private Object value;
    public Object get() { return value; }
}

class Child extends Parent {
    public String get() { return (String) super.get(); }

    // Bridge method để giữ tính đa hình:
    public Object get() { return get(); }
}
```

### Đánh Đổi Kiến Trúc

| Thuộc tính          | Mảng                | Generics              |
| ----------------- | --------------------- | --------------------- |
| **Covariance**    | ✅ Covariant           | ❌ Bất biến (Invariant)          |
| **Kiểm tra runtime** | ✅ ArrayStoreException | ❌ Chỉ compile-time   |
| **An toàn kiểu**   | Runtime               | Compile-time          |
| **Tính linh hoạt**   | Cao (nguy hiểm)      | Thấp (an toàn)            |

### Edge Cases

**1. Generics lồng nhau:**
```java
Map<String, List<Dog>> dogMap = new HashMap<>();
Map<String, List<Animal>> animalMap = dogMap;  // ❌ lỗi

// ✅ Với wildcard
Map<String, ? extends List<? extends Animal>> animalMap = dogMap;
```

**2. Subclass generic:**
```java
public class AnimalBox<T extends Animal> extends Box<T> {
    public void addAnimal(T animal) {
        set(animal);
    }
}

// AnimalBox<Dog> KHÔNG kế thừa AnimalBox<Animal>
// Nhưng AnimalBox<Dog> kế thừa Box<Dog>
```

**3. Kiểu trả về covariant:**
```java
// List<Dog> KHÔNG PHẢI là subtype của List<Animal> — generics là bất biến!
// Code này KHÔNG BIÊN DỊCH được.

// Kiểu trả về covariant đúng — với kiểu cụ thể (không phải generic):
class Parent {
    public Animal getAnimal() { return new Animal(); }
}
class Child extends Parent {
    @Override
    public Dog getAnimal() { return new Dog(); } // ✅ Dog là subtype của Animal
}

// Đối với generics, dùng wildcard:
class Parent {
    public List<? extends Animal> getAnimals() { return new ArrayList<>(); }
}
```

### Hiệu Năng

```
Kế thừa generic:
- Runtime: Overhead bằng không
- Bridge method: +1 lời gọi (JIT inline)
- Compile-time: kiểm tra kiểu phức tạp
```

### Kinh Nghiệm Production

**Pattern Repository:**
```java
public interface Repository<T, ID> {
    Optional<T> findById(ID id);
    List<T> findAll();
}

public interface UserRepository extends Repository<User, Long> {
    // User và Long được cụ thể hóa
    // Nhưng UserRepository KHÔNG kế thừa Repository<Object, Object>
}

// Service generic
public class BaseService<T> {
    private final Repository<T, Long> repo;

    public BaseService(Repository<T, Long> repo) {
        this.repo = repo;
    }
}

// Chuyên biệt hóa
public class UserService extends BaseService<User> {
    public UserService(UserRepository repo) {
        super(repo);  // ✅ UserRepository extends Repository<User, Long>
    }
}
```

**Hệ thống phân cấp Event:**
```java
public abstract class Event { }
public class UserCreatedEvent extends Event { }
public class UserDeletedEvent extends Event { }

// Listener với wildcard
public interface EventListener<T extends Event> {
    void onEvent(T event);
}

// Processor chấp nhận tất cả các Event
public class EventProcessor {
    private final List<EventListener<? extends Event>> listeners = new ArrayList<>();

    public <T extends Event> void register(EventListener<T> listener) {
        listeners.add(listener);
    }

    public <T extends Event> void publish(T event) {
        for (EventListener<? extends Event> listener : listeners) {
            // dispatch
        }
    }
}
```

### Best Practices

```java
// ✅ Wildcard cho tính linh hoạt
public void process(List<? extends Animal> animals) { }

// ✅ Class generic với bound
public class AnimalBox<T extends Animal> { }

// ✅ Kiểu trả về covariant
@Override
public List<Dog> getAnimals() { }

// ❌ Mong đợi tính covariant
// ❌ Raw type để bỏ qua ràng buộc
// ❌ Bỏ qua tính bất biến
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Generics là bất biến: `List<Dog>` KHÔNG kế thừa từ `List<Animal>`, ngay cả khi Dog extends Animal
- Lý do: nếu covariance được cho phép, bạn có thể thêm một Cat vào một List<Dog>
- `<? extends T>` — covariance để đọc: `List<? extends Animal> animals = dogsList`
- `<? super T>` — contravariance để ghi: `List<? super Dog> dogs = animalList`
- Generics lồng nhau cũng bất biến: `Map<String, List<Dog>>` != `Map<String, List<Animal>>`
- Bridge method được tạo để giữ tính đa hình khi kế thừa class generic

**Các câu hỏi phụ thường gặp:**
- **Tại sao generics bất biến?** — An toàn kiểu: covariance sẽ phá vỡ tính toàn vẹn kiểu
- **Generics khác gì với mảng?** — Mảng là covariant (String[] extends Object[]), generics thì không
- **Cách truyền List<Dog> cho một phương thức nhận List<Animal>?** — Dùng `List<? extends Animal>`
- **Kiểu trả về covariant là gì?** — Một lớp con có thể trả về một kiểu cụ thể hơn: `Dog getAnimal()` thay vì `Animal`

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "List<Dog> là subtype của List<Animal>" — Generics là bất biến
- ❌ "Mảng và generics giống nhau trong kế thừa" — Mảng là covariant, generics là bất biến
- ❌ "Wildcard giải quyết mọi vấn đề" — Wildcard hạn chế khả năng đọc/ghi
- ❌ "Một class generic có thể kế thừa một class raw" — Có thể, nhưng tính an toàn kiểu bị mất

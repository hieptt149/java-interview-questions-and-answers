# Difference Between == and equals() for String (Sự khác biệt giữa == và equals() cho String)

## 🟢 Junior Level

**`==`** so sánh **địa chỉ bộ nhớ** (có phải cùng một object không).

**`equals()`** so sánh **nội dung** (văn bản bên trong có giống nhau không).

**Ví dụ:**
```java
String s1 = "Hello";
String s2 = "Hello";
String s3 = new String("Hello");

System.out.println(s1 == s2);      // true  — cùng object trong String Pool
System.out.println(s1 == s3);      // false — s3 là một object riêng biệt
System.out.println(s1.equals(s3)); // true  — văn bản giống nhau
```

**Quy tắc:** Đối với các chuỗi, luôn dùng `equals()`. Toán tử `==` — chỉ dùng để kiểm tra `null`.

## 🟡 Middle Level

### Cách equals() Hoạt Động

Thuật toán của `String.equals()`:
1. Đầu tiên kiểm tra `==` (fast path — nếu đó là cùng object, ngay lập tức `true`)
2. Kiểm tra object đó có phải là `String`
3. So sánh trường `coder` (cùng encoding?)

> `coder` (Java 9+) — một cờ chỉ ra chuỗi được lưu dưới dạng Latin1 (1 byte/ký tự) hay UTF-16 (2 byte/ký tự).
4. So sánh độ dài
5. So sánh từng ký tự của các mảng `byte[]`

```java
// Đơn giản hóa
public boolean equals(Object o) {
    if (this == o) return true;           // Fast path
    if (!(o instanceof String)) return false;
    String other = (String) o;
    if (this.value.length != other.value.length) return false;
    return Arrays.equals(this.value, other.value);
}
```

### Các Lỗi Điển Hình
1. **Lỗi:** `s1.equals(s2)` khi `s1` có thể là `null`
   **Giải pháp:** `"constant".equals(variable)` hoặc `Objects.equals(s1, s2)`

2. **Lỗi:** Nghĩ rằng `==` luôn hoạt động cho các literal giống hệt nhau
   **Giải pháp:** Điều này chỉ hoạt động cho các literal trong cùng class. Dữ liệu bên ngoài — trong heap.

### So Sánh
| Tiêu chí        | `==`              | `equals()`                                                              |
| ---------------- | ----------------- | ----------------------------------------------------------------------- |
| So sánh cái gì    | Tham chiếu (identity) | Nội dung (equality)                                                  |
| Tốc độ            | O(1)              | O(1) cho các object giống hệt nhau, O(n) cho các object khác nhau với cùng nội dung        |
| Với literal     | Hoạt động             | Hoạt động                                                                   |
| Với new String() | Không hoạt động      | Hoạt động                                                                   |
| null-safe        | Có (`s == null`) | Không (`s.equals()` sẽ ném NPE)                                        |

## 🔴 Senior Level

### Hiện Thực Nội Bộ

**So sánh bytecode:**
```java
// == → if_acmpeq (lệnh JVM: so sánh tham chiếu)
// equals() → invokevirtual java/lang/String.equals
```

**Hiện thực của OpenJDK (Java 9+):**
```java
public boolean equals(Object anObject) {
    if (this == anObject) return true;
    if (anObject instanceof String anotherString) {
        if (coder == anotherString.coder) {
            return isLatin1()
                ? StringLatin1.equals(value, anotherString.value)
                : StringUTF16.equals(value, anotherString.value);
        }
    }
    return false;
}

// StringLatin1.equals — intrinsic
@HotSpotIntrinsicCandidate
public static boolean equals(byte[] value, byte[] other) {
    if (value.length == other.length) {
        for (int i = 0; i < value.length; i++) {
            if (value[i] != other[i]) return false;
        }
        return true;
    }
    return false;
}
```

`@HotSpotIntrinsicCandidate` — JVM thay thế code Java bằng các lệnh CPU đã tối ưu hóa (so sánh vector hóa SIMD).

### Đánh Đổi Về Kiến Trúc (Trade-off)

**Identity (==) vs Equality (equals()):**
- `==` — kiểm tra identity của object (bình đẳng tham chiếu)
- `equals()` — kiểm tra tính tương đương nội dung (bình đẳng logic)

**Contract của equals():**
- Tính phản xạ: `x.equals(x)` luôn là `true`
- Tính đối xứng: `x.equals(y)` == `y.equals(x)`
- Tính bắc cầu: nếu `x.equals(y)` và `y.equals(z)`, thì `x.equals(z)`
- Tính nhất quán: các lời gọi lặp lại cho cùng kết quả
- Với bất kỳ `x` nào: `x.equals(null)` → `false`

### Các Trường Hợp Biên

1. **Contract với hashCode():** Nếu `s1.equals(s2)` → `s1.hashCode() == s2.hashCode()`. Trong `String` điều này được duy trì — hash được tính từ nội dung.

2. **Không khớp coder:** Một `String` với Latin1 (`"abc"`) và một `String` với UTF-16 (`"abc"` + Cyrillic) — `equals()` trả về `false` ở giai đoạn kiểm tra `coder`, ngay cả khi các ký tự trông giống nhau.

3. **String deduplication (G1 GC):** Kết hợp các mảng `byte[]`, nhưng các object `String` vẫn khác nhau. `==` trả về `false`, `equals()` — `true`.

### Hiệu Năng
| Kịch bản                         | `==`   | `equals()`            |
| -------------------------------- | ------ | ---------------------- |
| Các object giống hệt nhau                | ~0.3ns | ~0.3ns (fast path)    |
| Cùng nội dung, các object khác nhau  | ~0.3ns | ~2-5ns (SIMD)         |
| Nội dung khác nhau, cùng độ dài   | ~0.3ns | ~1-2ns (thoát sớm)   |
| Độ dài khác nhau                | ~0.3ns | ~0.5ns (kiểm tra độ dài) |

### Kinh Nghiệm Production
**Kịch bản:** Auth middleware — xác minh API key:
```java
// XẤU: == — có thể bị bypass nếu hacker đoán được địa chỉ
if (apiKey == expectedKey) { grant(); }

// TỐT: equals()
if (expectedKey.equals(apiKey)) { grant(); }

// TỐT HƠN: so sánh thời gian hằng số (bảo vệ khỏi timing attack)
if (MessageDigest.isEqual(expectedKey.getBytes(), apiKey.getBytes())) { grant(); }
// Lưu ý: getBytes() tạo các mảng mới — đây là một cấp phát.
// Với các hệ thống tải cao, cân nhắc so sánh trực tiếp ở cấp độ byte[].
```

### Best Practices Cho Highload
- `equals()` — lựa chọn mặc định cho so sánh nội dung
- `Objects.equals(a, b)` — null-safe, ủy quyền cho `a.equals(b)`
- `"CONSTANT".equals(variable)` — null-safe không cần object thừa
- Cho so sánh nhạy cảm về bảo mật: các thuật toán thời gian hằng số (bảo vệ khỏi timing attack)
- `==` — chỉ dùng cho kiểm tra `null` và các chuỗi đã đảm bảo intern

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `==` so sánh tham chiếu (địa chỉ bộ nhớ), `equals()` — nội dung chuỗi
- `equals()` có một fast path: đầu tiên kiểm tra `==` (nếu cùng object — ngay lập tức `true`)
- `String.equals()` kiểm tra coder, độ dài, sau đó so sánh từng ký tự
- `==` — O(1), `equals()` — O(n) với n — độ dài chuỗi
- `equals()` có thể ném NPE nếu gọi trên `null` — dùng `"const".equals(var)` hoặc `Objects.equals()`
- JVM tối ưu hóa `equals()` qua các lệnh SIMD cho các chuỗi ngắn
- Cho so sánh nhạy cảm về bảo mật, dùng so sánh thời gian hằng số

**Các câu hỏi phụ thường gặp:**
- **Bạn có thể dùng `==` cho các chuỗi không?** — Chỉ cho kiểm tra null (`s == null`) hoặc các chuỗi đã đảm bảo intern. Trong 99% các trường hợp — không.
- **Tại sao `equals()` nhanh hơn vẻ ngoài của nó?** — Fast path `==` + tối ưu hóa SIMD + thoát sớm khi không khớp.
- **Cái nào nhanh hơn: `==` hay `equals()`?** — `==` luôn là O(1), nhưng `equals()` với các object giống hệt nhau cũng là O(1) qua fast path.
- **Contract của `equals()`?** — Tính phản xạ, đối xứng, bắc cầu, nhất quán, `x.equals(null) → false`.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "`==` so sánh nội dung chuỗi" — chỉ so sánh tham chiếu
- ❌ "`equals()` luôn chậm" — fast path làm cho nó O(1) với các object giống hệt nhau
- ❌ "Bạn có thể so sánh các chuỗi qua `==` nếu chúng giống nhau" — chỉ hoạt động cho các literal trong cùng class
- ❌ "`equals()` không hoạt động với null" — trả về `false` đúng cách với tham số `null`

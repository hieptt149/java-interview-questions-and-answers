# What is TreeSet and how does it work? (TreeSet là gì và nó hoạt động như thế nào?)

## 🟢 Junior Level

**TreeSet** — một collection các phần tử duy nhất đã được sắp xếp.

**Ví dụ minh họa đơn giản:** Một cuốn từ điển — các từ luôn theo thứ tự bảng chữ cái, bất kể bạn thêm chúng theo thứ tự nào.

```java
TreeSet<Integer> set = new TreeSet<>();
set.add(5);
set.add(2);
set.add(8);
set.add(1);

System.out.println(set);  // → [1, 2, 5, 8] (luôn được sắp xếp!)
```

**Các thuộc tính then chốt:**
- Các phần tử luôn được sắp xếp
- null không được cho phép
- Chậm hơn HashSet: O(log n) thay vì O(1) + mỗi node là một đối tượng riêng trên heap (cache miss khi duyệt). Nhưng dữ liệu được sắp xếp.

## 🟡 Middle Level

### Bên trong: TreeMap

```java
// TreeSet = adapter bên trên TreeMap
private transient TreeMap<E, Object> m;
private static final Object PRESENT = new Object();

// Tất cả các thao tác đều ủy thác cho TreeMap
// Độ phức tạp: O(log n) cho add/remove/contains
```

### Cây đỏ-đen (Red-black tree)

```
Cây nhị phân tự cân bằng:
  → Chiều cao luôn là O(log n)
  → Khi chèn/xóa: tái cân bằng (các phép xoay — rotation)
    Rotation = tái cấu trúc các liên kết giữa các node của cây để giữ chiều cao O(log n). Nếu không có rotation, cây sẽ thoái hóa thành một danh sách liên kết với O(n).
  → Màu của node (đỏ/đen) để cân bằng

    5(B)
   /   \
  2(R)  8(R)
 /  \
1(B) 3(B)
```

### Điều hướng (Navigation)

```java
TreeSet<Integer> set = new TreeSet<>(Set.of(1, 3, 5, 7, 9));

set.floor(6);    // → 5 (≤ 6 gần nhất)
set.ceiling(6);  // → 7 (≥ 6 gần nhất)
set.lower(5);    // → 3 (< 5 nghiêm ngặt)
set.higher(5);   // → 7 (> 5 nghiêm ngặt)

set.subSet(3, 8);    // → [3, 5, 7] (khoảng — range)
set.headSet(5);      // → [1, 3] (nhỏ hơn 5)
set.tailSet(5);      // → [5, 7, 9] (lớn hơn hoặc bằng)
```

### compareTo so với equals

```java
// TreeSet dùng compareTo, KHÔNG phải equals!
class Person implements Comparable<Person> {
    String name;
    public int compareTo(Person o) {
        return name.compareTo(o.name);  // Theo name
    }
}

// Nếu compareTo = 0 → phần tử sẽ KHÔNG được thêm vào
// Ngay cả khi equals trả về false!

// → equals và compareTo phải nhất quán với nhau!
```

---

### Khi nào KHÔNG dùng TreeSet

1. **Chỉ cần tính duy nhất** — HashSet nhanh hơn (O(1) so với O(log n))
2. **Các phần tử không implement Comparable và không có Comparator** — TreeSet không thể sắp xếp
3. **Bộ nhớ là yếu tố quan trọng** — TreeSet lớn hơn HashSet 3-4 lần (các node cây với prev/next/left/right)

## 🔴 Senior Level

### Memory Footprint

```
Mỗi Entry trong TreeMap:
  Object Header: 12 byte
  K key: 4-8 byte
  V value: 4 byte (PRESENT)
  Entry left: 4-8 byte
  Entry right: 4-8 byte
  Entry parent: 4-8 byte
  boolean color: 1 byte
  Padding: tối đa 8 byte

Tổng: ~40-48 byte cho mỗi phần tử!

→ TreeSet lớn hơn HashSet 3-4 lần
```

### Vấn đề Cache Locality

```
Các node của cây nằm rải rác khắp Heap:
  [Entry1]...[Entry2]...[Entry3]

Mỗi lần chuyển đến một node con = cache miss!
  → Chờ từ RAM: 100+ chu kỳ

→ Iterate TreeSet chậm hơn HashSet
```

### Java 21: SequencedSet

```java
// TreeSet → SequencedSet (SequencedSet yêu cầu Java 21+, không có sẵn trên Java 11/17.)
set.getFirst();   // Phần tử nhỏ nhất
set.getLast();    // Phần tử lớn nhất
set.reversed();   // Thứ tự đảo ngược (view)

// addFirst/addLast → UnsupportedOperationException
// → Thứ tự của cây là cố định!
```

### Ngữ nghĩa của View

```java
NavigableSet<Integer> view = set.subSet(3, true, 7, true);
// → View "sống" (live), không phải một bản sao!

view.add(5);       // Thêm vào set GỐC
set.remove(5);     // Xóa khỏi view luôn!

view.add(10);      // → IllegalArgumentException!
// → 10 nằm ngoài khoảng [3, 7]
```

### Comparator tùy chỉnh với null

```java
// TreeSet không chấp nhận null theo mặc định
// Nhưng có thể thông qua Comparator:
TreeSet<String> set = new TreeSet<>(
    Comparator.nullsFirst(Comparator.naturalOrder())
);
set.add(null);  // OK! null đi đầu tiên
```

### Các tối ưu hóa của Spliterator

```java
Spliterator<Integer> spliterator = set.spliterator();
// Các đặc tính (characteristics):
//   SORTED   → Stream API tối ưu hóa
//   DISTINCT → distinct() là miễn phí
//   SIZED    → biết trước kích thước

set.stream()
   .distinct()  // → Không làm gì cả! Đã duy nhất rồi
   .count();    // → O(1), biết trước kích thước
```

### Kinh nghiệm Production

**Tình huống thực tế: Các bậc thuế (Tax brackets)**
```java
// Thuế suất theo ngưỡng thu nhập
NavigableMap<Integer, Double> taxBrackets = new TreeMap<>();
taxBrackets.put(0, 0.0);      // 0% đến 0
taxBrackets.put(10000, 0.1);  // 10% đến 10k
taxBrackets.put(50000, 0.2);  // 20% đến 50k

// Tìm thuế suất cho thu nhập 35,000
double rate = taxBrackets.floorEntry(35000).getValue();
// → 0.1 (10%)

// HashMap không làm được điều này! Cần sắp xếp
```

### Best Practices

1. **TreeMap** bên trong → các thao tác O(log n)
2. **Hợp đồng compareTo = equals**!
3. **null bị cấm** (nếu không có Comparator tùy chỉnh)
4. **View = sống (live)**, không phải một bản sao
5. **Java 21** → API SequencedSet
6. **Cache miss** khi iterate — hãy lưu ý điều này
7. **Bộ nhớ** nhiều hơn HashSet 3-4 lần

### Tóm tắt cho Senior

- **TreeSet** = TreeMap + placeholder PRESENT
- **Cây đỏ-đen** → O(log n), cân bằng
- **compareTo** quyết định tính duy nhất, không phải equals
- **NavigableSet** → floor/ceiling/subSet
- **View** = view sống, tạo O(1)
- **Cache Locality** tệ → các node nằm rải rác
- **Bộ nhớ** ~40-48 byte cho mỗi phần tử
- **SequencedSet (Java 21)** → getFirst/reversed

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- TreeSet = adapter bên trên TreeMap, các phần tử được lưu như các key, value = static final Object PRESENT
- Bên trong: cây đỏ-đen (cây nhị phân tự cân bằng), chiều cao luôn là O(log n)
- Độ phức tạp: O(log n) cho add/remove/contains — chậm hơn HashSet (O(1))
- API NavigableSet: floor, ceiling, lower, higher, subSet, headSet, tailSet
- Không chấp nhận null (nếu không có Comparator tùy chỉnh) — NullPointerException
- compareTo quyết định tính duy nhất, không phải equals — nếu compareTo = 0, phần tử sẽ không được thêm vào
- Bộ nhớ: ~40-48 byte cho mỗi phần tử (left, right, parent, color) — nhiều hơn HashSet 3-4 lần
- Cache locality tệ — các node nằm rải rác khắp heap, mỗi lần chuyển = cache miss
- View (subSet, v.v.) = view sống, không phải một bản sao, tạo O(1)

**Các câu hỏi phụ thường gặp:**
- **Tại sao TreeSet chậm hơn HashSet?** — O(log n) do cây + cache miss ở mỗi lần chuyển giữa các node.
- **Điều gì xảy ra nếu compareTo và equals không nhất quán?** — TreeSet có thể coi các phần tử khác nhau (theo equals) là giống hệt nhau (theo compareTo = 0) — mất dữ liệu.
- **Làm sao thêm null vào TreeSet?** — Thông qua Comparator.nullsFirst(Comparator.naturalOrder()).
- **View (subSet) là gì và các hạn chế của nó là gì?** — Biểu diễn khoảng dưới dạng sống. Bạn chỉ có thể thêm các phần tử trong khoảng — nếu không thì IllegalArgumentException.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "TreeSet dùng equals để so sánh các phần tử" — nó dùng compareTo!
- ❌ "TreeSet nhanh hơn HashSet" — chậm hơn 50 lần do O(log n) và cache miss
- ❌ "TreeSet làm việc với null theo mặc định" — không, chỉ với Comparator tùy chỉnh
- ❌ "subSet tạo một bản sao của dữ liệu" — nó là một view sống, các thay đổi phản ánh trong set gốc

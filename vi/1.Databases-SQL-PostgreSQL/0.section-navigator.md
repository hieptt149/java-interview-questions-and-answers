## 🔗 Các mối liên kết chính giữa các chủ đề

### Chủ đề: Indexes

```
Q1 (Tại sao cần) → Q2 (B-tree) → Q3 (Composite) → Q4 (Khi nào) → Q5 (Nhược điểm) → Q6 (Cardinality)
                                              ↓
                                    Q21 (Tối ưu Query)
```

**Các mối liên kết chính:**
- Q1 ↔ Q17 (MVCC): HOT updates không thể thực hiện đối với các cột có index
- Q2 ↔ Q18 (VACUUM): Bloat (phình bảng) → REINDEX
- Q3 ↔ Q6 (Cardinality): thứ tự cột theo độ chọn lọc (selectivity)
- Q4 ↔ Q19 (ANALYZE): thống kê ảnh hưởng đến việc planner (bộ lập kế hoạch) chọn index
- Q5 ↔ Q21 (Tối ưu hóa): Write Amplification (khuếch đại ghi), cân bằng index

### Chủ đề: JOIN và Subqueries

```
Q7 (Các loại JOIN) → Q8 (INNER vs LEFT) → Q9 (JOIN vs subquery) → Q10 (Correlated)
                                                    ↓
                                          Q20 (EXPLAIN: tìm SubPlan)
```

**Các mối liên kết chính:**
- Q7 ↔ Q20 (EXPLAIN): các chiến lược vật lý trong plan (Nested Loop, Hash, Merge)
- Q8 ↔ Q11 (WHERE vs HAVING): bộ lọc trên bảng bên phải → đặt trong ON, không phải WHERE
- Q9 ↔ Q10: Semi-Join, decorrelation, SubPlan vs InitPlan
- Q10 ↔ Q14 (Window Functions): window functions như một giải pháp thay thế cho correlated subquery

### Chủ đề: GROUP BY và Window Functions

```
Q11 (WHERE vs HAVING) → Q12 (GROUP BY) → Q13 (Khi nào dùng HAVING)
                                                ↓
                                    Q14 (Window Functions) → Q15 (ROW_NUMBER) → Q16 (RANK)
```

**Các mối liên kết chính:**
- Q11 ↔ Q12: WHERE thực thi trước GROUP BY, HAVING thực thi sau
- Q12 ↔ Q14: window functions KHÔNG gộp (collapse) các dòng lại (khác với GROUP BY)
- Q13 ↔ Q14: window functions được tính toán SAU HAVING → cần dùng subquery
- Q14 ↔ Q15, Q16: ROW_NUMBER, RANK, DENSE_RANK, NTILE, PERCENT_RANK

### Chủ đề: MVCC và Bảo trì (Maintenance)

```
Q17 (MVCC) → Q18 (VACUUM) → Q19 (ANALYZE) → Q20 (EXPLAIN) → Q21 (Tối ưu hóa)
```

**Các mối liên kết chính:**
- Q17 ↔ Q18: MVCC tạo ra dead tuples (dòng dữ liệu chết) → VACUUM loại bỏ chúng
- Q18 ↔ Q19: Autovacuum kích hoạt ANALYZE
- Q19 ↔ Q20: Thống kê lỗi thời (stale statistics) → plan sai → cần ANALYZE
- Q20 ↔ Q21: EXPLAIN (ANALYZE, BUFFERS) — công cụ tối ưu hóa chính

## 🎓 Bảng tóm tắt: Cần biết gì cho mỗi cấp độ

### 🟢 Junior
- Index là gì và tại sao cần
- Các loại JOIN (INNER, LEFT, RIGHT, FULL, CROSS)
- WHERE vs HAVING: khi nào dùng cái nào
- GROUP BY + các hàm tổng hợp (aggregate functions) (COUNT, SUM, AVG)
- MVCC: reader (người đọc) không chặn writer (người ghi)
- VACUUM: tại sao cần, regular vs FULL

### 🟡 Middle
- Cấu trúc B-tree, composite index, quy tắc left-prefix (tiền tố bên trái)
- Các chiến lược JOIN vật lý (Nested Loop, Hash, Merge)
- EXISTS vs JOIN, SubPlan vs InitPlan
- Window functions: ROW_NUMBER, RANK, LAG/LEAD
- Autovacuum: threshold (ngưỡng), scale_factor, tuning (tinh chỉnh)
- ANALYZE: thống kê, n_distinct, MCV
- EXPLAIN (ANALYZE, BUFFERS): cách đọc plan

### 🔴 Senior
- Lehman-Yao, High Key, deduplication (PG 13+), Skip Scan emulation (giả lập Skip Scan)
- GEQO, Join Reordering, Outer Join Removal (loại bỏ Outer Join), Memoize (PG 14+)
- MVCC: Hint Bits, HOT, SSI, CLOG, XID Wraparound
- VACUUM: Visibility Map, Parallel, pg_repack, Cost-based
- Extended Statistics, Reservoir Sampling
- Generic vs Custom Plans, plan_cache_mode, JIT, WAL
- Tối ưu hệ thống: denormalization, pgBouncer, Partitioning (phân vùng)

# How to Find Out How Much Memory a String Occupies (Cách tìm hiểu một String chiếm bao nhiêu bộ nhớ)

## 🟢 Junior Level

Kích thước của một chuỗi trong bộ nhớ phụ thuộc vào phiên bản Java và nội dung chuỗi.

**Tính toán đơn giản cho Java 9+:**
```
Tổng kích thước = Object String (~24 byte) + mảng byte[] (~16 byte header) + các ký tự
```

**Ví dụ:**
```java
String s = "Hello"; // 5 ký tự Latin-1
// Object String: ~24 byte
// Mảng byte[5]:  ~21 byte (16 header + 5 dữ liệu, làm tròn thành 24)
// Tổng: ~48 byte
```

**Cách đo chính xác:**
Dùng thư viện JOL (Java Object Layout):

```java
import org.openjdk.jol.info.GraphLayout;

String s = "Hello";
System.out.println(GraphLayout.parseInstance(s).totalSize());
// In ra kích thước chính xác tính bằng byte, bao gồm cả bản thân object và tất cả dữ liệu liên quan
```

**Ví dụ minh họa đơn giản:** String giống như một cái hộp (object String) chứa một cái hộp khác (mảng byte). Để tìm tổng kích thước, bạn cần cộng cả hai cái hộp lại.

## 🟡 Middle Level

### Cấu Trúc Object String (Java 9+, JVM 64-bit Với CompressedOops)

```
Object String (24 byte):
├── Mark Word (header object):    12 byte
├── Class Pointer (nén):    4 byte
├── byte[] value (tham chiếu):      4 byte
├── byte coder:                    1 byte
├── int hash:                      4 byte
├── Padding:                       3 byte (căn chỉnh 8-byte)
└── TỔNG:                        24 byte (làm tròn theo bội số của 8)

Mảng byte[]:
├── Array Header (Mark + Class):  12 byte
├── Độ dài mảng:                  4 byte
├── Dữ liệu:                          N byte (1 byte/ký tự cho Latin-1, 2 cho UTF-16)
├── Padding:                       theo ranh giới 8-byte
└── TỔNG:                        16 + N (làm tròn theo 8) byte
```

### Ví Dụ Tính Toán

| Chuỗi            | Java 8 (`char[]`) | Java 9+ (Latin-1) | Java 9+ (UTF-16) |
| ----------------- | ----------------- | ----------------- | ---------------- |
| `""`              | 40 byte          | 48 byte          | N/A              |
| `"Hello"`         | 48 byte          | 48 byte          | N/A              |
| `"Привет"`        | 52 byte          | N/A               | 52 byte          |
| 100 ký tự (Latin-1) | 232 byte       | 140 byte         | N/A              |
| 100 ký tự (trộn) | 232 byte         | N/A               | 240 byte          |

### Cách Đo Trong Thực Tế

**JOL (Java Object Layout):**
```xml
<dependency>
    <groupId>org.openjdk.jol</groupId>
    <artifactId>jol-core</artifactId>
    <version>0.17</version>
</dependency>
```

```java
// Kích thước đầy đủ (String + mảng)
long total = GraphLayout.parseInstance(s).totalSize();

// Layout chi tiết
System.out.println(GraphLayout.parseInstance(s).toPrintable());
```

### Bảng Các Lỗi Điển Hình

| Lỗi                                      | Hậu quả                        | Giải pháp                                                 |
| -------------------------------------------- | ----------------------------------- | -------------------------------------------------------- |
| Dùng `sizeof` như trong C++                   | Java không có `sizeof`                | Dùng JOL hoặc `Instrumentation.getObjectSize()`             |
| Chỉ đếm ký tự, quên header | Ước tính thiếu ~28–40 byte     | Luôn tính đến overhead: object String + header mảng|
| Không tính đến CompressedOops            | Tính toán sai với Heap > 32GB  | Không có CompressedOops, mỗi con trỏ = 8 byte thay vì 4|

### So Sánh: Java 8 vs Java 9+

| Khía cạnh           | Java 8                 | Java 9+ (Latin-1)     | Java 9+ (UTF-16)       |
| ---------------- | ---------------------- | --------------------- | ----------------------- |
| Mảng nội bộ   | `char[]` (2 byte/ký tự)| `byte[]` (1 byte/ký tự)| `byte[]` (2 byte/ký tự)|
| Trường coder      | Không                     | 1 byte                | 1 byte                 |
| Kích thước `"Hello"`   | 48 byte               | 48 byte              | N/A                    |
| Kích thước `"Привет"`  | 52 byte               | N/A                   | 52 byte                 |

### Khi Nào Bạn Không Cần Đo Kích Thước String Chính Xác
- **Các chuỗi tồn tại ngắn** — Young GC thu gom chúng miễn phí
- **Số lượng chuỗi nhỏ** — overhead không đáng chú ý so với Heap
- **Prototype và PoC** — chỉ tối ưu hóa khi vấn đề đã được chứng minh

## 🔴 Senior Level

### Hiện Thực Nội Bộ — Tính Toán Chính Xác

**JVM 64-bit Với UseCompressedOops (mặc định cho Heap < 32GB):**

```java
// Object String (Java 9+)
// Mark Word:       12 byte (8 mark word + 4 klass pointer nén)
// value ref:        4 byte
// coder:            1 byte
// hash:             4 byte
// hashIsZero:       1 byte (trong một số bản build JDK)
// Padding:          đến 24 byte (bội số của 8)
// = tổng 24 byte

// Mảng byte[]
// Mark Word:       12 byte
// length:           4 byte
// data:             N byte
// Padding:          đến ranh giới 8-byte
// = 16 + N (làm tròn lên 8)
```

**Không Có CompressedOops (`-XX:-UseCompressedOops`, Heap > 32GB):**
- Mỗi con trỏ = 8 byte thay vì 4
- Object String: ~40 byte (so với 24 khi nén)
- Mảng byte[]: ~24 + N byte

### Các Trường Hợp Biên (Tối Thiểu 3)

**1. String Pool — một object, nhiều tham chiếu:**
```java
String s1 = "Hello";
String s2 = "Hello";
String s3 = "Hello";
// Cả ba tham chiếu đều trỏ đến MỘT object trong String Pool
// Tổng bộ nhớ: 44 byte (không phải 3 × 44 = 132)
```

**2. Substring (Java 7+) — sao chép mảng:**
```java
String huge = "A".repeat(1_000_000); // ~1MB
String sub = huge.substring(0, 5);    // "AAAAA"
// sub — byte[5] riêng biệt, không phải một tham chiếu đến một phần của huge
// Trước Java 7: sub chia sẻ mảng của huge (rò rỉ bộ nhớ với huge.substring(0,5))
// Java 7+: sao chép — an toàn, nhưng sub = ~44 byte
```

**3. Các chuỗi đã intern — overhead bổ sung:**
```java
String s = new String("Hello").intern();
// Object String: ~44 byte
// + mục trong StringTable: ~24-40 byte (tùy phiên bản JVM, mục hashtable native)
// Tổng: ~76 byte mỗi chuỗi độc nhất đã intern
```

**4. CompressedOops bị vô hiệu hóa ở Heap > 32GB:**
```bash
# Ở -Xmx64g: CompressedOops có thể bị vô hiệu hóa
# Object String: 40 byte thay vì 24
# Với 10M chuỗi: +160MB overhead!
```

**5. Substring từ chuỗi UTF-16 — kế thừa UTF-16:**
```java
String mixed = "Hello Мир";    // UTF-16 (do có Cyrillic)
String sub = mixed.substring(0, 5); // "Hello" — vẫn UTF-16!
// sub chiếm ~56 byte (UTF-16: 24 String + 32 byte[10]) thay vì ~48 byte
// (Latin-1: 24 String + 24 byte[5]). Chênh lệch ~8 byte.
// Mất mát: ~5 byte mỗi chuỗi con
```

### Hiệu Năng — Đo Lường Thực Tế

```java
// Benchmark JOL
String empty = "";
String latin5 = "Hello";
String cyrillic5 = "Привет";
```

| Chuỗi rỗng     | 40 byte        | 40MB       | 400MB       |
| Latin-1, 5 ký tự | 44 byte        | 44MB       | 440MB       |

### Tác Động Đến Bộ Nhớ Và GC

**Tiết kiệm Heap:**
- Compact String (Java 9+): **~40–50% tiết kiệm** cho các chuỗi ASCII/Latin-1
- Với 70% chuỗi Latin-1 trong ứng dụng: giảm Heap tổng thể 20–30%
- Heap ít hơn → Full GC ít thường xuyên hơn → latency thấp hơn

**Các chu kỳ GC:**
- Young GC: quét Eden/Survivor — ít cấp phát chuỗi hơn → quét nhanh hơn
- Old Gen: ít object hơn → ít công việc hơn cho marking/compaction
- G1 GC: kích thước region nhỏ hơn cho các ứng dụng nhiều chuỗi → evacuation hiệu quả hơn

### Thread Safety

`String` — bất biến, thread-safe. Kích thước không thay đổi sau khi tạo. `coder` — `final`, `value` — `@Stable`. Không có race condition khi đọc kích thước từ nhiều thread.

### Câu Chuyện Thực Tế Trong Production

**Kịch bản:** Cache 1M chuỗi trong bộ nhớ (profile người dùng, service JSON API):
- **Java 8:** 1M × ~50 byte (trung bình) = ~50MB
- **Java 9+ Compact:** 1M × ~35 byte (trung bình, 70% Latin-1) = ~35MB
- Tiết kiệm: 15MB → ít áp lực GC hơn, Full GC ít thường xuyên hơn 25%

**Kịch bản 2:** Service tải cao với `-Xmx2g`:
- Không có CompressedOops: overhead String = ~40 byte/object
- Với CompressedOops: overhead String = ~24 byte/object
- Với 10M object: **tiết kiệm 160MB** chỉ riêng về header
- Đây là sự khác biệt giữa hoạt động ổn định và OOM khi tải đỉnh

**Kịch bản 3:** Bộ tổng hợp log — lưu trữ 10M dòng log trong bộ nhớ:
- Mỗi chuỗi: ~200 byte (trung bình, trộn lẫn Latin-1/UTF-16)
- Tổng: ~2GB chỉ riêng cho các chuỗi
- Bật `-XX:+UseStringDeduplication`: tiết kiệm 400MB (các log level trùng lặp, tên host)

### Best Practices Cho Highload

- Dùng **JOL** để đo chính xác, đừng đếm thủ công
- **CompressedOops** được bật theo mặc định — đừng vô hiệu hóa nếu không có lý do chính đáng
- **Compact String** (Java 9+) mang lại tiết kiệm 40–50% miễn phí cho Latin-1
- **String Pool:** các chuỗi trùng lặp = một object (tiết kiệm với deduplication cao)
- Cho **độ trễ cực thấp**: tránh String, dùng `byte[]` hoặc `ByteBuf` (Netty)
- Ở **Heap > 32GB**: CompressedOops bị vô hiệu hóa → +30–50% overhead trên các object → lập kế hoạch capacity
- Cho các ứng dụng nhiều chuỗi: cân nhắc `-XX:+UseStringDeduplication` (G1 GC)
- Profile trước khi tối ưu hóa: đôi khi String chỉ chiếm 5% Heap, và tối ưu hóa sẽ không giúp ích

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Kích thước String = object (~24 byte) + mảng byte[] (~16 + N byte), với N phụ thuộc vào coder
- Latin-1: 1 byte/ký tự, UTF-16: 2 byte/ký tự (Java 9+)
- `"Hello"` ≈ 48 byte (24 String + 24 byte[5]), `"Привет"` ≈ 52 byte (UTF-16)
- JOL (Java Object Layout) — thư viện để đo chính xác: `GraphLayout.parseInstance(s).totalSize()`
- CompressedOops (mặc định cho Heap < 32GB) giảm con trỏ từ 8 xuống 4 byte
- Không có CompressedOops (Heap > 32GB): object String ≈ 40 byte thay vì 24

**Các câu hỏi phụ thường gặp:**
- **Làm sao tìm kích thước String chính xác?** — JOL: `GraphLayout.parseInstance(s).totalSize()`. Hoặc `Instrumentation.getObjectSize()`.
- **Tại sao `""` (chuỗi rỗng) chiếm 48 byte?** — 24 byte (object String) + 24 byte (mảng byte[] rỗng với header).
- **String Pool có ảnh hưởng đến kích thước không?** — Có: các literal trùng lặp = một object. 100 tham chiếu đến `"Hello"` = tổng cộng 48 byte, không phải 4800.
- **Điều gì xảy ra ở Heap > 32GB?** — CompressedOops bị vô hiệu hóa, mỗi con trỏ = 8 byte. Với 10M chuỗi: +160MB overhead.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Java có `sizeof` như C++" — không, dùng JOL hoặc `Instrumentation`
- ❌ "Kích thước String = chỉ độ dài ký tự" — quên về header object (~40 byte overhead)
- ❌ "CompressedOops luôn được bật" — bị vô hiệu hóa ở Heap > 32GB
- ❌ "substring() vẫn chia sẻ mảng" — kể từ Java 7u6, sao chép, rò rỉ bộ nhớ đã được sửa

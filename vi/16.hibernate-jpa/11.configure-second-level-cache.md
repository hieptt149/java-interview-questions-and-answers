# How to Configure the Second-Level Cache (Cách cấu hình second-level cache)

## Overview

Cấu hình second-level cache bao gồm việc chọn provider, cấu hình Hibernate, thiết lập các cache region, và định nghĩa chiến lược caching cho mỗi entity.

---

## Junior Level

### Thiết Lập Cơ Bản

Để thiết lập L2 cache, bạn cần hoàn thành 3 bước:

1. **Bật cache** trong cấu hình
2. **Chọn một provider** (Ehcache, Hazelcast, Redis)
3. **Đánh dấu các entity** với annotation `@Cacheable`

```yaml
# application.yml
spring:
  jpa:
    properties:
      hibernate:
        cache:
          use_second_level_cache: true
          region:
            factory_class: org.hibernate.cache.jcache.JCacheRegionFactory
      javax.persistence.sharedCache.mode: ENABLE_SELECTIVE
```

```java
@Entity
@Cacheable
@Cache(usage = CacheConcurrencyStrategy.READ_WRITE)
public class User {
    @Id
    private Long id;
    private String name;
}
```

### Các Chế Độ Caching

```yaml
# Tất cả entity được cache theo mặc định
javax.persistence.sharedCache.mode: ALL

# Chỉ những cái được đánh dấu @Cacheable (khuyến nghị)
javax.persistence.sharedCache.mode: ENABLE_SELECTIVE

# Tất cả trừ những cái được đánh dấu @Cacheable(false)
javax.persistence.sharedCache.mode: DISABLE_SELECTIVE

# Không có (cache bị tắt)
javax.persistence.sharedCache.mode: NONE
```

## Middle Level

### Khi Nào KHÔNG Nên Dùng L2 Cache

1. **Khối lượng công việc ghi nhiều** - invalidate cache liên tục tốn kém hơn SELECT từ DB
2. **Dữ liệu chuẩn hóa cao** với nhiều JOIN thường xuyên - cache không hiệu quả
3. **Cluster nhiều node với cập nhật thường xuyên** - lưu lượng invalidation vượt quá lợi ích

### Cấu Hình Ehcache

```xml
<!-- ehcache.xml trong src/main/resources -->
<config xmlns:xsi='http://www.w3.org/2001/XMLSchema-instance'
        xmlns='http://www.ehcache.org/v3'>

    <cache alias="com.example.User">
        <heap unit="entries">1000</heap>
        <offheap unit="MB">50</offheap>
        <expiry>
            <ttl unit="minutes">30</ttl>
        </expiry>
    </cache>

    <cache alias="com.example.Country">
        <heap unit="entries">500</heap>
        <expiry>
            <ttl unit="hours">24</ttl>
        </expiry>
    </cache>
</config>
```

### Quản Lý Cache Theo Cách Lập Trình

```java
Cache cache = entityManager.getEntityManagerFactory().getCache();

// Evict entity cụ thể
cache.evict(User.class, userId);

// Evict tất cả entity của loại đó
cache.evict(User.class);

// Evict mọi thứ
cache.evictAll();
```

### Collection Trong Cache

```java
@Entity
@Cacheable
@Cache(usage = CacheConcurrencyStrategy.READ_WRITE)
public class User {

    @OneToMany(mappedBy = "user")
    @Cache(usage = CacheConcurrencyStrategy.READ_WRITE)
    private List<Order> orders;  // cache collection
}
```

### Các Lỗi Thường Gặp

```java
// Không có TTL - cache tăng vô hạn
// Giải pháp: luôn đặt TTL trong cấu hình provider

// Cache tất cả entity
// Giải pháp: chỉ cache những cái đọc thường xuyên, hiếm khi sửa đổi

// Chiến lược sai
@Cache(usage = CacheConcurrencyStrategy.READ_ONLY)
public class Order { }  // Order thay đổi thường xuyên
```

## Senior Level

### Clustered Cache

```yaml
# Hazelcast cho cluster
spring:
  jpa:
    properties:
      hibernate:
        cache:
          region:
            factory_class: com.hazelcast.hibernate.HazelcastCacheRegionFactory

# Redis
spring:
  jpa:
    properties:
      hibernate:
        cache:
          region:
            factory_class: com.redislabs.hibernate.redisson.cache.impl.RedissonRegionFactory
```

```
Các vấn đề của clustered cache:
- Eventual consistency (không phải strong) - dữ liệu trên các node cluster khác nhau trở nên giống nhau không ngay lập tức, mà sau một khoảng thời gian. Trong thời gian đó, một node có thể thấy dữ liệu cũ, node khác - dữ liệu mới.
- Độ trễ network khi replicate
- Xung đột khi cập nhật đồng thời
- Cần có chiến lược invalidate cache
```

### Cấu Hình Region

```java
@Entity
@Cacheable
@org.hibernate.annotations.Cache(
    usage = CacheConcurrencyStrategy.READ_WRITE,
    region = "userCache"  // tên region
)
public class User { }
```

```xml
<!-- Các cài đặt khác nhau cho các region khác nhau -->
<cache alias="userCache">
    <heap>5000</heap>
    <expiry><ttl unit="minutes">15</ttl></expiry>
</cache>

<cache alias="countryCache">
    <heap>500</heap>
    <expiry><ttl unit="hours">48</ttl></expiry>
</cache>
```

### Monitoring Production

```java
Statistics stats = entityManagerFactory
    .unwrap(SessionFactory.class)
    .getStatistics();

// Metric L2 cache
long hitCount = stats.getSecondLevelCacheHitCount();
long missCount = stats.getSecondLevelCacheMissCount();
long putCount = stats.getSecondLevelCachePutCount();
long evictionCount = stats.getSecondLevelCacheEvictionCount();

double hitRatio = (double) hitCount / (hitCount + missCount);

// Logging
log.info("L2 Cache: hits={}, misses={}, ratio={:.2f}",
    hitCount, missCount, hitRatio);

// hitRatio > 0.8 thường tốt cho khối lượng công việc đọc nhiều; cho khối lượng công việc ghi nhiều thì thậm chí 0.5 cũng có thể bình thường.
```

### Query Cache

```yaml
spring:
  jpa:
    properties:
      hibernate:
        cache:
          use_query_cache: true
```

```java
@QueryHint(name = "org.hibernate.cacheable", value = "true")
@Query("SELECT u FROM User u WHERE u.status = :status")
List<User> findByStatus(@Param("status") String status);

// Quan trọng: query cache chỉ lưu ID entity
// Các entity thực tế đến từ L2 cache
```

### Best Practices

```
TTL cho mỗi region
Giới hạn heap để ngăn rò rỉ bộ nhớ
Clustered cache cho ứng dụng multi-node
Giám sát hit ratio
Chế độ ENABLE_SELECTIVE
READ_ONLY cho dữ liệu tham chiếu

Không có TTL và giới hạn
Cache cho dữ liệu thay đổi thường xuyên
Không giám sát hit ratio
Query cache không có L2 cache
INVALIDATE_ALL ở mỗi lần thay đổi
```

## Interview Cheat Sheet

**Cần phải biết:**
- 3 bước thiết lập: bật cache, chọn provider, đánh dấu entity với @Cacheable
- Các chế độ: ENABLE_SELECTIVE (khuyến nghị), ALL, DISABLE_SELECTIVE, NONE
- Các chiến lược caching: READ_ONLY cho dữ liệu tham chiếu, READ_WRITE cho dữ liệu thay đổi
- Cấu hình Ehcache: kích thước heap, offheap, TTL cho mỗi region
- Clustered cache: Hazelcast/Redis, eventual consistency, overhead network
- Query cache vô dụng nếu không có L2 cache - chỉ lưu ID entity

**Các câu hỏi phụ thường gặp:**
- **Nên chọn chế độ caching nào?** ENABLE_SELECTIVE - chỉ những cái được đánh dấu @Cacheable, kiểm soát tốt nhất
- **Cách đặt TTL khác nhau cho các entity khác nhau?** Thông qua region: region = "userCache" và các cài đặt khác nhau trong ehcache.xml
- **Điều gì xảy ra khi một entity được cập nhật trong cluster?** Thông báo invalidation được broadcast đến tất cả các node, request tiếp theo - miss
- **Cách giám sát trong production?** Statistics: hitCount, missCount, hitRatio, evictionCount

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi bật cache mà không có TTL" - rò rỉ bộ nhớ
- "READ_ONLY cho Order" - order thay đổi thường xuyên
- "Query cache không có L2 cache" - vô dụng
- "ENABLE_SELECTIVE nhưng không đánh dấu @Cacheable" - cache không hoạt động

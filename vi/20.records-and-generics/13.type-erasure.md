# What Is Type Erasure? (Type erasure là gì)

## 🟢 Junior Level

**Type erasure** là một quá trình trong đó trình biên dịch Java **loại bỏ thông tin kiểu generic** trong quá trình biên dịch.

Sau khi biên dịch, JVM không biết kiểu nào đã được chỉ định trong generic.

```java
// Code của bạn:
List<String> strings = new ArrayList<>();
List<Integer> integers = new ArrayList<>();

// Sau khi biên dịch (type erasure):
List strings = new ArrayList();  // String -> Object
List integers = new ArrayList(); // Integer -> Object

// JVM chỉ thấy List, không có thông tin kiểu!
```

**Tại sao cần thiết:**
- Tương thích với code cũ (trước Java 5)
- Không có overhead tại runtime
- Code chạy nhanh như nhau

## 🟡 Middle Level

### Cách Hoạt Động

Trình biên dịch thay thế type parameter bằng **bound** của chúng (hoặc `Object` nếu không có bound):

```java
// Source code
public class Box<T> {
    private T value;
    public void set(T value) { this.value = value; }
    public T get() { return value; }
}

// Sau type erasure
public class Box {
    private Object value;  // T -> Object (không có bound)
    public void set(Object value) { this.value = value; }
    public Object get() { return value; }
}
```

**Bounded type erasure:**
```java
public class NumberBox<T extends Number> {
    private T value;
    public double doubleValue() { return value.doubleValue(); }
}

// Sau erasure: T -> Number (bound đầu tiên)
public class NumberBox {
    private Number value;
    public double doubleValue() { return value.doubleValue(); }
}
```

**Trình biên dịch thêm cast:**
```java
Box<String> box = new Box<>();
box.set("Hello");
String s = box.get();

// Sau khi biên dịch:
Box box = new Box();
box.set("Hello");
String s = (String) box.get();  // cast ngầm định được thêm vào
```

### Các Ràng Buộc Do Type Erasure

**1. Không thể tạo instance của T:**
```java
public class Box<T> {
    // ❌ Không thể làm
    public Box() {
        value = new T();  // lỗi biên dịch
    }
}
```

**2. Không thể instanceof T:**
```java
public void check(Object obj) {
    // ❌ Không thể làm
    if (obj instanceof T) { }  // lỗi biên dịch
}
```

**3. Không thể tạo mảng của T:**
```java
public class Box<T> {
    // ❌ Không thể làm
    private T[] array = new T[10];  // lỗi biên dịch

    // ✅ Giải pháp
    private T[] array = (T[]) new Object[10];
}
```

**4. Không thể có trường static với T:**
```java
public class Box<T> {
    // ❌ Không thể làm — ngữ cảnh static không biết về T
    private static T value;  // lỗi biên dịch
}
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Đặc tả JLS (4.6):**
```
Ánh xạ type erasure:
1. Type parameter -> bound đầu tiên (hoặc Object)
2. Parameterized type -> erasure của raw type
3. Nested type -> áp dụng đệ quy
```

**Bridge method:**
```java
public class Node<T extends Comparable<T>> {
    private T data;
    public void setData(T data) { this.data = data; }
    public T getData() { return data; }
}

public class DateNode extends Node<Date> {
    @Override
    public void setData(Date data) { super.setData(data); }
    @Override
    public Date getData() { return super.getData(); }
}

// Sau erasure:
class Node {
    private Comparable data;
    public void setData(Comparable data) { }
    public Comparable getData() { return data; }
}

class DateNode extends Node {
    public void setData(Date data) { super.setData(data); }
    public Date getData() { return super.getData(); }

    // Bridge method để giữ tính đa hình:
    // Bridge method với chữ ký đã bị xóa (erased) ủy quyền cho phương thức cụ thể
    public void setData(Comparable data) { setData((Date) data); }
    public Comparable getData() { return getData(); }
    // Trong DateNode trình biên dịch sinh ra:
    // public Object getData() { return this.getData(); } // gọi Date getData()
    // Đây KHÔNG PHẢI là đệ quy — nó gọi phương thức nạp chồng với chữ ký trả về khác.
}
```

**Reflection:**
```java
// Kiểm tra qua reflection
public void inspect() {
    List<String> list = new ArrayList<>();

    // Type erasure — runtime không biết về String
    Type genericType = list.getClass().getGenericSuperclass();
    System.out.println(genericType);  // java.util.AbstractList<E>

    // Nhưng bạn có thể lấy thông tin từ field/method
    Field field = MyClass.class.getDeclaredField("stringList");
    ParameterizedType pt = (ParameterizedType) field.getGenericType();
    System.out.println(pt.getActualTypeArguments()[0]);  // class java.lang.String
}
```

### Đánh Đổi Kiến Trúc

**Type erasure so với reified generics:**

| Type Erasure (Java)             | Reified (C#, Kotlin)        |
| ------------------------------- | --------------------------- |
| Tương thích nhị phân          | Thông tin đầy đủ tại runtime |
| Overhead bằng không                   | Overhead runtime            |
| Ràng buộc (new T, instanceof) | Chức năng đầy đủ     |
| Bridge method                  | Không có bridge method          |

### Edge Cases

**1. Ngoại lệ tạo mảng generic:**
```java
public class GenericArray<T> {
    private T[] elements;

    public GenericArray(int size) {
        // Không thể new T[], nhưng có thể qua Class
        elements = (T[]) Array.newInstance(
            Object.class, size
        );
        // Đây vẫn là một unchecked cast. Array.newInstance(Object.class) tạo Object[],
        // không phải T[]. Cách tiếp cận an toàn kiểu cần Class<T>.
    }
}
```

**2. Xử lý ngoại lệ generic:**
```java
public class ExceptionHandler {
    // Type erasure — không thể bắt theo kiểu generic
    public void handle(Exception e) {
        // ❌ Không thể làm
        // if (e instanceof RuntimeException<String>) { }

        // ✅ Kiểm tra qua class
        if (e instanceof RuntimeException) { }
    }
}
```

**3. Heap pollution:**
```java
// Heap pollution — khi collection generic chứa kiểu sai
List rawList = new ArrayList();
rawList.add("Hello");

List<String> stringList = rawList;  // cảnh báo unchecked
String s = stringList.get(0);  // OK

rawList.add(42);  // heap pollution — Integer xuất hiện trong một list của String
Integer i = (Integer) stringList.get(1);  // ClassCastException!

// @SafeVarargs giúp ích
@SafeVarargs
public static <T> void safeMethod(List<T>... lists) { }
```

### Hiệu Năng

```
Overhead của type erasure:
- Thời gian biên dịch: kiểm tra kiểu
- Runtime: Overhead bằng không
- Bộ nhớ: Không có dữ liệu bổ sung
- Cast: Cast ngầm định khi truy cập

Benchmark:
Thao tác         | Có generics | Không có generics
------------------|---------------|-----------------
List.get()        | 1 ns          | 1 ns (+ cast)
Map.put()         | 5 ns          | 5 ns
Kiểm tra kiểu        | thời gian biên dịch  | runtime (nguy cơ ClassCastException)
```

### Kinh Nghiệm Production

**Cách giải quyết type erasure:**
```java
// 1. Truyền Class<T> để tạo instance
public class Factory<T> {
    private final Class<T> type;

    public Factory(Class<T> type) {
        this.type = type;
    }

    public T create() throws Exception {
        return type.getDeclaredConstructor().newInstance();
    }
}

// 2. Type token cho generics
public class TypeReference<T> {
    private final Type type;

    protected TypeReference() {
        ParameterizedType pt = (ParameterizedType)
            getClass().getGenericSuperclass();
        this.type = pt.getActualTypeArguments()[0];
    }

    public Type getType() { return type; }
}

// Sử dụng (kiểu Jackson)
User user = mapper.readValue(json, new TypeReference<User>() {});
```

### Best Practices

```java
// ✅ Dùng Class<T> để tạo instance
public <T> T create(Class<T> type) { return type.newInstance(); }

// ✅ Wildcard cho tính linh hoạt
public void process(List<? extends Number> numbers) { }

// ✅ @SafeVarargs cho varargs generic
@SafeVarargs
public static <T> void safeMethod(T... items) { }

// ❌ new T()
// ❌ instanceof T
// ❌ new T[]
// ❌ Ngữ cảnh static với T
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Type erasure — trình biên dịch thay T bằng Object (hoặc bound đầu tiên) khi biên dịch
- Tại sao: tương thích nhị phân với code trước Java 5, overhead runtime bằng không
- Ràng buộc: không thể `new T()`, `instanceof T`, `new T[]`, trường static với T
- Bridge method — trình biên dịch tạo chúng để giữ tính đa hình sau erasure
- Bounded erasure: `<T extends Number>` — T được thay bằng Number, không phải Object
- Heap pollution — khi collection generic chứa các phần tử kiểu sai

**Các câu hỏi phụ thường gặp:**
- **Tại sao không thể new T()?** — Sau erasure T -> Object, trình biên dịch không biết constructor nào để gọi
- **Có thể xác định kiểu T tại runtime không?** — Không trực tiếp, nhưng có thể qua Class<T> hoặc TypeReference
- **Bridge method là gì?** — Phương thức tổng hợp với chữ ký đã bị erased, ủy quyền cho phương thức gốc
- **Type erasure vs reified generics (C#)?** — Java: chỉ tại compile-time, C#: thông tin đầy đủ tại runtime

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "JVM kiểm tra kiểu generic tại runtime" — Type erasure, JVM không thấy kiểu generic
- ❌ "new T() hoạt động qua reflection" — Bị cấm ở tầng trình biên dịch
- ❌ "Type erasure thêm overhead" — Overhead bằng không, không có dữ liệu bổ sung
- ❌ "Có thể kiểm tra instanceof T" — Lỗi biên dịch, kiểu đã bị xóa

# What is the difference between synchronous and asynchronous communication (Sự khác biệt giữa giao tiếp đồng bộ và bất đồng bộ là gì)

## 🟢 Junior Level

**Đồng bộ (Synchronous)** — gửi một request và **chờ response** (giống một cuộc gọi điện thoại).

**Bất đồng bộ (Asynchronous)** — gửi một message và **quên nó đi**, response đến khi sẵn sàng (giống email).

```
Đồng bộ:
Service A → request → Service B → response → Service A (chờ)

Bất đồng bộ:
Service A → message → Queue → Service B (lấy khi sẵn sàng)
```

## 🟡 Middle Level

### Đồng Bộ

**HTTP/REST:**
```java
ResponseEntity<User> response = restTemplate.getForEntity(
    "http://user-service/users/{id}", User.class, userId);
```

**gRPC:**
```java
UserResponse user = userServiceBlocking.getUser(UserRequest.newBuilder()
    .setUserId(userId).build());
```

**Ưu điểm:**
- Đơn giản
- Response tức thì

**Nhược điểm:**
- Cascading failure
- Coupling tạm thời

### Bất Đồng Bộ

**Kafka:**
```java
kafkaTemplate.send("user-events", event); // Trả về Future/ListenableFuture
// Có thể chờ xác nhận từ broker, nhưng thường là fire-and-forget.
```

**Ưu điểm:**
- Fault tolerance
- Khả năng mở rộng

**Nhược điểm:**
- Eventual consistency
- Khó debug hơn

### Các Lỗi Thường Gặp

1. **Đồng bộ cho các thao tác chạy lâu:**
```
HTTP request 30 giây → timeout
Giải pháp: async + polling/webhook
```

## 🔴 Senior Level

### Đánh Đổi Kiến Trúc

| Đồng bộ                                              | Bất đồng bộ                                                                             |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Strong consistency                                  | Eventual consistency                                                                     |
| Đơn giản hơn                                             | Fault-tolerant hơn                                                                      |
| Ít độ trễ hơn: gọi trực tiếp, không có overhead broker.      | Throughput cao hơn: broker đệm các request, consumer xử lý theo tốc độ riêng của nó.            |
| Cascading failure                                  | Đệm (buffering)                                                                                |

### Kinh Nghiệm Production

**Cách tiếp cận kết hợp:**
```
Đồng bộ: đọc dữ liệu (read)
Bất đồng bộ: các event, command (write)
```

### Best Practices

```
// Nếu dùng async cho dữ liệu quan trọng (payment):
// bạn sẽ không biết kết quả ngay lập tức — người dùng phải chờ.
// Cần polling hoặc callback, điều này làm phức tạp UX.
✅ Đồng bộ cho các thao tác đọc đơn giản
✅ Bất đồng bộ cho các event và command
✅ Circuit Breaker cho các call sync
✅ Idempotency cho các message async

❌ Chuỗi sync > 2 service
❌ Async cho dữ liệu quan trọng
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Đồng bộ: gửi → chờ response (giống cuộc gọi điện thoại), strong consistency, ít độ trễ hơn
- Bất đồng bộ: gửi → quên đi, response đến khi sẵn sàng (giống email), eventual consistency
- Đồng bộ: HTTP/REST, gRPC — đơn giản hơn, nhưng nguy cơ cascade failure
- Bất đồng bộ: Kafka, RabbitMQ — fault-tolerant hơn, đệm cho các đợt tăng traffic
- Cách tiếp cận kết hợp: sync cho đọc, async cho ghi/event
- Đồng bộ cho dữ liệu quan trọng (payment) — người dùng chờ kết quả
- Bất đồng bộ cho dữ liệu quan trọng khó hơn: cần polling/callback

**Các câu hỏi phụ thường gặp:**
- **Khi nào chọn đồng bộ?** Các thao tác đọc đơn giản, cần response tức thì, < 2 service trong chuỗi.
- **Khi nào chọn bất đồng bộ?** Các event, command (write), tác vụ nền, tải cao.
- **Tại sao cascade failure trong sync?** A→B→C→D, D sập → tất cả bị treo → phản ứng dây chuyền.
- **Thundering herd là gì?** Nhiều client retry đồng thời — cần jitter.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Đồng bộ luôn nhanh hơn" — đúng, cho các trường hợp đơn giản, nhưng cascade failure có thể làm nó chậm hơn
- "Bất đồng bộ = fire and forget" — không, cần monitoring và xử lý lỗi
- "Chuỗi sync 5 service là ổn" — không, nguy cơ cascade failure
- "Bất đồng bộ cho thanh toán" — phức tạp, người dùng phải chờ

# What is the First-Level Cache in Hibernate (First-level cache trong Hibernate là gì)

## Overview

First-level cache (L1 cache) là một cache tích hợp sẵn ở cấp độ EntityManager/Session. Đây là một phần nền tảng của Hibernate và cung cấp identity của entity, dirty checking, và tối ưu truy vấn.

**Tại sao:** L1 cache giải quyết ba vấn đề: (1) Đảm bảo identity - một ID = một object trong bộ nhớ; (2) Dirty checking - cần lưu một snapshot để so sánh; (3) Tối ưu - find() lặp lại không thực hiện SELECT.

---

## Junior Level

### L1 Cache Là Gì

First-level cache là một cache bên trong `EntityManager` (session). Tất cả các entity đã tải được lưu trữ trong đó tự động.

```java
// Request đầu tiên - SELECT từ DB
User user1 = entityManager.find(User.class, 1L);
// SQL: SELECT * FROM users WHERE id = 1

// Request thứ hai - từ cache, KHÔNG có SELECT!
User user2 = entityManager.find(User.class, 1L);
// SQL: (không có truy vấn!)

assert user1 == user2;  // true - cùng một object trong bộ nhớ
```

### Các Đặc Tính Chính

- Bật **theo mặc định**, không thể tắt
- Tồn tại trong phạm vi **một session/transaction**
- Tự động xóa khi EntityManager đóng
- Cung cấp **đảm bảo identity** (một ID = một object). Nếu bạn tải User(1) hai lần trong một transaction, Hibernate trả về CÙNG MỘT object trong bộ nhớ (user1 == user2). Điều này cần thiết để dirty checking hoạt động đúng - nếu không, các thay đổi trên một object có thể xung đột với object khác.

### Khi Nào Nó Kích Hoạt

```java
// find() - kiểm tra cache trước khi truy vấn DB
User user1 = entityManager.find(User.class, 1L);  // SELECT
User user2 = entityManager.find(User.class, 1L);  // từ cache

// persist() - thêm vào cache
User newUser = new User();
entityManager.persist(newUser);  // trong cache

// merge() - thêm bản sao đã cập nhật vào cache
User managed = entityManager.merge(detachedUser);  // trong cache
```

## Middle Level

### Khi Nào L1 Cache Có Hại

1. **Tải 10k+ entity trong một transaction** - OutOfMemoryError
2. **Streaming dữ liệu lớn** - dùng ScrollableResults
3. **Các thao tác batch** - dùng StatelessSession

### Dirty Checking Thông Qua L1 Cache

```java
// Hibernate lưu snapshot khi tải
User user = entityManager.find(User.class, 1L);  // snapshot được tạo

// Thay đổi một trường
user.setName("New Name");

// Khi commit/flush - Hibernate so sánh snapshot với trạng thái hiện tại
// Nếu khác nhau - tự động thực hiện UPDATE
// Không cần entityManager.merge() rõ ràng!
```

### Quản Lý Cache

```java
// Xóa toàn bộ cache
entityManager.clear();
// Tất cả entity trở thành detached

// Loại bỏ entity cụ thể khỏi cache
entityManager.detach(user);
// user trở thành detached, các cái khác vẫn giữ nguyên

// Tải lại từ DB (cập nhật cache)
entityManager.refresh(user);
// SELECT từ DB, snapshot được cập nhật

// Kiểm tra sự có mặt trong cache
boolean isManaged = entityManager.contains(user);
```

### Vấn Đề Lớn Của L1 Cache

```java
// Đã tải 100k entity -> OutOfMemoryError!
for (Long id : allIds) {
    entityManager.find(User.class, id);  // tất cả trong cache
}

// Giải pháp: dọn dẹp định kỳ
for (int i = 0; i < allIds.size(); i++) {
    entityManager.find(User.class, allIds.get(i));

    if (i % 100 == 0) {
        entityManager.flush();   // flush vào DB
        entityManager.clear();   // xóa cache
    }
}
```

### Các Lỗi Thường Gặp

```java
// Transaction sống lâu với cache lớn
@Transactional
public void processAll() {
    List<User> users = userRepository.findAll();  // 50k user
    for (User user : users) {
        process(user);  // L1 cache tăng lên
    }
    // OutOfMemoryError!
}

// Giải pháp: xử lý theo batch
@Transactional
public void processAll() {
    List<User> users = userRepository.findAll();
    for (int i = 0; i < users.size(); i++) {
        process(users.get(i));
        if (i % 100 == 0) {
            entityManager.flush();
            entityManager.clear();
        }
    }
}
```

## Senior Level

### L1 Cache vs Map<String, User> Thủ Công

Khác với một Map thủ công, L1 cache:
(1) tự động được điền vào ở bất kỳ truy vấn nào;
(2) cung cấp đảm bảo identity;
(3) lưu trữ snapshot cho dirty checking;
(4) tự động xóa khi EntityManager đóng.

### Triển Khai Nội Bộ

```
StatefulPersistenceContext {
    // Map<EntityKey, Entity> - cache theo ID
    entitiesByKey: Map<EntityKey, Object>

    // Map<Object, EntityEntry> - theo dõi trạng thái
    entityEntries: Map<Object, EntityEntry>
}

EntityEntry chứa:
- loadedState - snapshot khi tải
- status - MANAGED, DELETED, READ_ONLY
- id - định danh
- version - cho optimistic locking
```

### Thuật Toán find()

```
entityManager.find(User.class, 1L):

1. Tạo EntityKey(User, 1L)
2. Kiểm tra entitiesByKey.containsKey(key)
   -> Có: trả về object từ cache (KHÔNG có SQL)
   -> Không: thực thi SELECT
3. Kết quả SELECT -> tạo object
4. Thêm vào entitiesByKey
5. Tạo EntityEntry với snapshot
6. Trả về object
```

### Read-Only Hint Để Tối Ưu

```java
// Cho các entity sẽ không bị sửa đổi
List<User> users = entityManager.createQuery("FROM User", User.class)
    .setHint("org.hibernate.readOnly", true)
    .getResultList();

// Nếu bạn sửa đổi một entity read-only, dirty checking sẽ KHÔNG phát hiện thay đổi
// và UPDATE sẽ không được thực thi. Hibernate đơn giản bỏ qua các thay đổi.

// Ưu điểm:
// 1. Không tạo snapshot (tiết kiệm bộ nhớ)
// 2. Dirty checking không thực thi
// 3. Ít overhead flush hơn
```

### Đặc Tính Hiệu Năng

```
Overhead của L1 Cache:
- O(1) cho find() (tra cứu HashMap)
- O(N) cho dirty checking (duyệt qua tất cả entity)
- O(N) bộ nhớ (lưu snapshot cho mỗi entity)

Cho các thao tác lớn:
- flush() + clear() mỗi 50-100 entity
- read-only hint khi không cần sửa đổi
- StatelessSession cho các thao tác bulk
```

### Best Practices

```
L1 cache hoạt động theo mặc định
entityManager.clear() cho các thao tác batch
entityManager.detach() cho các object riêng lẻ
refresh() để tải lại DB
read-only hint cho các truy vấn chỉ đọc
flush + clear mỗi 50-100 entity trong batch

Tải một số lượng lớn entity mà không có clear
Bỏ qua OutOfMemoryError trong các thao tác lớn
Transaction sống lâu với cache lớn
Dùng L1 cache như một cache liên request
```

## Interview Cheat Sheet

**Cần phải biết:**
- L1 cache - cache tích hợp sẵn của EntityManager, bật theo mặc định, không thể tắt
- Giải quyết 3 vấn đề: đảm bảo identity, dirty checking (snapshot), tối ưu truy vấn
- find() kiểm tra cache trước khi truy vấn DB - find() lặp lại không có SQL
- Tồn tại trong một transaction, được xóa khi EntityManager đóng
- Khi tải 10k+ entity - OutOfMemoryError, cần clear()
- Read-only hint tiết kiệm bộ nhớ (không tạo snapshot)

**Các câu hỏi phụ thường gặp:**
- **L1 cache có thể tắt được không?** Không, đó là một phần nền tảng của Hibernate
- **Tại sao find() lặp lại không thực hiện SELECT?** Object đã có trong Map entitiesByKey
- **Cách tránh OOM trong batch?** flush() + clear() mỗi 50-100 entity
- **L1 cache vs Map thủ công?** L1 cache tự động điền, cung cấp đảm bảo identity, lưu snapshot

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi dùng L1 cache như một cache liên request" - nó chỉ tồn tại trong một session
- "Tôi tắt L1 cache để tăng hiệu năng" - không thể tắt được
- "Tôi tải 100k entity mà không có clear" - OutOfMemoryError
- "L1 cache thay thế L2 cache" - các cấp độ khác nhau với mục đích khác nhau

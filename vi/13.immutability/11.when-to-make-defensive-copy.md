# When should you make a defensive copy? (Khi nào nên tạo defensive copy?)

---

## Basic Level

Một defensive copy nên được tạo khi class của bạn nhận hoặc đưa ra dữ liệu **mutable** từ/đến ai đó.

### Khi Nào Nên Tạo Bản Sao

**1. Khi nhận dữ liệu (trong constructor)**
```java
// Với một class hoàn toàn bất biến không có setter.
// Ví dụ này cho thấy Builder pattern hoặc constructor với việc sao chép:
public class MyClass {
    private final List<String> items;

    public MyClass(List<String> items) {
        this.items = new ArrayList<>(items); // defensive copy trong constructor
    }
}
```

**2. Khi trả về dữ liệu (trong getter)**
```java
public List<String> getItems() {
    return new ArrayList<>(items); // bản sao của dữ liệu ra
}
```

### Khi Bạn KHÔNG Cần Tạo Bản Sao

- Các kiểu nguyên thủy (`int`, `boolean`) — chúng bất biến
- `String` — bất biến
- Dữ liệu nội bộ không bao giờ rời khỏi class

---

## Intermediate Level

### Các Kịch Bản Chính

**A. Mảng**
```java
public class MyClass {
    private final int[] numbers;

    public MyClass(int[] numbers) {
        this.numbers = numbers.clone(); // hoặc Arrays.copyOf(numbers)
    }

    public int[] getNumbers() {
        return numbers.clone();
    }
}
```

**B. Collection**
```java
this.list = List.copyOf(input);        // Java 10+
this.list = new ArrayList<>(input);    // Java 8
```

**C. Date**
```java
this.date = new Date(date.getTime());
```

### Khi Nào Sao Chép KHÔNG Cần Thiết

1. **Các kiểu bất biến** — `String`, `BigDecimal`, `LocalDate`, `Integer`
2. **Dữ liệu private** — object được tạo bên trong class và không bao giờ rời khỏi nó
3. **Transfer Object** — nếu class theo thiết kế là một DTO mutable
4. **Mutable DTO / Builder pattern** — các object mutable theo thiết kế
5. **Các kiểu nguyên thủy và wrapper** (int, Integer, String) — bất biến theo bản chất

### Copy vs Unmodifiable

- **Trong constructor** — chỉ **Copy** (`new ArrayList(original)`)
- **Trong getter** — có thể là **Copy** hoặc **Unmodifiable** (`Collections.unmodifiableList(original)`)

// List.copyOf ném NPE với các phần tử null, new ArrayList — cho phép chúng.

## Advanced Level

### TOCTOU Và Thứ Tự Thao Tác

Sao chép **trước** khi validate:
```java
public SecureConfig(Map<String, String> config) {
    Map<String, String> copy = new HashMap<>(config); // sao chép trước
    if (!copy.containsKey("auth")) throw new IllegalStateException(); // sau đó kiểm tra
    this.config = Map.copyOf(copy);
}
```
Không có điều này, trong môi trường đa luồng, map có thể thay đổi sau khi kiểm tra nhưng trước khi lưu.

### Hiệu Năng

- `List.copyOf()` — được tối ưu hóa trong JDK 10+, có thể trả về cùng object nếu đầu vào đã bất biến rồi
- Với các collection lớn trong vòng lặp hot, cân nhắc các **cấu trúc dữ liệu persistent** (Vavr)
- Tránh deep copy các đồ thị object khổng lồ

### Tóm Tắt Cho Advanced
- Sao chép mọi thứ có thể bị thay đổi từ bên ngoài
- Sao chép trước, sau đó validate
- Dùng `List.copyOf()` cho defensive copy hiện đại
- Đừng sao chép các mảng khổng lồ trong các vòng lặp "hot" khi không cần thiết
- Phân biệt wrapper và copy: wrapper không bảo vệ khỏi các thay đổi đến bản gốc

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Sao chép khi nhận (constructor) và khi trả về (getter) dữ liệu mutable
- KHÔNG cần sao chép: các kiểu nguyên thủy, String, LocalDate, Integer, dữ liệu private
- Mảng: `numbers.clone()` hoặc `Arrays.copyOf()`
- Collection: `List.copyOf(input)` (Java 10+) hoặc `new ArrayList<>(input)` (Java 8)
- Date: `new Date(date.getTime())`
- Copy vs Unmodifiable: trong constructor — chỉ Copy, trong getter — Copy hoặc Unmodifiable
- TOCTOU: sao chép trước, sau đó validate

**Các câu hỏi phụ thường gặp:**
- *Khi nào KHÔNG cần sao chép?* — Các kiểu bất biến, dữ liệu private, Transfer Object
- *List.copyOf vs new ArrayList?* — List.copyOf trả về bất biến; new ArrayList — mutable
- *Điều gì nếu collection khổng lồ?* — Cân nhắc các cấu trúc persistent (Vavr) hoặc COW
- *List.copyOf có cho phép null không?* — Không, ném NPE; new ArrayList cho phép

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Defensive copy cần thiết cho mọi kiểu" — các kiểu nguyên thủy và String không cần
- "Bạn có thể mutate một mutable key trong HashMap" — object bị thất lạc trong bucket
- "UnmodifiableList trong constructor — bảo vệ" — đó là một wrapper, không phải một bản sao
- "Sao chép sau khi validate — an toàn" — cuộc tấn công TOCTOU có thể xảy ra

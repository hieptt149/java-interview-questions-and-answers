## Các kết nối chủ đề then chốt

### Chủ đề: Đồng bộ hóa (Synchronization)

```
Q1 (synchronized vs volatile) → Q4 (Monitor) → Q5 (synchronized internals)
     ↓                                ↓                     ↓
Q3 (Visibility)              Q6 (method vs block)   Q7 (ReentrantLock)
```

**Các kết nối then chốt:**
- Q1 ↔ Q3: volatile giải quyết vấn đề visibility, nhưng KHÔNG giải quyết atomicity
- Q4 ↔ Q5: monitor là khái niệm, synchronized là hiện thực
- Q5 ↔ Q7: synchronized → ReentrantLock (tiến hóa từ mức ngôn ngữ sang mức thư viện)
- Q6 ↔ Q7: synchronized block = ReentrantLock.lock/unlock

### Chủ đề: Lock-Free

```
Q9 (CAS) → Q8 (các lớp Atomic) → Q10 (AtomicInteger/Long)
     ↓                               ↓
     └──────────────────────→ Q11 (vs synchronized)
```

**Các kết nối then chốt:**
- Q9 ↔ Q10: AtomicInteger = wrapper bọc quanh CAS
- Q8 ↔ Q11: Atomic vs synchronized — cách tiếp cận lạc quan vs bi quan
- Q9 ↔ Q18: CAS phòng ngừa deadlock (không blocking), nhưng không phòng ngừa race condition

### Chủ đề: Các vấn đề đa luồng

```
Q18 (Deadlock) → Q19 (các điều kiện Coffman) → Q20 (Phòng ngừa)
Q21 (Race condition) → Q22 (Tránh)
```

**Các kết nối then chốt:**
- Q18 ↔ Q21: Deadlock = các thread chờ nhau, Race = kết quả phụ thuộc vào thứ tự
- Q19 ↔ Q20: Phá vỡ một điều kiện Coffman → deadlock trở nên không thể
- Q21 ↔ Q3: Các race condition thường do các vấn đề visibility gây ra

### Chủ đề: Thread Pool

```
Q12 (Thread Pool) → Q13 (Các loại) → Q15 (ExecutorService)
     ↓                    ↓              ↓
Q16 (Fixed vs Cached)  Q17 (ForkJoin)  Q16 (so sánh)
```

**Các kết nối then chốt:**
- Q12 ↔ Q13: Khái niệm pool → các hiện thực cụ thể
- Q15 ↔ Q16: ExecutorService → các factory cụ thể (Fixed, Cached)
- Q17 ↔ Q13: ForkJoinPool = WorkStealingPool cho chia để trị

### Chủ đề: Java 21+ (Tương lai)

```
Q23 (Virtual Threads) → Q24 (Ưu điểm) → Q25 (Khi nào dùng)
     ↓
```

**Các kết nối then chốt:**

## Tóm tắt: Cần biết gì ở mỗi cấp độ

### Junior
- synchronized = khóa, volatile = visibility
- Thread được tạo qua Runnable (kết hợp, không phải kế thừa)
- Callable trả về một kết quả, Runnable thì không
- Deadlock = hai thread chờ nhau mãi mãi
- Race condition = kết quả phụ thuộc vào thứ tự thực thi thread
- Thread Pool tái sử dụng các thread, tiết kiệm bộ nhớ và thời gian

### Middle
- happens-before: program order, volatile, monitor, start/join, tính bắc cầu
- Monitor: No Lock → Thin Lock → Fat Lock, Mark Word, ObjectMonitor
- ReentrantLock: AQS, fair vs non-fair, Condition (tương đương wait/notify)
- CAS: cách tiếp cận lạc quan, chu kỳ retry, vấn đề ABA → AtomicStampedReference
- Thread Pool: Fixed (tải đã biết), Cached (tác vụ ngắn), Scheduled (định kỳ)
- Phòng ngừa deadlock: lock ordering, tryLock(timeout), một khóa duy nhất
- AtomicInteger: chu kỳ CAS, lazySet, LongAdder cho tranh chấp cao

### Senior
- synchronized internals: biased (gỡ bỏ ở Java 21), thin (CAS spin), fat (OS park)
- JIT: lock elision (escape analysis), lock coarsening
- CAS: lock cmpxchg (x86), memory barrier, đảm bảo tiến triển (wait-free > lock-free > obstruction-free)
- Virtual Threads: StackChunk, carrier thread, unmount khi I/O, pinning (synchronized chặn carrier!)
- Structured Concurrency: ShutdownOnFailure/Success, thời gian sống của scope, preview API
- ThreadPool sizing: CPU-bound = số lõi + 1, I/O-bound = số lõi × (1 + W/S)
- ForkJoinPool: deque work-stealing, LIFO cho owner/FIFO cho thief, các nguy hiểm của commonPool

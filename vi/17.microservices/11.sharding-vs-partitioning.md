# What is the difference between sharding and partitioning (Sự khác biệt giữa sharding và partitioning là gì)

## Junior Level

Cả hai đều chia dữ liệu, nhưng **ở các cấp độ khác nhau**:

- **Partitioning** — chia **trong một database duy nhất** trên một server
- **Sharding** — chia **qua các server khác nhau**

```
Partitioning (một DB):
Table -> Partition 1 (2023)
      -> Partition 2 (2024)
      -> Partition 3 (2025)

Sharding (nhiều server):
DB -> Shard 1 (Server 1)
   -> Shard 2 (Server 2)
   -> Shard 3 (Server 3)
```

---

## Middle Level

### Partitioning

```sql
-- PostgreSQL range partitioning
-- PARTITION BY RANGE — PostgreSQL chia table thành các phần về mặt vật lý.
-- Mỗi partition lưu dữ liệu riêng của nó, nhưng về mặt logic đó là một table.
CREATE TABLE orders (
    id BIGINT,
    created_at DATE
) PARTITION BY RANGE (created_at);

CREATE TABLE orders_2024 PARTITION OF orders
    FOR VALUES FROM ('2024-01-01') TO ('2025-01-01');

CREATE TABLE orders_2025 PARTITION OF orders
    FOR VALUES FROM ('2025-01-01') TO ('2026-01-01');
```
// Một truy vấn WHERE created_at = '2023-06-15' không khớp với partition nào cả!
// Cần một partition mặc định hoặc xử lý lỗi.

### Sharding

```
MongoDB:
sh.shardCollection("db.orders", { user_id: "hashed" })

Cassandra:
Sharding tự động theo partition key
```

### So Sánh

| Partitioning              | Sharding               |
| ------------------------ | ---------------------- |
| Một server                | Nhiều server           |
| Một database               | Nhiều database          |
| Đơn giản hơn                  | Phức tạp hơn            |
| Cho tối ưu truy vấn        | Cho scaling             |

## Senior Level

### Khi Nào Dùng Cái Gì

Nếu table vừa trong bộ nhớ và các truy vấn nhanh — không cần partitioning cũng không cần sharding.

**Partitioning:**
```
✅ Table lớn, một server
✅ Tối ưu truy vấn theo ngày
✅ Lưu trữ dữ liệu cũ
```

**Sharding:**
```
✅ Một server không đủ
✅ Cần horizontal scaling
✅ Dữ liệu không vừa trên một server
```

### Best Practices

```
✅ Partitioning để tối ưu
✅ Sharding để scaling
✅ Bắt đầu với partitioning
✅ Shard khi bạn đạt giới hạn

❌ Sharding mà không cần thiết
❌ Các truy vấn cross-shard phức tạp
```

## Interview Cheat Sheet

**Cần phải biết:**
- Partitioning — chia trong MỘT database trên một server
- Sharding — chia qua các server KHÁC NHAU
- Partitioning để tối ưu truy vấn, sharding để scaling
- Bắt đầu với partitioning — đơn giản hơn, ít overhead hơn
- PostgreSQL hỗ trợ PARTITION BY RANGE/LIST/HASH
- MongoDB/Cassandra hỗ trợ sharding tự động
- Nếu table vừa trong RAM và các truy vấn nhanh — không cần cái nào

**Các câu hỏi phụ thường gặp:**
- **Khi nào partitioning?** Table lớn, một server, tối ưu theo ngày, lưu trữ.
- **Khi nào sharding?** Một server không đủ, dữ liệu không vừa, cần horizontal scaling.
- **Có thể kết hợp chúng không?** Có — partitioning trong một shard.
- **PostgreSQL partitioning hoạt động như thế nào?** PARTITION BY RANGE/LIST — chia vật lý, logic là một table.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Partitioning và sharding là cùng một thứ" — không, các cấp độ khác nhau
- "Sharding luôn tốt hơn" — không, phức tạp và tốn kém hơn
- "Partitioning giải quyết vấn đề scaling" — không, chỉ giới hạn của một server
- "Cần sharding ngay từ đầu" — không, bắt đầu khi bạn đạt giới hạn

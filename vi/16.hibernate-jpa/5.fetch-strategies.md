# What Fetch Strategies Exist in Hibernate (Những fetch strategy nào tồn tại trong Hibernate)

## Overview

Fetch strategy xác định **cách** Hibernate tải các entity liên quan từ database.

FetchType (JPA) nói về "khi nào" - ngay lập tức hay khi truy cập. FetchMode (Hibernate) nói về "cách nào" - trong một truy vấn, riêng biệt, hay theo batch. Hiểu về fetch strategy là chìa khóa để tối ưu hiệu năng và ngăn ngừa các vấn đề như N+1.

---

## Junior Level

### Các Chiến Lược Cơ Bản

Hibernate cung cấp **4 fetch strategy**:

1. **SELECT** - truy vấn riêng biệt khi truy cập association (mặc định cho LAZY)
2. **JOIN** - một truy vấn duy nhất với JOIN (mặc định cho EAGER)
3. **SUBSELECT** - subquery cho một collection
4. **BATCH** - tải theo batch nhiều entity

Quan trọng: BATCH không phải là một FetchMode, mà là một cơ chế riêng biệt thông qua `@BatchSize`.
Phân loại thực tế:
- FetchMode (đặc thù Hibernate): SELECT, JOIN, SUBSELECT
- Cơ chế riêng biệt: @BatchSize (tải theo batch)
- Động: EntityGraph (chuẩn JPA)

```java
// SELECT - truy vấn riêng biệt khi truy cập
@OneToMany(fetch = FetchType.LAZY)
@Fetch(FetchMode.SELECT)
private List<OrderItem> items;

// JOIN - một truy vấn duy nhất với JOIN
@OneToMany(fetch = FetchType.EAGER)
@Fetch(FetchMode.JOIN)
private List<OrderItem> items;

// SUBSELECT - subquery cho collection
@OneToMany(mappedBy = "order")
@Fetch(FetchMode.SUBSELECT)
private List<OrderItem> items;
```

### Sự Khác Biệt Giữa FetchType Và FetchMode

|              | FetchType (JPA) | @Fetch (Hibernate)      |
| ------------ | --------------- | ----------------------- |
| **Chuẩn**    | Chuẩn JPA       | Đặc thù Hibernate       |
| **Giá trị**  | LAZY, EAGER     | SELECT, JOIN, SUBSELECT |
| **Khi nào**  | Khi nào tải     | Cách nào để tải          |

## Middle Level

### Mô Tả Chi Tiết FetchMode

#### SELECT

```java
@Fetch(FetchMode.SELECT)
// SELECT riêng biệt cho mỗi entity
// Tải 10 Order -> 10 SELECT cho items
// Gây ra N+1 problem!
```

#### JOIN

```java
@Fetch(FetchMode.JOIN)
// Một truy vấn duy nhất với JOIN
// SELECT o.*, i.* FROM orders o JOIN order_items i ON o.id = i.order_id

// Quan trọng: JOIN bỏ qua FetchType.LAZY!
// Ngay cả khi LAZY được chỉ định, nó vẫn tải ngay lập tức
// Trong Hibernate 5.x JOIN bỏ qua LAZY. Trong Hibernate 6+ hành vi được tinh chỉnh, nhưng để đảm bảo lazy hãy dùng JOIN FETCH trong JPQL.
```

#### SUBSELECT

```java
@Fetch(FetchMode.SUBSELECT)
// Một subquery cho toàn bộ collection
// SELECT * FROM order_items WHERE order_id IN (SELECT id FROM orders)

// Hữu ích khi nhiều entity parent được tải
// SUBSELECT chỉ hoạt động nếu các entity parent được tải trong một truy vấn duy nhất.
// Nếu tải từng cái một - Hibernate rơi lại về SELECT.
```

### Các Ví Dụ Thực Tế

```java
@Entity
public class Order {

    // LAZY + SELECT = N+1 (xấu)
    @OneToMany(mappedBy = "order", fetch = FetchType.LAZY)
    @Fetch(FetchMode.SELECT)
    private List<OrderItem> items;

    // LAZY + JOIN = luôn JOIN (bỏ qua LAZY)
    @OneToMany(mappedBy = "order", fetch = FetchType.LAZY)
    @Fetch(FetchMode.JOIN)
    private List<OrderItem> items;

    // LAZY + SUBSELECT = một subquery
    @OneToMany(mappedBy = "order", fetch = FetchType.LAZY)
    @Fetch(FetchMode.SUBSELECT)
    private List<OrderItem> items;
}
```

### Các Lỗi Thường Gặp

```java
// FetchMode.JOIN bỏ qua LAZY
@Fetch(FetchMode.JOIN)
@OneToMany(fetch = FetchType.LAZY)
// Vẫn tải ngay lập tức thông qua JOIN

// Dùng mà không hiểu hậu quả
@Fetch(FetchMode.SUBSELECT)
@ManyToOne
// SUBSELECT chỉ hợp lý cho các collection
```

## Senior Level

### Triển Khai Nội Bộ

Khi có xung đột, FetchMode ghi đè FetchType. LAZY + JOIN = vẫn JOIN. Đây là một lỗi thường gặp.

```
FetchMode.JOIN:
- Khi tải entity, ngay lập tức thực hiện LEFT/INNER JOIN
- Hoàn toàn bỏ qua FetchType.LAZY
- Kết quả: tất cả entity liên quan được tải
- Phù hợp khi association cần thiết 100% thời gian

FetchMode.SELECT:
- Ở lần truy cập proxy đầu tiên
- Thực thi SELECT WHERE foreign_key = ?
- Truy vấn riêng biệt cho mỗi entity
- Gây ra N+1 problem

FetchMode.SUBSELECT:
- Thu thập tất cả ID của các entity đã tải
- Một truy vấn: WHERE parent_id IN (id1, id2, ...)
- Hiệu quả cho các collection parent nhỏ
```

### Cấu Hình Toàn Cục

```yaml
# application.yml
spring:
  jpa:
    properties:
      hibernate:
        # Batch size toàn cục cho tất cả association LAZY
        default_batch_fetch_size: 50

        # Hoặc thông qua annotation Hibernate
        # @BatchSize(size = 50) ở cấp độ class/collection
```

### Các Chiến Lược Nâng Cao

#### Batch fetching (cách tiếp cận khuyến nghị)

```java
@OneToMany(mappedBy = "order")
@BatchSize(size = 25)
private List<OrderItem> items;

// Thay vì 100 truy vấn -> 4 truy vấn (100/25)
// Hibernate: SELECT * FROM order_items WHERE order_id IN (?, ..., ?) -- 25 ID
```

#### Tải Động Thông Qua EntityGraph

```java
// EntityGraph tĩnh
@NamedEntityGraph(
    name = "Order.withItems",
    attributeNodes = @NamedAttributeNode("items")
)
@Entity
public class Order { }

// Cách dùng
EntityGraph<Order> graph = entityManager.getEntityGraph("Order.withItems");
List<Order> orders = entityManager.createQuery("SELECT o FROM Order o", Order.class)
    .setHint("jakarta.persistence.fetchgraph", graph)
    .getResultList();
```

### So Sánh Các Cách Tiếp Cận

| Chiến lược  | Số truy vấn | Linh hoạt  | Khi nào dùng                              |
| ----------- | ----------- | ---------- | ---------------------------------------- |
| SELECT      | N+1         | Không      | Khi association không cần (LAZY mặc định) |
| JOIN        | 1           | Không      | Association luôn cần thiết                |
| SUBSELECT   | 1           | Không      | Ít parent                                 |
| BATCH       | N/batchSize | Có         | Collection                                |
| EntityGraph | 1           | Có         | Tải động                                  |
| JOIN FETCH  | 1           | Có         | Truy vấn JPQL                             |

### Best Practices

```
@BatchSize cho collection (10-50)
LAZY + JOIN FETCH trong truy vấn JPQL
EntityGraph để tải động
SUBSELECT cho các trường hợp hiếm

FetchMode.JOIN mà không có lý do (bỏ qua LAZY)
FetchMode.SELECT (gây ra N+1)
Trộn EAGER + JOIN
EAGER toàn cục mà không cần thiết
```

## Interview Cheat Sheet

**Cần phải biết:**
- FetchType (JPA): LAZY, EAGER - xác định "khi nào" tải
- FetchMode (Hibernate): SELECT, JOIN, SUBSELECT - xác định "cách nào" để tải
- FetchMode.JOIN bỏ qua LAZY - lỗi thường gặp
- @BatchSize - cơ chế riêng biệt, không phải FetchMode, tải theo batch
- EntityGraph - tải động, cách tiếp cận linh hoạt nhất
- Khi xung đột, FetchMode ghi đè FetchType

**Các câu hỏi phụ thường gặp:**
- **Sự khác biệt FetchType vs FetchMode?** FetchType - chuẩn JPA (khi nào), FetchMode - đặc thù Hibernate (cách nào)
- **Tại sao FetchMode.JOIN bỏ qua LAZY?** JOIN thực hiện ngay một JOIN trong SQL, LAZY không thể hoạt động
- **SUBSELECT là gì?** Một subquery cho tất cả parent đã tải: WHERE parent_id IN (SELECT id FROM parents)
- **Khi nào dùng EntityGraph?** Khi cần chọn động cái gì cần tải trong các kịch bản khác nhau

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "FetchMode.JOIN + LAZY = lazy loading" - JOIN bỏ qua LAZY
- "Tôi dùng FetchMode.SELECT theo mặc định" - gây ra N+1
- "@BatchSize là một FetchMode" - đó là một cơ chế riêng biệt
- "EAGER + JOIN là kết hợp tốt nhất" - antipattern

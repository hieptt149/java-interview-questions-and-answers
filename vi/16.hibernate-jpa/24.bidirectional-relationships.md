# What Are the Peculiarities of Bidirectional Relationships (Những đặc điểm riêng của các mối quan hệ hai chiều là gì)

## Overview

Các mối quan hệ hai chiều (bidirectional) cho phép điều hướng giữa các entity theo cả hai hướng. Chúng yêu cầu đồng bộ thủ công cả hai phía và dùng đúng `mappedBy`.

---

## Junior Level

### Mối Quan Hệ Hai Chiều Là Gì

Đây là một mối quan hệ trong đó **cả hai phía** biết về nhau.

```java
// Order biết về User
@Entity
public class Order {
    @ManyToOne
    private User user;
}

// User biết về Orders
@Entity
public class User {
    @OneToMany(mappedBy = "user")
    private List<Order> orders;
}
```

### Phía Owner Và Phía Inverse

**Phía owner** - phía có FK (Order với `@ManyToOne`).

**Phía inverse** - phía có `mappedBy` (User với `@OneToMany(mappedBy = "user")`).

```java
// Owner - chứa @JoinColumn
@ManyToOne
@JoinColumn(name = "user_id")
private User user;

// Inverse - chứa mappedBy
@OneToMany(mappedBy = "user")
private List<Order> orders;
```

## Middle Level

### Đồng Bộ Là Bắt Buộc

```java
@Entity
public class User {
    @OneToMany(mappedBy = "user", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Order> orders = new ArrayList<>();

    // Phương thức helper - bắt buộc!
    public void addOrder(Order order) {
        orders.add(order);
        order.setUser(this);  // BẮT BUỘC!
    }

    public void removeOrder(Order order) {
        orders.remove(order);
        order.setUser(null);  // BẮT BUỘC!
    }
}
```

### Tại Sao Mất Đồng Bộ Là Một Vấn Đề

```java
// Mất đồng bộ
User user = new User();
Order order = new Order();
user.getOrders().add(order);

// order.getUser() == null -> FK không được đặt!
entityManager.persist(user);  // Với cascade=ALL order được lưu,
// nhưng order.getUser() = null -> cột FK = NULL -> vi phạm ràng buộc hoặc UPDATE thừa

// Đồng bộ thông qua helper
User user = new User();
Order order = new Order();
user.addOrder(order);  // setter + setUser

// order.getUser() == user -> FK được đặt
entityManager.persist(user);  // cascade -> order được lưu
```

### Các Lỗi Thường Gặp

```java
// Mất đồng bộ
user.getOrders().add(order);
// order.user == null -> FK không được đặt

// mappedBy ở phía owner
@ManyToOne(mappedBy = "orders")  // mappedBy chỉ ở phía inverse
private User user;

// Không có phương thức helper
order.setUser(user);
// user.orders không chứa order -> không nhất quán
```

## Senior Level

### equals/hashCode Cho Bidirectional

```java
// Dùng business key, KHÔNG phải ID!
@Entity
public class User {
    @Column(unique = true, nullable = false)
    private String email;  // business key

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof User)) return false;
        User user = (User) o;
        return email != null && email.equals(user.email);
    }

    @Override
    public int hashCode() {
        return email != null ? email.hashCode() : 0;
    }
}
```

### Tại Sao Không Dùng ID Cho equals/hashCode

```java
// ID cho equals/hashCode - các vấn đề
@Entity
public class User {
    @Id
    @GeneratedValue
    private Long id;

    @Override
    public boolean equals(Object o) {
        if (!(o instanceof User)) return false;
        return id != null && id.equals(((User) o).id);
    }
}

// Các vấn đề:
// 1. Entity transient (id=null) != Entity transient (id=null)
// 2. HashSet mất entity sau persist (id thay đổi)
// 3. Không thể thêm vào HashSet trước persist
```

**Nếu không có business/natural key:** dùng UUID, được gán khi tạo object.
```java
public class User {
    private final UUID uuid = UUID.randomUUID();
    // equals/hashCode theo uuid
}
```

### Business Key Pattern

```java
@Entity
public class OrderItem {
    @Id
    @GeneratedValue
    private Long id;

    @Column(nullable = false)
    private String sku;  // business key

    @ManyToOne
    private Order order;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof OrderItem)) return false;
        OrderItem that = (OrderItem) o;
        return sku != null && sku.equals(that.sku);
    }

    @Override
    public int hashCode() {
        return sku != null ? sku.hashCode() : 0;
    }
}
```

### Đồng Bộ Nâng Cao

```java
@Entity
public class Order {
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();

    public void addItem(OrderItem item) {
        items.add(item);
        item.setOrder(this);
    }

    public void removeItem(OrderItem item) {
        if (items.remove(item)) {
            item.setOrder(null);  // quan trọng cho tính nhất quán
        }
    }

    // Để thay thế
    public void replaceItems(List<OrderItem> newItems) {
        items.clear();  // orphanRemoval xóa cái cũ
        for (OrderItem item : newItems) {
            addItem(item);
        }
    }
}
```

### Các Cân Nhắc Về Hiệu Năng

```
Overhead của bidirectional:
- Phương thức helper (tối thiểu)
- Bộ nhớ cho cả hai tham chiếu
- Đồng bộ khi thay đổi

Lợi ích:
- Điều hướng theo cả hai hướng
- Cascade với orphanRemoval
- Domain model hoàn chỉnh
```

### Best Practices

```
Phương thức helper để đồng bộ
Business key cho equals/hashCode
mappedBy ở phía inverse
Đồng bộ cả hai phía
Khởi tạo các collection

ID cho equals/hashCode
Không có phương thức helper
mappedBy ở phía owner
Mất đồng bộ
Sửa đổi collection trực tiếp
```

## Interview Cheat Sheet

**Cần phải biết:**
- Bidirectional = điều hướng theo cả hai hướng, yêu cầu đồng bộ cả hai phía
- Phía owner - có FK (@ManyToOne), Phía inverse - có mappedBy (@OneToMany)
- Phương thức helper BẮT BUỘC: addOrder/addItem đồng bộ cả hai phía
- equals/hashCode theo business key (email, SKU), KHÔNG theo ID - ID thay đổi khi persist
- Cho equals/hashCode không có business key - dùng UUID khi tạo object
- mappedBy chỉ ở phía inverse - không tồn tại ở phía owner

**Các câu hỏi phụ thường gặp:**
- **Tại sao ID xấu cho equals/hashCode?** Entity transient (id=null) != Entity transient, HashSet mất entity sau persist
- **Điều gì nếu mất đồng bộ?** FK không được đặt hoặc NULL - vi phạm ràng buộc hoặc UPDATE thừa
- **Điều gì nếu không có business key?** UUID khi tạo object - định danh ổn định trước persist
- **Overhead hiệu năng của bidirectional?** Tối thiểu: phương thức helper + bộ nhớ cho tham chiếu, lợi ích vượt quá chi phí

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "ID cho equals/hashCode" - vấn đề HashSet/HashMap, mất entity
- "Không có phương thức helper" - mất đồng bộ, FK không được đặt
- "Sửa đổi collection trực tiếp" - bỏ qua phương thức helper -> không nhất quán
- "mappedBy ở phía owner" - không tồn tại, chỉ ở phía inverse

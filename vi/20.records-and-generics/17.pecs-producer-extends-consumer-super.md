# What Is PECS (Producer Extends Consumer Super)? (PECS (Producer Extends Consumer Super) là gì)

## 🟢 Junior Level

**PECS** là một quy tắc ghi nhớ (mnemonic) để làm việc với wildcard trong Java generics:

- **P**roducer **E**xtends — nếu bạn cần **đọc** dữ liệu, dùng `? extends T`
- **C**onsumer **S**uper — nếu bạn cần **ghi** dữ liệu, dùng `? super T`

```java
// Producer Extends — chỉ đọc
List<? extends Number> numbers = List.of(1, 2, 3);
Number n = numbers.get(0);  // ✅ có thể đọc
// numbers.add(4);  // ❌ không thể ghi

// Consumer Super — chỉ ghi
List<? super Integer> integers = new ArrayList<>();
integers.add(42);  // ✅ có thể ghi
// Integer i = integers.get(0);  // ❌ không thể đọc (chỉ Object)
```

**Analogy đơn giản:**
- **Producer** (nhà cung cấp) — cho dữ liệu → `extends`
- **Consumer** (người tiêu thụ) — nhận dữ liệu → `super`

## 🟡 Middle Level

### Cách Hoạt Động

**Producer Extends:**
```java
// Đọc từ nguồn — đây là producer
public static double sum(List<? extends Number> source) {
    return source.stream()
        .mapToDouble(Number::doubleValue)  // ✅ có thể đọc Number
        .sum();
}

List<Integer> ints = List.of(1, 2, 3);
List<Double> doubles = List.of(1.5, 2.5);

sum(ints);     // ✅ Integer extends Number
sum(doubles);  // ✅ Double extends Number
```

**Consumer Super:**
```java
// Ghi vào target — đây là consumer
public static void addNumbers(List<? super Integer> target, int count) {
    for (int i = 0; i < count; i++) {
        target.add(i);  // ✅ có thể ghi Integer
    }
}

List<Integer> ints = new ArrayList<>();
List<Number> numbers = new ArrayList<>();
List<Object> objects = new ArrayList<>();

addNumbers(ints, 3);     // ✅ Integer super Integer
addNumbers(numbers, 3);  // ✅ Number super Integer
addNumbers(objects, 3);  // ✅ Object super Integer
```

### Quy Tắc PECS Đầy Đủ

```java
// Cả producer VÀ consumer — không có wildcard
public static <T> void copy(List<T> dest, List<T> src) {
    dest.addAll(src);  // cả đọc và ghi
}

// Chữ ký đúng (như trong JDK Collections.max):
public static <T extends Comparable<? super T>> T max(Collection<? extends T> coll)
// ? super T cho phép compareTo được kế thừa từ một lớp cha.

// Chỉ consumer — super
public static <T> void fill(List<? super T> list, T value, int count) {
    for (int i = 0; i < count; i++) {
        list.add(value);
    }
}
```

### Các Lỗi Thường Gặp

1. **Nhầm lẫn hướng:**
```java
// ❌ Sai
List<? super Number> numbers = List.of(1, 2, 3);  // lỗi
// numbers.get(0);  // chỉ có thể lấy Object

// ✅ Đúng — producer dùng extends
List<? extends Number> numbers = List.of(1, 2, 3);
Number n = numbers.get(0);  // ✅
```

2. **Cả hai hướng — không cần wildcard:**
```java
// ❌ Vô dụng
public void process(List<? extends T> list) {
    list.add(item);  // ❌ không thể
}

// ✅ Nếu bạn cần cả đọc và ghi — không dùng wildcard
public <T> void process(List<T> list) {
    list.add(list.get(0));  // ✅ mọi thứ hoạt động
}
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Kiểm tra compile-time:**
```java
List<? extends Number> extendsList = new ArrayList<Integer>();
List<? super Number> superList = new ArrayList<Object>();

// Extends — trình biên dịch biết bound dưới
Number n1 = extendsList.get(0);  // ✅ Number — tối thiểu
// extendsList.add(42);  // ❌ kiểu không xác định

// Super — trình biên dịch biết bound trên
superList.add(42);  // ✅ Number chắc chắn phù hợp
Object o = superList.get(0);  // ✅ Object — tối đa
```

**Capture conversion:**
```java
// Đảo ngược một list — cả đọc và ghi
public static <T> void reverse(List<T> list) {
    int size = list.size();
    for (int i = 0; i < size / 2; i++) {
        T temp = list.get(i);
        list.set(i, list.get(size - 1 - i));
        list.set(size - 1 - i, temp);
    }
}

// Không thể dùng wildcard — cần cả đọc và ghi
// reverse(List<? extends T>) — không thể set
// reverse(List<? super T>) — không thể lấy kiểu cụ thể
```

### Đánh Đổi Kiến Trúc

| Tình huống           | Wildcard      | Đọc   | Ghi     |
| ------------------- | ------------- | ------ | --------- |
| **Chỉ đọc**       | `? extends T` | ✅ T    | ❌         |
| **Chỉ ghi**      | `? super T`   | Object | ✅ T       |
| **Cả hai**            | `<T>`         | ✅ T    | ✅ T       |
| **Kiểu không xác định**    | `?`           | Object | chỉ null |

### Edge Cases

**1. PECS lồng nhau:**
```java
// Comparator — consumer
Comparator<? super T> comparator

// Factory — producer
public static <T> List<T> produce(List<? extends T> source) {
    return new ArrayList<>(source);
}

// Kết hợp
public static <T> void sort(List<T> list, Comparator<? super T> comp) {
    list.sort(comp);  // list — cả đọc/ghi, comp — consumer
}
```

**2. Stream API:**
```java
// Collector<T, A, R> — A là accumulator (consumer)
public static <T> Collector<T, ?, List<T>> toList() {
    return Collectors.toList();
}

// ? — kiểu accumulator không xác định (chi tiết triển khai)
```

**3. Interface functional:**
```java
// Function — producer (trả về R)
Function<? super T, ? extends R>

// Consumer — consumer (nhận T)
Consumer<? super T>

// Supplier — producer (trả về T)
Supplier<? extends T>
```

### Hiệu Năng

```
PECS:
- Runtime: Overhead bằng không
- Compile time: kiểm tra kiểu nghiêm ngặt
- An toàn: ngăn ClassCastException

Hiệu năng giống nhau cho tất cả các kiểu wildcard
```

### Kinh Nghiệm Production

**Ví dụ từ JDK:**

```java
// Collections.copy — PECS kinh điển
public static <T> void copy(
    List<? super T> dest,      // consumer — ghi T
    List<? extends T> src      // producer — đọc T
) {
    Iterator<? extends T> si = src.iterator();
    for (int i = 0; i < src.size(); i++) {
        dest.set(i, si.next());
    }
}

// Stream.collect
public final class Stream<T> {
    public <R, A> R collect(
        Collector<? super T, A, R> collector  // T — consumer
    ) { }
}

// Optional.orElseGet
public T orElseGet(Supplier<? extends T> supplier) {  // T — producer
    return value != null ? value : supplier.get();
}
```

**Trường hợp thực tế:**
```java
// Pattern Repository
public interface Repository<T> {
    // Producer — trả về dữ liệu
    Optional<? extends T> findById(Long id);
    List<? extends T> findAll();

    // Consumer — nhận dữ liệu
    void save(T entity);
    void saveAll(List<? extends T> entities);
}

// Event Publisher
public class EventPublisher<T extends Event> {
    private final List<Consumer<? super T>> listeners = new ArrayList<>();

    public void subscribe(Consumer<? super T> listener) {
        listeners.add(listener);  // consumer
    }

    public void publish(T event) {
        listeners.forEach(l -> l.accept(event));
    }
}
```

### Best Practices

```java
// ✅ PECS để linh hoạt tối đa
public static <T> void copy(List<? super T> dest, List<? extends T> src) { }

// ✅ Producer để đọc
public double sum(List<? extends Number> numbers) { }

// ✅ Consumer để ghi
public void fill(List<? super Integer> list, int value) { }

// ✅ Cả hai — không dùng wildcard
public <T> void swap(List<T> list, int i, int j) { }

// ❌ Extends để ghi
// ❌ Super để đọc một kiểu cụ thể
// ❌ Wildcard khi bạn cần cả đọc và ghi
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- PECS: **P**roducer **E**xtends — đọc dữ liệu, **C**onsumer **S**uper — ghi dữ liệu
- `List<? extends Number>` — producer: đọc dưới dạng Number, cấm ghi
- `List<? super Integer>` — consumer: ghi Integer, chỉ đọc dưới dạng Object
- Khi bạn cần cả đọc và ghi — dùng `<T>`, không dùng wildcard
- Ví dụ từ JDK: `Collections.copy(List<? super T>, List<? extends T>)`, `Collections.max(Collection<? extends T>)`
- PECS — use-site variance, khác với `out T` / `in T` của Kotlin (declaration-site)

**Các câu hỏi phụ thường gặp:**
- **Cho một ví dụ PECS từ JDK?** — `Collections.copy(dest, src)`, `Stream.collect(Collector)`
- **Khi nào KHÔNG cần wildcard?** — Khi phương thức vừa đọc vừa ghi (swap, reverse)
- **PECS lồng nhau là gì?** — `Function<? super T, ? extends R>` — T consumer, R producer
- **Có thể thêm null vào List<? extends T> không?** — Có, null hợp lệ cho bất kỳ kiểu nào

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "PECS ngăn ClassCastException tại runtime" — Đó là kiểm tra compile-time
- ❌ "Extends cho phép ghi kiểu con" — Extends cấm ghi hoàn toàn
- ❌ "Super cho phép đọc dưới dạng T" — Super chỉ cho phép đọc dưới dạng Object
- ❌ "PECS là một design pattern" — Đó là một quy tắc ghi nhớ cho wildcard

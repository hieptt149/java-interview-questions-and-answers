# What Cascade Types Exist (Những loại Cascade nào tồn tại)

## Overview

JPA cung cấp một số loại thao tác cascade, mỗi loại kiểm soát việc truyền một loại thao tác cụ thể đến các entity liên quan. Chọn đúng loại cascade là chìa khóa để làm việc đúng đắn với object graph.

---

## Junior Level

### Tất Cả Các Loại CascadeType

```java
CascadeType.ALL       - tất cả thao tác (persist, merge, remove, refresh, detach)
CascadeType.PERSIST   - khi persist(parent) -> persist(child)
CascadeType.MERGE     - khi merge(parent) -> merge(child)
CascadeType.REMOVE    - khi remove(parent) -> remove(child)
CascadeType.REFRESH   - khi refresh(parent) -> refresh(child)
CascadeType.DETACH    - khi detach(parent) -> detach(child)
```

### Ví Dụ Từng Loại

```java
// PERSIST - lưu cùng với child
@OneToMany(cascade = CascadeType.PERSIST)
private List<OrderItem> items;

entityManager.persist(order);  // -> persist cho tất cả items

// MERGE - cập nhật cùng với child
@OneToMany(cascade = CascadeType.MERGE)
private List<OrderItem> items;

entityManager.merge(order);  // -> merge cho tất cả items

// REMOVE - xóa cùng với child
@OneToMany(cascade = CascadeType.REMOVE)
private List<OrderItem> items;

entityManager.remove(order);  // -> remove cho tất cả items

// ALL - tất cả thao tác
@OneToMany(cascade = CascadeType.ALL)
private List<OrderItem> items;
```

### Khi Nào KHÔNG Nên Dùng Cascade Hoàn Toàn

Đừng dùng cascade khi cả hai entity là aggregate root với vòng đời riêng. Ví dụ, `Order` và `Customer` là các aggregate riêng biệt, cascade giữa chúng nguy hiểm.

## Middle Level

### Khi Nào Dùng Cái Gì

```
@OneToMany (composite):  CascadeType.ALL + orphanRemoval = true
@ManyToOne:              CascadeType.PERSIST, MERGE (hoặc không có cascade)
@OneToOne:               CascadeType.ALL
@ManyToMany:             CascadeType.PERSIST, MERGE
```

### Composite vs Association

```java
// Composite - child không tồn tại nếu không có parent
@Entity
public class Order {
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderItem> items;  // OrderItem không có Order thì không có ý nghĩa
}

// Association - các entity độc lập
@Entity
public class Order {
    @ManyToOne  // không có cascade
    private User user;  // User tồn tại độc lập với Order
}
```

### Các Lỗi Thường Gặp

```java
// Cascade.REMOVE cho các entity dùng chung
@ManyToOne(cascade = CascadeType.REMOVE)
private User user;

entityManager.remove(order);  // User cũng bị xóa!

// Cascade.ALL cho @ManyToOne
@ManyToOne(cascade = CascadeType.ALL)
private Category category;

entityManager.remove(product);  // Category bị xóa!

// Không có cascade cho entity dùng chung
@ManyToOne
private User user;  // User được quản lý riêng biệt
```

## Senior Level

### Các Kịch Bản Nâng Cao

```java
// Kịch bản 1: Cascade PERSIST + MERGE cho @ManyToOne
@Entity
public class Order {
    @ManyToOne(cascade = {CascadeType.PERSIST, CascadeType.MERGE})
    // Code smell: cascade từ Order sang User - entity dùng chung.
    // Có thể vô tình tạo ra các user trùng lặp.
    // Cascade PERSIST/MERGE từ child sang parent là một antipattern.
    private User user;
}

// User mới sẽ được lưu cùng với Order
User newUser = new User();
Order order = new Order();
order.setUser(newUser);
entityManager.persist(order);  // -> persist User, persist Order

// User đã tồn tại sẽ được merge
order.setUser(existingUser);
entityManager.merge(order);  // -> merge User, merge Order
```

### Cascading Và Validation

```java
@Entity
public class Order {
    @Valid  // Bean Validation cascade. @Valid là Hibernate Validator (đặc thù Hibernate), không phải chuẩn JPA. Validation kích hoạt khi persist/merge.
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL)
    private List<OrderItem> items;
}

// Khi persist/merge - validation cho tất cả items
entityManager.persist(order);  // -> validation cho Order + tất cả items
```

### Các Pattern Production

```java
// Pattern 1: Order -> OrderItem (composite)
@Entity
public class Order {
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();

    public void addItem(OrderItem item) {
        items.add(item);
        item.setOrder(this);
    }
}

// Pattern 2: Order -> User (dùng chung)
@Entity
public class Order {
    @ManyToOne  // không có cascade
    private User user;
}

// Pattern 3: User -> Address (composite)
@Entity
public class User {
    @OneToMany(mappedBy = "user", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Address> addresses = new ArrayList<>();
}
```

### Ma Trận Quyết Định

| Association             | Cascade        | orphanRemoval   | Tại Sao                          |
| ---------------------- | -------------- | --------------- | ------------------------------- |
| @OneToMany (composite)  | ALL            | true            | Child không tồn tại nếu không có parent |
| @ManyToOne (dùng chung) | PERSIST, MERGE | false           | Entity được quản lý riêng biệt     |
| @OneToOne (composite)   | ALL            | true            | One-to-one, composition          |
| @ManyToMany             | PERSIST, MERGE | false           | Entity dùng chung, nguy hiểm khi xóa |

### Best Practices

```
ALL cho các child composite
PERSIST, MERGE cho entity dùng chung
Không có REMOVE cho entity dùng chung
orphanRemoval cho các child composite
Ma trận quyết định cho mỗi association

REMOVE cho entity dùng chung
ALL cho @ManyToOne
Cascade.REMOVE trong Many-to-Many
Không hiểu sự khác biệt composite/association
```

## Interview Cheat Sheet

**Cần phải biết:**
- 6 loại CascadeType: ALL, PERSIST, MERGE, REMOVE, REFRESH, DETACH
- ALL - tất cả thao tác, nhưng nguy hiểm cho @ManyToOne và Many-to-Many
- Composition (Order -> OrderItem): CascadeType.ALL + orphanRemoval = true
- Association (Order -> User): PERSIST, MERGE hoặc không có cascade
- @ManyToOne với cascade PERSIST/MERGE từ child sang parent - antipattern (trùng lặp)
- Ma trận quyết định: mỗi association có cascade riêng, không phổ quát

**Các câu hỏi phụ thường gặp:**
- **Tại sao @ManyToOne với cascade là code smell?** Cascade từ Order sang User có thể tạo ra các user trùng lặp
- **Composite vs association là gì?** Composite - child không tồn tại nếu không có parent (OrderItem), association - các entity độc lập (User)
- **Các loại cascade có thể kết hợp không?** Có: cascade = {CascadeType.PERSIST, CascadeType.MERGE}
- **Khi nào hoàn toàn không cần cascade?** Khi các entity được quản lý riêng biệt thông qua repository riêng của chúng

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "CascadeType.ALL cho tất cả association" - REMOVE xóa các entity dùng chung
- "Cascade.REMOVE cho @ManyToOne" - xóa Order xóa User
- "Cascade.ALL cho Many-to-Many" - xóa Author xóa tất cả Book
- "Tôi không hiểu sự khác biệt composite/association" - quan trọng để chọn cascade

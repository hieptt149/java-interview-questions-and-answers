# What is Docker Compose? (Docker Compose là gì?)

## Junior Level

### Giải Thích Đơn Giản

**Docker Compose** là một công cụ để định nghĩa và chạy các ứng dụng đa container. Bạn mô tả toàn bộ hạ tầng (service, network, volume) trong một file YAML duy nhất. Nếu Docker quản lý các container riêng lẻ, Docker Compose quản lý một **hệ thống** các container liên kết với nhau.

### Phép So Sánh

Docker giống như việc quản lý các nhạc công riêng lẻ. Docker Compose giống như một nhạc trưởng dàn nhạc: nó biết ai vào khi nào, chơi to như thế nào, và các nhạc công nghe nhau ra sao.

### Ví Dụ docker-compose.yml

```yaml
version: "3.8"

services:
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      - DATABASE_URL=jdbc:postgresql://db:5432/mydb
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:15
    environment:
      - POSTGRES_DB=mydb
      - POSTGRES_USER=admin
      - POSTGRES_PASSWORD=secret
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U admin"]
      interval: 5s
      timeout: 3s
      retries: 5

# Healthcheck — kiểm tra định kỳ xem service bên trong container có còn sống
# (không chỉ đang chạy, mà còn đang chấp nhận kết nối).

volumes:
  postgres_data:
```

### Các Lệnh Chính

| Lệnh                          | Nó làm gì                              |
| -------------------------------- | ----------------------------------------- |
| `docker compose up -d`           | Khởi động tất cả các service trong nền          |
| `docker compose down`            | Dừng và loại bỏ các container và network   |
| `docker compose logs -f`         | Log của tất cả các service theo thời gian thực          |
| `docker compose exec app bash`   | Vào một container đang chạy                 |
| `docker compose ps`              | Hiển thị các service đang chạy                     |

### Cần Nhớ

- Docker Compose mô tả toàn bộ hạ tầng trong một file YAML
- Một lệnh `docker compose up` đưa toàn bộ ứng dụng lên
- Các service giao tiếp với nhau qua tên thông qua một network nội bộ
- Các volume giữ dữ liệu tồn tại qua các lần restart
- Lý tưởng cho phát triển local

## Middle Level

### Các Tính Năng Chính

- **Tính khai báo (Declarativity)** — bạn mô tả trạng thái mong muốn trong `docker-compose.yml`.
- **Cô lập môi trường** — một network riêng biệt được tạo cho mỗi dự án, cho phép nhiều bản sao chạy mà không xung đột port.
- **Quản lý dependency** — `depends_on` với `condition: service_healthy` chờ DB sẵn sàng.
- **Tính bền vững dữ liệu** — các volume cho việc lưu trữ dữ liệu DB lâu dài.

Compose tốt hơn vì: một lệnh duy nhất thay vì N lệnh docker run,
network hóa tự động giữa các service, mô tả khai báo thay vì các lệnh mệnh lệnh (imperative).

### Cấu Trúc File YAML

```yaml
version: "3.8"

services:        # Các container ứng dụng
  app:
    build: .
    ports: ["8080:8080"]
    environment:
      DATABASE_URL: jdbc:postgresql://db:5432/mydb
    depends_on:
      db: { condition: service_healthy }  # chờ DB sẵn sàng, không chỉ container khởi động
    networks: [app-network]

  db:
    image: postgres:15
    volumes: [postgres_data:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready"]
      interval: 5s
    networks: [app-network]

networks:        # Các network để service giao tiếp
  app-network:
    driver: bridge

volumes:         # Bộ nhớ ngoài
  postgres_data:
```

### Các Lỗi Thường Gặp

| Lỗi                        | Hậu quả                                | Cách tránh                                                  |
| ------------------------------ | ------------------------------------------ | --------------------------------------------------------------- |
| `depends_on` không có healthcheck | Ứng dụng khởi động trước khi DB sẵn sàng            | Dùng `condition: service_healthy`                              |
| Mật khẩu hardcode trong YAML    | Rò rỉ secret trong git                      | Dùng các file `.env`                                              |
| Không có chính sách `restart`            | Container không restart khi crash         | `restart: unless-stopped`                                     |
| Xung đột port trên host         | "Port already in use"                      | Dùng port khác hoặc không có `ports` cho các service nội bộ       |
| Quên `networks`          | Tất cả các service trên network mặc định, không cô lập | Tạo một network riêng biệt                                   |

### Khi Nào KHÔNG Nên Dùng Docker Compose

ĐỪNG dùng Compose cho: production với >1 server, yêu cầu deploy không downtime,
scaling ngang, self-healing. Cho những trường hợp này — dùng Kubernetes.

### Docker Compose Trong Development vs Production

- **Trong development** — công cụ lý tưởng. Với một lệnh, một developer đưa lên backend, frontend, Postgres, Redis, và Kafka.
- **Trong production** — chỉ dùng cho các dự án nhỏ trên một server duy nhất. Với các hệ thống có thể scale, các orchestrator được dùng (Kubernetes, Docker Swarm, Nomad).

### Các Tính Năng Hữu Ích

1. **Environment Variables** — hỗ trợ các file `.env` để lưu trữ cài đặt.
2. **Profile (v3.9+)** — chỉ chạy một phần của các service: `docker compose --profile monitoring up`.
3. **Healthcheck** — Compose chờ DB sẵn sàng hoàn toàn trước khi khởi động các service phụ thuộc.
4. **Override file** — `docker-compose.override.yml` cho các cài đặt local trên nền file chính.

### Cần Nhớ

- Docker Compose là một trong những công cụ phổ biến nhất cho phát triển local (các lựa chọn thay thế: script docker run, devcontainer, Tilt, Okteto)
- Tự động hóa việc cấu hình các kết nối giữa các microservice
- Đừng lưu mật khẩu trong các file YAML, hãy dùng `.env`
- Để deploy hãy dùng Helm chart hoặc manifest K8s
- `depends_on` không có healthcheck không đảm bảo thứ tự sẵn sàng

## Senior Level

### Docker Compose Như Một Công Cụ Kiến Trúc

Docker Compose không chỉ là "khởi chạy tiện lợi" — nó là một **mô tả khai báo về topology của hệ thống microservice**. Nó định nghĩa: các service nào tồn tại, chúng được kết nối như thế nào, dữ liệu nào là lâu dài, service discovery hoạt động ra sao.

### Cách Hoạt Động Bên Trong

Docker Compose không phải là một daemon. Nó:
1. Phân tích `docker-compose.yml` và xây dựng một đồ thị dependency
2. Chuyển đổi mô hình compose thành các lời gọi Docker API (tạo network → tạo volume → tạo container → khởi động)
3. Với `depends_on` và healthcheck — poll trạng thái health trước khi khởi động các service phụ thuộc
4. Tạo một Docker network với DNS nhúng sẵn — các service phân giải lẫn nhau theo tên

### Đánh Đổi (Trade-offs)

| Khía cạnh             | Docker Compose                       | Kubernetes                  |
| ------------------ | ------------------------------------ | --------------------------- |
| Độ phức tạp         | Thấp (YAML + 1 lệnh)               | Cao (nhiều object)         |
| Scaling            | Thủ công (`docker compose up --scale`) | Tự động (HPA)             |
| Self-healing       | Không                                   | Có                         |
| Rolling update    | Không                                   | Có                         |
| Service discovery  | DNS trong network compose           | kube-proxy + CoreDNS        |
| Multi-node         | Không (một host duy nhất)                     | Có                         |
| Đường cong học tập     | Vài giờ                                | Vài tuần/tháng                |

### Edge Case

- **`depends_on` không chờ sẵn sàng theo mặc định**: `depends_on` chỉ đảm bảo thứ tự **khởi động** của các container, không phải thứ tự **sẵn sàng**. Service DB có thể đã khởi động nhưng chưa chấp nhận kết nối. Giải pháp: `condition: service_healthy` + healthcheck.
- **Phân giải tên network**: Compose tạo một network với DNS. Service `db` phân giải thành `db`. Nhưng nếu `docker compose up` chạy từ các thư mục khác nhau, các network là khác nhau — `db` trong dự án A ≠ `db` trong dự án B.
- **Đặt tên volume**: `postgres_data` trong Compose nhận một tiền tố dự án: `myproject_postgres_data`. Điều này có thể phá vỡ các migration khi đổi tên dự án.
- **Giới hạn tài nguyên**: Compose v3 hỗ trợ `deploy.resources`, nhưng chỉ cho Docker Swarm. Với Docker standalone, dùng cú pháp v2 `mem_limit`, `cpus`.
- **Đường dẫn Windows**: trên Windows các volume được mount qua CIFS/SMB. Vấn đề với permission, hiệu năng (đặc biệt với nhiều file nhỏ), symlink.

### Cách Tiếp Cận Production Cho Các Hệ Thống Nhỏ

```yaml
version: "3.8"

services:
  app:
    image: myregistry.com/app:${APP_VERSION:-latest}  # ghim phiên bản
    restart: unless-stopped
    deploy:
      resources:
        limits:
          cpus: "2"
          memory: 1G
        reservations:
          cpus: "0.5"
          memory: 512M
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - DATABASE_URL=jdbc:postgresql://db:5432/mydb
    depends_on:
      db: { condition: service_healthy }
    networks: [app-net]
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"

  db:
    image: postgres:15.4-alpine
    restart: unless-stopped
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U admin"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s
    networks: [app-net]

volumes:
  postgres_data:
    driver: local

networks:
  app-net:
    driver: bridge
```

### Bảo Mật

- **Đừng lưu secret trong YAML** — dùng các file `.env` được thêm vào `.gitignore`.
- **Docker secrets** — cho chế độ Swarm: `echo "password" | docker secret create db_pass -`.
- **Container chỉ đọc** — `read_only: true` + `tmpfs` cho các file tạm.
- **User non-root** — `user: "1000:1000"` trong định nghĩa service.
- **Cô lập network** — các network riêng biệt cho các service frontend/backend.

### Hiệu Năng

| Chỉ số                      | Compose (một host)          | Kubernetes (cluster)        |
| --------------------------- | ------------------------------- | --------------------------- |
| Số service tối đa                | ~50-100 (giới hạn host)           | Hàng nghìn                   |
| Thời gian khởi động tất cả service   | 10-60s                         | 1-5 phút               |
| Tiêu thụ RAM             | Tối thiểu (chỉ container)      | 500MB+ (thành phần hệ thống)  |
| Overhead network            | Bridge network, tối thiểu        | kube-proxy, CNI overlay     |

### Di Chuyển Compose → Kubernetes

Các công cụ chuyển đổi tồn tại:
- **Kompose** — `kompose convert -f docker-compose.yml` → manifest K8s
- **Docker Compose for K8s** (thử nghiệm) — `docker compose up` trực tiếp vào K8s
- **Okteto** — phát triển trong K8s với trải nghiệm giống Compose

Nhưng chuyển đổi tự động không mang lại manifest K8s sẵn sàng cho production. Bạn cần cấu hình thủ công: HPA, PDB, ingress, liveness/readiness probe, resource quota.

### Câu Chuyện Production

Một startup 5 developer dùng Docker Compose cho production trên một VPS duy nhất (8 CPU, 16GB RAM). Ứng dụng: 6 microservice + PostgreSQL + Redis + Nginx. Nó chạy ổn định trong 18 tháng. Khi lưu lượng tăng 10 lần, Compose không còn đủ nữa: không có scaling ngang, không có rolling update, không có self-healing. Di chuyển sang Kubernetes mất 3 tuần nhưng mang lại: scaling tự động dưới tải, deploy không downtime, tự động phục hồi khi crash. Compose vẫn được giữ lại cho phát triển local — như "tài liệu khởi chạy."

### Monitoring

- `docker compose ps` — trạng thái service
- `docker compose top` — các process trong container
- `docker stats` — CPU/RAM/network theo thời gian thực
- Tổng hợp log: `driver: json-file` + fluentd/Fluentbit cho logging tập trung
- Trạng thái healthcheck: `docker compose ps` hiển thị các service unhealthy

### Tóm Tắt

- Docker Compose là tiêu chuẩn cho phát triển local và tạo prototype.
- Cho phép tự động hóa việc cấu hình các kết nối giữa các microservice.
- `depends_on` không có healthcheck không đảm bảo thứ tự sẵn sàng — một lỗi nghiêm trọng.
- Chấp nhận được cho production trên một server duy nhất, nhưng có giới hạn (không scaling, không self-healing).
- Trong các hệ thống lớn — Compose như "tài liệu khởi chạy local", để deploy — K8s.
- Bảo mật: `.env` cho secret, user non-root, filesystem chỉ đọc.

## Interview Cheat Sheet

**Cần phải biết:**
- Docker Compose — khởi chạy khai báo các ứng dụng đa container từ một file YAML duy nhất
- Các service giao tiếp qua network nội bộ theo tên (DNS nhúng sẵn)
- `depends_on` không có `condition: service_healthy` chỉ đảm bảo thứ tự khởi động, không phải sẵn sàng
- Các volume đảm bảo tính bền vững dữ liệu qua các lần restart container
- Compose là tiêu chuẩn cho phát triển local; cho production — Kubernetes
- Các override file (`docker-compose.override.yml`) cho cài đặt local
- Kompose chuyển đổi Compose → manifest K8s (nhưng không sẵn sàng cho production)

**Các câu hỏi phụ thường gặp:**
- *"Tại sao depends_on không có healthcheck là không đủ?"* — Container DB đã khởi động, nhưng chưa chấp nhận kết nối
- *"Các service tìm nhau như thế nào?"* — Compose tạo một network với DNS; service `db` phân giải thành `db`
- *"Compose có thể dùng trong production không?"* — Có, cho các dự án nhỏ trên một server duy nhất (không có HA, scaling)
- *"Profile trong Compose là gì?"* — Cho phép chỉ chạy một phần của các service (`--profile monitoring`)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Compose thay thế Kubernetes" (không có HA, self-healing, rolling update)
- "Tôi lưu mật khẩu trực tiếp trong docker-compose.yml" (dùng .env, Docker secrets)
- "depends_on đảm bảo DB đã sẵn sàng" (chỉ đảm bảo thứ tự khởi động)
- "Compose hoạt động trên nhiều server" (chỉ một host duy nhất)

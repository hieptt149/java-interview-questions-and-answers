# What Is the Difference Between thenApply() and thenApplyAsync()? (Sự khác biệt giữa thenApply() và thenApplyAsync() là gì)

## 🟢 Junior Level

Cả hai phương thức đều biến đổi kết quả của một CompletableFuture, nhưng **ở các thread khác nhau**:

- **`thenApply()`** — thực thi trong **cùng thread** đã hoàn thành CF trước
- **`thenApplyAsync()`** — thực thi trong **một thread khác** (ForkJoinPool hoặc Executor được chỉ định)

```java
CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> {
    System.out.println("Supply: " + Thread.currentThread().getName());
    return "Hello";
});

// thenApply — cùng thread
cf.thenApply(s -> {
    System.out.println("thenApply: " + Thread.currentThread().getName());
    return s + " World";
});

// thenApplyAsync — thread khác (ForkJoinPool)
cf.thenApplyAsync(s -> {
    System.out.println("thenApplyAsync: " + Thread.currentThread().getName());
    return s + " World";
});
```

## 🟡 Middle Level

### Khi Nào Dùng Cái Nào

**thenApply — cho các thao tác nhẹ:**
```java
// Biến đổi nhẹ — không cần thiết phải chuyển thread
cf.thenApply(s -> s.toUpperCase())
  .thenApply(s -> s.trim())
  .thenAccept(System.out::println);
```

**thenApplyAsync — cho các thao tác nặng:**
```java
// Xử lý nặng — tốt hơn nên ở thread khác
cf.thenApplyAsync(s -> heavyProcessing(s), executor)
  .thenAccept(System.out::println);
```

**Với Executor tùy chỉnh:**
```java
ExecutorService executor = Executors.newFixedThreadPool(10);

cf.thenApplyAsync(s -> transform(s), executor);
```

### Các Lỗi Thường Gặp

1. **thenApplyAsync không có Executor:**
```java
// Dùng ForkJoinPool.commonPool()
cf.thenApplyAsync(s -> s.toUpperCase());

// ⚠️ commonPool có số lượng thread hạn chế
// Đối với thao tác I/O — xấu

// ✅ Executor tùy chỉnh
cf.thenApplyAsync(s -> s.toUpperCase(), ioExecutor);
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**thenApply:**
```java
public <U> CompletableFuture<U> thenApply(Function<? super T,? extends U> fn) {
    return uniApplyStage(null, fn);
}

// Thực thi trong thread đã hoàn thành CF trước
// Không chuyển thread — overhead tối thiểu
```

**thenApplyAsync:**
```java
public <U> CompletableFuture<U> thenApplyAsync(Function<? super T,? extends U> fn) {
    return uniApplyStage(asyncPool, fn);  // asyncPool = ForkJoinPool.commonPool()
}

public <U> CompletableFuture<U> thenApplyAsync(
    Function<? super T,? extends U> fn, Executor executor
) {
    return uniApplyStage(screenExecutor(executor), fn);
}

// asyncPool — thread từ ForkJoinPool.commonPool()
// hoặc executor được chỉ định
```

### Đánh Đổi Kiến Trúc

| thenApply                  | thenApplyAsync          |
| -------------------------- | ----------------------- |
| Cùng thread                | Thread khác        |
| Overhead ~5 ns             | Overhead ~1μs           |
| Cho thao tác nhẹ | Cho thao tác nặng/chặn      |
| Không chuyển ngữ cảnh          | Chuyển thread           |

### Edge Cases

**1. ThreadLocal:**
```java
// thenApply — ThreadLocal được giữ nguyên
ThreadLocal<String> context = new ThreadLocal<>();
context.set("value");

cf.thenApply(s -> {
    String ctx = context.get();  // OK — cùng thread
    return s + ctx;
});

// thenApplyAsync — ThreadLocal bị mất
cf.thenApplyAsync(s -> {
    String ctx = context.get();  // null! — thread khác
    return s;
});
```

**2. Thao tác chặn:**
```java
// ❌ thenApply với một thao tác chặn
cf.thenApply(s -> {
    Thread.sleep(1000);  // chặn thread ForkJoinPool!
    return s;
});

// ✅ thenApplyAsync với một Executor riêng biệt
cf.thenApplyAsync(s -> {
    Thread.sleep(1000);
    return s;
}, ioExecutor);
```

### Hiệu Năng

```
thenApply:
- Overhead: ~5 ns
- Không chuyển thread

thenApplyAsync (commonPool):
- Overhead: ~1μs
- Chuyển thread + hàng đợi

thenApplyAsync (custom executor):
- Overhead: ~2-5μs
- Chuyển thread + hàng đợi

Đối với các thao tác nhẹ: thenApply nhanh hơn đáng kể so với thenApplyAsync
(không có overhead lập lịch), nhưng tỷ lệ chính xác phụ thuộc vào JVM, tải, và phần cứng.
```

### Khi Nào KHÔNG Nên Dùng thenApplyAsync

- **Ngữ cảnh ThreadLocal** — Async có thể chuyển thread, ThreadLocal bị mất
- **Biến đổi đơn giản** (getLength, toString) — overhead lập lịch > lợi ích

### Kinh Nghiệm Production

**Pipeline:**
```java
// thenApply cho các biến đổi nhẹ
fetchDataAsync()
    .thenApply(data -> parseJson(data))       // nhẹ
    .thenApply(obj -> validate(obj))          // nhẹ
    .thenApplyAsync(valid -> transform(valid), transformExecutor)  // nặng
    .thenAcceptAsync(result -> save(result), ioExecutor);  // I/O
```

### Best Practices

```java
// ✅ thenApply cho các thao tác nhẹ
cf.thenApply(s -> s.toUpperCase());

// ✅ thenApplyAsync cho thao tác nặng/chặn
cf.thenApplyAsync(s -> heavyProcessing(s), executor);

// ✅ Executor tùy chỉnh cho I/O
cf.thenApplyAsync(s -> ioOperation(s), ioExecutor);

// ❌ thenApplyAsync không có lý do (overhead)
// ❌ thenApply với thao tác chặn
// ❌ commonPool cho I/O
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- thenApply — trong cùng thread với CF trước, overhead ~5 ns
- thenApplyAsync — trong ForkJoinPool.commonPool() hoặc Executor được chỉ định, overhead ~1μs
- thenApply cho biến đổi CPU nhẹ, thenApplyAsync cho thao tác nặng/chặn
- ThreadLocal bị mất với Async — thread khác
- Không có Executor, thenApplyAsync dùng ForkJoinPool.commonPool()

**Các câu hỏi phụ thường gặp:**
- **Khi nào dùng thenApply, khi nào dùng thenApplyAsync?** — thenApply cho nhẹ (toUpperCase), thenApplyAsync cho nặng (heavyProcessing, I/O)
- **thenApplyAsync không có Executor — pool nào?** — ForkJoinPool.commonPool(), đối với I/O đây là thread pool starvation
- **Tại sao thenApply nhanh hơn?** — Không chuyển thread, hàng đợi, hoặc overhead lập lịch
- **ThreadLocal với thenApplyAsync?** — Sẽ bị mất, vì đó là thread khác. Cần truyền ngữ cảnh một cách rõ ràng

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "thenApplyAsync luôn tốt hơn — vì nó bất đồng bộ" — +~1μs overhead, thừa thãi cho các thao tác nhẹ
- "thenApply chặn thread" — nó thực thi trong thread đã hoàn thành CF, không có việc chặn bổ sung
- "thenApplyAsync không có Executor an toàn cho I/O" — dùng commonPool, thread pool starvation

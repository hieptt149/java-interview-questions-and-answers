# Can HashMap Store a null Key? (HashMap có thể lưu một null Key không?)

## 🟢 Junior Level

**Có**, HashMap cho phép dùng **một `null` làm key**. Nếu bạn cố thêm một null key thứ hai, giá trị chỉ đơn giản bị ghi đè.

**Ví dụ:**
```java
HashMap<Object, String> map = new HashMap<>();
map.put(null, "First");
map.put(null, "Second"); // Ghi đè

System.out.println(map.get(null)); // "Second"
System.out.println(map.size());    // 1 (chỉ một null key)
```

**Cách nó hoạt động:** HashMap xử lý null đặc biệt — với nó, `hash(null) = 0`, và nó luôn rơi vào bucket đầu tiên (`table[0]`).

**Các Map khác:**
- `ConcurrentHashMap` — **không** (ném NullPointerException)
- `TreeMap` — **không** (các key cần được so sánh)
- `Hashtable` — **không** (hiện thực cũ)

## 🟡 Middle Level

### Hiện thực kỹ thuật

```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

Khi `put(null, value)`:
1. `hash(null)` trả về 0
2. `index = (n - 1) & 0 = 0`
3. Phần tử được đặt vào `table[0]`

### So sánh các hiện thực

| Hiện thực         | Null key    | Null value    |
| ----------------- | ----------- | --------------- |
| HashMap           | Có (1)      | Có (nhiều)      |
| LinkedHashMap     | Có (1)      | Có              |
| TreeMap           | Không       | Có              |
| ConcurrentHashMap | Không       | Không           |
| Hashtable         | Không       | Không           |

### Tại sao điều này nguy hiểm?

1. **Không hiển nhiên** — một null key có thể là một bug khó phát hiện
2. **Một null key ngầm định có thể gây NPE trong code không mong đợi null trong số các key** (ví dụ, `key.length()` không có kiểm tra null)
3. **Không tương thích** — chuyển sang ConcurrentHashMap sẽ phá vỡ code

### Best Practices

- Tránh dùng null làm key
- Dùng pattern Null Object hoặc một hằng số:
```java
static final Object EMPTY_KEY = new Object();
map.put(EMPTY_KEY, defaultValue);
```

### Các sai lầm thường gặp

1. **Null tình cờ** — một kết quả method trả về null, và bạn put nó làm key
2. **Iterate không có kiểm tra** — NPE khi dùng key

## 🔴 Senior Level

### Cơ chế bên trong

Null key được xử lý riêng trong `putVal`:
```java
if (key == null)
    hash = 0;
else
    hash = spread(key.hashCode());
```

Khi va chạm trong bucket 0:
```java
// So sánh: (p.key == key || (key != null && key.equals(p.key)))
// Với null: p.key == null → true (so sánh tham chiếu)
```

Null chỉ được so sánh qua `==` — `equals()` không được gọi.

### Hệ quả về bảo mật

Null key như một vector tấn công:
- Khi deserialize JSON/XML, một null key có thể đến từ một tài liệu đầu vào không hợp lệ. Hãy xử lý điều này một cách tường minh để tránh NPE trong code không mong đợi null trong số các key.

### Tại sao ConcurrentHashMap cấm Null?

Sự mơ hồ trong đa luồng:
```java
// Trong ConcurrentHashMap:
// get(key) = null rõ ràng = key vắng mặt
// Không cần lời gọi containsKey() thứ hai
```

Trong HashMap với các null key:
```java
V val = map.get(key);
if (val == null) {
    // Không có key? Hay value = null?
    if (!map.containsKey(key)) {
        // Race TOCTOU trong đa luồng!
    }
}
```

### Các pattern thay thế

**Null Object Pattern:**
```java
enum SpecialKey { NONE }
map.put(SpecialKey.NONE, defaultValue);
```

**Optional:**
```java
Map<Optional<String>, Value> map; // Nhưng cái này là quá mức cần thiết
```

### Chẩn đoán Production

Khi debug các null key:
- Null key vô hình trong một số profiler
- Heap dump hiển thị Entry với `key = null`
- Trong log: `null=SomeValue` — có thể trông như một bug định dạng

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- HashMap cho phép MỘT null key, hash(null) = 0 → table[0]
- Khi put(null, ...) lặp lại, giá trị bị ghi đè
- null được so sánh qua ==, equals() không được gọi
- ConcurrentHashMap/TreeMap/Hashtable cấm null key (NPE)
- Khi deserialize JSON/XML, một null key có thể đến từ một tài liệu không hợp lệ
- Null Object Pattern: dùng một hằng số EMPTY_KEY thay vì null

**Các câu hỏi phụ thường gặp:**
- **Tại sao ConcurrentHashMap cấm null key?** — sự mơ hồ: get=null = không có key hay value=null?
- **Được phép bao nhiêu null key?** — đúng một, cái thứ hai ghi đè
- **Tại sao một null key nguy hiểm?** — NPE trong code không mong đợi null trong số các key
- **Làm sao bảo vệ?** — Null Object Pattern, Optional, hoặc kiểm chứng đầu vào tường minh

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "HashMap không cho phép null key" — có, một cái
- "null key = một bug" — nó là hành vi được cho phép, dù không được khuyến nghị
- "ConcurrentHashMap cho phép null key" — không, nó ném NPE

# Can You Manually Complete a CompletableFuture with a Result? (Có thể hoàn thành thủ công một CompletableFuture với một kết quả không)

## 🟢 Junior Level

**Có!** Phương thức **`complete()`** cho phép bạn hoàn thành thủ công một CompletableFuture:

```java
CompletableFuture<String> cf = new CompletableFuture<>();

// Hoàn thành thủ công với một kết quả
cf.complete("Hello");

// Bây giờ cf đã hoàn thành
System.out.println(cf.isDone());  // true
System.out.println(cf.join());    // Hello
```

Bạn cũng có thể hoàn thành với một ngoại lệ:
```java
cf.completeExceptionally(new RuntimeException("Error"));
```

## 🟡 Middle Level

### complete()

```java
CompletableFuture<String> cf = new CompletableFuture<>();

// Hoàn thành
boolean completed = cf.complete("result");  // true

// Hoàn thành lặp lại bị bỏ qua
completed = cf.complete("other");  // false
System.out.println(cf.join());  // "result" — cái đầu tiên thắng
```

### completeExceptionally()

```java
cf.completeExceptionally(new RuntimeException("Error"));

// Khi cố gắng lấy kết quả
try {
    cf.join();
} catch (CompletionException e) {
    System.out.println(e.getCause());  // RuntimeException: Error
}
```

### obtrudeValue() — Hoàn Thành Bắt Buộc

```java
cf.complete("first");
cf.obtrudeValue("overridden");  // buộc thay đổi

System.out.println(cf.join());  // "overridden"
```

### Các Lỗi Thường Gặp

1. **Dùng obtrudeValue không có lý do chính đáng:**
```java
// ⚠️ obtrudeValue vi phạm hợp đồng "single completion" của CompletableFuture.
// Bất kỳ code nào đã nhận được kết quả và bắt đầu xử lý có thể làm việc
// với dữ liệu cũ. Chỉ những ai truy cập CF SAU lời gọi obtrudeValue
// mới thấy kết quả mới. Trong môi trường đa luồng — race condition.
cf.obtrudeValue("new value");
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

```java
public boolean complete(T value) {
    boolean triggered = completeValue(value);
    if (triggered)
        postComplete();  // thực thi tất cả callback
    return triggered;
}

public void obtrudeValue(T value) {
    result = (value == null) ? NIL : value;  // buộc thiết lập
}
```

### Kinh Nghiệm Production

**Hoàn thành thủ công trong test:**
```java
@Test
void testManualCompletion() {
    CompletableFuture<String> cf = new CompletableFuture<>();

    // Mô phỏng hoàn thành bất đồng bộ
    new Thread(() -> {
        Thread.sleep(100);
        cf.complete("done");
    }).start();

    assertEquals("done", cf.get(1, TimeUnit.SECONDS));
}
```

### Best Practices

```java
// ✅ complete() cho hoàn thành thủ công
cf.complete(result);

// ✅ completeExceptionally() cho lỗi
cf.completeExceptionally(error);

// ❌ obtrudeValue() không có lý do chính đáng
// ❌ Bỏ qua giá trị trả về của complete()
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- complete(value) — hoàn thành CF nếu chưa hoàn thành. Trả về true/false
- completeExceptionally(ex) — hoàn thành CF với một lỗi
- obtrudeValue(value) — buộc thay đổi kết quả, vi phạm hợp đồng single-completion
- Complete đầu tiên thắng, các cái sau bị bỏ qua
- Khi hoàn thành, tất cả các callback đang chờ được thực thi (postComplete)

**Các câu hỏi phụ thường gặp:**
- **complete() được gọi hai lần — điều gì xảy ra?** — Cái đầu trả về true, cái thứ hai false. Kết quả = giá trị đầu tiên
- **obtrudeValue vs complete?** — obtrudeValue buộc thiết lập ngay cả khi CF đã hoàn thành. Nguy hiểm
- **completeExceptionally + complete — điều gì xảy ra?** — Phụ thuộc vào thời điểm. Ai đến trước thắng
- **Tại sao cần hoàn thành thủ công?** — Test, cache, bất đồng bộ có điều kiện, tích hợp với API chặn

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "complete() có thể được gọi nhiều lần" — chỉ lần đầu thành công
- "obtrudeValue an toàn cho production" — race condition, vi phạm hợp đồng single-completion
- "completeExceptionally không thực thi callback" — nó có thực thi, giống như complete

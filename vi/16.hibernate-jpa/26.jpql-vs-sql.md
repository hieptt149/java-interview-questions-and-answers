# What is JPQL and How Does It Differ from SQL (JPQL là gì và khác với SQL như thế nào)

## Overview

JPQL (Java Persistence Query Language) là một ngôn ngữ truy vấn hướng đối tượng làm việc với entity và các trường của chúng, không phải table và cột. Hiểu sự khác biệt giữa JPQL và SQL là quan trọng để dùng JPA hiệu quả.

---

## Junior Level

### JPQL Là Gì

JPQL - một ngôn ngữ truy vấn làm việc với **entity và trường**, không phải table và cột.

```java
// JPQL - làm việc với các lớp entity
List<User> users = entityManager.createQuery(
    "SELECT u FROM User u WHERE u.age > :age", User.class)
    .setParameter("age", 18)
    .getResultList();

// SQL - làm việc với table
// SELECT * FROM users WHERE age > 18;
```

### Sự Khác Biệt Chính

| JPQL                                                                                                                                     | SQL                         |
| ---------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| `User` (lớp entity)                                                                                                                    | `users` (tên table)         |
| `u.age` (tên trường)                                                                                                                     | `age` (tên cột)             |
| `u.userProfile.city` (điều hướng)                                                                                                        | `JOIN user_profiles ON ...` |
| Không phụ thuộc DB (trừu tượng hóa cấu trúc truy vấn, nhưng không phải mọi khác biệt dialect - ví dụ, các hàm string và date có thể khác nhau) | Đặc thù cho DB               |
| Tự động tạo SQL                                                                                                                             | SQL trực tiếp                |

### Các Ví Dụ JPQL

```java
// SELECT đơn giản
SELECT u FROM User u WHERE u.email = :email

// JOIN
SELECT o FROM Order o JOIN o.user u WHERE u.name = :name

// Aggregation
SELECT u, COUNT(o) FROM User u LEFT JOIN u.orders o GROUP BY u

// UPDATE
UPDATE User u SET u.status = :status WHERE u.id = :id

// DELETE
DELETE FROM Order o WHERE o.status = 'cancelled'
```

### Tham Số Hóa

```java
// Named parameter (khuyến nghị)
@Query("SELECT u FROM User u WHERE u.name = :name AND u.age > :age")
List<User> find(@Param("name") String name, @Param("age") int age);

// Nối chuỗi (SQL injection!)
"SELECT u FROM User u WHERE u.name = '" + name + "'"  // rủi ro SQL injection!
```

## Middle Level

### JPQL vs SQL - So Sánh Chi Tiết

```
JPQL:
- Làm việc với entity và trường
- Không phụ thuộc DB (hoạt động với bất kỳ DB nào)
- Tự động tạo SQL
- Hỗ trợ truy vấn polymorphic
- Làm việc với inheritance

SQL:
- Làm việc với table và cột
- Đặc thù cho DB (cú pháp phụ thuộc vào DB)
- Kiểm soát truy vấn hoàn toàn
- Không có mapping tự động
- Không có polymorphism
```

### Các Ví Dụ JPQL

```java
// SELECT với constructor (DTO projection)
@Query("SELECT new com.example.UserDto(u.name, u.email) FROM User u")
List<UserDto> findUserDtos();

// JOIN FETCH
@Query("SELECT DISTINCT o FROM Order o JOIN FETCH o.items WHERE o.id = :id")
Order findByIdWithItems(@Param("id") Long id);

// Subquery
@Query("SELECT u FROM User u WHERE u.id IN (SELECT o.user.id FROM Order o WHERE o.total > :amount)")
List<User> findUsersWithOrdersOver(@Param("amount") BigDecimal amount);

// GROUP BY với HAVING
@Query("SELECT u, COUNT(o) FROM User u JOIN u.orders o GROUP BY u HAVING COUNT(o) > :minOrders")
List<Object[]> findActiveUsers(@Param("minOrders") int minOrders);

// CASE WHEN
@Query("SELECT u, CASE WHEN COUNT(o) > 0 THEN 'active' ELSE 'inactive' END FROM User u LEFT JOIN u.orders o GROUP BY u")
List<Object[]> findUserStatus();
```

### Native SQL - Khi Nào Cần

```java
// Các hàm đặc thù cho DB
List<User> users = entityManager.createNativeQuery(
    "SELECT * FROM users WHERE created_at > NOW() - INTERVAL '30 days'",  // đặc thù PostgreSQL! Trong MySQL: NOW() - INTERVAL 30 DAY
    User.class
).getResultList();

// CTE (Common Table Expressions)
List<User> users = entityManager.createNativeQuery("""
    WITH recent_orders AS (
        SELECT user_id, MAX(created_at) as last_order
        FROM orders GROUP BY user_id
    )
    SELECT u.* FROM users u JOIN recent_orders ro ON u.id = ro.user_id
    WHERE ro.last_order > :date
    """, User.class).setParameter("date", date).getResultList();
```

### Các Lỗi Thường Gặp

```java
// Tên table thay vì entity
entityManager.createQuery("SELECT u FROM users u", User.class);  // sai
// Tên entity
entityManager.createQuery("SELECT u FROM User u", User.class);  // đúng

// Tên cột thay vì trường
"SELECT u FROM User u WHERE u.email_address = :email"  // sai
// Tên trường
"SELECT u FROM User u WHERE u.email = :email"  // đúng

// Nối chuỗi cho tham số (SQL injection!)
"SELECT u FROM User u WHERE u.name = '" + name + "'"  // sai
// Tham số
"SELECT u FROM User u WHERE u.name = :name"  // đúng
```

## Senior Level

### JPQL Và Inheritance

```java
// Truy vấn polymorphic - bao gồm tất cả subclass
SELECT p FROM Payment p  // CardPayment, CashPayment, CryptoPayment
// Truy vấn polymorphic bao gồm tất cả subclass. Trên SINGLE_TABLE - nhanh (một table).
// Trên JOINED - tạo ra nhiều JOIN (chậm). Trên TABLE_PER_CLASS - UNION ALL (chậm hơn nữa).

// Với TYPE - lọc theo subclass
SELECT p FROM Payment p WHERE TYPE(p) = CardPayment

// Với TREAT - cast sang subclass
SELECT p FROM Payment p JOIN TREAT(p AS CardPayment) cp WHERE cp.cardNumber = :number
```

### Các Hàm JPQL

```
String: CONCAT, SUBSTRING, TRIM, LOWER, UPPER, LENGTH, LOCATE
Math: ABS, SQRT, MOD, SIZE
Date: CURRENT_DATE, CURRENT_TIME, CURRENT_TIMESTAMP
Collection: SIZE, INDEX, MEMBER OF
Null: NULLIF, COALESCE
Conditional: CASE WHEN, NULLIF
```

### Các Cân Nhắc Về Hiệu Năng

```
Overhead của JPQL:
- Parse JPQL -> tạo SQL
- Bind tham số
- Mapping entity

Overhead của Native SQL:
- Không có parsing (SQL trực tiếp)
- Bind tham số
- Mapping entity (nếu lớp entity được chỉ định)

Sự khác biệt không đáng kể cho các truy vấn đơn giản.
Cho các truy vấn phức tạp - native SQL có thể nhanh hơn.
```

### Khi Nào Dùng JPQL vs SQL

```
JPQL:
Truy vấn không phụ thuộc DB
Truy vấn đơn giản và trung bình
Khi cần polymorphism
Khi làm việc với entity

Native SQL:
Các hàm đặc thù cho DB (CTE, window function)
Truy vấn phân tích phức tạp
Các thao tác bulk (UPDATE/DELETE hàng nghìn bản ghi)
Khi JPQL không hỗ trợ cú pháp
```

### Best Practices

```
JPQL cho truy vấn không phụ thuộc DB
Native SQL cho truy vấn đặc thù DB
Truy vấn tham số hóa (không nối chuỗi!)
Index cho các trường trong WHERE
DTO projection cho chỉ đọc
JOIN FETCH cho dữ liệu liên quan

Nối chuỗi cho tham số (SQL injection!)
JPQL cho các truy vấn phức tạp đặc thù DB
Không có index trên các trường WHERE
Tải toàn bộ entity cho report chỉ đọc
```

## Interview Cheat Sheet

**Cần phải biết:**
- JPQL làm việc với entity và trường, SQL - với table và cột
- JPQL không phụ thuộc DB (hoạt động với bất kỳ DB nào), SQL - đặc thù cho DB
- JPQL tự động tạo SQL, hỗ trợ truy vấn polymorphic và inheritance
- Tham số hóa bắt buộc: :name (named parameter), KHÔNG nối chuỗi (SQL injection!)
- Native SQL cần thiết cho: CTE, window function, thao tác bulk, các hàm đặc thù DB
- DTO projection trong JPQL thông qua constructor: SELECT new com.example.Dto(...)

**Các câu hỏi phụ thường gặp:**
- **Khi nào dùng native SQL thay vì JPQL?** CTE, window function, truy vấn phân tích phức tạp, bulk UPDATE/DELETE
- **JPQL và inheritance - hoạt động như thế nào?** Truy vấn polymorphic SELECT FROM Parent bao gồm tất cả subclass; TYPE để lọc, TREAT để cast
- **Tại sao nối chuỗi nguy hiểm?** SQL injection: "WHERE name = '" + userInput + "' - lỗ hổng
- **Tại sao dùng JOIN FETCH trong JPQL?** Tải các entity liên quan trong một truy vấn (giải pháp N+1)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi dùng tên table thay vì tên entity trong JPQL" - PersistenceException
- "Nối chuỗi cho tham số" - lỗ hổng SQL injection
- "JPQL cho CTE và window function" - JPQL không hỗ trợ, cần native SQL
- "Tôi tải toàn bộ entity cho report chỉ đọc" - DTO projection hiệu quả hơn

# How to configure exactly-once semantics (Cách cấu hình exactly-once semantics)

## Junior Level

### Cấu Hình Cơ Bản

Để có exactly-once bạn cần cấu hình cả **producer** và **consumer**:

```java
// Producer
props.put("enable.idempotence", "true");
props.put("acks", "all");
props.put("retries", Integer.MAX_VALUE);

// Consumer
props.put("isolation.level", "read_committed");
props.put("enable.auto.commit", "false");
```

### Mỗi Cài Đặt Làm Gì?

```
enable.idempotence=true  → producer sẽ không gửi trùng lặp
acks=all                 → chờ xác nhận từ tất cả các replica
retries=INT_MAX           → số lần retry vô hạn khi có lỗi
isolation.level=read_committed → chỉ đọc các message đã commit
enable.auto.commit=false → kiểm soát commit thủ công
```

### Ví Dụ Đơn Giản

```java
// Producer
KafkaProducer<String, String> producer = new KafkaProducer<>(props);
producer.send(new ProducerRecord<>("orders", "order-1", "created"));

// Consumer
consumer.subscribe(List.of("orders"));
ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
for (var record : records) {
    process(record);
}
consumer.commitSync();  // chỉ sau khi xử lý
```

## Middle Level

### Transaction API Cho Exactly-Once

```java
// Khởi tạo (một lần khi khởi động)
producer.initTransactions();

try {
    producer.beginTransaction();

    // 1. Đọc từ Kafka
    ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));

    // 2. Xử lý
    for (var record : records) {
        Result result = process(record);
    }

    // 3. Ghi kết quả
    producer.send(new ProducerRecord<>("output", result));

    // 4. Commit cả hai hành động một cách nguyên tử
    producer.commitTransaction();

} catch (Exception e) {
    // Rollback khi có bất kỳ lỗi nào
    producer.abortTransaction();
}
```

### Pattern Read-Process-Write

```
1. Read    → consumer.poll() từ topic đầu vào
2. Process → business logic
3. Write   → producer.send() đến topic đầu ra
4. Commit  → producer.commitTransaction() một cách nguyên tử

Tất cả trong một transaction!
```

### Cấu Hình Broker

```properties
# Broker phải hỗ trợ transaction
transaction.state.log.replication.factor=3
transaction.state.log.min.isr=2
transaction.max.timeout.ms=900000
```

### Các Lỗi Thường Gặp

1. **initTransactions() không được gọi:**
```
producer.beginTransaction() không có initTransactions()
→ IllegalStateException
```

2. **Không abort transaction khi có lỗi:**
```
Dữ liệu commit một phần → không nhất quán
```

3. **Không có transactional.id:**
```
props.put("transactional.id", "my-tx-id");
// Không có điều này, các transaction không hoạt động
```

## Senior Level

### Cài Đặt Nội Bộ

**Transaction Coordinator:**
```
Một thành phần riêng biệt trên broker
Quản lý vòng đời transaction
Lưu trữ trạng thái trong topic __transaction_state
```

**Máy Trạng Thái Transaction:**
```
Empty → Ongoing → PrepareCommit → CompleteCommit
                    ↓
                PrepareAbort → CompleteAbort
```

**Transaction Log:**
```
Topic __transaction_state (nội bộ)
Lưu trữ:
- Transactional ID
- Producer ID và Epoch

PID (Producer ID) — định danh producer duy nhất, được gán bởi broker.
Epoch — thế hệ producer, tăng lên khi restart. Cùng nhau chúng cho phép
broker phân biệt các message mới với các bản trùng lặp.

- Trạng thái transaction
- Danh sách các partition bị ảnh hưởng
```

### Exactly-Once Semantics (EOS) v2

```
EOS v1 (Kafka 1.0): yêu cầu một transaction coordinator riêng biệt cho mỗi consumer.
EOS v2 (Kafka 2.5): một producer điều phối cho tất cả các consumer trong transaction —
ít overhead hơn, API đơn giản hơn.

Cấu hình:
props.put("processing.guarantee", "exactly_once_v2");
```

### Timeout Transaction

```java
// Cấu hình timeout
props.put("transaction.timeout.ms", "60000");  // 60 giây

// Nếu transaction không hoàn thành → tự động abort
// Consumer với isolation.level=read_committed không thấy các message đã abort
```

**Hậu Quả Của Timeout:**
```
Transaction > timeout → abort
Các message → không hiển thị với các consumer
Producer → phải bắt đầu lại
```

### Các Pattern Transaction Nâng Cao

**1. Nhiều Topic Đầu Ra:**
```java
producer.beginTransaction();

// Đọc
ConsumerRecords<String, String> records = consumer.poll();

// Xử lý và ghi vào nhiều topic
for (var record : records) {
    Result result = process(record);
    producer.send(new ProducerRecord<>("output-1", result));
    producer.send(new ProducerRecord<>("output-2", result));
}

// Commit nguyên tử của tất cả các ghi
producer.commitTransaction();
```

**2. Send Offsets To Transaction:**
```java
// Đọc từ topic A → xử lý → ghi vào topic B → commit offset
producer.beginTransaction();

// Gửi đến output
producer.send(outputRecord);

// Commit offset consumer trong cùng transaction
producer.sendOffsetsToTransaction(
    offsets,
    consumer.groupMetadata()
);

producer.commitTransaction();
```

### Tối Ưu Hóa Hiệu Năng

```
Overhead transaction:
- Giao tiếp coordinator
- Lưu trữ trạng thái bền vững
- Giao thức commit/abort

Các tối ưu hóa:
1. Batch nhiều lần gửi trong một transaction
2. Tăng transaction.timeout.ms cho các thao tác dài
3. Dùng transactional.id để phục hồi trạng thái producer
4. Giám sát độ trễ transaction
```

### Giám Sát Transaction

**Các metrics chính:**
```
kafka.producer:transaction-commit-rate
kafka.producer:transaction-abort-rate
kafka.producer:transaction-commit-failed-rate
kafka.consumer:committed-offset
```

**Các Alert:**
```yaml
- Tỷ lệ abort transaction > 1% → warning
- Độ trễ commit transaction > 1s → warning
- Các transaction bị abort trong log → điều tra
```

### Phục Hồi Sau Lỗi

**Restart Producer:**
```java
// Khi restart, producer với cùng transactional.id:
// 1. initTransactions() abort tất cả các transaction chưa hoàn thành
// 2. Producer có thể tiếp tục từ nơi đã dừng
props.put("transactional.id", "my-producer-1");
producer.initTransactions();  // abort các transaction chưa hoàn thành
```

**Restart Consumer:**
```
Consumer với isolation.level=read_committed:
- Chỉ thấy các message đã commit
- Các message đã abort được tự động ẩn
- Offset không được commit cho các transaction đã abort
```

### Các Thực Hành Tốt Nhất

```
✅ initTransactions() khi khởi động
✅ abortTransaction() khi có bất kỳ lỗi nào
✅ Read-process-write trong một transaction
✅ Cấu hình transaction.timeout.ms
✅ Transactional.id để phục hồi
✅ Giám sát tỷ lệ commit/abort

❌ Không có enable.idempotence
❌ Không có abort khi có lỗi
❌ Các transaction dài (> timeout)
❌ Không có transactional.id
❌ Bỏ qua các transaction đã abort
```

### Các Quyết Định Kiến Trúc

1. **Exactly-once dựa trên transaction chỉ hoạt động cho Kafka-to-Kafka. Idempotent producer cung cấp delivery exactly-once đến topic (loại bỏ trùng lặp khi retry).**
2. **Timeout transaction rất quan trọng** — quá ngắn → abort, quá dài → lãng phí tài nguyên
3. **Transactional.id để phục hồi** — cho phép tiếp tục sau khi restart
4. **Monitoring là bắt buộc** — các transaction đã abort có thể không được chú ý

### Tóm Tắt Cho Senior

- Transaction API cung cấp read-process-write nguyên tử
- Exactly-once yêu cầu cấu hình broker đặc biệt
- Timeout transaction — cân bằng giữa độ tin cậy và mức sử dụng tài nguyên
- Transactional.id rất quan trọng để phục hồi sau khi restart
- Giám sát tỷ lệ commit/abort là bắt buộc cho production

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Producer: `enable.idempotence=true`, `acks=all`, `transactional.id`
- Consumer: `isolation.level=read_committed`, `enable.auto.commit=false`
- Transaction API: `initTransactions()` → `beginTransaction()` → `commitTransaction()` / `abortTransaction()`
- Pattern Read-Process-Write: poll → process → send → commitTransaction (nguyên tử)
- Exactly-once chỉ hoạt động cho Kafka-to-Kafka, không cho các hệ thống bên ngoài
- EOS v2 (Kafka 2.5): một producer điều phối cho tất cả các consumer, ít overhead hơn
- Timeout transaction rất quan trọng: quá ngắn → abort, quá dài → lãng phí tài nguyên
- Khi restart: `initTransactions()` abort tất cả các transaction chưa hoàn thành

**Các câu hỏi phụ thường gặp:**
- *Điều gì xảy ra nếu không có transactional.id?* — Các transaction không hoạt động, cần thiết để phục hồi.
- *Điều gì nếu transaction vượt timeout?* — Tự động abort, các message không hiển thị với các consumer.
- *Làm sao commit offset trong một transaction?* — `sendOffsetsToTransaction(offsets, groupMetadata)`.
- *EOS v2 khác v1 như thế nào?* — Ít overhead hơn, API đơn giản hơn, một producer cho tất cả các consumer.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Exactly-once hoạt động cho Kafka → PostgreSQL" — chỉ Kafka-to-Kafka
- "Bạn có thể gọi beginTransaction mà không cần initTransactions" — IllegalStateException
- "Các transaction miễn phí về mặt hiệu năng" — overhead độ trễ 2-3x
- "Abort khi có lỗi là tùy chọn" — dữ liệu commit một phần = không nhất quán

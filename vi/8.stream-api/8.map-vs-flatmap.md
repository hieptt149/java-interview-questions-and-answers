# What is the difference between map() and flatMap()? (Sự khác biệt giữa map() và flatMap() là gì?)

## Junior Level

Khác biệt chính là **hàm mapper trả về cái gì**:

| Tiêu chí         | `map()`             | `flatMap()`                      |
| --------------- | ------------------- | -------------------------------- |
| Khi nào         | biến đổi 1->1        | biến đổi 1->N + gộp lại           |
| Mapper trả về   | `R` (một object)     | `Stream<R>` (stream các object)   |
| Tương ứng       | 1-đối-1             | 1-đối-nhiều                       |
| Lồng nhau       | Không               | Thu gọn các stream lồng nhau      |

**`map(Function<T, R>)`:**
- Hàm trả về **một object** kiểu `R`
- Tương ứng 1-đối-1
```java
List<String> words = List.of("hello", "world");
words.stream().map(String::length)  // [5, 5]
```

**`flatMap(Function<T, Stream<R>>)`:**
- Hàm trả về một **stream** các object kiểu `R`
- Tương ứng 1-đối-nhiều (0, 1 hoặc nhiều)
```java
List<List<String>> nested = List.of(List.of("a", "b"), List.of("c"));
nested.stream().flatMap(Collection::stream)  // ["a", "b", "c"]
```

**Quy tắc đơn giản:** Nếu bạn có một collection bên trong một phần tử — `flatMap`, nếu biến đổi đơn giản — `map`.

## Middle Level

### Chữ ký

```java
// map — nhận T, trả về R
<R> Stream<R> map(Function<T, R> mapper)

// flatMap — nhận T, trả về Stream<R>
<R> Stream<R> flatMap(Function<T, Stream<R>> mapper)
```

### Khi nào chọn map

- Biến đổi dữ liệu (`User -> UserDTO`)
- Trích xuất trường (`User -> User.getEmail()`)
- Kiểu thay đổi nhưng cấu trúc là tuyến tính

### Khi nào chọn flatMap

- Object chứa một collection (`Order -> Stream<OrderItem>`)
- Các nguồn bên ngoài trả về các stream
- Lọc + biến đổi đồng thời (trả về `Stream.empty()`)

### Optional: một khác biệt đặc biệt

```java
Optional<User> user = ...;

// map sẽ trả về Optional<Optional<String>> — lồng nhau!
Optional<Optional<String>> bad = user.map(u -> u.getEmailAsync());

// flatMap sẽ trả về Optional<String> — đúng
Optional<String> good = user.flatMap(u -> u.getEmailAsync());
```

Trong `Optional`, `flatMap` "thu gọn" sự lồng nhau.

### Khi nào KHÔNG nên dùng cả hai

- **KHÔNG flatMap** nếu bạn chỉ cần biến đổi một phần tử — dùng `map()`
- **KHÔNG map** nếu một phần tử biến thành một collection và bạn muốn một kết quả phẳng duy nhất — `map()` cho ra `Stream<List<T>>`, nhưng bạn cần `Stream<T>`
- **KHÔNG cả hai** nếu bạn chỉ cần lọc — `filter()` dễ đọc hơn

## Senior Level

### Hiệu suất

**Memory Overhead:** `flatMap` đắt hơn — một object `Stream` mới được tạo cho mỗi phần tử. Với hàng triệu phần tử điều này tạo áp lực lên Young Gen.

**Short-Circuiting:** `flatMap` hỗ trợ short-circuiting. Nếu `.findFirst()` được đặt sau nó, việc thực thi sẽ dừng sau phần tử đầu tiên từ stream lồng nhau đầu tiên.

**Tính song song:** `flatMap` trong các parallel stream kém hiệu quả hơn — việc chia trở nên khó dự đoán hơn do số lượng phần tử đầu ra thay đổi.

### Xử lý Null

- Trong `map`: trả về `null` tạo một stream với một phần tử `null`
- Trong `flatMap`: trả về `null` thay vì một stream -> `NullPointerException`

### Stream vô hạn

`flatMap` có thể kết hợp các stream vô hạn, nhưng thao tác terminal sẽ không kết thúc (trừ khi có short-circuiting).

### Chẩn đoán

- **Kiểm tra kiểu:** Nếu bạn thấy `Stream<List<String>>` — bạn rất có thể đã quên `flatMap`
- **Kiểm thử:** Luôn test các trường hợp mapper trả về một stream rỗng và một stream với một phần tử `null` duy nhất

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `map(Function<T, R>)` — trả về một object R, tương ứng 1-đối-1
- `flatMap(Function<T, Stream<R>>)` — trả về một stream các object, thu gọn sự lồng nhau, 1-đối-nhiều
- map cho biến đổi dữ liệu (User -> UserDTO), flatMap cho trích xuất các collection (Order -> Stream<OrderItem>)
- Trong Optional: map có thể tạo `Optional<Optional<T>>`, flatMap luôn trả về một `Optional<T>` phẳng
- flatMap đắt hơn — tạo một Stream mới cho mỗi phần tử
- Cả hai hỗ trợ short-circuiting: findFirst() sẽ dừng việc thực thi sau phần tử đầu tiên

**Các câu hỏi phụ thường gặp:**
- Khi nào map cho ra Stream<List<T>>? — Khi mapper trích xuất một collection từ một phần tử nhưng bạn cần Stream<T> -> dùng flatMap
- null trong map vs flatMap? — map truyền null đi tiếp, flatMap ném NullPointerException
- Khi nào flatMap chậm hơn? — Với hàng triệu phần tử do cấp phát object Stream
- flatMap có thể thay thế filter không? — Có, bằng cách trả về Stream.empty() cho những cái bị lọc, nhưng filter dễ đọc hơn

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "map và flatMap có thể thay thế cho nhau" — không, khác chữ ký và ngữ nghĩa
- "flatMap nhanh hơn map" — không, flatMap luôn đắt hơn do việc tạo object Stream
- "map có thể trả về 0 phần tử" — không, map luôn trả về 1 object (hoặc null)
- "flatMap đảm bảo thứ tự trong các parallel stream" — không, việc chia khó dự đoán hơn

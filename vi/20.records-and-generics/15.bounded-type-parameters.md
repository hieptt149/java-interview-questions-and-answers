# What Are Bounded Type Parameters? (Bounded type parameter là gì)

## 🟢 Junior Level

**Bounded type parameter** là một cách để **giới hạn** các kiểu có thể được dùng với một generic.

Bạn chỉ định rằng kiểu phải kế thừa một class nhất định hoặc triển khai một interface.

```java
// Không có giới hạn — bất kỳ kiểu nào
public class Box<T> { }
Box<String> box1 = new Box<>();  // OK
Box<Integer> box2 = new Box<>();  // OK

// Có giới hạn — chỉ Number và các lớp con
public class NumberBox<T extends Number> { }
NumberBox<Integer> box1 = new NumberBox<>();  // ✅ OK
NumberBox<Double> box2 = new NumberBox<>();   // ✅ OK
NumberBox<String> box3 = new NumberBox<>();   // ❌ Lỗi!
```

**Cú pháp:**
- `T extends Class` — chỉ class này và các lớp con của nó
- `T extends Interface` — chỉ các class triển khai interface

## 🟡 Middle Level

### Cách Hoạt Động

**Bound đơn:**
```java
// Chỉ các kiểu Comparable
public class SortedList<T extends Comparable<T>> {
    private List<T> list = new ArrayList<>();

    public void add(T item) {
        list.add(item);
        list.sort(Comparable::compareTo);  // hoạt động — T chắc chắn là Comparable
    }
}

SortedList<Integer> ints = new SortedList<>();  // ✅ Integer triển khai Comparable
SortedList<String> strings = new SortedList<>(); // ✅ String triển khai Comparable
SortedList<Object> objs = new SortedList<>();    // ❌ Object không triển khai Comparable
```

**Tại sao cần thiết:**
```java
// Không có bound — không thể gọi phương thức
public class Box<T> {
    public void process(T item) {
        // item.compareTo(other);  // không thể — T có thể là bất cứ thứ gì
    }
}

// Có bound — có thể gọi phương thức của Number
public class Stats<T extends Number> {
    private List<T> numbers;

    public double average() {
        return numbers.stream()
            .mapToDouble(Number::doubleValue)  // ✅ hoạt động!
            .average().orElse(0);
    }
}
```

### Nhiều Bound

Bạn có thể chỉ định nhiều ràng buộc:
```java
// T phải là Serializable VÀ Comparable
public class DataBox<T extends Comparable<T> & Serializable> {
    private T value;

    public int compare(T other) {
        return value.compareTo(other);  // ✅
    }

    public byte[] serialize() {
        // ✅ có thể serialize — T extends Serializable
        return serializeValue(value);
    }

    private static byte[] serializeValue(Serializable value) {
        // serialization Java chuẩn
        try (var baos = new java.io.ByteArrayOutputStream();
             var oos = new java.io.ObjectOutputStream(baos)) {
            oos.writeObject(value);
            return baos.toByteArray();
        } catch (java.io.IOException e) {
            throw new RuntimeException(e);
        }
    }
}

DataBox<String> box = new DataBox<>();  // ✅ String triển khai cả hai
DataBox<Integer> box2 = new DataBox<>(); // ✅ Integer triển khai cả hai
```

### Các Lỗi Thường Gặp

1. **Sai thứ tự:**
```java
// ❌ Class phải đứng đầu tiên
public class Bad<T extends Serializable & Number> {}  // lỗi
// JLS yêu cầu: class (nếu có) phải đứng đầu tiên, vì erasure dùng
// bound đầu tiên. Java có kế thừa đơn — chỉ cho phép một class.

// ✅ Class trước, sau đó là interface
public class Good<T extends Number & Serializable> {}  // OK
```

2. **Bound không tồn tại:**
```java
// ❌ Integer là một class final, không thể là bound cho kế thừa
public class Box<T extends Integer> {}  // về mặt kỹ thuật OK nhưng vô dụng
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Type erasure với bound:**
```java
public class Stats<T extends Number> {
    private T value;
    public double doubleValue() { return value.doubleValue(); }
}

// Sau erasure: T -> Number (bound đầu tiên)
public class Stats {
    private Number value;
    public double doubleValue() { return value.doubleValue(); }
}
```

**Erasure của nhiều bound:**
```java
public class Box<T extends Comparable<T> & Serializable> { }

// Erasure: T -> bound đầu tiên (Comparable)
public class Box {
    private Comparable value;
}
```

### Đánh Đổi Kiến Trúc

**Bounded so với unbounded:**

| Bounded               | Unbounded              |
| --------------------- | ---------------------- |
| Có thể gọi phương thức      | Không thể gọi phương thức    |
| An toàn kiểu             | Ít an toàn kiểu hơn         |
| Tính linh hoạt hạn chế   | Tính linh hoạt tối đa    |

### Edge Cases

**1. Bound đệ quy:**
```java
// T phải là Comparable với chính nó
public class Enum<E extends Enum<E>> implements Comparable<E> {
    // Nội bộ enum của Java
}

// Kiểu tự ràng buộc
public class SelfBounded<T extends SelfBounded<T>> {
    private T self;

    public T set(T self) {
        this.self = self;
        return self;
    }
}
```

**2. Wildcard so với bounded parameter:**
```java
// Bounded type parameter — cho class/phương thức
public class NumberBox<T extends Number> { }

// Bounded wildcard — cho tham số
public void process(List<? extends Number> numbers) { }

// Khác biệt:
// - <T extends Number> — bạn có thể dùng T trong phương thức
// - <? extends Number> — không thể tạo phần tử mới
```

**3. Bridge method với bound:**
```java
public class Node<T extends Comparable<T>> {
    private T data;
    public T getData() { return data; }
    public void setData(T data) { this.data = data; }
}

public class DateNode extends Node<Date> {
    @Override
    public Date getData() { return super.getData(); }
    @Override
    public void setData(Date data) { super.setData(data); }

    // Bridge method sau erasure:
    // public void setData(Comparable data) { setData((Date) data); }
}
```

### Hiệu Năng

```
Bounded type:
- Runtime: Overhead bằng không
- Thời gian biên dịch: kiểm tra kiểu bổ sung
- Type erasure: bound trở thành kiểu sau khi biên dịch

Bounded vs unbounded:
- Giống nhau tại runtime
- Bounded cung cấp nhiều thông tin hơn cho trình biên dịch
// Sau type erasure, bound trở thành một kiểm tra compile-time.
// JIT không thấy khác biệt giữa bounded và unbounded — bytecode giống hệt.
// Bound chỉ hữu ích cho tính an toàn kiểu tại compile-time.
```

### Kinh Nghiệm Production

**Generic Repository:**
```java
public interface BaseEntity<ID extends Serializable> {
    ID getId();
}

public abstract class JpaRepository<T extends BaseEntity<ID>, ID extends Serializable> {
    private final Class<T> entityType;

    public Optional<T> findById(ID id) {
        // findById an toàn kiểu
        return entityManager.find(entityType, id);
    }

    public <S extends T> S save(S entity) {
        if (entity.getId() == null) {
            return persist(entity);
        } else {
            return merge(entity);
        }
    }
}
```

**Pattern Builder với bound:**
```java
public abstract class Builder<T, B extends Builder<T, B>> {
    protected abstract B self();

    public B withName(String name) {
        // ... thiết lập
        return self();
    }

    public T build() {
        // ... xây dựng
    }
}

public class UserBuilder extends Builder<User, UserBuilder> {
    @Override
    protected UserBuilder self() { return this; }
}

User user = new UserBuilder()
    .withName("John")
    .build();
```

### Best Practices

```java
// ✅ Bounded để gọi phương thức
public class Stats<T extends Number> {
    public double average() { /* dùng Number::doubleValue */ }
}

// ✅ Nhiều bound cho nhiều hợp đồng
public class DataBox<T extends Comparable<T> & Serializable> {}

// ✅ Bound đệ quy cho self-type
public class Enum<E extends Enum<E>> {}

// ❌ Bound quá nghiêm ngặt
// ❌ Bound trên raw type
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Bounded type parameter: `<T extends Number>` — chỉ Number và các lớp con
- Cho phép gọi phương thức của bound-type: `value.doubleValue()` cho `T extends Number`
- Nhiều bound: `<T extends Comparable<T> & Serializable>` — class trước, sau đó là interface
- Type erasure dùng bound đầu tiên: `T extends Number & Serializable` -> erasure = Number
- Bound đệ quy: `<E extends Enum<E>>` — kiểu được so sánh với chính nó
- JLS yêu cầu: class (nếu có) phải đứng đầu tiên trong danh sách bound

**Các câu hỏi phụ thường gặp:**
- **Tại sao cần bounded type?** — Để gọi các phương thức của bound-type bên trong một generic class
- **Tại sao class phải đứng đầu trong nhiều bound?** — Erasure dùng bound đầu tiên, kế thừa đơn
- **Bound đệ quy là gì?** — `T extends Comparable<T>` — kiểu được so sánh với cùng kiểu đó
- **Bound đệ quy nới lỏng?** — `T extends Comparable<? super T>` — cho phép các lớp con cũng hoạt động

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Bạn có thể đặt interface trước class trong bound" — JLS yêu cầu class trước
- ❌ "Nhiều bound tạo overhead runtime" — Overhead bằng không, bound chỉ là compile-time
- ❌ "Bounded và unbounded giống nhau tại runtime" — Giống nhau sau erasure, nhưng bound cung cấp nhiều thông tin compile-time hơn
- ❌ "Bạn có thể có nhiều class trong bound" — Java kế thừa đơn, tối đa một class

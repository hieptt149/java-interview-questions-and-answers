# What Proxy Types Exist? (Có những loại Proxy nào?)

## Junior Level

**Proxy** là một đối tượng đại diện (surrogate object) kiểm soát quyền truy cập đến một đối tượng khác.

**Ví dụ minh họa đơn giản:** Một thư ký không làm công việc của giám đốc, nhưng lại kiểm soát ai có thể tiếp cận được với họ.

**Ví dụ:**
```java
// Đối tượng thật
interface Image { void display(); }

class RealImage implements Image {
    private String filename;

    public RealImage(String filename) {
        this.filename = filename;
        loadFromDisk();  // Thao tác tốn kém!
    }

    private void loadFromDisk() {
        System.out.println("Loading: " + filename);
    }

    public void display() {
        System.out.println("Displaying: " + filename);
    }
}

// Proxy — chỉ tải khi cần thiết
class ProxyImage implements Image {
    private String filename;
    private RealImage realImage;  // Chưa được tạo!

    public ProxyImage(String filename) {
        this.filename = filename;
    }

    public void display() {
        // Tải lười (Lazy loading)
        if (realImage == null) {
            realImage = new RealImage(filename);
        }
        realImage.display();
    }
}

// Cách sử dụng
Image image = new ProxyImage("photo.jpg");  // Nhanh
image.display();  // Chỉ tải ở đây!
```

## Middle Level

### Các loại Proxy

**1. Virtual Proxy (tải lười):**
```java
// Chỉ tải khi được yêu cầu
class LazyLoader<T> {
    private final Supplier<T> factory;
    private T instance;

    public T get() {
        if (instance == null) {
            instance = factory.get();
        }
        return instance;
    }
}
```

**2. Protection Proxy (kiểm soát quyền truy cập):**
```java
class ProtectedDocument {
    private final String content;
    private final String owner;

    public void read(String user) {
        if (!user.equals(owner)) {
            throw new SecurityException("Access denied");
        }
        System.out.println(content);
    }
}
```

**3. Remote Proxy (truy cập từ xa):**
```java
// RMI, gRPC — proxy cho các đối tượng từ xa
interface RemoteService { String getData(); }

class RemoteServiceProxy implements RemoteService {
    public String getData() {
        // Lời gọi qua mạng đến dịch vụ từ xa
        return httpClient.get("http://remote-service/data");
    }
}
```

**4. Logging Proxy:**
```java
class LoggingProxy implements UserService {
    private final UserService real;
    private final Logger log;

    public User findById(Long id) {
        log.info("findById(" + id + ")");
        return real.findById(id);
    }
}
```

### JDK Dynamic Proxy

```java
// Proxy được tạo ra tại thời điểm chạy (runtime)
interface BusinessService { void process(); }

class RealService implements BusinessService {
    public void process() { System.out.println("Processing..."); }
}

// Tạo proxy
BusinessService proxy = (BusinessService) Proxy.newProxyInstance(
    BusinessService.class.getClassLoader(),
    new Class<?>[] { BusinessService.class },
    (proxyObj, method, args) -> {
        System.out.println("Before: " + method.getName());
        Object result = method.invoke(new RealService(), args);
        System.out.println("After: " + method.getName());
        return result;
    }
);

proxy.process();
// Before: process
// Processing...
// After: process
```

## Senior Level

### JDK Proxy vs CGLIB

> Trong JDK hiện đại (8u40+), sự khác biệt là tối thiểu — JDK Proxy sử dụng MethodHandle/invokedynamic.

| Tiêu chí             | JDK Dynamic Proxy           | CGLIB                   |
| --------------------- | --------------------------- | ------------------------ |
| **Yêu cầu**          | Interface                   | Kế thừa             |
| **Tốc độ tạo**    | Nhanh                        | Chậm                    |
| **Tốc độ gọi**        | ~= CGLIB (MethodHandle)     | ~= JDK Proxy             |
| **Phương thức final**     | Không áp dụng                          | Không thể override         |

### Cách Spring lựa chọn Proxy

```java
// Spring Framework: JDK Proxy (nếu có interface).
// Spring Boot 2.x+: proxyTargetClass=true theo mặc định -> CGLIB.
@Service
public class UserServiceImpl implements UserService { }
// -> Spring Framework: JDK Dynamic Proxy
// -> Spring Boot 2.x+: CGLIB (proxyTargetClass=true theo mặc định)

// forceAutoProxy = CGLIB
@Service
public class UserService { }  // Không có interface
// -> CGLIB Proxy (kế thừa)
```

### @Transactional như một Proxy

```java
@Transactional
public void transfer() {
    // Spring bao bọc phương thức trong:
    // 1. BEGIN TRANSACTION
    // 2. Gọi phương thức thật
    // 3. COMMIT / ROLLBACK
}
```

### Kinh nghiệm Production

**Tình huống thực tế: Vấn đề self-invocation (tự gọi chính mình)**
```java
@Service
public class OrderService {
    @Transactional
    public void create() { /* ... */ }

    public void createBatch() {
        for (int i = 0; i < 10; i++) {
            this.create();  // Proxy sẽ không hoạt động!
        }
    }
}
```

Các giải pháp: (1) self-injection: `@Autowired private OrderService self; self.create()`,
(2) `AopContext.currentProxy()`, (3) tái cấu trúc (refactoring) — tách ra thành một bean riêng biệt.

### Best Practices (Thực hành tốt nhất)

1. **JDK Proxy** nếu có interface
2. **CGLIB** nếu không có interface
3. **Tránh** self-invocation
4. **Chi phí phát sinh của Proxy** trong hot path

### Tóm tắt cho Senior

- **JDK Proxy** = interface, trong JDK hiện đại tốc độ ~= CGLIB (MethodHandle)
- **CGLIB** = kế thừa
- **Spring** = tự động chọn loại phù hợp (Boot 2.x+: mặc định là CGLIB)
- **Self-invocation** = proxy không hoạt động

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Proxy — đối tượng đại diện kiểm soát quyền truy cập đến một đối tượng khác (logging, caching, bảo mật, tải lười)
- JDK Dynamic Proxy yêu cầu phải có interface, CGLIB hoạt động thông qua kế thừa (không thể override phương thức final)
- Spring Framework: JDK Proxy nếu có interface; Spring Boot 2.x+: mặc định là CGLIB (proxyTargetClass=true)
- @Transactional, @Cacheable, @Async — tất cả đều sử dụng Proxy ở bên dưới
- Vấn đề self-invocation: gọi this.method() bên trong một bean sẽ bỏ qua (bypass) Proxy
- Virtual Proxy — tải lười, Protection Proxy — kiểm soát quyền truy cập, Remote Proxy — truy cập từ xa
- Trong JDK hiện đại, sự khác biệt về tốc độ giữa JDK Proxy vs CGLIB là tối thiểu (MethodHandle/invokedynamic)

**Các câu hỏi phụ thường gặp:**
- **Tại sao @Transactional không hoạt động với các lời gọi this?** — this bỏ qua Proxy, cần self-injection hoặc AopContext.currentProxy()
- **Khi nào Spring chọn CGLIB thay vì JDK Proxy?** — Khi không có interface hoặc proxyTargetClass=true (Boot 2.x+)
- **Proxy khác Decorator như thế nào?** — Proxy kiểm soát quyền truy cập đến đối tượng, Decorator thêm chức năng
- **Chi phí phát sinh (overhead) của Proxy là gì?** — Thêm một tầng gián tiếp, tối thiểu trong JDK hiện đại (MethodHandle)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Proxy luôn luôn chậm hơn lời gọi trực tiếp" — trong JDK hiện đại sự khác biệt là tối thiểu
- "Tôi có thể dùng @Transactional trên một phương thức private" — Proxy không hoạt động trên các phương thức private
- "this.create() sẽ kích hoạt @Transactional" — vấn đề self-invocation, Proxy sẽ không hoạt động
- "CGLIB luôn luôn nhanh hơn JDK Proxy" — trong JDK hiện đại tốc độ của chúng xấp xỉ bằng nhau

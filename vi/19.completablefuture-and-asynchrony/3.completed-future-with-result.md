# How to Create a CompletableFuture That Is Already Completed with Result? (Cách tạo một CompletableFuture đã hoàn thành sẵn với kết quả)

## 🟢 Junior Level

Đôi khi bạn cần trả về một CompletableFuture **đã hoàn thành sẵn** — ví dụ, khi dữ liệu ở trong cache hoặc để test.

### completedFuture(value)

```java
// CF hoàn thành ngay lập tức với một kết quả
CompletableFuture<String> cf = CompletableFuture.completedFuture("Hello");

cf.thenAccept(s -> System.out.println(s));  // Hello — không có độ trễ
```

### failedFuture(Throwable) — Java 9+

```java
// CF hoàn thành ngay lập tức với một lỗi
CompletableFuture<String> cf = CompletableFuture.failedFuture(
    new RuntimeException("Error")
);

cf.exceptionally(ex -> "fallback");  // sẽ bắt được lỗi
```

**Trước Java 9** bạn phải làm điều này thủ công:
```java
CompletableFuture<String> cf = new CompletableFuture<>();
cf.completeExceptionally(new RuntimeException("Error"));
```

## 🟡 Middle Level

### Tại Sao Cần Điều Này Trong Dự Án Thực Tế?

**1. Bất đồng bộ có điều kiện (Caching):**
```java
public CompletableFuture<Data> getData(String id) {
    Data cached = cache.get(id);
    if (cached != null) {
        return CompletableFuture.completedFuture(cached); // Phản hồi tức thì
    }
    return CompletableFuture.supplyAsync(() -> db.fetch(id)); // Request bất đồng bộ
}
```

**2. Fallback / Null Object:**
```java
return CompletableFuture.completedFuture(Collections.emptyList());
```

**3. Mocking và test:**
```java
// Trong unit test — chế độ đồng bộ
when(service.getDataAsync("1")).thenReturn(
    CompletableFuture.completedFuture(testData)
);
```

### Sắc Thái Quan Trọng: Thread Thực Thi

Nếu bạn gọi `.thenApply()` trên một CF **đã hoàn thành sẵn**:
- **Callback sẽ thực thi trong thread HIỆN TẠI** (thread gọi `thenApply`)
- Nếu CF **chưa hoàn thành**, callback sẽ thực thi trong thread hoàn thành CF

**Hậu quả:** Nếu bạn mong đợi tính bất đồng bộ nhưng nhận được một CF đã hoàn thành sẵn, callback "nặng" của bạn có thể chặn thread chính.

**Giải pháp:** Dùng các phiên bản `*Async` của các phương thức nếu bạn không chắc chắn về nguồn gốc của CF.

```java
// An toàn: thenApplyAsync luôn chuyển thread
completedFuture.thenApplyAsync(data -> heavyTransform(data), executor);

// Nguy hiểm: có thể thực thi trong thread hiện tại
completedFuture.thenApply(data -> heavyTransform(data));
```

### completedStage(value) — Java 12+

```java
// Trả về một CompletionStage — không thể hoàn thành thủ công
CompletionStage<String> stage = CompletableFuture.completedStage("Hello");
// stage.complete(...) — sẽ không biên dịch được!
```

Biểu diễn bất biến (immutable) — an toàn hơn cho các API công khai.

## 🔴 Senior Level

### Hiệu Năng Và Highload

- **Cấp phát**: `completedFuture` tạo một object trên heap. Trong các trường hợp cực đoan (hàng triệu request mỗi giây) điều này có thể gây áp lực lên GC.
- **Project Valhalla**: Trong tương lai CF có thể trở thành một Value type (hoặc được tối ưu hóa qua Scalar Replacement), loại bỏ overhead cấp phát.
// Project Valhalla — đang được phát triển, chưa có mốc thời gian xác định.
// Đừng dựa vào điều này trong các giải pháp production.

### Edge Cases

**1. Failed Future vs exceptionally:**
`failedFuture` ngay lập tức đặt chuỗi vào trạng thái lỗi. Tất cả các lời gọi `thenApply` tiếp theo sẽ bị bỏ qua.

**2. Short-circuit:**
Nếu một `exceptionally` ở giữa một chuỗi dài trả về một kết quả, tất cả các lời gọi `thenApply` tiếp theo sẽ làm việc với kết quả này như thể không có lỗi nào xảy ra.

### Best Practices

```java
// ✅ Dùng completedFuture cho cache
if (cached != null) return CompletableFuture.completedFuture(cached);

// ✅ failedFuture cho lỗi (Java 9+)
return CompletableFuture.failedFuture(new BusinessException("Not found"));

// ✅ completedStage cho các API công khai (Java 12+)
public CompletionStage<Data> getData() { ... }

// ❌ Đừng chặn trong callback của các CF đã hoàn thành
// ❌ Đừng bỏ qua việc CF đã hoàn thành sẵn
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- completedFuture(value) — CF hoàn thành ngay lập tức với một kết quả
- failedFuture(Throwable) — Java 9+, CF hoàn thành ngay lập tức với một lỗi
- completedStage(value) — Java 12+, CompletionStage bất biến
- completedFuture chạy trong CÙNG thread — các callback thực thi đồng bộ
- completedFuture hữu ích cho cache, mock, fallback, bất đồng bộ có điều kiện

**Các câu hỏi phụ thường gặp:**
- **Tại sao cần completedFuture nếu kết quả đã có sẵn?** — Để có một API bất đồng bộ thống nhất: cache trả về completedFuture, DB — supplyAsync
- **completedFuture.thenApply — nó sẽ chạy trong thread nào?** — Trong thread hiện tại (thread gọi), vì CF đã hoàn thành sẵn
- **Cách tạo một CF thất bại trong Java 8?** — new CompletableFuture() + completeExceptionally(ex)
- **Khi nào dùng completedStage thay vì completedFuture?** — Đối với các API công khai để bên gọi không thể hoàn thành thủ công

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "completedFuture tạo một thread mới" — nó đồng bộ, không có thread
- "completedFuture.thenApplyAsync luôn an toàn" — Async chuyển thread, nhưng overhead quá mức cho các thao tác nhẹ
- "failedFuture và exceptionally giống nhau" — failedFuture tạo một CF ở trạng thái lỗi, exceptionally xử lý một lỗi trên một CF đã tồn tại

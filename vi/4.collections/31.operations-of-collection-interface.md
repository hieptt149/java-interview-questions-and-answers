# What operations does the Collection interface support? (Interface Collection hỗ trợ những thao tác nào?)

## 🟢 Junior Level

**Collection** — interface cơ sở cho List, Set, Queue.

> ⚠️ **ĐỪNG nhầm lẫn:** `Collection` (không có 's') — một interface (List, Set, Queue). `Collections` (có 's') — một class tiện ích với các phương thức tĩnh (`sort`, `synchronizedList`, `unmodifiableList`). Đây là những thứ khác nhau!

**Các phương thức chính:**
```java
Collection<String> coll = new ArrayList<>();

// Thêm vào
coll.add("A");
coll.addAll(List.of("B", "C"));

// Kiểm tra
coll.contains("A");       // true
coll.containsAll(...);    // true
coll.isEmpty();           // false
coll.size();              // 3

// Xóa
coll.remove("A");
coll.removeAll(...);
coll.clear();

// Chuyển đổi
Object[] arr = coll.toArray();
String[] strArr = coll.toArray(String[]::new);  // Java 11+
```

## 🟡 Middle Level

### Các nhóm phương thức

**Sửa đổi:**
```java
add(e)           // → true nếu đã thay đổi
addAll(c)        // → true nếu đã thay đổi
remove(e)        // → true nếu đã xóa
removeAll(c)     // Xóa tất cả từ c
retainAll(c)     // Chỉ giữ lại từ c (giao — intersection)
clear()          // Xóa sạch
```

**Hàm (functional) Java 8+:**
```java
// removeIf — xóa theo điều kiện
list.removeIf(e -> e.startsWith("A"));  // O(n) cho ArrayList!

// stream / parallelStream
coll.stream()
    .filter(e -> e.length() > 3)
    .map(String::toUpperCase)
    .collect(Collectors.toList());
```

### Độ phức tạp của contains

```java
// ArrayList: O(n)
list.contains("A");  // Iterate!

// HashSet: O(1)
set.contains("A");   // Hash!

// containsAll cho hai list: O(n × m)!
list1.containsAll(list2);  // Với mỗi phần tử của list2, iterate list1!
```

### toArray

```java
// Java 11+: cách tiếp cận hiện đại nhất
String[] arr = list.toArray(String[]::new);

// Cách tiếp cận cũ (cũng hoạt động)
String[] arr = list.toArray(new String[0]);
// → JVM tối ưu hóa, không cần tạo một mảng có kích thước đúng!
```

Nếu dự án ở trên Java 8 — hãy dùng `coll.toArray(new String[0])`. JVM tối ưu hóa điều này hiệu quả không kém.

## 🔴 Senior Level

### Khi nào KHÔNG dùng parallelStream

1. **Collection < 10K phần tử** — overhead của fork > lợi ích
2. **Các thao tác nhanh** (số học, getter)
3. **Thứ tự quan trọng** — parallelStream không đảm bảo thứ tự
4. **Có side effect** — race condition

### Tối ưu hóa removeIf

```java
// ArrayList.removeIf:
// 1. Tìm phần tử đầu tiên cần xóa
// 2. Trước nó — KHÔNG động vào
// 3. Sau đó — MỘT System.arraycopy
// → O(n), ghi tối thiểu!

// SO VỚI iterator.remove() trong một vòng lặp:
// → System.arraycopy MỖI lần
// → O(n²)!
```

### Độ phức tạp của các thao tác hàng loạt (bulk)

```java
// list1.removeAll(list2)
// Nếu list2 = ArrayList: O(n × m)
// Nếu list2 = HashSet: O(n + m)

// → Luôn chuyển đổi sang Set cho các thao tác hàng loạt!
Set<String> set = new HashSet<>(list2);
list1.removeAll(set);  // O(n + m)
```

Với các collection vừa và lớn — việc chuyển đổi sang Set là có lợi. Với các collection nhỏ (< 10 phần tử), overhead của việc tạo một HashSet có thể lớn hơn lợi ích.

### Các đặc tính của Spliterator

```java
Spliterator<String> spliterator = coll.spliterator();

// Các cờ (flag) tối ưu hóa:
// IMMUTABLE  → collection không thay đổi
// CONCURRENT → có thể được sửa đổi song song
// DISTINCT   → tất cả các phần tử là duy nhất
// SORTED     → được sắp xếp
// SIZED      → biết trước kích thước chính xác

// Stream API dùng các cờ này!
set.stream()
   .distinct()  // → Không làm gì cả! Đã DISTINCT rồi
   .count();    // → O(1) chỉ khi Stream biết kích thước chính xác và không có thao tác nào thay đổi số lượng. distinct() vẫn yêu cầu một lần duyệt.
```

### Áp lực GC (GC Pressure)

```java
// toArray() tạo một BẢN SAO của tất cả dữ liệu!
Object[] copy = collection.toArray();  // O(n) bộ nhớ

// Với các collection lớn → áp lực GC
// → Hãy dùng stream thay vì sao chép
collection.stream().forEach(this::process);
```

toArray tạo một bản sao đầy đủ. Hãy tránh nếu: (1) Collection > 100K phần tử (áp lực GC). (2) Bạn chỉ đọc (dùng stream/forEach). Chấp nhận được nếu: (1) Cần một mảng cho một API legacy. (2) Collection nhỏ.

### Kinh nghiệm Production

**Tình huống thực tế: containsAll O(n²)**
```java
// 10,000 phần tử trong cả hai list
list1.containsAll(list2);  // 10,000 × 10,000 = 100 triệu thao tác!

// Giải pháp:
Set<String> set = new HashSet<>(list2);
list1.containsAll(set);  // 10,000 × O(1) = 10,000 thao tác
// → Tăng tốc 10,000 lần!
```

### Best Practices

1. **removeIf** → O(n) cho ArrayList
2. **toArray(T[]::new)** → phong cách Java 11+
3. **containsAll với Set** → O(n+m) thay vì O(n×m)
4. **Các cờ Spliterator** → các tối ưu hóa của Stream
5. **Tránh toArray** cho các collection lớn (GC)
6. **retainAll** = giao của tập hợp
7. **addAll** = hợp (union)

### Tóm tắt cho Senior

- **removeIf** = O(n), được tối ưu hóa bên trong
- **Các thao tác hàng loạt** → chuyển đổi sang Set
- **toArray** → bản sao, áp lực GC
- **Spliterator** → các cờ cho các tối ưu hóa của Stream
- **contains** → O(n) cho List, O(1) cho Set
- **Java 11+** → toArray(T[]::new)

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `Collection` (interface) != `Collections` (class tiện ích) — đừng nhầm lẫn trong một buổi phỏng vấn
- Các nhóm cơ bản: sửa đổi (`add`, `remove`, `retainAll`), kiểm tra (`contains`, `isEmpty`), chuyển đổi (`stream`, `toArray`)
- `removeIf()` — O(n) cho ArrayList (một `System.arraycopy` duy nhất), tốt hơn `iterator.remove()` O(n^2)
- `containsAll`/`removeAll` cho hai ArrayList = O(n × m); chuyển đổi một cái sang Set = O(n + m)
- `toArray(T[]::new)` (Java 11+) — phong cách hiện đại; JVM tối ưu hóa `new T[0]` hiệu quả không kém
- `toArray()` tạo một bản sao đầy đủ — áp lực GC cho các collection lớn (>100K phần tử)
- Các cờ `Spliterator` (DISTINCT, SORTED, SIZED) — các tối ưu hóa nội bộ của Stream API

**Các câu hỏi phụ thường gặp:**
- *Tại sao `containsAll` của hai list 10K phần tử = 100 triệu thao tác?* — Với mỗi phần tử của list2, list1 được iterate: 10K × 10K. Giải pháp: `new HashSet(list2)`.
- *Khi nào KHÔNG đáng dùng `parallelStream`?* — Collection < 10K phần tử, các thao tác nhanh, thứ tự quan trọng, có side effect.
- *Tại sao chuyển đổi sang Set trước `removeAll`?* — HashSet.contains = O(1); thay vì O(n × m) ta được O(n + m).
- *Các cờ Spliterator làm gì?* — Các gợi ý cho Stream API để tối ưu hóa: DISTINCT — `distinct()` là noop, SIZED — `count()` = O(1).

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Collection và Collections là cùng một thứ" — không, Collection = interface, Collections = class tiện ích
- "`contains` cho ArrayList = O(1)" — không, O(n), iterate tất cả các phần tử
- "`toArray()` không tạo một bản sao" — không, nó là một bản sao đầy đủ của dữ liệu vào một mảng mới
- "`parallelStream` luôn nhanh hơn `stream` thông thường" — không, overhead của fork cho các collection nhỏ lớn hơn lợi ích

# What is Delegation in OOP (Delegation trong OOP là gì)

## 🟢 Junior Level

**Delegation** là một cơ chế trong đó một object không tự thực hiện một tác vụ, mà giao nó cho một object khác trong khi vẫn giữ trách nhiệm cho kết quả. Nó giống như khi một manager giao một nhiệm vụ cho một developer nhưng vẫn chịu trách nhiệm với client.

**Analogy đơn giản:** Bạn muốn đặt một chiếc pizza. Thay vì tự nấu nó (inheritance), bạn gọi cho một tiệm pizza (delegation). Bạn là interface, tiệm pizza là triển khai.

**Ví dụ delegation:**
```java
// Delegate — thực hiện công việc
public class Printer {
    public void print(String text) {
        System.out.println("Printing: " + text);
    }
}

// Delegator — giao công việc
public class DocumentProcessor {
    private final Printer printer;  // Delegate

    public DocumentProcessor(Printer printer) {
        this.printer = printer;
    }

    public void processAndPrint(String doc) {
        // xử lý document
        printer.print(doc);  // Delegation việc in
    }
}
```

**Khi nào dùng:**
- Khi bạn cần tái sử dụng code mà không cần inheritance
- Khi bạn cần khả năng thay đổi triển khai tại runtime
- Để triển khai các pattern Strategy, State, Decorator

## 🟡 Middle Level

### Cách Hoạt Động

**Delegation** = một object (Delegator) chuyển tiếp các lệnh gọi đến một object khác (Delegate). Trong Java điều này phổ biến nhất là **Method Forwarding** — một lệnh gọi rõ ràng đến phương thức của delegate.

**Khác biệt với một lệnh gọi đơn giản:** Trong delegation "thuần túy", delegate có thể giữ một tham chiếu đến context của delegator (truyền `this`). Trong Java, forwarding đơn giản phổ biến hơn.

### Ứng Dụng Thực Tế

**Ví dụ từ JDK — Collections.synchronizedList:**
```java
List<String> syncList = Collections.synchronizedList(new ArrayList<>());
// SynchronizedList delegate đến ArrayList, thêm synchronized
```

**Kotlin: delegation tích hợp sẵn:**
```kotlin
class MyList(inner: List<String>) : List<String> by inner
// Compiler tự động tạo tất cả các phương thức delegate
```

### Delegation vs Proxy

| Đặc tính         | Delegation                                                    | Proxy                                                                                     |
| ---------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| **Binding**            | Tĩnh (code)                                                 | Động (runtime)                                                                         |
| **Triển khai**     | Các phương thức rõ ràng                                                              | `java.lang.reflect.Proxy` / CGLIB (thư viện để tạo các proxy subclass bytecode)      |
| **Hiệu năng**        | Nhanh hơn (lệnh gọi phương thức trực tiếp — JVM có thể inline, ~0.3ns)          | Chậm hơn (reflection thông qua `java.lang.reflect.Proxy`, ~100-500ns)                             |
| **Linh hoạt**        | Cố định                                                         | Có thể thay đổi ngay lập tức                                                                 |

### Các Lỗi Thường Gặp

| Lỗi                                         | Giải pháp                           |
| ----------------------------------------------- | ----------------------------------- |
| Delegation vòng lặp (A→B→A) → StackOverflow     | Phân tích kiến trúc             |
| Delegate không có quyền truy cập trường private       | Truyền context thông qua tham số    |
| Viết thủ công 20 phương thức delegate            | Dùng IDE Generate / Lombok          |

### Khi Nào KHÔNG Nên Dùng Delegation

- Các tiện ích đơn giản (các phương thức static tốt hơn)
- Khi overhead boilerplate vượt quá lợi ích
- Các phần quan trọng về hiệu năng (độ trễ thấp)

## 🔴 Senior Level

### Triển Khai Nội Bộ Ở Cấp Độ JVM

**Method Forwarding — bytecode:**
```
INVOKEVIRTUAL Printer.print(Ljava/lang/String;)V
→ invokevirtual → VTable lookup → Printer.print()

Với trường final:
private final Printer printer;
→ monomorphic call → JIT inline → lệnh gọi trực tiếp (0.3ns)
```

**Tối Ưu JIT:** Nếu trường delegate là `final`, JIT compiler có thể **inline** code của delegate (nhúng nội dung phương thức trực tiếp tại vị trí gọi, loại bỏ hoàn toàn overhead gọi). Điều này được gọi là monomorphic inline caching — JVM thấy một loại và tối ưu.

### Đánh Đổi Kiến Trúc

**Delegation Thủ Công:**
- ✅ Ưu điểm: An toàn tại compile-time, không có overhead reflection, IDE hỗ trợ
- ❌ Nhược điểm: Boilerplate, gánh nặng bảo trì

**Dynamic Proxy:**
- ✅ Ưu điểm: Không có boilerplate, linh hoạt tại runtime
- ❌ Nhược điểm: Overhead reflection (~10-100x chậm hơn), không có kiểm tra tại compile-time

### Edge Cases

1. **Circular Delegation**: A→B→A → StackOverflowError
   - **Giải pháp**: Test kiến trúc (ArchUnit), cấm rõ ràng

2. **Giới Hạn Khả Năng Nhìn Thấy**: Delegate không thể thấy các trường private của delegator
   - **Giải pháp**: Truyền context thông qua tham số, quyền truy cập package-private

3. **Chuỗi Delegation Dài**: A→B→C→D → khó debug
   - **Giải pháp**: Giới hạn ở 2-3 hop, monitoring thông qua stack trace

### Hiệu Năng

| Cách tiếp cận               | Độ trễ     | Ghi chú         |
| ---------------------- | ----------- | ------------ |
| **Lệnh gọi trực tiếp**        | ~0.3 ns     | Cơ sở     |
| **Delegate final**     | ~0.3 ns     | JIT inline  |
| **Delegate không phải final** | ~1-3 ns     | Monomorphic  |
| **JDK Proxy**          | ~100-500 ns | Reflection   |
| **CGLIB Proxy**        | ~50-200 ns  | Sinh bytecode |

- **Inlining**: final → overhead 0
- **Bộ nhớ**: +16 byte cho mỗi header object delegate

### Thread Safety

- **Delegate không có trạng thái**: Thread-safe theo mặc định
- **Delegate có trạng thái**: Cần đồng bộ hóa
- **Delegation đồng thời**: Có thể dùng các instance delegate khác nhau cho mỗi thread

```java
class ConcurrentProcessor {
    private final ThreadLocal<Delegate> delegate =
        ThreadLocal.withInitial(Delegate::new);
    // Một delegate mỗi thread — không có tranh chấp
}
```

### Kinh Nghiệm Production

**Spring AOP (Aspect-Oriented Programming — cho phép thêm các mối quan tâm xuyên suốt như transaction mà không sửa đổi business code) thông qua delegation:**
`@Transactional` tạo một proxy delegate các lệnh gọi đến bean thật, bọc chúng trong một transaction. Overhead ~50-200ns mỗi lệnh gọi, nhưng cung cấp tính transactional khai báo.

**Trường hợp thực tế:** Migration từ JDBC sang JPA — trích xuất `DataAccessDelegate`, chuyển đổi delegate mà không thay đổi business logic. **Kết quả**: migration không có downtime.

### Monitoring

**ArchUnit (thư viện cho các test kiến trúc — kiểm tra các dependency giữa các class ở cấp độ junit test):**
```java
@ArchTest
static void no_circular_delegation = slices()
    .matching("*(..)")
    .should().notCycleDependency();
```

**SonarQube (bộ phân tích code tĩnh — tìm code smell, bug, lỗ hổng)**: Độ dài chuỗi delegation tối đa → cấu hình ngưỡng

### Best Practices Cho Highload

- **Delegate final** để inline
- **Delegate không có trạng thái** để thread-safety
- **Tối đa 2-3 hop** để dễ debug
- **Sinh delegate** thông qua IDE/Lombok cho boilerplate

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Delegation = object giao một tác vụ cho object khác, giữ trách nhiệm cho kết quả
- Method Forwarding — lệnh gọi rõ ràng đến phương thức của delegate, nhanh hơn Dynamic Proxy
- Delegate `final` → JIT inline → overhead 0 (~0.3 ns), không phải final → monomorphic (~1-3 ns)
- JDK Proxy (~100-500 ns) vs CGLIB Proxy (~50-200 ns) vs delegation thủ công (~0.3 ns)
- Circular delegation (A→B→A) → StackOverflowError — cần kiểm soát kiến trúc
- Spring AOP `@Transactional` — proxy delegate các lệnh gọi đến bean thật, overhead ~50-200ns

**Các câu hỏi phụ thường gặp:**
- **Delegation vs Proxy?** — Delegation = tĩnh (compile-time), Proxy = động (runtime thông qua reflection)
- **Cách tránh Circular Delegation?** — Test ArchUnit cho các chu trình dependency, cấm rõ ràng
- **Tại sao `final` quan trọng cho một delegate?** — JIT thấy một loại → monomorphic inline caching → inline hoàn toàn
- **Delegation và Thread Safety?** — Các delegate không có trạng thái thread-safe theo mặc định; ThreadLocal cho có trạng thái

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Delegation luôn chậm hơn một lệnh gọi trực tiếp" (với một trường `final` — cùng ~0.3 ns sau khi inline)
- "Dynamic Proxy luôn là lựa chọn tốt nhất" (overhead 100-500ns, quan trọng trong hot path)
- "Các chuỗi delegation dài là ổn" (Tối đa 2-3 hop, nếu không sẽ khó debug)

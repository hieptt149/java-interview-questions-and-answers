# What happens when you add a new consumer to the group (Điều gì xảy ra khi bạn thêm một consumer mới vào group)

## Junior Level

### Câu Trả Lời Ngắn Gọn

Khi bạn thêm một consumer mới, một **rebalance** xảy ra — các partition được phân phối lại giữa tất cả các consumer.

### Ví Dụ

```
Trước khi thêm:
  C1 → P0, P1
  C2 → P2

Đã thêm C3:
  C1 → P0
  C2 → P1
  C3 → P2
```

### Điều Gì Xảy Ra Trong Quá Trình Rebalance?

```
Eager rebalancing: downtime hoàn toàn 5-30 giây.
Cooperative rebalancing: 1-5 giây với việc xử lý tiếp tục trên các partition còn lại.
Các message tích lũy trong Kafka
Sau rebalance, việc đọc tiếp tục
```

### Cách Thêm Một Consumer?

```java
// Chỉ cần khởi chạy một consumer mới với cùng group.id
props.put("group.id", "my-group");
consumer.subscribe(List.of("orders"));
// Kafka sẽ tự động kích hoạt một rebalance
```

## Middle Level

### Quá Trình Rebalancing (Từng Bước)

```
1. Consumer mới kết nối đến broker
2. Gửi request JoinGroup
3. Group coordinator bắt đầu rebalance
4. Tất cả các consumer nhận thông báo
5. Tất cả các consumer dừng đọc (eager)
   hoặc tiếp tục với một số partition (cooperative)
6. Gán mới được tính toán
7. Gán được phân phối đến các consumer
8. Các consumer bắt đầu đọc các partition mới
```

### Các Chiến Lược Rebalancing

**1. Eager (cách tiếp cận cũ):**
```
Tất cả các consumer dừng hoàn toàn
Phân phối lại hoàn toàn
Tất cả tiếp tục làm việc
→ Downtime hoàn toàn của group
```

**2. Cooperative (Kafka 2.3+):**
```
Di chuyển partition dần dần
Các consumer tiếp tục làm việc với các partition còn lại
→ Downtime tối thiểu
```

### ConsumerRebalanceListener

```java
consumer.subscribe(List.of("orders"), new ConsumerRebalanceListener() {
    @Override
    public void onPartitionsRevoked(Collection<TopicPartition> partitions) {
        // Commit offset trước khi mất partition
        consumer.commitSync();
        // Dọn dẹp trạng thái cục bộ
        cleanupState(partitions);
    }

    @Override
    public void onPartitionsAssigned(Collection<TopicPartition> partitions) {
        // Khởi tạo các partition mới
        initializeState(partitions);
        // Có thể bắt đầu đọc từ một offset cụ thể
        for (TopicPartition tp : partitions) {
            consumer.seek(tp, getSavedOffset(tp));
        }
    }
});
```

### Rebalance Thường Xuyên — Một Vấn Đề

```
Các consumer không ổn định → rebalance liên tục → downtime hệ thống

Nguyên nhân:
- session.timeout.ms quá ngắn
- Vượt max.poll.interval.ms (xử lý lâu)
- Vấn đề network
- GC pause

Triệu chứng:
- Log message: "Rebalance triggered"
- Consumer lag tăng
- Throughput giảm
```

### Các Lỗi Thường Gặp

1. **Không có ConsumerRebalanceListener:**
```
Mất dữ liệu khi rebalance (offset không được commit)
```

2. **Rebalance thường xuyên:**
```
Các consumer crash → rebalance → crash lần nữa → chu kỳ
```

3. **Xử lý lâu giữa các lần poll:**
```
Vượt max.poll.interval.ms → consumer bị loại → rebalance
```

## Senior Level

### Cooperative Rebalancing — Chi Tiết

**Incremental Cooperative Rebalancing (Kafka 2.3+):**

```
Eager:
  Thu hồi tất cả partition → Gán mới → Tiếp tục
  → Downtime hoàn toàn

Cooperative:
  Di chuyển từng bước:
  1. Thu hồi một số partition
  2. Gán các partition mới
  3. Tiếp tục làm việc
  4. Lặp lại nếu cần
  → Downtime tối thiểu
```

**Cấu hình:**
```java
props.put("partition.assignment.strategy",
    "org.apache.kafka.clients.consumer.CooperativeStickyAssignor");
```

### Giao Thức Group Coordinator

```
Giao thức rebalancing:

JoinGroup — consumer nói "Tôi muốn tham gia group".
SyncGroup — leader phân phối kết quả gán.

1. Giai đoạn Join:
   - Consumer → request JoinGroup
   - Coordinator → thu thập tất cả các thành viên
   - Coordinator → chọn leader

2. Giai đoạn Assignment:
   - Leader → tính toán gán
   - Leader → request SyncGroup với gán
   - Coordinator → phân phối các gán

3. Trạng Thái Ổn Định:
   - Các consumer → các request Heartbeat
   - Coordinator → xác nhận còn sống
   - Các consumer → xử lý message
```

### Cấu Hình Production

```yaml
partition.assignment.strategy: cooperative-sticky
session.timeout.ms: 30000           # 30 giây
heartbeat.interval.ms: 10000        # 10 giây (1/3)
max.poll.interval.ms: 300000        # 5 phút
max.poll.records: 500               # batch
enable.auto.commit: false
```

### Static Membership

```java
// ID consumer cố định
props.put("group.instance.id", "consumer-1");

// Khi restart:
// - Không kích hoạt rebalance
// - Trả về cùng các partition
// - Chờ session.timeout.ms trước khi rebalance
```

### Giám Sát Rebalancing

**Các metrics chính:**
```
kafka.consumer.coordinator:num-rebalances
kafka.consumer.coordinator:time-since-last-rebalance
kafka.consumer:assigned-partitions
kafka.consumer:commit-latency-avg
```

**Các Alert:**
```yaml
- Rebalance thường xuyên hơn mỗi 10 phút → warning
- Rebalance thường xuyên hơn mỗi 5 phút → critical
- Consumer chưa gửi heartbeat > 30s → critical
- Consumer lag tăng → warning
```

### Xử Lý Sự Cố Rebalancing

**1. Xác định nguyên nhân:**
```java
// Log hiển thị:
"Heartbeat session expired" → session.timeout.ms quá ngắn
"Max poll interval exceeded" → xử lý quá chậm
"Member is dead" → consumer crash
```

**2. Giải quyết vấn đề:**
```
Vấn đề heartbeat:
  Tăng session.timeout.ms
  Tăng heartbeat.interval.ms

Vấn đề poll interval:
  Giảm max.poll.records
  Tối ưu hóa xử lý message
  Tăng max.poll.interval.ms

Vấn đề network:
  Kiểm tra kết nối đến các broker
  Kiểm tra các quy tắc firewall
```

### Các Pattern Nâng Cao

**1. Gradual Rollout:**
```
Thêm các consumer dần dần:
1. Khởi chạy một consumer
2. Chờ ổn định
3. Kiểm tra lag và throughput
4. Thêm cái tiếp theo
```

**2. Quản Lý Trạng Thái Nhận Biết Partition:**
```java
public class StatefulConsumer {
    private final Map<TopicPartition, State> states = new HashMap<>();

    public void onPartitionsRevoked(Collection<TopicPartition> partitions) {
        // Lưu trạng thái cho mỗi partition
        for (TopicPartition tp : partitions) {
            states.get(tp).save();
            states.remove(tp);
        }
    }

    public void onPartitionsAssigned(Collection<TopicPartition> partitions) {
        // Tải trạng thái cho các partition mới
        for (TopicPartition tp : partitions) {
            states.put(tp, State.load(tp));
        }
    }
}
```

### Các Thực Hành Tốt Nhất

```
✅ Assignor cooperative-sticky
✅ Session timeout đủ lớn (30s+)
✅ Xử lý message nhanh
✅ ConsumerRebalanceListener để xử lý graceful
✅ Static membership cho các instance ổn định
✅ Giám sát tần suất rebalance

❌ Eager assignor chấp nhận được cho các cluster tĩnh. Cho production với rolling deploy — hãy dùng CooperativeSticky.
❌ Timeout quá ngắn
❌ Không có xử lý onPartitionsRevoked
❌ Bỏ qua consumer lag
```

### Các Quyết Định Kiến Trúc

1. **Cooperative rebalancing** — tiêu chuẩn cho production
2. **Static membership** — cho các instance ổn định
3. **Quản lý trạng thái** — lưu trạng thái khi rebalance
4. **Monitoring** — phát hiện vấn đề sớm

### Tóm Tắt Cho Senior

- Rebalancing — quá trình quan trọng cho tính khả dụng của group
- Cooperative rebalancing giảm thiểu gián đoạn
- ConsumerRebalanceListener là bắt buộc cho production
- Static membership giảm các rebalance không cần thiết
- Giám sát tần suất rebalance — chỉ báo vấn đề sớm
- Xử lý sự cố cần phân tích log và metrics

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Thêm một consumer mới kích hoạt một rebalance — các partition được phân phối lại
- Eager rebalancing: downtime hoàn toàn 5-30 giây; Cooperative: 1-5 giây
- ConsumerRebalanceListener là bắt buộc: commitSync trong onPartitionsRevoked
- Rebalance thường xuyên — một vấn đề: vượt session.timeout, vượt max.poll.interval
- CooperativeStickyAssignor — tiêu chuẩn cho production (Kafka 2.3+)
- Static membership (`group.instance.id`) — loại bỏ rebalance khi rolling deploy
- Gradual rollout: thêm các consumer dần dần, kiểm tra lag

**Các câu hỏi phụ thường gặp:**
- *Điều gì xảy ra nếu một consumer xử lý quá lâu?* — Vượt max.poll.interval → loại bỏ → rebalance.
- *Làm sao tăng tốc rebalance?* — CooperativeStickyAssignor + static membership.
- *Phải làm gì với consumer stateful khi rebalance?* — Lưu trạng thái trong onPartitionsRevoked, tải trong onPartitionsAssigned.
- *Bạn có thể tắt rebalance không?* — Không, nhưng static membership giảm thiểu nó cho các instance đã biết.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Rebalancing xảy ra tức thì" — 5-30 giây eager, 1-5 cooperative
- "Bạn có thể bỏ qua onPartitionsRevoked" — mất offset và trạng thái
- "Rebalance thường xuyên là bình thường" — dấu hiệu của vấn đề timeout hoặc xử lý
- "Eager rebalancing là lựa chọn tốt nhất" — cooperative giảm thiểu gián đoạn

# What is try-with-resources? (try-with-resources là gì?)

## Junior Level

### Định nghĩa

**Try-with-resources** (TWR) - một cấu trúc của Java 7+. Phiên bản tối thiểu: Java 7. Với Java 6 trở xuống - dùng `finally`. Trong Android - API 19+ (KitKat). Tự động đóng resource sau khi thoát khỏi khối `try`.

### Tại sao cần nó

Trước đây bạn phải đóng resource thủ công trong `finally`:

```java
// Cách cũ (trước Java 7)
BufferedReader br = null;
try {
    br = new BufferedReader(new FileReader("file.txt"));
    br.readLine();
} finally {
    if (br != null) br.close(); // Thủ công!
}
```

Giờ đây tự động:

```java
// Cách hiện đại (Java 7+)
try (BufferedReader br = new BufferedReader(new FileReader("file.txt"))) {
    br.readLine();
} // br.close() được gọi tự động!
```

### Những resource nào có thể được dùng

Bất kỳ resource nào implement `AutoCloseable`:
- `FileInputStream`, `BufferedReader` - file
- `Connection`, `Statement` - database
- `Socket` - mạng

### Nhiều resource

```java
try (FileInputStream fis = new FileInputStream("in.txt");
     FileOutputStream fos = new FileOutputStream("out.txt")) {
    // Cả hai sẽ được đóng tự động
}
```

---

### Khi nào KHÔNG nên dùng try-with-resources

1. **Factory method** - bạn tạo một resource và trả nó về cho bên gọi (TWR sẽ đóng nó trước khi return)
2. **Resource sống lâu hơn một phương thức** - vòng đời được quản lý từ bên ngoài
3. **Resource dạng pool** (HikariCP connection) - trả về pool != đóng, pool tự quản lý

## Middle Level

### Cách hoạt động

Compiler bung TWR thành code với `finally` và xử lý suppressed exception:

```java
// Code của bạn
try (Resource r = new Resource()) {
    r.doWork();
}

// Compiler tạo template này để:
// (1) đảm bảo resource được đóng
// (2) không làm mất exception từ close() nếu đã có lỗi trong try
//     -- nó được thêm vào danh sách suppressed của primaryException
// Bung thành:
Resource r = new Resource();
Throwable primaryException = null;
try {
    r.doWork();
} catch (Throwable t) {
    primaryException = t;
    throw t;
} finally {
    if (r != null) {
        if (primaryException != null) {
            try { r.close(); }
            catch (Throwable t) { primaryException.addSuppressed(t); }
        } else {
            r.close();
        }
    }
}
```

### Suppressed Exception

Nếu exception #1 được ném trong `try`, và exception #2 trong lúc `close()`:
- #1 vẫn là cái chính
- #2 được thêm vào dưới dạng **suppressed**
- Bạn có bức tranh đầy đủ: `Error A (Suppressed: Error B)`

Lấy suppressed: `exception.getSuppressed()`

### Hiệu ứng bẫy resource lồng nhau

```java
// NGUY HIỂM - FileWriter có thể rò rỉ!
try (BufferedWriter writer = new BufferedWriter(new FileWriter("file.txt"))) {
    // Nếu constructor của BufferedWriter ném exception, FileWriter sẽ KHÔNG được đóng
}

// AN TOÀN - mỗi resource riêng biệt
try (FileWriter fw = new FileWriter("file.txt");
     BufferedWriter writer = new BufferedWriter(fw)) {
    writer.write("data");
}
```

### Java 9+ - effectively final

Bạn có thể dùng các biến bên ngoài:

```java
BufferedReader br = createReader();
try (br) { // br là effectively final
    br.readLine();
}
```

## Senior Level

### Thứ tự đóng (LIFO)

Các resource được đóng theo thứ tự **ngược lại** với thứ tự khai báo của chúng:

LIFO (Last In, First Out) - cái mở sau cùng, đóng đầu tiên. Giống một chồng đĩa: cái bạn đặt cuối - cái bạn lấy đầu tiên. Với resource điều này nghĩa là: resource "bên trong" nhất được đóng đầu tiên.

```java
try (Socket socket = new Socket("localhost", 8080);
     OutputStream os = socket.getOutputStream();
     BufferedWriter writer = new BufferedWriter(new OutputStreamWriter(os))) {
    // Sẽ đóng: writer -> os -> socket
}
```

Điều này then chốt với các stack của stream. Nếu bạn đóng Socket trước Stream, Stream sẽ lỗi khi cố flush.

### Null Resource

Nếu một resource trong ngoặc được khởi tạo là `null`, TWR chỉ đơn giản bỏ qua nó - không có NPE.

### Hiệu suất: Suppressed Overhead

Khi đóng 1000 resource với lỗi hàng loạt, object exception chính chứa một danh sách suppressed khổng lồ. Điều này có thể ảnh hưởng tới bộ nhớ.

### Các trường hợp biên (Edge Case)

- **Thứ tự Catch/Finally** - `catch` và `finally` của bạn thực thi **sau** khi resource được đóng
- Bên trong `catch`, resource đã không còn khả dụng (đã đóng)
- Compiler tạo một biến local ẩn cho các resource bên ngoài (Java 9+)

### Chẩn đoán

- **`Throwable.getSuppressed()`** - luôn kiểm tra mảng này để phát hiện các vấn đề hạ tầng
- **Static Analysis** - SonarLint tìm các resource được tạo bên trong khối `try` nhưng không nằm trong ngoặc
- **`javap -v`** - xem bytecode được sinh ra để hiểu cơ chế

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Try-with-resources (TWR) - Java 7+, tự động đóng resource sau khi thoát `try`
- Resource phải implement `AutoCloseable`
- Compiler bung TWR thành `finally` với xử lý suppressed exception
- Suppressed exception: nếu cả `try` và `close()` đều lỗi - #1 là chính, #2 là suppressed
- Thứ tự đóng - LIFO (mở sau cùng, đóng đầu tiên)
- Hiệu ứng bẫy resource lồng nhau: `new B(new A())` - nếu B lỗi, A rò rỉ
- Java 9+ hỗ trợ các biến bên ngoài effectively final
- Null resource trong TWR chỉ đơn giản bị bỏ qua - không có NPE

**Các câu hỏi phụ thường gặp:**
- **Tại sao resource lồng nhau nguy hiểm?** - Nếu constructor của resource bên ngoài lỗi, cái bên trong rò rỉ; hãy khai báo mỗi cái riêng biệt
- **Resource được đóng theo thứ tự nào?** - LIFO: cái khai báo cuối được đóng đầu tiên
- **Điều gì xảy ra nếu resource = null?** - TWR bỏ qua nó, không có NPE
- **Khi nào KHÔNG nên dùng TWR?** - Factory method (return từ phương thức), resource dạng pool, resource sống lâu hơn phương thức

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi tạo resource bên trong try nhưng không nằm trong ngoặc" - chúng sẽ không được đóng tự động
- "Suppressed exception không quan trọng khi lỗi hàng loạt" - chúng có thể chứa thông tin chẩn đoán then chốt
- "TWR chỉ hoạt động với InputStream" - hoạt động với bất kỳ AutoCloseable nào

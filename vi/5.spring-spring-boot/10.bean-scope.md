# What is Bean Scope? (Bean Scope là gì?)

## Junior Level

**Scope** (phạm vi) xác định Spring tạo bao nhiêu instance của một bean.

**Các scope chính:**

| Scope         | Bao nhiêu instance                   |
| ------------- | ------------------------------------- |
| **Singleton** | Một cho toàn bộ ứng dụng (mặc định) |
| **Prototype** | Mới ở mỗi lần yêu cầu              |

```java
@Service  // Singleton theo mặc định
public class UserService { }

@Scope("prototype")
@Service
public class ReportGenerator { }
```

**Ví dụ:**
```java
// Singleton: luôn là cùng một cái
UserService s1 = context.getBean(UserService.class);
UserService s2 = context.getBean(UserService.class);
s1 == s2  // -> true

// Prototype: mới mỗi lần
ReportGenerator r1 = context.getBean(ReportGenerator.class);
ReportGenerator r2 = context.getBean(ReportGenerator.class);
r1 == r2  // -> false
```

## Middle Level

### Singleton

```java
// Theo mặc định!
@Service
public class UserService { }

// Một instance cho mỗi ApplicationContext
// Tất cả các thread dùng chung một đối tượng
// -> Phải là Stateless (không trạng thái)!
```

### Prototype

```java
@Scope("prototype")
@Service
public class ReportGenerator { }

// Instance mới ở MỖI getBean()
// Spring tạo nó nhưng KHÔNG quản lý việc hủy!
// -> @PreDestroy KHÔNG được gọi
```

### Web Scope

```java
@Scope("request")     // Một instance cho mỗi HTTP request
@Scope("session")     // Một instance cho mỗi HTTP session
@Scope("application") // Một cho mỗi ServletContext
```

### Vấn đề Prototype trong Singleton

```java
// Prototype được tạo MỘT LẦN!
@Service
public class SingletonService {
    @Autowired
    private PrototypeBean prototype;  // Bị kẹt với một instance duy nhất!
}

// ObjectProvider
@Service
public class SingletonService {
    @Autowired
    private ObjectProvider<PrototypeBean> provider;

    public void process() {
        PrototypeBean bean = provider.getObject();  // Mới mỗi lần!
    }
}
```

## Senior Level

### Khi nào KHÔNG dùng Singleton với trạng thái thay đổi được (mutable state)

KHÔNG lưu trạng thái thay đổi được trong các Singleton bean (ví dụ cache người dùng trong một field của service). Điều này sẽ dẫn đến race condition và memory leak. Thay vào đó:
- Tách trạng thái ra kho lưu trữ bên ngoài (Redis, DB)
- Dùng Request scope cho dữ liệu của request
- Dùng Prototype nếu bạn cần một instance mới

### Scoped Proxy

```java
// Giải pháp cho vấn đề Prototype/Request trong Singleton
@Bean
@Scope(value = "request", proxyMode = ScopedProxyMode.TARGET_CLASS)
public UserPreferences preferences() {
    return new UserPreferences();
}

// Spring inject một proxy vào Singleton
// Proxy truy cập RequestContextHolder (ThreadLocal) ở mỗi lời gọi, nơi lưu trữ các thuộc tính của HTTP request hiện tại. Nhờ vậy, ngay cả một singleton bean inject một request-scoped bean cũng nhận được đúng đối tượng cho mỗi request.
```

### Bên trong: Các bean được lưu ở đâu

```
Singleton -> DefaultSingletonBeanRegistry (ConcurrentHashMap)
Request -> RequestContextHolder (ThreadLocal) - ScopedProxyMode.TARGET_CLASS tạo một CGLIB proxy truy cập scope hiện tại (request/session) ở mỗi lời gọi. RequestContextHolder lưu dữ liệu HTTP request hiện tại trong ThreadLocal.
Session -> SessionAttributes
Prototype -> Được tạo, không được lưu
```

### Custom Scope

```java
// Scope của riêng bạn!
public class ThreadScope implements Scope {
    private final ThreadLocal<Map<String, Object>> threadLocal = new ThreadLocal<>();

    public Object get(String name, ObjectFactory<?> factory) {
        return threadLocal.get().computeIfAbsent(name, k -> factory.getObject());
    }
}

// Đăng ký
context.getBeanFactory().registerScope("thread", new ThreadScope());
```

### Kinh nghiệm Production

**Tình huống thực tế: Request bean trong Singleton**
```java
// Singleton nhận Request bean lúc khởi động
// -> Tất cả các request dùng dữ liệu của người dùng đầu tiên!

// ScopedProxyMode.TARGET_CLASS
// -> Proxy -> RequestContextHolder -> bean thực tế
```

### Best Practices

1. **Singleton** — theo mặc định (Stateless!)
2. **Prototype** — hiếm khi. Nếu bạn chỉ cần một đối tượng mới mà không có phụ thuộc từ Spring — dùng `new`. Nhưng nếu đối tượng cần tiêm phụ thuộc — Prototype là hợp lý.
3. **Request/Session** — cho dữ liệu web
4. **Scoped Proxy** — để inject các scope hẹp vào các scope rộng hơn
5. **ObjectProvider** — thay thế cho Scoped Proxy. **ObjectProvider so với ScopedProxy:** ObjectProvider — gọi `getObject()` tường minh trong code (dễ đọc hơn). ScopedProxy — proxy được thay thế một cách trong suốt (ít rõ ràng hơn nhưng tiện hơn). ObjectProvider được ưu tiên để kiểm soát tường minh.
6. **Tránh trạng thái** trong Singleton

### Tóm tắt cho Senior

- **Singleton** = một cho mỗi ứng dụng, Stateless
- **Prototype** = mới mỗi lần, @PreDestroy KHÔNG hoạt động
- **Request/Session** = web scope
- **Scoped Proxy** = proxy -> RequestContextHolder
- **ObjectProvider** = yêu cầu bean một cách tường minh
- **Custom Scope** = vòng đời của riêng bạn

## Interview Cheat Sheet

**Cần phải biết:**
- Singleton (mặc định) — một instance cho mỗi ApplicationContext, phải là Stateless
- Prototype — instance mới ở mỗi lần yêu cầu, `@PreDestroy` KHÔNG được gọi, Spring không quản lý việc hủy
- Web scope: `request` (mỗi HTTP request), `session` (mỗi HTTP session), `application` (mỗi ServletContext)
- Vấn đề Prototype trong Singleton: prototype được tạo MỘT LẦN khi được inject — dùng `ObjectProvider.getObject()`
- Scoped Proxy (`ScopedProxyMode.TARGET_CLASS`) — CGLIB proxy truy cập `RequestContextHolder` (ThreadLocal) ở mỗi lời gọi
- Tránh trạng thái thay đổi được trong Singleton — race condition và memory leak
- Custom Scope — có thể tạo scope của riêng bạn (ví dụ `ThreadScope` qua `ThreadLocal`)
- Singleton lưu các bean trong `DefaultSingletonBeanRegistry` (ConcurrentHashMap), Request — trong `ThreadLocal`

**Các câu hỏi phụ thường gặp:**
- **Làm sao inject Prototype vào Singleton?** `ObjectProvider<PrototypeBean>.getObject()` — mới mỗi lần, hoặc Scoped Proxy.
- **Scoped Proxy là gì?** Một proxy truy cập scope thực tế (request/session) qua `RequestContextHolder` ở mỗi lời gọi.
- **Tại sao Singleton phải là Stateless?** Một đối tượng được tất cả các thread dùng — trạng thái thay đổi được = race condition.
- **Khi nào dùng Prototype thay vì `new`?** Khi đối tượng cần tiêm phụ thuộc từ Spring.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Singleton có thể lưu trạng thái thay đổi được" (race condition và memory leak)
- "Prototype bean được hủy tự động" (`@PreDestroy` KHÔNG được gọi, dọn dẹp thủ công)
- "Request/Session scope hoạt động không cần Scoped Proxy trong Singleton" (sẽ là một instance cho tất cả các request!)
- "ObjectProvider và Scoped Proxy là cùng một thứ" (ObjectProvider — `getObject()` tường minh, ScopedProxy — thay thế trong suốt)

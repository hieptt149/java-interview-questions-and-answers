# Difference Between replace() vs replaceAll() (Sự khác biệt giữa replace() vs replaceAll())

## 🟢 Junior Level

Cả hai method đều thay thế **tất cả** các lần xuất hiện tìm thấy. Sự khác biệt là **cách** chúng tìm kiếm:

**`replace()`** — tìm kiếm văn bản thông thường (literal):
```java
String s = "apple.banana.orange";
System.out.println(s.replace(".", "/"));
// "apple/banana/orange" — dấu chấm được tìm kiếm theo nghĩa đen
```

**`replaceAll()`** — tìm kiếm bằng biểu thức chính quy:
```java
String s = "apple.banana.orange";
System.out.println(s.replaceAll(".", "/"));
// "/////////////////" — dấu chấm trong regex = "bất kỳ ký tự nào"!
```

**Cạm bẫy chính:** Tên `replace` gây hiểu nhầm — nó thay thế TẤT CẢ các lần xuất hiện, không chỉ lần đầu tiên. Để thay thế chỉ lần xuất hiện đầu tiên, có `replaceFirst()`.

---

## 🟡 Middle Level

### So Sánh Các Method

| Method                                          | Tìm kiếm cái gì      | Thay thế   | Tốc độ         |
| ----------------------------------------------- | ------------------ | ---------- | ------------- |
| `replace(char, char)`                           | Ký tự          | Tất cả        | Nhanh nhất       |
| `replace(CharSequence, CharSequence)`            | Literal (văn bản)     | Tất cả        | Nhanh          |
| `replaceAll(String regex, String replacement)`  | Biểu thức chính quy | Tất cả        | Chậm          |
| `replaceFirst(String regex, String replacement)`| Biểu thức chính quy | Lần đầu tiên      | Chậm          |

### Ứng Dụng Thực Tế
```java
// replace — cho văn bản thông thường
s.replace("old", "new");        // Thay thế literal
s.replace('a', 'b');            // Thay thế ký tự

// replaceAll — cho pattern
s.replaceAll("\\d+", "#");      // Tất cả các chữ số → #
s.replaceAll("\\s+", " ");      // Nhiều khoảng trắng → một

// replaceFirst — chỉ khớp đầu tiên
s.replaceFirst("\\d", "#");     // Chỉ chữ số đầu tiên
```

### Các Lỗi Điển Hình
1. **Lỗi:** `replaceAll("user.name", "admin")` — dấu chấm = bất kỳ ký tự nào
   **Giải pháp:** `replaceAll(Pattern.quote("user.name"), "admin")` hoặc `replace("user.name", "admin")`

2. **Lỗi:** Nghĩ rằng `replace` chỉ thay đổi cái đầu tiên
   **Giải pháp:** `replace` thay đổi TẤT CẢ. Cho cái đầu tiên — `replaceFirst`

3. **Lỗi:** `$` trong chuỗi thay thế cho `replaceAll`
   **Giải pháp:** `$1`, `$2` — tham chiếu nhóm. Cho `$` theo nghĩa đen, dùng `Matcher.quoteReplacement("$")`

## 🔴 Senior Level

### Hiện Thực Nội Bộ

**replace(CharSequence, CharSequence) — qua Pattern.LITERAL**
**replace(char, char) — method riêng, quét trực tiếp byte[], KHÔNG dùng Pattern**

```java
public String replace(CharSequence target, CharSequence replacement) {
    // Kiểm tra Fast Path cho ký tự đơn
    if (target instanceof String && replacement instanceof String) {
        String tgt = (String) target;
        String repl = (String) replacement;
        if (tgt.length() == 1 && repl.length() == 1) {
            return replace(tgt.charAt(0), repl.charAt(0));
        }
    }
    // Qua thay thế Pattern/Literal — không có regex engine
    return Pattern.compile(target.toString(), Pattern.LITERAL)
                  .matcher(this)
                  .replaceAll(Matcher.quoteReplacement(replacement.toString()));
}
```

**replaceAll(String regex, String replacement):**
```java
public String replaceAll(String regex, String replacement) {
    return Pattern.compile(regex).matcher(this).replaceAll(replacement);
}
```

Khác biệt then chốt: `replace` dùng `Pattern.LITERAL` (khớp theo nghĩa đen), `replaceAll` — regex engine đầy đủ.

### Đánh Đổi Về Kiến Trúc (Trade-off)

**replace (literal):**
- Ưu điểm: Không có overhead regex, an toàn với các ký tự đặc biệt, dễ dự đoán
- Nhược điểm: Không có pattern, nhóm, backreference

**replaceAll (regex):**
- Ưu điểm: Sức mạnh đầy đủ của regex (nhóm, lookahead, backreference)
- Nhược điểm: Biên dịch regex, cấp phát, các ký tự đặc biệt cần escape

### So Sánh Hiệu Năng

| Method                         | Cơ chế               | Cấp phát               | 1M lời gọi   |
| ------------------------------ | ----------------------- | -------------------------- | ---------- |
| `replace('a', 'b')`            | Duyệt trực tiếp byte[]      | 1 String                  | ~10ms      |
| `replace("ab", "cd")`          | indexOf + sao chép          | 1 String + Pattern        | ~50ms      |
| `replaceAll("a.b", "x")`       | Biên dịch regex + khớp   | Pattern + Matcher + String| ~300ms     |
| `replaceAll(đã biên dịch trước, "x")` | Chỉ khớp              | Matcher + String          | ~80ms      |

// Các con số là gần đúng, phụ thuộc vào JVM và độ dài chuỗi.

### Các Trường Hợp Biên

1. **Các metacharacter của regex trong replaceAll:**
   ```java
   s.replaceAll("path\\to\\file", "/new"); // \t = tab, \f = form feed!
   s.replaceAll(Pattern.quote("path\\to\\file"), "/new"); // Literal
   ```

2. **Thay thế với `$`:**
   ```java
   "price: $100".replaceAll("\\$100", "$200"); // $2 — backreference, lỗi!
   "price: $100".replaceAll("\\$100", Matcher.quoteReplacement("$200")); // OK
   ```

3. **Thay thế bằng rỗng:**
   ```java
   "abcabc".replace("b", ""); // "acac"
   "abcabc".replaceAll("b", ""); // "acac"
   ```

4. **Không khớp:**
   ```java
   "hello".replace("x", "y"); // "hello" — không đổi, object mới!
   ```

### Kinh Nghiệm Production
**Kịch bản:** Sanitize input người dùng:
```java
// XẤU — người dùng nhập "user[admin]" → lỗi cú pháp regex
String sanitized = input.replaceAll(userInput, "[REDACTED]");

// TỐT — thay thế literal
String sanitized = input.replace(userInput, "[REDACTED]");

// HOẶC — escape
String sanitized = input.replaceAll(Pattern.quote(userInput), "[REDACTED]");
```

**Kịch bản 2:** Che giấu dữ liệu log (100K dòng log/giây):
- `replaceAll("\\b\\d{4}\\b", "XXXX")` để che PIN → ~300ms mỗi 100K
- Pattern đã biên dịch trước → ~80ms
- Parse thủ công → ~15ms (nhưng khó bảo trì hơn)

### Best Practices Cho Highload
- **Mặc định:** `replace()` cho văn bản literal — an toàn hơn và nhanh hơn
- **Cho regex:** `Pattern` đã biên dịch trước + `matcher.replaceAll()`
- **Cho các ký tự đặc biệt trong thay thế:** `Matcher.quoteReplacement()`
- **Cho độ trễ cực thấp:** hiện thực thủ công qua `indexOf` + `StringBuilder`
- **Bảo mật:** luôn `Pattern.quote()` cho input người dùng trong regex

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `replace()` — thay thế literal (không phải regex), thay thế TẤT CẢ các lần xuất hiện
- `replaceAll()` — thay thế bằng biểu thức chính quy, thay thế TẤT CẢ các lần xuất hiện
- `replaceFirst()` — thay thế bằng regex, chỉ khớp đầu tiên
- Tên `replace` gây hiểu nhầm — nó thay thế tất cả, không phải một lần xuất hiện
- Các ký tự đặc biệt trong thay thế cho `replaceAll`: `$1`, `$2` — backreference đến các nhóm
- Cho `$` theo nghĩa đen trong thay thế: `Matcher.quoteReplacement("$")`

**Các câu hỏi phụ thường gặp:**
- **Tại sao `replaceAll(".", "/")` thay thế mọi thứ?** — Dấu chấm trong regex = "bất kỳ ký tự nào". Dùng `replace(".", "/")` để thay thế literal.
- **Cái nào nhanh hơn: `replace()` hay `replaceAll()`?** — `replace()` nhanh hơn — không có overhead regex. `replace('a','b')` — duyệt mảng trực tiếp.
- **`replace()` có chỉ thay đổi lần xuất hiện đầu tiên không?** — Không, mặc dù tên gọi, `replace()` thay đổi TẤT CẢ các lần xuất hiện.
- **Làm sao chỉ thay thế lần xuất hiện đầu tiên của văn bản?** — `replaceFirst()` — nhưng đây là regex. Cho literal — `indexOf` + `substring`.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "`replace()` chỉ thay đổi lần xuất hiện đầu tiên" — thay đổi TẤT CẢ, mặc dù tên gọi
- ❌ "`replaceAll()` nhanh hơn `replace()`" — ngược lại, regex chậm hơn
- ❌ "Bạn có thể truyền input người dùng trực tiếp vào `replaceAll()`" — regex injection, dùng `Pattern.quote()`
- ❌ "`$` trong thay thế — chỉ là một ký hiệu" — nó là một backreference đến các nhóm regex

# What Scopes Exist in Spring? (Spring có những Scope nào?)

## Junior Level

**Scope** (phạm vi) xác định Spring tạo bao nhiêu instance của một bean.

| Scope         | Bao nhiêu instance                   |
| ------------- | ------------------------------------- |
| **Singleton** | Một cho toàn bộ ứng dụng (mặc định) |
| **Prototype** | Mới ở mỗi lần yêu cầu              |
| **Request**   | Một cho mỗi HTTP request                   |
| **Session**   | Một cho mỗi HTTP session                   |

```java
@Service              // Singleton
public class UserService { }

@Scope("prototype")
@Service
public class Report { }  // Mới mỗi lần
```

## Middle Level

### Các Scope chuẩn

**Singleton:**
```java
// Một instance cho mỗi ApplicationContext
// Tất cả các thread dùng chung một đối tượng
// -> Phải là Stateless!
```

**Prototype:**
```java
// Mới ở mỗi getBean()
// Spring KHÔNG gọi @PreDestroy!
// -> Bạn tự dọn dẹp tài nguyên
```

### Web Scope

```java
@Scope("request")     // Một cho mỗi HTTP request
@Scope("session")     // Một cho mỗi phiên người dùng
@Scope("application") // Một cho mỗi ServletContext
```

### Custom Scope

```java
// Scope của riêng bạn!
context.getBeanFactory().registerScope("thread", new ThreadScope());
// ThreadScope - hiện thực tùy chỉnh của interface org.springframework.beans.factory.config.Scope.
// Lưu các bean trong ThreadLocal. Không có sẵn trong Spring chuẩn - đây là một ví dụ.

// Spring Cloud: Refresh Scope
// -> Bean được tạo lại khi cấu hình được cập nhật
```

### Vấn đề: Scope hẹp trong Singleton

```java
// Request bean được tạo một lần lúc Singleton khởi động
@Service
public class SingletonService {
    @Autowired RequestBean requestBean;  // Bị kẹt với cái đầu tiên!
}

// Scoped Proxy
@Scope(value = "request", proxyMode = ScopedProxyMode.TARGET_CLASS)
@Bean public RequestBean requestBean() { }

// ObjectProvider
@Autowired ObjectProvider<RequestBean> provider;
RequestBean bean = provider.getObject();  // Thực tế!
```

## Senior Level

### ScopedProxyMode

```
TARGET_CLASS (CGLIB):
  -> Tạo proxy subclass
  -> Proxy -> RequestContextHolder -> bean thực tế

INTERFACES (JDK):
  -> Chỉ proxy các interface

NO:
  -> Không có proxy -> vấn đề với Singleton
```

### Bên trong: Chúng được lưu ở đâu

```
Singleton -> DefaultSingletonBeanRegistry (ConcurrentHashMap)
Request -> lưu trong các thuộc tính của HttpServletRequest, truy cập qua RequestContextHolder (ThreadLocal)
Session -> SessionAttributes
Prototype -> Không được lưu, tạo mới mỗi lần
```

### Refresh Scope (Spring Cloud)

```java
@RefreshScope
@ConfigurationProperties("my.config")
public class MyConfig { }

// Khi cập nhật qua Spring Cloud Bus:
// -> Proxy bị vô hiệu hóa (invalidate)
// -> Ở lần yêu cầu tiếp theo, được tạo lại với dữ liệu mới
```

### Kinh nghiệm Production

**Tình huống thực tế: Session scope trong microservice**
```
Session scope -> ThreadLocal -> hoạt động trên một node
-> Load Balancer -> request đến node khác -> Session bị mất!

Giải pháp: Spring Session + Redis
-> Session lưu trong Redis -> có sẵn trên mọi node
```

### Best Practices

1. **Singleton** — cho các service và repository
2. **Prototype** — cho các đối tượng stateful nặng
3. **Web scope** — cho dữ liệu người dùng
4. **Scoped Proxy** — để inject các scope hẹp vào các scope rộng hơn
5. **ObjectProvider** — thay thế cho Scoped Proxy
6. **RefreshScope** — cho cấu hình động

### Tóm tắt cho Senior

- **Singleton** = một cho mỗi ApplicationContext
- **Prototype** = mới mỗi lần, @PreDestroy KHÔNG hoạt động
- **Request/Session** = web scope qua ThreadLocal
- **Scoped Proxy** = proxy -> RequestContextHolder
- **RefreshScope** = tạo lại khi cập nhật config
- **Custom Scope** = vòng đời của riêng bạn

## Interview Cheat Sheet

**Cần phải biết:**
- 4 scope chuẩn: Singleton (mặc định), Prototype, Request, Session
- Singleton = một instance cho mỗi ApplicationContext, Prototype = mới ở mỗi lần yêu cầu
- Web scope (Request/Session) được lưu qua ThreadLocal
- ScopedProxyMode (TARGET_CLASS/CGLIB, INTERFACES/JDK, NO) giải quyết vấn đề inject các scope hẹp vào các scope rộng hơn
- @PreDestroy KHÔNG được gọi cho Prototype — dọn dẹp tài nguyên thủ công
- ObjectProvider — thay thế cho Scoped Proxy khi có Prototype/Request trong Singleton
- RefreshScope (Spring Cloud) — tạo lại bean khi cập nhật cấu hình

**Các câu hỏi phụ thường gặp:**
- *Làm sao inject Request scope vào Singleton?* -> Scoped Proxy (`proxyMode = TARGET_CLASS`) hoặc ObjectProvider
- *Điều gì xảy ra nếu một Prototype bean giữ tài nguyên?* -> Rò rỉ, Spring sẽ không gọi @PreDestroy, cần dọn dẹp thủ công qua try-finally
- *Spring lưu các Singleton bean ở đâu?* -> DefaultSingletonBeanRegistry (ConcurrentHashMap)
- *RefreshScope làm gì?* -> Vô hiệu hóa proxy, tạo lại bean với dữ liệu mới ở lần yêu cầu tiếp theo

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Prototype gọi @PreDestroy" — không gọi
- "Request scope được lưu trong cache của Spring" — được lưu trong các thuộc tính của HttpServletRequest
- "Singleton được tạo ở mỗi lần truy cập" — được tạo một lần
- "Custom Scope có sẵn trong Spring" — bạn cần tự viết hiện thực của interface Scope

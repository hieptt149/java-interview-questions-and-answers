# How to Test Code with CompletableFuture? (Cách test code với CompletableFuture)

## 🟢 Junior Level

Việc test CompletableFuture quy về việc **chờ hoàn thành** và **kiểm tra kết quả**:

```java
@Test
void testCompletableFuture() throws Exception {
    CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> "Hello");

    // Chờ hoàn thành
    String result = cf.get();  // hoặc cf.join()

    // Assert
    assertEquals("Hello", result);
}
```

**Dùng `join()` trong test** — nó không ném ra checked exception:
```java
String result = cf.join();  // đơn giản hơn get()
```

## 🟡 Middle Level

### Test Code Bất Đồng Bộ

**1. Test trực tiếp:**
```java
@Test
void testAsyncMethod() {
    CompletableFuture<String> cf = service.getDataAsync();

    // Chờ với timeout
    String result = cf.get(5, TimeUnit.SECONDS);

    assertEquals("expected", result);
}
```

**2. Test với mock:**
```java
@Test
void testWithMock() {
    // Mock dependency bất đồng bộ
    when(repository.findByIdAsync(1L))
        .thenReturn(CompletableFuture.completedFuture(
            new User(1L, "Test")
        ));

    CompletableFuture<User> cf = service.getUserAsync(1L);
    User user = cf.join();

    assertEquals("Test", user.name());
}
```

**3. Test lỗi:**
```java
@Test
void testError() {
    when(repository.findByIdAsync(1L))
        .thenReturn(CompletableFuture.failedFuture(
            new RuntimeException("Not found")
        ));

    CompletableFuture<User> cf = service.getUserAsync(1L);

    assertThrows(ExecutionException.class, () -> cf.get());
}
```

### Các Lỗi Thường Gặp

1. **Không chờ hoàn thành:**
```java
// ❌ Test kết thúc trước khi CF thực thi
CompletableFuture<String> cf = service.getDataAsync();
// assertEquals("expected", ???);

// ✅ Chờ
String result = cf.join();
assertEquals("expected", result);
```

## 🔴 Senior Level

### Pattern Test

**1. Awaitility cho test bất đồng bộ:**
```java
@Test
void testAsyncChain() {
    CompletableFuture<String> cf = service.processAsync();

    // Awaitility — một thư viện để chờ các thao tác bất đồng bộ hoàn thành.
    // Đừng nhầm lẫn với StepVerifier từ Project Reactor (reactor-test).
    await().atMost(5, SECONDS)
        .untilAsserted(() -> {
            assertTrue(cf.isDone());
            assertEquals("expected", cf.join());
        });
}
```

**2. Executor tùy chỉnh cho test:**
```java
@Test
void testWithCustomExecutor() {
    // Executor đơn luồng để đảm bảo tính xác định
    ExecutorService executor = Executors.newSingleThreadExecutor();

    CompletableFuture<String> cf = service.processAsync(executor);
    assertEquals("expected", cf.join());
}
```

**3. Test race condition:**
```java
@Test
void testConcurrentAccess() throws Exception {
    CompletableFuture<Void>[] futures = new CompletableFuture[100];

    for (int i = 0; i < 100; i++) {
        futures[i] = service.incrementAsync();
    }

    CompletableFuture.allOf(futures).join();

    assertEquals(100, service.getCount());
}
```

### Best Practices

```java
// ✅ join() trong test (không phải get)
String result = cf.join();

// ✅ Timeout
String result = cf.get(5, TimeUnit.SECONDS);

// ✅ completedFuture cho mock
when(mock.asyncMethod()).thenReturn(CompletableFuture.completedFuture(result));

// ✅ failedFuture cho test lỗi
when(mock.asyncMethod()).thenReturn(CompletableFuture.failedFuture(error));

// ❌ Chặn không có timeout
// ❌ Quên kiểm tra cf.isDone()
```

### Test Với Virtual Threads (Java 21+)

Với Virtual Threads, nhiều thao tác bất đồng bộ có thể được test giống như code đồng bộ:
```java
@Test
void testWithVirtualThreads() {
    try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
        CompletableFuture<String> cf = CompletableFuture.supplyAsync(
            () -> service.slowBlockingCall(), executor);

        // Virtual Threads cho phép các kiểm tra assert đồng bộ tiêu chuẩn
        // mà không cần chờ CompletableFuture hoàn thành.
        String result = cf.join();
        assertEquals("expected", result);
    }
}
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- join() trong test đơn giản hơn get() — không cần try-catch cho checked exception
- get(5, TimeUnit.SECONDS) — test với timeout, ngăn treo
- completedFuture cho mock, failedFuture cho test lỗi
- Awaitility cho test bất đồng bộ với việc chờ hoàn thành
- Executor tùy chỉnh (đơn luồng) để đảm bảo tính xác định của test

**Các câu hỏi phụ thường gặp:**
- **join() hay get() trong test?** — join() đơn giản hơn (không cần try-catch), get(timeout) an toàn hơn (có timeout)
- **Cách mock một phương thức bất đồng bộ?** — trả về CompletableFuture.completedFuture(testData)
- **Cách test một lỗi bất đồng bộ?** — trả về CompletableFuture.failedFuture(ex) + assertThrows(ExecutionException.class)
- **Test race condition?** — CompletableFuture.allOf(N futures).join() + kiểm tra trạng thái cuối cùng

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Test pass mà không cần cf.join()" — test kết thúc trước khi CF thực thi, dương tính giả
- "get() không có timeout trong test là ổn" — test bị treo khi có lỗi
- "Awaitility và StepVerifier giống nhau" — Awaitility dành cho bất đồng bộ nói chung, StepVerifier dành cho Reactor

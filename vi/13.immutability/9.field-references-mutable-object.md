# What to do if a class field of an immutable class references a mutable object? (Phải làm gì nếu trường của class tham chiếu đến một object mutable?)

---

## Basic Level

Nếu trường của bạn tham chiếu đến một object mutable (ví dụ: `ArrayList`, `Date`, mảng), bạn cần tạo một **bản sao** của nó.

### Ví Dụ Đơn Giản
```java
public final class Person {
    private final String name;
    private final Date birthDate; // Date là mutable!

    public Person(String name, Date birthDate) {
        this.name = name;
        // Cách thay thế: birthDate.clone() — với Date điều này hoạt động, nhưng clone()
        // nói chung được coi là hỏng (Effective Java Item 13).
        this.birthDate = new Date(birthDate.getTime()); // SAO CHÉP!
    }

    public Date getBirthDate() {
        return new Date(birthDate.getTime()); // SAO CHÉP!
    }
}
```

### Quy Tắc Hai Điểm
1. **Khi vào** (constructor) — sao chép các object mutable đầu vào
2. **Khi ra** (getter) — trả về các bản sao của các object mutable nội bộ

---

### Khi Defensive Copy Là Dư Thừa

Nếu bạn kiểm soát tất cả code truyền dữ liệu, và đây là một API nội bộ —
bạn có thể ghi tài liệu về hợp đồng "bên gọi không được mutate". Nhưng hãy cẩn thận:
các lập trình viên tương lai có thể không đọc tài liệu.

## Intermediate Level

### Bảo Vệ Các Collection
```java
public final class ImmutableClass {
    private final List<String> items;

    public ImmutableClass(List<String> items) {
        // Xấu: this.items = items;
        // Tốt:
        this.items = List.copyOf(items); // Java 10+
    }

    public List<String> getItems() {
        return items; // List.copyOf đã trả về một list bất biến — an toàn để trả về
    }
}
```

### Các Phiên Bản Java Cũ Hơn
```java
// Java 8
this.items = Collections.unmodifiableList(new ArrayList<>(items));

// Hoặc
this.items = new ArrayList<>(items);
// ...
return Collections.unmodifiableList(items);
```

### Sao Chép Sâu
Nếu list chứa các object mutable:
```java
public record Order(Long id, List<Item> items) {
    public Order {
        items = items.stream()
            .map(item -> new Item(item.getName(), item.getPrice())) // sao chép mỗi cái
            .toList();
    }
}
```

### Các Lựa Chọn Thay Thế Hiện Đại
- **Record** — đơn giản hóa cấu trúc, nhưng các collection được sao chép thủ công
- **Guava ImmutableCollections** — `ImmutableList.copyOf()`
- **Vavr** — các collection persistent

## Advanced Level

### Tấn Công TOCTOU (Time-of-Check to Time-of-Use)

Nếu bạn validate dữ liệu đầu vào, hãy tạo một bản sao **trước** khi validate:
```java
public ImmutableClass(List<String> items) {
    List<String> copy = List.copyOf(items); // sao chép trước
    if (copy.isEmpty()) throw new IllegalArgumentException(); // sau đó kiểm tra
    this.items = copy;
}
```
Nếu không, trong môi trường đa luồng, trạng thái của list gốc có thể thay đổi giữa lúc kiểm tra và lúc sử dụng.

### Shallow vs Deep Copy — Sự Phân Biệt Then Chốt

`List.copyOf(users)` tạo một list mới, nhưng các tham chiếu đến cùng các object `User`. Bằng cách thay đổi `user.setName()` trong code bên ngoài, bạn thay đổi dữ liệu bên trong class "bất biến".

**Giải pháp**: clone từng phần tử.

### Hiệu Năng

Sao chép các collection lớn là một thao tác có độ phức tạp O(n),
mà với n lớn và các lời gọi thường xuyên tạo ra overhead đáng kể. Trong các "hot path", cân nhắc:
- Các cấu trúc dữ liệu persistent (Vavr)
- Copy-on-write
- Các kiểu bất biến ở cấp độ API

### Tóm Tắt Cho Advanced
- Đối xử với mọi object mutable đầu vào với sự nghi ngờ
- Luôn tạo bản sao của các mảng và các collection tiêu chuẩn
- Phân biệt Shallow và Deep Copy
- Sao chép **trước** khi validate
- Nếu có thể, dùng `List.of`, `Map.copyOf`

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Quy tắc hai điểm: sao chép khi vào (constructor) và khi ra (getter)
- Với Date: `new Date(date.getTime())` — tạo một bản sao độc lập
- Với collection: `List.copyOf(input)` — Java 10+, tạo một bản sao bất biến
- Tấn công TOCTOU: sao chép TRƯỚC khi validate, nếu không dữ liệu thay đổi giữa lúc kiểm tra và lúc sử dụng
- Shallow vs Deep Copy: `List.copyOf(users)` sao chép container, nhưng không sao chép các object User
- Cho sao chép sâu: `stream().map(item -> new Item(item)).toList()`
- Khi defensive copy là dư thừa: API nội bộ được kiểm soát hoàn toàn

**Các câu hỏi phụ thường gặp:**
- *Sao chép cái gì — đầu vào hay đầu ra?* — Cả hai: dữ liệu đầu vào và dữ liệu trả về từ getter
- *List.copyOf vs Collections.unmodifiableList?* — List.copyOf tạo một bản sao; unmodifiableList — một wrapper trên bản gốc
- *Làm gì với các object mutable lồng nhau?* — Deep Copy: clone từng phần tử
- *Khi nào bạn KHÔNG cần sao chép?* — API nội bộ, bên gọi được đảm bảo không mutate

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Bạn có thể trả về bản gốc nếu getter là private" — các lập trình viên tương lai có thể không đọc tài liệu
- "unmodifiableList trong constructor là đủ" — đó là một wrapper, bản gốc có thể bị thay đổi
- "clone() là một cách bình thường để sao chép" — clone() được coi là hỏng
- "Sao chép luôn tốn kém" — với các collection nhỏ, overhead không đáng kể

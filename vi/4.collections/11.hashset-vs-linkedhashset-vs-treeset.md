# What is the difference between HashSet, LinkedHashSet and TreeSet? (Sự khác nhau giữa HashSet, LinkedHashSet và TreeSet là gì?)

## 🟢 Junior Level

**HashSet, LinkedHashSet và TreeSet** — ba cài đặt của Set (một collection các phần tử duy nhất).

**Sự khác biệt chính:**

|              | HashSet                  | LinkedHashSet                          | TreeSet                                 |
| ------------ | ------------------------ | -------------------------------------- | --------------------------------------- |
| **Thứ tự**   | Không có                 | Thứ tự chèn vào                        | Sắp xếp                                 |
| **Tốc độ**   | Nhanh O(1) hash table    | Trung bình O(1) + overhead của linked list | Chậm hơn O(log n) cây đỏ-đen         |
| **null**     | ✅ Cho phép               | ✅ Cho phép                            | ❌ Không cho phép                        |

**Ví dụ:**
```java
// HashSet: không có thứ tự
Set<String> hs = new HashSet<>();
hs.add("C"); hs.add("A"); hs.add("B");
// Thứ tự phụ thuộc vào hashCode() — có thể khác nhau giữa các JVM!
// → [A, C, B] (không đảm bảo thứ tự)

// LinkedHashSet: thứ tự chèn vào
Set<String> lhs = new LinkedHashSet<>();
lhs.add("C"); lhs.add("A"); lhs.add("B");
// → [C, A, B] (như đã chèn vào)

// TreeSet: được sắp xếp
Set<String> ts = new TreeSet<>();
ts.add("C"); ts.add("A"); ts.add("B");
// → [A, B, C] (được sắp xếp!)
```

## 🟡 Middle Level

### HashSet

```java
// Bên trong: HashMap
// Độ phức tạp: O(1) cho add/remove/contains
Set<String> set = new HashSet<>();

// ⚠️ Thứ tự phụ thuộc vào hashCode()
// Thứ tự có thể thay đổi khi resize!

// Iterate: O(capacity + size)
// → HashSet(1_000_000) rỗng → iterate chậm!
```

### LinkedHashSet

```java
// Bên trong: LinkedHashMap
// Độ phức tạp: O(1) cho add/remove/contains
// + danh sách liên kết đôi để giữ thứ tự

Set<String> set = new LinkedHashSet<>();
// Giữ nguyên thứ tự CHÈN VÀO

// Iterate: O(size) — nhanh hơn HashSet!
// → Không phụ thuộc vào capacity
// HashSet iterate qua TẤT CẢ các bucket kể cả các bucket rỗng (O(capacity + size)). LinkedHashSet chỉ iterate qua các phần tử của danh sách liên kết (O(size)). Sự khác biệt đáng chú ý khi fill factor thấp.

// Bộ nhớ: +2 tham chiếu cho mỗi phần tử (next, before)
```

### TreeSet

```java
// Bên trong: TreeMap (cây đỏ-đen)
// Độ phức tạp: O(log n) cho tất cả các thao tác
Set<String> set = new TreeSet<>();

// Điều hướng (navigation):
set.add("A"); set.add("C"); set.add("E");
set.floor("D");   // → "C" (nhỏ hơn gần nhất)
set.ceiling("D"); // → "E" (lớn hơn gần nhất)
set.subSet("A", "D"); // → [A, C] (khoảng — range)
```

### Khi nào dùng cái nào

| Kịch bản                        | Chọn cái gì                                            |
| ------------------------------- | ------------------------------------------------------ |
| Tính duy nhất, tốc độ           | **HashSet**                                            |
| Tính duy nhất + thứ tự chèn vào | **LinkedHashSet**                                      |
| Sắp xếp + các khoảng            | **TreeSet**                                            |
| Cache theo thứ tự truy cập      | **LinkedHashMap (accessOrder=true)**, KHÔNG phải LinkedHashSet |

### Bẫy: các phần tử có thể thay đổi (mutable)

```java
// ❌ Nguy hiểm!
Set<Person> set = new HashSet<>();
Person p = new Person("Ivan");
set.add(p);
p.setName("Petr");  // hashCode() đã thay đổi!
set.contains(p);    // → FALSE! Đối tượng bị "mất"

// ✅ Hãy dùng các đối tượng bất biến (immutable)
record Person(String name) {}  // Bất biến!
```

---

### Khi nào KHÔNG nên dùng

- **HashSet:** nếu cần thứ tự iterate — hãy dùng LinkedHashSet
- **LinkedHashSet:** nếu bộ nhớ hạn chế (+50% overhead của linked list) — hãy dùng HashSet
- **TreeSet:** nếu không cần sắp xếp (chậm hơn HashMap 50 lần) — hãy dùng HashSet

## 🔴 Senior Level

### Memory Footprint (mức chiếm dụng bộ nhớ)

```
HashSet (JVM 64-bit, Compressed OOPs):
  Node: 32 byte overhead cho mỗi phần tử

LinkedHashSet:
  Node: 48 byte (thêm next/before)

TreeSet:
  Entry: 40+ byte (left, right, parent, color)

→ Với 1 triệu Long:
  HashSet: ~36 MB
  LinkedHashSet: ~52 MB
  TreeSet: ~44 MB
```

### Java 21: SequencedSet

```java
// LinkedHashSet và TreeSet → SequencedSet
LinkedHashSet<String> set = new LinkedHashSet<>();
set.addFirst("A");    // Phương thức mới!
set.addLast("Z");     // Phương thức mới!
set.getFirst();       // Phương thức mới!
set.reversed();       // Thứ tự đảo ngược (view)

// HashSet KHÔNG phải là SequencedSet (không có thứ tự)
```

### Iterator của HashSet là O(capacity + size)

```java
// ❌ Chậm: capacity 1 triệu, size 10
HashSet<String> set = new HashSet<>(1_000_000);
for (int i = 0; i < 10; i++) set.add("x");

for (String s : set) { ... }
// → Iterate qua 1 triệu bucket!

// ✅ LinkedHashSet: O(size) = 10 lần iterate
```

### LRU Cache với LinkedHashSet

```java
// LinkedHashMap với accessOrder = true
Map<K, V> cache = new LinkedHashMap<>(16, 0.75f, true) {
    protected boolean removeEldestEntry(Map.Entry eldest) {
        return size() > MAX_SIZE;  // Loại bỏ phần tử cũ nhất
    }
};

// get() di chuyển phần tử về cuối → loại bỏ theo LRU
```

### compareTo so với equals

```java
// TreeSet dùng compareTo, KHÔNG phải equals!
class Person implements Comparable<Person> {
    String name;
    public int compareTo(Person o) {
        return name.compareTo(o.name);
    }
    public boolean equals(Object o) {
        return false;  // Logic khác!
    }
}

// Nếu compareTo = 0 → phần tử sẽ KHÔNG được thêm vào
// Ngay cả khi equals = false!
```

### Kinh nghiệm Production

**Tình huống thực tế: Iterate HashSet giết chết latency**
- HashSet(capacity 10 triệu, 100 phần tử)
- Iterate: 50 ms (duyệt qua 10 triệu bucket!)
- Giải pháp: LinkedHashSet
- Kết quả: 0.01 ms (100 phần tử)

### Best Practices

1. **HashSet** — lựa chọn mặc định cho tính duy nhất
2. **LinkedHashSet** — khi thứ tự quan trọng
3. **TreeSet** — cho sắp xếp và các khoảng
4. **Các phần tử bất biến** — bắt buộc!
5. **initialCapacity** cho HashSet — tránh resize
6. **Java 21** → API SequencedSet
7. **Kiểu nguyên thủy (primitive)** → fastutil/Trove (ít bộ nhớ hơn)

### Tóm tắt cho Senior

- **HashSet** = O(1), không có thứ tự, iterate O(capacity+size)
- **LinkedHashSet** = O(1), thứ tự chèn vào, iterate O(size)
- **TreeSet** = O(log n), sắp xếp, điều hướng, các khoảng
- **Bộ nhớ:** HashSet < TreeSet < LinkedHashSet
- **SequencedSet (Java 21)** → getFirst/reversed
- **Các phần tử bất biến** — cực kỳ quan trọng!
- **compareTo ≠ equals** → mất dữ liệu trong TreeSet

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- HashSet = O(1), không có thứ tự, bên trong là HashMap, iterate O(capacity + size)
- LinkedHashSet = O(1), thứ tự chèn vào, bên trong là LinkedHashMap, iterate O(size)
- TreeSet = O(log n), sắp xếp, bên trong là TreeMap (cây đỏ-đen), điều hướng (floor/ceiling/subSet)
- LinkedHashSet lưu thứ tự thông qua danh sách liên kết đôi (+2 tham chiếu cho mỗi phần tử)
- Iterate HashSet duyệt qua TẤT CẢ các bucket kể cả các bucket rỗng — LinkedHashSet chỉ duyệt qua các phần tử
- TreeSet dùng compareTo cho tính duy nhất, không phải equals
- Các phần tử mutable thì nguy hiểm: thay đổi hashCode() sau khi thêm vào = phần tử bị mất
- Java 21: API SequencedSet (getFirst, addLast, reversed) cho LinkedHashSet và TreeSet

**Các câu hỏi phụ thường gặp:**
- **Tại sao iterate HashSet chậm hơn khi capacity lớn?** — Vì nó duyệt tất cả các bucket (O(capacity + size)), kể cả các bucket rỗng. LinkedHashSet chỉ duyệt danh sách liên kết (O(size)).
- **Khi nào TreeSet từ chối một phần tử?** — Khi compareTo trả về 0, ngay cả khi equals trả về false.
- **Điều gì xảy ra nếu bạn thay đổi (mutate) một phần tử trong HashSet sau khi thêm nó?** — hashCode() thay đổi, phần tử kết thúc ở "sai" bucket — contains trả về false.
- **Chọn Set nào cho một LRU cache?** — LinkedHashMap với accessOrder=true và removeEldestEntry được override.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "TreeSet dùng equals để kiểm tra tính duy nhất" — nó dùng compareTo!
- ❌ "HashSet giữ nguyên thứ tự chèn vào" — không, thứ tự không được đảm bảo
- ❌ "Bạn có thể yên tâm thay đổi các phần tử mutable trong một Set" — điều này phá vỡ hợp đồng hashCode/equals
- ❌ "LinkedHashSet chậm hơn HashSet cho tất cả các thao tác" — chỉ về bộ nhớ, độ phức tạp là như nhau O(1)

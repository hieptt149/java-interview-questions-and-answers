# What is Record and how does it help create immutable classes? (Record là gì và nó giúp gì cho việc tạo immutable class?)

---

## Basic Level

**Record** là một loại class đặc biệt trong Java (được giới thiệu trong Java 14, ổn định từ Java 16) tự động tạo một immutable class để lưu trữ dữ liệu.

### Trước Khi Có Record
```java
public final class Point {
    private final int x;
    private final int y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    public int getX() { return x; }
    public int getY() { return y; }

    @Override public boolean equals(Object o) { ... }
    @Override public int hashCode() { ... }
    @Override public String toString() { ... }
}
```

### Với Record
```java
public record Point(int x, int y) {}
```
Một dòng thay vì 20+. Tự động:
- Class là `final`
- Các trường là `private final`
- Constructor
- Các getter (`x()`, `y()` — không phải `getX()`)
- `equals()`, `hashCode()`, `toString()`

## Intermediate Level

### Những Gì Trình Biên Dịch Làm Cho Bạn

```java
public record User(String name, int age) {}
```

Sinh ra:
```java
public final class User extends java.lang.Record {
    private final String name;
    private final int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String name() { return name; }
    public int age() { return age; }

    // equals, hashCode, toString — trên tất cả các trường
}
```

### Tính Bất Biến Nông (Shallow)

`record` đảm bảo rằng **các tham chiếu** sẽ không thay đổi. Nhưng nếu một trường là một collection mutable, nội dung của nó vẫn có thể bị sửa đổi:
```java
public record Order(Long id, List<String> items) {}

Order order = new Order(1L, new ArrayList<>(List.of("A")));
order.items().add("B"); // CÓ THỂ! items — cùng một list
```

### Giải Pháp — Compact Constructor
```java
public record Order(Long id, List<String> items) {
    public Order {
        items = List.copyOf(items); // defensive copy
    }
}
```

### Khi Nào Dùng
- **DTO** — chuyển dữ liệu giữa các layer
- **Map key** — hashCode ổn định
- **Cấu trúc local** — lưu trữ tuple tạm thời

## Advanced Level

### Các Giới Hạn

- Không thể kế thừa các class khác (đã kế thừa `java.lang.Record`)
- Không thể là base class (luôn `final`)
- Không thể có các trường `instance` nào khác ngoài những trường được khai báo trong header
- Không thể là `abstract`

### Record vs Lombok @Value vs Final Class Thông Thường

|              | Record  | Lombok @Value | Final class |
| ------------ | ------- | ------------- | ----------- |
| Boilerplate  | Tối thiểu | Tối thiểu   | Thủ công    |
| Kế thừa      | Không   | Có thể        | Có thể      |
| Các trường bổ sung | Không | Có thể   | Có thể      |
| Dependency   | JDK     | Lombok        | Không có    |

### Compact Constructor Và Validate
```java
public record User(String email, int age) {
    public User {
        Objects.requireNonNull(email, "Email required");
        if (age < 0) throw new IllegalArgumentException("Age must be positive");
    }
}
```

### Các Method Tùy Chỉnh
```java
public record Rectangle(int width, int height) {
    public int area() {
        return width * height;
    }
}
```

### Tóm Tắt Cho Advanced
- `record` — một cấu trúc ngôn ngữ đặc biệt cho các value class bất biến.
  Đây không chỉ là cú pháp đường (syntactic sugar) — record có những giới hạn riêng (không thể kế thừa,
  không thể có các trường instance nào khác ngoài các trường đã khai báo)
- Giảm đáng kể khối lượng code và khả năng lỗi trong `equals/hashCode`
- Vẫn cần sao chép collection thủ công
- Dùng cho DTO, Map key, các cấu trúc tạm thời
- Không thể tham gia vào các hệ thống phân cấp kế thừa

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Record (Java 14+, ổn định Java 16) — cấu trúc ngôn ngữ đặc biệt cho các value class bất biến
- Tự động: class `final`, các trường `private final`, constructor, getter (`name()` không phải `getName()`), equals/hashCode/toString
- Tính bất biến nông: các tham chiếu bất biến, nhưng các collection mutable vẫn có thể bị sửa đổi
- Compact constructor: `public Order { items = List.copyOf(items); }` — để sao chép defensive
- Các giới hạn: không kế thừa, không có trường instance bổ sung, không `abstract`
- Record vs Lombok @Value: Record — JDK, không dependency; Lombok — nhiều tính linh hoạt hơn

**Các câu hỏi phụ thường gặp:**
- *Record có sao chép sâu các collection không?* — Không, chỉ nông; cần làm thủ công trong compact constructor
- *Bạn có thể thêm một trường vào Record không?* — Không, chỉ những trường được khai báo trong header
- *Record có thể được kế thừa không?* — Không, luôn `final`; không thể là base class
- *Getter trong Record có phải là getX() không?* — Không, chỉ là `x()` — không có tiền tố get

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Record hoàn toàn bất biến" — các collection cần được sao chép thủ công
- "Record có thể được mở rộng" — luôn final, không kế thừa
- "Record thay thế Lombok" — Lombok @Builder, @Singular cung cấp nhiều chức năng hơn
- "Record chỉ là cú pháp đường" — record có những giới hạn và ngữ nghĩa riêng

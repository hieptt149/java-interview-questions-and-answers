# What is a Bean in Spring? (Bean trong Spring là gì?)

## Junior Level

**Bean** là một đối tượng được quản lý bởi Spring Container (ApplicationContext).

**"Được quản lý" nghĩa là:** Spring tự tạo đối tượng, inject các phụ thuộc của nó, có thể bọc nó trong một proxy để thêm hành vi (transaction, security, caching), và gọi các phương thức khởi tạo/dọn dẹp. Bạn không làm `new Bean()` — Spring làm.

**Ví dụ minh họa đơn giản:** Spring là một khách sạn. Một bean là một vị khách đã đăng ký và nhận mọi dịch vụ từ khách sạn.

**Đối tượng thông thường:**
```java
User user = new User();  // Bạn tự tạo
```

**Bean:**
```java
@Service  // Spring sẽ tự tạo và quản lý nó
public class UserService { }
```

**Sự khác nhau:**

| Đối tượng thông thường   | Spring Bean   |
| ---------------- | ------------- |
| Bạn tạo bằng `new` | Spring tự tạo
| Bạn quản lý vòng đời | Spring quản lý vòng đời
| Không có phụ thuộc | Phụ thuộc được inject tự động
| Không có proxy | Có thể được bọc trong Proxy

## Middle Level

### BeanDefinition

```
BeanDefinition = "công thức" để tạo một bean
  -> Tên class
  -> Scope (Singleton, Prototype)
  -> Các phụ thuộc
  -> Các phương thức Init/Destroy

-> Spring trước tiên tạo BeanDefinition
-> Rồi tạo một bean từ nó
```

### Cách tạo một Bean

**1. Các annotation stereotype:**
```java
@Component       // Cơ sở
@Service         // Logic nghiệp vụ
@Repository      // Truy cập database
@Controller      // Web controller
```

**2. Java Config:**
```java
@Configuration
public class Config {
    @Bean
    public ObjectMapper mapper() {
        return new ObjectMapper();
    }
}
```

### Proxy hóa

```java
@Transactional  // Spring sẽ tạo một Proxy bao quanh bean
public void save() { }

// Bạn nhận được không phải đối tượng, mà là một Proxy!
// Proxy -> chặn lời gọi -> thêm transaction -> gọi phương thức
```

### Các cách khai báo

```
1. @Component + @ComponentScan -> quét tự động
2. @Bean trong @Configuration -> cấu hình thủ công
3. @Import -> import các configuration
```

## Senior Level

### DefaultListableBeanFactory

```
Trái tim của Spring:
  -> BeanDefinitionRegistry -> lưu trữ các công thức
  -> Singleton Objects Cache -> lưu trữ các bean đã tạo

-> ConcurrentHashMap để đảm bảo thread safety
-> Khởi tạo lazy (trừ Singleton theo mặc định)
```

### Các loại Proxy

```
JDK Dynamic Proxy — cơ chế có sẵn của Java để proxy CHỈ qua interface. Tạo một đối tượng implement cùng interface và ủy quyền các lời gọi cho đối tượng thật.

JDK Dynamic Proxy:
  -> Nếu class implement một interface
  -> Chỉ proxy các phương thức của interface

CGLIB — thư viện để tạo các subclass lúc runtime. Spring dùng nó khi một class không implement interface nào. Subclass chặn các lời gọi phương thức và thêm hành vi.

CGLIB:
  -> Nếu không có interface
  -> Tạo subclass lúc runtime
  -> Không thể proxy các phương thức final!
```

### Bean so với POJO

```
POJO và Bean KHÔNG phải là các loại class khác nhau. Cùng một class có thể là một POJO (tạo bằng `new`) hoặc một Bean (được Spring tạo). Sự khác nhau là AI tạo ra đối tượng và ai quản lý nó.

POJO:
  -> new User()
  -> Bạn quản lý

Bean:
  -> Được tạo qua Reflection/CGLIB
  -> DI các phụ thuộc
  -> Có thể là một Proxy
  -> Vòng đời: @PostConstruct, @PreDestroy
  -> Được quản lý bởi container
```

### Kinh nghiệm Production

**Tình huống thực tế: CGLIB không thể proxy final**
```java
@Service
public class UserService {
    public final void save() { }  // final!
}

// @Transactional trên save() sẽ KHÔNG hoạt động!
// CGLIB không thể override một phương thức final
// -> Không có transaction -> bug trên production
```

### Khi nào KHÔNG nên biến một đối tượng thành Bean

1. **DTO / Entity / Value Object** — đây là các đối tượng dữ liệu thông thường, tạo bằng `new` hoặc bởi ORM
2. **Tiện ích cục bộ** — các phương thức static không cần bean
3. **Đối tượng có vòng đời ngắn** — được tạo và hủy trong phạm vi một request duy nhất

### Best Practices

1. **@Component/@Service** cho code của bạn
2. **@Bean** cho các thư viện bên thứ ba
3. **Nhớ về Proxy** — các phương thức final không được proxy (CGLIB tạo một subclass, final không thể override). Trong Spring Boot 2.2+ @Configuration có thể dùng `proxyBeanMethods = false` để tắt CGLIB — điều này tăng tốc khởi động.
4. **BeanDefinition** có thể được sửa đổi qua BeanFactoryPostProcessor
5. **Quét (scanning)** chậm trên các dự án lớn -> hạn chế các package

### Tóm tắt cho Senior

- **Bean** = đối tượng được Spring quản lý
- **BeanDefinition** = thông tin meta để tạo
- **Proxy** -> @Transactional, @Async, @Cacheable
- **CGLIB** -> subclass, không proxy final
- **JDK Proxy** -> chỉ interface
- **BeanFactory** -> trái tim của container

## Interview Cheat Sheet

**Cần phải biết:**
- Bean là một đối tượng được Spring Container (ApplicationContext) quản lý: tạo, inject phụ thuộc, proxy, gọi init/destroy
- Bạn không làm `new Bean()` — Spring làm qua Reflection hoặc CGLIB
- BeanDefinition = "công thức" của bean: tên class, scope, các phụ thuộc, các phương thức init/destroy
- Các annotation stereotype: `@Component`, `@Service`, `@Repository`, `@Controller`
- `@Bean` trong `@Configuration` — cho các thư viện bên thứ ba và cấu hình phức tạp
- Spring có thể bọc một bean trong một Proxy cho `@Transactional`, `@Async`, `@Cacheable`
- CGLIB không thể proxy các phương thức `final` — `@Transactional` trên chúng sẽ không hoạt động
- DTO, Entity, Value Object — KHÔNG nên là bean

**Các câu hỏi phụ thường gặp:**
- **Bean khác POJO như thế nào?** Cùng một class có thể là POJO (`new User()`) hoặc Bean (được Spring tạo). Sự khác nhau là ai tạo ra nó và ai quản lý nó.
- **Khi nào CGLIB so với JDK Dynamic Proxy?** JDK Proxy — nếu có interface, CGLIB — nếu không. JDK chỉ proxy các phương thức của interface.
- **Có thể thay đổi BeanDefinition trước khi tạo không?** Có, qua `BeanFactoryPostProcessor`.
- **Tại sao một phương thức `final` không hoạt động với `@Transactional`?** CGLIB tạo một subclass, `final` không thể override — transaction sẽ không được thêm vào.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Mọi đối tượng đều nên là bean" (DTO, Entity, Value Object là các đối tượng thông thường)
- "Spring Bean là một loại class riêng biệt" (Bean và POJO không phải các loại class khác nhau, khác biệt nằm ở việc quản lý)
- "`@Transactional` hoạt động trên bất kỳ phương thức nào" (không trên `final` — CGLIB không thể override)
- "Proxy là cùng một đối tượng" (Proxy là một lớp bọc chặn các lời gọi và thêm hành vi)

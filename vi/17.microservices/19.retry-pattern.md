# What is Retry pattern and how to use it correctly (Retry pattern là gì và cách dùng nó đúng cách)

## 🟢 Junior Level

**Retry** là việc gọi lại tự động một service khi có lỗi tạm thời.

```
Call 1 → lỗi (timeout)
Retry 1 → lỗi (timeout)
Retry 2 → thành công! ✅
```

**Tại sao:** Các lỗi tạm thời xảy ra thường xuyên (network, timeout, quá tải). Retry cho service thời gian để phục hồi.

---

## 🟡 Middle Level

### Resilience4j Retry

```java
RetryConfig config = RetryConfig.custom()
    .maxAttempts(3)  // 3 lần thử
    .waitDuration(Duration.ofSeconds(1))  // chờ 1 giây giữa các lần thử
    .retryExceptions(TimeoutException.class, ConnectException.class)
    .build();

Retry retry = Retry.of("backend", config);

Supplier<String> decorated = Retry.decorateSupplier(retry,
    () -> backendService.call());
```

### Exponential Backoff

```java
RetryConfig config = RetryConfig.custom()
    .maxAttempts(5)
    .waitDuration(Duration.ofMillis(500))
    .intervalFunction(IntervalFunction.ofExponentialBackoff(500, 2.0))
    .build();

// 500 = delay ban đầu (ms), 2.0 = hệ số nhân (exponential).
// 500ms → 1000ms → 2000ms → 4000ms ...

// Các lần thử: 500ms → 1s → 2s → 4s → 8s
```

### Các Lỗi Thường Gặp

1. **Retry tất cả các lỗi:**
```
404 Not Found → retry vô ích
500 Internal Error → retry có thể giúp
Giải pháp: chỉ retry các lỗi có thể retry
```

## 🔴 Senior Level

### Retry Với Jitter

```java
// Jitter ngăn ngừa thundering herd
// Thundering herd — khi nhiều client retry đồng thời,
// tạo ra một đợt tăng tải mới. Jitter "trải" các lần retry ra theo thời gian.
Random random = new Random();
long waitTime = baseDelay + random.nextInt((int)(baseDelay * 0.1)); // jitter 10% của delay
```

### Kinh Nghiệm Production

**Spring Retry:**
```java
@Retryable(
    value = {RetryableException.class},
    maxAttempts = 3,
    backoff = @Backoff(delay = 1000, multiplier = 2)
)
// @Recover — phương thức được gọi khi tất cả các lần retry đã hết.
// Chữ ký: cùng kiểu trả về + Exception như tham số đầu tiên.
public String callService(String input) {
    return restTemplate.getForObject(url, String.class);
}

@Recover
public String recover(RetryableException e) {
    return "fallback";
}
```

### Best Practices

```
✅ Exponential backoff
✅ Jitter để ngăn ngừa thundering herd
✅ Chỉ retry cho các lỗi có thể retry
✅ Giới hạn số lần thử
✅ Fallback sau khi hết tất cả các lần retry

❌ Retry cho các lỗi 4xx
❌ Không có backoff
❌ Không có giới hạn số lần thử
❌ Retry cho các thao tác idempotent
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Retry — gọi lại tự động khi có lỗi tạm thời (timeout, network)
- Exponential backoff: 500ms → 1s → 2s → 4s — cho service thời gian để phục hồi
- Jitter thêm tính ngẫu nhiên để ngăn ngừa thundering herd
- Chỉ retry cho các lỗi có thể retry (TimeoutException, ConnectException)
- 4xx (Not Found, Bad Request) — retry vô ích, server sẽ không tự sửa
- maxAttempts là bắt buộc — retry vô hạn = treo
- Fallback sau khi hết tất cả các lần thử

**Các câu hỏi phụ thường gặp:**
- **Thundering herd là gì?** Nhiều client retry đồng thời — jitter "trải" các lần retry ra theo thời gian.
- **Những lỗi nào có thể retry?** Timeout, connection refused, 5xx. KHÔNG thể retry: 4xx, các business exception.
- **Công thức exponential backoff?** delay = baseDelay * multiplier^attempt, ví dụ 500ms, 1s, 2s, 4s.
- **Spring Retry vs Resilience4j?** Spring Retry đơn giản hơn, Resilience4j linh hoạt hơn (bulkhead, circuit breaker, time limiter).

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Retry cho tất cả các lỗi" — không, retry 404 là vô ích
- "Retry không có giới hạn = đáng tin cậy hơn" — không, retry vô hạn = hệ thống treo
- "Không cần jitter, server sẽ xử lý" — không có jitter, thundering herd sẽ xảy ra
- "Retry = idempotency không quan trọng" — cực kỳ quan trọng, request trùng lặp có thể xảy ra

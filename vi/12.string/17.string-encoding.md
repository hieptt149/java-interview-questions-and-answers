# What is String Encoding? (String Encoding là gì?)

## 🟢 Junior Level

**Encoding (mã hóa)** là một tập hợp các quy tắc xác định cách các ký tự (chữ cái, chữ số, ký hiệu) được chuyển đổi thành byte để lưu trữ và truyền tải, và ngược lại.

Máy tính chỉ hiểu số. Encoding là một "từ điển" nói rằng: "Ký tự 'A' tương ứng với số 1040, ký tự 'B' — số 66" v.v.

**Ví dụ minh họa đơn giản:** Encoding giống như một ngôn ngữ dịch thuật. Bạn nói với người phiên dịch: "Dịch câu này sang tiếng Đức" (encode), rồi sau đó: "Dịch lại sang tiếng Nga" (decode). Nếu cả hai phiên dịch viên dùng cùng một từ điển — mọi thứ sẽ được hiểu đúng.

**Ví dụ:**
```java
String s = "Привет";

// Encode: String → byte[]
byte[] bytes = s.getBytes(StandardCharsets.UTF_8);

// Decode: byte[] → String
String restored = new String(bytes, StandardCharsets.UTF_8);
```

**Các encoding quan trọng nhất:**
| Encoding         | Dùng cho                                                            | Kích thước "Привет" |
| ---------------- | ------------------------------------------------------------------- | ---------------- |
| **UTF-8**        | Internet, file, cơ sở dữ liệu                                          | 12 byte         |
| **UTF-16**       | Định dạng nội bộ của Java 8 trở về trước / cho ký tự không phải Latin trong Java 9+    | 12 byte         |
| **Windows-1251** | Các hệ thống Windows cũ                                                 | 6 byte         |

**Quy tắc chính:** LUÔN chỉ định encoding tường minh! Không bao giờ dựa vào encoding mặc định — nó khác nhau trên Windows và Linux.

## 🟡 Middle Level

### Cách Java Lưu Trữ Chuỗi Nội Bộ

**Trước Java 9:** Các chuỗi được lưu dưới dạng `char[]` với encoding **UTF-16** (luôn 2 byte mỗi ký tự).

**Java 9+ (Compact String):** Java tự động chọn định dạng tối ưu:
- Chỉ có các ký tự Latin (U+0000–U+00FF) → **Latin-1** (1 byte/ký tự)
- Có các ký tự không phải Latin → **UTF-16** (2 byte/ký tự)
- Quyết định được lưu trong trường `coder` (0 = Latin-1, 1 = UTF-16)

### Chuyển Đổi Trong Quá Trình I/O

Khi một chuỗi rời khỏi JVM (ghi file, gửi qua mạng, query DB), nó phải được chuyển đổi sang byte với encoding được chỉ định:

```java
// ✅ TỐT — encoding tường minh
byte[] bytes = str.getBytes(StandardCharsets.UTF_8);
String str = new String(bytes, StandardCharsets.UTF_8);

// ❌ XẤU — encoding mặc định phụ thuộc vào OS!
byte[] bytes = str.getBytes();           // Windows-1251 trên Windows, UTF-8 trên Linux
String str = new String(bytes);          // Có thể tạo ra "văn bản lỗi ký tự"
```

### Bảng Các Lỗi Điển Hình

| Lỗi                              | Hậu quả                             | Giải pháp                                                        |
| ------------------------------------ | ---------------------------------------- | --------------------------------------------------------------- |
| `new String(bytes)` không có encoding | "Văn bản lỗi ký tự" khi đổi OS              | Luôn `new String(bytes, StandardCharsets.UTF_8)`              |
| `getBytes()` không có encoding        | Không thể decode trên hệ thống khác          | Luôn `getBytes(StandardCharsets.UTF_8)`                       |
| Nhầm lẫn `str.length()` và `bytes.length` | Logic xử lý dữ liệu sai       | `"Привет".length()` = 6, `"Привет".getBytes(UTF_8).length` = 12 |

### So Sánh Các Encoding Phổ Biến

| Encoding     | Byte/ký tự     | Hỗ trợ          | Tương thích           |
| ------------ | -------------- | ---------------- | ------------------------ |
| UTF-8        | 1–4 (biến đổi) | Toàn bộ Unicode      | Tương thích ASCII        |
| UTF-16 LE/BE | 2–4            | Toàn bộ Unicode      | Cần BOM hoặc thỏa thuận|
| Latin-1      | 1              | Tây Âu | Không hỗ trợ Cyrillic|
| Windows-1251 | 1              | Cyrillic          | Chỉ Windows|
| ASCII        | 1              | 128 ký tự   | Không hỗ trợ Cyrillic|

### Khi Nào KHÔNG Nên Chuyển Đổi Sang String
- **Dữ liệu nhị phân** (hình ảnh, protobuf, file nén) — làm việc trực tiếp với `byte[]`
- **Các hệ thống độ trễ cực thấp** — chuyển đổi thêm overhead 50–200ns
- **Dữ liệu stream với encoding không rõ** — dùng `BOMInputStream` hoặc auto-detect

## 🔴 Senior Level

### Hiện Thực Nội Bộ — Compact String Và Encoding

```java
public final class String {
    @Stable
    private final byte[] value;  // byte[] thay vì char[] (Java 9+)
    private final byte coder;    // LATIN1=0 hoặc UTF16=1
}
```

Khi `getBytes(Charset)` được gọi:
1. Kiểm tra `coder` hiện tại của String
2. Chọn thuật toán encoding trong `StringCoding.encode(value, coder, charset)`
3. Với UTF-8: chuyển đổi từng ký tự qua `CharsetEncoder`
   - Latin-1 → UTF-8: 1 byte → 1 byte (ASCII), 1 byte → 2 byte (Latin-1 mở rộng)
   - UTF-16 → UTF-8: 2 byte → 1–3 byte (tùy code point)

Khi `new String(byte[], Charset)`:
1. `StringCoding.decode(bytes, charset)` → `byte[] value` + `coder`
2. Nếu decoder phát hiện byte không hợp lệ → thay thế bằng `�` (ký tự thay thế)

### Các Trường Hợp Biên (Tối Thiểu 3)

**1. BOM (Byte Order Mark):**
```java
byte[] withBom = {(byte)0xEF, (byte)0xBB, (byte)0xBF, (byte)'H', (byte)'i'};
String s = new String(withBom, StandardCharsets.UTF_8);
// s.charAt(0) = '﻿' — ký tự vô hình!
// s.startsWith("Hi") → false!
```
Giải pháp: `BOMInputStream` (Apache Commons IO) hoặc kiểm tra thủ công 3 byte đầu.

**2. Input dị dạng — các chuỗi UTF-8 không hợp lệ:**
```java
byte[] bad = {(byte) 0xFF, (byte) 0xFE};
String s = new String(bad, StandardCharsets.UTF_8);
// Kết quả: "��" — các ký tự thay thế
```
Hành vi phụ thuộc vào `CodingErrorAction` (mặc định là REPLACE, có thể đổi thành REPORT hoặc IGNORE).

**3. Charset encoding roundtrip — mất dữ liệu:**
```java
String s = "Привет";
byte[] ascii = s.getBytes(StandardCharsets.US_ASCII);
// "??????" — Cyrillic không được hỗ trợ trong ASCII, thay bằng '?'
// Chuyển đổi ngược là không thể — dữ liệu bị mất!
```

**4. Bảo mật — bypass encoding:**
```java
// SQL injection thông qua bypass encoding đa byte
String input = "%C0%27 OR 1=1 --";
// Một số hệ thống cũ decode %C0%27 thành một dấu nháy đơn
// Luôn validate input SAU KHI decode, không phải trước!
```

### Hiệu Năng

| Thao tác        | UTF-8   | UTF-16   | Latin-1   |
| ---------------- | ------- | -------- | --------- |
| Encode "Hello"   | ~5ns    | ~3ns     | ~2ns      |
| Encode "Привет"  | ~15ns   | ~5ns     | N/A       |
| Decode 12 byte  | ~10ns   | ~5ns     | ~3ns      |
| Encode văn bản 10KB | ~500ns  | ~150ns   | ~80ns     |

// UTF-8 cho Cyrillic = 2 byte/ký tự với logic encoding đa byte.
// UTF-16 = sao chép trực tiếp 1:1 cho các ký tự BMP — nhanh hơn.

**Bộ nhớ (Java 9+):**
- Chuỗi Latin-1: 24 byte (object) + 16 + N (byte[]) → ~40+N byte
- Chuỗi UTF-16: 24 byte (object) + 16 + 2N (byte[]) → ~40+2N byte
- Tiết kiệm cho ASCII/Latin-1: **~50% bộ nhớ**

### Thread Safety

Các class `StandardCharsets`, `Charset`, `CharsetEncoder`, `CharsetDecoder`:
- `StandardCharsets.UTF_8` — thread-safe (singleton bất biến)
- `CharsetEncoder` / `CharsetDecoder` — **KHÔNG thread-safe**! Một instance duy nhất không thể được dùng từ nhiều thread đồng thời
- Giải pháp: tạo encoder/decoder mới cho mỗi thread hoặc dùng `ThreadLocal`

### Câu Chuyện Thực Tế Trong Production

**Kịch bản:** Microservice trên Linux (Spring Boot) đọc dữ liệu từ hệ thống Windows legacy.

Hệ thống Windows gửi dữ liệu bằng `Windows-1251`. Service Linux đọc byte như `UTF-8` (encoding mặc định của Linux) → "văn bản lỗi ký tự" trong log. Khách hàng phàn nàn về phản hồi không chính xác.

Chẩn đoán: `Charset.defaultCharset()` trên Linux = UTF-8, trên Windows = Windows-1251 (hoặc Cp1252).

Sửa lỗi:
```java
// Encoding tường minh ở cấp độ giao thức
String text = new String(bytes, Charset.forName("Windows-1251"));
```
Giải pháp lâu dài: thống nhất UTF-8 ở cấp độ hợp đồng API giữa tất cả các service.

**Kịch bản 2:** Phản hồi HTTP API với Cyrillic — không có `Content-Type: application/json; charset=UTF-8`, trình duyệt hiểu phản hồi như ISO-8859-1, Cyrillic biến thành "văn bản lỗi ký tự".

### Best Practices Cho Highload

- **Luôn** chỉ định `Charset` — dùng `StandardCharsets.UTF_8` (hằng số, không cấp phát)
- Cho JSON/XML/HTTP: UTF-8 — chuẩn thực tế (de facto)
- Cho dữ liệu nhị phân: làm việc trực tiếp với `byte[]`/`ByteBuffer`, **đừng chuyển sang String**
- `CharsetEncoder`/`CharsetDecoder` — **đừng chia sẻ giữa các thread**, tạo cho mỗi thread hoặc dùng `ThreadLocal`
- Cho độ trễ cực thấp: tránh String cho I/O — dùng `ByteBuf` (Netty), các cách tiếp cận zero-copy
- Xử lý BOM: `BOMInputStream` hoặc kiểm tra thủ công các byte đầu trước khi decode
- Bảo mật: validate input SAU KHI decode, dùng so sánh thời gian hằng số cho các bí mật

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Encoding — các quy tắc chuyển đổi ký tự thành byte và ngược lại
- UTF-8 — chuẩn thực tế cho internet, JSON, HTTP (tương thích ASCII, 1-4 byte/ký tự)
- Java 9+: Compact String — Latin-1 (1 byte/ký tự) hoặc UTF-16 (2 byte/ký tự) tự động
- `getBytes()` không có encoding phụ thuộc vào OS — kết quả khác nhau trên Windows và Linux
- `CharsetEncoder`/`CharsetDecoder` — KHÔNG thread-safe, không thể chia sẻ giữa các thread
- BOM (Byte Order Mark) — ký tự vô hình `﻿` ở đầu file UTF-8

**Các câu hỏi phụ thường gặp:**
- **Tại sao không thể dùng `getBytes()` không có encoding?** — Encoding mặc định phụ thuộc vào OS. Trên Windows có thể là Cp1251, trên Linux — UTF-8.
- **Cách xử lý BOM?** — `BOMInputStream` (Apache Commons IO) hoặc kiểm tra thủ công 3 byte đầu (`EF BB BF`).
- **Điều gì xảy ra khi decode byte UTF-8 không hợp lệ?** — Thay thế bằng `�` (ký tự thay thế). Có thể cấu hình qua `CodingErrorAction`.
- **Java 9+ lưu trữ chuỗi như thế nào?** — `byte[]` + `coder`: Latin-1 cho U+0000–U+00FF, UTF-16 cho các ký tự khác.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Encoding mặc định — luôn là UTF-8" — phụ thuộc vào OS và locale
- ❌ "`CharsetEncoder` thread-safe" — KHÔNG thread-safe, cần `ThreadLocal` hoặc tạo mỗi lần gọi
- ❌ "Bạn có thể chuyển đổi dữ liệu nhị phân sang String" — mất dữ liệu, làm việc trực tiếp với `byte[]`
- ❌ "BOM — chỉ là vấn đề của UTF-16" — UTF-8 cũng có thể có BOM

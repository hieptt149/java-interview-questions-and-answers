# What is offset in Kafka (Offset trong Kafka là gì)

## Junior Level

### Định Nghĩa

**Offset** là số thứ tự của một message trong một partition.

Offset KHÔNG phải là một ID message duy nhất. Đó là một vị trí trong log. Cùng một message
ở các partition khác nhau có các offset khác nhau. Offset tăng đơn điệu (0, 1, 2...) và không bao giờ
giảm, ngay cả khi các message bị xóa.

Mỗi message nhận một offset duy nhất.

```
Partition 0:
  offset 0: {"user": "user-1", "action": "login"}
  offset 1: {"user": "user-2", "action": "purchase"}
  offset 2: {"user": "user-1", "action": "logout"}
  offset 3: {"user": "user-3", "action": "login"}
```

### Các Thuộc Tính Chính

- Offset là một **số**, bắt đầu từ 0
- Offset chỉ duy nhất **trong một partition duy nhất**
- Offset **không thể thay đổi** sau khi ghi
- Các message được sắp xếp theo offset

### Consumer Dùng Offset Như Thế Nào?

```
Consumer nhớ offset của nó:
  Đọc offset 5 → nhớ 5
  Khi restart → tiếp tục từ offset 6
```

### Ví Dụ Code

```java
ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
for (ConsumerRecord<String, String> record : records) {
    System.out.println("Partition: " + record.partition());
    System.out.println("Offset: " + record.offset());
    System.out.println("Value: " + record.value());
}
```

## Middle Level

### Committed Offset

```
Committed offset — offset đã xử lý cuối cùng được lưu trong Kafka

Consumer đọc offset 5 → xử lý → commit offset 5
Khi restart → tiếp tục từ offset 6
```

### Vị Trí Consumer

```java
// Vị trí hiện tại (offset tiếp theo để đọc)
long position = consumer.position(new TopicPartition("orders", 0));

// Offset đã commit cuối cùng
OffsetAndMetadata committed = consumer.committed(new TopicPartition("orders", 0));
```

### Quản Lý Offset

```java
// Commit thủ công
props.put("enable.auto.commit", "false");

// Commit đồng bộ (đáng tin cậy)
consumer.commitSync();

// Commit bất đồng bộ (nhanh)
consumer.commitAsync((offsets, exception) -> {
    if (exception != null) {
        log.error("Commit failed", exception);
    }
});
```

### Seek — Đọc Từ Một Offset Cụ Thể

```java
TopicPartition partition = new TopicPartition("orders", 0);

// Đọc từ offset cụ thể
consumer.seek(partition, 1000);

// Đọc từ đầu
consumer.seekToBeginning(List.of(partition));

// Đọc từ cuối
consumer.seekToEnd(List.of(partition));
```

### Các Lỗi Thường Gặp

1. **Commit trước khi xử lý:**
```java
consumer.commitSync();  // ❌ commit trước
process(records);       // sau đó xử lý
// Nếu crash → mất dữ liệu
```

2. **Thay đổi offset thủ công không có lý do:**
```
consumer.seek(partition, 0);  // đọc từ đầu
// Có thể gây trùng lặp
```

## Senior Level

### Cài Đặt Nội Bộ

**Topic __consumer_offsets:**
```
Topic Kafka nội bộ để lưu trữ offset
- Compacted (log compaction)
- Lưu trữ offset cho tất cả các consumer group
- Key: group.id + topic + partition
- Value: offset + metadata + timestamp
```

**Định Dạng Lưu Trữ Offset:**
```
Key: [group.id, topic, partition]
Value: {
    offset: long,
    metadata: String,
    leaderEpoch: int,
    timestamp: long
}
```

### Các Chiến Lược Commit Offset

**1. Synchronous Commit:**
```java
// Chặn cho đến khi broker xác nhận
consumer.commitSync();
// Reliable, nhưng chậm hơn
```

**2. Asynchronous Commit:**
```java
// Không chờ xác nhận
consumer.commitAsync((offsets, exception) -> {
    if (exception != null) {
        // Retry hoặc log
        log.error("Commit failed for offsets: {}", offsets, exception);
    }
});
// Nhanh hơn, nhưng có thể mất khi lỗi
```

**3. Batch Commit:**
```java
// Commit mỗi N message
int count = 0;
for (var record : records) {
    process(record);
    if (++count % 100 == 0) {
        consumer.commitAsync();
    }
}
```

### Offset Reset Policy

```java
// auto.offset.reset — hành vi khi không có offset đã commit
props.put("auto.offset.reset", "earliest");  // đọc từ đầu
props.put("auto.offset.reset", "latest");    // đọc từ cuối (mặc định)
props.put("auto.offset.reset", "none");      // exception
```

### Leader Epoch Và Xác Thực Offset

```
Từ Kafka 0.11:
- Leader Epoch được lưu cùng mỗi offset
- Khi failover, consumer có thể xác định
  message nào có thể đã bị mất
- Ngăn mất dữ liệu âm thầm

Leader Epoch — số thế hệ leader partition. Mỗi khi leader thay đổi, epoch
tăng lên. Điều này cho phép consumer xác định message nào có thể đã bị mất
trong quá trình failover.
```

### Giám Sát Offset

**Các metrics chính:**
```
Current Offset → offset đã đọc cuối cùng
Committed Offset → offset đã commit cuối cùng
Log End Offset → offset cuối cùng trong partition
Consumer Lag = Log End Offset - Committed Offset
```

**Giám sát lag:**
```bash
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --describe --group my-group

GROUP           TOPIC  PARTITION  CURRENT-OFFSET  LOG-END-OFFSET  LAG
my-group        orders 0          1000            1200            200
```

LAG=200 nghĩa là: 200 message trong partition chưa được đọc. Tính nghiêm trọng phụ thuộc
vào throughput: ở 100 msg/s — chậm 2 giây (bình thường), ở 1 msg/s —
200 giây (nghiêm trọng).

### Phục Hồi Offset Sau Lỗi

```
Kịch bản:
1. Consumer đọc offset 100
2. Bắt đầu xử lý → crash
3. Chưa commit offset

Khi restart:
- Offset đã commit = 99
- Tiếp tục từ offset 100
- Message 100 sẽ được xử lý lại (at-least-once)
```

### Các Thực Hành Tốt Nhất

```
✅ Commit sau khi xử lý
✅ Commit đồng bộ cho độ tin cậy
✅ Commit bất đồng bộ cho throughput cao
✅ Giám sát lag
✅ Cấu hình auto.offset.reset

❌ Auto commit cho dữ liệu quan trọng
❌ Commit trước khi xử lý
❌ Thay đổi offset thủ công không có lý do
❌ Bỏ qua consumer lag
❌ Không có giám sát offset
```

### Các Quyết Định Kiến Trúc

1. **Committed offset — nền tảng của at-least-once** — đảm bảo delivery
2. **__consumer_offsets — topic nội bộ compacted** — lưu trữ hiệu quả
3. **Xác thực leader epoch** — ngăn mất dữ liệu âm thầm
4. **Giám sát lag** — chỉ báo vấn đề sớm

### Tóm Tắt Cho Senior

- Offset — cơ chế theo dõi tiến trình nền tảng
- __consumer_offsets lưu trữ offset cho tất cả các group
- Chiến lược commit ảnh hưởng đến độ tin cậy và hiệu năng
- Xác thực leader epoch rất quan trọng cho an toàn dữ liệu
- Giám sát lag là bắt buộc cho production

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Offset — số thứ tự message trong một partition, bắt đầu từ 0
- Offset chỉ duy nhất trong một partition, không phải toàn cục
- Offset không thể thay đổi sau khi ghi; các message được sắp xếp theo offset
- Committed offset — offset đã xử lý cuối cùng được lưu trong `__consumer_offsets`
- Consumer Lag = LogEndOffset - CommittedOffset — metric sức khỏe chính
- `auto.offset.reset`: earliest (từ đầu), latest (từ cuối, mặc định), none (exception)
- Leader Epoch (từ Kafka 0.11) — ngăn mất dữ liệu âm thầm khi failover
- Seek cho phép đọc từ bất kỳ offset nào: đầu, cuối, số cụ thể, timestamp

**Các câu hỏi phụ thường gặp:**
- *Leader Epoch là gì?* — Số thế hệ leader; giúp xác định các message bị mất khi failover.
- *Các offset đã commit được lưu ở đâu?* — Trong topic nội bộ `__consumer_offsets` (compact).
- *LAG=200 nghĩa là gì?* — 200 message chưa được đọc; tính nghiêm trọng phụ thuộc vào throughput.
- *Điều gì xảy ra nếu bạn commit trước khi xử lý?* — Khi crash, các message bị mất (offset đã commit, chưa xử lý).

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Offset là một ID message duy nhất" — nó là một vị trí trong log, không phải một ID
- "Offset có thể thay đổi" — không thể, bất biến
- "Offset duy nhất trên toàn bộ topic" — chỉ trong một partition
- "Commit trước khi xử lý là ổn" — đó là mất dữ liệu khi crash

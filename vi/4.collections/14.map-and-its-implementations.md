# What is Map and what implementations exist? (Map là gì và có những cài đặt nào?)

## 🟢 Junior Level

**Map (Từ điển)** — một collection các cặp **key-value** (khóa-giá trị).

**Ví dụ minh họa:** Map giống như một cuốn từ điển giấy: qua một từ (key) bạn tìm được định nghĩa của nó (value). Key là duy nhất (một từ chỉ xuất hiện trong từ điển một lần), value có thể lặp lại (các từ khác nhau có thể có cùng định nghĩa).

```java
Map<String, Integer> ages = new HashMap<>();
ages.put("Ivan", 25);    // Put
ages.put("Maria", 30);

int age = ages.get("Ivan");  // Get → 25
boolean has = ages.containsKey("Ivan");  // → true
```

**Các cài đặt chính:**

| Cài đặt               | Khi nào dùng           |
| --------------------- | ---------------------- |
| **HashMap**           | Mặc định (nhanh)       |
| **LinkedHashMap**     | Cần thứ tự             |
| **TreeMap**           | Cần sắp xếp            |
| **ConcurrentHashMap** | Đa luồng               |

**Map ≠ Collection!**
- Map làm việc với các CẶP (key-value)
- Collection làm việc với các phần tử ĐƠN LẺ

## 🟡 Middle Level

### Các cài đặt chính

**HashMap:**
```java
Map<String, Integer> map = new HashMap<>();
map.put("A", 1);  // O(1)
map.get("A");     // O(1)
// → Nhanh, không có thứ tự
```

**LinkedHashMap:**
```java
Map<String, Integer> map = new LinkedHashMap<>();
map.put("C", 3);
map.put("A", 1);
map.put("B", 2);
// → Thứ tự: C, A, B (như đã chèn vào)
```

**TreeMap:**
```java
Map<String, Integer> map = new TreeMap<>();
map.put("C", 3);
map.put("A", 1);
map.put("B", 2);
// → Thứ tự: A, B, C (được sắp xếp)
// → floorKey, ceilingKey, subMap
```

### Các Map chuyên biệt

**EnumMap:**
```java
// Cho các key kiểu Enum — nhanh nhất! Bên trong là một mảng — index = enum.ordinal(), không có hashing và không có va chạm. Đánh chỉ mục trực tiếp = O(1) mà không có overhead.
enum Status { ACTIVE, INACTIVE }
Map<Status, String> map = new EnumMap<>(Status.class);
// → Bên trong: mảng! O(1), bộ nhớ tối thiểu
```

**WeakHashMap:**
```java
// Các key = weak reference
// Bị loại bỏ khi không còn strong reference nào đến key
Map<Object, String> map = new WeakHashMap<>();
// → Cho cache và metadata
```

**IdentityHashMap:**
```java
// So sánh bằng == (địa chỉ), không phải equals
Map<String, String> map = new IdentityHashMap<>();
map.put(new String("A"), "1");
map.put(new String("A"), "2");  // Hai key khác nhau!
// → Cho serialization, phát hiện chu trình (cycle detection)
```

### Các Map bất biến (immutable) của Java 9+

```java
// Các phương thức factory
Map<String, Integer> map = Map.of(
    "A", 1,
    "B", 2,
    "C", 3
);
// → Không thể sửa đổi!
// → Bộ nhớ gọn
// → Thứ tự được ngẫu nhiên hóa!
// Các hạn chế của Map.of(): tối đa 10 cặp, cấm key/value null. Với > 10 cặp — hãy dùng Map.ofEntries().
```

### Các phương thức hữu ích của Java 8+

```java
map.computeIfAbsent(key, k -> new ArrayList<>())
   .add(value);

map.merge(key, 1, Integer::sum);  // Bộ đếm

map.putIfAbsent(key, value);
```

## 🔴 Senior Level

### Java 21: SequencedMap

```java
// LinkedHashMap và TreeMap → SequencedMap
LinkedHashMap<String, Integer> map = new LinkedHashMap<>();
map.putFirst("A", 1);   // Phương thức mới!
map.putLast("Z", 26);   // Phương thức mới!
map.firstEntry();       // Phương thức mới!
map.reversed();         // Thứ tự đảo ngược (view)

// HashMap KHÔNG phải là SequencedMap (không có thứ tự)
```

### Memory Footprint

```
HashMap Entry: ~32-48 byte
  → Node: hash, key, value, next

LinkedHashMap: ~48 byte
  → + các tham chiếu before, after

TreeMap: ~40-56 byte
  → Entry: key, value, left, right, parent, color

→ Với hàng triệu entry → hàng gigabyte!
```

### Đánh đổi của Load Factor

```
Load Factor = tỉ lệ giữa số lượng phần tử và số lượng bucket. Với load factor 0.75 và một map 100 phần tử — 133 bucket. Khi fill factor vượt quá 75% — resize (tạo lại table).

Mặc định: 0.75

0.75 = cân bằng giữa:
  → Bộ nhớ (thấp hơn → fill factor cao hơn)
  → Va chạm (cao hơn → tìm kiếm chậm hơn)

Tăng lên (0.9):
  → -20% bộ nhớ
  → +va chạm

Giảm xuống (0.5):
  → +50% bộ nhớ
  → -va chạm
```

### Các trường hợp sử dụng của IdentityHashMap

```java
// 1. Phát hiện chu trình trong các đồ thị đối tượng
IdentityHashMap<Object, Boolean> visited = new IdentityHashMap<>();

// 2. Serialization (theo dõi những cái đã được serialize)
IdentityHashMap<Object, Integer> serialized = new IdentityHashMap<>();

// 3. Khi equals bị override nhưng cần identity (định danh)
```

### EnumMap: tại sao nó nhanh nhất?

```java
// Bên trong: mảng Object[]
// Index = ordinal()_enum

// put(key, value):
array[key.ordinal()] = value;  // O(1), đánh chỉ mục trực tiếp!

// get(key):
return array[key.ordinal()];   // O(1), không có hashing!

→ Nhanh hơn HashMap, ít bộ nhớ hơn
```

### Các khía cạnh Highload

```
HashMap:
  → Treeification khi có va chạm (> 8)
  → Resize: O(n), latency spike (đỉnh độ trễ)
  → Bộ nhớ: ~32 byte cho mỗi entry

ConcurrentHashMap:
  → Đọc lock-free
  → CAS + synchronized cho mỗi bucket
  → Latency bằng không cho các lần đọc
```

### Kinh nghiệm Production

**Tình huống thực tế: HashMap → EnumMap**
```java
// Trước: HashMap<Status, Counter>
// 100,000 request/giây → áp lực GC

// Sau: EnumMap<Status, Counter>
// → -40% bộ nhớ
// → +25% throughput
```

### Best Practices

1. **HashMap** — theo mặc định
2. **EnumMap** — cho các key kiểu Enum
3. **LinkedHashMap** — thứ tự hoặc LRU
4. **TreeMap** — sắp xếp/các khoảng
5. **ConcurrentHashMap** — đa luồng
6. **Map.of()** — cho các lookup tĩnh
7. **Các key bất biến** — bắt buộc!
8. **computeIfAbsent/merge** — các thao tác nguyên tử (atomic)

### Tóm tắt cho Senior

- **Map** ≠ Collection (các cặp so với các phần tử đơn lẻ)
- **SequencedMap (Java 21)** → putFirst/reversed
- **EnumMap** = mảng → nhanh nhất
- **IdentityHashMap** = so sánh bằng ==
- **Load Factor** = đánh đổi bộ nhớ so với va chạm
- **computeIfAbsent/merge** — nguyên tử, Java 8+
- **Các key bất biến** — cực kỳ quan trọng!
- **Map.of()** → các map bất biến gọn

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Map — collection các cặp key-value, các key là duy nhất, Map ≠ Collection
- HashMap = O(1), mặc định; LinkedHashMap = O(1) + thứ tự chèn vào; TreeMap = O(log n) + sắp xếp; ConcurrentHashMap = thread-safe
- EnumMap — Map nhanh nhất (bên trong là mảng, index = ordinal), cho các key kiểu enum
- WeakHashMap — các key tự động bị loại bỏ khi không còn strong reference (cho metadata, KHÔNG phải cho cache)
- IdentityHashMap — so sánh bằng == thay vì equals (cho serialization, phát hiện chu trình)
- Load factor 0.75 — cân bằng giữa bộ nhớ và va chạm
- Java 21: API SequencedMap (putFirst, putLast, reversed) cho LinkedHashMap và TreeMap
- Java 8+: computeIfAbsent, merge, putIfAbsent — các thao tác nguyên tử
- Map.of() — các Map bất biến, tối đa 10 cặp, cấm null

**Các câu hỏi phụ thường gặp:**
- **Tại sao EnumMap nhanh nhất?** — Bên trong là một mảng, đánh chỉ mục trực tiếp theo ordinal(), không có hashing và không có va chạm — O(1) với overhead tối thiểu.
- **WeakHashMap khác một Map thông thường cho việc caching như thế nào?** — WeakHashMap loại bỏ các entry ở MỖI lần Minor GC — cache có thể biến mất trong vòng vài mili-giây. Cho cache, Caffeine hoặc SoftReference tốt hơn.
- **Khi nào dùng IdentityHashMap?** — Khi cần so sánh tham chiếu (==) thay vì equals: serialization, phát hiện chu trình trong các đồ thị đối tượng.
- **SequencedMap là gì?** — Interface của Java 21 cho các Map có thứ tự: putFirst, putLast, firstEntry, reversed.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Map là một Collection" — Map KHÔNG extend Collection, nó làm việc với các cặp key-value
- ❌ "WeakHashMap là một lựa chọn tốt cho caching" — việc dọn dẹp quá quyết liệt, hãy dùng Caffeine
- ❌ "IdentityHashMap giống với HashMap" — IdentityHashMap so sánh các key bằng ==, không phải equals
- ❌ "Map.of() có thể được sửa đổi" — nó là một collection bất biến, UnsupportedOperationException khi sửa đổi

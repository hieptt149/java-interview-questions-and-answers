# What Happens When Concatenating Strings with + Operator? (Điều gì xảy ra khi nối String bằng toán tử +?)

## 🟢 Junior Level

Khi bạn dùng `+` để nối các chuỗi, Java tạo ra một chuỗi **mới** từ hai (hoặc nhiều) chuỗi nguồn. Vì `String` là bất biến, các chuỗi gốc không thay đổi.

**Ví dụ:**
```java
String s1 = "Hello";
String s2 = "World";
String result = s1 + " " + s2; // "Hello World"
```

**Điểm quan trọng:** Nếu bạn nối các chuỗi trong vòng lặp qua `+`, một chuỗi mới được tạo ở mỗi lần lặp. Điều này rất kém hiệu quả.

```java
// XẤU — tạo ra N object String mới
String result = "";
for (int i = 0; i < 1000; i++) {
    result += i; // String mới ở mỗi lần lặp!
}

// TỐT — một object StringBuilder duy nhất
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) {
    sb.append(i);
}
```

**Quy tắc:** `+` tiện lợi cho các biểu thức đơn giản (1-2 chuỗi), nhưng bị cấm trong vòng lặp.

### Khi + Làm Giảm Khả Năng Đọc

Các biểu thức phức tạp với các lời gọi method lồng nhau:
`"User: " + user.getName() + " (" + user.getAge() + " years)"` — tốt hơn nên dùng StringBuilder hoặc formatting.

## 🟡 Middle Level

### Cách Nó Hoạt Động

Hành vi phụ thuộc vào việc các giá trị có được biết tại thời điểm biên dịch hay không:

**Nối các hằng số (Constant Folding tại thời điểm biên dịch):**
```java
String s = "Hello" + " " + "World";
// Compiler chuyển đổi cái này thành:
String s = "Hello World"; // Một chuỗi trong bytecode, 0 thao tác tại thời điểm chạy
```

**Nối các biến (tại thời điểm chạy):**
```java
String a = getName();
String b = getLastName();
String full = a + " " + b;
```
Những gì xảy ra "bên dưới" phụ thuộc vào phiên bản Java (xem phần Senior).

### Các Lỗi Điển Hình
1. **Lỗi:** `+` trong vòng lặp
   **Giải pháp:** `StringBuilder` bên ngoài vòng lặp

2. **Lỗi:** `split(".")` — dấu chấm là một metacharacter của regex
   **Giải pháp:** `split("\\.")` hoặc `split(Pattern.quote("."))`

3. **Lỗi:** `null` + chuỗi
   **Giải pháp:** Kết quả sẽ là `"nullWorld"`. Đây không phải lỗi, nhưng có thể gây ngạc nhiên.

### So Sánh Các Cách Tiếp Cận
| Kịch bản                              | Cách tiếp cận                           | Hiệu quả                        |
| ------------------------------------- | ---------------------------------- | ---------------------------------- |
| `"A" + "B" + "C"`                     | `+`                                | Tuyệt vời (constant folding)          |
| `a + b + c` (biến, 1 dòng)       | `+`                                | Tuyệt vời (đã tối ưu hóa)                 |
| Vòng lặp với `+=`                        | `StringBuilder`                    | `+` — O(n²), StringBuilder — O(n) |
| Formatting                            | `String.format()` hoặc `StringBuilder`| Tùy ngữ cảnh                |

## 🔴 Senior Level

### Hiện Thực Nội Bộ — Sự Tiến Hóa

**Java 5-8: Sinh Code StringBuilder**
Compiler thay thế biểu thức `a + b + c` bằng:
```java
new StringBuilder().append(a).append(b).append(c).toString()
```
Vấn đề: bytecode bị "hardcode" trong `.class`. Một chiến lược tối ưu hóa mới sẽ đòi hỏi biên dịch lại.

**JEP 280 (Java 9) giới thiệu invokedynamic cho việc nối chuỗi. Theo mặc định, Java 9 dùng BC_SB, và trong Java 11+ chiến lược có thể thay đổi qua StringConcatFactory.**
```java
String full = a + " " + b;
```
Bytecode:
```
0: aload_1  // a
1: aload_2  // " "
2: aload_3  // b
3: invokedynamic #7  // makeConcatWithConstants:(Ljava/lang/String;Ljava/lang/String;Ljava/lang/String;)Ljava/lang/String;
8: astore 4
```

`invokedynamic` tham chiếu đến `StringConcatFactory`. Ở lần gọi đầu tiên, bootstrap method sinh ra code tối ưu cho việc nối chuỗi cụ thể này.

**Các chiến lược của StringConcatFactory:**
1. **MH_LF (MethodHandle với LambdaForm):** Sinh một MethodHandle cho việc nối chuỗi
2. **BC_SB (Bytecode StringBuilder):** Sinh bytecode với StringBuilder
3. **BH_SB (Bootstrap method với StringBuilder — gọn):** Biến thể tối ưu hóa

### Đánh Đổi Về Kiến Trúc (Trade-off)

**Ưu điểm của invokedynamic:**
- JVM chọn chiến lược tại thời điểm chạy (tính thích ứng)
- Các chiến lược mới có thể được thêm mà không cần biên dịch lại
- Ít cấp phát hơn — JVM biết tất cả các tham số và cấp phát `byte[]` với kích thước đúng ngay lập tức

**Nhược điểm:**
- Overhead bootstrap ở lần gọi đầu (~1-5μs)
- Khó debug bytecode hơn

### Các Trường Hợp Biên

1. **Nối chuỗi với null:** `"val: " + null` → `"val: null"`. `StringConcatFactory` và `StringBuilder` gọi `String.valueOf(null)` → `"null"`.

2. **Các kiểu trộn lẫn:** `"Value: " + 42` → `StringConcatFactory` biết kiểu `int` và dùng chuyển đổi tối ưu mà không tạo một `String` trung gian.

3. **Vòng lặp:** `invokedynamic` chỉ tối ưu hóa **một biểu thức**. Một vòng lặp vẫn tạo một context nối chuỗi mới ở mỗi lần lặp:
   ```java
   for (int i = 0; i < n; i++) s += i;
   // Mỗi lần lặp: invokedynamic → byte[] mới → String mới
   // Tổng: cấp phát O(n²)
   ```

### Hiệu Năng
| Kịch bản         | Java 8 (StringBuilder) | Java 9+ (invokedynamic) |
| ---------------- | ---------------------- | ----------------------- |
| 3 biến      | ~30ns                  | ~15ns                   |
| 10 biến     | ~80ns                  | ~30ns                   |
| 3 biến + int| ~35ns                  | ~18ns                   |
| Vòng lặp 10K lần   | O(n²)                  | O(n²) (không được tối ưu hóa!)  |

### Kinh Nghiệm Production
**Kịch bản:** Logging `log.info("User " + user.getId() + " action " + action)` — 100K lời gọi/giây:
- Java 8: 100K `new StringBuilder()` → ~30ms CPU
- Java 9+: invokedynamic với cấp phát trực tiếp → ~15ms CPU
- Nếu log bị lọc (level < INFO): cả hai phiên bản đều lãng phí CPU. Giải pháp: `if (log.isInfoEnabled())`

### Best Practices Cho Highload
- Cho các phép nối đơn giản (1 dòng code): `+` — dễ đọc và hiệu quả
- Trong vòng lặp: **luôn luôn** `StringBuilder` với `initialCapacity`
- Cho formatting: `String.format()` tiện lợi nhưng chậm hơn (phải parse template). Các lựa chọn thay thế: `MessageFormat`, text block (Java 15+), hoặc StringBuilder thủ công
- Lazy evaluation: nếu việc nối chuỗi tốn kém và có thể không cần thiết — hãy trì hoãn nó

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Toán tử `+` tạo một chuỗi MỚI — String bất biến, các bản gốc không thay đổi
- Constant folding: `"A" + "B" + "C"` → `"ABC"` tại thời điểm biên dịch, 0 thao tác tại thời điểm chạy
- Java 5-8: compiler thay thế `a + b + c` bằng `new StringBuilder().append(a).append(b).append(c).toString()`
- Java 9+: `invokedynamic` + `StringConcatFactory` — JVM chọn chiến lược tối ưu tại thời điểm chạy
- Trong vòng lặp, `+` tạo cấp phát O(n²) — dùng `StringBuilder`
- `null + "text"` → `"nulltext"` — không phải lỗi, nhưng có thể gây ngạc nhiên

**Các câu hỏi phụ thường gặp:**
- **Tại sao `+` trong vòng lặp lại xấu?** — Mỗi lần lặp tạo một StringBuilder mới + một String mới. Với 1000 lần lặp: 1000 StringBuilder + 1000 String = O(n²).
- **`invokedynamic` cho việc nối chuỗi là gì?** — Trong Java 9+, compiler sinh `invokedynamic makeConcatWithConstants`. Ở lần gọi đầu, JVM chọn chiến lược tối ưu (MH_LF, BC_SB, BH_SB).
- **Compiler có tối ưu hóa các vòng lặp với `+` không?** — Không. `invokedynamic` chỉ tối ưu hóa một biểu thức duy nhất, không phải vòng lặp.
- **StringConcatFactory là gì?** — Một factory trong `java.lang.invoke` sinh code tối ưu cho một phép nối chuỗi cụ thể.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "`+` trong vòng lặp — ổn thôi" — cấp phát O(n²), dùng `StringBuilder`
- ❌ "Compiler tối ưu hóa `+` trong vòng lặp" — chỉ tối ưu hóa một biểu thức duy nhất, không phải vòng lặp
- ❌ "`invokedynamic` chậm hơn `StringBuilder`" — với một biểu thức đơn — nhanh hơn, với vòng lặp — cùng tệ như nhau
- ❌ "Nối chuỗi qua `+` sửa đổi các chuỗi gốc" — String bất biến, luôn tạo một chuỗi mới

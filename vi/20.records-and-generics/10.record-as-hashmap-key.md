# Can You Use Record as a Key in HashMap? (Có thể dùng Record làm key trong HashMap không)

## 🟢 Junior Level

**Có, Record là một key tuyệt vời cho HashMap!** Đây là một trong những vai trò tốt nhất của Record.

Record tự động nhận được `equals()` và `hashCode()` đúng đắn, điều này cực kỳ quan trọng để HashMap hoạt động.

```java
public record CacheKey(String tenantId, String entityType, String entityId) {}

Map<CacheKey, Object> cache = new HashMap<>();

CacheKey key1 = new CacheKey("t1", "user", "u1");
cache.put(key1, userData);

// Một object khác với cùng giá trị — sẽ tìm thấy dữ liệu!
CacheKey key2 = new CacheKey("t1", "user", "u1");
cache.get(key2);  // userData ✅
```

**Tại sao Record tốt làm key:**
- ✅ Bất biến — key sẽ không thay đổi sau khi được thêm vào
- ✅ equals/hashCode tự động sinh
- ✅ Gọn gàng và rõ ràng

## 🟡 Middle Level

### Cách Hoạt Động

**Hợp đồng key trong HashMap:**
1. Nếu `a.equals(b)`, thì `a.hashCode() == b.hashCode()`
2. Key không được thay đổi sau khi thêm vào Map

Record thỏa mãn cả hai điều kiện:
```java
public record Point(int x, int y) {}

Point p1 = new Point(1, 2);
Point p2 = new Point(1, 2);

// Hợp đồng được thỏa mãn
assert p1.equals(p2);           // true
assert p1.hashCode() == p2.hashCode();  // true
```

### Các Lỗi Thường Gặp

1. **Các thành phần mutable trong key:**
```java
public record BadKey(List<String> values) {}

BadKey key = new BadKey(new ArrayList<>(List.of("a", "b")));
map.put(key, "value");

key.values().add("c");  // Đã thay đổi! hashCode không còn đúng
map.get(key);  // Có thể không tìm thấy!
```

**Giải pháp:**
```java
public record GoodKey(List<String> values) {
    public GoodKey {
        values = List.copyOf(values);  // bất biến
    }
}
```

2. **Mảng trong key:**
```java
public record ArrayKey(int[] ids) {}

ArrayKey k1 = new ArrayKey(new int[]{1, 2, 3});
ArrayKey k2 = new ArrayKey(new int[]{1, 2, 3});

k1.equals(k2);  // false! Mảng so sánh theo tham chiếu
k1.hashCode() == k2.hashCode();  // gần như chắc chắn false
```

**Giải pháp:**
```java
public record ArrayKey(int[] ids) {
    @Override
    public boolean equals(Object o) {
        if (!(o instanceof ArrayKey other)) return false;
        return Arrays.equals(ids, other.ids);
    }

    @Override
    public int hashCode() {
        return Arrays.hashCode(ids);
    }
}
```

### Ứng Dụng Thực Tế

**1. Cache:**
```java
public record CacheKey(String tenantId, String query, List<String> params) {
    public CacheKey {
        params = List.copyOf(params);
    }
}

Map<CacheKey, List<User>> queryCache = new ConcurrentHashMap<>();
```

**2. Key tổng hợp:**
```java
public record OrderItemId(String orderId, String itemId) {}

Map<OrderItemId, OrderItem> items = new HashMap<>();
items.put(new OrderItemId("order-1", "item-1"), item);
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**Cách HashMap dùng hashCode:**
```java
// hash nội bộ của HashMap
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

// hashCode của Record được sinh bởi trình biên dịch thông qua một chuỗi phép nhân được tối ưu hóa,
// KHÔNG PHẢI thông qua Objects.hash(). Objects.hash tạo một Object[] và chậm hơn.
// hashCode tự động sinh cho Record:
```

**hashCode tự động sinh cho Record:**
```java
public record User(String name, int age) {
    // Tự động sinh:
    @Override
    public int hashCode() {
        return Objects.hash(name, age);
    }
}

// Objects.hash dùng Arrays.hashCode:
// int result = Arrays.hashCode(new Object[]{name, age});
```

### Đánh Đổi Kiến Trúc

**Record so với class thông thường làm key:**

| Khía cạnh                 | Record           | Class thông thường           |
| ---------------------- | ---------------- | ----------------------- |
| **equals/hashCode**    | Tự động, đúng | Thủ công, có thể lỗi |
| **Tính bất biến**       | Được đảm bảo    | Cần duy trì           |
| **Hiệu năng** | Tối ưu      | Phụ thuộc vào triển khai   |
| **Trường mutable**   | Cần bảo vệ   | Cần duy trì           |

### Edge Cases

**1. Record lớn làm key:**
```java
// hashCode được tính mỗi lần — có thể chậm
public record LargeKey(
    String field1, String field2, String field3,
    String field4, String field5, String field6
) {}

// Đối với hot path — cache hashCode
public record CachedHashKey(String value) {
    private final int hash;

    public CachedHashKey {
        hash = value.hashCode();
    }

    @Override
    public int hashCode() {
        return hash;
    }
}
```

**2. Null trong Record:**
```java
public record NullableKey(String name) {}

NullableKey k1 = new NullableKey(null);
NullableKey k2 = new NullableKey(null);

k1.equals(k2);  // true (Objects.equals xử lý null đúng cách)
```

### Hiệu Năng

```
Thao tác          | Key Record | Key String
-------------------|------------|-----------
hashCode()         | 15 ns      | 10 ns
equals()           | 12 ns      | 8 ns
HashMap get/put    | O(1)       | O(1)

Đối với key tổng hợp — đắt hơn một chút, nhưng O(1) vẫn được giữ
```

### Kinh Nghiệm Production

**Query cache:**
```java
public record QueryCacheKey(
    String query,
    List<Object> params,
    int limit,
    int offset
) {
    public QueryCacheKey {
        params = List.copyOf(params);
    }

    @Override
    public int hashCode() {
        // Cache cho key lớn
        return Objects.hash(query, params, limit, offset);
    }
}

@Service
public class QueryCache {
    private final Map<QueryCacheKey, List<User>> cache = new ConcurrentHashMap<>();

    public List<User> getOrLoad(String query, List<Object> params, int limit, int offset) {
        var key = new QueryCacheKey(query, params, limit, offset);
        return cache.computeIfAbsent(key, k -> loadFromDb(k));
    }
}
```

### Best Practices

```java
// ✅ Record cho key tổng hợp
public record CacheKey(String tenant, String entityType, String id) {}

// ✅ Các thành phần bất biến
public record SafeKey(List<String> values) {
    public SafeKey { values = List.copyOf(values); }
}

// ✅ Dùng Record làm key trong ConcurrentHashMap
Map<CacheKey, Object> cache = new ConcurrentHashMap<>();

// ❌ Các thành phần mutable không được bảo vệ
// ❌ Mảng trong key mà không override equals/hashCode
// ❌ Record với nhiều trường (hashCode đắt)
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Record là một key tuyệt vời cho HashMap nhờ equals/hashCode tự động sinh
- Record là bất biến — key sẽ không thay đổi sau khi thêm vào Map
- Các thành phần mutable (List, mảng) phá vỡ hợp đồng hashCode — cần bản sao phòng thủ
- Mảng được so sánh theo tham chiếu, không phải nội dung — cần override equals/hashCode với Arrays.equals
- Đối với Record lớn, hashCode có thể đắt — có thể cache nó
- Null trong các thành phần được xử lý đúng cách qua Objects.equals

**Các câu hỏi phụ thường gặp:**
- **Tại sao Record tốt hơn class thông thường làm key?** — Tự động sinh equals/hashCode, đảm bảo tính bất biến
- **Điều gì xảy ra với thành phần mutable trong key?** — Khi thay đổi, hashCode thay đổi — dữ liệu bị mất trong HashMap
- **Có thể dùng mảng làm thành phần key không?** — Chỉ khi override equals/hashCode qua Arrays.equals/hashCode
- **hashCode của Record có được tính mỗi lần không?** — Có, nhưng có thể cache cho key lớn

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Mảng trong Record so sánh đúng" — Mảng được so sánh theo tham chiếu, không phải nội dung
- ❌ "List mutable trong key là an toàn" — Thay đổi list làm hỏng HashMap
- ❌ "hashCode của Record được cache tự động" — Không, được tính mỗi lần
- ❌ "hashCode() dùng Objects.hash()" — Dùng chuỗi phép nhân được tối ưu hóa

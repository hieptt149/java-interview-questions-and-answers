# What is a defensive copy? (Defensive copy là gì?)

---

## Basic Level

Một **Defensive Copy** là việc tạo một bản sao của dữ liệu để bảo vệ object nội bộ khỏi các sửa đổi từ bên ngoài.

Giống như một bản photocopy của một tài liệu: bạn đưa ra một bản sao, và nếu ai đó viết lên nó, bản gốc của bạn không bị ảnh hưởng.

### Ví Dụ Đơn Giản
```java
public class MyClass {
    private Date date;

    public MyClass(Date date) {
        // XẤU: this.date = date; // biến bên ngoài có thể thay đổi
        // TỐT:
        this.date = new Date(date.getTime()); // đã tạo một bản sao
    }

    public Date getDate() {
        return new Date(date.getTime()); // trả về một bản sao
    }
}
```

### Tại Sao Điều Này Cần Thiết
Không có bản sao, code gọi có thể thay đổi dữ liệu nội bộ của bạn thông qua tham chiếu:
```java
Date d = new Date();
MyClass obj = new MyClass(d);
d.setYear(2000); // Đã thay đổi object nội bộ của MyClass!
```

---

### Khi Nào KHÔNG Nên Tạo Defensive Copy

1. **Các kiểu bất biến** (String, Integer, LocalDate) — sao chép là vô nghĩa
2. **API nội bộ được kiểm soát hoàn toàn** — bên gọi được đảm bảo không mutate
3. **Code nhạy cảm về hiệu năng** — sao chép ở mỗi lời gọi tạo ra overhead không chấp nhận được

## Intermediate Level

### Hai Điểm Bảo Vệ

**1. Trong constructor (đầu vào dữ liệu)**
```java
public class MyObject {
    private final Date startDate;
    private final List<String> items;

    public MyObject(Date date, List<String> items) {
        this.startDate = new Date(date.getTime());
        this.items = new ArrayList<>(items);
    }
}
```

**2. Trong getter (đầu ra dữ liệu)**
```java
public Date getStartDate() {
    return new Date(startDate.getTime());
}

public List<String> getItems() {
    return Collections.unmodifiableList(new ArrayList<>(items));
}
```

### Shallow vs Deep Copy

- **Shallow Copy** — container được sao chép, nhưng các phần tử vẫn giữ nguyên
  ```java
  List<String> copy = new ArrayList<>(original);
  ```
- **Deep Copy** — tất cả các object lồng nhau được sao chép đệ quy
  ```java
  List<User> copy = original.stream()
      .map(u -> new User(u.getName(), u.getAge()))
      .toList();
  ```

### Cách Tiếp Cận Hiện Đại (Java 10+)
```java
this.items = List.copyOf(items); // bản sao bất biến
```

## Advanced Level

### TOCTOU Và Thứ Tự Thao Tác

Sao chép **trước** khi validate:
```java
public SecureClass(List<String> roles) {
    List<String> copy = new ArrayList<>(roles); // 1. Sao chép
    if (copy.contains("admin")) {               // 2. Kiểm tra
        // ...
    }
    this.roles = List.copyOf(copy);             // 3. Lưu
}
```
Nếu không, một cuộc tấn công TOCTOU có thể xảy ra: dữ liệu thay đổi giữa lúc kiểm tra và lúc sử dụng.

### Wrapper vs Copy

`Collections.unmodifiableList(original)` là một **wrapper**, không phải một bản sao. Nếu `original` thay đổi, wrapper cũng thay đổi. Chỉ dùng cho việc trả về từ getter, nhưng không dùng trong constructor.

### Hiệu Năng

Defensive copy là một thao tác O(n). Trong các hệ thống tải cao:
- Tránh sao chép trong các vòng lặp hot
- Dùng các cấu trúc persistent (Vavr) cho structural sharing
- Cache các bản sao chỉ an toàn nếu dữ liệu thực sự tĩnh;
nếu không bạn có nguy cơ trả về dữ liệu cũ (stale).

### Tóm Tắt Cho Advanced
- Defensive copy — tạo một "snapshot" của dữ liệu mutable
- Điều kiện bắt buộc cho tính bất biến khi có các trường object
- Luôn tạo một bản sao **trước** khi validate
- `Collections.unmodifiableList()` — một wrapper, không phải một bản sao; dùng `List.copyOf()` để bảo vệ thực sự

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Defensive Copy — tạo một bản sao của dữ liệu để bảo vệ khỏi các thay đổi bên ngoài
- Hai điểm bảo vệ: constructor (đầu vào) và getter (đầu ra)
- Shallow Copy — container được sao chép, Deep Copy — tất cả các object lồng nhau đệ quy
- TOCTOU: sao chép TRƯỚC khi validate, nếu không dữ liệu thay đổi giữa lúc kiểm tra và lúc sử dụng
- Wrapper vs Copy: `unmodifiableList` — wrapper (O(1)), `List.copyOf` — bản sao (O(n))
- Khi nào KHÔNG cần tạo: các kiểu bất biến, API nội bộ, code nhạy cảm về hiệu năng

**Các câu hỏi phụ thường gặp:**
- *Cái nào rẻ hơn — wrapper hay copy?* — Wrapper O(1), copy O(n); nhưng wrapper không bảo vệ khỏi các thay đổi đến bản gốc
- *Khi nào shallow copy là đủ?* — Khi collection chứa các object bất biến (String, Integer)
- *Tấn công TOCTOU là gì?* — Dữ liệu thay đổi giữa lúc kiểm tra và lúc sao chép
- `List.copyOf` vs `new ArrayList`? — List.copyOf trả về một list bất biến; new ArrayList — mutable

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "UnmodifiableList là một bản sao" — đó là một wrapper, các thay đổi đến bản gốc vẫn hiển thị
- "Defensive copy luôn cần thiết" — vô nghĩa với các kiểu bất biến
- "clone() là một cách đáng tin cậy" — clone() được coi là hỏng (Effective Java Item 13)
- "Sao chép sau khi validate — đúng" — bạn cần SAO CHÉP TRƯỚC khi validate

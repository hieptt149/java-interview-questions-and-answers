# What types of Thread Pool exist in Java? (Có những loại Thread Pool nào trong Java?)

---

## Junior Level

### Hiểu biết cơ bản

Java cung cấp một số loại thread pool sẵn có thông qua factory `Executors`. Mỗi loại được tối ưu cho một kịch bản cụ thể.

### 1. FixedThreadPool

Số lượng thread cố định. Mọi tác vụ thực thi song song, phần còn lại chờ trong một hàng đợi. Chọn khi bạn biết trước tải tối đa (ví dụ: xử lý 10 file đồng thời).

```java
ExecutorService pool = Executors.newFixedThreadPool(10);

for (int i = 0; i < 100; i++) {
    pool.submit(() -> {
        // Tối đa 10 tác vụ thực thi đồng thời
        // 90 tác vụ còn lại chờ trong hàng đợi
    });
}
```

| Tham số            | Giá trị                            |
| ------------------ | ---------------------------------- |
| Kích thước pool    | Cố định (10)                       |
| Hàng đợi           | Không giới hạn (LinkedBlockingQueue)|
| Khi nào dùng       | Tải đã biết, ổn định              |

### 2. CachedThreadPool

Tạo các thread mới khi cần, tái sử dụng các thread rảnh.

```java
ExecutorService pool = Executors.newCachedThreadPool();

pool.submit(() -> {
    // Nếu không có thread rảnh — một thread mới được tạo
    // Nếu một thread rảnh trong 60 giây — nó bị hủy
});
```

| Tham số            | Giá trị                                                                                                                |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- |
| Kích thước pool    | 0 tới Integer.MAX_VALUE (lý thuyết ~2 tỷ, thực tế bị giới hạn bởi bộ nhớ OS — thường tối đa 32K thread trên Linux)     |
| Hàng đợi           | SynchronousQueue (sức chứa 0)                                                                                        |
| Khi nào dùng       | Nhiều tác vụ ngắn                                                                                                    |

### 3. SingleThreadExecutor

Đúng một thread. Các tác vụ thực thi tuần tự nghiêm ngặt.

```java
ExecutorService pool = Executors.newSingleThreadExecutor();

pool.submit(() -> System.out.println("Task 1"));
pool.submit(() -> System.out.println("Task 2"));
// Luôn: "Task 1" → "Task 2"
```

| Tham số            | Giá trị                     |
| ------------------ | --------------------------- |
| Kích thước pool    | 1                           |
| Hàng đợi           | Không giới hạn              |
| Khi nào dùng       | Thực thi tuần tự            |

### 4. ScheduledThreadPool

Lập lịch các tác vụ với một độ trễ hoặc định kỳ.

```java
ScheduledExecutorService pool = Executors.newScheduledThreadPool(5);

// Thực thi sau 10 giây
pool.schedule(() -> System.out.println("Delayed"), 10, TimeUnit.SECONDS);

// Thực thi mỗi 5 giây
pool.scheduleAtFixedRate(() -> System.out.println("Periodic"), 0, 5, TimeUnit.SECONDS);
```

| Tham số            | Giá trị              |
| ------------------ | -------------------- |
| Kích thước pool    | Cố định              |
| Hàng đợi           | DelayedWorkQueue     |
| Khi nào dùng       | Các tác vụ định kỳ   |

### 5. WorkStealingPool (Java 8+)

> Lưu ý: trong Java 21+ với virtual thread (Project Loom), cho các tác vụ I/O-bound hãy ưu tiên `Executors.newVirtualThreadPerTaskExecutor()`. Virtual thread tốn ~KB thay vì ~1MB và có thể được tạo hàng triệu cái.

Dùng ForkJoinPool với thuật toán work-stealing.

```java
ExecutorService pool = Executors.newWorkStealingPool();
// Mặc định: số thread = số lõi CPU
```

| Tham số            | Giá trị                      |
| ------------------ | ---------------------------- |
| Kích thước pool    | Số lõi CPU                   |
| Thuật toán         | Work-stealing                |
| Khi nào dùng       | Song song hóa các phép tính  |

### Bảng so sánh

| Loại                 | Kích thước    | Hàng đợi         | Tốt nhất cho          |
| -------------------- | ------------- | ---------------- | --------------------- |
| FixedThreadPool      | Cố định       | Không giới hạn   | Tải ổn định           |
| CachedThreadPool     | Động          | SynchronousQueue | Tác vụ ngắn           |
| SingleThreadExecutor | 1             | Không giới hạn   | Thực thi tuần tự      |
| ScheduledThreadPool  | Cố định       | DelayedWorkQueue | Lập lịch              |
| WorkStealingPool     | Số lõi CPU    | Work-stealing    | Tính toán             |

## Middle Level

### FixedThreadPool — Chi tiết

```java
// Hiện thực nội bộ
public static ExecutorService newFixedThreadPool(int nThreads) {
    return new ThreadPoolExecutor(
        nThreads,                   // corePoolSize
        nThreads,                   // maximumPoolSize
        0L, TimeUnit.MILLISECONDS,  // keepAliveTime
        new LinkedBlockingQueue<Runnable>() // hàng đợi KHÔNG GIỚI HẠN
    );
}
```

**Nguy hiểm:** Nếu các tác vụ đến nhanh hơn mức được xử lý, hàng đợi tăng vô hạn → `OutOfMemoryError`.

**Giải pháp:** Tạo thủ công với một hàng đợi có giới hạn:

```java
ExecutorService safePool = new ThreadPoolExecutor(
    10, 10, 0L, TimeUnit.MILLISECONDS,
    new ArrayBlockingQueue<>(1000) // Giới hạn 1000 tác vụ
);
```

### CachedThreadPool — Chi tiết

```java
public static ExecutorService newCachedThreadPool() {
    return new ThreadPoolExecutor(
        0,                          // corePoolSize
        Integer.MAX_VALUE,          // maximumPoolSize — không giới hạn!
        60L, TimeUnit.SECONDS,      // Các thread chết sau 60s
        new SynchronousQueue<Runnable>() // Sức chứa = 0
    );
}
```

**Nguy hiểm:** Khi tải tăng đột biến, nó có thể tạo hàng nghìn thread → `OutOfMemoryError: unable to create new native thread`.

### SingleThreadExecutor — Chi tiết

```java
public static ExecutorService newSingleThreadExecutor() {
    return new FinalizableDelegatedExecutorService(
        new ThreadPoolExecutor(
            1, 1, 0L, TimeUnit.MILLISECONDS,
            new LinkedBlockingQueue<Runnable>()
        )
    );
}
```

**Khác biệt so với `newFixedThreadPool(1)`:** đảm bảo rằng các cài đặt không thể bị thay đổi (đóng gói).

### ScheduledThreadPool — Chi tiết

```java
ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(3);

// Thực thi một lần sau một độ trễ
scheduler.schedule(task, 10, TimeUnit.SECONDS);

// Fixed rate (từ lúc bắt đầu lần chạy trước)
scheduler.scheduleAtFixedRate(task, 0, 5, TimeUnit.SECONDS);

// Fixed delay (từ lúc kết thúc lần chạy trước)
scheduler.scheduleWithFixedDelay(task, 0, 5, TimeUnit.SECONDS);
```

```
// scheduleAtFixedRate: nếu tác vụ mất 7 giây, và period là 5s —
// cái tiếp theo khởi động NGAY LẬP TỨC sau khi hoàn thành (bỏ qua khoảng chờ)
// scheduleWithFixedDelay: chờ 5 giây SAU khi lần trước hoàn thành
```

### WorkStealingPool — Chi tiết

```java
public static ExecutorService newWorkStealingPool() {
    return new ForkJoinPool(
        Runtime.getRuntime().availableProcessors(),
        ForkJoinPool.defaultForkJoinWorkerThreadFactory,
        null,   // UncaughtExceptionHandler
        true    // asyncMode
    );
}
```

**Thuật toán work-stealing:**
- Mỗi thread có hàng đợi tác vụ riêng
- Nếu một thread làm xong các tác vụ của nó — nó "trộm" từ đuôi hàng đợi của một thread khác
- Rất tốt cho các tác vụ không đồng đều, vì một thread rảnh không ngồi không mà "trộm" các tác vụ chưa được xử lý từ các thread bận (thuật toán work-stealing).

---

### Loại pool nào KHÔNG nên dùng

- **KHÔNG dùng CachedThreadPool cho các tác vụ dài** → bùng nổ thread (hàng nghìn thread)
- **KHÔNG dùng FixedThreadPool với LinkedBlockingQueue cho tải không dự đoán được** → OOM (hàng đợi tăng vô hạn)
- **KHÔNG dùng SingleThreadExecutor cho song song hóa CPU-bound** → một thread, không song song
- **KHÔNG dùng WorkStealingPool cho I/O-bound** → chặn một thread sẽ chặn work-stealing

## Senior Level

### Khi nào Executors không phù hợp

Các developer senior thường tránh các method `Executors.*` và tạo `ThreadPoolExecutor` trực tiếp.

**Tại sao:**

| Vấn đề                   | Executors.*      | ThreadPoolExecutor thủ công   |
| ------------------------ | ---------------- | ----------------------------- |
| Giới hạn hàng đợi        | Không (rủi ro OOM)| Có (ArrayBlockingQueue)      |
| RejectedExecutionHandler | AbortPolicy      | Bất kỳ (CallerRunsPolicy)     |
| ThreadFactory            | Mặc định         | Tùy chỉnh (tên, priority)     |
| keepAliveTime            | Cố định          | Cấu hình được                 |

### Chọn Pool dựa trên loại tác vụ

| Loại tác vụ             | Pool khuyến nghị              | Công thức             |
| ----------------------- | ----------------------------- | --------------------- |
| **CPU-bound** (tính toán) | FixedThreadPool             | `N` hoặc `N+1` lõi    |
| **I/O-bound** (DB, API) | FixedThreadPool hoặc custom   | `N * (1 + W/S)`       |
| **Tác vụ ngắn**         | CachedThreadPool (có giới hạn!) | maxPoolSize giới hạn |
| **Đệ quy / Stream**     | ForkJoinPool                  | `N` lõi               |
| **Tác vụ nền**          | ScheduledThreadPool           | Tùy tần suất          |

### Công thức Sizing cho các tải hỗn hợp

```
Số thread = Số lõi * Mức sử dụng CPU mục tiêu * (1 + Thời gian chờ / Thời gian phục vụ)
```

Ví dụ:
- CPU 8 lõi
- Mức sử dụng mục tiêu: 80% (0.8)
- 90% thời gian chờ (W/S = 9)

```
Số thread = 8 * 0.8 * (1 + 9) = 8 * 0.8 * 10 = 64 thread
```

### Thread Starvation (đói thread)

```
Pool I/O-bound quá nhỏ (5 thread):
  → Cả 5 thread chờ phản hồi từ DB
  → Các request mới chờ trong hàng đợi
  → Hệ thống "khựng lại"

Giải pháp: tăng kích thước pool cho các tác vụ I/O-bound
```

### Công thức Sizing trong code

```java
public class PoolSizer {
    public static int calculatePoolSize(int cores, double targetUtilization,
                                        double waitTime, double serviceTime) {
        return (int) Math.ceil(
            cores * targetUtilization * (1 + waitTime / serviceTime)
        );
    }

    public static void main(String[] args) {
        int cores = Runtime.getRuntime().availableProcessors();
        int poolSize = calculatePoolSize(cores, 0.8, 90, 10);
        // 8 * 0.8 * (1 + 90/10) = 64
        System.out.println("Recommended pool size: " + poolSize);
    }
}
```

### Chẩn đoán

```java
// Giám sát pool
ThreadPoolExecutor executor = ...;

// Các metric then chốt
executor.getActiveCount();         // Bao nhiêu thread đang làm việc
executor.getQueue().size();        // Hàng đợi tăng dần = vấn đề
executor.getCompletedTaskCount();  // Tiến độ
executor.getPoolSize();            // Kích thước hiện tại
```

### Best Practices

1. **Tránh Executors.newCachedThreadPool()** trong production — dùng custom với giới hạn
2. **Giới hạn hàng đợi** — ArrayBlockingQueue thay vì LinkedBlockingQueue
3. **Công thức sizing** — CPU-bound: N+1, I/O-bound: N * (1 + W/S)
4. **WorkStealingPool** — cho các tác vụ đệ quy và parallel stream
5. **ScheduledThreadPool** — cho các tác vụ định kỳ (kiểu cron)
6. **Giám sát queue.size()** — hàng đợi tăng dần = suy giảm
7. **Custom ThreadFactory** — đặt tên thread để debug

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- 5 loại pool: FixedThreadPool (kích thước cố định), CachedThreadPool (động), SingleThreadExecutor (1 thread), ScheduledThreadPool (lập lịch), WorkStealingPool (thuật toán work-stealing)
- FixedThreadPool dùng LinkedBlockingQueue không có giới hạn — rủi ro OOM khi tải không dự đoán được
- CachedThreadPool: maximumPoolSize = Integer.MAX_VALUE, SynchronousQueue (sức chứa 0) — rủi ro bùng nổ thread
- WorkStealingPool = ForkJoinPool với asyncMode=true, mỗi thread có hàng đợi deque riêng
- scheduleAtFixedRate — từ lúc bắt đầu lần chạy trước (có thể bỏ qua nếu tác vụ dài), scheduleWithFixedDelay — từ lúc kết thúc
- SingleThreadExecutor đảm bảo đóng gói — các cài đặt không thể bị thay đổi, khác với newFixedThreadPool(1)
- Trong production, tránh Executors.* — tạo ThreadPoolExecutor thủ công với hàng đợi có giới hạn và RejectedExecutionHandler
- Công thức sizing: CPU-bound = N+1, I/O-bound = N * (1 + W/S), hỗn hợp = N * util * (1 + W/S)

**Các câu hỏi phụ thường gặp:**
- **FixedThreadPool khác SingleThreadExecutor như thế nào?** — FixedThreadPool có thể được cấu hình lại, SingleThreadExecutor được đóng gói (FinalizableDelegatedExecutorService)
- **Tại sao CachedThreadPool nguy hiểm trong production?** — Khi tải tăng đột biến, tạo hàng nghìn thread → unable to create new native thread
- **Work-stealing hoạt động như thế nào?** — Mỗi thread có deque riêng; một thread rảnh "trộm" các tác vụ từ đuôi deque của thread khác (FIFO), owner lấy từ đầu (LIFO)
- **Chọn gì cho các tác vụ I/O-bound?** — FixedThreadPool với công thức N * (1 + W/S) hoặc virtual thread (Java 21+)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "CachedThreadPool là lựa chọn production của tôi" — nguy hiểm khi không có giới hạn, cần maxPoolSize
- "FixedThreadPool với LinkedBlockingQueue là an toàn" — hàng đợi không giới hạn = OOM
- "WorkStealingPool tốt cho I/O" — không, chặn một thread sẽ chặn work-stealing
- "scheduleAtFixedRate đảm bảo khoảng thời gian" — không, nếu tác vụ dài hơn period — cái tiếp theo chạy ngay lập tức

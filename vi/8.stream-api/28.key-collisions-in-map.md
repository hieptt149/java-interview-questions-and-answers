# What to do about key collisions when collecting into Map? (Làm gì khi có va chạm key khi collect thành Map?)

## 🟢 Junior Level

**Va chạm key (key collision)** — khi hai phần tử của stream tạo ra cùng một key cho một `Map`.

Mặc định, `toMap` ném một lỗi:
```java
// Nếu hai user có cùng id → IllegalStateException
users.stream().collect(toMap(User::getId, u -> u));
```

**Giải pháp:** Thêm một tham số thứ ba — hàm merge:
```java
users.stream().collect(toMap(
    User::getId,
    u -> u,
    (existing, replacement) -> existing  // giữ cái đầu tiên
));
```

**Các tùy chọn của hàm merge:**
- `(old, newVal) -> old` — giữ giá trị đầu tiên
- `(old, newVal) -> newVal` — thay bằng cái mới
- `(old, newVal) -> old + newVal` — kết hợp

// (existing, replacement) -> existing — giữ giá trị ĐẦU TIÊN
// (existing, replacement) -> replacement — giữ giá trị CUỐI CÙNG
// (existing, replacement) -> existing + replacement — kết hợp

## 🟡 Middle Level

### Các chiến lược giải quyết xung đột

**1. Ghi đè:**
```java
// Keep First — để loại trùng lặp (deduplication)
(oldValue, newValue) -> oldValue

// Keep Last — trạng thái hiện tại
(oldValue, newValue) -> newValue
```

**2. Tổng hợp (Collating):**
```java
// Nối chuỗi
.toMap(User::getRole, User::getName, (n1, n2) -> n1 + ", " + n2)
```

**3. Lựa chọn phức tạp (Business Logic):**
```java
(existing, replacement) ->
    existing.getSalary() > replacement.getSalary() ? existing : replacement
```

### Khi nào toMap() là một lựa chọn tồi?

Nếu một key **nên** tương ứng với nhiều value — dùng `Collectors.groupingBy()`:
```java
// Đúng — tạo Map<Role, List<User>>
users.stream().collect(groupingBy(User::getRole));
```

## 🔴 Senior Level

### Chi phí của Hàm Merge

Hàm merge được gọi trong vùng tới hạn (critical section) của việc collect. Các phép tính nặng sẽ làm chậm toàn bộ stream.

### Parallel Stream

Trong các parallel stream, các va chạm được xử lý khi gộp các kết quả con (`combiner`):
- Ít va chạm — overhead không đáng kể
- Nhiều va chạm — tốt hơn nên dùng `groupingByConcurrent`

```
// Trong parallelStream, combiner được gọi để gộp các kết quả từ các worker khác nhau.
// Nó phải tương thích với mergeFunction, nếu không kết quả sẽ sai.
```

### Giá trị Null

`toMap` không dung nạp các giá trị `null`, ngay cả khi hàm merge xử lý chúng → NPE bên trong `Map.merge`.

### Static Analysis

Các công cụ **Error Prone** (Google) và **Sonar** đánh dấu `toMap` không có tham số thứ 3 là một "bug tiềm ẩn". Đây là một tiêu chuẩn code an toàn.

### Chẩn đoán

Với code then chốt, hãy bọc `toMap` trong một block ghi log các object xung đột khi lỗi:
```java
.collect(toMap(
    User::getId, u -> u,
    (old, newVal) -> {
        log.warn("Duplicate key: {}, values: {} and {}", key, old, newVal);
        return old;
    }
))
```

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Va chạm key = hai phần tử tạo ra cùng một key → không có hàm merge: IllegalStateException
- Các chiến lược: `(old, new) -> old` (giữ cái đầu tiên), `(old, new) -> newVal` (thay), kết hợp
- Nếu một key cần nhiều value — dùng `groupingBy()`, không phải toMap
- Trong các parallel stream, các va chạm được xử lý khi gộp các kết quả con (combiner)
- Nhiều va chạm trong parallelStream — tốt hơn nên dùng `groupingByConcurrent` với ConcurrentHashMap
- toMap không dung nạp các giá trị null → NPE bên trong Map.merge, ngay cả với một hàm merge
- Error Prone và Sonar đánh dấu toMap không có tham số thứ 3 là một "bug tiềm ẩn"

**Các câu hỏi phụ thường gặp:**
- **Cách giữ giá trị đầu tiên khi va chạm?** — `(existing, replacement) -> existing` — giữ phần tử được tìm thấy đầu tiên.
- **Khi nào dùng groupingBy thay vì toMap?** — Khi một key tương ứng với nhiều value — groupingBy tạo Map<K, List<V>>.
- **Tại sao hàm merge trong parallelStream phải có tính kết hợp (associative)?** — Vì combiner có thể kết hợp các kết quả theo thứ tự khác nhau — một hàm không kết hợp cho một kết quả không tất định.
- **Cách ghi log các trùng lặp khi va chạm?** — Bọc hàm merge trong một block ghi log các object xung đột.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "toMap không có một hàm merge là an toàn" — sai, khi trùng lặp nó ném IllegalStateException
- "hàm merge được gọi cho mọi phần tử" — sai, chỉ khi key khớp
- "các giá trị null chấp nhận được trong toMap" — sai, Map.merge sẽ ném NPE
- "groupingByConcurrent luôn nhanh hơn toMap" — sai, nó chỉ hiệu quả với nhiều va chạm

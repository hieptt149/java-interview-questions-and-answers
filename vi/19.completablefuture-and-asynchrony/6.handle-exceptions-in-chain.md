# How to Handle Exceptions in CompletableFuture Chain? (Cách xử lý ngoại lệ trong chuỗi CompletableFuture)

## 🟢 Junior Level

Có **3 cách chính** để xử lý ngoại lệ trong CompletableFuture:

1. **`exceptionally()`** — trả về một giá trị mặc định khi có lỗi
2. **`handle()`** — xử lý cả kết quả và lỗi
3. **`whenComplete()`** — thực hiện một hành động khi hoàn thành (không thay đổi kết quả)

```java
// 1. exceptionally — giá trị fallback
CompletableFuture.supplyAsync(() -> {
    throw new RuntimeException("Error");
}).exceptionally(ex -> "default value");  // sẽ trả về "default value"

// 2. handle — xử lý cả thành công và lỗi
CompletableFuture.supplyAsync(() -> {
    throw new RuntimeException("Error");
}).handle((result, ex) -> {
    if (ex != null) return "error occurred";
    return result;
});

// 3. whenComplete — chỉ để biết về việc hoàn thành
CompletableFuture.supplyAsync(() -> "Hello")
    .whenComplete((result, ex) -> {
        if (ex != null) {
            System.err.println("Error: " + ex);
        } else {
            System.out.println("Result: " + result);
        }
    });
```

## 🟡 Middle Level

### So Sánh Chi Tiết

**exceptionally — giống như try-catch:**
```java
CompletableFuture<String> cf = fetchDataAsync()
    .exceptionally(ex -> {
        log.error("Fetch failed", ex);
        return "default";  // giá trị fallback
    });
```

**handle — kiểm soát toàn diện:**
```java
CompletableFuture<String> cf = fetchDataAsync()
    .handle((result, ex) -> {
        if (ex != null) {
            log.error("Failed", ex);
            return "error";
        }
        return result.toUpperCase();  // có thể sửa đổi kết quả
    });
```

**whenComplete — side effect:**
```java
CompletableFuture<String> cf = fetchDataAsync()
    .whenComplete((result, ex) -> {
        // Không thay đổi kết quả — chỉ là side effect
        if (ex == null) {
            metrics.increment("success");
        } else {
            metrics.increment("failure");
        }
    })
    .thenApply(s -> s.toUpperCase());  // kết quả không thay đổi
```

### Các Lỗi Thường Gặp

1. **exceptionally BẮT ngoại lệ từ thenApply:**
```java
// ✅ Ngoại lệ trong thenApply sẽ được exceptionally phía sau bắt
cf.thenApply(s -> {
    throw new RuntimeException("Error");
}).exceptionally(ex -> "default");  // ✅ OK, bắt được nó

// ✅ Nhưng handle tốt hơn cho kiểm soát toàn diện
cf.handle((result, ex) -> {
    if (ex != null) return "default";
    return result;
});
```

2. **Bọc CompletionException:**
```java
// Ngoại lệ được bọc trong CompletionException
cf.exceptionally(ex -> {
    // ex — CompletionException, không phải ngoại lệ gốc!
    Throwable cause = ex.getCause();  // gốc
    return "default";
});
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**exceptionally:**
```java
public CompletableFuture<T> exceptionally(Function<Throwable, ? extends T> fn) {
    return uniExceptioniallyStage(fn);
}

// Chỉ được gọi khi có lỗi
// Nếu thành công — fn không được gọi
// Trả về một giá trị fallback
```

**handle:**
```java
public <U> CompletableFuture<U> handle(BiFunction<? super T, Throwable, ? extends U> fn) {
    return uniHandleStage(null, fn);
}

// Được gọi LUÔN LUÔN — cả khi thành công và lỗi
// result — giá trị (null khi lỗi)
// ex — ngoại lệ (null khi thành công)
```

**whenComplete:**
```java
public CompletableFuture<T> whenComplete(BiConsumer<? super T, ? super Throwable> action) {
    return uniWhenCompleteStage(null, action);
}

// Được gọi LUÔN LUÔN
// KHÔNG thay đổi kết quả — chỉ là một side effect
// Ngoại lệ từ action sẽ được bọc
```

### Đánh Đổi Kiến Trúc

| Phương thức            | Luôn được gọi   | Thay đổi kết quả   | Bắt lỗi |
| ----------------- | --------------- | ---------------- | -------------- |
| **exceptionally** | ❌ Chỉ khi lỗi| ✅ Fallback       | ✅              |
| **handle**        | ✅              | ✅ Kiểm soát toàn diện   | ✅              |
| **whenComplete**  | ✅              | ❌ Chỉ side effect| ❌             |

### Edge Cases

**1. Nhiều error handler:**
```java
cf.exceptionally(ex -> {
    log.error("First handler", ex);
    return "first";
}).exceptionally(ex -> {
    // Không được gọi — cái đầu tiên đã xử lý rồi
    return "second";
});
```

**2. Ngoại lệ trong handler:**
```java
cf.exceptionally(ex -> {
    throw new RuntimeException("Handler error");  // Ngoại lệ mới
}).exceptionally(ex -> {
    // Sẽ bắt được ngoại lệ từ handler đầu tiên
    return "recovered";
});
```

**3. handle để biến đổi:**
```java
// handle có thể thay đổi kiểu
cf.<String>handle((result, ex) -> {
    if (ex != null) {
        return "Error: " + ex.getMessage();
    }
    return "Success: " + result;
});
```

### Hiệu Năng

```
exceptionally: ~5 ns (chỉ khi lỗi)
handle: ~10 ns (luôn luôn)
whenComplete: ~8 ns (luôn luôn)

Overhead không đáng kể so với các thao tác bất đồng bộ
```

### Kinh Nghiệm Production

**Logic retry:**
```java
public <T> CompletableFuture<T> withRetry(
    Supplier<CompletableFuture<T>> operation,
    int maxRetries
) {
    return operation.get()
        .exceptionallyCompose(ex -> {
            if (maxRetries > 0 && isRetryable(ex)) {
                log.warn("Retry after error", ex);
                // Trong production, thêm một khoảng trễ:
                return CompletableFuture.delayedExecutor(100, MILLISECONDS)
                    .thenCompose(v -> withRetry(operation, maxRetries - 1));
            }
            return CompletableFuture.failedFuture(ex);
        });
}

// Java 12+
cf.exceptionallyCompose(ex -> {
    if (shouldRetry(ex)) {
        return retryOperation();
    }
    return CompletableFuture.failedFuture(ex);
});
```

**Pattern Circuit Breaker:**
```java
public CompletableFuture<Response> callWithCircuitBreaker(Request req) {
    if (circuitBreaker.isOpen()) {
        return CompletableFuture.failedFuture(
            new CircuitBreakerOpenException());
    }

    return callAsync(req)
        .handle((result, ex) -> {
            if (ex != null) {
                circuitBreaker.recordFailure();
                throw new CompletionException(ex);
            }
            circuitBreaker.recordSuccess();
            return result;
        });
}
```

### Best Practices

```java
// ✅ exceptionally cho fallback
cf.exceptionally(ex -> defaultValue);

// ✅ handle cho kiểm soát toàn diện
cf.handle((result, ex) -> ex != null ? fallback : result);

// ✅ whenComplete cho giám sát
cf.whenComplete((r, ex) -> metrics.record(r, ex));

// ❌ Bỏ qua lỗi
// ❌ Thao tác chặn trong handler
// ❌ Tạo ngoại lệ mới không có lý do
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- exceptionally(Function<Throwable, T>) — fallback khi lỗi, giống catch
- handle(BiFunction<T, Throwable, U>) — luôn được gọi, kiểm soát toàn diện
- whenComplete(BiConsumer<T, Throwable>) — chỉ side effect, không thay đổi kết quả
- Ngoại lệ được bọc trong CompletionException, gốc thông qua getCause()
- exceptionallyCompose (Java 12+) — trả về một CF khác khi lỗi (cho retry)

**Các câu hỏi phụ thường gặp:**
- **whenComplete có bắt ngoại lệ không?** — Không, nó chỉ quan sát. Ngoại lệ vẫn còn trong CF
- **exceptionally có được gọi khi thành công không?** — Không, chỉ khi lỗi
- **Cách làm retry?** — exceptionallyCompose (Java 12+) hoặc đệ quy trong exceptionally
- **Có thể xử lý một lỗi trong nhiều handler không?** — Có, nhưng handler đầu tiên bắt được nó sẽ tiêu thụ nó

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "whenComplete bắt ngoại lệ" — nó chỉ quan sát, không chặn
- "exceptionally luôn được gọi" — chỉ khi lỗi, handle luôn được gọi
- "Ngoại lệ trong handler sẽ không được xử lý" — ngoại lệ trong handler cũng được exceptionally phía sau bắt

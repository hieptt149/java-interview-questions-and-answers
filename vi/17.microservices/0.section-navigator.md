## Tóm Tắt: Cần Biết Gì Cho Mỗi Cấp Độ

### Junior
- Database per Service = mỗi service có DB riêng (không có JOIN qua các service)
- Sync = HTTP/gRPC (chờ response), Async = Kafka/RabbitMQ (fire-and-forget)
- Service Discovery = cơ chế tìm IP của service trong môi trường động
- API Gateway = một điểm vào duy nhất cho các client bên ngoài

### Middle
- Circuit Breaker: Closed -> Open (khi tỷ lệ lỗi > ngưỡng) -> Half-Open (thử nghiệm)
- Exponential backoff + jitter ngăn ngừa thundering herd
- Sharding = dữ liệu khác nhau trên các server khác nhau, Partitioning = chia trong một DB
- Distributed tracing: trace ID -> span ID -> truyền qua HTTP header
- Contract testing (Pact) bắt các breaking change trong API trước khi lên production

### Senior
- Saga: orchestration (bộ điều phối trung tâm) vs choreography (dựa trên event)
- Compensating transaction != rollback — đó là một transaction mới làm điều ngược lại
- Outbox pattern: ghi event trong cùng transaction + CDC -> Kafka
- Bulkhead: Thread Pool (cô lập hoàn toàn) vs Semaphore (nhẹ hơn, nhưng không cô lập thread)
- Strangler Fig: thay thế monolith dần dần, vấn đề dual write -> Outbox/CDC
- Overhead JWT: 200K thao tác HMAC/RSA ở 10K req/s x 20 service

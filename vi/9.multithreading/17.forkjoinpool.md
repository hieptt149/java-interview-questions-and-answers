# What is ForkJoinPool? (ForkJoinPool là gì?)

---

## Junior Level

### Hiểu biết cơ bản

`ForkJoinPool` là một thread pool chuyên biệt được tối ưu để thực thi các tác vụ dựa trên nguyên lý **"Chia để trị" (Divide and Conquer)**.

**Tại sao:** một pool thông thường với một hàng đợi duy nhất không hiệu quả cho các tác vụ đệ quy — các thread ngồi không trong khi một số tác vụ vẫn đang chạy. ForkJoinPool giải quyết điều này với thuật toán work-stealing: một thread rảnh "trộm" các tác vụ từ đuôi hàng đợi của một thread bận.

### Ví dụ minh họa

Hãy tưởng tượng bạn cần đếm 1.000.000 đồng xu:
- **Pool thông thường:** Một người nhận một tác vụ, đếm, chuyển cho người tiếp theo
- **ForkJoinPool:** Bạn chia xu thành các đống, phát ra. Nếu ai đó xong — họ giúp những người khác

### Hai method then chốt

| Method   | Mô tả                                            |
| -------- | ----------------------------------------------- |
| `fork()` | Submit một subtask để thực thi (bất đồng bộ)     |
| `join()` | Chờ kết quả của subtask                          |

### Ví dụ đơn giản: Tổng mảng

```java
// Tác vụ có kết quả
class SumTask extends RecursiveTask<Long> {
    private final long[] numbers;
    private final int start, end;

    public SumTask(long[] numbers, int start, int end) {
        this.numbers = numbers;
        this.start = start;
        this.end = end;
    }

    @Override
    protected Long compute() {
        // Nếu tác vụ đủ nhỏ — tính trực tiếp
        if (end - start <= 1000) {
            long sum = 0;
            for (int i = start; i < end; i++) {
                sum += numbers[i];
            }
            return sum;
        }

        // Ngược lại — chia đôi
        int mid = (start + end) / 2;
        SumTask left = new SumTask(numbers, start, mid);
        SumTask right = new SumTask(numbers, mid, end);

        left.fork();                    // Gửi phần bên trái
        long rightResult = right.compute(); // Tự tính phần bên phải
        long leftResult = left.join();  // Chờ kết quả bên trái

        return leftResult + rightResult;
    }
}

// Sử dụng
long[] numbers = ...;
ForkJoinPool pool = ForkJoinPool.commonPool();
long total = pool.invoke(new SumTask(numbers, 0, numbers.length));
```

### ForkJoinPool được dùng ở đâu

| Nơi                    | Mô tả                                |
| ---------------------- | ------------------------------------ |
| **Parallel Stream**    | `list.parallelStream().map(...)`     |
| **CompletableFuture**  | Dùng commonPool theo mặc định        |
| **Tác vụ đệ quy**      | Xử lý cây, duyệt đồ thị              |

## Middle Level

### Thuật toán Work-Stealing

Khác với các pool thông thường (một hàng đợi dùng chung), trong ForkJoinPool:

```
Pool thông thường:
    [Hàng đợi dùng chung: T1, T2, T3, T4, T5]
    Thread 1 → T1
    Thread 2 → T2
    Thread 3 → (đang chờ)

ForkJoinPool:
    Thread 1: [T1a, T1b, T1c] ← Deque riêng
    Thread 2: [T2a, T2b]      ← Deque riêng
    Thread 3: []              ← rỗng! Trộm từ đuôi của Thread 1
```

#### Các quy tắc

| Quy tắc                | Mô tả                                                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Deque riêng**        | Mỗi worker có hàng đợi hai đầu (double-ended queue) riêng                                                                                                                                              |
| **LIFO (của mình)**    | Worker lấy các tác vụ từ ĐẦU hàng đợi của chính nó (Last-In-First-Out)                                                                                                                                 |
| **FIFO (của người khác)** | Khi trộm, lấy từ ĐUÔI hàng đợi của một worker khác                                                                                                                                                 |
| **Locality**           | LIFO giữ locality of reference — subtask mới nhất làm việc với dữ liệu vẫn còn trong CPU cache line. Truy cập cache = ~1ns, RAM = ~100ns (chậm hơn 100 lần).                                          |
| **Tranh chấp tối thiểu** | Owner lấy từ đầu, thief trộm từ đuôi — chúng không xen vào nhau                                                                                                                                       |

### RecursiveTask vs RecursiveAction

| Lớp                | Trả về kết quả? | Ví dụ                    |
| ------------------ | --------------- | ------------------------ |
| `RecursiveTask<V>` | Có              | Tổng, tìm giá trị lớn nhất|
| `RecursiveAction`  | Không           | Sắp xếp, xử lý           |

```java
// RecursiveTask — có kết quả
class MaxTask extends RecursiveTask<Integer> {
    @Override
    protected Integer compute() {
        // ...
        return maxValue;
    }
}

// RecursiveAction — không có kết quả
class SortTask extends RecursiveAction {
    @Override
    protected void compute() {
        // Sắp xếp tại chỗ, không trả về kết quả
    }
}
```

### Common Pool

```java
// Instance static — luôn có sẵn
ForkJoinPool commonPool = ForkJoinPool.commonPool();

// Parallelism = số lõi CPU - 1
int parallelism = commonPool.getParallelism();
```

**Tại sao -1?** Điều này chừa một thread logic cho các tác vụ khác (các thao tác nền). Trên một server không có GUI, bạn có thể đổi nó qua `-Djava.util.concurrent.ForkJoinPool.common.parallelism=N`.

### ForkJoinPool vs ThreadPoolExecutor

| Đặc điểm             | ThreadPoolExecutor                | ForkJoinPool                  |
| -------------------- | --------------------------------- | ----------------------------- |
| **Hàng đợi**         | Một cái dùng chung (FIFO)         | Một cái mỗi thread (LIFO/FIFO)|
| **Loại tác vụ**      | Độc lập, blocking                 | Đệ quy, tính toán             |
| **Hiệu quả**         | Trung bình với thời gian tác vụ đa dạng | Cao (work-stealing)         |
| **Context Switching**| Thường xuyên                      | Tối thiểu                     |
| **Tốt nhất cho**     | Các tác vụ I/O-bound              | Các tác vụ CPU-bound          |

## Senior Level

### Khi nào KHÔNG dùng ForkJoinPool

1. **Các tác vụ độc lập đơn giản** — ThreadPoolExecutor thông thường đơn giản và hiệu quả hơn
2. **Các tác vụ I/O-bound** — chặn một thread sẽ chặn work-stealing, dùng virtual thread (Java 21+)
3. **Khối lượng dữ liệu nhỏ** — overhead fork/join vượt quá lợi ích song song
4. **KHÔNG dùng commonPool cho I/O** — bạn sẽ chặn mọi tác vụ dùng nó

### Bên trong: Cấu trúc Work-Queue

```java
// Cấu trúc đơn giản hóa
class ForkJoinPool {
    // Mảng các hàng đợi — một cái mỗi thread
    WorkQueue[] queues;

    static final class WorkQueue {
        ForkJoinTask<?>[] array; // Mảng vòng cho các tác vụ
        ForkJoinThread thread;   // Worker thread
        int base;                // Đuôi (để trộm — FIFO)
        int top;                 // Đầu (cho owner — LIFO)
    }
}
```

### Pattern Fork/Join được tối ưu

```java
@Override
protected Long compute() {
    if (size < THRESHOLD) {
        return computeSequentially();
    }

    MyTask left = new MyTask(subList1);
    MyTask right = new MyTask(subList2);

    // TỐI ƯU: fork() cho một cái, compute() cho cái kia
    left.fork();                     // Bất đồng bộ — vào hàng đợi
    // Tối ưu then chốt: right.compute() chạy trong thread HIỆN TẠI
    // (không tiêu thụ một thread của pool), trong khi left.fork() vào hàng đợi.
    // Hai fork() + hai join() sẽ tiêu thụ 2 thread thay vì 1.
    long rightResult = right.compute(); // Trong thread hiện tại — tiết kiệm một thread!
    long leftResult = left.join();   // Chờ kết quả

    return leftResult + rightResult;
}
```

**Luôn làm `fork()` cho một phần và `compute()` cho phần kia.** Nếu bạn `fork()` cả hai rồi `join()`, bạn lãng phí một thread thừa.

### ManagedBlocker — Cho các thao tác blocking

```java
// ForkJoinPool có thể tạo một thread bổ sung nếu một tác vụ bị block
ForkJoinPool.managedBlock(new ForkJoinPool.ManagedBlocker() {
    private boolean done = false;

    @Override
    public boolean block() throws InterruptedException {
        // Thao tác blocking
        result = blockingCall();
        done = true;
        return true;
    }

    @Override
    public boolean isReleasable() {
        return done;
    }
});
```

### Hiệu năng: THRESHOLD

```java
// Quá nhỏ — nhiều tác vụ, áp lực GC
// Quá lớn — ít song song

// Heuristic: THRESHOLD nên sao cho
// việc xử lý tuần tự mất ~100-500 micro giây

private static final int THRESHOLD = 1000;
```

### Vấn đề: Common Pool Starvation

```java
// XẤU: thao tác blocking trong commonPool
CompletableFuture.supplyAsync(() -> {
    return httpClient.get(url); // I/O blocking dài!
}).thenApply(...);
// Sẽ chặn một trong các thread của commonPool → mọi parallel stream chậm lại!

// TỐT: pool riêng cho I/O
ExecutorService ioPool = Executors.newFixedThreadPool(20);
CompletableFuture.supplyAsync(() -> httpClient.get(url), ioPool);
```

### Chẩn đoán

#### Metric của ForkJoinPool

```java
ForkJoinPool pool = ForkJoinPool.commonPool();

pool.getStealCount();       // Bao nhiêu tác vụ đã bị "trộm" — cao = tác vụ không đồng đều
pool.getQueuedTaskCount();  // Các tác vụ trong hàng đợi
pool.getActiveThreadCount();// Các thread đang hoạt động
pool.getParallelism();      // Parallelism mục tiêu
```

#### jstack

```
"ForkJoinPool.commonPool-worker-1" #10 daemon prio=5
"ForkJoinPool.commonPool-worker-2" #11 daemon prio=5
// Các thread của ForkJoinPool có những tên này
```

### Best Practices

1. **Dùng ForkJoinPool cho các tác vụ CPU-bound** (tính toán)
2. **Đừng dùng commonPool cho I/O** — blocking làm tê liệt mọi parallel stream
3. **THRESHOLD tối ưu** — việc xử lý tuần tự nên mất ~100-500 micro giây
4. **fork() + compute()** — luôn tối ưu, đừng làm fork()+fork()+join()+join()
5. **Giám sát stealCount** — cao = các tác vụ được phân bố không đồng đều
6. **ManagedBlocker** — cho các thao tác blocking bên trong ForkJoinPool
7. **Pool riêng cho I/O** — đừng dùng commonPool

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- ForkJoinPool — pool cho các tác vụ đệ quy dùng "chia để trị", dùng thuật toán work-stealing
- Pool thông thường = một hàng đợi dùng chung (FIFO), ForkJoinPool = mỗi thread có deque riêng (owner: LIFO từ đầu, thief: FIFO từ đuôi)
- LIFO cho owner giữ locality of reference — subtask mới nhất làm việc với dữ liệu từ CPU cache line
- RecursiveTask<V> trả về một kết quả, RecursiveAction — không
- Kích thước commonPool = số lõi CPU - 1 (chừa 1 thread cho các tác vụ nền)
- Tối ưu: fork() cho một phần, compute() cho phần kia — tiết kiệm một thread của pool
- parallelStream() và CompletableFuture dùng commonPool theo mặc định
- KHÔNG BAO GIỜ dùng commonPool cho I/O — bạn sẽ chặn mọi parallel stream trong ứng dụng

**Các câu hỏi phụ thường gặp:**
- **Tại sao thief trộm từ đuôi (FIFO) còn owner lấy từ đầu (LIFO)?** — Để giảm thiểu tranh chấp: owner và thief làm việc từ hai đầu đối diện của deque
- **Tại sao fork()+compute() tốt hơn fork()+fork()+join()+join()?** — fork()+compute() thực thi một phần trong thread hiện tại, tiết kiệm một thread của pool
- **Tại sao commonPool tệ cho I/O?** — Chặn một thread work-stealing làm tê liệt mọi tác vụ dùng commonPool (kể cả parallel stream)
- **ManagedBlocker là gì?** — Một cơ chế cho phép ForkJoinPool tạo một thread bổ sung nếu một tác vụ bị block

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "ForkJoinPool tốt cho các tác vụ I/O-bound" — không, blocking làm tê liệt work-stealing
- "Tôi dùng commonPool cho các HTTP request" — bạn sẽ chặn mọi parallel stream trong JVM
- "ForkJoinPool = pool thông thường với vài hàng đợi" — không, khác biệt then chốt là thuật toán work-stealing
- "Tôi fork() cả hai subtask" — anti-pattern, fork()+compute() tiết kiệm một thread

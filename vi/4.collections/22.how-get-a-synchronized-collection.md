# How to get a synchronized collection? (Cách lấy được một synchronized collection?)

Một **synchronized collection** là một lớp bọc (wrapper / decorator) quanh một collection thông thường, bọc mọi phương thức trong một khối synchronized. Điều này đảm bảo rằng chỉ một luồng tại một thời điểm có thể gọi bất kỳ phương thức nào của collection.

## 🟢 Junior Level

**Dùng Collections.synchronizedX:**

```java
List<String> list = Collections.synchronizedList(new ArrayList<>());
Map<String, Integer> map = Collections.synchronizedMap(new HashMap<>());
Set<String> set = Collections.synchronizedSet(new HashSet<>());
```

**QUAN TRỌNG: iterate yêu cầu synchronized!**
```java
// ❌ Không đúng
for (String s : syncList) { ... }

// ✅ Đúng
synchronized (syncList) {
    for (String s : syncList) { ... }
}
```

## 🟡 Middle Level

### Các phương thức factory

```java
Collections.synchronizedList(list)
Collections.synchronizedMap(map)
Collections.synchronizedSet(set)
Collections.synchronizedNavigableMap(navigableMap)  // Java 8+
```

### Cơ chế: Pattern Decorator

```java
// Bên trong:
class SynchronizedList<E> implements List<E> {
    final List<E> list;
    final Object mutex;  // = this theo mặc định

    public synchronized E get(int index) {
        return list.get(index);  // synchronized trên mutex
    }
}
```

**Điều gì xảy ra khi truy cập đồng thời:**
1. Luồng A gọi `get(0)` → chiếm monitor `mutex`
2. Luồng B gọi `get(1)` → bị chặn trên `synchronized`, chờ
3. Luồng A kết thúc → nhả monitor
4. Luồng B được truy cập

### So sánh với các giải pháp thay thế

| Phương pháp                   | Khi nào                       |
| ----------------------------- | ----------------------------- |
| **Collections.synchronizedX** | Cần khóa toàn bộ              |
| **ConcurrentHashMap**         | Tải cao, ghi thường xuyên     |
| **CopyOnWriteArrayList**      | Các danh sách listener        |
| **Vector/Hashtable**          | KHÔNG BAO GIỜ (legacy)        |

### Các lỗi điển hình

```java
// 1. Quên synchronized khi iterate
for (var e : syncList) { ... }  // CME!

// 2. Để lộ collection gốc
List original = new ArrayList<>();
List sync = Collections.synchronizedList(original);
original.add("x");  // Thread-safety bị vi phạm!

// 3. Đồng bộ hóa kép
synchronized (syncList) {
    syncList.add(e);  // synchronized nội bộ + bên ngoài
}
```

## 🔴 Senior Level

### Đối tượng mutex

```java
// Theo mặc định mutex (mutual exclusion — đối tượng khóa cho synchronized) = this (lớp bọc)
// → Tất cả các phương thức synchronized chặn lẫn nhau
// backing collection — collection gốc được lớp bọc synchronized bao bọc

// Bạn có thể (thông qua reflection) đặt một mutex tùy chỉnh
// → Nhưng API của JDK không hỗ trợ điều này trực tiếp
```

### Kinh nghiệm Production

**Tại sao ConcurrentHashMap tốt hơn:**
```
synchronizedMap:
  → 1 khóa cho mọi thứ
  → Đọc chặn đọc

ConcurrentHashMap:
  → Đọc lock-free
  → CAS cho các lần ghi
  → Các khóa chi tiết (granular) cho mỗi bucket
```

### Best Practices

1. **Iterate** → khối synchronized
2. **Đừng để lộ** collection gốc
3. **ConcurrentHashMap** được ưu tiên hơn
4. **mutex** = this theo mặc định
5. **Tránh** đồng bộ hóa kép

### Tóm tắt cho Senior

- Pattern **Decorator** → synchronized trên mọi phương thức
- **Iterate** → khối synchronized thủ công
- **mutex** = this → khóa toàn bộ
- **ConcurrentHashMap** > synchronizedMap
- **Đừng để lộ** backing collection (collection gốc đang được bao bọc)

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- `Collections.synchronizedList/Set/Map` — các phương thức factory tạo lớp bọc (pattern Decorator)
- Mỗi cái synchronized trên một đối tượng `mutex` duy nhất (theo mặc định là `this`)
- Iterate luôn yêu cầu một khối `synchronized(list) { ... }`
- Collection gốc vẫn có thể truy cập được — sửa đổi nó thông qua collection gốc phá vỡ thread-safety
- Đồng bộ hóa kép (`synchronized(syncList) { syncList.add(e); }`) — overhead thừa
- Các giải pháp thay thế: ConcurrentHashMap (tải cao), CopyOnWriteArrayList (các danh sách listener)
- Vector/Hashtable — legacy, KHÔNG BAO GIỜ trong code mới

**Các câu hỏi phụ thường gặp:**
- *mutex trong synchronized collections là gì?* — Đối tượng khóa cho `synchronized`; theo mặc định là `this`, tất cả các phương thức chặn lẫn nhau.
- *Tại sao iterate qua một synchronizedList mà không có khối synchronized dẫn đến CME?* — Iterator gọi hasNext/next riêng biệt; giữa các lời gọi, một luồng khác có thể sửa đổi collection.
- *Collections.synchronizedList khác ConcurrentHashMap như thế nào?* — Cái đầu — một khóa cho mọi thứ; cái sau — đọc lock-free + các khóa chi tiết.
- *backing collection là gì?* — Collection gốc được lớp bọc synchronized bao bọc; truy cập nó mà bỏ qua lớp bọc phá vỡ thread-safety.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Bạn có thể sửa đổi collection gốc mà không có hậu quả" — điều này phá vỡ thread-safety
- "synchronizedList đảm bảo tính nguyên tử của các thao tác kép" — không, cần một synchronized bên ngoài
- "Iterator.remove() hoạt động mà không cần synchronized cho synchronizedList" — iterate luôn yêu cầu khóa thủ công
- "Vector là một giải pháp thay thế hiện đại" — nó là legacy với khóa thô

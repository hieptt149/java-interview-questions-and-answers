# What is Shenandoah GC? (Shenandoah GC là gì?)

## Junior Level

**Shenandoah GC** — garbage collector với độ trễ (latency) cực thấp, giải pháp thay thế cho ZGC.

**Đặc điểm chính:** Khoảng dừng < 1 ms, giống ZGC, nhưng được phát triển bởi Red Hat cho OpenJDK.

**Khi nào dùng:**
- Cần độ trễ thấp
- Sử dụng OpenJDK/Alpine Linux
- ZGC không có sẵn

---

## Middle Level

### Đổi mới chính

```
Concurrent compaction (dồn nén đồng thời) (Evacuation):
  → Các đối tượng được di chuyển KHÔNG cần dừng ứng dụng
  → Khác với G1 (Evacuation = STW)
```

### Load Reference Barriers

```
Khi đọc tham chiếu:
  → Kiểm tra xem đối tượng có bị di chuyển không
  → Nếu bị di chuyển → trả về địa chỉ mới

→ Rẻ hơn Brooks Pointers (cách tiếp cận cũ)
```

Barrier — một phép kiểm tra được JIT chèn vào trên mỗi thao tác bộ nhớ.
Load Reference Barrier: khi đọc tham chiếu, kiểm tra xem đối tượng có bị di chuyển không.
Nếu bị di chuyển — tự động sửa con trỏ.

### Vòng đời

```
1. Init Mark (STW) — quét Roots
2. Concurrent Marking — đánh dấu ở nền (background)
3. Final Mark (STW) — hoàn tất (finalization)
4. Concurrent Evacuation — di dời đối tượng
5. Update References (STW) — cập nhật tham chiếu
```

### Shenandoah vs ZGC

| Tiêu chí      | Shenandoah      | ZGC                     |
| ------------- | --------------- | ----------------------- |
| Nhà phát triển | Red Hat         | Oracle                  |
| Barriers      | Load Reference  | Load + Colored Pointers |
| Các thế hệ    | Có (Java 21+)   | Có (Java 21+)           |

Shenandoah vs ZGC: cả hai đều concurrent, nhưng cơ chế khác nhau. ZGC dùng Colored Pointers (metadata trong con trỏ) và Load Barriers. Shenandoah dùng Load Reference Barriers — barrier trên lần ĐỌC THAM CHIẾU, tự động sửa con trỏ nếu đối tượng bị di chuyển.

## Senior Level

### Degenerated GC

```
Evacuation Failure → Degenerated GC (STW)
  → Nếu không giúp được → Full GC

Nguyên nhân:
  - Allocation Rate cao
  - Heap nhỏ

Giải pháp: tăng -Xmx hoặc ConcGCThreads
```

### CPU Overhead (Chi phí CPU)

```
Load Barriers + các luồng Concurrent
  → chi phí 5-15% CPU
  → Các luồng GC nền tiêu thụ các lõi CPU
```

### Generational Shenandoah

```
Java 21+: chia theo thế hệ
  → -50% chi phí
  → Thu gom các đối tượng young hiệu quả hơn
```

### Best Practices

1. **Alpine Linux (musl libc)**: Shenandoah ổn định hơn ZGC trên musl. ZGC trong lịch sử từng có vấn đề với musl libc.
2. **Adaptive heuristics** theo mặc định
3. **Tăng ConcGCThreads** khi có Allocation Stall
4. **Giám sát** Degenerated GC trong logs
5. **Java 21+** → hãy test chế độ Generational

### Tóm tắt cho Senior

- **Shenandoah** = concurrent compaction
- **Load Reference Barriers** = kiểm tra khi đọc
- **Degenerated GC** = fallback khi thất bại
- **Generational (Java 21+)** = -50% chi phí
- **Giải pháp thay thế cho ZGC** dành cho OpenJDK

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Shenandoah: khoảng dừng < 1 ms, concurrent compaction (Evacuation KHÔNG cần STW); được phát triển bởi Red Hat cho OpenJDK
- Load Reference Barriers: khi đọc tham chiếu, kiểm tra xem đối tượng có bị di chuyển không; nếu có — tự động sửa con trỏ
- Vòng đời: Init Mark (STW) → Concurrent Marking → Final Mark (STW) → Concurrent Evacuation → Update References (STW)
- Degenerated GC: Evacuation Failure → cố gắng khôi phục theo kiểu STW; nếu thất bại → Full GC
- Generational Shenandoah (Java 21+): chia theo thế hệ → -50% chi phí
- Shenandoah ổn định hơn ZGC trên Alpine Linux (musl libc); ZGC trong lịch sử từng có vấn đề với musl

**Các câu hỏi phụ thường gặp:**
- **Shenandoah khác ZGC như thế nào?** — ZGC dùng Colored Pointers + Load Barriers; Shenandoah dùng Load Reference Barriers (chỉ kiểm tra khi đọc tham chiếu, rẻ hơn)
- **Degenerated GC là gì?** — Fallback khi Evacuation Failure: cố gắng hoàn tất thu gom theo kiểu STW; nếu thất bại → Full GC
- **Khi nào chọn Shenandoah thay vì ZGC?** — Alpine Linux (musl), OpenJDK không có ZGC, hoặc nếu Load Reference Barriers rẻ hơn cho workload của bạn
- **Adaptive Heuristics là gì?** — Shenandoah tự động tinh chỉnh các tham số GC dựa trên hành vi của ứng dụng; thường không yêu cầu tuning thủ công

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Shenandoah dùng Colored Pointers" — đó là ZGC; Shenandoah dùng Load Reference Barriers
- "Shenandoah và ZGC là một" — cơ chế khác nhau: ZGC = Colored Pointers, Shenandoah = Load Reference Barriers
- "Shenandoah không có các thế hệ" — từ Java 21, đã có Generational Shenandoah

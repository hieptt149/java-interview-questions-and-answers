# Why is the String class immutable? (Tại sao class String là bất biến?)

---

## Basic Level

Class `String` trong Java không thể thay đổi sau khi tạo. Bất kỳ thao tác nào "sửa đổi" một chuỗi thực ra đều tạo ra một chuỗi mới.

```java
String s = "Hello";
s.concat(" World"); // s vẫn là "Hello", kết quả phải được gán
s = s.concat(" World"); // giờ s = "Hello World" (object mới)
```

### Tại Sao Nó Được Thiết Kế Như Vậy?

1. **Bảo mật** — các chuỗi được dùng cho đường dẫn file, URL, kết nối DB
2. **Thread-safety** — các chuỗi có thể được truyền giữa các thread mà không gặp vấn đề
3. **Tiết kiệm bộ nhớ** — các chuỗi giống hệt nhau được tái sử dụng (String Pool)

> Mặt trái: lưu trữ mật khẩu trong String là thực hành xấu (xem file 5).

## Intermediate Level

### String Pool

Khi tạo một string literal, JVM kiểm tra xem chuỗi đó đã tồn tại trong pool chưa. Nếu tồn tại — một tham chiếu đến nó được trả về, nếu không — một chuỗi mới được tạo:

```java
String a = "Hello";
String b = "Hello";
System.out.println(a == b); // true — cùng tham chiếu từ pool
```

### Bảo Mật

Các chuỗi được dùng làm tham số khi mở file, kết nối mạng, và kết nối DB. Nếu các chuỗi mutable, một kẻ tấn công có thể truyền một đường dẫn hợp lệ, chờ việc kiểm tra, rồi sau đó thay đổi nó trong bộ nhớ.

### Tính Ổn Định Của hashCode

`String` cache `hashCode()` của nó tại lần tính đầu tiên. Điều này làm cho các chuỗi trở thành key lý tưởng cho `HashMap`:
```java
Map<String, Integer> map = new HashMap<>();
map.put("key", 42); // hashCode được tính một lần
map.get("key");     // cùng hashCode được dùng
```

### Cách Nó Được Hiện Thực Trong JDK
- Class được đánh dấu `final` (cấm kế thừa)
- Trường nội bộ `byte[] value` (Java 9+) hoặc `char[]` (các phiên bản cũ hơn) — `private final`
- Không có method nào sửa đổi trường này

## Advanced Level

### Ý Nghĩa Kiến Trúc

Tính bất biến của `String` không chỉ là sự tiện lợi — đó là một **quyết định kiến trúc cơ bản** mà những điều sau được xây dựng dựa trên nó:

1. **String Pool (pattern Flyweight)** — không có tính bất biến, pool là không thể: thay đổi một chuỗi ở một nơi sẽ phá vỡ tất cả các tham chiếu đến nó
2. **Security Manager** — các kiểm tra truy cập file, mạng, và class dựa trên tính bất biến của các tham số chuỗi
3. **Class Loading** — tên class và đường dẫn load là bất biến, ngăn việc thay thế class
4. **Tính ổn định của HashMap** — `hashCode` được cache đảm bảo hoạt động đúng của hash table

### Sự Tiến Hóa Của Hiện Thực
- **Java 8 trở về trước**: `private final char[] value` — mỗi ký tự là 2 byte (UTF-16)
- **Java 9+**: `private final byte[] value` + trường `coder` — Compact String (Latin-1 = 1 byte, UTF-16 = 2 byte)
  // Thay thế char[] bằng byte[] (Java 9+, Compact String) tiết kiệm ~50% bộ nhớ cho các chuỗi có ký tự Latin.

### Tóm Tắt Cho Advanced
- Tính bất biến của `String` là nền tảng cho **String Pool**, **Bảo mật**, và **Thread Safety**
- Cho phép JVM tối ưu hóa việc sử dụng bộ nhớ và cache hash code
- Bất kỳ "sửa đổi" nào của một chuỗi đều tạo ra một object mới trên heap
- Không có tính bất biến của `String`, toàn bộ nền tảng Java sẽ dễ bị tổn thương. Ví dụ tấn công TOCTOU: đường dẫn `/safe/path` được kiểm tra, nhưng sau đó chuỗi được thay đổi thành `/etc/passwd`.

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- String — class final, trường private `byte[] value`, không có method sửa đổi
- String Pool — các chuỗi giống hệt nhau được tái sử dụng, chỉ hoạt động NHỜ tính bất biến
- Bảo mật — các chuỗi được dùng cho đường dẫn file, URL, kết nối DB
- Tính ổn định của hashCode — String cache hashCode, lý tưởng làm key HashMap
- Sự tiến hóa: Java 8 `char[]` (2 byte/ký tự) → Java 9+ `byte[]` + coder (Compact String, 1 byte cho Latin-1)
- Không có tính bất biến của String, toàn bộ nền tảng Java dễ bị tổn thương (các cuộc tấn công TOCTOU)

**Các câu hỏi phụ thường gặp:**
- *Tại sao String là final?* — Để một subclass không thể thêm tính mutable hoặc override hashCode/equals
- *Compact String là gì?* — Java 9+: các ký tự Latin được lưu trong 1 byte thay vì 2
- *Tại sao String cache hashCode?* — Được tính một lần, tăng tốc hoạt động của HashMap
- *Điều gì sẽ xảy ra nếu không có tính bất biến của String?* — String Pool không thể tồn tại, Security Manager bị bypass

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "String có thể thay đổi qua concat" — concat tạo một chuỗi MỚI, bản gốc không thay đổi
- "String Pool nằm trong PermGen" — kể từ Java 7+, pool đã chuyển sang Heap
- "Tính bất biến của String chỉ là sự tiện lợi" — đó là một quyết định kiến trúc cơ bản
- "byte[] nghĩa là String mutable" — trường là `private final`, không có quyền truy cập bên ngoài

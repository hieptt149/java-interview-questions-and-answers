# What are Profiles in Spring? (Profile trong Spring là gì?)

## Junior Level

**Profiles** — một cách để dùng các thiết lập khác nhau cho các môi trường khác nhau (dev, test, prod).

```yaml
# application.yaml (thiết lập chung)
server.port: 8080

# application-dev.yaml (cho phát triển)
spring.datasource.url: jdbc:h2:mem:dev

# application-prod.yaml (cho production)
spring.datasource.url: jdbc:postgresql://prod-db:5432/mydb
```

**Kích hoạt:**
```bash
java -jar app.jar --spring.profiles.active=prod
```

---

## Middle Level

### Các cách kích hoạt

```bash
# 1. Dòng lệnh
--spring.profiles.active=prod

# 2. Biến môi trường
SPRING_PROFILES_ACTIVE=prod

# 3. Tham số JVM
-Dspring.profiles.active=prod

# 4. Trong test
@ActiveProfiles("test")
```

### @Profile trên các Bean

```java
@Bean
@Profile("dev")
public DataSource devDataSource() { ... }

@Bean
@Profile("prod")
public DataSource prodDataSource() { ... }
```

### Biểu thức logic

```java
@Profile("prod & !cloud")    // Prod, nhưng không phải trong cloud
// Spring 5.1+ hỗ trợ các toán tử logic trong @Profile: &, |, !
@Profile("dev | test")       // Dev hoặc test
@Profile("prod & (mysql | postgres)")  // Điều kiện phức tạp
```

## Senior Level

### Profile Group (nhóm profile)

```yaml
spring:
  profiles:
    group:
      "highload": "cache, async, metrics"

# Kích hoạt highload -> bật cache, async, metrics
```

### Import theo profile (Boot 2.4+)

```yaml
# application.yaml
server.port: 8080
---
spring.config.activate.on-profile: dev
server.port: 9090
---
spring.config.activate.on-profile: prod
server.port: 80
```

### Profile so với Feature Flag

```
Profile:
  -> Hạ tầng (DB, queue)
  -> Cần khởi động lại

Feature Flag:
  -> Logic nghiệp vụ
  -> Thay đổi tức thì (on the fly)

-> Đừng nhầm lẫn chúng!
```

Profile so với Feature Flag: nếu bạn cần bật/tắt chức năng
trên production MÀ KHÔNG khởi động lại - dùng Feature Flag (Unleash, LaunchDarkly).
Nếu hạ tầng khác nhau cho dev/test/prod - dùng Profile.

### Cloud-Native

```
Kubernetes ConfigMaps -> thay thế profile
Spring Cloud Config -> config server bên ngoài
HashiCorp Vault -> secret

Profile -> cầu nối tới các config bên ngoài
```

### Kinh nghiệm Production

**Tình huống thực tế: quên kích hoạt prod**
```
Ứng dụng khởi động với profile mặc định
-> Kết nối tới DB dev!
-> Mất dữ liệu!

Giải pháp:
  -> Bắt buộc phải có profile qua validation
  -> ConfigMaps trong K8s
```

### Chẩn đoán

```bash
# Các profile đang hoạt động:
/actuator/env -> activeProfiles

# Log lúc khởi động:
"The following 1 profile is active: prod"

# Theo lối lập trình:
@Autowired Environment env;
env.getActiveProfiles();
```

### Best Practices

1. **Đừng lưu secret** trong application.yaml
2. **Bắt buộc profile** cho prod -> validation
3. **Profile Group** -> nhóm lại
4. **Feature Flag** -> cho logic nghiệp vụ
5. **Cloud Config** -> quản lý bên ngoài
6. **@ActiveProfiles** -> cho test

### Tóm tắt cho Senior

- **Profile** -> cấu hình khác nhau cho các môi trường
- **Ưu tiên của nguồn (cao nhất tới thấp nhất):**
  Tham số CLI > tham số JVM -D > biến môi trường >
  application-{profile}.properties > application.properties
- **Group** -> gộp các profile
- **Profile so với Feature Flag** -> hạ tầng so với nghiệp vụ
- **Cloud-Native** -> ConfigMaps, Vault
- **Validation** -> bắt buộc profile cho prod

## Interview Cheat Sheet

**Cần phải biết:**
- Profile — cơ chế cho cấu hình khác nhau theo từng môi trường (dev, test, prod)
- Kích hoạt: --spring.profiles.active, SPRING_PROFILES_ACTIVE, JVM -D, @ActiveProfiles trong test
- @Profile trên các phương thức @Bean và các class — bean chỉ được tạo khi profile đang hoạt động
- Biểu thức logic trong @Profile (Spring 5.1+): "prod & !cloud", "dev | test"
- Profile Group (Spring Boot 2.4+): một profile kích hoạt cả một nhóm — spring.profiles.group
- YAML nhiều tài liệu: nhiều profile trong một file qua spring.config.activate.on-profile
- Profile != Feature Flag: profile — hạ tầng (khởi động lại), flag — logic nghiệp vụ (tức thì)

**Các câu hỏi phụ thường gặp:**
- *Làm sao kích hoạt nhiều profile?* — Ngăn cách bằng dấu phẩy: --spring.profiles.active=prod,cache,async.
- *Điều gì xảy ra nếu không kích hoạt profile nào?* — Chỉ application.yaml được dùng (thiết lập mặc định) — nguy hiểm cho prod.
- *Profile khác Feature Flag như thế nào?* — Profile cần khởi động lại và thay đổi hạ tầng; Feature Flag bật/tắt logic nghiệp vụ tức thì.
- *Làm sao đảm bảo chỉ khởi động với đúng profile?* — Validation: kiểm tra env.getActiveProfiles() lúc khởi động và ném lỗi nếu là prod mà không có profile.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Profile có thể thay đổi mà không cần khởi động lại" — không, chỉ kích hoạt lúc khởi động.
- "Feature Flag giống như Profile" — không, flag thay đổi logic nghiệp vụ tức thì.
- "Secret có thể lưu trong application-prod.yaml" — không, dùng Vault, K8s Secrets, các biến CI/CD.
- "Profile group thay thế các profile riêng lẻ" — không, group là một alias cho một tập các profile.

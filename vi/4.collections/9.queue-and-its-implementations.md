# What is Queue and what implementations exist? (Queue là gì và có những cài đặt nào?)

## 🟢 Junior Level

**Queue** — cấu trúc dữ liệu tuân theo nguyên tắc **FIFO** (First In, First Out — vào trước, ra trước).

**Ví dụ minh họa đơn giản:** Hàng xếp hàng ở cửa hàng. Đến trước, được phục vụ trước.

**Các phương thức chính:**

| Hành động  | Exception            | Phương thức an toàn |
| ---------- | -------------------- | ------------------- |
| Thêm       | `add(e)`             | `offer(e)`          |
| Lấy ra     | `remove()`           | `poll()`            |
| Xem đỉnh   | `element()`          | `peek()`            |

```java
Queue<String> queue = new ArrayDeque<>();

queue.offer("A");  // Đã thêm
queue.offer("B");

String first = queue.poll();  // → "A" (rời đi đầu tiên)
String next = queue.peek();   // → "B" (đã xem)
```

**offer/poll/peek được ưu tiên** trong code production vì chúng không ném exception — trả về `false`/`null` khi có lỗi, cho phép xử lý một cách nhẹ nhàng (graceful).

## 🟡 Middle Level

### Các cài đặt chính

**ArrayDeque:**
```java
// Mảng vòng (circular array) → chèn/xóa O(1)
Queue<String> queue = new ArrayDeque<>();
queue.offer("A");  // Nhanh
queue.poll();      // Nhanh
```

**PriorityQueue:**
```java
// Binary Heap → lấy ra theo độ ưu tiên
Queue<Integer> pq = new PriorityQueue<>();
pq.offer(5);
pq.offer(1);
pq.offer(3);
pq.poll();  // → 1 (nhỏ nhất!)
```

### Các phương thức: Exception so với Giá trị đặc biệt

```java
// Ném exception:
queue.add(e);     // IllegalStateException nếu đầy
queue.remove();   // NoSuchElementException nếu rỗng
queue.element();  // NoSuchElementException nếu rỗng

// Trả về giá trị đặc biệt:
queue.offer(e);   // false nếu đầy
queue.poll();     // null nếu rỗng
queue.peek();     // null nếu rỗng

// ✅ Trong production hãy dùng offer/poll/peek!
```

### Các queue thread-safe

```java
// Lock-free (throughput cao)
Queue<String> q = new ConcurrentLinkedQueue<>();

// Blocking (Producer-Consumer)
BlockingQueue<String> q = new LinkedBlockingQueue<>();
q.put("A");       // Chặn (block) nếu đầy
String e = q.take();  // Chặn nếu rỗng

// Bounded (kiểm soát bộ nhớ)
BlockingQueue<String> q = new ArrayBlockingQueue<>(100);
// → Tối đa 100 phần tử → bảo vệ chống OOM
```

## 🔴 Senior Level

### Khi nào KHÔNG dùng Queue

1. **Nếu cần truy cập ngẫu nhiên** — hãy dùng List
2. **Nếu cần tính duy nhất** — hãy dùng Set
3. **Nếu dữ liệu cần được sắp xếp** — PriorityQueue với comparator hoặc TreeSet

### Tại sao các queue không thích null?

```java
// Hầu hết các queue cấm null
queue.offer(null);  // → NullPointerException!

// Tại sao?
// poll() và peek() trả về null cho queue rỗng
// Nếu null là một phần tử hợp lệ → mơ hồ (ambiguity)!
// → "queue rỗng" hay "null ở đỉnh"?
```

### Các pattern của BlockingQueue

```java
// Producer-Consumer
BlockingQueue<Task> queue = new LinkedBlockingQueue<>(1000);

// Producer
queue.put(task);  // Chặn nếu đầy → backpressure!

**Backpressure** — cơ chế mà một consumer chậm báo hiệu cho một producer nhanh chậm lại. Bounded Queue chặn producer cho đến khi consumer giải phóng chỗ.

// Consumer
Task task = queue.take();  // Chặn nếu rỗng
```

### SynchronousQueue

```java
// Queue có sức chứa bằng không!
BlockingQueue<String> q = new SynchronousQueue<>();

// put chặn cho đến khi có ai đó thực hiện take
// Chặn (block) = luồng "ngủ" và không tiêu thụ CPU cho đến khi một luồng khác lấy phần tử. Hiệu quả cho việc đồng bộ hóa mà không cần busy-wait.
q.put("A");  // Đang chờ...

// Trong một luồng khác:
String s = q.take();  // → "A", put được giải phóng

// Cách dùng: Executors.newCachedThreadPool()
```

### DelayQueue

```java
// Các phần tử chỉ khả dụng sau một độ trễ (delay)
class DelayedTask implements Delayed {
    private final long deadline;

    public long getDelay(TimeUnit unit) {
        return unit.convert(deadline - System.currentTimeMillis(), MILLISECONDS);
    }
}

DelayQueue<DelayedTask> queue = new DelayQueue<>();
// poll() chỉ trả về phần tử khi getDelay() <= 0
```

### TransferQueue (Java 7+)

```java
// Producer chờ cho đến khi Consumer lấy phần tử
TransferQueue<String> q = new LinkedTransferQueue<>();

// Producer
q.transfer("message");  // Chặn cho đến khi consumer lấy!

// Consumer
String msg = q.take();  // Lấy, producer được giải phóng

// Cách dùng: truyền dữ liệu đồng bộ
// Truyền đồng bộ = producer chờ đúng thời điểm khi consumer *chấp nhận* phần tử (không chỉ đưa vào buffer). Ví dụ: trao file tận tay người khác so với để trong hộp thư.
```

### Kinh nghiệm Production

**Trường hợp thực tế: Bounded Queue đã cứu khỏi OOM**
- Producer nhanh hơn Consumer → queue phình to
- Unbounded Queue → OOM sau 2 giờ
- Giải pháp: ArrayBlockingQueue(10000)
- Kết quả: Producer bị chặn → hệ thống ổn định

### Best Practices

1. **offer/poll/peek** thay vì add/remove/element
2. **ArrayDeque** — cho một luồng
3. **Bounded Queue** — cho backpressure
4. **ConcurrentLinkedQueue** — lock-free
5. **BlockingQueue** — Producer-Consumer
6. **null bị cấm** trong hầu hết các queue
7. **SynchronousQueue** — cho việc trao tay trực tiếp (direct handoff)

### Tóm tắt cho Senior

- **Queue** = FIFO, offer/poll/peek được ưu tiên
- **ArrayDeque** — nhanh nhất cho một luồng
- **BlockingQueue** — Producer-Consumer với backpressure
- **Bounded** — bảo vệ chống OOM
- **ConcurrentLinkedQueue** — lock-free
- **TransferQueue** — trao tay đồng bộ
- **null** bị cấm (mơ hồ với poll)

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Queue = FIFO (First In, First Out), các phương thức: offer/poll/peek được ưu tiên hơn add/remove/element
- offer/poll/peek trả về false/null thay vì exception — an toàn hơn cho production
- ArrayDeque — nhanh nhất cho một luồng (mảng vòng, chèn/xóa O(1))
- PriorityQueue = Binary Heap, lấy ra theo độ ưu tiên (phần tử nhỏ nhất), O(log n)
- BlockingQueue = pattern Producer-Consumer, put/take chặn, bounded queue = backpressure
- SynchronousQueue = sức chứa bằng không, producer chặn cho đến khi consumer lấy phần tử
- TransferQueue (Java 7+) — trao tay đồng bộ: transfer() chặn cho đến khi consumer lấy
- null bị cấm trong hầu hết các queue — mơ hồ với việc poll() trả về null

**Các câu hỏi phụ thường gặp:**
- Tại sao offer/poll/peek tốt hơn add/remove/element? — Không ném exception, cho phép xử lý nhẹ nhàng
- Tại sao dùng bounded queue? — Backpressure: consumer chậm chặn producer nhanh, bảo vệ chống OOM
- SynchronousQueue khác queue thông thường như thế nào? — Sức chứa bằng không, put chặn cho đến khi có ai đó thực hiện take
- Khi nào dùng TransferQueue? — Cho việc truyền dữ liệu đồng bộ, producer chờ đúng thời điểm chấp nhận

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- ❌ "Queue cho phép lưu null" — hầu hết các cài đặt cấm null (mơ hồ với poll)
- ❌ "Unbounded Queue — lựa chọn ổn cho production" — không có bounded queue thì có nguy cơ OOM từ producer nhanh
- ❌ "add/remove/element — lựa chọn tốt nhất" — chúng ném exception, offer/poll/peek an toàn hơn
- ❌ "PriorityQueue lấy ra phần tử lớn nhất" — theo mặc định lấy ra phần tử NHỎ NHẤT (cần Comparator đảo ngược cho phần tử lớn nhất)

# What Is the Difference Between thenApply() and thenCompose()? (Sự khác biệt giữa thenApply() và thenCompose() là gì)

## 🟢 Junior Level

Cả hai phương thức đều dùng để **tạo chuỗi** CompletableFuture, nhưng khác nhau ở những gì chúng trả về:

- **`thenApply()`** — nhận một hàm `T -> U`, trả về `CompletableFuture<U>`
- **`thenCompose()`** — nhận một hàm `T -> CompletableFuture<U>`, trả về `CompletableFuture<U>`

```java
// thenApply — biến đổi đơn giản
CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> "Hello");
cf.thenApply(s -> s.length())     // String -> Integer
  .thenAccept(len -> System.out.println(len));  // 5

// thenCompose — khi hàm đã trả về CompletableFuture
CompletableFuture<String> cf = getUserIdAsync();
cf.thenCompose(userId -> getUserDetailsAsync(userId))  // String -> CompletableFuture<User>
  .thenAccept(user -> System.out.println(user.name()));
```

**Analogy đơn giản:**
- `thenApply` — giống như `map` trong Stream: biến đổi giá trị
- `thenCompose` — giống như `flatMap` trong Stream: mở gói (unwrap) CompletableFuture lồng nhau

## 🟡 Middle Level

### So Sánh Chi Tiết

**thenApply — cho các biến đổi đồng bộ:**
```java
CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> "Hello");

// Hàm: String -> Integer (đồng bộ)
cf.thenApply(String::length)       // CompletableFuture<Integer>
  .thenApply(len -> len * 2)       // CompletableFuture<Integer>
  .thenAccept(System.out::println); // 10
```

**thenCompose — cho các thao tác bất đồng bộ:**
```java
CompletableFuture<String> cf = getUserIdAsync();

// Hàm: String -> CompletableFuture<User> (bất đồng bộ)
cf.thenCompose(userId -> getUserAsync(userId))  // CompletableFuture<User>
  .thenCompose(user -> getOrdersAsync(user.id()))  // CompletableFuture<List<Order>>
  .thenAccept(orders -> System.out.println(orders.size()));
```

### Các Lỗi Thường Gặp

1. **CompletableFuture lồng nhau:**
```java
// ❌ thenApply tạo một CompletableFuture lồng nhau
CompletableFuture<String> userId = getUserIdAsync();
CompletableFuture<CompletableFuture<User>> nested =
    userId.thenApply(id -> getUserAsync(id));  // Lồng nhau!

// ✅ thenCompose mở gói việc lồng nhau
CompletableFuture<User> flat =
    userId.thenCompose(id -> getUserAsync(id));  // Phẳng!
```

2. **Nhầm lẫn về khi nào dùng cái gì:**
```java
// thenApply — khi kết quả là đồng bộ
cf.thenApply(s -> s.toUpperCase());

// thenCompose — khi kết quả là bất đồng bộ
cf.thenCompose(id -> fetchDataFromApi(id));
```

## 🔴 Senior Level

### Triển Khai Nội Bộ

**thenApply:**
```java
public <U> CompletableFuture<U> thenApply(Function<? super T,? extends U> fn) {
    return uniApplyStage(null, fn);
}

// Tạo một CompletableFuture mới với dependency UniApply
// Khi CF này hoàn thành — hàm fn được áp dụng
// Kết quả của fn được thiết lập vào CF mới
```

**thenCompose:**
```java
public <U> CompletableFuture<U> thenCompose(
    Function<? super T, ? extends CompletionStage<U>> fn
) {
    return uniComposeStage(null, fn);
}

// Tạo một CompletableFuture mới với dependency UniCompose
// Khi CF này hoàn thành — fn được gọi (trả về một CompletionStage)
// Kết quả của fn được "mở gói" vào CF mới
```

### Đánh Đổi Kiến Trúc

| thenApply          | thenCompose               |
| ------------------ | ------------------------- |
| Hàm đồng bộ | Hàm bất đồng bộ   |
| T -> U             | T -> CompletableFuture<U> |
| Giống map           | Giống flatMap              |
| Không lồng nhau         | Mở gói việc lồng nhau           |

### Edge Cases

**1. Chuỗi thenCompose:**
```java
// Workflow bất đồng bộ điển hình
getUserIdAsync()
    .thenCompose(userId -> getUserAsync(userId))
    .thenCompose(user -> getOrdersAsync(user.id()))
    .thenCompose(orders ->
        orders.isEmpty()
            ? CompletableFuture.completedFuture(List.<OrderDetail>of())
            : getOrderDetailsAsync(orders.get(0).id())
    )
    .thenAccept(details -> process(details));
```

**2. Lan truyền ngoại lệ:**
```java
// Ngoại lệ trong thenApply:
cf.thenApply(s -> { throw new RuntimeException("Error"); })
  .exceptionally(ex -> "recovered");  // sẽ bắt được

// Ngoại lệ trong CF được compose:
cf.thenCompose(id ->
    getUserAsync(id)  // có thể ném ra ngoại lệ
        .exceptionally(ex -> defaultUser)  // xử lý bên trong
)
.exceptionally(ex -> fallback);  // xử lý bên ngoài
```

### Hiệu Năng

```
thenApply:
- Overhead: ~5 ns (áp dụng hàm)
- Không chuyển thread

thenCompose:
- Overhead: ~10 ns (mở gói CF)
- Có thể chuyển thread (nếu CF bên trong là async)

thenApplyAsync / thenComposeAsync:
- + ~1μs cho mỗi lần chuyển thread
```

### Kinh Nghiệm Production

**Chuỗi lời gọi microservice:**
```java
@Service
public class OrderFacade {
    public CompletableFuture<OrderSummary> getOrderSummary(Long orderId) {
        return orderRepository.findByIdAsync(orderId)
            .thenCompose(order ->
                userService.findByIdAsync(order.userId())
                    .thenApply(user -> new OrderSummary(order, user))
            );
    }

    // so với dùng thenApply — nếu user đã có sẵn trong bộ nhớ
    public OrderSummary getOrderSummarySync(Order order, User user) {
        return CompletableFuture.completedFuture(order)
            .thenApply(o -> new OrderSummary(o, user));
    }
}
```

### Best Practices

```java
// ✅ thenApply cho các biến đổi đồng bộ
cf.thenApply(s -> s.toUpperCase());

// ✅ thenCompose cho các lời gọi bất đồng bộ
cf.thenCompose(id -> fetchDataAsync(id));

// ✅ Chuỗi thenCompose cho workflow
cf.thenCompose(a -> callB(a))
  .thenCompose(b -> callC(b));

// ❌ CompletableFuture lồng nhau
// ❌ thenCompose khi thenApply là đủ
// ❌ Bỏ qua lỗi trong chuỗi
```

### Khi Nào KHÔNG Nên Dùng thenCompose

Khi thao tác thứ hai KHÔNG phụ thuộc vào kết quả của thao tác đầu và có thể thực thi song song.
Trong trường hợp này, dùng `thenCombine` để thực thi song song.

```java
// ❌ thenCompose — tuần tự, chậm không cần thiết
CompletableFuture<User> user = getUserAsync(userId);
user.thenCompose(u -> getOrdersAsync(userId));  // không phụ thuộc vào user!

// ✅ thenCombine — song song
CompletableFuture<User> user = getUserAsync(userId);
CompletableFuture<List<Order>> orders = getOrdersAsync(userId);
user.thenCombine(orders, UserProfile::new);
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- thenApply — hàm T -> U, cho các biến đổi đồng bộ (giống map)
- thenCompose — hàm T -> CompletableFuture<U>, cho các lời gọi bất đồng bộ (giống flatMap)
- thenApply có thể tạo một CompletableFuture<CompletableFuture<U>> lồng nhau — đây là một bug
- thenCompose mở gói việc lồng nhau, trả về CompletableFuture<U>
- thenCompose thực thi tuần tự, thenCombine — song song

**Các câu hỏi phụ thường gặp:**
- **Khi nào dùng thenApply, khi nào dùng thenCompose?** — thenApply nếu hàm trả về một giá trị thuần túy, thenCompose nếu nó trả về một CompletableFuture
- **Điều gì xảy ra nếu dùng thenApply với một hàm bất đồng bộ?** — Bạn nhận được CompletableFuture<CompletableFuture<U>> — lồng nhau, cần thenCompose
- **thenCompose vs thenCombine — khi nào dùng cái nào?** — thenCompose khi CF thứ hai phụ thuộc vào CF đầu, thenCombine khi chúng độc lập
- **Overhead của thenCompose là gì?** — ~10 ns cho việc mở gói CF, cộng thêm khả năng chuyển thread

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "thenApply và thenCompose có thể thay thế cho nhau" — thenApply sẽ tạo một CF lồng nhau
- "thenCompose nhanh hơn thenCombine" — thenCompose là tuần tự, thenCombine là song song
- "thenApply luôn ở trong cùng thread" — thenApplyAsync chuyển thread

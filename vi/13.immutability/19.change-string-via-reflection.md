# Can you change String value via reflection? (Bạn có thể thay đổi giá trị String qua reflection không?)

---

## Basic Level

Về mặt kỹ thuật — **có**, thông qua Reflection API bạn có thể thay đổi nội dung bên trong của một chuỗi, nhưng đây là một thực hành rất tồi.

```java
String s = "Hello";
// Truy cập trường private value
// Trong Java 8 và trước đó trường này là char[] value. Từ Java 9 (Compact Strings) — byte[] value.
Field field = String.class.getDeclaredField("value");
field.setAccessible(true);
byte[] value = (byte[]) field.get(s);
value[0] = 'J'; // Đổi 'H' thành 'J'
System.out.println(s); // In ra "Jello"
```

**Tại sao điều này tồi**:
- Chuỗi thay đổi **ở khắp mọi nơi** mà `"Hello"` được dùng (string pool)
- `hashCode` bị hỏng — chuỗi bị thất lạc trong `HashMap`
- Đây là một vi phạm bảo mật của JVM

> CẢNH BÁO: Kỹ thuật này KHÔNG ĐƯỢC dùng trong code production.
> Đó là một vi phạm bảo mật phá vỡ JVM. Chỉ dùng cho mục đích giáo dục.

## Intermediate Level

### Hậu Quả

1. **Hỏng String Pool** — chuỗi thay đổi ở mọi nơi mà literal đó được dùng (log, config, tên class)

2. **Hỏng HashMap** — `String` cache `hashCode`. Sau khi thay đổi mảng `value`, nội dung chuỗi thay đổi nhưng hash vẫn giữ giá trị cũ → object không thể tìm thấy trong `HashMap`

3. **Bỏ qua bảo mật (Security Bypass)** — các kiểm tra bảo mật (truy cập file, URL) dựa trên chuỗi. Thay đổi một chuỗi "sau khi validate" là một lỗ hổng kinh điển

### Bảo Vệ Trong Các JDK Hiện Đại

Trong **Java 17+**, quyền truy cập vào các trường nội bộ của `java.base` qua reflection bị **chặn** bởi module system (Project Jigsaw). Bạn sẽ nhận được `InaccessibleObjectException`.

Bạn có thể vượt qua điều này với các cờ khởi chạy (`--add-opens java.base/java.lang=ALL-UNNAMED`), nhưng điều này không khả thi trong production.

## Advanced Level

### Ví Dụ Tấn Công Đầy Đủ
```java
String s = "admin";
Field valueField = String.class.getDeclaredField("value");
valueField.setAccessible(true);
byte[] value = (byte[]) valueField.get(s);
// Đổi "admin" thành "hacker"
value[0] = 'h'; value[1] = 'a'; value[2] = 'c';
value[3] = 'k'; value[4] = 'e'; value[5] = 'r';
```

### Hậu Quả Sâu Xa

- **Ô nhiễm ClassLoader** — tên class, loader, đường dẫn — mọi thứ đều có thể bị xâm phạm
- **Security Manager** — nếu được dùng, các kiểm tra có thể bị vượt qua
- **SerialVersionUID** — phụ thuộc vào tên class, có thể bị xâm phạm

### Sự Tiến Hóa Của Bảo Vệ
- **Java 8 và trước đó**: `setAccessible(true)` hoạt động không có giới hạn
- **Java 9**: module system hạn chế quyền truy cập vào `java.base`
- **Java 16+**: `InaccessibleObjectException` theo mặc định
- **Java 17+**: `--illegal-access=deny` theo mặc định

### Tóm Tắt Cho Advanced
- Tấn công reflection vào `String` — một ví dụ về cách các thao tác cấp thấp phá hủy các đảm bảo cấp cao
- Các JDK hiện đại (17+) chặn điều này ở cấp module
- Trong production với các cờ đúng đắn, điều này là không thể
- Đối với Senior: điều này minh họa tầm quan trọng của tính đóng gói (encapsulation) ở mọi cấp độ

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Về mặt kỹ thuật là có thể qua `setAccessible(true)` trên trường `value`, nhưng đó là một vi phạm bảo mật
- Hậu quả: hỏng String Pool (thay đổi ở khắp nơi), hashCode hỏng (thất lạc trong HashMap), Security Bypass
- Java 9+: module system hạn chế quyền truy cập; Java 16+: `InaccessibleObjectException` theo mặc định
- Java 17+: `--illegal-access=deny` — reflection vào java.base bị chặn
- Có thể vượt qua với các cờ (`--add-opens`), nhưng không khả thi trong production
- Điều này KHÔNG ĐƯỢC dùng trong production — chỉ cho mục đích giáo dục

**Các câu hỏi phụ thường gặp:**
- *Nó có hoạt động trong Java 17+ không?* — Không, `InaccessibleObjectException` nếu không có `--add-opens`
- *Điều gì bị hỏng nếu bạn thay đổi một chuỗi?* — Mọi nơi dùng literal đó, hashCode trong HashMap, Security Manager
- *Ô nhiễm ClassLoader là gì?* — Tên class, loader, đường dẫn — mọi thứ đều có thể bị xâm phạm
- *SerialVersionUID có phụ thuộc vào điều này không?* — Có, phụ thuộc vào tên class, có thể bị xâm phạm

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Đây là một kỹ thuật production bình thường" — đó là một vi phạm bảo mật của JVM
- "Reflection hoạt động trong mọi phiên bản" — trong Java 16+ nó bị chặn với java.base
- "Chỉ chuỗi này thay đổi" — TẤT CẢ các instance của literal đó trong pool đều thay đổi
- "Bạn có thể thêm một cờ trong production" — `--add-opens java.base/java.lang=ALL-UNNAMED` — rủi ro bảo mật

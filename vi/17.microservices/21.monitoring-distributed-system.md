# How to monitor a distributed microservices system (Cách giám sát một hệ thống microservice phân tán)

## 🟢 Junior Level

**Monitoring** là việc quan sát tình trạng của tất cả các service theo thời gian thực.

**Bốn tín hiệu chính (Golden Signals):**
1. **Latency** — một request mất bao lâu
2. **Traffic** — bao nhiêu request mỗi giây
3. **Errors** — bao nhiêu lỗi mỗi giây
4. **Saturation** — tài nguyên đầy đến đâu (CPU, bộ nhớ)

**Các công cụ:**
- **Prometheus** — thu thập metric
- **Grafana** — trực quan hóa
- **Alertmanager** — alert

## 🟡 Middle Level

### Metric

**Metric ứng dụng:**
```
- Request rate (req/s)
- Error rate (%)
- Latency (p50, p95, p99)
- Số connection đang hoạt động
- Sử dụng thread pool
```

**Metric hạ tầng:**
```
- Sử dụng CPU
- Sử dụng bộ nhớ
- Disk I/O
- Network I/O
```

### Prometheus + Grafana

```java
// Micrometer cho Spring Boot
@RestController
public class OrderController {
    private final Counter orderCounter;
    private final Timer orderTimer;

    public OrderController(MeterRegistry registry) {
        this.orderCounter = registry.counter("orders.created");
        this.orderTimer = registry.timer("orders.processing.time");
    }

    @PostMapping("/orders")
    public Order createOrder(@RequestBody OrderRequest req) {
        return orderTimer.record(() -> {
            // MeterRegistry — interface của Micrometer (Spring Boot Actuator).
            // record() — đo thời gian thực thi lambda và ghi vào Timer.
            orderCounter.increment();
            return orderService.create(req);
        });
    }
}
```

## 🔴 Senior Level

### Phương Pháp RED

```
Cho các service:
- Rate: request mỗi giây
- Errors: request thất bại mỗi giây
- Duration: phân phối độ trễ request
```

### Phương Pháp USE

```
Cho tài nguyên:
- Utilization: thời gian trung bình tài nguyên bận
- Saturation: khối lượng công việc đang xếp hàng
- Errors: số lượng lỗi
```

### Kinh Nghiệm Production

**Cấu hình Prometheus:**
```yaml
scrape_configs:
  - job_name: 'user-service'
    metrics_path: '/actuator/prometheus'
    scrape_interval: 15s

  - job_name: 'order-service'
    metrics_path: '/actuator/prometheus'
    scrape_interval: 15s
```

**Quy tắc alerting:**
```yaml
groups:
- name: service_alerts
  rules:
  - alert: HighErrorRate
    expr: rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m]) > 0.05
    # Đây là >5% tỷ lệ lỗi, không phải >0.05 request/giây.
    for: 5m
    labels:
      severity: critical
```

### Best Practices

```
✅ Golden Signals
✅ Phương pháp RED/USE
✅ Chỉ dùng các alert có thể hành động
✅ Dashboard cho mỗi service
✅ Theo dõi SLI/SLO

❌ Quá nhiều alert
❌ Không có dashboard
❌ Không có SLO
```

## 🎯 Interview Cheat Sheet

**Cần phải biết:**
- Golden Signals: Latency, Traffic, Errors, Saturation
- Prometheus — thu thập metric, Grafana — trực quan hóa, Alertmanager — alert
- Micrometer + Spring Boot Actuator — chuẩn cho ứng dụng Java
- Phương pháp RED (Rate, Errors, Duration) — cho các service
- Phương pháp USE (Utilization, Saturation, Errors) — cho tài nguyên
- Chỉ dùng các alert có thể hành động — nếu kích hoạt, kỹ sư biết chính xác cần hành động gì
- Latency p50, p95, p99 — p99 cho thấy trải nghiệm người dùng trường hợp xấu nhất

**Các câu hỏi phụ thường gặp:**
- **Actionable alert là gì?** Một alert mà kỹ sư biết một hành động cụ thể. Không có hành động = noise, loại bỏ nó.
- **RED vs USE?** RED — cho các service (Rate, Errors, Duration), USE — cho tài nguyên (Utilization, Saturation, Errors).
- **Tại sao p99 thay vì trung bình?** Trung bình ẩn đi các outlier — p99 cho thấy trải nghiệm của 1% người dùng tệ nhất.
- **Alert fatigue là gì?** 100 alert mỗi giờ → các alert thật bị bỏ lỡ → chỉ dùng các alert có thể hành động.

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Nhiều alert hơn = tốt hơn" — không, alert fatigue dẫn đến bỏ lỡ các vấn đề thật
- "Latency trung bình là đủ" — không, nó ẩn đi các outlier, p99 quan trọng
- "Metric = log" — không, metric = con số tổng hợp, log = chi tiết
- "Prometheus không có Grafana là ổn" — không có dashboard, bạn không thể phản ứng nhanh

# What Does the @BatchSize Annotation Do (Annotation @BatchSize làm gì)

## Overview

`@BatchSize` là một trong những annotation hữu ích nhất của Hibernate để chống lại N+1 problem. Nó cho phép tải các entity liên quan theo batch, giảm đáng kể số lượng truy vấn SQL.

---

## Junior Level

### @BatchSize Là Gì

Annotation `@BatchSize` khiến Hibernate tải các entity liên quan **theo batch** thay vì thực thi một truy vấn riêng biệt cho mỗi entity.

```java
// Không có @BatchSize - N truy vấn
for (Order order : orders) {
    order.getItems().size();
    // SELECT * FROM order_items WHERE order_id = ?  (cho mỗi Order)
}
// 100 order -> 100 truy vấn

// Có @BatchSize(size = 10) - N/10 truy vấn
@Entity
public class Order {
    @OneToMany(mappedBy = "order")
    @BatchSize(size = 10)
    private List<OrderItem> items;
}

// Hibernate: SELECT * FROM order_items WHERE order_id IN (?,?,?,?,?,?,?,?,?,?)
// 100 order -> 10 truy vấn (10 trong mỗi cái)
```

Mệnh đề IN - một phần của truy vấn SQL WHERE id IN (...). Database giới hạn số lượng tham số. Prepared statement - một truy vấn SQL được biên dịch sẵn.

### Cách Hoạt Động

```
1. Hibernate thu thập ID của các entity mà association cần tải
2. Thay vì N truy vấn riêng biệt - tạo một truy vấn với IN (id1, id2, ...)
3. Batch size = giá trị @BatchSize
4. Số truy vấn = N / batchSize
```

### Nơi Có Thể Dùng

```java
// Trên một collection
@OneToMany(mappedBy = "order")
@BatchSize(size = 25)
private List<OrderItem> items;

// Trên một class (để tải nhiều entity theo ID)
@Entity
@BatchSize(size = 50)
public class User { }

// Khi tải
List<User> users = session.createQuery("FROM User", User.class)
    .setHint(AvailableHints.HINT_SPEC_FETCH_SIZE, 50)
    .getResultList();
// Đây là một cơ chế khác: fetch size kiểm soát số dòng mà JDBC driver
// fetch mỗi lần từ cursor. @BatchSize kiểm soát số ID
// được thay vào mệnh đề IN. Đừng nhầm lẫn chúng!
```

### Khi Nào @BatchSize Vô Dụng

1. **Chỉ tải một entity** - không cần batch
2. **JOIN FETCH được dùng** - dữ liệu đã được tải rồi
3. **Collection nhỏ** (1-3 phần tử) - overhead của batch > lợi ích

## Middle Level

### Chọn Kích Thước Tối Ưu

```java
// Kích thước quá nhỏ
@BatchSize(size = 2)  // hầu như không giúp ích gì, 50 truy vấn thay vì 100

// Khoảng tối ưu
@BatchSize(size = 10)  // tối thiểu
@BatchSize(size = 25)  // thường tốt
@BatchSize(size = 50)  // tối đa (nhiều hơn có thể gây vấn đề với mệnh đề IN)
```

### Cấu Hình Toàn Cục

```yaml
# application.yml - batch size toàn cục cho tất cả
spring:
  jpa:
    properties:
      hibernate:
        default_batch_fetch_size: 50
```

```java
// Hoặc thông qua Java Config
@Configuration
public class HibernateConfig {
    @Bean
    public LocalContainerEntityManagerFactoryBean entityManagerFactory() {
        // ...
        properties.put("hibernate.default_batch_fetch_size", 50);
        return factory;
    }
}
```

### Các Lỗi Thường Gặp

```java
// Kích thước quá nhỏ
@BatchSize(size = 1)  // tương đương với không có @BatchSize

// Kích thước quá lớn (vấn đề DB)
@BatchSize(size = 1000)  // có thể vượt quá giới hạn tham số của mệnh đề IN
// Oracle: tối đa 1000 tham số
// PostgreSQL: phụ thuộc vào cấu hình

// Dùng cho @ManyToOne mà không hiểu
@ManyToOne
@BatchSize(size = 25)
private User user;
// Vẫn hoạt động, nhưng chỉ hợp lý khi nhiều entity tham chiếu đến các User khác nhau
```

### So Sánh Với @Fetch

```java
// @BatchSize - tải theo batch khi truy cập
@BatchSize(size = 25)
private List<OrderItem> items;

// @Fetch(SUBSELECT) - một subquery cho tất cả
@Fetch(FetchMode.SUBSELECT)
private List<OrderItem> items;

// Kết hợp - cách tiếp cận tốt nhất
@BatchSize(size = 25)
@Fetch(FetchMode.SUBSELECT)
private List<OrderItem> items;
```

## Senior Level

### Triển Khai Nội Bộ

Trong Hibernate 6+, batch fetching hoạt động hiệu quả hơn nhờ thuật toán tạo mệnh đề IN được cải tiến.

```
Cách @BatchSize hoạt động:

1. Ở lần truy cập đầu tiên vào một proxy collection:
   - Hibernate kiểm tra BatchSize
   - Thu thập các ID entity parent khả dụng

2. Tạo truy vấn:
   - WHERE parent_id IN (id1, id2, ..., idN)
   - N = min(@BatchSize, ID khả dụng, default_batch_fetch_size)

3. Tải tất cả entity liên quan trong một truy vấn
4. Cache chúng trong Persistence Context
5. Khi truy cập các collection khác - lấy từ cache

Quan trọng:
- Batch size thực tế = min(@BatchSize, hibernate.default_batch_fetch_size)
- Hibernate điều chỉnh động kích thước mệnh đề IN
```

### Giới Hạn Của Database

```
Oracle:       tối đa 1000 tham số trong mệnh đề IN
PostgreSQL:   phụ thuộc vào max_stack_depth và prepared statement
MySQL:        phụ thuộc vào max_allowed_packet
SQL Server:   lên đến 2100 tham số
```

### Tối Ưu Trong Production

```java
// Cấu hình thông qua Hibernate 6
spring.jpa.properties.hibernate.default_batch_fetch_size=50

// Cho các entity cụ thể - ghi đè
@Entity
@BatchSize(size = 100)  // lớn hơn cho những cái thường dùng
public class User { }

// Nhỏ hơn cho các collection lớn
@OneToMany
@BatchSize(size = 10)
private List<LogEntry> logs;
```

### Kết Hợp Các Chiến Lược

```java
@Entity
public class Order {

    // JOIN FETCH cho dữ liệu bắt buộc
    @Query("SELECT DISTINCT o FROM Order o JOIN FETCH o.user WHERE o.id = :id")
    Order findByIdWithUser(@Param("id") Long id);

    // @BatchSize cho dữ liệu bổ sung
    @OneToMany(mappedBy = "order")
    @BatchSize(size = 25)
    private List<OrderItem> items;

    // EntityGraph để tải động
    @EntityGraph(attributePaths = {"items", "payments"})
    List<Order> findByStatus(String status);
}
```

### Monitoring Và Debug

```yaml
# Bật SQL logging để kiểm tra
spring.jpa.show-sql: true
spring.jpa.properties.hibernate.format_sql: true

# Để đếm truy vấn
logging.level.org.hibernate.SQL: DEBUG
logging.level.org.hibernate.type.descriptor.sql.BasicBinder: TRACE
```

### Best Practices

```
@BatchSize(10-50) cho collection
default_batch_fetch_size toàn cục = 25-50
Kết hợp với JOIN FETCH
Tính đến giới hạn DB (giới hạn mệnh đề IN)
Giám sát số lượng truy vấn thực tế

Kích thước quá nhỏ (< 5)
Kích thước quá lớn (> 100 cần kiểm tra: đảm bảo DB của bạn hỗ trợ mệnh đề IN như vậy và truy vấn không vượt quá max_allowed_packet. Với các bảng tham chiếu có 5000 bản ghi, batch size 100 có thể tối ưu.)
Không giám sát truy vấn
Dùng thay cho JOIN FETCH khi dữ liệu luôn cần thiết
```

## Interview Cheat Sheet

**Cần phải biết:**
- @BatchSize tải các entity liên quan theo batch: N truy vấn -> N/batchSize
- Kích thước thực tế = min(@BatchSize, hibernate.default_batch_fetch_size)
- Khoảng tối ưu: 10-50, quá nhỏ - không giúp ích, quá lớn - vấn đề với mệnh đề IN
- Có thể dùng trên collection, class, và toàn cục thông qua default_batch_fetch_size
- DB có giới hạn: Oracle - 1000 tham số, SQL Server - 2100
- Kết hợp với JOIN FETCH và SUBSELECT để có kết quả tối ưu

**Các câu hỏi phụ thường gặp:**
- **@BatchSize có thể dùng ở đâu?** Trên collection (@OneToMany), trên class, toàn cục thông qua cấu hình
- **Điều gì nếu các parent được tải từng cái một?** @BatchSize vẫn hoạt động - thu thập ID khi truy cập
- **@BatchSize vs @Fetch(SUBSELECT)?** SUBSELECT - một truy vấn cho tất cả parent, BatchSize - chia thành các nhóm
- **Khi nào @BatchSize vô dụng?** Chỉ một entity, JOIN FETCH được dùng, hoặc collection rất nhỏ

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi đặt @BatchSize(size = 1000)" - sẽ vượt quá giới hạn tham số DB
- "@BatchSize thay thế JOIN FETCH" - chúng bổ sung, không thay thế nhau
- "Kích thước toàn cục 1000 cho mọi thứ" - vấn đề mệnh đề IN và hiệu năng
- "Tôi không giám sát SQL sau @BatchSize" - không thể thấy hiệu quả nếu không giám sát

# What is the Difference Between ConfigMap and Secret? (Sự khác biệt giữa ConfigMap và Secret là gì?)

---

## Junior Level

### Giải Thích Đơn Giản

**ConfigMap** và **Secret** là các object Kubernetes để lưu trữ cài đặt ứng dụng tách biệt khỏi code. Sự khác biệt là ConfigMap dành cho các cài đặt thông thường, còn Secret dành cho mật khẩu và dữ liệu nhạy cảm.

### Phép So Sánh Đơn Giản

- **ConfigMap** — giống như một ghi chú dán trên màn hình với các cài đặt (địa chỉ server, port)
- **Secret** — giống như một két sắt với mật khẩu và khóa

### ConfigMap

Cho các cài đặt thông thường:
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  DB_HOST: "postgres.default.svc.cluster.local"
  DB_PORT: "5432"
  APP_ENV: "production"
```

### Secret

Cho mật khẩu và khóa:
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secret
type: Opaque
data:
  DB_PASSWORD: cGFzc3dvcmQxMjM=    # base64 của "password123"
  API_KEY: c2VjcmV0LWtleQ==        # base64 của "secret-key"
```

**Quan trọng:** base64 không phải là mã hóa! Đó chỉ là encoding. Bất kỳ ai cũng có thể decode nó.

### Cách Dùng Trong Một Pod?

**Như các biến môi trường:**
```yaml
containers:
- name: app
  image: myapp
  env:
  - name: DB_HOST
    valueFrom:
      configMapKeyRef:
        name: app-config
        key: DB_HOST
  - name: DB_PASSWORD
    valueFrom:
      secretKeyRef:
        name: app-secret
        key: DB_PASSWORD
```

**Như các file (volume):**
```yaml
volumes:
- name: config-volume
  configMap:
    name: app-config
- name: secret-volume
  secret:
    secretName: app-secret
```

### So Sánh

|                  | ConfigMap       | Secret                   |
| ---------------- | --------------- | ------------------------ |
| **Dữ liệu**         | Văn bản thô      | Base64                   |
| **Mục đích**      | Cài đặt        | Mật khẩu, khóa          |
| **Bảo mật**     | Thấp             | Trung bình (cần RBAC)      |

### Những Gì Một Junior Developer Nên Nhớ

- ConfigMap — cho các cài đặt thông thường, Secret — cho mật khẩu
- Các secret được lưu trữ dưới dạng base64 (đây không phải là mã hóa!)
- Cả hai đều có thể dùng như biến môi trường hoặc như file
- Các file từ ConfigMap/Secret được cập nhật mà không cần restart Pod
- Đừng lưu secret trong git — hãy dùng external secrets

---

### Khi Nào KHÔNG Nên Dùng ConfigMap/Secret

ĐỪNG lưu trong ConfigMap: các file lớn (giới hạn >1MB), các file nhị phân.
ĐỪNG lưu trong Secret: các secret của hệ thống bên ngoài (key API bên thứ ba) — hãy dùng Vault thay thế.

## Middle Level

### Lưu Trữ Dữ Liệu

**ConfigMap:**
- Dữ liệu dưới dạng văn bản thô trong etcd
- Giới hạn kích thước: 1 MB (giới hạn của etcd)

**Secret:**
- Dữ liệu dưới dạng base64 (KHÔNG PHẢI mã hóa! base64 dễ dàng decode). Cho mã hóa, hãy dùng EncryptionConfiguration hoặc giải pháp bên ngoài (Vault, Sealed Secrets).
- Các Secret được lưu trong etcd dưới dạng văn bản thô (trừ khi EncryptionConfiguration được bật). Truy cập vào etcd = truy cập vào tất cả các Secret.
- Để bảo vệ thực sự, bạn cần bật **Encryption at Rest (mã hóa khi lưu trữ)** trong etcd

### Hai Cách Sử Dụng

#### 1. Biến Môi Trường

```yaml
env:
- name: DB_HOST
  valueFrom:
    configMapKeyRef:
      name: app-config
      key: DB_HOST
```

**Điểm cộng:** đơn giản
**Điểm trừ:** không được cập nhật "trực tiếp" mà không restart Pod

#### 2. Volume (mount file)

```yaml
volumeMounts:
- name: config-volume
  mountPath: /etc/config
  readOnly: true
```

**Điểm cộng:** được cập nhật tự động (Kubelet cập nhật các file)
**Điểm trừ:** ứng dụng phải có khả năng đọc lại config

### ConfigMap/Secret Bất Biến (Immutable)

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  APP_ENV: "production"
immutable: true    # Không thể sửa đổi sau khi tạo
```

**Lợi ích:**
- Bảo vệ khỏi các thay đổi vô tình
- Giảm tải lên kube-apiserver
- Kubelet không giám sát các thay đổi

### External Secrets

Với các dự án lớn, hãy dùng External Secrets Operator:

```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: db-credentials
spec:
  secretStoreRef:
    name: aws-secrets-manager
    kind: ClusterSecretStore
  target:
    name: db-credentials-secret
  data:
  - secretKey: DB_PASSWORD
    remoteRef:
      key: prod/db/password
```

Đồng bộ hóa các secret từ HashiCorp Vault, AWS Secrets Manager, Azure Key Vault.

### Những Gì Một Middle Developer Nên Nhớ

- Secret dưới dạng base64 ≠ mã hóa. Cần cấu hình bổ sung.
- Biến môi trường không được cập nhật, volume — được cập nhật tự động
- Các object bất biến bảo vệ khỏi các thay đổi vô tình
- External Secrets Operator — tiêu chuẩn production
- RBAC: giới hạn quyền truy cập vào các Secret

## Senior Level

### Kiến Trúc Lưu Trữ Secret

**Không Có Encryption at Rest:**
```
etcd lưu trữ: DB_PASSWORD: cGFzc3dvcmQxMjM=
Bất kỳ ai có quyền truy cập vào etcd đều có thể decode.
```

**Với Encryption at Rest:**
```yaml
# Cấu hình kube-apiserver
encryption-provider-config:
  kind: EncryptionConfiguration
  resources:
  - resources: ["secrets"]
    providers:
    - aescbc:
        keys:
        - name: key1
          secret: <base64-encoded-key>
    - identity: {}
```

Bây giờ các secret được mã hóa trong etcd.

### Bảo Mật: Phân Tích Sâu

| Cấp độ                  | Bảo vệ | Mô tả                          |
| ---------------------- | ---------- | ------------------------------------ |
| **Chỉ Base64**        | Không có       | Bất kỳ ai có quyền truy cập etcd/API đều có thể đọc |
| **RBAC**               | Một phần    | Giới hạn quyền truy cập API                 |
| **Encryption at Rest** | Tốt       | Mã hóa dữ liệu trong etcd                |
| **External KMS**       | Tốt nhất      | Các khóa mã hóa nằm ngoài cluster  |

### RBAC Cho Secret

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: secret-reader
rules:
- apiGroups: [""]
  resources: ["secrets"]
  verbs: ["get", "list"]
  resourceNames: ["app-secret"]  # chỉ secret cụ thể
```

### So Sánh: Env vs Volume

| Khía cạnh      | Biến Env                      | Volume                            |
| ----------- | ----------------------------- | ----------------------------------- |
| Cập nhật      | Yêu cầu restart Pod          | Tự động                          |
| Kích thước        | Tốt cho các giá trị đơn giản        | Tốt cho các file                     |
| Bảo mật    | Hiển thị trong `kubectl describe pod` | Chỉ qua exec vào container   |
| Hot reload  | Không                            | Có (ứng dụng phải đọc lại)     |

### Spring Boot + ConfigMap/Secret

**ConfigMap dưới dạng application.properties:**
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: spring-config
data:
  application.properties: |
    spring.datasource.url=jdbc:postgresql://db:5432/mydb
    spring.jpa.hibernate.ddl-auto=validate
```

```yaml
volumeMounts:
- name: config
  mountPath: /config
  readOnly: true
env:
- name: SPRING_CONFIG_LOCATION
  value: "file:/config/application.properties"
```

### Quản Lý Secret: Sự Tiến Hóa

```
Cấp 0: Secret trong git (anti-pattern)
Cấp 1: Kubernetes Secret (base64)
Cấp 2: Secret + Encryption at Rest
Cấp 3: External Secrets Operator + Vault/KMS
Cấp 4: Service Mesh (mTLS) + SPIFFE/SPIRE (định danh)
```

### Các Object Bất Biến: Khi Nào Dùng

```yaml
immutable: true
```

**Dùng khi:**
- Cấu hình không thay đổi giữa các lần deploy
- Bạn muốn bảo vệ bổ sung khỏi các thay đổi
- Giảm tải API server (các ConfigMap lớn)

**Không dùng khi:**
- Các cài đặt thay đổi động
- A/B testing với các cấu hình khác nhau

### Xử Lý Sự Cố (Troubleshooting)

**Secret không mount:**
```bash
kubectl describe pod myapp
# Warning: Couldn't find secret app-secret in namespace default
```

Nguyên nhân:
1. Secret chưa được tạo
2. Secret nằm trong một namespace khác
3. Lỗi chính tả trong tên

**ConfigMap đã cập nhật nhưng Pod không thấy thay đổi:**
- Độ trễ cập nhật volume: Kubelet cập nhật các file với độ trễ (syncPeriod, mặc định 1 phút)
- Ứng dụng không đọc lại file — cần cơ chế hot reload

### Tóm Tắt Cho Senior

- ConfigMap cho cấu hình, Secret — cho mật khẩu.
- Secret không an toàn theo mặc định nếu không có Encryption at Rest hoặc external KMS.
- Ưu tiên mount file cho hot reload.
- External Secrets Operator + Vault/KMS — tiêu chuẩn production.
- RBAC: giới hạn quyền truy cập Secret theo nguyên tắc đặc quyền tối thiểu.
- Các object bất biến: bảo vệ khỏi thay đổi + giảm tải API server.
- Spring Boot: mount ConfigMap như application.properties cho cấu hình động.

## Interview Cheat Sheet

**Cần phải biết:**
- ConfigMap — cài đặt thông thường (văn bản), Secret — dữ liệu nhạy cảm (base64)
- Base64 ≠ mã hóa! Bất kỳ ai cũng có thể decode; cần Encryption at Rest
- Cả hai đều có thể dùng như biến env (không cập nhật nếu không restart) hoặc volume (tự động cập nhật)
- Giới hạn kích thước: 1 MB (giới hạn của etcd)
- ConfigMap/Secret bất biến — bảo vệ khỏi thay đổi + giảm tải API server
- External Secrets Operator + Vault/KMS — tiêu chuẩn production
- RBAC: giới hạn quyền truy cập Secret theo nguyên tắc đặc quyền tối thiểu

**Các câu hỏi phụ thường gặp:**
- *"Các Secret có được lưu trữ an toàn không?"* — Không theo mặc định (base64 trong etcd); cần EncryptionConfiguration
- *"Biến env vs volume?"* — Volume được cập nhật tự động, biến env yêu cầu restart Pod
- *"External Secrets Operator là gì?"* — Đồng bộ hóa các secret từ Vault, AWS Secrets Manager, Azure Key Vault
- *"Khi nào dùng immutable?"* — Khi cấu hình không thay đổi giữa các lần deploy (bảo vệ + hiệu năng)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Các Secret được mã hóa trong K8s" (chỉ là base64; cần bật Encryption at Rest)
- "Tôi lưu secret trong git dưới dạng base64" (đây không phải mã hóa, bất kỳ ai cũng có thể decode)
- "ConfigMap cho mật khẩu" (hãy dùng Secret)
- "Biến env được cập nhật mà không cần restart" (chỉ volume mới tự động cập nhật)

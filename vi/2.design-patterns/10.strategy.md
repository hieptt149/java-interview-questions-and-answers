# When to Use Strategy? (Khi nào nên dùng Strategy?)

## Junior Level

**Strategy** là một pattern cho phép lựa chọn **các thuật toán khác nhau** cho cùng một công việc.

**Ví dụ minh họa đơn giản:** Thiết bị định vị GPS. Mục tiêu là như nhau (đi từ A đến B), nhưng lộ trình lại khác nhau: bằng ô tô, đi bộ, phương tiện công cộng.

**Ví dụ:**
```java
// Interface Strategy
interface PaymentStrategy {
    void pay(BigDecimal amount);
}

// Các strategy cụ thể
class CreditCardStrategy implements PaymentStrategy {
    public void pay(BigDecimal amount) {
        System.out.println("Paid " + amount + " by credit card");
    }
}

class PayPalStrategy implements PaymentStrategy {
    public void pay(BigDecimal amount) {
        System.out.println("Paid " + amount + " via PayPal");
    }
}

// Cách sử dụng
PaymentStrategy strategy = new CreditCardStrategy();
strategy.pay(new BigDecimal("100"));

// Dễ dàng hoán đổi
strategy = new PayPalStrategy();
strategy.pay(new BigDecimal("200"));
```

**Khi nào nên sử dụng:**
- Có nhiều cách khác nhau để làm cùng một việc
- Cần chọn thuật toán tại thời điểm chạy (runtime)
- Có nhiều `if-else` hoặc `switch`

## Middle Level

### Vấn đề: switch ngày càng phình to

```java
// Không tốt: thêm một loại mới = phải sửa đổi phương thức
public void processPayment(PaymentType type, BigDecimal amount) {
    switch (type) {
        case CREDIT_CARD:
            processCreditCard(amount);
            break;
        case PAYPAL:
            processPayPal(amount);
            break;
        case CRYPTO:
            processCrypto(amount);
            break;
        // Mỗi loại mới -> phải sửa đổi phương thức!
    }
}
```

### Giải pháp: Strategy

```java
// Tốt: thêm một loại mới = class mới
interface PaymentStrategy {
    void pay(BigDecimal amount);
}

class CreditCardPayment implements PaymentStrategy {
    public void pay(BigDecimal amount) { /* logic */ }
}

class PayPalPayment implements PaymentStrategy {
    public void pay(BigDecimal amount) { /* logic */ }
}

// Lựa chọn strategy
Map<PaymentType, PaymentStrategy> strategies = Map.of(
    CREDIT_CARD, new CreditCardPayment(),
    PAYPAL, new PayPalPayment(),
    CRYPTO, new CryptoPayment()
);

strategies.get(type).pay(amount);
```

### Java hiện đại: Lambda

```java
// Đối với các strategy đơn giản, không cần class!
Map<PaymentType, Consumer<BigDecimal>> strategies = Map.of(
    CREDIT_CARD, amount -> processCreditCard(amount),
    PAYPAL, amount -> processPayPal(amount),
    CRYPTO, amount -> processCrypto(amount)
);

strategies.get(type).accept(amount);
```

### Enum Strategy

```java
// Đối với một tập hợp giới hạn các strategy
public enum ShippingStrategy {
    AIR {
        public BigDecimal calculate(BigDecimal weight) {
            return weight.multiply(BigDecimal.TEN);
        }
    },
    SEA {
        public BigDecimal calculate(BigDecimal weight) {
            return weight.multiply(BigDecimal.ONE);
        }
    };

    public abstract BigDecimal calculate(BigDecimal weight);
}

// Cách sử dụng
BigDecimal cost = ShippingStrategy.AIR.calculate(weight);
```

### Spring: Tự động đăng ký Strategy (Auto-registry)

```java
// Tự động đăng ký tất cả các strategy
public interface DiscountStrategy {
    BigDecimal apply(BigDecimal amount);
    String getType();
}

@Component
public class PercentageDiscount implements DiscountStrategy {
    public String getType() { return "PERCENTAGE"; }
    public BigDecimal apply(BigDecimal amount) { return amount.multiply(new BigDecimal("0.9")); }
}

@Component
public class FixedDiscount implements DiscountStrategy {
    public String getType() { return "FIXED"; }
    public BigDecimal apply(BigDecimal amount) { return amount.subtract(new BigDecimal("100")); }
}

// Map tự động
@Service
public class DiscountService {
    private final Map<String, DiscountStrategy> strategies;

    public DiscountService(List<DiscountStrategy> allStrategies) {
        this.strategies = allStrategies.stream()
            .collect(Collectors.toMap(
                DiscountStrategy::getType,
                Function.identity()
            ));
    }

    public BigDecimal applyDiscount(String type, BigDecimal amount) {
        return strategies.get(type).apply(amount);
    }
}

// Thêm một strategy mới = tạo một @Component mới!
```

### Các lỗi thường gặp

1. **Strategy cho if-else đơn giản**
   ```java
   // Overengineering (thiết kế thừa)
   interface CompareStrategy { int compare(int a, int b); }
   class AscendingCompare implements CompareStrategy { ... }
   class DescendingCompare implements CompareStrategy { ... }

   // Lambda là đủ dùng
   Comparator<Integer> asc = Integer::compare;
   Comparator<Integer> desc = (a, b) -> Integer.compare(b, a);
   ```

2. **Interface phình to (Fat interface)**
   ```java
   // Quá nhiều phương thức
   interface Strategy {
       void init();
       void process();
       void cleanup();
       String getName();
       int getPriority();
   }

   // Hãy chia nhỏ thành các strategy riêng biệt
   ```

## Senior Level

### Strategy vs State vs Template Method

**Strategy vs State:**
```java
// Strategy: được chọn từ bên ngoài
order.setPaymentStrategy(new CreditCardPayment());  // Client quyết định

// State: được thay đổi từ bên trong
order.setState(PaidState.INSTANCE);  // Đối tượng tự thay đổi trạng thái của chính nó
order.process();  // Hành vi phụ thuộc vào trạng thái
```

**Strategy vs Template Method:**
```java
// Template Method: kế thừa, các phần của thuật toán
abstract class AbstractReport {
    public void generate() {
        loadData();      // Được override
        formatData();    // Được override
        saveReport();    // Code chung
    }
}

// Strategy: composition, toàn bộ thuật toán
interface ReportGenerator { Report generate(); }
class PdfReportGenerator implements ReportGenerator { ... }
class HtmlReportGenerator implements ReportGenerator { ... }
```

### JIT và Đa hình (Polymorphism)

```java
// Monomorphic call (1 cách triển khai) -> inline
PaymentStrategy strategy = new CreditCardPayment();
strategy.pay(amount);  // JIT inline code -> 0 chi phí phát sinh

// Bimorphic call (2 cách triển khai) -> inline cache
// JIT vẫn tối ưu hóa được

// Megamorphic call (>5 cách triển khai — ngưỡng của HotSpot) -> tra cứu vtable
interface PaymentStrategy { void pay(); }
class A implements PaymentStrategy { ... }
class B implements PaymentStrategy { ... }
class C implements PaymentStrategy { ... }
class D implements PaymentStrategy { ... }  // >2!

// JIT không thể inline -> gọi gián tiếp
// -> chi phí phát sinh ~5-10ns cho mỗi lần gọi
// -> Trong hot path (1 triệu lần gọi/giây) = mất 5-10ms
```

**Tối ưu hóa hot-path:**
```java
// Thay vì interface -> enum switch
public enum PaymentType {
    CREDIT_CARD, PAYPAL, CRYPTO
}

public void process(PaymentType type, BigDecimal amount) {
    switch (type) {
        case CREDIT_CARD -> processCreditCard(amount);
        case PAYPAL -> processPayPal(amount);
        case CRYPTO -> processCrypto(amount);
    }
}

// -> JIT biên dịch thành tableswitch -> O(1) -> nhanh!
```

### Pattern Context Object

```java
// Vấn đề: strategy cần rất nhiều dữ liệu
interface PricingStrategy {
    BigDecimal calculate(Product p, Customer c, Cart cart,
                        Promotion promo, Locale locale);
}

// Giải pháp: đối tượng context
public record PricingContext(
    Product product,
    Customer customer,
    Cart cart,
    Promotion promotion,
    Locale locale
) {}

interface PricingStrategy {
    BigDecimal calculate(PricingContext context);
}

// Việc thêm dữ liệu mới không làm hỏng interface!
```

### Kinh nghiệm Production

**Tình huống thực tế #1: Sự chậm đi do Megamorphic**
- 10 cách triển khai DiscountStrategy
- Hot path: 100,000 lần gọi/giây
- Vấn đề: chi phí phát sinh của virtual call ~5-10ns (nano giây), không phải mili giây
- Giải pháp: dùng enum switch thay vì interface
- Kết quả: nhanh hơn 10 lần

**Tình huống thực tế #2: Tự động đăng ký trong Spring**
- 20 strategy validation
- Đăng ký Map thủ công -> gây lỗi
- Giải pháp: tự động đăng ký thông qua List injection
- Kết quả: strategy mới = @Component mới

### Best Practices (Thực hành tốt nhất)

1. **Lambda** cho các strategy đơn giản
2. **Enum** cho một tập hợp giới hạn
3. **Class** cho logic phức tạp
4. **Tự động đăng ký (Auto-registry)** trong Spring thông qua List
5. **Context Object** để truyền dữ liệu
6. **Tránh** dùng trong hot path (>5 cách triển khai — ngưỡng của HotSpot)
7. **Template Method** cho các phần của thuật toán
8. **Strategy** để thay thế toàn bộ thuật toán

### Tóm tắt cho Senior

- **Strategy** = thay thế toàn bộ thuật toán thông qua composition
- **State** = thay đổi hành vi từ bên trong
- **Template Method** = thay thế từng phần thông qua kế thừa
- **JIT:** megamorphic call >5 cách triển khai (ngưỡng của HotSpot) -> chi phí phát sinh
- **Hot path:** enum switch > interface
- **Context Object** để truyền dữ liệu cho strategy
- **Spring auto-registry:** List<Strategy> -> Map
- **Java hiện đại:** lambda thay thế các strategy đơn giản

## Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- Strategy thay thế switch/if-else ngày càng phình to thông qua composition — mỗi thuật toán trong một class riêng biệt
- Trong Java hiện đại, lambda thay thế các strategy đơn giản: Map<Enum, Function> thay vì 10+ class
- Spring auto-registry: inject List<Strategy> -> tự động sinh ra Map<String, Strategy>
- Tối ưu hóa JIT: megamorphic call (>5 cách triển khai — ngưỡng của HotSpot) -> chi phí phát sinh của virtual call ~5-10ns
- Đối với hot path: enum switch nhanh hơn interface (JIT biên dịch thành tableswitch -> O(1))
- Pattern Context Object: truyền dữ liệu cho strategy thông qua một đối tượng context thay vì 5+ tham số
- Enum Strategy — dành cho một tập hợp giới hạn các thuật toán với code gọn nhẹ

**Các câu hỏi phụ thường gặp:**
- **Khi nào Strategy trở thành overengineering?** — if-else đơn giản có 2-3 nhánh và logic không phức tạp
- **Strategy khác State như thế nào?** — Strategy được chọn từ bên ngoài (client), State thay đổi từ bên trong (bản thân đối tượng)
- **Megamorphic call là gì?** — Lời gọi phương thức với >5 cách triển khai (ngưỡng của HotSpot) -> JIT không thể inline -> chi phí phát sinh
- **Spring tự động đăng ký strategy như thế nào?** — Inject List<Strategy> -> Stream.collect(toMap)

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "Tôi dùng Strategy cho 2 nhánh if-else" — overengineering, lambda là đủ dùng
- "Strategy không ảnh hưởng đến hiệu năng" — megamorphic call >5 cách triển khai có chi phí phát sinh có thể đo lường được
- "Tôi không dùng Strategy, tôi viết switch" — vi phạm OCP, thêm một loại mới = phải sửa đổi code
- "Tất cả các strategy đều phải nằm trong các class riêng biệt" — lambda và enum thay thế được các strategy đơn giản

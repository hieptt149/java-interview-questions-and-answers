# What is ConcurrentHashMap and How Does It Differ from HashMap? (ConcurrentHashMap là gì và nó khác HashMap như thế nào?)

## 🟢 Junior Level

**ConcurrentHashMap** là một phiên bản thread-safe của HashMap. Nhiều thread có thể đồng thời đọc và ghi dữ liệu mà không có vấn đề.

**Các khác biệt then chốt:**

| HashMap                       | ConcurrentHashMap                           |
| ----------------------------- | ------------------------------------------- |
| Không thread-safe             | Thread-safe                                 |
| Nhanh hơn trong một thread    | Chậm hơn một chút, nhưng an toàn            |
| Cho phép null key/value       | Cấm null                                    |
| Fail-fast iterator            | Weakly Consistent iterator (không CME)      |

**Ví dụ:**
```java
// HashMap — sập trong môi trường đa luồng
Map<String, Integer> unsafe = new HashMap<>();

// ConcurrentHashMap — an toàn
ConcurrentMap<String, Integer> safe = new ConcurrentHashMap<>();
safe.put("key1", 100);
safe.putIfAbsent("key2", 200); // Thao tác atomic
```

**Khi nào dùng:** Khi nhiều thread truy cập map đồng thời.

## 🟡 Middle Level

### Kiến trúc ConcurrentHashMap (Java 8+)

| Đặc điểm              | HashMap   | ConcurrentHashMap                               |
| --------------------- | --------- | ----------------------------------------------- |
| Thread safety         | Không     | Có                                             |
| Khóa                  | Không     | Mức bucket (synchronized trên đầu bucket)      |
| null key/value        | Cho phép  | Bị cấm (NPE)                                    |
| Iterator              | Fail-fast | Weakly Consistent (snapshot tại thời điểm tạo)  |
| Các thao tác atomic   | Không     | `putIfAbsent`, `computeIfAbsent`, `merge`       |

### Thread Safety hoạt động như thế nào

1. **CAS (Compare-And-Swap)** — không cần khóa cho bucket rỗng
2. **synchronized trên đầu bucket** — chỉ khi va chạm
3. **Các field volatile** — đảm bảo visibility giữa các thread

```java
// CAS cho bucket rỗng:
if (casTabAt(tab, i, null, newNode))
    break; // Thành công, không khóa!

// synchronized khi va chạm:
synchronized (f) {
    // Thêm vào list/tree
}
```

### Tại sao Null bị cấm?

Trong môi trường đa luồng, `get(key) = null` là mơ hồ:
- Key vắng mặt? Hay value = null?
- Không thể kiểm tra atomic `containsKey()` sau `get()` — trạng thái có thể thay đổi

### Các thao tác atomic

```java
map.putIfAbsent("key", 100);     // Kiểm tra + chèn = atomic
map.computeIfAbsent("key", k -> computeExpensive(k)); // Tính toán lười
map.merge("key", 1, Integer::sum); // Cập nhật atomic
```

### Iterate: Weakly Consistent

```java
for (Map.Entry<String, Integer> e : map.entrySet()) {
    // Sẽ không ném ConcurrentModificationException
    // Có thể không thấy các thay đổi được thực hiện sau khi tạo iterator
}
```

## 🔴 Senior Level

### Hiện thực bên trong (Java 8+)

```java
transient volatile Node<K,V>[] table;
```

Các khác biệt then chốt so với HashMap:
- Mảng `volatile` — đảm bảo visibility
- Các field Node `volatile` (`val`, `next`) — happens-before
- ForwardingNode trong lúc resize — báo hiệu tiến độ

### Multi-threaded Resize

```java
// Khi resize, nhiều thread có thể giúp:
private transient volatile int transferIndex;
```

Các thread phối hợp qua `transferIndex`, mỗi cái xử lý range bucket riêng của nó. Điều này tăng tốc resize trong các hệ thống tải cao.

### Lock Striping vs Node-level Locking

| Cách tiếp cận | Java 7 (Segment) | Java 8+ (Node)     |
| ------------ | ---------------- | ------------------ |
| Độ mịn       | 16 segment       | Mỗi bucket         |
| Concurrency  | Tối đa 16 thread | Tối đa capacity thread |
| Overhead     | Thấp hơn         | Tối thiểu          |

### Memory Ordering

ConcurrentHashMap dùng full memory barrier qua `volatile`:
- Ghi vào `val` được mọi thread nhìn thấy
- Happens-before giữa put và get từ các thread khác nhau
- Không có stale read

### Tại sao không có Null?

Vấn đề Liveness trong đa luồng:
```java
// Kịch bản tiềm tàng nếu không cấm null:
if (map.get(key) == null) {      // null hay không có key?
    if (!map.containsKey(key)) { // Không có key... hay nó bị xóa giữa các lời gọi?
        map.put(key, value);     // Race TOCTOU!
    }
}
```

### Benchmark

| Chỉ số          | HashMap    | ConcurrentHashMap   |
| --------------- | ---------- | ------------------- |
| get (1 thread)  | 5 ns       | 8 ns                |
| get (8 thread)  | Không áp dụng (race) | 60 ns     |
| put (1 thread)  | 8 ns       | 15 ns               |
| put (8 thread)  | Không áp dụng (race) | 120 ns    |

Overhead ~60% trên một thread, nhưng trên 8 thread — lựa chọn đúng đắn duy nhất.

### Best Practices Production

1. **Lựa chọn mặc định cho concurrency** — ConcurrentHashMap
2. **Các thao tác atomic** — `compute`, `merge` thay vì check-then-act
3. **size() trong Java 8+** dùng một hệ thống CounterCell và hoạt động trong O(1) trong trường hợp thông thường. Kết quả là chính xác, nhưng có thể đã cũ vào thời điểm nó được dùng — đừng dùng trong hot path.
4. **Các thao tác Bulk** — `forEach`, `search`, `reduce` (Java 8+) với ngưỡng parallelism

## 🎯 Tóm tắt phỏng vấn (Interview Cheat Sheet)

**Cần phải biết:**
- ConcurrentHashMap — thread-safe qua CAS + synchronized trên đầu bucket
- Cấm null key/value — loại bỏ sự mơ hồ trong check-then-act
- Weakly Consistent iterator — snapshot tại thời điểm tạo, không ném CME
- Các thao tác atomic: putIfAbsent, computeIfAbsent, merge — thay thế check-then-act
- Java 8+: khóa mức node (Java 7 trước đó: mức segment, 16 segment)
- size() qua CounterCell: O(1), chính xác nhưng có thể đã cũ
- Multi-threaded resize: các thread giúp qua transferIndex

**Các câu hỏi phụ thường gặp:**
- **Tại sao null bị cấm?** — get=null là mơ hồ (không có key hay value=null?), phá vỡ putIfAbsent
- **Weakly Consistent khác Fail-safe như thế nào?** — Weakly Consistent: thấy các thay đổi sau khi tạo, nhưng không đảm bảo tính đầy đủ
- **Tại sao không dùng synchronizedMap?** — một mutex duy nhất cho mọi thứ; CHM = truy cập đồng thời tới các bucket khác nhau
- **Overhead so với HashMap?** — ~60% trên một thread, nhưng là lựa chọn đúng đắn duy nhất cho đa luồng

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "ConcurrentHashMap dùng các field Node volatile" — không, CAS + memory barrier
- "Fail-safe iterator" — thuật ngữ đúng: Weakly Consistent
- "size() = O(n)" — không, trong Java 8+ qua CounterCell = O(1)

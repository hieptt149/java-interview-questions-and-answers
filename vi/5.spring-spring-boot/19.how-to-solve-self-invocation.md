# How to Solve the Self-Invocation Problem? (Cách giải quyết vấn đề Self-Invocation?)

## Junior Level

**Giải pháp:** Gọi phương thức thông qua một bean khác!

```java
// Self-invocation
@Service
public class UserService {
    public void outer() {
        inner();  // Vòng qua Proxy!
    }
    @Transactional public void inner() { }
}

// Tách thành hai bean
@Service
public class UserService {
    @Autowired private InnerService innerService;

    public void outer() {
        innerService.inner();  // Qua Proxy!
    }
}

@Service
public class InnerService {
    @Transactional public void inner() { }
}
```

## Middle Level

### Giải pháp 1: Tách bean (tốt nhất)

```java
// Tách logic ra một bean riêng
@Service
public class OrderService {
    @Autowired private NotificationService notifier;

    public void createOrder() {
        repository.save(order);
        notifier.send(order);  // Qua Proxy của một bean khác!
    }
}
```

### Giải pháp 2: ObjectProvider

```java
@Service
public class MyService {
    private final ObjectProvider<MyService> selfProvider;

    public void outer() {
        selfProvider.getObject().inner();  // Qua Proxy!
    }

    @Transactional
    public void inner() { }
}
```

### Giải pháp 3: TransactionTemplate

```java
@Service
public class MyService {
    private final TransactionTemplate transactionTemplate;

    public void outer() {
        transactionTemplate.execute(status -> {
            return inner();  // Trong transaction mà không cần Proxy!
        });
    }
    // Nếu inner() trả về void, dùng:
    // transactionTemplate.executeWithoutResult(status -> { inner(); });

    public void inner() { }
}
```

### Giải pháp 4: @Lazy Self-Injection

```java
@Service
public class MyService {
    @Autowired @Lazy
    private MyService self;  // Proxy của chính nó!

    public void outer() {
        self.inner();  // Qua Proxy!
    }

    @Transactional
    public void inner() { }
}
```

## Senior Level

### Tại sao @Lazy hoạt động

```
@Lazy -> Spring tạo một Proxy tạm (stub)
-> Ở lần gọi đầu tiên, Proxy khởi tạo bean thật
-> self = Proxy -> inner() đi qua Proxy!
```

### AopContext.currentProxy() (Không khuyến nghị!)

```java
// Code mong manh, gắn chặt với Spring
((MyService) AopContext.currentProxy()).inner();

// Yêu cầu: exposeProxy = true
// -> Overhead bổ sung
// -> Đừng dùng!

// Các vấn đề với AopContext.currentProxy():
// (1) yêu cầu exposeProxy = true trong cấu hình,
// (2) thêm overhead ThreadLocal ở mỗi lời gọi,
// (3) code bị gắn chặt với Spring AOP, khó test.
```

### AspectJ Weaving

```
LTW (Load-Time Weaving):
  -> Java Agent dệt các aspect lúc nạp class
  -> Self-invocation hoạt động!

CTW (Compile-Time Weaving):
  -> Plugin Maven/Gradle dệt lúc biên dịch

-> Thiết lập phức tạp
-> Làm phức tạp việc debug
```

### Kinh nghiệm Production

**Tình huống thực tế: ObjectProvider trong legacy**
```
Service lớn với self-invocation
-> Refactoring quá tốn kém
-> ObjectProvider giải quyết vấn đề trong 10 phút
```

### Best Practices

1. **Tách bean** -> giải pháp tốt nhất
2. **TransactionTemplate** -> kiểm soát có chủ đích
3. **ObjectProvider + @Lazy** -> cho legacy
4. **Tránh** AopContext.currentProxy()
5. **AspectJ** — yêu cầu thiết lập weaving bổ sung (compile-time hoặc load-time), làm phức tạp việc debug. Chỉ dùng nếu các giải pháp khác không phù hợp.
6. **Code Review** -> kiểm tra self-invocation

### Tóm tắt cho Senior

- **Tách bean** -> kiến trúc sạch
- **ObjectProvider** -> cách tiếp cận hiện đại
- **TransactionTemplate** -> không có vấn đề proxy
- **@Lazy self-injection** -> cho legacy
- **AopContext** -> đừng dùng
- **AspectJ** -> phức tạp, nhưng giải quyết được

## Interview Cheat Sheet

**Cần phải biết:**
- 4 giải pháp chính: (1) Tách thành các bean khác nhau, (2) ObjectProvider, (3) TransactionTemplate, (4) @Lazy self-injection
- Tách bean là giải pháp tốt nhất xét theo góc độ kiến trúc sạch
- ObjectProvider.getObject() — lấy một proxy của chính nó, cách tiếp cận hiện đại
- TransactionTemplate — kiểm soát transaction theo lối lập trình, không có vấn đề proxy
- @Lazy self-injection — Spring tạo một Proxy tạm, khởi tạo bean thật ở lần gọi đầu tiên
- AopContext.currentProxy() — KHÔNG KHUYẾN NGHỊ: yêu cầu exposeProxy=true, overhead ThreadLocal, gắn chặt với Spring
- AspectJ Weaving (LTW/CTW) — giải quyết được vấn đề, nhưng thiết lập và debug phức tạp

**Các câu hỏi phụ thường gặp:**
- *Tại sao @Lazy hoạt động?* -> Spring hoãn việc khởi tạo, inject một Proxy tạm ủy quyền cho bean thật ở lần gọi đầu tiên
- *Khi nào chọn TransactionTemplate?* -> Khi bạn cần một transaction có chủ đích bên trong một phương thức, mà không tạo một bean riêng
- *Tại sao AopContext.currentProxy() không tốt?* -> (1) exposeProxy=true, (2) overhead ThreadLocal, (3) gắn chặt với Spring, (4) khó test
- *Cái nào tốt hơn: ObjectProvider hay @Lazy?* -> ObjectProvider — tường minh hơn và dễ test hơn; @Lazy — ngắn hơn, nhưng ít rõ ràng hơn

**Dấu hiệu cảnh báo (Red flags — KHÔNG nên nói):**
- "AopContext.currentProxy() là giải pháp được khuyến nghị" — không được khuyến nghị
- "Không cần AspectJ, Spring AOP luôn là đủ" — với self-invocation mà không refactoring, AspectJ là một lựa chọn
- "TransactionTemplate = giống @Transactional" — không, nó là kiểm soát theo lối lập trình, không có proxy
- "@Lazy tạo một bean mới" — tạo một proxy tạm tới cùng một bean
